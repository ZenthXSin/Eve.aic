# 任务工作集与历史归档

已结算的大正文可以填满 16 MiB 逻辑账本，导致不足 128 项的任务目录也拒绝新的空闲回顾。格式 5 将已结算历史与运行工作集分开计数，保留任务正文、身份、来源、授权和全部回执。自由探索不需要目标、收益、小结或成功成果；经历确认只表示独立经历已经持久化。

## 格式与容量

- 格式 4 的索引项保持 `{directory, record}`；格式 5 必须是 `{directory, record, archived}`，`archived` 必须为布尔值。缺省、null、未知字段和错误类型拒绝读取；格式 4 中出现归档字段也拒绝。
- `directory` 的投影规则与格式 4 相同；`record` 保留完整正文的 SHA-256 和字节数。历史仍保留上下文、检查点、结果、失败原因、授权证据、身份、来源、创建时间及全部通知和进度元数据。
- 未归档完整正文按合成任务序列计算，含 JSON 开销，并扣除按全部目录计算的原收尾预留，合计最多 16 MiB。写入还按下述最大收尾正文准入。全部历史及运行正文引用之和最多 64 MiB；单正文和索引各最多 16 MiB，目录仍最多 128 项。
- `FileTaskArchive` 的物理配额是平面归档目录全部条目的 `symlink_metadata().len()` 之和，连同待写正文最多 64 MiB，最多 8192 个目录项。旧版本、未提交正文、链接、锁、未知名字及备份均计数；不递归计算子目录，不等于整个磁盘的已分配空间或可用空间。
- 只有 `Task::settled_at()` 有值的记录才可归档。普通任务的结束通知和最后一条进度尝试须已了结；自由探索须完成独立经历确认。

无字节压力的格式 4 读取与写入保持格式 4；第一次工作集压力（包括收尾预留）出现时，按结算时间、任务 ID 排序选择最早可归档记录，直到整个候选工作集能装入，再提交格式 5。格式 5 不自动降回格式 4。

## 收尾与替换预留

对每个未结算任务，`c` 是候选当前完整正文长度，`M` 是保留同一上下文、检查点和授权正文时，直到结局、通知和经历确认的保守最大序列化长度。上界通过流式 JSON 编码计量：结果与失败原因按控制字符六倍转义，时间、用量、状态、最多六次结束通知和四十八条进度回执按各字段最大编码计算。该投影仅测量容量，绝不会保存成任务或回执。

严格任务重启时可能把已保存的结果转为三条固定修复消息。计量与执行共用实际消息构造器，计入 JSON 的再次转义和剩余恢复次数；一次修复增加消息时同步消耗一份增长预留。自由探索没有目标验收合同，不进入这条修复路径。检查点增大或 Blocked 接续按新的候选重新准入，不承诺无界增长仍能容纳。

工作集准入用 `M` 替代每条未结算正文的 `c`，已结算且未归档记录仍按当前长度计；因此结果转义或通知增长不能再次挤满已接纳工作集。物理预留为全部未结算记录的 `R = Σ(2M − c)`：其中 `M − c` 留给后续增长，另一份 `M` 留给整批重启的完整替换正文，文件数也各预留一个。

每批提交先计算真实目录占用 `P`、本批尚不存在的不同 hash 新正文 `N`、以及当前确认索引中本次将退役且可回收的不同 hash `D`。须同时满足 `P + N ≤ 64 MiB` 和 `P + N − D + R ≤ 64 MiB`，文件数按相同规则检查。仍共享的 hash 不能扣除，不预支未知、备份或其他孤儿文件的空间。需要抵扣退役文件时，先验证全部标准无引用文件；损坏文件会使整体回收失败，不能被当作可用空间。

例如 61 MiB 已结算历史接纳约 1 MiB Running 后，再接纳 1.5 MiB 排队任务会在写入前被拒绝；原 Running 仍保留重启、最坏转义结果和通知所需空间。预留不扩大原常量，也不提前删除当前正文。外部填盘、I/O 故障或自行增加未知文件仍可能阻止后续写入，此时如实报错并保留现场。

## 提交与恢复

候选在独立克隆中构造。更改或复活历史任务前先取消该条的归档位；仍已结算的候选可再次归档，恢复为 Running 的任务必须重新计入工作集。单正文、全部引用、最大收尾工作集、索引编码和整批物理预检全部通过后，才写第一份新正文，最后一次提交完整索引。容量失败不提交部分归档位，不写半批新正文。

正文存储或校验失败，或索引提交无法确认时关闭当前句柄；确认尚未写入的准入失败安全返回，不关闭句柄。无法确认时正文可能已落盘，因此保留旧、新文件，不猜测哪份索引已提交。重开先完整检查全部目录和正文，包括归档任务，再构造所有恢复候选；整批统一预检后才写本批正文和一次索引。读取确认失败时不回收、不恢复。损坏、缺失、身份不符或未知格式均保留原文件并拒绝打开。

索引确认后可以回收无引用且摘要有效的标准正文。若提交确认后、清理之前崩溃，或上次清理失败，下一次预检可能因残留文件超额：此时仅依据已经确认的当前索引验证并补回收，再重做整批物理预检；绝不提前删除本次候选将替换的当前正文。损坏孤儿、未知名字、链接和备份不会被这条路径删除。回收失败不能撤销已确认的业务结果；写入所需的补回收失败则返回错误。

达到 128 项时沿用旧的已结算淘汰范围，以及最近二十四小时进度回执保护；本次没有扩大删除范围，因此历史保留不是无限的。

## 读取与兼容

`M` 和物理预留属于写入准入策略，不是额外的持久格式字段。格式 4/5 只读打开仍核对正文、目录、归档资格、实际工作集与全部引用容量；不因新版本的保守上界把原合法状态误报为损坏。旧记录不天然具有新预留，恢复或变更必须重新通过整批准入；不能容纳时零新正文失败。

来源幂等、每日创建计数、进度范围预算、调度目录、`get_owned`、全快照和 `evidence_snapshot` 仍包含历史。完整校验逐条读取；恢复阶段暂存全部发生变化的完整任务及本批编码，内存不再是始终单条正文。兼容全快照也会加载全部历史，不承诺恒定内存。

替换 `TaskArchiveStore` 必须实现 `check_capacity` 的真实物理预检；默认返回 `UnsupportedVersion`。自定义实现可以保留更多旧正文，但不能假装已回收而抵扣空间；预检、写入与索引提交须独占同一索引和档案。

Python 升级监督器、源码更新共用门和 QQ 验收读取器识别格式 5，并按只读规则核对每份正文；它们不复制 Rust 的写入上界投影。仓库外部署工具必须收集格式 5 的完整引用，在下一发布工作副本更新和验证，不修改冻结证据。

只识别格式 4 的旧二进制将拒绝格式 5；无归档适配器的宿主同样拒绝打开。首次启用格式 5 不支持旧二进制的普通自动回退或便携发布回退。当前 Linux 发布路径限定为新版完整配置、同一二进制与脚本的最小恢复配置、停止；不能把旧快照覆盖到已经产生新回执的状态上。备份仍须在停写或一致性快照下，同时保留整个 `eve.task` 命名空间、初始化标记和全部 `task-archive` 引用。

## 验证范围

`tests/tasks/working_set.rs` 使用自有临时文件档案和真实 TaskAdmin 入口，覆盖四十条终态的保留、新准入的收尾预留、整批恢复零写拒绝、提交确认与清理之间崩溃、索引确认未知、损坏孤儿、严格结果修复、未知效果与回执、来源幂等及原额度和淘汰规则。Python 用例仅证明只读消费者与升级控制流程；未运行 Rust 编译时不能把合成夹具或 rustfmt 报告为 Rust 行为验收通过。
