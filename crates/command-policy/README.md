# 命令准入策略

`PrefixRulePolicy` 实现 `eve-developer-api::CommandPolicy`。规则从 JSON 加载，自带匹配与不匹配例子；无效规则拒绝加载。策略只分析程序和完整参数，不执行命令，也不保存持久化状态。

每次判断都有明确结论。未知程序、解释器、脚本、包装器，以及无法证明安全的参数至少返回 `Prompt`，交给宿主独立行动审核。即使追加规则写了 `Allow`，也不能降低该审核下限。所有规则与语义检查取最严格结论，内置 `Forbidden` 不能被追加规则放开。

仅固定 `/bin/`、`/usr/bin/` 路径下，完整参数符合约束的 `pwd`、`whoami`、`uname`、`id`、当前目录 `ls`、`echo`、无参数 `true`/`false` 可以返回 `Allow`。这些目录属于宿主受信安装范围；任意同名工作区程序、相对路径、裸命令及未知选项都需审核。裸命令通过宿主 `PATH` 查找，策略不能证明其实际程序来源。

`ls` 免审核只列当前目录，文件内容读取和其他路径要经过审核或专门文件工具的路径授权。Git 即使表面只读，也可能加载仓库钩子、外部 diff 或配置的命令，因此需要审核。策略接口没有工作目录、用户身份和文件状态，不能凭命令名批准这些行为。

shell 的文本拆分不是 AST。它只尝试发现更严格的禁令，例如脚本里的 `reboot`；所有 shell 调用本身仍需审核，包括简单命令、复合命令、替换、重定向和脚本文件。包装器仅在参数语义确定时提取子命令；遇到未知参数保持审核，不猜测执行目标。

`Prompt` 表示自动送审，不表示相信模型填写的 `owner_confirmed`。宿主负责真实身份与原话授权、审核超时和失败关闭、执行前再次核权以及完整操作审计。主人或管理员的业务权限也不能跳过这些安全底座。`Allow` 只省略独立风险审核，不豁免宿主身份、权限和审计。

测试覆盖未知二进制、解释器、shell 复合与替换语法、伪装系统程序、危险参数、宽前缀放行规则、包装器参数和已有禁令。运行 `cargo test -p eve-command-policy` 验证。
