# 命令准入策略

`PrefixRulePolicy` 实现可替换的 `eve-developer-api::CommandPolicy`，只分析程序和完整参数，不执行命令、不保存状态。JSON 规则携带匹配和不匹配例子，无效规则拒绝加载。

普通读写、构建、测试、脚本、解释器、未知程序和工作区清理默认 `Allow`，不需要模型逐步审查。未发现风险表示没有命中具体危险，不能理解为静态证明程序安全。用户身份、文件边界、撤销与取消仍由实际执行宿主核对。

凭据位置、提权、修改关键系统路径、终止服务或扩大权限等具体行为返回 `Prompt`，只审查它是否直接危害系统安全。停机、格式化、递归删除系统根目录等明确破坏返回 `Forbidden`。用户目标、业务价值、是否预先指定每一步都不是审查条件；一般不确定性、使用 shell 或工程外路径也不构成危险。

已知包装器和 shell 子命令会继续匹配具体禁令；这不是完整 shell 或源码分析，也不保证发现所有动态危险。宿主提供的追加规则可收紧结论，不能放开已有禁令。`Allow` 省略模型风险请求，仍留下真实执行回执；`Prompt` 不是要求用户再说一句同意。

运行 `cargo test -p eve-command-policy` 可验证普通命令免审、具体系统危险、包装器与自定义规则。
