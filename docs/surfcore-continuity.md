# SurfCore 机制的 Eve 适配

参考 [SurfCore](https://github.com/Mieksido/surfcore/tree/0ce8580048d3dddb21860114edb8b115d5d79d1e)
的 `purpose-engine.js`、`conversation-closure.js`、`vector-memory.js` 和
`qq-chat-v2/agent.cordis.yml`。 复用 Eve 的近期重心、意识日志、便签、异步向量索引和 QQ
主动发送；没有引入上游桥接器、额外人格模型或独立记忆库。

- `set_focus`
  保持旧参数兼容，增加可选来源、依据、把握、过期时间和明确反馈。依据必须是未回滚的真实意识记录，反馈必须引用真实入站消息。同一依据不能重复提高把握，也不会把后续任意一句话自动归因给全部目标。
- `set_conversation` 记录 `continue / linger / close`，保存摘要和下次线索，最多保留 12
  个会话。关闭不发消息、不修改通知、不增加等待或模型调用。陈旧会话水位、未回答的实质消息、待回应事项和未确认送达的出站消息会拒绝关闭。简短完整的道别/附和可以直接收尾；私信和新通知仍走现有唤醒路径。
- `start_conversation` 从一个真实 active 重心主动开口，一次发送一条原文。夜间 23:30–08:30
  保持安静，目标一屏消息静默至少半小时，全局至少间隔 3 小时，每天最多 4 次，刚收尾冷却 20 分钟。使用
  Eve
  的现有时区，不修改预算或模型。相同角度不重复，同一重心在该会话无人接续最多主动提两次；拒绝只作用于反馈所在会话。没有机会返回
  `deferred`，不触发工具失败恢复。发送前持久保留机会和原
  actionId，恢复先核查原回执；未知送达不换编号重发。保留最多 16 条机会记录，失败尝试也保守计入节流。
- `memory.recall` 接入现有异步 memory 向量索引，采用语义 0.65、词法 0.15、实际使用重要性 0.10、时间
  0.10
  的混合排序。未入索引的新记忆和服务暂不可用时有词法兜底。单纯重复召回不增加排序重要性；相关度门槛防止近期无关材料进入结果。保持原始相关度
  `score`，另给 `rankingScore` 与分项；旧记忆标记 `historical`
  并保留原来源。索引等待期间新增回滚仍在返回前过滤。

聊天提示词借鉴上游的“结束不是终止”“没有自然话题就安静”“旧事不是当前事实”及具体场景取舍，保留 Eve
的身份、用户约定、委派偏好和真实回执原则。自定义身份前缀按已有升级规则保留，仓库生成的社交规则随升级更新。

所有判断在现有轮次内进行，不额外请求模型。接续状态只有变化时才追加到上下文，不在轮询中改写时间或计数，沿用固定上下文投影和缓存前缀。
