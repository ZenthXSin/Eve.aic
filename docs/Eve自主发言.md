# Eve 自主发言

QQ 默认实时交互由 Eve 自己决定是否开口、何时开口和说什么。宿主保存事实、执行等待、校验权限和传输消息；模型结束、工具计数、超时、任务完成、提醒到期都不是自动发消息的理由。没有开场确认、定时进度、结尾总结或失败兜底。群聊被叫到也可以等待或沉默。

## 当前对话

`send_message` 是模型明确发出一条正文的工具，闲聊、问题、进展和最终结果走同一条链路。普通 assistant final 只结束内部处理，不会自动复制到 QQ。已确认送达的内容才进入交流记忆；不能把内部草稿当成对方已经收到的回复。

- 每次一条完整正文，最多 32768 个 UTF-8 字节；分几条由模型决定，不按标点切句或按字数模拟打字。
- `after_ms` 可选 0 至 10000 毫秒。期间新输入到来，未发出的旧决定返回 stale；模型读取新内容后重新决定。
- `wait_for_input` 等待 1 至 60000 毫秒，没有占位消息；同一可信会话、同一发送者的新消息加入当前轮，沿用原预算及已执行结果。长期等待使用持久触发器。
- 表情包也必须由 `send_sticker` 明确决定，与文本共用串行发送作用域和真实平台回执。
- 每轮最多 64 次表达尝试。私聊前两条使用原消息被动额度，后续或被动窗口接近到期时走原会话主动发送；当前群内轮次最多三条被动表达，超额返回未发送。群后台的主动发言另走来源认领。平台权限、频率和拒绝仍以实际回执为准。

宿主在实际写入桥接和 SDK 发送前再次核对控制代、会话及最新人类消息。已经开始的平台操作不能靠取消保证撤回；结果未知的消息不重发。工具返回 `sent=true` 且带有效 `message_id` 才证明送达，`unknown` 不等于失败。来源、收件人和平台锚点由宿主绑定，模型不能从正文改路由。

工具预算预留最后一次表达机会，仍计入原上限；预算结束不会额外代写一条收尾。模型可以不用这次机会，安静结束。旧阶段、压缩、工具里程碑和慢步骤事件继续服务内部诊断，在实时路径不产生聊天文字。`EVE_QQ_LIVE_INTERACTION=false` 仅用于显式旧兼容组合，不具备这里的自主发言保证。

## 后台事实

提醒、任务完成、进展、故障、触发器、澄清、邀请与命令执行结果只提供带版本的事实。统一交流审视读取当前 AGENT、同一身份的会话、记忆和真实送达记录，由 Eve 返回严格 JSON：

| 决定 | 行为 |
| --- | --- |
| `{"action":"speak","text":"完整一条正文","after_ms":0}` | 保存这条明确决定，正文最多 2048 个 UTF-8 字节，可延后 0 至 60000 毫秒。 |
| `{"action":"wait","after_ms":60000}` | 1000 至 86400000 毫秒后重新审视；到期没有预定台词，也不承诺届时一定开口。 |
| `{"action":"silence"}` | 结束这次事实的交流决定，不创建发送尝试，也不等于业务完成或承诺取消。 |

审视没有执行工具；资料和旧内部结束文本不是已完成新操作的证据。普通文字、额外字段、无效 JSON、模型失败不产生备用消息，保留事实并至少等待一分钟再审视。无路由、权限不足或暂时不满足条件的来源不能堵住其他会话。

候选读取不认领。只有准备发送时才比较完整来源版本、状态、身份、正文、决定与最新人类锚点并原子认领；不按名称猜最新任务，也不把过期决定发送到新话题。群聊观察采用同样的三态协议和只读候选分页，见[群聊自主交流](./群聊插话.md)。

## 持久化与恢复

QQ 主回执格式为 9。`Handled` 表示这次输入已处理，不代表说过话；真实 Control 轮次通过 `control_turn_id` 绑定，命令不能伪造它。独立表达保存决定编号、正文或图片路径、Sending/Sent/Failed 状态及真实平台消息编号。原来格式 1 至 8 的记录保持可读，旧程序不能读取新格式。

`speech.sqlite3` 独立保存事实、决定、等待期限和送达凭据，使用 WAL、完整同步和独占锁。群观察数据库升级为格式 4；任务通知、触发器和健康通知等来源同步采用新认领/沉默状态。备份与迁移必须包含整个状态目录、SQLite 的 WAL 和 required 标记，不能只复制 `state.json`。

等待和未认领的决定跨重启保留；新来源使旧决定失效。中断的模型审视稍后重新检查事实；已进入发送却没有回执的记录保留为 unknown，不自动补发。损坏、未知格式、身份不匹配、缺失必需数据库或伪造成功回执都拒绝打开并保留原文件，不清空重建。

自升级门禁验证明确表达已结算或本轮安静结束、Control 轮次完成、没有在途新发送或模型审视。历史未决记录只按未变化指纹排除对空闲的影响，不能证明当前轮成功。切换前必须准备能读取新格式的恢复版本；不能把已迁移状态交给旧版二进制或用旧备份覆盖新会话来回滚。

## 提示词与验证

稳定人格在 `AGENT.md`；对话表达协议在 `llm-api/src/dialogue_prompt.md` 和组合层表达约束；后台与群聊协议各自单独保存。自然交流强调理解当前反馈、自己的判断及有依据的表达，不规定固定句式、汇报次数或打字节奏，不靠编造经历表演真人。

实际进程验收覆盖显式文本和表情、连续补充、等待、取消、过期决定、部分失败、静默结束、提醒跨重启、群聊三态及真实 Node 发送入口。Rust 覆盖来源精确认领、并发、格式校验、容量与恢复；监督器测试覆盖新的升级门禁。替身证明机制，不能证明用户对语气的满意程度。真实配置模型另做六轮隔离对话，验证显式发送、两次要求沉默、已发送历史与重启不补发；平台出口用本地替身，不向生产聊天发送测试内容。
