# 普通朋友空闲私聊与恢复

普通闲聊复用 `eve.outreach` 的撰写、预算、投递、回应识别和 `/outreach` 开关，不创建虚假的认知目标或实践记录。`Invitation.origin` 默认为 `Goal`，兼容旧记录；`IdleChat` 保存真实私聊的 session_id、证据 ID 和时间。闲聊的 `goal_id` 仅作 `chat-` 命名空间中的去重键，不代表 Cognition 目标；`milestone` 为 null。学习目标关闭检查只处理 Goal。闲聊收到新对话、达到最长间隔或配置关闭时取消尚未发送的邀请。

默认空闲 6 小时至不足 30 天；只看通道核验的私聊，最多 64 个近期作用域，每 60 秒扫描一次。学习候选优先，没有学习候选才扫描闲聊。只有存在真实、已完成私聊记忆才有候选。facts 仅含可核对的时间间隔，不推测近况或情绪。`runtime.idle_chat.after_ms` 可热修改，0 关闭，默认 21600000；没有另外绕过 affordable 的模型调用。

quiet/off、连续负反馈、已有在途邀请、对方尚未回复上次邀请、冷却和平台回执仍生效。普通用户可操作自己会话的 `/outreach off|on`。普通朋友的主动发送仅接受本组件已领取的 IdleChat 账本凭据及真实私聊路由，ID 前缀不能授权；不开放其他管理消息。用户已经回来时不会把闲聊附在回复后。失败与未知不主动重发；重启复用已有账本的 Interrupted/Unknown 规则。

旧邀请缺省 origin 为 Goal，已有 milestone 的 JSON 结构不变。新闲聊来源不能被旧二进制识别；降级必须使用部署前的成套备份或先明确迁移新记录，不能静默删除记录。所有原始私聊、摘要和平台回执保留。

验收使用本地模型、fake QQ bridge、真实文件状态库和测试数据库，不能替代正式 QQ 配额验证；不会为了验收向真实用户发消息。
