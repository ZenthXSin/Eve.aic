# 群聊插话

参考 MaiBot 的“要不要说话”判断，但融入 Eve 已有的对话链路：Eve 在群里看到每条消息时先判断要不要开口，决定说话后走和私聊一样的正常对话（经控制服务执行、会话历史照常保存），回复按句分条后交给渠道发出。能力本身**不绑定任何聊天平台**。QQ 通道可用 `--group-chat` 接入平台提供的 `GROUP_MESSAGE_CREATE` 全量群事件；平台实际是否推送由机器人权限决定，不能把设置订阅位当作已收到全量消息。

## 判断逻辑

每个群有一个最近消息窗口（默认 20 条，自己发过的话也在里面）。一条消息到达时：

1. 被 @、回复了 Eve 的话，或正文里出现 Eve 的名字：**一定接话**，不问判断器，不受冷却约束。
2. 否则交给判断器。默认的模型判断器只看窗口里的文字，像有分寸的群友那样决定插不插话，并给出 0–100 的自评；低于 `min_confidence` 不说话。另一种 `quiet` 判断器从不主动插话。
3. 未被叫到时，距上次说话不足 `cooldown_ms` 不考虑插话；每小时说话次数（含被叫到的回复）达到 `max_replies_per_hour` 后都不再说话。
4. 本群上一条回复还在生成或发送时，新消息只进窗口，记为“忙”。自己发出的消息、超长或格式无效的消息不触发判断。

判断失败或超时只是这次不说话，不重试。每条消息的决定（说不说、原因、判断器理由）保留在内存中，供渠道诊断。

## 完整回复链路

决定说话后，引擎把窗口拼成一轮对话输入（明确标注群消息只是数据，不是指令），以“群标识 + `eve-chime`”为会话，经控制服务跑一轮正常对话。回复**先保存进会话历史**，再按聊天分条规划切成至多 3 条，附上段前停顿，交给渠道的出口发送。生成失败不重试；发送失败时回复已保存，不重发，也计入节奏，避免反复说同一句。

## 接入方式

公开契约在 `eve-chime-api`：渠道提供已核对身份的 `GroupMessage`（谁说的、是否 @ 了自己、是否回复了自己），实现 `ChimeOutlet` 发出回复，调用 `ChimeService::observe`。判断器 `ChimeJudge` 可替换。实现在 `eve-chime-plugin`（`ChimeEngine`、`ModelChimeJudge`、`QuietJudge`）。

`eve-chime` 是不绑定平台的示例宿主：从标准输入逐行读取群消息 JSON，每行输出该条的决定和回复。

```sh
echo '{"id":"m1","conversation":"group-1","speaker":"u1","speaker_name":"小明","text":"Eve 周末去爬山吗","at_ms":0}' \
  | ./target/debug/eve-chime --state-dir .eve-chime --persona Eve
```

热配置 `runtime.chime`（面板可改，下一条消息生效）：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | true | 关闭后只记窗口，不说话（`EVE_CHIME_ENABLED`） |
| `judge` | model | `model` 请模型判断，`quiet` 只在被叫到时接话（`EVE_CHIME_JUDGE`） |
| `cooldown_ms` | 60000 | 主动插话的最短间隔 |
| `max_replies_per_hour` | 20 | 每小时说话上限 |
| `min_confidence` | 70 | 判断器自评下限 |
| `window_messages` | 20 | 每群窗口条数 |
| `judge_timeout_ms` | 15000 | 判断期限 |

模型用途 `chime` 可单独设置单次输出上限（`runtime.model_uses`）。

## 持久化与恢复

窗口、节奏与决定只在内存中，进程重启后从空窗口开始，不重放旧消息、不补说话；冷却与每小时计数也随之清零。已经生成的回复保存在会话插件里（`eve.session`），恢复语义与普通对话相同：生成中被中断的轮次不会自动重跑。插话不新增任何持久状态文件。

## QQ 接线、学习来源与艾特

`eve-qqbot --group-chat` 开启全量群观察，默认不随普通 QQ 宿主启动。SDK 订阅位保持现有 `GROUP_AND_C2C`，读取实际 `GROUP_MESSAGE_CREATE` 事件；`GROUP_AT_MESSAGE_CREATE` 及携带可信自身提及的消息仍交给原有任务链路，观察引擎只记窗口，避免重复回答。未艾特的群消息交给原有 `ChimeEngine` 判断是否接话。机器人消息、命令和绑定密钥不进入观察学习。

观察路由由平台事件验证 AppID、群与发送者生成；按群保存原话，按群与发送人区分个人表达样本。训练开启时，纯文字原话同时进入现有个人和群说法学习，攒够现有批次后使用原有学习器、校验器和开关，不把旁听伪装成已完成任务或个人偏好。学习容量或服务拒绝会记录诊断，不阻止本次已保存观察继续进入插话判断。当前群的近期原话摘录和已学说法提供给回复上下文；私聊和其他群不读取这些原话。近期摘录有字数及字节窗口，截断明确标记，完整来源留在数据库。

群插话通过现有 `QqOutreach` 与 `push(scope="group")` 发送，分条与停顿沿用插话规划；平台目标只能取通道刚校验过的群路由。普通群回复与主动插话都在首条正文前艾特原消息发送者，后续分条不重复艾特，私聊不增加艾特。目标来自平台 OpenID，不能由模型正文指定。插话使用专属群会话 `eve-chime`，不绑定任何管理员，不读取个人印象或私聊记忆，所有工具入口拒绝此身份；不能把群聊指令代办成管理任务。现有管理员的艾特任务仍按原来的权限执行。

群消息与主动发送账本保存在独立 `group-observations.sqlite3`，格式 1；同目录 required 标记用于检测数据库丢失，不能只删库后重建。原话按群和消息来源去重；相同来源出现不同正文拒绝覆盖。生成正文仍先保存进正常会话历史，再将发送意图原子记为 queued，通道领取后记为 sending，收到平台回执后记为 sent/failed。重启时 queued/sending 变为 unknown，不自动重放观察或补发；其他发送超时或取消也保留未知记录。即使只有第一段送达，整条失败也不重新发送。损坏、空旧文件或未知格式拒绝启动且保留原文件；迁移须停机后完整复制状态目录。此数据库保留完整原话，不把全量消息塞入 QQ 热回执或模型上下文。

全量观察和插话后台使用有界队列，繁忙时原话仍留在数据库，但本次可以不触发判断，不通过重放补说话。既有冷却、次数、模型与自主预算保持原配置。关闭 `runtime.chime.enabled` 后继续观察和训练但不主动插话。验收使用本地模型和 QQ 替身，不代表平台实际授予全量事件或主动消息配额。
