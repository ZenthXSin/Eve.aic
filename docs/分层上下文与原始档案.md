# 分层上下文与原始档案

QQ 宿主在现有历史窗口内选择完整轮次，原会话、原工具回执和任务检查点不因此删改。固定人格与本轮真实工具清单仍由运行时装配；200000 的既有总上下文上限及工具调用预算不变。工作集、当前输入和固定前缀均计入总预算，不是额外无限额度。

## 装载层次

QQ 还默认装配[可编辑工作便笺](./可编辑工作便笺.md)：当前用户在当前会话的工作状态可预览、CAS 修改及回退，下一轮注入，版本正文冷存。它是独立的低优先级参考，仍计入总预算，不替代本节的原始任务、原话与执行证据。

1. 当前任务工作集：只读取当前真实 session/user 的任务，优先活动且相关的一项。保存原目标、完整任务约束、当前状态、原截止时间、原预算和用量、下一步、未知调用 ID、最近回执类别及完整记录引用。模型报告的成果单独标为 reported_result，不当作真实交付证明。摘要超过 16 KiB 拒绝本轮，不截坏约束和检查点。近期原话仅在此处保存完整轮次引用和索引，不重复复制进工作集；它们仍由原始历史和独立审核通道保留。
2. 近期与相关历史：保持完整轮次和原顺序。近期两轮优先；最新完整轮次本身超过历史字节上限时明确拒绝本轮，原记录保留，不能静默略去刚发生的工具结果。早期相关轮次与其余近期轮次在既有窗口剩余容量内选择。独立保留最近六条审核原话；审核原话合计超 64 KiB 时拒绝，不能用摘要替授权。当前轮和 pending 执行记录不能被剪坏。
3. 长期经验：按现有 scope、可信 principal 和公开产物契约自动召回相关经验。模型只保存原 scope 草稿，不能自行把私聊提升为个人共享或公共知识。跨会话个人经验仍需宿主验证身份及明确分享意图。更正保留旧版，撤销、归档和到期停止自动召回；原文和证据引用保留。可选 expires_at_ms 由宿主设定，旧记录缺字段按无期限读取，模型更正不能刷新期限。
4. 原始档案：read_context_record 可搜索和分页读取当前真实 scope 的历史以及任务记录。完整工具回执仍在原始记录中；每页最多 8192 UTF-8 字节，返回引用、总长度和下一偏移。不接受模型指定其他用户或会话，不提供重放或新授权。

任务摘要中的 success_receipt 只描述已记录的工具结果；Unknown 不会因被摘要或被召回而变成可重放。相同 principal 的其他窗口不会自动取得原 scope 的私聊档案。

## Jev 与确定性回退

复用现有 Jev 客户端、配置、并发槽和协议，不新增外部存储服务。宿主先完成 scope 过滤，再提供至多 24 个不含路由身份的候选，每项最多 2 KiB，问题最多 4 KiB。Jev 只建议至多八个 opaque ID，不能改变身份、可见范围、预算或授权。

候选摘录直接构造预算内的 UTF-8 前缀，不先把整轮大文本连接为另一个完整字符串；空段、无正文消息、换行分隔和中文截断与原结果相同。原始完整历史仍供指纹核验和原文读取，候选的有界临时分配不代表完整历史已经按需装载。

每次计划至多一次 Jev 调用，三秒外层超时；并发槽忙、超时、HTTP 或协议失败、伪造 ID 均回退到确定性相关词与近期顺序。缓存最多 32 项、五分钟，绑定 scope、原始历史 revision 内容、候选和任务工作集；原记录修正立即失效。取消由运行时传播，不能在后台继续等待建议。

内部群主动观察上下文旁路该个人历史规划器，仍使用当前真实锚点和最近 20 条既定输入。没有重新开启用户关闭的 Jev 群消息筛选或主动回复。

选择后的历史不复用原全历史的 covered_turns 摘要缓存；需要压缩时使用临时、无持久 scope 的压缩，避免子序列偏移错套。后台持久摘要仍可维护原全历史中连续省略的前缀，但不纳入选择后的请求；中间空洞不能拼接为另一份前缀。原 journal 和 checkpoint 不改写。

## 可复验边界

`eve-app` 的 layered_context 测试实测原始历史 20/40/60/80/100 轮分别为 232988/465768/698548/931328/1164109 字节，选中完整轮次为 58417/58417/58417/58417/58418 字节。运行时 history_planner 测试另覆盖 100/300/1000 轮完整工具回执，实际请求为 28544/28551/28551 字节。这些是序列化请求/记录字节量，不宣称为提供商计费 tokenizer 的精确 token。

实际 SessionLlmHost 测试通过工具保存 A 窗口经验；未分享时 B 无法使用，明确个人分享并重启文件账本后，B 调用本地工具核验真实产物。陌生身份、同名冒充、其他群或私聊、无关请求、更正、撤销及过期经验均不能驱动该产物验证。测试使用确定性模型响应和真实宿主/插件/文件工具，不以模型自述作为通过依据；它不证明真实 Jev 的语义质量。

Jev HTTP 测试覆盖有效回复、损坏协议和服务失败。坏选择、缓存失效、原文精确召回、跨 scope 拒绝、任务期限与检查点保持另有单测。真实外部模型与长期多窗口运行仍需独立进程验收；这些测试不代表已部署或已完成全部代码审查。


## QQ进程长程集成验收

新增 layered_context_test.py 使用真实QQ宿主进程、确定性本地模型/平台，连续完成76轮并在中间重启。保持产品原有200000自适应上限，72条约5KiB输入的请求messages在16/32/48/64/72轮为130613/133113/133111/133120/133120个UTF-8字节。后台按原配置维护了14次连续前缀摘要，覆盖轮次按4/8/12递增至56；摘要请求无工具，原轮次编号连续。没有主动上下文压缩事件，不靠每轮重压缩限制请求大小。早期相关口令在工具检索前被选回，随后search→read取得完整原文；异scope不能按同一引用读取，重启后原文SHA256一致，原会话75条轮次仍完整保存。数字为字节量，不是提供商计费token，也不是新的真实外部模型验收。

该实际进程测试先发现并复现了一个工作集错误：把最近六条原话完整重复复制到16KiB任务工作集后，正常长输入在第5轮超限。修复只将这份重复原文改为历史索引与引用；完整近期轮次、独立审核六条原文、原始档案及真正任务约束均保留，16KiB/64KiB上限没有扩大。原失败与修后通过日志分别保留。

后续CI还发现最新整轮过大时曾被静默省略，以及分层旁路了后台摘要维护。修复后恢复最近整轮超窗拒绝；150k主动压缩、压缩HTTP 403、超时、重启安全重算、后台摘要生成/热关闭/坏文件保留均通过实际进程回归。主动压缩和后台原前缀维护分别验收，不把后台摘要请求冒充主动压缩。
