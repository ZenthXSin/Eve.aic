# 兴趣观察归档与恢复

本页说明兴趣观察账本的归档格式、读取边界和故障恢复。它不改变观察器的判断规则，也不把观察完成、兴趣产生、学习目标推进和正式知识入库视为同一件事。现有观察配置与取消语义见[兴趣观察](./兴趣观察.md)。本页描述源码行为，不作为测试通过或线上启用证明。

## 装配与格式

定义层 `eve-interest-api` 提供 `InterestJobArchiveStore`、历史分页和容量统计契约；实现层 `eve-interest-plugin` 保存根索引，并通过可替换归档保存不可变原件；组合层 `eve-app` 为 QQ 兴趣插件装配状态目录下的 `interest-job-archive`。QQ 承载的 Web 页面复用同一控制器，不额外建库。独立 Web 宿主的其他兴趣系统不由本改动迁移。

只构造 `InterestPlugin::new()` 而未装配归档的宿主继续使用格式 1，保留原有 128 批次上限。内置 QQ 装配归档后，启动时先完整验证现有状态，再迁移格式 1：按原批次顺序分配从 1 开始的全局连续序号，保全输入、记忆修订、状态、输出和应用结果；未完成的 `Running` 转为 `Interrupted`，不伪造结束时间。终态原件持久保存后才提交格式 2 根索引，完成后才公开控制器。

格式 2 的根索引保留当前 `Running` 正文、全部终态引用和兴趣记录。`Completed`、`Failed`、`Interrupted` 都进入归档；空更新的 `Completed` 也保留。原件为带格式版本的 JSON 封装，文件名来自完整原始字节的 SHA256。归档不裁剪历史，也不要求失败或没有产生兴趣的批次重新执行。

没有根状态时，归档必须通过 `is_empty()` 证明没有历史，才能初始化新库。已知锁文件可排除；未引用原件、提交未知的临时文件或其他未知内容不能当作空库。替换实现若不能可靠证明为空，默认返回不可用。有归档而根丢失时保留现场并拒绝启动，不能新建空索引重新消费旧交流。

## 消费、读取与并发

每条终态引用记录序号、完整作用域、批次状态和时间、记忆修订、原件摘要与大小，以及每份已消费证据的 ID、修订和完整内容摘要。摘要包含时间戳，不能仅凭 ID 相同放过被改写的证据。读取原件核对大小、摘要、严格 JSON、封装版本与完整引用，并检查来源及兴趣关联。

准入检查先使用打开或上次提交时已核实的消费索引，拒绝记忆修订回退、已消费来源缺失、来源改写或重复消费。没有足够新输入或尚在冷却时返回 `None`，不重读兴趣归档冷正文；准备保存新 `Running` 时仍完整核验已有冷历史，核验与持久化成功后才返回批次并允许请求模型。分页记忆入口使用固定版本读取器，即使本批已满或尚在冷却，也继续核完剩余来源页再决定是否提交。失败、超时、取消、空结果和中断的输入始终已消费。重复提交相同的已保存结局只返回原结果，不再写入；不同结局不能覆盖历史，中断记录也不能补成成功。

普通 `snapshot(scope)` 只返回该完整作用域的兴趣、热批次及归档数量，不恢复冷正文。不能再用 `jobs.len()` 判断全部观察次数。`jobs_page(scope, after_sequence, limit)` 按持久序号合并热冷历史，每页 1–20 条，从 `after_sequence=0` 开始；只读取本页选中的原件。`next_after` 为后续读取位置，为空只表示本次读取时没有更多记录。

分页不是跨多次调用的冻结快照：其间新增批次可能出现在后续页，已返回的热批次也可能随后完成；归档移动不改变序号。每次操作由账本锁串行化，原始记忆则由其固定版本游标核验。文件归档持有目录锁，内置实现拒绝另一个归档实例同时打开同目录；同一实例的配额检查与写入在同一操作锁内。替换存储和宿主仍须保证同一根账本只有一个有效写入者，不能把这个接口当作分布式多主事务。

历史页只交给可信宿主，并按完整作用域过滤，不自动进入模型上下文，不扩大个人资料投影或跨会话原文访问范围。

## 容量与资源

| 限制 | 当前含义 |
| --- | --- |
| 热批次 128 条 | 格式 2 仅保留运行中批次；格式 1 仍是全部批次总上限 |
| 热批次与终态引用合计 4096 条 | 达到后拒绝新观察，不删除旧记录 |
| 根状态 4 MiB | 含兴趣和消费索引，并为已准入批次的基本中断或失败收尾保留索引差额 |
| 单条归档原件 128 KiB | 超过就拒写，不截断原件 |
| 文件归档 8192 个文件、512 MiB 声明长度 | 锁、原件、未引用文件和临时文件都计入；不预支未来清理空间 |
| 单次来源核验 262144 条证据 | 在读取来源正文前限制唯一性元数据规模，超限不准入 |
| 兴趣 64 条、陈述 16 条、推断 8 条 | 原限制保留；普通陈述留出最后一个撤回位置 |

这些上限可能分别先到达，不保证一定容纳 4096 个批次。根索引的收尾余量不保证任意模型兴趣更新都能保存，更不能预留物理磁盘。文件系统剩余空间、inode、其他进程写入及存储故障仍会令写入失败；即使 `Running` 已保存，终态冷文件也可能无法落盘，此时保留已消费输入并停止当前实例。

QQ 在新批次准入返回 `LimitReached` 后等待至少 60 秒再检查，继续遵守启用状态、取消和预算门槛；这只是重新判断新观察能否准入，不重试已消费批次，也不自动腾空历史。若容量问题发生在冷文件写入，实例已经关闭，低频检查不会自动修复它。

`archive_status()` 供可信宿主查看热批次数、已引用归档数、已引用正文长度和根索引长度。这不是物理目录占用统计，不包含孤儿文件，也不证明还有空间或已经生成知识。未实现统计的替换服务默认 `enabled=false`，其余零值不能当作已核实结果。`capacity_check=completed` 也只表示一次准入检查没有报错，可能没有可观察的新输入。

冷正文不长期驻留。空闲或冷却检查返回 `None` 时不读取兴趣归档冷正文，但仍核验原始记忆来源；原始记忆自身的冷读不在此优化范围。`None` 和普通快照只依据上次核实的兴趣索引，不证明冷库此刻仍完好。启动及实际保存新批次、收尾或其他变更时，仍有线性冷 I/O：会逐条核验全部引用，兴趣陈述与推断的来源校验还可能再次读取相关原件；冷历史损坏会在新批次提交及模型请求之前阻断并关闭实例。每次新文件写入也扫描物理目录计算配额。普通快照无兴趣冷 I/O，历史页只恢复选中正文；这些改进不等于常数时间、固定峰值内存或无限容量。索引和来源唯一性元数据仍随历史增长。

## 提交、故障与停止

内置 Linux 文件实现拒绝路径链接、非普通文件、额外硬链接以及运行中目录或锁文件被替换。写入先检查配额，创建唯一临时文件并同步，再以禁止覆盖的原子重命名发布原件，复核内容并同步目录。同摘要已存在时只验证一致性，绝不覆盖；未知目录内容不递归清理。

冷原件先于根索引提交，二者不是跨后端事务。任何冷写错误，或根状态提交失败而结果无法确认，都会关闭当前账本实例，后续读写返回不可用，不能继续使用旧缓存覆盖实际后端。坏引用、缺块、未知格式也不被跳过或自动修复。根索引未提交时旧根仍是恢复依据；冷目录可能留下唯一原件或临时文件，错误路径不删除它们。

恢复时重新读取真实根并核验全部引用：若已保存终态，采用原结局；若仍为 `Running`，持久保存 `Interrupted` 后才公开；若原件或根仍损坏，继续拒绝启动并保留字节。此过程没有模型请求，不重放观察，也不依据无引用文件猜测一次未知结果已经成功。

关闭观察会停止新准入，在途请求按既有取消语义收尾；远端计算是否停止仍可能未知。归档不会给后台重新领取预算，不会把暂停、撤回或取消改成继续执行。

## 备份与回退

迁移前保留匹配的程序版本、完整插件状态和原始记忆备份。迁移保全批次语义，但会提交新的根状态；不要将它理解为自动另存了一份格式 1 根文件原字节。

迁移后的备份必须同时包含插件状态、原始记忆及其归档、整个 `interest-job-archive` 目录，以及相关兴趣配置与认知状态。PostgreSQL 根状态也依赖这个文件目录，仅备份数据库不足以恢复。为取得一致副本，应在宿主停止写入后通过既有备份流程保存；不能将任意时刻分别复制的根与冷目录视为同一快照，也不能假定旧升级检查已经涵盖新增目录。

旧程序或未装配归档的实现不能直接读取格式 2。回退应先保留迁移后的完整现场，再使用匹配程序与一致备份；不得手改格式版本、删除归档字段、清空消费索引或删原件来绕过。回到旧时间点也不自动授权重放已经执行的操作，需保留并核对该时间点之后的实际记录。

本功能没有垃圾回收或自动清理接口。未引用文件也可能是未知提交留下的唯一证据，不属于构建缓存。若必须回收，先核对真实根、全部引用、完整可验证备份与已有副作用，再通过单独确认的恢复方案处理；不能为恢复观察容量直接删历史。
