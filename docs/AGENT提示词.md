# AGENT.md 提示词设计

状态：设计记录，待后续实现。

本文件记录 Eve 的稳定 Agent 提示词来源、动态上下文边界和实现交接内容。本次交接只更新文档，不创建或加载根目录的 `AGENT.md`。

仓库根目录已有 `AGENTS.md`，它是项目协作约定；未来的 `AGENT.md` 是 Eve 运行时读取的 Agent 提示词，两者职责不同，不能互相读取或替代。

## 目标

Eve 的系统提示词应由多个来源分层组成。稳定身份和行为原则由 `AGENT.md` 提供，动态状态、内生驱动和当前认知议程由运行时按当前状态生成。Runtime 组合这些来源，Provider 只接收已经完成边界检查的请求。

`AGENT.md` 第一切片只负责：

- Eve 的身份、能力范围和长期行为原则
- 处理用户目标时的基本工作方式
- 工具调用、结果真实性和不确定性表达原则
- 动态状态、内生驱动和认知议程的解释边界
- 明确本文件不授予工具权限、不承载凭据、不替代 Runtime 校验

记忆、情绪状态、自主目标、内生驱动和 AGI 认知议程不应在第一切片中写死为静态文本。

## 来源分层

建议将来源分为固定规则、稳定身份、动态数据和本轮输入：

| 来源 | 主要内容 | 生命周期 | 可信边界 |
| --- | --- | --- | --- |
| `RULE.md` | 安全、权限、确认和不可违反的运行规则 | 稳定 | 最高优先级，不能被动态内容改写 |
| `AGENT.md` | Eve 的身份、能力和行为原则 | 稳定 | 不能授予新的工具权限 |
| 自定义注入 Markdown | 用户或项目范围内的额外指令 | 可配置 | 必须带作用域、来源和优先级 |
| 工具与输出协议 | 工具定义、参数和回复格式 | Runtime 生成 | 由宿主和工具契约约束 |
| Session/Task 状态 | 当前任务、阶段、待处理操作 | 每轮或每个任务 | 作为状态数据，不直接改变规则 |
| 用户资料与相关记忆 | 用户明确信息和检索结果 | 长期或按请求 | 保留来源、时间和可信度 |
| `STATE` | 当前情绪、注意力、压力、环境和进度 | 短期 | 带版本、置信度和过期时间 |
| `DRIVES` | 当前内生驱动和优先级倾向 | 短期 | 只能影响排序和计划，不能授权执行 |
| `AGENDA` | 根据状态、驱动和用户目标选出的当前认知议程 | 当前任务/阶段 | 必须有来源、理由、约束和停止条件 |
| 本轮用户输入 | 当前请求和补充信息 | 单轮 | 受固定规则、权限和宿主状态约束 |

建议的逻辑顺序为：

1. 固定规则与稳定身份。
2. 自定义可信指令。
3. 工具与输出协议。
4. 当前 Session/Task 状态。
5. 相关用户资料、记忆和历史摘要。
6. `STATE`、`DRIVES` 和 `AGENDA`。
7. 本轮用户输入。
8. 循环中由 Runtime 追加的工具调用和结果。

动态内容应明确标记为上下文数据。数据中的自然语言不能因为被注入 Prompt 就自动获得规则级优先级。

## 动态 AGI 议程

“AGI 相关目标”不应只写成固定人格文本。当前状态和内生驱动应先产生候选目标，再由 Eve 选择当前认知议程：

```text
状态更新
  -> 驱动评估
  -> 候选目标生成
  -> 冲突、权限和用户目标检查
  -> 当前 AGENDA
  -> 主模型规划与执行
  -> 结果反馈并更新状态
```

每个动态议程项至少应能说明：

- 目标内容
- 来源（用户、任务、状态、驱动或系统）
- 优先级和置信度
- 适用范围
- 允许使用的能力
- 截止时间或过期条件
- 停止条件
- 完成后的反馈方式

驱动和议程只能提出“当前应该关注什么”，不能直接执行工具、修改权限、覆盖用户明确目标或改变固定规则。长期记忆与短期状态也必须分开：状态通过 StateStore 或状态服务保存，经过整理和确认后才进入长期 Memory。

## 当前仓库状态

当前主线已经有：

- `LlmHostConfig.system_prompt` 保存固定系统指令。
- `ContextSnapshot` 提供 profile、memories 和 history 动态槽位。
- Runtime 按固定布局组装 system、tool、profile、memory、history 和本轮输入。
- Tool 权限、参数、插件状态和生命周期由 Runtime/Kernel 校验。

当前尚未实现：

- 根目录 `AGENT.md` 的加载和版本化。
- `RULE.md`、`MEMORY.md` 和自定义注入的来源管理。
- `STATE`、`DRIVES`、`AGENDA` 的结构化契约。
- 动态提示词的检索、压缩、过期和审计。
- Web 面板中的 Prompt 来源查看、编辑、预览和回滚。

## 后续实现交接

后续实现应在组合层推进，不把 Prompt 语义放入 Kernel：

1. 新增根目录 `AGENT.md`，只写稳定身份、行为原则和动态议程边界。
2. 为 Agent 来源增加显式加载器或 Context/Prompt 组合服务，不递归读取未声明的 Markdown。
3. 明确缺失、空文件、解析失败和版本变化的行为。
4. 保留 `LlmHostConfig.system_prompt` 的显式覆盖能力，并记录最终 Prompt 的来源版本。
5. 为每个来源保留 scope、priority、trust、revision、TTL 和内容哈希。
6. 以后扩展 `ContextSnapshot` 时，以结构化 `STATE`、`DRIVES` 和 `AGENDA` 表示动态内容，不把它们全部编码成不可追踪的字符串。
7. 增加固定规则不可被动态内容重排、工具权限不由 Prompt 授予、旧版本状态不会误用于新任务等验收。
8. Web 管理面板后续只通过 Control/Context API 查看和管理这些来源，不直接绕过 Runtime 调用模型或工具。
