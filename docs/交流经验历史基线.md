# 交流经验历史基线

交流学习可以修订当前经验，也可以重新审视因容量限制而移出当前集合的旧经验。修订会完整替换经验文字，因此新建批次展示可修订历史时，必须同时提供同范围、同 ID 的最新版本。仅提供旧版本，不能让模型了解最新版已增加的适用条件。

## 取批与分页

最新版本由持久存储的 `latest_revision(scope, lesson_id)` 决定，以范围内版本序号为准，不依据更新时间，也不把历史页中最后一条当作最新版本。

新批次的经验部分按以下顺序构造：

1. 当前集合非空时，先放入当前轮转位置的一条完整经验。
2. 读取最多四条历史。真正旧版本与对应最新基线作为一组试放；同 ID 最新基线已有完整副本时不重复加入。与当前经验完整相同的历史延后确认，不占用当前轮转的预算。
3. 按原轮转顺序补充其余当前经验。已因历史配套提前加入的当前条目视为走过该位置，不重复添加。

批次仍最多包含 24 条 `lessons` 和四条 `lesson_history`，最终请求 JSON 仍不超过 65,536 字节。当前经验试放继续使用 49,152 字节阈值，历史与配套基线使用 57,344 字节阈值，为后续消息保留原有预算。每次判断使用实际 JSON 编码长度，包含转义带来的扩张。

一组历史与最新基线因条数或字节预算放不下时，两者的新增部分一起撤回；该历史游标不前进。下一批先保留新的当前轮转头，再尝试这组历史，避免当前集合占满 24 个位置而让归档经验一直无法参与。当前游标按连续走过的当前条目数推进，不能按批次 `lessons` 总数推进，因为其中可能包含归档条目和提前加入的后续当前条目。

正常补齐当前经验后，才确认延后的等价历史是否已随当前基线完整展示。历史游标只推进连续已展示或已明确重置的前缀，遇到尚未展示的等价历史就停下；不能仅因当前集合保存了它而跳过。排在其后的真正旧版本可能本批已展示，但游标不会越过前项，因此后续批次仍可重访它。归档基线即使与历史文字相同，也保留同 ID 的历史原件，用于检查点恢复时核验其来源。

这些分页安排保证经验两侧持续获得展示机会。后续原消息及其 metadata 的容纳、分片仍由原有逻辑决定，不额外承诺所有最大 metadata 都能放进预留空间。

## 来源校验与重置

批次中的最新基线只用于模型输入。只读取批不把容量归档条目写回当前经验，不改变支持数、活跃状态或前台经验投影。模型提交合法修订时，才沿用原提交路径恢复或更新经验、维护容量与归档版本。

恢复固定批次时，先逐条核对历史是否仍等于同范围的持久原件，且历史序号必须位于当前重置边界之后。随后核验 `lessons`：

- 当前集合有同 ID 时，必须与当前条目完整相等，包括文字、计数、状态及证据。
- 当前集合没有该 ID 时，必须有本批已核验的同 ID 历史来源；基线还必须完整等于同范围 authoritative latest，且其序号位于重置边界之后、原因不是 `reset`。
- 不能把任意真实旧版本伪装成最新基线；同 ID 当前版本不一致时，也不能借归档规则绕过检查。

新取批发现某条历史的最新版本明确为 `reset` 时，该经验已经不可修订，只推进历史游标跳过，不展示或恢复它。正常范围重置会同步推进历史下界，使此前历史不再参与新取批。最新版本缺失、来源不一致或越过重置边界都属于状态错误，保留原记录；不能当作空页或普通容量淘汰跳过。

## 固定批次与旧记录兼容

本调整不改变 schema 或数据库协议。新取批保证可修订历史配套最新基线，但不追溯改写部署前已经冻结的批次：原格式可能只含历史而没有配套基线，无法在无版本标记的情况下与新批次删字段区分。

旧固定批次继续使用原始消息、经验及历史内容；明确失败后的重试沿用原内容，仅按原规则推进尝试次数。没有明确失败记录的在途请求在重启后仍按未知结果结算，不自动重放。新批次中的归档基线通过上述来源校验后，同样遵守这些冻结和恢复规则。单纯增加新消息不会重新选择已冻结批次的经验版本。

本修复保证模型能看到被完整替换的最新内容，不自动合并模型草稿，也不能保证模型保留全部语义条件。它不处理首次归纳保真或聊天表达自然度；这些效果需要另外对照实际模型输出。

## 验证状态

2026-11-10，本地 93 项不重复相关测试全部通过：training-plugin 40 项、固定批次完整性 4 项、conversation_flow 40 项、conversation_storage 5 项、storage 4 项。三项新增回归先在旧实现上实际失败；新测试还覆盖归档只读展示与恢复、旧证据不重复计数、冻结重试、伪造基线拒绝、范围隔离及新旧重置来源。

原有大原文分片期间展示全部 24 条当前经验的回归保持原断言，并已通过。等价当前历史延后确认，不挤占正常轮转预算。最终格式、差异检查与严格 Clippy 均通过。这些验证未调用真实模型，也未部署生产。
