# 持续意识流与休息、提醒

这批实现让新基座从演示用的有限轮次进入可持续运行的单一意识流。它不是旧 Eve
的恢复，也没有导入旧聊天或旧记忆。

## 当前行为

- `eve` 是插件。启用只恢复状态，宿主显式调用 `eve.start`
  才运行；普通插件启动或健康探测不会消耗模型请求。
- 意识流与脚本账本启动默认允许五分钟恢复长历史，可分别通过 `eve.startupTimeoutMs`、`scripts.startupTimeoutMs` 调整；配置只接受有效的正整数计时期限。
- 一个脑子处理全部来源。手机通知、脚本完成、异步命令实际终止和自己的提醒在当前工具批次结束后进入同一条经历，不打断正在等待的模型或动作。
- 每次模型响应先存盘，再执行其中的脚本。上游重复使用工具短编号时，以持久响应序号生成执行编号，避免把两个不同决定误当成同一动作。
- 重启时先核对未结束的决定。已经有脚本任务的采用原任务回执，不重新发送；模型请求结果不明时保留未知费用和恢复记录，不凭猜测补出成功结果。
- 普通模型文字留在意识流；对外消息必须由真实手机动作产生。没有固定开场、固定分条、强制进度汇报或自动转发模型文字。
- Eve
  可以通过脚本选择休息、预约时间提醒、取消提醒、提出自写摘要及结果保留方式。控制动作先持久保存，随后应用到意识流；拒绝的请求也能在
  `mind.status` 的近期应用结果中看到。
- 默认没有继续动作时长时间休息。新手机通知和到期提醒可以唤醒；已经作为同步工具结果观察过的完成通知只推进游标，不再次唤醒。
- 模型失败保留原消息，采用有上限的退避。依赖失败与恢复单独留证据，恢复事件不撤销刚决定的休息。

接口由 `contracts/mind.ts`、`contracts/script.ts` 定义，并进入提示词生成与 Deno
脚本检查的同一份类型说明。`mind` 的控制队列与 `eve`
分开，因此脚本可以提交请求而无需反向依赖正在等待脚本的 Eve。

## 存储与视图

意识流每个事件一个文件，包含连续序号、前件摘要和自身摘要。写入使用临时文件、文件同步、重命名及目录同步。恢复遇到未知临时文件、损坏或断链时保留现场并拒绝启用。目录锁防止两个实例同时写同一个目录；这不是跨目录的全局在线所有权令牌。

换版的提醒与脚本账本交接由两个隔离进程完成：旧实例 UID 导出，候选 UID 导入，监督器只传送有界数据管道。完整文件清单与逐文件摘要核验后才接入候选；脚本 v2 的内容对象、提交事件和旧迁移原件一并保留，不复制写锁，不因交接重放未知动作。同编号可以在传输中断后补齐，候选已有不同事实时拒绝覆盖。导入成功删除本轮暂存副本。

候选回滚后，意识流视图排除候选范围内的决定、摘要与工具挂起状态，但保留原始事件；实际已经发生的外部动作不会被宣称撤销。候选形成的记忆和强化不参与默认回忆，笔记默认读取恢复已接受版本；显式版本查询仍可查看带隔离标记的候选原件。

请求布局为固定身份和契约、保留时间线、追加的对话与动作流。身份只在组装时生成，时间、用量和新通知追加到末尾。真实原件不会随压缩或结果保留选择而删除。

275k 只提醒。默认使用公开的字符估算（图像另作明确的未校验估算），到 500k
触线时，机械移出最早的完整消息或工具批次，标明由系统压缩并指向原件；单个超大片段也可以整体移出。固定身份和契约仍然超线时停止请求，不删身份凑数。最终请求再次检查，包含工具说明及新感知。

**当前估算不是指定模型的精确分词器。** 500k
行为已在估算口径下验证，尚未完成精确分词及实际模型窗口验收。`ContextCounter`
可替换计数实现并公开其说明，当前没有把其它编码器冒充指定模型的分词器。已有摘要被机械替换时，其原始事件仍在硬盘。

`retain(omit)`
会同时移出指定工具调用及其回执，只留一句清除痕迹；同一批其它调用仍配对，原件不变，后续 `raw`
可以恢复视图。`phone.image` 默认先用同一个模型作独立客观描述，描述不使用 Eve
身份或意识流，费用记共享预算；主意识只追加描述文本、来源和可能误判的说明。Eve 可以明确选
`mode:"original"`，这时真实原图在工具批次全部配对后作为独立的 `user.images`
输入。描述失败不会擅自改用原图。两种路径的文字视图均不重复灌入
base64；超过原图传输容量时明确标记移出的旧图像。

守护写入的 `upgrade_rollback`
事实指明未确认候选记录区间。当前视图、未完成决定及恢复游标排除该区间，追加回滚标记；原始记录和已发生的外部动作回执保留，预算也仍计入真实花费。活动记录视图只缓存数字索引，不将回滚区间之外的正文复制成第二份常驻数组。

## 预算

每日只计非缓存输入及输出。完整、有效的上游用量可核算实际成本；缓存字段缺失不写成零。输出已知而缓存未知时，输出计入已知成本，输入保留为未知成本上界；全部用量缺失或请求中断时保留请求预留。请求前检查安全余量，不足便停止模型请求。默认按
Asia/Shanghai 日期核算，可在配置中显式设置有效时区。

独立运行出口统一核算在线意识流、观察换版与试聊的请求；远端意识流在每次轮询时刷新共享预算，即使休息或暂停，也能看到主人动态调整的额度、时区和已知/未知花费。请求前的最终仲裁仍在出口，实例自己的估算不能覆盖共享账本。这些测试证明核算和阻止请求的路径，不证明中转站实际缓存提升。

## 身份与 QQ

固定身份参考用户仓库的历史身份资料，仅沿用 Eve.aic、基金会
AIC、关系和自然交流方向；旧记忆、旧执行流程及旧工具声明没有迁移。QQ 提示词沿用本次基于
`Derpyu520/qq-bridge` 的交互研究，强调上下文、省略、真实手机动作及自主交流时机。

身份由平台事实及已确认配置提供；机器人 AppID
不能代替主人平台标识。主人绑定已通过私信挑战核验，进入会话的通知水位与实际展示范围已持久化，详细原件未冒充已读。上线测试继续限定私信；上线后由
Eve 给主人发一次通知的要求仍须真实发送并留平台回执才能验收。

## 验证口径与剩余工作

测试使用真实 Deno 插件、脚本工作线程、HTTP 模型协议、手机 RPC 和本地模拟 QQ
平台。它覆盖响应先保存、重启采用回执、当前步骤不被新消息打断、超过八次模型请求、持续休息与唤醒、提醒不重复、依赖恢复、预算及原件完整性。停止测试也要求清理过程没有错误；停止时拒绝新的宿主动作，依赖服务在上层收尾结束前仍可调用。

本批没有调用付费模型、接收真实 QQ 流量或发送真实 QQ 消息。协议通过不代表自然表达、蒸馏增益或 QQ
线上送达通过。

`mind.watch` 提供通用条件提醒：Eve 写 async 函数体，返回 boolean；系统在隔离 worker
中检查，不调用模型。`facts` 是共享预算等当前感知，`tools` 只提供
files.read/list/search、commands.poll、notes.get/list/search 和
records.page/text。检查失败或超过执行期限时保留原条件并在 `mind.status`
报错；条件和取消状态重启后保留，恢复时补查并标记迟到。条件不在模型等待或工具批次中途打断她。
