# QQ 交互参考与当前实现

主人要求手机交互、对应提示词和说话方式重点参考企划案中的
[Derpyu520/qq-bridge](https://github.com/Derpyu520/qq-bridge)。本批按源码核对后独立实现屏幕投影，
并接入交流原则；底层接入仍使用官方 QQ 机器人接口。

参考版本：`781e02f24e17004d3821c1b71501a442e07ed756`。源码定位：

- [二代交流与工具提示词](https://github.com/Derpyu520/qq-bridge/blob/781e02f24e17004d3821c1b71501a442e07ed756/dsh/agent-presets/qq-chat-v2/agent.cordis.yml)
- [消息投影](https://github.com/Derpyu520/qq-bridge/blob/781e02f24e17004d3821c1b71501a442e07ed756/src/qq-model-view.js)
- [浏览、已读、发送、引用、附件和唤醒接口](https://github.com/Derpyu520/qq-bridge/blob/781e02f24e17004d3821c1b71501a442e07ed756/src/mcp-snowluma-safe.js)
- [预设与人格的组织](https://github.com/Derpyu520/qq-bridge/blob/781e02f24e17004d3821c1b71501a442e07ed756/src/preset-prompt.js)

上游区分群聊参与方式和人格，并采用显式发送、消息水位、分批浏览与按需展开。当前许可证为 PolyForm
Noncommercial 1.0.0；本批没有复制它的实现或提示词正文。参考代码保留在本机证据目录， 不引入
SnowLuma、DSH 或 OneBot 运行依赖。

## 当前对照与落点

下列为当前源码能力，替代最初“仅屏幕候选、尚未接通”的阶段记录；真实生产收发、升级和恢复证据见整体验收记录。接口回归不等于交流自然性验收。

| 参考中的设计                     | Eve 当前实现                                                    | 定位与边界                                                                                                 |
| -------------------------------- | --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 最新、历史、搜索与按需展开       | 独立适配器经手机 RPC 提供有界分页，长文、附件按原句柄展开       | `adapters/qq/phone.ts`、`sdk/phone-view.ts`；历史游标绑定日志快照                                          |
| 本地 seq、平台编号和引用索引分开 | 手机句柄、platformMessageId、referenceIndex 独立保留            | `contracts/phone.ts`；引用索引不冒充平台消息编号                                                           |
| 不清掉后来到达的新通知           | open 先持久保存本机会话通知水位，返回实际 displayedSeqs         | 历史、搜索、通知预览不消除提醒；不是发给对方的平台已读回执                                                 |
| 压缩视图、原件不改               | Unicode 预览、长文本分页、附件卡片；原始事件留在独立日志        | `adapters/qq/journal.ts`；不把省略预览视为完整阅读                                                         |
| 时间和旧话题                     | 绝对时间与 age；缺失、非法、未来时间明确区分                    | `sdk/phone-view.ts`；不把未来时间夹成“刚刚”                                                                |
| 明确引用对象                     | 本消息引用索引以 referenceIndex 展示；引用关系以 reference 展示 | `reference.target` 只在同会话已有索引唯一匹配时提供，可用 phone.message 点开；缺失表示引用对象未知，不能猜 |
| 工具发送和真实回执               | 每个发送动作有持久编号与 sent/failed/unknown 回执               | 普通模型文字不自动转发；未知结果核对原动作，不重放                                                         |
| 看图再接话                       | 附件按原消息句柄下载；默认相同配置模型先描述再交给 Eve          | 可显式选择原图；失败不自动换路，两路计入共享预算                                                           |
| 自主交流与持续意识               | 稳定身份、交流原则和真实契约一起加载，通知追加到时间线          | `composition/eve.ts`；同一主体决定接话、行动、等待或休息                                                   |
| 分条、语感与经验                 | 支持独立发送动作；提示词指导完整意思、语境、反馈与选择性参与    | 机制已接通，不能据此宣称真人感或学习增益已通过验收                                                         |

引用增强只投影既有入站包装字段及真实发送回执，不重写旧入站原件、指纹、通知水位或时间线编号。
同会话内索引缺失、重复、只命中本消息或只在其他会话出现时，仍保留明确引用事实，不生成目标或正文。
手机每次快照一次线性建立引用索引，不对每一条消息重新扫描历史。合并转发展开、收藏表情、拍一拍与语音等上游能力不因本次参考自动存在；只能按当前契约和官方平台真实能力使用。

## 提示词的取舍

[qq-social.md](../prompts/qq-social.md) 已由 `composition/eve.ts`
与身份、当前类型契约一起生成模型提示词，由意识流启动加载。 它保留 Eve
的主体与身份，不把上游鲸鱼角色、无本地工具或独立会话人格移植过来。

参考重点是：理解眼前话题、关系与引用对象；有具体理由再开口；允许等待补充和选择性接话；
一条承载完整意思；结合本群语境与反馈学习交流节奏。不能靠固定开场、强制分条、预制催话或随机迟延获得“像人”的验收。

上游固定字数、沉睡观察时长、必回 @、轮次表情概率和跨会话模式限制属于自己的部署规则。 Eve
保留一个主体、自主判断和真实能力，不导入这些规定；也不编造“刚没看手机”解释送达或处理故障。
已发生的发送与事实依据实际回执，未看过的引用内容、图片与文件仍然未知。

## 自然交流验收

协议支持多条、模型实际选择多条，以及随真实交流阶段自然补充，是三个不同观察。
现有屏幕、RPC、日志和回执回归验证链路行为，不证明自然分条、经验学习增益或线上聊天体验改善。
自然性需结合未参与学习的多轮交互观察：短句省略、连续补充、多人引用、旧话题、群聊选择性参与、
闲聊与任务切换、暂时安静以及后续实际采用经验。不要为了通过观察预置固定台词、强制回应或定时催话。

2026-11-12 主人明确授权开放群聊。发送范围由 `qq.replyScope` 控制：缺省 `private`，
显式 `all` 开放群聊与私信；接收群消息和拥有群发送权限分别验收。旧 scope 失败不重放，
新群动作仍须取得平台真实回执；开放权限不等于绕过官方平台限制。
