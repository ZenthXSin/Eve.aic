# QQ 交互参考与当前实现

主人要求手机交互、对应提示词和说话方式重点参考企划案中的
[Derpyu520/qq-bridge](https://github.com/Derpyu520/qq-bridge)。本批按源码核对后独立实现屏幕投影，
并整理交流提示词候选；底层接入仍使用官方 QQ 机器人接口。

参考版本：`781e02f24e17004d3821c1b71501a442e07ed756`。源码定位：

- [二代交流与工具提示词](https://github.com/Derpyu520/qq-bridge/blob/781e02f24e17004d3821c1b71501a442e07ed756/dsh/agent-presets/qq-chat-v2/agent.cordis.yml)
- [消息投影](https://github.com/Derpyu520/qq-bridge/blob/781e02f24e17004d3821c1b71501a442e07ed756/src/qq-model-view.js)
- [浏览、已读、发送、引用、附件和唤醒接口](https://github.com/Derpyu520/qq-bridge/blob/781e02f24e17004d3821c1b71501a442e07ed756/src/mcp-snowluma-safe.js)
- [预设与人格的组织](https://github.com/Derpyu520/qq-bridge/blob/781e02f24e17004d3821c1b71501a442e07ed756/src/preset-prompt.js)

上游区分群聊参与方式和人格，并采用显式发送、消息水位、分批浏览与按需展开。当前许可证为 PolyForm
Noncommercial 1.0.0；本批没有复制它的实现或提示词正文。参考代码保留在本机证据目录， 不引入
SnowLuma、DSH 或 OneBot 运行依赖。

## 对照与落点

| ---------------------------------- | ------------------------------------------------------------------- | ----------------------------------------------- |

| 本地 seq 与平台 messageId 分开     | 本地句柄用于浏览，平台编号用于引用与真实发送回执                    | 屏幕契约已实现                                  |
| 只确认已看过的 readThroughSeq      | 返回实际展示水位；进入自动已读还是显式确认待主人选择                | 未实现已读写入，见 Issue #548                   |
| 压缩模型视图，原始记录不改         | 正文按 Unicode 码点预览，长文可按文本页展开；不改原文或内部原始字段 | 屏幕函数已实现                                  |
| 时间直接呈现绝对值与距离           | 显示明确时区的时间和 age；缺失、非法、未来时间分别标记              | 已实现；不把未来时间夹成“刚刚”                  |

| 明白在回复谁，按语境决定引用与开口 | 一条意识流中保留来源、时间和引用；开口与继续行动由 Eve 判断         | 交流提示词候选已整理，未注入模型                |
| 学习群友的接话与分条节奏           | 学情境、反馈、完整意思和交流时机，保留 Eve 自己的判断               | 仅提示词候选；经验学习与效果尚未验收            |

## 提示词的取舍

[qq-social.md](../prompts/qq-social.md) 是用于后续手机接通的交流段落，不替代企划案指定的 Eve
身份文件，也不注册或声称已有具体脚本接口。当前宿主没有自动加载它。

参考的重点是：眼前话题和关系、引用对象、发言的具体理由、等待补充、一个完整意思一条消息，
以及学习本群的交流节奏。它们是判断材料，不能靠固定开场、强制分条或预制催话获得“像人”的验收。

上游也有固定字数、固定沉睡观察、必回 @、轮次表情概率和跨会话模式限制等自己的部署规则。 Eve
按本项目企划案保留一个主体、自主选择和真实能力：这些部署规则不导入。
本批也不采用上游“没有本地工具”的能力否认，不用编造“刚没看手机”解释送达或处理故障。

后续接入时稳定身份、交流原则、由真实契约生成的能力说明分开组织；运行状态和新消息追加到
时间线末尾，不每轮重写系统提示词或把便签全部挂上。

## 边界与未验收

当前 `plugins/phone/view.ts` 是纯函数，并非可启动的手机插件。它消费查询所得记录，在内存中
生成屏幕；不实现全量日志索引、通知调度、认证、身份映射、搜索、已读持久化或任何发送。
平台事实必须来自独立适配器，这组类型和函数本身不能证明平台认证。

显示策略由调用方显式给出，没有默认值。实现约束每屏 1～20 条、正文预览/文本页 1～1024 码点、附件页
1～8 项；具体手机默认可在接通时调节。姓名与附件名只展示 100 码点预览，
完整正文和资源仍由适配器保存。识别符过长则报错，不截断成另一个可操作对象。

历史翻页需要适配器返回同一快照中的稳定记录；如果日志重写或记录缺失，本函数不能证明页完整。
`readThroughSeq` 仅是本屏最高编号，不证明此前所有消息都已看过，也不是送达回执、权限证明或
已读提交。入站积压时，要分清确认会话当前位置与逐页读完旧未读，不能把最新一屏称为已读全部
历史。发送未知时仍要核对已有动作，不能自动重放。

需要区分三个表达观察：协议支持多条发送、模型是否选择一次多条、以及随交流阶段自然发送
独立消息。本批只有屏幕回归和人工对照，不调用真实模型，不证明自然分条、蒸馏增益或线上 QQ
体验改善。后续用未参与学习的多轮场景检验接话、补充、省略、任务交流和真实采用经验。
