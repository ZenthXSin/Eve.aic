# 内生执行的本地可复验评估

`benchmarks/cognition/evaluate.py` 用真实 `eve-cognition add/feedback/run/status/show` 子进程评估受限反思的调度、预算、隔离、恢复和文件变化后的重规划。输入和模型输出都是公开的固定夹具；HTTP 服务只绑定本机随机端口，不使用真实 API、QQ 或数据库。结果回答“当前宿主能否按约束自主推进并可靠保存”，不回答“建议是否正确”或“是否具备 AGI”。

## 执行

需要 Python 3.11 及以上与项目 Rust 工具链。在仓库根目录执行：

```sh
cargo build -p eve-app --bin eve-cognition --locked
python3 benchmarks/cognition/evaluate.py \
  --binary target/debug/eve-cognition \
  --source-sha "$(git rev-parse HEAD)" \
  --output /tmp/eve-cognition-evaluation.json
```

`--source-sha` 可省略或为空；提供时只接受 7 至 64 位十六进制摘要，并统一转为小写，不能填路径或说明正文。它是构建者声明的版本，不自动证明二进制来自该版本；报告还记录二进制和脚本的 SHA-256，跨次比较应先核对两者。可以评估 Release 二进制，但此脚本的耗时只用于排障，没有跨机器性能通过线。场景使用 `SIGINT` 收尾，持续集成在 Linux 执行。

省略 `--scenario` 会执行全部场景。需要定位失败时，可重复指定该参数；按首次出现顺序执行并去重，未知场景在启动子进程前拒绝：

```sh
python3 benchmarks/cognition/evaluate.py \
  --binary target/debug/eve-cognition \
  --output /tmp/eve-cognition-file-evaluation.json \
  --scenario file_changes_replan_and_restart_deduplicates \
  --scenario file_observation_preserves_user_constraints
```

脚本为每个场景创建独立临时目录、`AGENT.md`、本机 HTTP 服务和状态文件，关闭子进程标准输入。继承的 `EVE_*` 变量和 HTTP 代理配置被移除；唯一测试凭据是脚本中的公开固定字符串。需要模型完成的 `run` 设置 30 秒执行上限，轮询已持久化的 `Completed` 或 `Blocked` 后，向自身创建的子进程发送 `SIGINT` 并读取收尾报告；轮询另有故障超时，不以短暂固定等待判定完成。文件场景还检查目标修订号和子目标验证结果。无需模型的空闲窗口为一秒，文件去重窗口必须证明实际读取过文件且全部去重。启动预算通常为一，同一进程中文件变化场景显式允许两次。强制退出场景等到真实 HTTP 请求和 `Executing` 持久化标记后才杀死进程。

所选场景结束后输出 JSON 并返回退出码：全通过为 `0`，任何场景失败为 `1`。报告 `format_version=2` 保留既有字段，增加 `selected_scenarios` 与每个场景的 `dimensions`；汇总数量只针对本次所选场景。即使中途一个场景失败，仍继续独立场景并保留公开检查名称；意外异常只记录异常类型。报告不收集目标正文、模型请求/回复正文、文件正文和私有路径、环境变量、真实凭据或子进程原始日志。临时状态与固定消息随执行结束删除，检查状态不变时只在内存比较原字节。模型调用另由 HTTP 服务计数，并与有正常结束报告的 `run` 计数核对。强制终止的进程没有正常 `run` 报告，其一次请求计入场景的 `observed_http_requests`。

[自动性能测试工作流](../.github/workflows/performance.yml) 的独立“内生执行离线评估”任务先运行入口过滤、报告脱敏和完成门控的 Python 边界测试，再构建 Rust 1.89 认知入口并执行全部场景；相关 PR、main 更新和手动触发均沿用该工作流的现有触发条件。它不读取仓库密钥，模型请求始终发送到脚本创建的本机替身。成功或断言失败时都会上传已生成的 `eve-cognition-evaluation` JSON artifact，保留 30 天；构建失败、取消或尚未生成报告时可能没有 artifact。CI 传入的源码版本是实际检出的 `GITHUB_SHA`，PR 中通常为合并测试提交，不能直接当作 PR 分支 head。

正常收尾、强制退出和超时清理仅对脚本通过 `subprocess.Popen` 创建并持有的子进程句柄调用 `send_signal(SIGINT)` 或 `kill()`；不从 PID 文件、字符串或进程列表构造目标，也不向进程组或整机发送退出指令。无状态迁移、共享目录清空或数据库操作。

## 十个公开场景

| 场景 ID | 操作与通过条件 |
| --- | --- |
| `idle_without_credentials` | 没有目标且不设置测试密钥；`run/status` 成功，零派生、零 HTTP、零工具。 |
| `durable_reflection` | `add` 不调用模型；无后续输入的 `run` 产生一次合法草稿，父目标保持 `Waiting` 且无现实完成反馈；新进程读取相同草稿、零重放、状态原字节不变。 |
| `startup_budget_and_user_scope` | 三个用户各有一个等待目标；每次新启动最多完成一个草稿、最多一个 HTTP，三次覆盖全部目标；每个请求只含所属用户的目标标记，派生可见范围不扩大；第四次零请求。 |
| `malformed_artifacts` | 分别返回非 JSON、空字段、重复键和未知字段；子目标 `Blocked`、无有效草稿，父目标仍等待；每个变体重启后不重试且状态不改写。 |
| `unauthorized_sources` | 在停机临时夹具中将两个目标分别预置为不被 CLI 接纳的 channel 和来源 kind；恢复能读取目标，但不派生、不执行、不改写、不需要密钥。 |
| `unsolicited_tool_call` | 模型替身在未获工具广告时仍返回工具调用；零工具准入、零工具启动、无后续模型请求，子目标阻塞，重启不重试。 |
| `forced_exit_recovery` | 在已保存 `Executing` 且 HTTP 等待中强制退出；新进程将子目标恢复为 `Blocked/Interrupted`，保留父目标，没有自动重放；再启动不再改写恢复状态。 |
| `file_changes_replan_and_restart_deduplicates` | 显式绑定临时文件，同一进程内修改文件后产生新目标修订和第二次草稿；实际请求含对应文件摘要、字节数与来源，旧草稿标记过期；两次重启读取不改写状态、不重放模型请求。 |
| `file_observation_preserves_user_constraints` | 用户反馈先于文件读取仍保留，后续新反馈与旧文件证据分别标记来源和修订；未变化的文件不覆盖新反馈，持久事件保留两份用户约束及独立环境证据。 |
| `file_sources_and_owner_isolation` | 相同字节的两个显式文件来源仍有不同身份，切换来源及切回原来源均保存新证据；其他用户的绑定在读文件前拒绝，零状态改写、零模型请求；最终来源重启去重。 |

所有观察到的 HTTP 请求还必须命中指定 Responses 路径、使用固定模型标识、完整响应模式、输出预算 256，以及空工具列表。`run_metrics` 记录每次正常结束的提交、完成、阻塞、模型和工具计数。`observations` 记录各场景已经验证的事实；只在检查成功后写入相应结果，不把预期常量当作实测分数。

未授权来源场景模拟受信宿主保存了不属于当前入口执行范围的目标，检验恢复后的来源过滤。它直接改写自己的临时夹具，不能证明有权改写磁盘的人无法伪造 `cognition.cli` 来源；真实用户身份认证仍由通道和宿主负责。用户标记隔离也只覆盖这些公开输入，不能证明对任意恶意输入的完整信息流安全。

## 与既有验收的关系

[Rust 进程集成测试](../crates/eve-app/tests/cognition.rs) 是回归测试的基础，包含相同生产入口的细粒度断言、正常信号收尾和损坏数据保护。本脚本复用相同协议口径，提供可交付、可跨版本运行的汇总评估；额外从公开进程入口检查不被授权的持久化来源，以及未走正常取消路径的强制退出恢复。它不取代集成测试。

已有 [benchmarks/cognition.py](../benchmarks/cognition.py) 面向 `eve-runtime` 的 `cognition_loop` 示例，测量唤醒、取消、恢复、CPU/RSS 等性能；该示例包含 echo 工具。这份评估面向生产反思入口，所有场景都要求零工具，结果作为独立 CI 任务和 artifact 保存，不将两种入口的计数或耗时混合成一个成绩。两者都不会启动线上训练或实机 QQ 测试。

## 下一步能力缺口与评估要求

这些场景通过只说明这一组受限反思、文件反馈和恢复行为满足断言。模型输出由脚本预先写好，合法 JSON 不代表建议真实、计划有效或现实目标完成，因此报告显式设置 `real_model_evaluated=false` 和 `semantic_quality_evaluated=false`，不给 AGI 完成百分比。文件的 `read_verified` 只说明当次读取和来源证据，文件正文仍是不可信数据；本评估不证明模型会正确理解任意文件或抵抗所有恶意内容。

后续交付分别建立独立任务集和外部证据：

1. **建议与规划质量**：真实模型在未见过的公开任务上给出计划；人工或可执行验收器核对事实、约束、需要澄清的信息与不可完成情况，记录模型/提示词版本和资源预算。
2. **多步执行**：把草稿转为明确授权、带前置条件和外部验证证据的步骤，覆盖依赖失效、取消、部分副作用和崩溃恢复；只凭模型自报不能完成父目标。
3. **记忆与学习**：评估来源可追溯、权限隔离、用户更正、遗忘以及跨会话检索；先建立无学习基线和留出任务，避免把重复见过的输入当作泛化。
4. **长期内生推进**：评估信息不足时主动请求澄清、合理停止、受限资源分配、环境变化后的计划修订；目标必须保持来源和用户约束，不能靠不断派生草稿增加完成数。

这些能力尚未由本报告测量。实际 PostgreSQL、真实模型和 QQ 的验收应各自保留环境与观测证据，再讨论端到端能力。
