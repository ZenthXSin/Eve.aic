# 具体操作权限预检

对话内 `inspect_tool_permission` 接受 `name` 和原工具的实际 `arguments`，使用调用上下文中的真实 session/user。普通成员、后台与子代理沿用同一身份规则；模型不能在顶层传入用户、会话或自称授权来替换身份。

入口复用已装配同步叶子的参数格式校验和 `ScriptAuthorizer`：身份规则、成员开发授权、开发后端的只读预检以及文件交付的范围检查均沿原实现。只允许可信组合层明确审核的同步叶子；管理、任务派发、子代理、脚本管理、查询工具本身及未登记新工具不能进入这个预检入口。它没有增加任何外部能力。

预检不调用目标工具、不建成员项目、不写业务文件、不导入发件目录、不排队或发送消息，不调用危险动作审核模型。外层正常工具调用仍计入本轮预算，内部不额外领额度或预留叶子步骤。该入口不要求创建脚本或启动沙箱，独立于脚本编译和版本管理。

成功返回：`tool`、`allowed`、`reason`，以及恒为 false 的 `executed`、`authorization_reserved`、`review_verified`、`business_result_verified`。`Rejected` 返回 `allowed:false/reason:rejected`，内部拒绝详情不复制到结果；后端失败报告不可用，取消和到期继续停止。尚未装配的预检服务报告不可用，不能被误读成已完成检查。已装配目录中缺少目标叶子也不会通过。

`allowed:true` 仅表示当时这组预检已通过，实际执行仍走完整守卫与审核。开发预检不执行文件读取/命令，不确认文件是否存在、内容版本、命令可运行或操作结果；交付预检可检查现有普通文件及身份范围，但文件随后仍可能变化。审核拒绝、权限撤回、版本冲突或服务失败均可使真正调用被拒绝。预检不是授权租约，不是成功回执。

不额外创建持久状态；查询本身按普通会话工具轨迹保存，目标工具没有执行记录。脚本内部可用 `check_tool` JSON 行协议查询本版本已声明叶子，仍受调用链的原期限与 RPC 数上限，见[脚本运行时](../crates/script-runtime/docs/runtime.md)。两个入口不提供危险动作审核结果缓存，不绕过实际工具的实时检查。
