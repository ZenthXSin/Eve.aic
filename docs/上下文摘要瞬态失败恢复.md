# 上下文摘要瞬态失败恢复

摘要失败日志已观察到 provider timeout，之后相同作用域可成功生成摘要。代码同时存在外层只按单次 provider_timeout 限时、超时或空响应直接结束摘要的问题：格式修复与瞬态重试共用最多两次请求，给短期限 provider 留出第二次预算，总期限仍不超过 301 秒（运行时主动压缩上限 300 秒）。只重试超时、无效输出、网络、限流和 5xx 等瞬态错误；认证、余额、普通 4xx、取消不重试。重试依据同一份原始数据，不重放业务工具；失败保留原文和已提交摘要进度。`EVE_HISTORY_DIGEST_RETRY` 只记录有限类别，不记录私聊正文或凭据。

本次宿主配置将 `runtime.history.adaptive_limit_tokens` 从 200000 改为 275000。此值为本地估算的输入上下文预算，不表示供应商承诺支持 275k；配置不能扩大上游模型的实际窗口。压缩会在上限前预留空间，不把 MB 当作 token 数。

验收使用本地模型、fake QQ bridge、真实文件状态库和测试数据库，不能替代正式 QQ 配额验证；不会为了验收向真实用户发消息。


宿主模型解析器沿用现有底层有界瞬态重试，不再只对 dialogue 使用名启用，后台任务也纳入相同策略。这里的两次上限是摘要器调用预算，底层 provider 的既有重试仍有自己的上限；不会重放业务工具。
