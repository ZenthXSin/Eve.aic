# 所有权交接与 QQ 出口

本候选接上独立守护的持久仲裁、租约与出口检查，并把 QQ 手机的读取和发送接到该接口。
这不是整套自升级已经完成的声明：双版本拉起、旧 Eve 观察确认、自动回切、共享日预算和
意识流/命令出口的令牌检查仍待贯通；正式 Eve 主程序尚未上线。

## 已有行为

守护独占自己的目录，以原子写入及文件/目录同步保存状态。启动先增加代际号码，旧租约
立即失效；重启不能清除已开始的出口许可，也不能自动解除主人保存的暂停。格式损坏、
未知文件、未完成写入、容量超限或号码达到安全整数上限都保留原件并报错。

控制凭据、出口凭据和每个实例的凭据彼此分开。实例可续自己的当前租约、查看控制状态；
不能直接登记实例、发出交接、暂停/恢复、发许可或结算许可。完整自升级的指令入口将在
监督组合层接入，不把管理密钥放进 Eve 的工具参数。注册的源码提交目前只是组合层提供的
标识，尚未由守护校验运行产物来源。

一次交接先进入 draining，拒绝旧实例新增动作；已有动作等待实际处理结束。未结算许可
不会因为租约过期、调用方等待超时或守护重启而失效。排空后重用同一个交接申请编号，
持久增加号码并发给候选。历史回执可查询，但历史 granted 不证明它仍是当前在线实例。
暂停撤销新动作权限，既有动作仍保留结算责任；显式恢复才能离开持久暂停。

## 申请、执行与回执

每个出口先保存自己的申请编号、实例编号、代际和参数摘要，再向守护申请许可。申请回执
未知时可以用同一个编号取消；取消墓碑使迟到的申请不能再次获准。此取消只适用于出口
持久记录能证明真实操作还没有开始的 requested 阶段。

收到许可后，出口先保存 admitted 才执行。处理结束后先保存 settled，再结算守护许可，
最后移除出口的派生待结算项。调用方离开或超时不会提前终结底层处理。中断恢复时：

- requested：取消原申请，不开始操作。
- admitted：查询真实业务回执；缺证据时保持待核对，不猜完成、不重放。
- settled：重交原终态，采用守护已有结果，不重新执行。

出口另存已见过的最大代际。即使守护错误回到旧号码，出口也拒绝更旧的动作。实际权限
仍须经当前守护验证，不能把客户端自报的大号码当作有效权限。业务正文与实例秘密不进入
仲裁记录；参数/结果摘要不证明业务目标成功。

`completed` 只表示出口处理已结束；例如手机返回了 `state: unknown`，也可能是一次正常结束
的 RPC。是否送达仍以原 QQ 回执的 state 和平台 message ID 为准，不用许可终态替代送达。

## QQ 接线

配置 `qqOwnership` 后，独立适配器在手机 RPC 信封中接收实例证明和动作编号；包括发送、
通知、历史、搜索及回执读取，均先检查令牌。号码不进入手机业务参数，来源身份和主人关系
仍来自平台事件及可信配置，不能由正文宣称。发送信封编号必须与业务 actionId 相同。

同一 actionId 的重复发送依然采用 QQ 原账本。换版、网络等待超时和重启不清空这份账本，
所以交接后的同一发送不会再触发平台请求。启动时，适配器可用已恢复的发送回执补结算；
没有对应业务回执的 admitted 读取继续待核对，目前没有通用自动解除路径。

手机 worker 的清单只读自身实例证明、手机连接和桥接密钥，不授予守护管理/出口密钥。
实例证明文件应每个实例独立，监督层不得把新版凭据写进旧实例仍可读的同一路径。请求携带
凭据只是本机 IPC，工具返回及仲裁记录不复制它。此机制防并存和卡住的旧实例，不宣称能
防范拥有本机管理权限的恶意进程。

守护重启会换本机端口。生产组合客户端每次读原子更新的连接文件，因此 QQ 适配器可保持
连接，不必为了发现新端口重启网关；未知请求仍沿原申请编号核对。

## 私有配置和入口

守护独立启动：

```sh
deno run --allow-read --allow-write --allow-net=127.0.0.1 guardian/main.ts /absolute/private-config.json
```

私有配置的 `ownership` 包含 directory、adminKeyFile、exitKeyFile 和 leaseMs。前三项是绝对
路径；密钥文件私有，管理和出口密钥须不同。守护写 directory/connection.json，只有本机
连接地址，不写密钥。

适配器配置的 `qqOwnership` 包含 guardianConnectionFile、exitKeyFile；手机插件的 phone
配置在原 adapterUrl、adapterKeyFile 和可选 ownerPlatformUserId 之外，加独立实例的
ownershipProofFile。模型与 QQ 原凭据继续沿用原配置，不复制进仓库。

省略 qqOwnership 仅保留已有独立接收探针和离线契约兼容。正式主程序组合须配置并检查
ownershipFenced，不能把这个兼容模式当作多实例上线保护。health 的 available 是适配器
可用性，不证明某个实例持有当前租约，也不证明 QQ 网关已经 READY。

## 验证与未覆盖

新增本地测试覆盖交接排空、续租拒绝、持久暂停、历史回执、重复编号冲突、回执丢失、
取消迟到申请、坏凭据、号码回退/上限、损坏保留及 RPC 角色。实际子进程覆盖 SIGKILL
守护/出口、查原回执、不重放、守护换端口和两份守护竞争。QQ 回环贯通覆盖客户端超时、
实际 worker 与网关、旧实例拒读、发送幂等、私信限制及凭据清单。

这批不使用付费模型或真实 QQ 发送，不证明自然表达、蒸馏增益或线上稳定性。具体测试
结果与候选提交写入本轮验收记录，不以文档本身替代证据。

目前状态是单 JSON 索引：守护上限 32 MiB，出口待结算索引上限 4 MiB；达到上限停止并
保留现场，没有悄悄删历史。租约依赖宿主时钟；尚未实现全磁盘快照回退后的号码恢复协调。
请求/许可原记录不能为了“解除阻塞”删除。双版本自升级的观察、确认与失败标记还需接入。

守护替换权限仍等待 Issue #548 的既有问题回复，本候选没有开放该能力。回退源码时保留
仲裁、出口和 QQ 业务原件；停用令牌保护只能配合单实例受控运行，不能通过删除未知记录
或重放真实动作实现回退。
