# 跨会话个人记忆

启用 QQ 交互记忆后，跨会话读取默认开启，无需新增命令行参数。历史依然按原来的 `MemoryScope { channel, session_id, user_id }` 保存；新增的是按可信身份选取的只读个人记忆层，不重写 SessionKey、不合并历史、不搬迁或复制原始证据。

设计参考老 [eve-portable](https://gitee.com/zenthxsin/eve-portable) 的 `knowledge/concepts/persistent-memory-policy.md`：长期层保持稳定偏好和可复用规则，具体经历保留来源，详细技术事实继续留在知识库。这里的偏好来自原有的明确确认或已启用的自主学习确认，不把跨会话读取变成新的自动确认授权，也不将旧助手输出提升为事实。

## 身份与可见范围

QQ 旧版 SessionKey 同时包含 AppID、群/私聊、目标与发送者，因此它区分了会话，却不能单独证明两个会话属于同一人。新增路由身份索引只从校验过的平台事件和持久回执构造，保留旧会话 ID。相同 AppID、相同 OpenID 命名空间下的同一平台发送者可跨群识别；群 OpenID 与私聊 OpenID 不自动视为同一身份。

需要关联不同 OpenID 或账号时，在本机面板设置明确绑定：

- “人名称呼与主人”配置的 `runtime.people.owner_principals` 已是同一位主人的账号绑定，默认供个人记忆读取使用。名字或自称“主人”不会建立绑定。
- 其他账号在“跨会话个人记忆”的 `identity_groups` 填写 JSON 数组，每组列出同一个人的可信会话用户标识，例如 `[["qq:第一条完整摘要", "qq:另一条完整摘要"]]`。完整标识从面板记忆作用域查看；示例中的中文须换成真实 64 位十六进制摘要。单个标识只能出现在一组，不支持昵称、任意用户正文或工具参数指定身份。
- 未绑定、未知来源或不同 AppID 的记录不纳入。不会把开发工具操作者列表自动当作同一人的账号。

默认读取规则：

| 当前对话 | 已验证为同一人的来源 | 可用内容 |
| --- | --- | --- |
| 私聊 | 私聊或群聊 | 当前有效偏好、与本轮查询相关的历史片段 |
| 群聊 | 同一群中的已绑定来源 | 当前有效偏好、相关历史片段 |
| 群聊 | 其他群 | 仅当前有效偏好 |
| 群聊 | 私聊 | 默认不读取 |

人物印象（此人自述的事）按同一套授权跨会话合并，只要来源可见就可读取，不区分上表的“仅偏好”与“含经历”两档，详见[人名与主人身份](./人名与主人身份.md)。

偏好也可能仅适用于原场景，模型会收到来源和适用范围说明；当前会话的最新反馈优先。普通聊天经历不会因跨群识别而自动变成公共资料。

## 面板热配置

在插件页面的“跨会话个人记忆”（`runtime.memory_continuity`）修改，下次读取生效：

| 字段 | 默认 | 作用 |
| --- | --- | --- |
| `enabled` | true | 开启跨会话只读个人记忆 |
| `share_group_preferences` | true | 同一人的不同群之间延续已确认偏好 |
| `share_private_to_groups` | false | 显式允许已绑定身份的私聊记忆在群里使用，包含相关经历 |
| `use_owner_binding` | true | 使用已有主人账号绑定 |
| `identity_groups` | `[]` | 同一人的其他账号绑定组 |

前四项分别支持 `EVE_MEMORY_CONTINUITY_ENABLED`、`EVE_MEMORY_CONTINUITY_GROUP_PREFERENCES`、`EVE_MEMORY_CONTINUITY_PRIVATE_TO_GROUPS`、`EVE_MEMORY_CONTINUITY_OWNER_BINDING`。配置仍按文件覆盖环境、环境覆盖默认的顺序生效。非法 JSON、重复账号或无效标识拒绝保存。

## 上下文、检索与修改

上下文用 `eve-person-memory-v1` JSON 添加有界个人记忆；最多检查 8 个授权来源、携带 8 条完整偏好和 3 条历史命中，数据视图不超过 8192 字节。超限会标记 `truncated`，不截成含义不同的偏好。每个来源分别保留 `scope`、修订与证据 ID，不将不同会话里相同的局部 ID 混为同一记录。

`search_memory` 工具原参数不变，结果增加 `cross_session` 来源视图；模型不能传入用户或来源会话来扩大范围。`/recall 关键词` 同时显示有限的跨会话匹配片段。`/memories`、`/correct-memory` 和 `/forget` 继续管理当前来源会话；在原会话更正或撤销后，其他会话下一次读取会核对当前版本，不再使用旧偏好。关闭绑定或关闭功能也在下一次读取生效，不修改已经捕获的在途请求。

跨会话读取只访问本地已保存资料，不等待向量或模型，也不重新执行旧任务。当前会话自己的语义召回继续使用已装配的后台向量机制。跨会话片段来自确定性词项检索，冷查询没有匹配时不会编造记忆。

## 持久化与恢复

个人记忆层不引入新的记忆格式或后台查询队列。原始证据、偏好版本、撤销记录和 SQL/文件后端的恢复规则保持不变；绑定通过原配置服务持久化。QQ 重启时只从当前 AppID 的已验证回执重建只读路由身份索引，不重放旧消息、不补发、不补采记忆、不调用模型。旧回执已经淘汰且缺少可信路由的范围先保持不可见，重新收到该来源的平台消息后再恢复识别，旧记忆不删除。

读取服务每次重新检查授权和当前来源快照；错误范围、重复来源、无效修订、损坏状态或停止后的服务明确报错，不回退成“没有记忆”。读取句柄绑定创建时的记忆服务，插件重启不会使旧句柄重新可用。全局容量仍见[交互记忆](./交互记忆.md)，此功能不解除容量限制，也不自动清理记录。

实际宿主验收位于 `connectors/qqbot/test/memory_continuity_test.py`：覆盖跨群偏好、来源不迁移、更正/撤销、重启、明确账号绑定、私聊可见范围、热关闭、同名冒充与真实 `search_memory` 工具往返。

## 整理原则

人物印象、跨会话画像和对话历史摘要按同一组原则整理（参考 openai/codex 的记忆写入规则，Apache-2.0）：

- 按原话的范围记：一次说到的状态或打算照当时的样子写，不升级成长期喜好或习惯；只有本人用了“一直”“最喜欢”“从来不”这类长期说法，才写成稳定喜好。
- 每条只写来源支持的范围，一个场景里说的事不推广到所有场景；被后来的说法纠正或撤回的旧说法不再保留。
- 历史摘要区分用户要求的、助手提议的、已经做完的和实际验证过的；用户对某一步的同意只记在那一步，不写成以后同类操作都已获准。

这些原则写在各自的提示词里，单元测试核对它们仍在；模型是否遵守由[记忆与缓存评估](./记忆与缓存评估.md)的真实模型模式（`one_off_not_generalized`）衡量。
