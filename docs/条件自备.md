# 条件自备

Eve 想做的事缺少运行条件时，不停在“没有环境”，而是自己创造条件。她自己找来源取得所需文件，宿主核对摘要并实际使用一次，验证通过才启用。第一个条件是实践验证用的 Mindustry 无头服务端：开启自主学习却没有指定服务端时，Eve 可以自己把它准备好。

## 分层

| 层 | 内容 |
| --- | --- |
| 定义层 `eve-provision-api` | 条件（`ConditionSpec`）、来源（HTTPS 地址或本机文件）、取得结果（`Acquisition`）、尝试记录、验证器 `ConditionVerifier` 与条件服务 `ConditionProvider` |
| 实现层 `eve-provision-plugin` | 下载或复制到暂存目录、核对大小与 SHA-256、调用验证器、通过后移入条件目录并写账本 |
| 组合层 `qq_provision` | 登记条件与验证方式、`acquire_condition` 工具、缺少条件的提示、启动时使用已取得的服务端、热配置 |

替换实现时只需提供新的 `ConditionProvider`；新增条件时在组合层登记 `ConditionSpec` 和对应的验证器，不改定义层。

## 取得流程

1. 来源由模型自己找：官方发布的 HTTPS 地址，或它用开发工具在本机构建出的文件的绝对路径。下载只接受 HTTPS（本机回环地址可用 HTTP，仅供本地验收），逐跳核对重定向，不携带账号或 Cookie。
2. 文件写入条件目录下的 `.staging/`，边写边计算 SHA-256，超过该条件的大小上限立即中止。给出 `sha256` 时必须一致，不一致不运行验证。
3. 交给宿主登记的验证器实际使用一次。Mindustry 服务端的验证方式是：用一个最小纯数据模组实际启动服务端，模组加载成功且探测值一致才通过。
4. 通过后移到 `conditions/<条件>/<sha256>/<文件名>`，再写账本；写盘成功才在内存里替换为新版本。失败时删除暂存文件，只记下来源与原因，此前启用的版本不受影响。
5. 同一条件同时只进行一次取得。

## 对话中的行为

- `acquire_condition` 是管理能力，只有主人和管理员的对话可以调用；普通成员调用会被拒绝，也看不到提示。
- 开启自主学习而缺少实践运行环境时，主人和管理员的对话里会出现一段数据 `eve.conditions.v1`：缺少哪个条件、谁需要它、最近失败的来源和原因，并提示她自己找来源、换掉失败过的来源。没有缺少的条件时不加这段，不影响提示缓存。
- 一轮回复里换来源重试需要多批工具调用，即 `--max-tool-rounds` 大于 1。

## 生效时机

实践运行环境在启动时决定。取得成功后工具结果会注明“下次启动”生效，Eve 应告诉主人需要重启。重启时如果没有用 `--practice-mindustry-server` 指定服务端，宿主使用账本里已启用的版本，实践验证随之启用；成员项目的无头加载验证也使用同一个文件。`--practice-java` 与 `--practice-java-arg` 可以不带服务端单独指定，用来启动 Eve 自己取得的服务端。

## 开关

热配置页“条件自备”（`runtime.provision`）：

| 字段 | 环境变量 | 默认 | 含义 |
| --- | --- | --- | --- |
| `enabled` | `EVE_PROVISION_ENABLED` | 开 | 关闭后工具明确拒绝取得、对话中不再提示；已启用的条件不删除，启动时仍会使用 |

## 持久化与恢复

- 账本 `eve.provision/provisions.v1` 保存在状态存储中：每个条件的当前启用版本，以及最近 8 次尝试（来源、时间、是否通过、证据或原因）。
- 先写盘再更新内存；写入结果不能确认时关闭账本，工具返回“结果未确认”。重启后以磁盘为准。
- 账本损坏、格式版本未知或内容不合法时拒绝启动，保留原字节，不自动清空。
- 条件文件不在账本里，而在 `<状态目录>/conditions/` 下。账本记录的文件丢失时视为未启用，会重新提示缺少。换成新版本后旧文件保留在磁盘上，不自动删除。
- 验证通过、文件已移入但账本写入失败时，文件会留在条件目录里，不被引用，也不会被当作已启用。

## 边界

- 下载的服务端会在宿主上以 Java 进程运行，所以只有主人和管理员能取得条件。验证只证明它能作为运行环境，不证明来源可信；有官方摘要时应当给出。
- Java 运行时本身还不能自备；缺少 Java 时验证会失败并记下原因。
- 新取得的条件不会在运行中替换实践运行环境，需要重启。
