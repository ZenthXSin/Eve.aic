# 委派上下文与恢复

后台任务及子代理的当前用户消息只包含本次任务、固定验收条件和执行指导。`include_context=true` 捕获的完整消息仍原样存入 `TaskSpec.context.messages_json`；不通过截断业务记忆来缩小请求。

执行器把冻结消息绑定原会话身份，放入独立资料槽。请求副本中每条历史消息作为没有实际工具调用的历史资料呈现，允许既有摘要器按完整记录压缩。历史系统文字不是当前系统指令，历史工具回执不是待执行操作。真实授权原话继续走独立通道，不从资料、模型总结或任务说明重新推导。临时资料摘要不占用主会话的摘要作用域。

再次委派时平铺原始冻结资料与父任务当前执行消息，不重新捕获已经包裹的 JSON 投影。当前执行器的工具目录不会反复被嵌入当前用户任务。源记录和本轮真实工具回执保持完整，摘要只影响模型请求副本。

执行检查点格式不变，只记录该任务真正执行的调用、回执、计数及状态。恢复先核对身份、模型会话、未知结果与持久记录，再重新装配委派资料。旧检查点中原先内联的历史 JSON 仅在后缀与可信冻结快照完整匹配时从请求副本分离；持久原文不改写。正文变化沿用已有请求指纹机制分配新请求序号，任务会话不变。已执行调用不重放，失败任务和结果未知任务不会因本更新自动复活。

内置 `coding` 子代理独立读取 `runtime.history.coding_limit_tokens`，默认 450000；聊天与普通后台任务继续使用原上下文策略。工具预算、父期限、取消和真实回执仍共用既有执行机制。无法压缩的上下文错误按固定错误类别报告具体原因，不输出用户正文。
