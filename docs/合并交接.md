## 验收与继续开发

整合后的版本须运行 Rust 1.89 工作区格式、Clippy、全目标测试，Node 桥接测试、实际 Eve/QQ 替身进程及认知/消息恢复示例。本机浏览器使用合成正文、环回模型与专用测试令牌，不能访问正式 QQ 数据。独立状态目录的公开规则评估不发送外部模型请求。

Jev 和 Web 面板仍默认关闭：`--message-judge primary|jev` 与 `--web-listen 127.0.0.1:8765` 必须显式开启；Jev 使用独立配置和凭据，面板使用专用 `EVE_WEB_TOKEN`。认知反馈须开启 `--cognition`，使用 `/goal-feedback 目标ID 当前版本 新事实`；草稿不等于目标完成。

接手顺序：

1. 核对 main 的提交与 CI，阅读本地私有交接记录核实实际运行源码、二进制、状态和原训练截止时间。仓库合并不自动升级现有 QQ 进程；不能从磁盘新二进制推断旧进程运行版本。
2. 回收当前窗口的已保存结果，保留来源、失败和投递不确定记录；不得重置旧窗口、补发或重放旧消息，不将原始训练语料写入公开 Issue。
3. 使用公开同一批样本评估真实 Jev/主模型的误取消、纠正漏判和延迟，再决定生产启用。规则样本是构造基线，不代表独立真实质量。
4. 按 #115 推进实时诊断的公开只读契约、认知/记忆页和版本化管理操作；离线报告不能冒充 QQ 实时数据，默认不开放远程访问。
5. 继续受控目标执行与结果验证，保持用户事实、模型建议、执行证据分离；未验证草稿不能标为现实目标完成。
