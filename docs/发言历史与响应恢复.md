# 发言历史与响应恢复

自主发言只需要理解眼前原话、近期事实和实际投递结果。此前每次决定都会载入最近六个已完成轮次的完整模型消息；工具输出合计超过 256 KiB 后直接返回上下文错误。线上日志证实，这会使命令结果和后台事件一直等待，聊天模型本身可用也无法解除。

现在通过公开的 `SessionService::recent_turns` 读取同一身份、同一会话最近六轮。内置存储只读取所需尾页，包含进行中、失败和中断轮次，不再先复制整个会话。旧服务仍可使用默认游标兼容实现，接口与存储语义见 `crates/session-plugin/RECENT_TURNS.md`。

发言模型收到的是派生事实视图：每轮用户原话与内部收尾各保留最多 2048 UTF-8 字节，明确原始长度和是否截取；最多四个最近工具只提供名称、真实结果状态及存在时的成功标识、退出码。完整工具正文继续保存在原始历史，视图不会修改、清空或重放它们。内部收尾不代表已发送，是否送达仍以独立投递回执为准。最后收到的原话单独完整传入，不受历史片段长度限制；仅真实入站触发时作为当前输入，后台事件将其放在历史语境中，见[后台发言事件与用户输入](后台发言事件与用户输入.md)。

整个发言决定过程受 60 秒异步期限约束。模型、上下文或决定前后的新鲜度读取失败都会回到可重试状态；取消决定 future 或同进程停止通道插件也会释放仍在判断中的记录，不必等整个宿主重启。同步存储读取仍由存储本身完成，计时器不能抢占同步 I/O。新消息到来后旧决定不能发送。记录已发送、发送未知或沉默的恢复语义保持不变：发送未知不能自动重发，沉默不是完成任务，也不写成对方已收到。

发言模型使用独立的 `speech` 配置用途和健康统计，默认继承当前模型配置。此用途不会更换模型或额外传入温度参数。诊断只记录固定阶段、错误类别、HTTP 状态和时间，不记录消息原文、身份或供应商错误正文。

`speech_history_test.py` 使用真实 Eve 进程与本地模型、QQ 替身，恢复六轮超过旧限制的工具历史后验证命令实际投递、历史字节不变、主线程没有重新执行旧工具，以及再次重启不重复发送。应用单元测试另覆盖 UTF-8 边界、失败与进行中轮次、仅调用尾页接口，以及原始历史不变。
