# 空闲回顾、行动与判断修订

QQ 宿主启用后台任务并获得主人有限自主授权后，可以在没有新用户消息时回顾经历，由模型选择等待、继续思考或提出行动。回顾没有工具，行动通过原执行器、权限和行动审查；回顾成功不会自动发送完成通知。普通聊天仍可读取当前想法与可修正判断。

## 实际流程

主人可以直接说“允许你空闲时回顾经历、自己决定做什么，最多二十个目标，各五百五十步”。模型使用 `configure_subject_autonomy`，宿主按原真实主人身份和最近原话审核后保存授权。新授权默认 `idle_reflection=true`，也可以显式关闭；旧授权缺少该字段时继续原探索方式，不自动迁移、重置用量或延长期限。只有一句角色提示词不会产生授权。

至少三十分钟没有本范围用户准入，且前台没有在途或未知控制报告、同范围没有未完成后台任务时，调度器才准入回顾。停止、用户输入及恢复仍优先；准入后新消息按原对话机制处理，不取消未知副作用或自动重跑工作。

宿主冻结当前作用域、认知修订、兴趣、最多六条关注、四个已结束任务和六个完整轮次中的对话节选。任务材料区分模型结果与已保存的工具回执，最近三步通过原诊断投影提供；完整记录仍在原 Session/Task 服务。材料带来源 ID、类型与节选标志；内部冻结合同及其中的授权原话不作为普通关注经历节选，也不挤占六条关注名额。私聊、群聊和其他用户不会自动合并。不会序列化整轮全部工具正文来生成对话节选。

模型输出严格的 `IdleReflection`：`choice`、简短想法和理由、最多四条判断、可选行动，以及三十分钟至一天的再回顾间隔。它可以等待，也可以保留兴趣继续思考，不必为了活跃制造行动。宿主不保存或要求模型的原始推理过程。

- `wait`、`reflect`：保存当前看法与再回顾时间，到期才继续；轮询与重启不把时间不断往后推。
- `act`：要求明确目标、收益、成本风险与实际验证方法，引用当前冻结材料中的 ID，且符合原候选正收益检查。`completion_contract` 可提供执行前冻结的工具回执验收条件，组合层严格反序列化并核对实际观察工具；支持工作区内 `read_file` 返回的完整文件 SHA256，或明确冻结工作目录和参数的受限 `cargo test/check/clippy`、`python3 -I -m unittest` 检查退出码。任意 shell、脚本输出和参数回显不能充当验收。行动必须在最后一个工具批次完成全部固定检查，该批次不能混入额外动作，文本或 JSON 自述不能证明行动完成；固定测试通过也只证明其实际覆盖的范围。宿主按原预算受理目标。相同问题键已经派发时不再执行，之后仍可到期回顾。回顾期间到达新用户输入时，旧行动草稿只作历史，等待重新回顾，不直接采用过时行动。
- 实际行动完成后，下一次回顾能看到原判断、新结果和工具回执节选。修改同一判断的正文或置信度须引用不同于旧判断的新证据，并说明修订原因。来源存在只表示真实记录存在，不证明模型结论正确。

没有候选或授权时，不会单独启动无预算的模型循环。轻量调度每秒检查，不代表每秒请求模型；新回顾、必要的无工具规划和新行动各消耗原授权的一个目标名额，步骤上限、共享并发、单次调用期限和固定授权截止沿用既有配置。回顾本身零工具，通常一次主模型请求，启用小模型筛选时另有一次辅助请求。

## 失败、持久化与恢复

协议由 `eve-subject-api` 定义，来源校验和认知修订由 `eve-subject-plugin` 实现，QQ 组合层绑定真实身份、冻结经历、持久受理任务并核对回执。当前宿主接线是 QQ 后台自主调度；独立 Web 对话入口没有因此自动获得后台内循环。

当前认知保存为主体账本中的保留关注 `idle-mind-v1`，普通模型关注工具不能覆盖它。它是最多六条、总计受原 8192 字节关注正文上限约束的当前视图；较旧判断从当前视图移出，旧完整输出与冻结输入仍由原任务及其归档保存，遵守原任务记录的容量和回收策略，不承诺无限审计历史。读到坏 JSON、来源或修订不一致时保留现场并阻塞，不清空重建。

回顾任务先持久受理，再请求模型，最终输出先保存在原执行日志与任务结果中，再幂等更新当前认知。重启可据已完成回顾补做本地结算，同一任务不会增加认知修订或刷新等待时间；旧修订只作历史，不覆盖新看法。目标名额先消耗再建关注，若跨账本提交无法确认，保留阻塞而不补发额度。

旧版行动提议没有 `completion_contract` 时仍可读取和结算回顾，但不能据此创建无合同执行任务；宿主先在原范围与预算内进行无工具规划，保存行动验收合同后再派发。合同只是候选数据，不产生新身份、权限或预算，未知字段、重复 JSON 键、无效检查和伪造授权字段均拒绝。已冻结合同随原作用域持久保存，重启不能从行动结果反推或改写成功标准。

已确认失败可成为新经历：零工具失败，或本执行者全部已启动调用均有可恢复的确定回执、没有子调用未知用量时，至少等待三十分钟后再做一次新回顾，仍扣原目标名额，不重跑原动作。待确认调用、超时/取消/执行失败等未知回执、旧任务中断或资料缺失继续阻塞。已知失败的新回顾也只能在原总目标数、授权截止及既有有限恢复规则内推进。失败通知沿原后台诊断；成功的内部回顾不产生对外通知。旧版任务校验器不认识这种无通知的内部完成记录，回退须使用匹配源码及状态备份，不把新状态直接交给旧版继续写。

## 无密钥小模型

小模型目前承担回顾线索挑选：最多返回四个给定证据 ID，不能生成工具调用、授权或替代原文。非法 ID、无效格式或服务失败时，主模型继续读取原始冻结材料；不将小模型判断当作事实。主模型请求保留原材料与合法线索提示。辅助请求在 Runtime 恢复日志之后计数，与原任务同一检查点、取消链和宿主五并发总准入；不占用额外工具步骤。

部署端可选择：

```bash
export EVE_IDLE_SMALL_BASE_URL=http://api.imc.mcmay.top
export EVE_IDLE_SMALL_MODEL=models/gpt-oss-20b-MXFP4.gguf
```

不需要 key；未设置端点则跳过辅助筛选。请求不继承或发送主模型 Authorization，匿名客户端不跟随重定向；单次十五秒、响应最多 64 KiB，不会循环重试。此设置在宿主启动环境中提供，不写死用户端点为所有安装的默认值。

普通按用途路由也支持无认证辅助角色，可将偏好提炼、摘要等已有用途交给该端点：

```bash
export EVE_MODELS_AUXILIARY_SMALL_ENABLED=true
export EVE_MODELS_AUXILIARY_SMALL_PROVIDER=openai
export EVE_MODELS_AUXILIARY_SMALL_MODEL=models/gpt-oss-20b-MXFP4.gguf
export EVE_MODELS_AUXILIARY_SMALL_CREDENTIAL_REF=anonymous
export EVE_OPENAI_AUXILIARY_BASE_URL=http://api.imc.mcmay.top
export EVE_OPENAI_AUXILIARY_PROTOCOL=chat
export EVE_MODEL_USE_PREFERENCE_ROLE=auxiliary_small
export EVE_MODEL_USE_SUMMARY_ROLE=auxiliary_small
```

`anonymous` 只适用于明确选择的辅助模型；角色和用途仍按原配置校验、共享并发和请求预算运行。主模型、Jev、语义凭据引用不因这个值而改变。能力分配须按实际质量评估，不自动把危险动作审查或最终行动决策切给新端点。

## 验收

`python connectors/qqbot/test/idle_loop_test.py` 使用真实 Eve 子进程、本地模型与 QQ 桥接替身，覆盖回顾零工具、文件写入后的独立末批读取与冻结 SHA256 验收、旧行动缺合同先无工具规划并保留原目标、拒绝纯文本行动合同、无新消息的后续修订、跨进程不重放，以及非法辅助选择回退。测试仅在自己创建的进程退出后推进临时状态的到期时刻，不在产品中加入改时钟接口。

可显式用 `EVE_TEST_IDLE_SMALL_URL` 运行其中的真实小模型专项；它只发送合成经历，并检查合法筛选提示确实进入后续请求，不将兜底当作接入成功。常规 CI 不访问该服务。测试证明执行、恢复和权限契约；长期选题质量、持续自主行为质量与正式 QQ 体验仍需部署端观察。
