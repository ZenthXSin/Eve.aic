# 条件周期触发与任务接续

本轮实现只在本地脚本模型、内存与临时文件账本中验收，不调用生产模型、QQ 平台或部署服务。

## 原会话条件与有限周期

`set_wakeup_trigger` 保持当前可信会话身份，支持时间、文件变更、后台任务结束、后续消息和进程实例状态。检查条件不调用模型。准入执行前写入 Running，执行结果另行保存，再由通道先记 Sending 后发送。不同触发器的观察与过期检查不再等待首个会话执行完成；QQ 既有全局闲置通道租约仍限制同时进入原会话唤醒的数量，不改变平台调度授权。

设置 `interval_seconds` 开启周期；仅允许一个时间条件，最短60秒，`max_runs` 默认48次、最多128次。每30分钟检查目标的示例参数：

```json
{
  "title": "检查构建目标",
  "instructions": "查看本会话已授权目标的构建状态。只核对本地结果，记录进展与阻塞，不部署。",
  "conditions": [{"type": "time", "after_seconds": 1800}],
  "interval_seconds": 1800,
  "max_runs": 48,
  "expires_in_seconds": 172800
}
```

这表示有限次数的目标检查，不承诺无人值守无限推进。每轮明确完成且投递已了结（Sent 或明确 Failed）后，从当下时间安排下次；延迟执行和离线期间不补跑，失败、取消、执行中断及 Unknown 投递不会自动开启下一轮。原始 `expires_at_ms` 不顺延，截止时仍未准入的轮次过期。时间条件必须早于有效期；`at_ms == expires_at_ms` 的新建请求明确拒绝，避免保存扫描永远无法准入的时间条件。旧边界记录仍可读取，并按原有效期过期，不清空账本。

运行次数和下一次时间条件保存在原触发器账本。新账本使用格式版本3，启动时验证并迁移旧版本1、2；旧运行程序不能读取新格式，禁止直接降级覆盖。损坏数据或提交失败均保留原文件并报错，不自动清空。周期通知带运行代号，账本原子比较代号与投递状态，上一轮迟到的回执不能改写下一轮。账本仍有总条目、每会话活跃条目、每日创建次数及90天有效期上限；条目满时明确拒绝，不删除现场。

## 冻结原始授权证据

新建普通自动唤醒时，可信宿主只从当前完整用户与会话绑定的专用审核槽读取最近六条真实消息正文，冻结到触发器的 `review_messages`。不从模型生成的任务说明、普通会话摘要或条件观察证据补造授权；恢复和每个周期继续使用创建时的同一份正文。幂等创建返回原记录，后来传入的正文不能替换原证据，也不能给旧触发器补写授权。插件扩展必须显式实现 `create_with_review_messages` 持久化契约；旧扩展默认拒绝这一创建请求，不调用旧接口丢弃证据。`resume_task_id` 接续已有任务时，继续使用原任务账本自己的授权证据，不把本次登记说明混入原任务授权。

消息正文包含原始空白和尾部，已验证附件消息的空正文也按原样保存。至少需要一条真实消息，最多六条；正文总字节数和 JSON 编码后容量都不得超过运行时审核槽的64 KiB上限。超限拒绝创建，绝不逐条裁剪。授权正文同时计入4 MiB触发器账本容量；容量不足不驱逐旧条件、执行回执或授权证据。

版本1、2旧记录和旧创建接口保留 `review_messages: None`，迁移不读取当前历史补造证据。旧记录仍可查询和取消；缺失冻结原话时宿主拒绝自动执行并记录失败原因。新格式里存在但为空数组、超过六条或超容量的原话视为损坏状态，启动失败且保留原账本，不自动清空。持久化后状态恢复及执行审核都只使用同一条触发器自身的冻结证据。

普通唤醒通过不可反序列化的 `ControlRunMetadata` 提交冻结原话；控制器核对用户、会话与任务编号，执行宿主标记为无人在线的委派运行。后来收到的新消息不能替换这份证据，任务正文即使伪造宿主前缀也不能选择来源。执行前仍复核当前主人或管理员权限，工具继续执行当前安全策略与危险操作审核。创建工具的回执不复制冻结原话到普通工具轨迹；原话保留在专用审核槽和账本中。

## 有条件地接续同一个后台任务

`resume_task_id` 指向本会话已有 Blocked 后台任务，与周期互斥。条件满足后由可信宿主调用 `TaskAdmin::resume_blocked`，不创建替代任务。示例在派发任务结束为 Blocked 后创建：

```json
{
  "title": "构建退出后核验",
  "instructions": "条件只表示构建进程退出；继续原任务读取日志并判断是否成功，不重新启动构建。",
  "resume_task_id": "task-原任务标识",
  "conditions": [{"type": "process_state", "pid": 12345, "running": false}],
  "expires_in_seconds": 900
}
```

宿主验证精确用户和会话、Blocked 状态、安全持久检查点、剩余工具步数和原总期限。没有检查点、存在待定工具或结果未知回执、预算耗尽、已进入预算收尾、原总期限已过的任务均拒绝接续，保存原现场。原任务仍可接续但通知正在发送时，返回明确的暂时繁忙结果：条件触发器和主体准入记录均保留重试能力，触发器退回 Ready，保留条件证据和原有效期，不增加运行次数或任务恢复次数；发送确认后下一轮自动接续。Ready 状态可跨重启保存；若原任务通知在重启后成为 Unknown，或等待期间原期限、预算已不允许接续，则停止并保留现场，不重放未知发送或工具。用户可以取消 Blocked 原任务，撤回后旧条件触发器也不能再接续。接续不追加步数，不重置已用工具、委派用量、模型请求数、恢复次数或总截止时间；条件接续消耗既有恢复次数，与失败自动恢复共用最多3次上限，不建立新恢复额度。父子共享预算仍由原执行器控制。

接续保留原任务 ID、冻结消息和工具回执，将上一轮阻塞结果、通知记录与条件证据作为历史数据写入同一检查点，清除已了结的最终文本并恢复 Running。下一轮沿该检查点推进，不能把旧工具调用当成待执行动作。宿主恢复 transcript 时也恢复已保存的工具回执，因而最后一次成功 `task_progress=blocked` 不会在模型超时接续后被误记 Completed；已有最终结果直接结算路径也保留这些证据。

严格纯文本合同的执行器不提供工具。宿主已确认条件解除时，仅为这类合同清除检查点中的等待标记，条件证据和旧结果仍保留在宿主历史事件中；后续文本必须通过原先冻结的合同，不能靠接续操作直接算完成。含工具回执的合同继续保存待核对事项，要求执行器显式确认剩余工作；所有接续仍受原预算、期限及未知副作用检查约束。

任务的原截止时间不会因为等待条件暂停计时。默认任务总期限30分钟；若30分钟时条件仍未满足，不能因为存在半小时周期检查就宣称原任务还能继续。用户需要更长目标周期时，应在既有授权与配置范围内明确设置期限，或在原目标的后续独立检查中报告已过期，不能自动新建任务扩张预算。

## 失败回执与安全复现

条件观察、准入、执行失败会保存结构化 JSON：`kind`、`trigger_id`、运行次数、`stage`、`execution`、`replay_safe`、观察证据和仅模拟的复现提示。明确失败和进程中断的回执也可通过原通道发送。进程退出时 Running 转 Interrupted；Sending 转 Unknown，均不自动重放。取消与扫描或结算竞争由持久 CAS 决定：输家只放弃该条转换，不终止所有触发器；真实存储失败仍关闭执行，不能静默回退。

定位现场先用 `list_wakeup_triggers` 查触发器与结果，用 `list_background_tasks` 查原任务的检查点摘要、剩余步骤和失败信息。复现应复制到隔离环境，用脚本模型、临时文件与模拟回执，保留原始状态；不得将未知工具调用、部署、发送或文件写入原样重放。上述 JSON 是定位回执，不能据 `replay_safe` 推导已有原任务副作用已经撤销。受支持的纯脚本失败另可用 `manage_failure_reproduction` 采集版本/数值fixture、真实隔离复现并验证候选；未知外部效果不能使用该入口自动重试。具体支持范围、持久化和容量见《失败现场与主体准入》。

验收命令（均无需生产服务）：

```sh
cargo test -p eve-trigger-api
cargo test -p eve-trigger-plugin --test recovery --test authorization
cargo test -p eve-task-plugin --test tasks
cargo test -p eve-runtime --test llm_host
cargo test -p eve-runtime --test control_run_metadata
cargo test -p eve-control-plugin --test run_metadata
cargo test -p eve-app qq_triggers::
cargo test -p eve-app qq_trigger_review::tests
```

触发器回归包含两个真实操作系统子进程顺序打开同一个 FileStateStore，验证半小时周期的下一次时间和运行次数跨进程保存；任务回归核验原任务接续、身份隔离、原期限与未知工具拒绝；运行时回归使用脚本模型制造 provider 超时，再验证正常恢复和已有最终结果恢复都保留 blocked 回执。
