# 长期目标持续推进

本实现延续现有学习目标、研究/实践账本和自主预算，不建立第二套执行器，不给模型追加权限或运行额度

## 停滞与恢复

启用现有 `--learning-stop` 后，宿主每轮从目标、兴趣、研究、实践、澄清和邀请账本读取事实

- 只有当前版本已无可继续工作、等待新资料的学习目标，连续 24 小时无外部新陈述、已得到引用来源的研究或已验证成功的实践，才暂停调度
- 运行中、等用户回答、等后续创作、预算不足、容量不足不视为停滞
- 暂停只写入 `pursuit-progress:v1` 检查点，目标仍为 Waiting，研究/实践准入读取检查点并跳过暂停目标
- 同一拥有者新增真实兴趣陈述，经已有兴趣派生器同步到目标后，仍有跨版本运行次数且没有运行中/中断不明记录时可以恢复
- 仅模型推断更新、服务重启、时间经过或预算窗口重置，不构成新外部证据
- 已取消、完成、阻塞、过期目标不自动恢复；不会撤销用户撤回，也不会重放执行结果不明的工作

`ProgressFacts` 只能由可信宿主构造，`can_resume` 不是语言模型授权。QQ 组合层验证用户、来源、同步修订、实际陈述数量、所有历史运行状态和剩余次数。恢复不改变目标 ID、预算、权限、研究/实践历史和全局自主预算

## 公平选择

开启学习推进时，仅兴趣学习目标参与公平排序，普通用户目标仍优先且保持原优先级。研究和实践分别以账本中最近真实开始时间排序：未执行过和最久未执行者优先，再比较既有优先级及目标 ID。每轮仍只启动一个，既有共享自主预算准入与扣账保持不变。历史时间随持久化账本恢复，重启不把已经执行过的目标重新当成新目标

这保证有限候选集内的目标轮转，不承诺多个后端之间的加权资源配额或抢占运行中任务

## 持久化与边界

进展事件追加到原有认知账本，与目标快照使用同一 CAS。暂停判断读取事实并保存的同步段，与研究/实践开始前重新读取暂停状态并写入运行账本的同步段，共用准入锁，锁不会跨模型请求或 await。轮询没有新事实时不写状态；暂停、恢复和新进展写入新事件，旧事件不覆盖。重启继续读取最新检查点，事件损坏直接报错，不清空、重置或默认放行

CAS 冲突返回 Deferred，下轮重新读取；事件容量不足时准入检查关闭本功能管理的学习任务，推进后台明确报告需要归档，不把无法保存的暂停当作成功；存储故障向后台传播。事件总量仍受认知账本既有 256 条上限约束，达到上限需要既有归档/运维流程处理，不能丢弃旧记录腾空间

当前仅集成兴趣派生学习目标，普通用户任务继续走原执行机制；对其他来源开放前需要对应的可信证据适配器。暂停记录不会扩大授权，也不代表实现通用人工智能
