# QQ 成功交互观察

可信组合宿主可以通过 `QqBotPlugin::with_interaction_observer` 接入 `QqInteractionObserver`，将已完成的普通交流交给可替换的本地记忆实现。未接线时沿用既有消息流程，也不增加 Session 读取。接线后插件显式依赖 Session 服务；正文、模型工具及桥接附加字段不能自行启用观察者。

观察者只收到通道构造的只读 `QqInteraction`。它包含 AppID、私聊或群来源、可信 SessionKey、原始消息 ID、已提交轮次 ID、用户原文和实际发送的回复。SessionKey 沿用 AppID、消息范围、目标和发送者共同隔离的映射；这不等于跨群、跨应用或跨用户授权。消息没有可信平台时间，观察者自己的时钟只能表示观察时间。

普通消息必须依次通过以下边界：

1. Control 报告同一完整生成代、`Completed`、无 failure、未取消，并给出有效轮次 ID。
2. Session 快照通过完整校验；同一轮次已完成，首条用户消息等于 QQ 原文，最后一条 assistant 等于待发送回复。
3. 回复展示资格仍有效，`ReplyPending` 已保存，桥接收到相同消息 ID 的回复命令。
4. 桥接确认匹配的 `delivery.ok=true`，且 `Sent` 保存成功后才调用观察者一次。

控制命令、`/train start` 发起轮和控制替代轮不观察；模型轮内部的工具消息不单独观察。失败轮、发送失败、等待确认、被撤销的旧代、重复输入及容量拒绝均不导入。

观察操作应是同步、有界的本地操作，不可发起模型、网络或嵌套通道任务。观察返回错误或 panic 时，通道保留已经保存的 `Sent`，记录固定诊断码 `interaction_observer_failed_no_retry` 并关闭，不撤销发送结果，也不重新调用观察者。提交凭据不匹配则在发送之前关闭并保留已有状态。

QQ 回执与观察者持久化不是跨服务事务：进程在保存 `Sent` 后、观察保存前退出，可能留下已投递但尚未采集的交流。首版在重启时不扫描补采既有回执，不将 `Processing` 或 `ReplyPending` 当作已投递，不自动重发。观察者应自行使用可信来源和消息 ID 去重，并如实保留自身提交失败状态。回执版本仍为 `receipts.v1`，既有数据不清空、不迁移、不伪造送达记录。

`cargo test -p eve-qqbot-plugin` 覆盖 Session 凭据替换、作用域隔离、真实 Node 子进程的延迟发送确认、发送及持久化失败、观察错误/panic、控制与训练排除、重启不补采和无观察器兼容行为。测试停止仅针对 Harness 所持有的内核和子进程句柄，不根据状态文件中的 PID 发送信号。
