# QQ 审核原文与恢复

危险动作的授权背景来自 QQ 通道认证后的独立原文库。SDK 的 `content` 原样放入 JSONL 的 `original_text`；`text` 仍可去掉机器人提及、转换表情和拼接引用、附件说明。两者用途不同。调试 `raw`、用户引用、附件名、模型输出、历史摘要及连发合并正文都不作为原话来源。原文保留换行、首尾空格和空正文；单条上限沿用 SDK 入口的 32768 UTF-8 字节，超限拒收，不截断。

同一 `AppID + message_id` 的原文和完整平台身份不可覆盖。审核按 `AppID + scope + target_id + user_id` 派生的完整会话身份查询，返回截至可信消息锚点最近六条独立正文，按接收先后排列。连发合并不会把多条原话变成一条。普通轮次通过不接受 JSON 反序列化的 `ControlRunMetadata::ChannelAnchor` 固定消息 ID；消息路由产生的新任务、修订任务沿用当前用户消息的锚点，只更新宿主分配的任务标识。实时引导在同一个队列锁内取出消息和批次末尾的锚点；后到而尚未消费的消息不会提前进入当前工具的授权背景。文字恰好以宿主事件提示开头仍然是原文，不按文字前缀删减。

原文保存在既有冷回执 SQLite 数据库的 `qq_originals` 表中，不写入可压缩的聊天历史。首次升级在一个事务中创建独立表、身份计数记录和禁止修改、删除、替换的触发器，使用 `PRAGMA user_version=1` 标记迁移。旧回执表不变。`review-originals.v1` 状态绑定该数据库身份与最低已提交行数；每次读写均在 SQLite 同一事务内核对绑定，提交原文成功后再更新状态标记，随后才准入模型。数据库先提交而标记尚未提交时崩溃，重启可接受同身份更大的行数；数据库缺失、回退、身份不符、原表或触发器缺损、非空原文库丢失状态标记均拒绝继续，保留原文件，不自动重建。

旧版本没有保存 SDK 原始正文，迁移不会把加工回执补充成原话。首次装配从已校验活跃回执中提取历史会话身份；冷归档策略为每个历史会话保留最新回执，因此也覆盖已归档正文的会话。这些历史会话在累积六条完整的新 SDK 正文前拒绝生成授权上下文，但可以正常进行不使用工具的文字交流：仅当独立原文库确认这是已记录的迁移缺口，且当前窗口内身份、绑定、消息锚点和每条原文都完整时，运行时移除本轮全部工具，不生成审核证据。模型主动提出的工具调用也在执行前拒绝。同轮后续引导不会重新开放工具；下一轮重新读取原文窗口，六条真实原文完整后才恢复常规工具审核。用户不必补说旧消息，旧历史也不会被写回原文库。委派任务与带检查点恢复的执行仍要求完整审核证据。

新会话可以从第一条完整原文开始。迁移缺口标记随状态持久化，重启不会清掉。旧桥接缺少 `original_text`、显式 `null`、以及包含绑定密钥的 `/bind` 输入保存缺口；任何最近六条内仍有这类缺失原文的轮次失败关闭，不进入上述文字模式，也不从显示正文猜测。数据库损坏、身份不符或不可用同样拒绝继续。附件消息真实空正文保存为空串，占据一个真实消息位置。

入站原文持久化、去重和群准入通过后，可立即调用宿主的同步缩权观察器。急停与撤销无须等待正在进行的模型审核；该入口只允许减权和取消。完整历史不可读但最新原文明确要求缩权时，宿主必须保留缺失事实并失败关闭，不能伪造六条授权背景。带冻结原话的后台任务及触发器使用专用委派证据，内部生成的任务说明不会新增一条用户原话。

这些校验保证正常读写、迁移、重启及可检测损坏时不会静默更换授权来源。持有宿主数据库和状态文件写权限的外部操作者可以同时回滚全部数据；跨存储一致回滚需要外部可信备份或独立高水位才能检测，不能由同一份本地状态自证未被改动。

## 迁移后自然聊天验收

`connectors/qqbot/test/receipt_capacity_test.py` 使用超过 10 MiB 的旧回执和真实 QQ 宿主进程验证：旧会话前两条普通聊天能正常完成，退出重启后继续三条普通聊天仍不提供工具，第六条完整平台原文到达后能够实际调用原文查询工具，再次重启后保持正常。全过程不依赖 `/admin` 等命令补足窗口；逐条核对热冷回执与原始旧记录相等，原文库中仅保存新收到的真实正文。

运行时回归同时覆盖模型强行返回工具调用时零执行、非迁移来源错误在模型请求前失败，以及同轮新消息不能重新开放工具。`trusted_review_originals_test.py` 继续核对原文完整性、连发和实时引导、独立审核等待中的撤销，以及缺失原文时不接受加工正文。
