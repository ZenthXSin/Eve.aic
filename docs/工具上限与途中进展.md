# 工具上限与途中进展

QQ 每轮最多处理 **50 个工具调用**，包括并行批次中的每个调用、未知工具、参数拒绝及执行失败。运行时默认 `max_tool_calls=50`，必须为正数；QQ 组合层固定为 50。开发配置的 `max_tool_rounds=0` 只取消批次数限制，不能绕过总数限制。更小的批次上限、模型请求预算、取消与单次超时仍独立有效。

若下一批大于剩余额度，**整批不执行**，避免悄悄执行前半批导致模型错误理解依赖关系。不会把未执行批次保存为已执行调用。QQ 随后请求一次不带工具的收尾答复，依据已有结果说明已完成、失败及未核实事项；恰好达到 50 次时直接收尾。OpenAI Chat 与 Responses 的无工具请求显式设置 `tool_choice: none`，完整及流式请求一致。

兼容服务仍返回工具调用时，该批不执行；宿主仅再请求一次独立的只读进度汇报。当前请求副本中的输入、历史、摘要、完整工具调用与回执全部作为历史 JSON 数据交给模型，并附上 `task_progress` 的剩余事项；旧执行提示及能力清单不再充当当前系统指令。只要求汇报已验证结果、失败或未知结果、剩余事项和阻塞，不要求用户重述原任务。沿用原先的历史窗口、150k 压缩策略、模型期限与请求预算，不另行截断原文，不经过后台任务的 2 MiB 委派入口。

这次汇报只增加一次模型请求，不增加工具步数；第二次仍返回工具调用时明确报告收尾失败，不无限重试，不自动派发另一个 50 步任务。取消及模型服务错误仍按原故障规则处理。已有工具回执与 Session/任务检查点保留原存储语义，重启不重放操作；没有新状态格式，旧版本可继续读取。新输入重新计算额度，需要继续未完成工作时由用户明确批准。

## 途中汇报

QQ 开启 `tool_progress_reports`。完整批次的工具回执返回后，宿主在累计调用数首次达到 **1、15、35** 时各产生一次 `ToolProgress` 事件，每批至多一次、每轮至多三次。单批完成 50 次调用只汇报一次；无工具结果的纯聊天不插入进展。

进展使用实际回执数、工具失败码数量和固定活动类别：源码与文件核对、资料检索、文件修改、命令执行、升级检查。不转述工具参数、路径、密钥或结果正文，不额外请求模型，不宣称业务目标成功。业务 JSON 的结果仍须最终答复核对，宿主计数不能替代业务验收。这是宿主里程碑反馈，尚不提供模型自由撰写的阶段小结。

QQ 使用有界队列，只按当前控制代绑定的平台消息路由发送。待处理取消、更正、切换和过期代抑制尚未写出的旧进展。模型继续执行期间仍可读取命令、平台回执及处理其他会话。

## 慢步骤进度

里程碑只看调用次数，单次很慢的模型请求或一批很慢的工具不会触发。QQ 通道因此按真实事件计时：

- 运行时发出“开始请求模型”或“开始一批工具”时，记为本轮当前步骤并开始计时；模型返回、本轮完成或失败时结束该步骤。
- 步骤持续超过 `runtime.progress.slow_after_ms`（默认 30000，环境变量 `EVE_PROGRESS_SLOW_AFTER_MS`，0 关闭，面板保存后下一次检查生效）仍未结束时，补发一条进度，例如“命令执行这一步已进行约 31 秒，仍在进行中；完成后会继续回复。”
- 同一步只提示一次，下一步重新计时。文字只含固定的活动类别（生成回复，或上节的工具类别）与已进行的秒数，不含参数、结果或模型文字。
- 与里程碑、压缩提示共用每轮至多 3 条进度和下面的被动回复配额，走同一投递、取消抑制、持久状态与恢复规则。步骤记录只在内存中，重启后不补发。

## 配额与恢复

`progress {id,index,text}` 与最终 `reply` / `segment`、附带邀请共同使用原消息 **5 次**被动回复预算。进展最多三条，`index` 从 0 递增；失败或未知尝试也占用预算。最终分段上限按剩余配额收窄，邀请有余量才附带。Node 独立校验进展序号与总配额，重复进展不重发。

进展回执为 `delivery {id,progress:true,index,ok}`。失败不重试，保留最终回复路由；35 秒没有回执时停止通道，保留未知状态。进展不改变整轮 Processing / ReplyPending / Sent 状态，不进入 Session 正文、成功交互观察或偏好训练。

原 Context `receipts.v1` 回执新增独立 `progress` 数组，写出前保存 `Sending`，平台确认后保存 `Sent` 或 `Failed`。有进展时文档格式为 **3**，既有格式 1 / 2 保持可读；旧程序必须拒绝格式 3。未知、损坏或超额状态不清空、不覆盖。

重启后 `Sending` 保留为“投递结果未知”，不补发进展、不重放工具，不将进展当作最终成功。已写出但结果未知的消息可能已在平台出现，不能撤回。回执仍受 4096 项 / 1 MiB 约束，新消息预留最终回复及进展的序列化空间；容量不足拒绝新任务，保留旧记录。

验收：`cargo test -p eve-runtime -p eve-qqbot-plugin -p eve-control-plugin`、桥接 Node 测试、`connectors/qqbot/test/tool_progress_test.py` 与 `slow_progress_test.py`（慢模型、慢命令、快速轮次与关闭、阈值前取消）。原生进程覆盖 50 次执行、超额并行批次、进展与分段配额、失败、取消、未知投递及独立进程恢复。
