# 持续自主运行

Eve 可以在授权持续有效期间自己回顾、选择想做的事，也可以休息、暂缓兴趣或改变方向。持续运行需要明确授权；一次任务或普通聊天不会被自动扩成长期授权。

## 周期与等待

当前可信主人或已获得业务权限的管理员，可说“持续自主回顾和行动，每天最多二十个目标，每个最多五百五十步，直到我暂停”。`configure_subject_autonomy` 使用 `continuous=true`，仍由原话审查确认持续意图。回顾、必要规划和行动各占一个目标名额；回顾本身不调用外部工具。

周期从启用时刻开始，每二十四小时最多 `max_goals` 个目标，不是午夜刷新。总派发序号持续增加，周期用量单独保存。重启与轮询不刷新额度；停机跨过几个周期只进入当前周期，不累计错过的额度。当前周期用尽后等待，旧的固定总额授权仍按原期限结束，不自动转为持续授权。

新消息、同范围前台在途执行、未知结果及未完成任务优先。模型选择的再回顾时间也必须到期。后台任务原有的同用户跨会话滚动二十四小时二十项上限和四项并发仍生效：额度暂满时等待，不提前消耗一个新的自主名额。若计划后被前台抢占名额，则保留同一个已计划关注，在原来源下重试受理，不另建目标或重复扣款。

`enabled=false` 暂停后续自主派发。已经开始的任务仍沿原取消与恢复规则；需要停止它时使用原后台任务取消入口。身份或业务权限撤销也会停止后续派发。持续授权不改变普通工具权限和行动审查，也不要求 Eve 每次都发消息或制造新任务。

## 宿主接入已有授权

部署操作者可用 `EVE_HOST_AUTONOMY_CONFIG` 指向一个本地 JSON 普通文件，把在部署对话中已明确给出的授权接入原调度服务。它不生成 QQ 消息、不增加对话轮次、不从模型自述推断授权，也不直接改写账本文件。

文件采用 `version=1`，包含唯一 `authorization_id`、精确 `scope`（`channel`、`conversation_id`、`principal_id`）、`max_goals`、`steps_per_goal`、`interests` 和完整 `review_messages`。文件上限 6000 字节，方向至多八项；范围必须匹配当前真实主人和已有非空会话。QQ 宿主启用后台任务时才接入；最小恢复组合未启用后台时只记录跳过原因，保留原授权而不派发。文件路径自动进入开发工具保护范围，Eve 不能通过自己的文件工具重写启动授权。

接入只发生一次。已有策略一律保持，包括暂停、到期和已用预算；启动配置不能覆盖已有策略。接入记录独立持久化，即使已取消策略后来被热关注容量回收，重启也不能复活授权。若接入记录已提交而关注写入失败，保留记录并停止接入；后续启动输出 `prior_receipt_without_policy=true`，不会默默再授予预算。操作者应核对原失败，通过正常授权入口恢复。

## 存储与恢复

`AutonomyWindow` 和 `AutonomyMemoryStore` 属于定义层，周期推进由主体插件实现，SQLite 实现独立历史，QQ/Web 组合层连接当前身份和执行器。独立 Web 仍只装配已有对话能力，本功能不额外为它开启后台循环。

`self-interests.sqlite3` 从格式 1 原子迁移至格式 2，原兴趣和修订保留，新增首次接入记录、问题派发预留及任务结算记录。先检查旧库结构和完整性，再提交迁移；损坏不清空。`self-interests.required` 沿用原缺库检测标记，启动时同时核对库内版本。迁移后恢复须用支持格式 2 的程序读取当前状态，不能让只识别格式 1 的旧程序继续写入。

同一范围内已预留的问题键不因周期变化、重新授权或热关注回收而再次执行。预留在关注和任务派发前提交；跨账本失败留下可核对记录，不把不确定结果当成“没做过”。旧版本仍在热关注中的已派发问题会补入索引，已经被旧版删除的历史无法补造。问题键只是明确问题的去重标识，不代表模型能够自动识别所有语义相同的提议。

已结算任务使用轻量目录与持久结算标识跳过，避免每秒重新加载完整任务正文，也避免旧关注被回收后不断重建。任务状态、结束时间、取消标志或恢复轮次变化时重新核对。原任务正文及回执仍由任务存储负责，结算标识不能替代实际成功证明。兴趣与自主索引按范围隔离，历史不自动清理，磁盘容量随经历增长。

## 验证

`connectors/qqbot/test/continuous_autonomy_test.py` 启动实际 Eve 子进程，以本地模型和 QQ 桥接替身验证周期用尽、重启保留用量、下一周期继续、真实工具暂停，以及宿主接入不伪造消息、暂停记录被热容量回收后不复活。测试仅修改已经停止的临时夹具时刻，不在产品中暴露改时间接口。

SQLite 测试覆盖超过热容量的去重历史、进程重开、精确范围隔离、格式 1 迁移及损坏原库保留。主体测试覆盖跨窗口任务配额与已结算关注回收。它们验证执行和恢复语义；自主选题、兴趣变化以及长期行为质量仍需持续观察实际回执。
