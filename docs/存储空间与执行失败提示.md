# 存储空间与执行失败提示

QQ 的协议检查失败与状态持久化失败分别提示。模型复用同轮工具调用 ID 时拒绝整个重复批次，已有工具结果保留；任务仍未完成而三次自动续行用尽时明确说明停止原因。协议错误按固定类别说明空回复、无效 JSON、工具参数、批次与终态、流中断、流标识或最终结果不一致，不向 QQ 输出原始模型回复、工具参数或错误正文；未知错误仍显示通用提示。

Chat SSE 的可选字段显式 `null` 与省略相同，包含后续工具片段的 `id/type/function/name/arguments` 和可选角色、响应 ID。它们不会清除已收集字段；终态仍必须提供完整、一致的工具 ID、函数类型、名称和合法对象参数，缺失字段、改变 ID、重复 JSON 键、截断流继续拒绝。仅解析兼容占位，不补造工具身份、不重发模型请求、不重放已执行工具。

失败会话的证据增加可选 `protocol_failure` 固定类别，Eve 的当前会话诊断工具也可读取；旧记录缺省为空，新轮次的原始响应与错误正文不写入。带新字段的记录须由支持该字段的版本读取，旧程序不认识字段时会明确拒绝，不能通过清空记录继续。回滚应保留失败数据并采用兼容版本或对应备份。

“收到回执”不等于“副作用已确认”：超时、取消和执行异常的回执可能只证明等待已结束。恢复提示最多指出三条调用的位置、工具名和固定失败类别，仍阻止自动派发，原始回执保留。准入前拒绝也有回执，但不计入启动数；恢复改为核对已登记调用与完整回执，并验证启动数范围，不能因两种计数不同而误报未知副作用。实际未知、缺回执、持久化不一致仍失败关闭。

结果提交失败、失败记录保存失败与会话存储失败会单独提示检查存储空间和权限。此提示不证明一定是磁盘满，也不把协议错误归因于存储。原始记录及未知工具副作用继续保留，不自动重启整轮、重放工具、清空损坏状态或提高预算。

文件状态后端使用整份快照的临时文件原子替换，至少需要容纳旧快照和待写入的新快照。后台编译与运行数据共用磁盘时必须预留空间；本次自升级的 Clippy、完整工作区测试和最终构建统一使用 release，复用同一套产物，避免重复生成 debug 与 release 两套缓存。检查项目、工具预算和失败停止条件保持不变。

清理范围限于确认闲置的 Cargo 构建目录、下载缓存和已经校验归档的打包中转副本。会话、记忆、凭据、源码、升级指针及其引用的运行/回退候选不作为缓存删除。清理释放空间后仍需重新核对运行状态；不能据此宣称历史失败都已修复。
