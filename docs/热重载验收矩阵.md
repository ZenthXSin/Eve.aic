# 热重载验收矩阵

本文件定义验收条件，不以接口存在代替通过。结果由对应真实测试和 CI 提供；未运行的平台不得标记为已验证。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 无状态旧调用执行期间激活新版 | 旧调用返回旧版结果；新调用绑定新版；宿主进程不重启 |
| 有状态版本迁移 | 读取已确认的源 revision；转换在无外部工具的隔离环境内执行；提交时再次 CAS |
| 迁移期间源状态变化 | 拒绝提交候选迁移，不覆盖新源状态或当前活动版本 |
| 迁移异常、超时、坏 schema、取消 | 旧活动版本和已确认状态保持可用；记录实际失败而非成功 |
| 回退 | 显式选择旧代码及其版本状态；不重放消息、文件写入或其他外部效果 |
| Rust 插件编译 | 只编译独立插件；不重新编译 Eve；编译产物绑定源码、编译器、目标和选项 |
| Rust 恶意编译输入 | 无法通过 include、构建脚本或编译器参数读取宿主私密文件或运行宿主命令 |
| Rust 编译失败或产物篡改 | 不激活候选；旧插件仍可调用；损坏缓存不能复用 |
| 运行进程崩溃 | 宿主仍可服务；未确认效果为 Unknown；不自动重放外部调用 |
| 父子插件与嵌套依赖 | 共用剩余预算、期限、身份与取消信号，不能重领额度 |
| 容器权限 | 真实运行 UID 不为 0，无宿主 socket、凭据、网络与可写宿主目录 |
| 容器资源与宿主退出 | 有独立硬期限和资源限制；取消清理进程及本次临时资源 |
| 跨平台 | Windows 实际运行隔离验证；缺少运行环境时报告阻断，不用模拟 CLI 结果代替 |

## 状态切换的限制

无状态版本可独立并存。有状态迁移必须明确如何取得稳定快照，不能为了立即切换而复制正在变化的状态。若当前协议要求源版本静止，应明确报告等待或拒绝，不能宣称已经完成无缝切换。旧调用的迟到结果只能写回其绑定版本，不能覆盖新版状态。

## 本次独立审查关注点

- 容器后端不能在 Windows 自动回退到 root，也不能因宿主源文件属于 root 而让插件以 root 运行。
- 版本句柄与真正并发切换须分别验证：能够保存两个版本，不代表可以在旧调用执行时切换新调用。
- 最小失败包中的轨迹回放不能代替执行复现；复现后的相同退出码或协议阶段也不证明内部根因完全相同。

## Rust 编译缓存的持续切换

编译缓存仍最多保留 32 个产物；满后按最近使用顺序回收没有被调用持有的产物。正在执行或准备执行的调用持有独立引用，不能被回收；所有缓存均被引用时，在开始新编译及扣除编译步数前拒绝，等待原调用结束。只有新产物编译并验证成功后才回收旧缓存，失败编译不主动删除旧产物。

缓存是临时产物，回收不删除已发布源码、版本句柄、状态或操作账本；再次调用旧句柄可能需要重编译，仍服从原调用链预算和期限。编译产物以固定缓冲逐段计算摘要，读取总量最多 16 MiB，拒绝超大文件、内容变化和最终文件符号链接，不把受损文件当成可执行代码。

本地 Linux 验收包含 50 个 Rust 版本逐次独立隔离编译、实际运行、显式激活，以及最初句柄被回收后的重编译和回退，返回值和活动版本均核对通过。原有在途旧版本、新调用、状态迁移、编译失败、取消、Unknown 不重放及共享预算回归同样执行。单元测试 11 项、真实沙箱集成 29 项通过（另有一个仅供子进程进入的辅助用例）；严格 Clippy、格式检查通过。此结果不等于多天持续运行、Windows 实际隔离或 Cargo 第三方依赖支持，后者仍单独验收。

## 编译诊断与修复

宿主可通过 `prepare_candidate` 区分已保存版本和编译失败；原 `publish_candidate` 保留失败返回错误的兼容语义。QQ 的 `save_script_plugin` 在失败时返回 `success=false`、`saved=false`、`compiled=false`、`executed=false`、`phase=compilation`、空版本及结构化 `compilation`：语言、实际退出码、终止信号、诊断前缀、截断标志。未成功编译的源码不发布、不切换状态，模型不能凭收到工具回执就宣称成功。

编译器 stderr 与进程等待并发处理，只保留最多 8192 UTF-8 字节，超出的内容继续排空以免管道阻塞；沿用原取消、20 秒编译期限和调用链预算。诊断不使用模型猜测，也不把业务执行的 Unknown 变成可重放错误。

Linux 实际沙箱覆盖不存在的标识符、大段中文编译错误的截断与不阻塞、失败候选不改旧状态、修复后独立编译并运行，以及 QQ 工具结构化回执。插件全套单元 11 项、实际沙箱集成 30 项通过，另有辅助进程入口不在父进程直接执行。

## 同一轮交互的修复链路

`connectors/qqbot/test/script_runtime_test.py` 启动实际 QQ 宿主，使用本地模型/桥接替身驱动同一轮连续工具调用：提交有错误的 Rust 源码、读取编译器实际诊断、保存修复源码、启用固定版本、dry-run、实际隔离运行并按调用 ID 查询回执。随后启动第二个宿主进程，读取一致的活动版本和持久回执，再以另一用户发起越界查询，要求拒绝且账本字节不变。

该实际进程用例分别使用 Rust 1.90 和项目最低 Rust 1.89 编译器本地通过，首轮有 7 次本地模型协议请求；不调用付费模型，不声称验证真实模型自主写代码的质量。QQ CI 新增 bubblewrap 安装和实际命名空间预检，脚本用例在 Linux 缺少沙箱时直接失败；原有成员开发隔离用例也不会因 CI 未安装 bubblewrap 而静默跳过。Windows 的实际隔离仍未交付。
