# 官方 QQ 入站与私信测试范围

主人允许在可测试时上线，并指定先只回私信、由 Eve 私发一条上线通知。本批接入发送范围与
入站事实/日志，尚未启动服务，不把本地验证当作真实 QQ 送达。

## 平台事件

实际读取 [单聊事件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/c2c_message_create.html)
和 [事件订阅](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/event-emit/payload.html)： 单聊
`C2C_MESSAGE_CREATE` 使用 `GROUP_AND_C2C_EVENT (1<<25)`，不是频道私信的
`DIRECT_MESSAGE (1<<12)`。订阅单聊这一位也可能收到群相关事件，发送范围必须独立限制。

官方注明消息可能重复推送；新事件结构用 `message_scene.ext` 的 msg_idx 区分同一 msg_id
下的并行消息，旧推送的 msg_seq 也可能有值。引用中的 ref_msg_idx 与发送/回复用的 messageId
不同，不能将二者互换。本批保留引用索引供详情解析，尚未展开嵌套引用或卡片正文。

`adapters/qq/inbound.ts` 将支持的 C2C/群消息转为平台事实；身份读取 user_openid/member_openid，
群目的地读取 group_openid，不从 author.id、昵称、正文、引用或群主角色猜“主人”。它不映射
用户权限，也不把平台 auth_token、资源 URL、原始扩展字段转给模型。原件由日志留存。

## 先持久化，再消费

`QqInboundJournal` 将原始事件与投影一次写入私有 0600 文件，文件同步、原子改名和目录同步
全部完成才返回 fresh。相同会话、平台消息 ID 与消息索引（旧事件无索引时用 msg_seq）再次
收到时返回已有记录，不制造第二次新消息；网关 s 与 dispatch ID 不参与消息去重。

重启重建本地序号与身份索引，拒绝重复编号、缺口、超大文件、原始事件与投影不符或损坏记录。 未完成 .tmp
与外来文件留原样报错，不静默删除。读出的副本不能修改内部记录。相同消息身份
但投影不同会停止该日志实例，保留原件并报告冲突，不覆盖原文或猜测哪份正确。

这里只是日志组件。还没有 WebSocket 消费水位、唤醒队列或意识流领取/提交；调用方需要把 fresh
记录可靠交给通知/意识流，再按官方建议持久化网关 s。不能仅靠去重日志宣称“消息一定
被处理”，也不能重启后直接重放历史全部已处理消息。

这份日志当前在内存保存索引和原件，启动时读取完整目录，尚未做大规模索引或日志分段；它不是
全量历史查询实现。仅支持一个进程写目录，外部守护/所有权令牌还未接通，不用于并行正式部署。

## 仅私信出口

`QqClientOptions.sendScope="private"` 在任何认证和发送网络请求前拒绝 group，返回
failed/attempted=false/scope。原通用组件默认 all 保持兼容；上线组合必须读取主人配置
replyScope=private 并显式传入，不能只在模型提示词里写“不要回群”。

本批回归用本地 HTTP 验证群请求为零，私信仍取得平台形式的编号。没有真实私信送达，也没有
多条发送、图像下载、引用展开或主动消息配额验证。主人身份绑定等 Issue #548 回复，未绑定
前不能向第一个私信用户发送“主人上线通知”。

QQ 提示词仍按企划案中的 qq-bridge 参考，候选交流原则见
[QQ 交互参考](./QQ交互参考.md)。模型实际使用、自然表达与旧经验采用继续单独验收。
