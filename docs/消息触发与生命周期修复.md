# 消息触发与生命周期修复

一次真实入站在长工具期间进入主线程，同时可以获得前台即时交流机会。此前两条路径没有原子交接；任务结果和健康巡检又把最后一条入站放在新请求末尾，导致多个不同事件反复回答同一句旧话。模型故障期间积压的健康事件恢复后逐条处理，会进一步放大这个问题。修复按事件来源处理，不比较回复正文，也不调用额外模型判断是否重复。

## 输入与后台事件

前台领取即时交流和主线程消费输入使用同一个锁。主线程先消费，前台不能再领取；前台先领取并保存 Sending，主线程一起收到用户补充与该输入的交流归属。主线程仍执行补充业务，正常结束不撤销已经交接的前台发送；真正取消、代际替换或可信输入变化仍阻止旧发送。失败转后台保留交接，Sending 和 Unknown 不冒充已经送达。具体恢复语义见[同一输入的交流职责交接](同一输入的交流职责交接.md)。

后台请求的末尾只包含本次事件。最后收到的完整原话保留在 System 语境中，用于理解纠正、取消和免打扰要求，不成为新的用户请求。新结果、需要追问的问题以及 Eve 自己的新想法仍可表达；不同事件选择相同文字也不被正文过滤器拦截。见[后台发言事件与用户输入](后台发言事件与用户输入.md)。

## 事件何时结束

同一健康问题持续失败属于同一次事件，确认恢复后结束原问题，再次失败才能产生新的事件。尚未发送的旧 Pending 在所有问题结束后退役；部分恢复保留未结束部分，未知观测不能冒充成功，也不能独自触发告警。启动后和领取前重新读取真实健康状态，避免直接发送上个进程留下的旧候选。已有 Sending、Unknown 与终态回执按原事实保留。见[主动健康巡检](主动健康巡检.md)。

条件唤醒只有在本次完整控制代匹配、运行提交成功、没有取消或失败，且原始最后一条助手输出是精确 `{"action":"silence"}` 时，才原子结束为 Completed + Silenced。中间不产生 Pending 表达机会。包含相似文字的业务结果、历史内部记录包装、失败与未知结果继续保留普通结果路径，不从其中提取静默协议。已观察到的包装回显不满足裸协议；其后续表达由后台事件语境修复处理，不能宣称原子静默一项就覆盖所有历史实例。

## 验证与上线

验收分别检查输入领取竞争、正常结束和取消、失败转后台、旧健康事件退役与复发、唤醒的严格结束语义，以及一次真实入站后多个真实到期事件的请求来源。重启后不重放旧消息或已执行工具，同时检查新补充业务仍能执行。测试使用实际 Eve 进程或 Rust 通道与 Node 桥接，模型和 QQ 出口为本地替身；这些证据不等于真实模型长期表达质量已经验收。

最终生产二进制的验收清单包含上述进程回归及后回复、缓存、群聊窗口和说法学习恢复。发布检查点在开放入站与后台工作前绑定真实进程和恢复状态；检查范围见[启动恢复检查点](startup-checkpoint.md)，不把健康账本当作该协议已精确证明的三份账本之一。新版写入新格式后保留当前状态，使用同一新版二进制的最小组合恢复，不能删除字段或用旧备份覆盖新经历来强行降级。
