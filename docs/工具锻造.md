# 工具锻造

这是[首个自主学习目标](./自主学习首个目标.md)（#134）第 5 条“反复遇到的能力缺口形成新的工具插件”的实现。在同一运行环境中，[实践验证](./实践验证.md)反复遇到同一个问题时，Eve 会尝试把它锻造成一个运行前检查工具。工具用实践账本里的真实草稿回放验证，通过后自动启用。之后的实践在实际运行前先经它检查：被拦下的草稿不运行，带着说明交给草稿器修正。

## 工具是什么

工具是数据，不是代码。它由 1 到 8 条只读草稿文件的规则组成：

- `require_file`：至少有一个匹配的文件。
- `require_text`：至少有一个匹配的文件，且每个匹配的文件都包含某段文本。
- `forbid_text`：没有匹配的文件包含某段文本。

规则的匹配模式是相对路径，或以 `*` 开头的路径后缀（如 `*.hjson`）。规则由契约内置的解释器执行，不执行任何生成的代码，也不触碰文件系统。所以工具不会给 Eve 增加新的执行权限，验证通过后在宿主既有授信范围内自动启用。

分层：
- **定义层**：`eve-toolforge-api` 规定规格、解释器、回放验证、锻造记录、版本与调用记录，以及 `ToolForger`/`ToolAdmin` 契约。实践契约新增 `DraftCheck`（运行前附加检查）与 `gap_key`（问题归类键）。
- **实现层**：`eve-toolforge-plugin` 提供账本、模型锻造器、锻造流程，以及作为 `DraftCheck` 实现的 `ForgedChecks`。
- **组合层**：QQ 宿主加入 `--tool-forging` 和 `/tools` 命令，并把检查挂到实践执行器上。

锻造器和账本都可以替换。

## 启用

```bash
./target/debug/eve-qqbot --state-dir .eve-qqbot --interest-learning \
  --practice-mindustry-server /opt/mindustry/server-release.jar --tool-forging
```

`--tool-forging` 默认关闭，必须同时指定实践运行环境（`--practice-mindustry-server` 或 `--practice-browser`），可以和 `--skill-learning` 同时开启。锻造复用主模型配置与 `EVE_OPENAI_API_KEY`。

QQ 命令：
- `/tools`：列出自己的工具（启用版本、版本数、检查与拦下次数）和最近的锻造结果（验证通过、未通过、复用、无法用规则识别、失败或中断）。
- `/tool 工具ID`：查看针对的问题、每个版本的规则、拦下时的提示、回放验证结果、启用记录与最近的调用。
- `/tool disable 工具ID`：停用。
- `/tool enable 工具ID 版本`：启用某个已验证版本。
- `/tool rollback 工具ID`：回退到当前版本之前的已验证版本。

工具只属于来源用户，并且只用于同一运行器。其他用户看不到，也不能更改。未开启时回复“工具锻造未启用。”。

## 锻造

每次实践之后（开启技能固化时在技能提炼之后），后台从实践账本推导能力缺口。只处理同时满足以下条件的缺口：

- 同一运行器下按 `gap_key` 归类、出现至少 2 次的结构问题或运行警告；`gap_key` 把数字换成 `#` 并合并空白。
- 不是运行前检查自身给出的问题（带 `[预检] ` 前缀的问题不算缺口）。
- 两侧都有真实草稿：出现过该问题的尝试，以及实际运行验证通过的尝试，各取最近的至多 4 份。被运行前检查拦下的尝试没有实际运行，不作样例。
- 用户没有停用这个缺口对应的工具。
- 同一出现次数还没处理过；每个缺口至多处理 3 次，只有出现次数增加时才再次处理。

对每个缺口按以下顺序处理：

1. **复用**：如果同一用户在该运行器下已启用的工具回放验证就能覆盖这个缺口，只写一条“复用”记录，不请求锻造器，不重复造工具。
2. **准入**：否则先保存 Running 的锻造记录，返回后才请求锻造器。
3. **锻造**：锻造器只收到问题原文、运行器说明和真实草稿文件，不含任务描述或用户原话；改进时附上同一缺口工具的当前规格。它至多发起一次无工具模型请求，输出严格 JSON，可以回答“无法用只读规则识别”。
4. **回放验证**：宿主用同一批草稿执行规格。出现过问题的必须全部被拦下，验证通过的一个都不能误报，否则记为“未通过”，不成为工具。
5. **启用**：通过后同一提交写入该工具的新版本；用户没有停用时，自动启用并记为“验证通过后自动启用”。

## 使用

实践执行器在运行器结构检查通过、即将实际运行时，调用该用户、该运行器当前启用的每个工具：

- 每次调用先写入调用记录（使用的版本、实践与尝试编号、发现的问题），返回后才把结果交给实践。
- 有工具发现问题时，问题加上 `[预检] ` 前缀记入这次尝试。尝试记为结构检查不通过，不启动运行环境。
- 草稿器在下一次尝试中看到这些问题并修正，修正后的草稿照常经运行器实际验证。

工具只能在运行前拦下草稿，不能代替实际运行。实践是否通过，仍以运行环境的证据为准。

## 持久化与恢复

工具账本保存在 `eve.toolforge` 的 `toolforge.v1` 状态键中，包含工具、锻造记录和调用记录。

**打开时校验，损坏不清空**：
- 账本按严格 JSON 读取，重复键、未知字段和版本不符都拒绝。
- 打开时整体核对。拒绝打开的情况包括：ID 与内容不符、版本不连续、版本的回放验证未通过、启用记录与当前启用版本不一致，以及锻造记录与工具版本对不上。
- 账本损坏时宿主拒绝启动，原字节不清空、不改写。

**先保存再动作，中断不重放**：
- 锻造请求发出前，Running 记录已保存。进程在 Running 时退出，重启后记为“中断”，不重放、也不伪造完成时间。
- 停止或超时（单次锻造 120 秒）时记为失败（取消或超时），不重试。
- 检查调用先保存再生效。

**提交失败**：提交无法确认时（可能已经写入），账本实例立即关闭，宿主停止并须重新打开核对，不在旧缓存上继续。

**容量上限**：

| 记录 | 上限 |
| --- | --- |
| 工具 | 32 个 |
| 每个工具的版本 | 8 个 |
| 启用变更 | 每个工具 64 条 |
| 锻造记录 | 64 条 |
| 调用记录 | 512 条 |

- 工具或锻造记录满时，保留原记录并停止新的锻造。
- 调用记录满时，暂停使用锻造的检查，实践照常实际运行，`/tools` 会明确显示。
- 记录都不会被自动淘汰。

## 边界

- 回放验证只用账本里已有的真实草稿，证明规则对这些草稿的判断正确，不保证覆盖今后所有写法。漏掉的新写法会在实际运行中再次出现，出现次数增加后可以锻造新版本。
- 工具只读草稿文件，不运行、不联网、不写文件，也不跨用户或跨运行器使用。
- 确定性替身测试只证明宿主契约与恢复语义；真实模型的锻造质量需另行评估。

## 验收

- `crates/toolforge-api`：规则解释、模式边界与回放验证判定。
- `crates/toolforge-plugin/tests/toolforge.rs`：用真实实践插件、替身运行器和替身锻造器覆盖以下场景：
  - 反复出现的警告锻造成检查并自动启用；
  - 另一条缺口被已有工具覆盖时只记复用；
  - 下一项独立实践的第一份草稿在运行前被拦下、没有运行，修正后验证通过；
  - 误报被拒绝；
  - 漏掉新写法后锻造第 2 版、回退与停用；
  - 中断、失败与放弃不重放；
  - 提交失败关闭账本；
  - 损坏账本拒绝打开且原样保留。
- `connectors/qqbot/test/toolforge_test.py`：实际 `eve-qqbot` 进程覆盖以下场景：
  - 两项独立实践都遇到 Mindustry 服务端替身的同一条警告，第二项之后锻造并启用；
  - 第三项实践的第一份草稿在运行前被拦下，没有启动运行环境；
  - `/tools`、`/tool` 的查看与停用、回退、启用；
  - 误报不启用；
  - 未开启时不请求锻造器；
  - 重启不重放。
