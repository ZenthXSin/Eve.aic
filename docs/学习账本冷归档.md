# 学习账本冷归档

QQ 宿主启用偏好学习时，会装配 FileLearningArchive，目录为状态目录下的 learning-archive。插件本身通过 LearningArchiveStore 公开契约接入，其他宿主可替换实现；未配置该能力的旧装配继续保留原容量保护，不自动丢弃数据。

## 保存与读取

每条学习批次保存完整输入、候选、记忆修订、失败和补做记录；每条决策保存完整作用域、连续序号和意图。正文按 SHA256 不可变保存，单条文件上限 128 KiB。写入流程先写临时文件并同步，再发布不覆盖的正文文件，最后原子提交插件状态里的格式 2 索引。索引单本上限仍为 32 MiB，旧的 1024 批次及 8192 决策限制仅对未装配冷存储的旧模式生效。没有删除历史来腾容量。

读取验证文件类型、长度、摘要、严格 JSON、批次绑定、消费去重及决策序列。缺失、损坏、未知格式不跳过、不清空。读取中发现异常关闭当前实例的全部学习入口；重开后重新核对。冷文件写入失败不提交索引，可能留下无引用文件；索引提交确认丢失则关闭实例，重开核对实际结果，不能自动重放工具或学习批次。原有中断补做的次数、期限和代数校验保持有效。

## 迁移和回退

原格式 1 的批次与决策仍可读取，单纯读取不会改写原账本。启用冷存储后，下一次对应账本写入会迁移成格式 2，两个账本允许逐个迁移；启动时先完整验证两本，再保存 Running 到 Interrupted 的恢复结局。冷正文不会因为格式迁移而消失。

旧二进制不能读取格式 2，会拒绝启动。迁移前应保留原状态备份；回退需恢复对应程序及备份。迁移后的备份、迁移或部署必须同时携带插件状态和整个 learning-archive 目录；仅复制 JSON 或 PostgreSQL 状态是不完整的。这里未提供自动删除或垃圾清理。

## 内存与容量边界

当前写入仍需载入并核对完整账本，操作结束释放冷正文，索引常驻；只读接口按页过滤到当前作用域，公开 snapshot 返回的该作用域历史仍由调用者持有。因此这是减少空闲数据驻留，不代表恒定峰值内存，也不能声称 RSS 一定立刻下降。

单本索引在读取冷文件前累计声明正文大小，超过 128 MiB 拒绝恢复；写入也拒绝生成超过该恢复预算的索引，保留已有状态。这是全历史兼容接口的临时保护，不是磁盘容量或 RSS 上限。逐作用域和按页消费仍待实现，不能把本实现称为无限长期账本。

## 验证

跨过 32 MiB 正文和旧批次数上限后，核对原文、继续准入、重启和不重复消费。跨过 8192 条决策后，核对追加序列、幂等判断及撤销历史。其他测试覆盖旧账本迁移、没有冷存储的旧装配拒绝新格式、正文损坏时不先提交中断恢复、冷写失败、提交前失败、提交后确认丢失和符号链接拒绝。

本地 QQ 替身进程继续通过学习触发、维护查询和决策恢复核对；它不代表真实付费模型质量或正式 QQ 平台验收。未部署。

## 固定版本分页读取

LearningAdmin 提供 scan_jobs 和 scan_decisions，默认适配旧实现的完整快照；内置实现固定创建时的不可变引用，每页最多 16 条，逐条读验并过滤到可信作用域。只读 snapshot/decisions 也通过该游标收集当前作用域结果，不在读取时恢复其他作用域的正文集合。游标遇到错误后永久拒绝继续，不能修复文件后接着跳读；重启不会激活旧游标。调用开始之后新增或更新的记录，只在新游标中可见。

索引暂时没有作用域倒排信息，读取小作用域仍可能遍历其他作用域的文件；不会向调用者返回这些正文。启动和写入仍使用全账本核验，因此 128 MiB 恢复保护仍在，尚未完成写入路径的分页化。旧实现的默认适配器仍先获得完整快照，不宣称其峰值内存已经降低。
