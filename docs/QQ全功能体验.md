# QQ 全功能体验

[全功能体验工作流](https://github.com/ZenthXSin/Eve.aic/actions/workflows/qqbot-full.yml)在 GitHub Actions 上把已合入 main 的 QQ 能力一次开启，手机上点 Run workflow 即可，不需要自己的服务器。凭据沿用仓库已有的 `QQBOT_APP_SECRET` 与 `EVE_OPENAI_API_KEY` Actions Secret，AppID 仍为 1904159860。

## 怎么用

1. 在 Actions 页面选“QQBot 全功能体验”，点 Run workflow。
2. 等“确认实际网关就绪”步骤变绿，就可以私聊机器人，或在已授权的群里 @ 它。
3. 窗口到时（默认 21300 秒，约 5 小时 55 分）后自动收尾，并上传状态包。
4. 下次想接着聊，把上次的运行 ID（运行页面网址里 `runs/` 后面的数字）填进 `continue_run_id`。

| 输入 | 默认 | 说明 |
| --- | --- | --- |
| `sandbox` | 关闭 | 打开后连接 QQ 沙箱，测试用户和群须在开放平台的沙箱范围内 |
| `seconds` | 21300 | 60 至 21300；从网关就绪开始计时 |
| `continue_run_id` | 空 | 接着某次已结束的全功能体验运行的状态继续；留空则全新开始 |
| `practice` | `mindustry` | 实践运行环境：`mindustry` 用校验过摘要的 Mindustry v160.7 无头服务端，并先跑继承的 JSON 预检；`browser` 用无头 Chrome 做网页实践 |
| `reasoning_effort` | `high` | 主模型推理强度：high、medium、low，none 为关闭 |
| `research_sources` | 继承资料的 `mindustry/`、`mod-making-guide/` 与 Mindustry 模组 Wiki | 受控研究入口，空格分隔，至多 8 个；可写 https 地址或 `eve-corpus://eve-portable/` 下的资料目录；留空则不做受控研究 |

工作流与[主动提问训练](./主动提问训练.md)共用并发组 `eve-qqbot-live`，同一时刻只有一个窗口连接机器人；训练窗口还在运行时，新的体验窗口会排队等它结束。

## 开启了什么

宿主参数集中在 `connectors/qqbot/training-window.py` 的 `FULL_PROFILE`，进程验收与工作流使用同一份：

- 对话：主动提问训练、分段投递、在途消息的主模型判断（`--message-judge primary`）、私聊提醒。
- 记忆：交互记忆、按本轮输入召回、持续自主学习（含偏好提炼与自动采纳）。
- 回复时查证：用 `search_reference` 和 `read_reference` 查 Mindustry v160.7 源码（含中英文名称表）、对应的 Arc 源码和继承资料，并引用路径与行号；单轮至多 50 批工具调用，用尽时不让本轮失败而是不再提供工具、按已查到的结果作答，见[回复时参考资料](./回复时参考资料.md)。
- 后台学习：内生反思、兴趣观察、受控研究（入口含 `eve-corpus://` 时同时装配仓库内的[继承资料](./继承-eve-portable-资料.md)）、实践（默认 Mindustry 加 JSON 预检，可选网页）、技能固化、工具锻造。
- 计划与交流：多步计划、待办完成确认、学习停止、请求澄清、议程上下文、主动邀请（被动窗口等待 30 分钟仍未送达时主动私聊一次）。
- 委托：后台任务（默认 50 步，做完私聊通知）与子代理（本轮内交回结果），见[后台任务与子代理](./后台任务与子代理.md)。
- 预算：后台模型请求每 24 小时合计至多 200 次（`/budget` 查看），回复用户消息不计入。

没有开启：语义召回需要单独的 embedding 模型角色；控制面板只监听本机，在 Actions 上无法访问；开发工具需要操作者配置。Mindustry 与网页实践只能二选一，由宿主参数校验保证。

模型为 deepseek-v4.1-flash（Chat 协议），默认开启 high 推理，单次输出上限 8192 token、请求期限 120 秒。各命令和行为见 [QQBot 通道](./QQBot通道.md)；私聊发 `/help tools` 可查看实际已装配的工具。

## 状态保存与续接

- **保存什么**：窗口结束后，完整状态目录（会话、QQ 回执、记忆、兴趣、计划、预算等全部插件状态）与计数报告用本轮 `QQBOT_APP_SECRET` 认证加密，存为 `eve-qqbot-full-results` artifact，保留 30 天。公开的 `training-summary.json` 只含时间、进程状态和计数，不含正文或路由 ID。
- **怎么续接**：填 `continue_run_id` 后，工作流核对来源是 main 上已结束的本工作流运行，下载其状态包，先认证后解密，再复制状态启动。原状态包不修改，可以重复续接；本轮报告只统计新回执与新轮次。
- **失败不会清空**：来源不是本工作流、artifact 缺失、认证失败、状态损坏或基线不匹配时，工作流在连接 QQ 之前失败，不会改用全新状态开始，也不会删除或改写来源。要从头开始，需要显式把 `continue_run_id` 留空。
- **取消**：在 Actions 里取消运行时，工作流先向 Eve 发送中断，最多等 150 秒，让它收尾并保存，然后上传状态包。超时、runner 被硬终止或 artifact 过期时，最新状态可能没有保存，工作流不会把这种情况报告为已保存。
- **轮换密钥**：状态包用当时的 `QQBOT_APP_SECRET` 加密；轮换 Secret 后，旧状态包无法续接。
- **跨工作流**：只能从全功能体验运行续接，不读取训练工作流的状态包。
- **换实践环境**：续接时可以改 `practice` 与研究入口，已有的实践、技能与知识记录照原样读回，不会被清空；新的实践只用本轮选择的运行环境。

Processing/ReplyPending 回执、在途后台任务和投递不确定的消息仍按各插件原有的恢复语义处理：重启不重放、不补发，见 [QQBot 通道](./QQBot通道.md#去重提交与恢复)。

## 边界

托管 Runner 不是常驻宿主：每个窗口最长约 6 小时，窗口之间机器人离线，提醒与主动邀请要等下一个窗口才可能送达。计数报告只覆盖 QQ 回执与会话，后台学习、计划与提醒的记录在加密状态包中。真实模型的体验质量和后台学习效果未经验收，进程验收只证明全部能力能一起启动、收发并从加密状态包续接。
