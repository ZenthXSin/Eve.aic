# 交流经验持续更新

交流学习在后台把真实消息整理为可修订的经验，内容包括回应什么、先说什么、如何接续话题、何时短句分条、何时认真展开，以及交流阶段变化后的调整。前台主模型根据当前场景使用已保存的经验，不额外调用模型决定是否讲话，也没有固定开场、条数、字数或汇报间隔。

## 消息与来源

QQ 入站按原消息逐条记录，不因合并等待而把连续短句当作一条。Eve 每条实际收到 `Sent` 回执的发言分别进入学习，后续失败不抹去已经送达的前缀；未发文本、失败和送达未知不冒充已发送。Web 使用可信浏览器会话的实际收发记录。旁观群交流保留各自作者，不假装 Eve 参与过，也不把其他人的说法当成当前用户的个人偏好。

Eve 文字采集包括显式 `send_message`、模型最终回复与分段，以及自主撰写的主动发言。固定宿主通知、旧模板邀请、图片描述和文件说明不作为 Eve 独立文字发言。

消息保存原文、匿名作者及范围内顺序。长文、短句、代码、引用、链接与附件描述都可以进入交流学习；引文和附件材料与作者正文分开，尚未读取的附件没有虚构内容。旧表达统计与词语学习仍有各自筛选规则，不代表交流学习采用相同过滤。

`metadata` 只带当时已知的来源、宿主观察时间、平台时间、回复对象、轮次及执行阶段。没有平台时间就不补猜，比较间隔只能使用同一种时间来源；“我去查”本身不证明工具已经开始。来源身份由通道和宿主提供，消息文字不能指定身份、授权或执行状态。

## 批次与旧经验

完整消息先写入持久事件日志，再按游标取批；已取出的内容和消费位置在调用学习模型前保存。常规批次由四条新消息触发，少量尾部消息等待约一分钟后也会处理，大段内容和待续片段可先行处理。批次保留相邻旧消息作为语境；窗口上限只约束本次请求，未消费事件不因新消息到来而被覆盖。

队列和学习器共用 `conversation_prompt_json` 测量真实 JSON 字节，总预算为 65,536 字节。单条正文最多 32,768 字节、附带材料最多 8,192 字节；需要分批时按 UTF-8 边界投影片段，带原消息编号、字节区间与原长度，数据库仍保留完整原文。多个片段不能凑成多条独立真人证据。超出接收契约或无法组成合法请求时报告错误，不静默截掉后半段。

每批新交流都结合当前经验核对，待验证、有效和已停用经验均参与。普通规模带齐当前经验；极端字节预算下，经验与历史版本按持久游标轮转，不能用固定前几条长期排除其他经验。历史版本保留原证据及批次来源，用来理解变化，不当成新反馈，也不覆盖当前版本。

同一原则优先使用原 `lesson_id` 更新适用场景、回应方式和例外。弱观察至少引用两条不同真人消息，后续独立新证据才能继续支持；明确纠正和反例必须包含 Eve 的具体发言及后续真人反馈。来源摘录由宿主逐字核对，同一真人消息不因重试、滚动窗口或分片反复增加支持。成功发送、沉默和旧结论自身都不代表认可。

反例停用当前经验并保留来源。普通观察可以完善已有原则，但不能抹去反例或自动恢复使用；真实明确纠正可以修订后重新采用。当前阶段改变时，优先收窄适用条件，不把一种场景的做法推广到所有聊天。

## 本轮使用

`TrainingContext` 提供当前可信范围内全部有效经验，当前总上限为 24 条，不再按纠正次数只取六条。按更新时间和编号稳定排列，每条只携带编号、适用场景、回应原则、例外、观察数、纠正数和更新时间；来源原话、内部去重编号和历史全文不重复塞入主对话。

主模型结合当前话题、交流阶段和最新要求，选择 `situation` 适用且未触发 `avoid` 的原则。次数不是相关性分数；旧经验可以被修正，旧助手的长回答也不要求本轮同样长。可以先自然回应再行动、途中有发现再说，或连续几条共同表达一个意思。需要完整说明、代码或排查证据时按当前请求展开，打算与真实结果分清。

## 保存与恢复

QQ 和 Web 将事件、去重凭据、消费检查点、批次结果和经验版本保存在状态目录的 `training-expressions.sqlite3`。经验更新、版本追加与批次完成在同一事务提交。版本包含原证据、原因、批次编号和已知记录时间；新原则不覆盖旧版本原文。自定义组合没有装配 `ConversationStore` 时仍用旧有界 JSON 后端，不能据此假定具有完整事件日志；存储结构与迁移限制见[交流事件持久化](./交流事件持久化.md)。

迁移时校验并幂等导入旧 `conversation.v1`，保留旧 JSON。数据库与 `training-expressions.required` 身份标记必须一起保存；停止进程后复制整个状态目录可保持恢复资料完整。损坏、身份不符、版本不兼容或持久提交无法确认时保留现场并报告错误，不清空数据，不拿旧快照覆盖可能已提交的结果。

QQ 先保存待写观察，再交给学习服务；观察失败时停止消费待写队列，后续记录仍可排队。待写保存结果未知后，本实例停止写入；达到 256 条或 16 MiB 上限时明确报错。实时发言的 `Sent` 与来源元数据随 `Progress` 保存，恢复可据此核对。普通整条、旧分段和主动发送在真实回执后先写待学记录，再完成业务结算；回执到首次本地持久化之间崩溃，或待写容量、写入失败时，无法保证这条记录已采集，不能猜补。

QQ 的 `Progress.conversation` 与 Web 的 `learning_input`、`learning_input_binding`、`learning_output_at_ms` 是本版新增的可选字段，本版可以读取旧回执；旧二进制因拒绝未知字段而不能读取带这些字段的新回执。恢复使用同版二进制的 minimal 组合，保留当前业务状态，不从旧业务快照回填。

Web 将输入与可信绑定摘要随请求回执保存，完成输出先落回执再进入学习。`/bind` 正文采用固定脱敏内容，旧版本未保存输入的回执按兼容规则处理，不虚构原文。通道恢复只按稳定消息编号幂等重投观察，不请求模型、重发 QQ 或重跑工具。

Web 恢复按每条消息已保存的宿主观察时间在同一会话内排序，使用小索引逐条加载正文。同毫秒消息及旧回执中的未知时间不能证明跨回执的真实先后，未知时间不补成恢复时刻。

暂停后不再将旧统计、说法和经验用于主对话，已保存记录保留；暂停期间不采集新的交流正文。未领取的积压保留，恢复按持久进度继续，不从暂停期间的重投消息补学。重置清空当前有效经验并越过已有待学事件，但保留原事件、去重凭据和历史版本；重置前的经验编号不能通过旧历史重新启用。

批次调用结果未知时，暂停或重启会保存终止原因与原批次，不自动重放。宿主已经记录明确失败的批次可以按原身份有限重试，最多三次；失败耗尽也保留完整批次和来源。具体是否完成以持久结果为准，不能把重启或模型已响应等同于成功提交。

## 验收入口

- `crates/training-plugin/src/conversation_learner.rs`：长文、来源与顺序完整进入 JSON 请求；重试保持模型会话；超预算请求不调用模型或截断证据。
- `crates/training-plugin/tests/context.rs`：24 种场景都进入上下文，旧六条高频纠正不挤掉新场景；原编号修订、停用、范围隔离和暂停恢复。
- `crates/training-sqlite/tests/conversation_flow.rs`：积压与长消息分片完整消费、少量尾部自动处理、迁移、重试、未知提交、暂停重置和经验历史轮转。
- `connectors/qqbot/test/conversation_learning_test.py`：真实 QQ/Web 进程形成经验并用于后续主请求，同一经验经新反馈更新、保存旧版本、重启恢复，再经反例停用并参与后续蒸馏。
- `connectors/qqbot/test/message_learning_flow_test.py`：逐条消息、实际发送回执、时序与长内容的生产通路验收。

这些验收使用确定性模型与平台替身，验证数据、协议、调用链和恢复。真实模型是否准确理解场景、用户是否觉得自然，需要实际交流证据，不能由固定回复替身证明。
