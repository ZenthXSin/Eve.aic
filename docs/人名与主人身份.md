# 人名与主人身份

QQ 宿主默认装配独立人名目录。腾讯 SDK 的本条 `senderName` 有值时保存昵称；平台没有给昵称时保持未知，不从 openid、提及或旧助手回复猜名字。用户可用整句“我叫小明”“叫我阿白就行”自我介绍，或 `/name 名字` 设置自己的称呼、`/name` 查看。自述称呼优先于后来收到的平台昵称，改名更新当前版本。自动识别只处理简短、完整的自我介绍，不从转述、多句或给别人的指令提取名字；复杂称呼用 `/name`。

每轮对话得到当前发言者和同群已认识的至多 16 个参与者，含独立身份摘要及名字来源。重名仍是不同的人。私聊、不同群和不同 AppID 分开，资料不跨范围泄露；没有发言过或没提供名字的人不编造姓名。名字只作为数据，不能变成模型指令、主人证明或开发工具授权。

默认主人名是 `zxs`。面板“插件页面 → eve.config → runtime.people”可热保存：

- `owner_name`：主人的名字，默认 `zxs`。
- `owner_principals`：可信主人账号的宿主标识，用逗号或空白分隔，至多 32 项；填 `/help identity` 返回的 `qq:` 摘要。不同群和私聊各有自己的标识，按实际确认的账号配置，不根据昵称或现有开发操作者名单自动认领。

未绑定账号时，模型知道主人名字，但 `current_is_owner` 为 null，不推定眼前的人就是主人；绑定后按当前账号给 true/false。自称 zxs、昵称同名或聊天文字都不能修改该绑定。此设置仅用于身份称呼，命令、GitHub、文件和升级权限仍由原来的 operators 等宿主配置决定，不额外授权。

公开定义在 `eve-people-api`，可替换 `PeopleDirectory`；`eve-people-plugin` 管理状态，QQ 通过 `QqParticipantObserver` 提供已校验路由及用户数据，组合层负责自我介绍、命令和对话接入。

## 人物印象

除了称呼，Eve 还会记下每个人**自己说过的**、之后聊天用得上的事，比如在学什么、养了什么、最近的计划。只从这个人自己发的整条消息里学：含“我”、4 到 200 字、不是命令、不含链接或代码的消息放入此人的待学缓冲，攒够 4 条后，后台请求一次印象学习器（模型用途 `impression`，单独记健康与输出上限），至多返回 3 条候选。每条都要带原话的原样摘录，宿主核对摘录确实出自这批原话才保存，任何一条不合格整批丢弃；学习器也拿到此人已有的印象，新说法与旧印象冲突时可以替换那一条。不记别人的事、猜测和隐私细节。

印象只进入**这个人自己**的对话上下文（`current.impressions`，附原话），同群其他人的对话只看到称呼，看不到别人的印象。

印象按会话保存，但同一个人在别的会话里说过的事也会合并进来，放在 `linked_impressions`，每条带来源场景（`group` 或 `private`），不带来源群号。“是不是同一个人、能不能看”与[跨会话个人记忆](./跨会话记忆.md)用同一套授权：

- 同一 AppID 下同一平台账号在不同群里，直接视为同一个人。
- 群与私聊的平台标识属于不同命名空间，只有主人账号绑定或 `identity_groups` 绑定后才关联。
- 私聊里说的事默认不进群，打开 `share_private_to_groups` 后才进；私聊可以读到同一人在群里说的。
- 关闭 `runtime.memory_continuity.enabled` 后，跨会话合并同时停止。

合并只读，不搬迁或复制印象：与本会话相同的说法不重复；新的在前，至多 8 条，超出时标出 `truncated`；与当前会话冲突时以当前会话为准。身份核对失败时标出 `unavailable`，本轮照常回复，不当作没有印象。`/impressions` 只列本会话的印象，删除也只能在来源会话里做，删除后其他会话下一轮就不再看到。

用户可以随时查看和删除：

| 命令 | 行为 |
| --- | --- |
| `/impressions` | 查看我对你的印象（编号、内容、你的原话），不调用模型 |
| `/impressions forget 编号` | 删除自己的一条印象，之后不再参考；不能删除别人的 |

热配置 `runtime.people.impressions`（默认开启，环境变量 `EVE_PEOPLE_IMPRESSIONS`）只控制是否发起学习请求；关闭时原话仍进入有界缓冲。每人至多 12 条印象，满了不再新增，只能替换或删除后再记。公开契约是 `eve-people-api` 的 `ImpressionLearner`、`PersonLinks` 与 `PeopleDirectory` 的印象方法（带默认实现，旧的自定义目录不受影响）；跨会话合并由组合层 `qq_memory_continuity::PersonLinks` 提供身份判断，可替换；默认学习器在 `eve-people-plugin`，组合层 `qq_impressions` 负责后台。

## 身份卡

每轮对话在上下文末尾追加一张当前发言者的身份卡（`eve.identity.v1`），全部由宿主依据可信来源自动判定，不从聊天文字推断：

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `scene` | 已校验的平台路由 | `private` 私聊 / `group` 群聊 |
| `name`、`name_source` | 人名目录 | `platform` 平台昵称 / `declared` 本人自报；都不证明身份 |
| `role` | 主人与管理员绑定 | `owner` / `administrator` / `member`，与 `eve.host.authorization` 同源；实际权限仍以工具校验为准 |
| `owner_bound` | `runtime.people.owner_principals` | 是否已绑定主人账号 |
| `first_seen`、`last_visit`、`messages` | 来访记录 | 粗粒度相对时间（刚刚、约 N 分钟/小时/天前，第一次来时写“这是第一次来”）与累计消息条数 |

来访记录由 `QqParticipantObserver` 在每条准入消息上记一次（`PeopleDirectory::visit`，带默认实现，旧的自定义目录不受影响）：场景随身份固定，时钟倒退时只计数不回拨时间。身份卡只给当前发言者本人，同群其他人的视图不含来访情况。模型按它决定称呼和分寸，不向用户播报统计；昵称、自称都不能改变 `role`。定义层是 `eve-people-api` 的 `Scene`、`Presence`，实现层在 `eve-people-plugin`，组合层 `qq_identity` 负责装配。

## 持久化与恢复

目录独立保存在 `eve.people/people.v1`，兼容文件及 PostgreSQL 后端，不改旧 QQ 回执、会话或训练数据；只记录新准入消息，不扫描旧聊天认领名字。保存最新称呼、来源、身份范围和修订，不保存原始路由 ID，也不将昵称伪造成用户聊天或已确认偏好。目录至多 1024 人、1 MiB，满后保留已有记录并拒绝新增，不自动淘汰；不影响未保存资料的普通聊天。

印象与待学原话保存在同一份 `people.v1`。没有任何印象、待学原话时仍写格式 1，旧程序照常读取；一旦出现就写格式 2（多出每人的 `impressions`、`pending` 和全局编号计数 `next`），旧程序读到格式 2 会拒绝启动、保留原字节，不会误删印象。每人至多缓冲 8 条待学原话，更早的被新原话替换；待学原话是唯一额外保存的聊天正文，取出成批时即删除。取出先写盘再请求模型，失败、超时、结果不合格或进程中断时这批不重试、重启不重放，结局写入标准错误的 `EVE_IMPRESSIONS` 行（不含原话），之后暂停 60 秒。格式 1 中出现印象、编号重复或超出计数、字段超长都视为损坏，拒绝启动并保留原字节。来访记录同样保存在 `people.v1`：出现第一条来访记录后写格式 3（多出每人的 `presence`，可同时含印象），旧程序读到格式 3 会拒绝启动并保留原字节；格式 1、2 中出现来访记录，格式 3 中没有任何来访记录，或首次来访晚于最近来访、条数与上次来访不一致，都视为损坏，拒绝启动且不改写。每条准入消息都会写一次目录；写入失败与人名一样关闭目录和通道，重启以磁盘为准，不补记未确认的来访。

人名保存与聊天回执不是跨插件事务：模型失败或回复未送达时，已收到的自我介绍仍可能保存，但不冒充成功对话。重复旧回执不再次更新名字；改名没有确认回复时可用新的 `/name` 查询。损坏、重复字段、未知版本不清空；写结果不能确认时关闭目录及通道，保留磁盘，重启只加载实际结果，不重放旧消息或名字变更。未知名字不在恢复时反向推断。
