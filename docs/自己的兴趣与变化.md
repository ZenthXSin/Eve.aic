# 自己的兴趣与变化

Eve 可以从实际交流和自己做过的事情中形成兴趣，记下吸引自己的原因、想尝试的具体事情，并在后续经历中改变看法。用户的爱好、配置中的探索方向和 Eve 自己的兴趣分别保存；没有预置一组必须喜欢的主题，也不要求每次回顾都提出工程任务。

## 形成与行动

空闲回顾的 `interest_updates` 每次最多提交两项变化：稳定的 `key`、主题、强度、理由、想尝试的事以及来源 ID。状态为好奇 `curious`、想继续 `active`、暂缓 `resting` 或放下 `dropped`。前两种必须写清自己想尝试什么；空更新保留原兴趣，不表示删除。

兴趣属于可修正的主观判断，不能宣称仅凭字段就具有人的感觉或已实际体验某事。每次新建或改变兴趣，至少要引用一条当前冻结材料中的新交流或行动结果，并说明自己的理由。反复读取自己的旧回顾不能形成新经历，来源去重覆盖该兴趣的完整历史；同一主题不能换一个键绕过原来放下的记录。已放下的主题仍能因新经历重新感兴趣。

行动提议可以用 `interest_key` 关联一项好奇或活动中的兴趣，包括本次刚形成的兴趣。暂缓或放下的兴趣不能直接驱动行动。兴趣只是选择依据，执行仍沿原真实授权、预算、工具权限和验收合同。行动结果进入后续回顾，可以继续、降低兴趣或放下；不以固定计划假装兴趣自然发展。

## 上下文与查询

聊天和回顾自动读取当前相关视图：优先好奇和活动项，再按强度与更新时间选择，最多八项、4096 字节；整份认知超过原 8192 字节关注上限时进一步减少自动展示项。这个上限只控制上下文，不限制终身兴趣数或修订次数。未展示的记录继续保存，不能被当作不存在。

已有工具 `manage_subject_focus` 提供两个只读动作：

- `{"action":"interests","limit":8}`：当前范围的兴趣列表、总数和认知修订。存在 `next_after` 时，用它作为下一页的 `after`。
- `{"action":"interest_history","id":"稳定兴趣键","limit":8}`：该兴趣按修订先后的变化。存在 `next_after` 时，作为下一页的 `after_revision`。

每页一至十六项，默认八项。兴趣列表分页是读取时的当前值；多页之间发生变化时可比较 `revision`，不承诺跨页的同一时刻快照。历史记录不可改写，第一次导入旧状态时可能从已有修订开始，不补造更早历史。查询绑定当前可信的精确作用域，参数不允许指定他人身份或会话；私聊内容不会自动传播到群或其他窗口。

## 持久化与恢复

契约在 `eve-subject-api`，来源校验和纯认知修订在 `eve-subject-plugin`，独立持久化在 `eve-subject-sqlite`，QQ/Web 组合层负责接线。存储接口可替换；仅使用不带持久历史实现的旧插件时，仍遵守原快照容量限制。

状态目录中的 `self-interests.sqlite3` 使用事务同时保存回顾输入、输出、当前认知、兴趣修订与来源消费。`self-interests.required` 标记此库已经初始化，`self-interests.lock` 阻止两个宿主同时使用。删除数据库而保留标记会停止启动，不创建空库；数据损坏、写入失败或提交结果不能确定时关闭该句柄，保留现场供恢复。不会在失败时覆盖旧数据、回退旧缓存或返还已消耗预算。

主体关注 `idle-mind-v1` 只保存有界投影。数据库提交后进程中断、投影尚未更新时，可据持久任务结果补投影，不重复增加修订、刷新期限或再次执行行动。旧认知第一次接入会保留已有兴趣、修订、时间与消费来源；没有记录过的历史不能推断补齐。保存过独立历史的投影带 `archived` 标记，缺库时不得用投影重建完整历史。

备份与迁移应保留完整状态目录、独立数据库及初始化标记；运行中复制数据库应使用 SQLite 备份接口，不能只复制正在写入的主文件。恢复后使用认识本格式的版本继续运行，不把新状态交给忽略独立兴趣历史的旧程序写入。持久历史目前不自动清理，容量随实际经历增长。

## 验证

`eve-subject-sqlite` 测试覆盖八十项兴趣、同一兴趣八十一次修订、重启恢复、超过旧去重窗口后仍拒绝重复经历、原子写入失败、缺库与并发宿主拒绝、损坏索引和跨范围隔离。应用测试检查投影恢复幂等及连续回顾不挤掉实际行动结果。`connectors/qqbot/test/idle_loop_test.py` 使用真实进程、模型与 QQ 替身，验证形成兴趣、实际文件实验、根据结果改变兴趣及聊天查询历史；它验证功能闭环，不证明长期选择质量或人的主观体验。
