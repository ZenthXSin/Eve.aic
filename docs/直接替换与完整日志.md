# 直接替换升级、第三方 QQ SDK 与完整日志

2026-11-13 按主人要求，生产自升级默认直接替换。固定完整 Git 提交的低 UID
检查和测试通过后，停用旧实例并终止其进程、排空真实出口，从同一业务数据目录以同一 UID/GID
启动新程序。机械健康和独占所有权通过后记录
`confirmed / direct_replacement_healthy`。不再复制账本、准备旧版观察快照、试聊或等待旧 Eve 确认。

实例控制连接与凭据仍分开；程序和配置可回退，意识流、脚本、未知动作及已完成动作留在原目录继续使用，不回退业务游标。新版启动失败恢复旧程序。历史并存观察模式保留用于旧状态恢复及专门测试，生产申请不使用它。

QQ API 使用 Satori/Koishi 生态的 `@satorijs/adapter-qq@4.14.1` 正式发布版中的真实 Internal
请求执行实现与完整 group/guild 路由表。固定上游提交、npm 完整性和 MIT 许可见
`adapters/qq/satori/upstream.json`；没有引入上游另一套自动网关和发送重试循环。官方 SDK
路由实现已移除。

QQ 请求先解析当前 DNS 地址，并发验证 TCP/TLS，选择首先完成证书验证的连接后才发送认证信息或
POST。失败地址不会阻塞健康地址，不固定 IP，不降低证书验证。一次消息提交只发一次，超时保持
unknown，不盲重发。文字、Markdown、图片、文件及系统指令回执统一主动发送，不带
`msg_id / msg_seq / event_id`。展示引用不改变主动发送性质。

`tools.upgrades.logs({})` 列出全部可读日志源：源码命令失败原始
stdout/stderr、升级检查和测试全文、准备失败堆栈、各实例输出，以及
guardian/runtime/qq-adapter/supervisor/admin 五个 systemd 服务的全部留存日志。QQ 连接诊断包含
requestId、目标 IP、DNS/TCP/TLS/写出/响应/完成各阶段，不记录认证秘密或消息正文。

文件日志按字节分页，返回 base64 数据、`nextOffset`、`totalBytes` 和 `eof`；先拼接解码后的字节再作
UTF-8 解码，避免跨页中文损坏。系统日志首次省略 cursor，从最早留存条目开始，后续使用
`nextCursor`，到末尾后仍可读新增。每页大小用于传输，不限制可读取的日志总量。检查/测试日志落盘已取消原来的
8 MiB 截断。系统日志只能读取机器实际留存的历史，不能恢复此前已被清理的记录。

```ts
return await tools.upgrades.logs({});
// 从目录选择 source；保留 nextOffset / nextCursor 继续读取。
```
