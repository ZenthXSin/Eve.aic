# 自主驱动真实交互验收

这条验收只测试 Eve 的自主驱动闭环，不向真实 QQ 群或联系人发消息。它使用一个隔离状态目录和真实主模型；模型只被允许返回结构化反思 JSON，工具预算固定为 0。

## 1. 构建

在仓库根目录执行：

```bash
cargo build -p eve-app --bin eve-cognition --locked
```

准备一个全新的状态目录，并确认 `AGENT.md` 存在。主模型凭据只通过宿主环境提供：

```bash
export EVE_OPENAI_API_KEY='...'
export EVE_OPENAI_MODEL='deepseek-v4.1-flash'       # 可替换
export EVE_OPENAI_PROTOCOL='chat'                   # 可替换
export EVE_OPENAI_BASE_URL='https://api.deepseek.com' # 按实际服务填写
```

不要复用旧验收目录，也不要把密钥写入状态目录或日志。

## 2. 直接对话与工具自动装配

普通主人会话不需要 `EVE_DEVELOPER_CONFIG`，也不需要手工注册工具：

```bash
cargo build -p eve-app --bin eve --locked
printf '请执行 pwd，并只回复当前目录。\n' | ./target/debug/eve \
  --state-dir .eve-direct \
  --agent AGENT.md
```

当宿主提供模型凭据并连接外部模型端点时，Eve 会自动把当前工作目录、文件读写、命令执行和 GitHub 读取能力装配到主人会话；对话中的自然语言请求会直接触发工具调用。命令仍经过内置策略和行动审查，GitHub 写入、自升级和实时切换需要显式授权与对应凭据。测试用的回环 HTTP 端点不会自动装配这些工具，避免 fixture 读取测试文件。

## 3. 提交一个受限自主驱动

```bash
STATE=.eve-autonomous-live-001
./target/debug/eve-cognition --state-dir "$STATE" drive-submit \
  --id live-drive-001 \
  --text '整理一个可验证的下一步，并明确仍需要主人确认的信息。' \
  --priority 80
```

预期输出包含：

- `autonomous_drives.total = 1`
- `autonomous_drives.ready = 1`
- `execution_contract.verification = reflection:v1`
- `execution_contract.max_tool_calls = 0`

可用下面命令确认候选仍未绑定 Goal：

```bash
./target/debug/eve-cognition --state-dir "$STATE" drive-show --id live-drive-001
```

## 4. 启动真实模型推进

```bash
./target/debug/eve-cognition --state-dir "$STATE" run \
  --seconds 45 \
  --max-executions 1
```

这里会经过固定审核、Ready 驱动物化、统一议程准入、一次真实模型请求和反馈落盘。模型输出必须是严格 JSON：

```json
{"summary":"...","next_step":"...","needs_user_input":true}
```

不会因为模型声称“已经完成”就把目标标记为现实完成。

## 5. 观察结果

```bash
./target/debug/eve-cognition --state-dir "$STATE" drive-show --id live-drive-001
./target/debug/eve-cognition --state-dir "$STATE" status
```

成功路径应看到：

- 驱动状态为 `Completed`
- 驱动绑定一个 `autonomous.goal.*` Goal
- 绑定 Goal 的反馈 `verification_met = true`
- `max_tool_calls = 0`，工具启动计数为 0
- 事件中出现审核、物化和执行反馈记录

如果模型请求失败、输出不合规、超时或反馈无法可靠保存，结果应为 `Blocked`，并保留失败原因；不得重放已经提交过的工具调用。若进程在执行中退出，重新启动后应先恢复为阻塞并解除 Goal 绑定，不能把旧执行伪装成成功。

## 6. QQ 真实交互边界

当前仓库已有主模型多轮验收和 QQBot 本地桥接验收，但本验收不自动连接真实 QQ。真实 QQ 测试需要单独的隔离账号、明确的群/私聊目标和可撤销的发送授权；准备好这些条件后，再把同一份状态观测接到 QQ 入口。没有这些条件时，先使用上面的真实模型 + 本地状态验收，不把 fake bridge 或 CI 结果称为真实 QQ 交互。
