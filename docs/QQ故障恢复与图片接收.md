# QQ 故障恢复与图片接收

用户提出明确任务后，Eve 在宿主已提供的工具和权限内直接推进；“试试”等简短确认结合上文理解。源码工作区可以包含 Eve 和渠道适配器，不能仅因代码属于宿主就拒绝检查。准备升级候选仍不等于替换正在运行的版本。

## 执行失败

定义层 `SessionFailureEvidence` 保存固定 HTTP 状态码、Provider 失败类别、请求的工具名和已经收到的工具结果；故障通知按类别说明原因，类别见[模型健康与就绪状态](./模型健康与就绪状态.md#失败类别)。运行时提交失败记录后，QQ 组合层不再无声结束，而是发送一条无需模型参与的故障通知，说明是否已启动工具、本轮已停止以及不会自动重试。取消和已被新任务替换的旧回复仍被抑制。保存状态不确定时不能声称没有副作用。

失败通知可以有 QQ 的 Sent 回执，但不属于成功模型交互，不进入交互记忆或成功训练样本。工具结果仅保存在私有失败账本，不作为指令回放。已经启动工具或执行数量未知的失败轮，会在之后的会话提供失败输入和明确标注的宿主失败摘要，从而知道此前已经开始；不会重放旧工具调用。取消轮和确认未启动工具的失败轮不回放输入。

旧状态可由新版读取，新增 evidence 缺省为空；旧记录没有保留的 HTTP 状态码和工具返回值无法补造。包含新字段的状态不能交给旧版本自动修复；回退前保留原始状态快照，未知或损坏记录继续拒绝加载，不清空。

## 图片接收的范围

Node 桥接接收本条消息顶层的图片附件，最多四张，每个 HTTPS 引用不超过 4096 字符；纯图片和图文消息都能进入持久回执。引用消息里的图片不会冒充新上传的图片。正文、附件 URL 分别保存，图片引用不自动下载，也不传给文本模型。

这一步仅完成附件接收，不代表视觉理解。模型得到明确的“附件已收到、尚未解析”的宿主说明，不能声称看见图片内容。包含附件的消息暂不作为表达或偏好训练证据，避免把通道生成的说明学成用户原话。完整多模态输入、模型视觉能力选择和受限下载仍待实现。

## 验收

`developer_tools_test.py` 用真实原生进程和本地协议替身运行文件、命令：命令确实产生一次副作用后，模型 HTTP 503 失败，必须发故障通知、保留工具输出、保持会话 Failed；重启后不能再次执行，也不能把故障通知计入训练。纯图片用例核对附件引用落盘、模型请求不含图片 URL，且不产生成功交互训练证据。

`training-window.py` 将失败轮放进加密报告的 failures 列表；公开摘要仅保留计数。`interaction_ok` 要求存在成功模型回复且无失败或未确认记录，`experience_acceptance` 始终为 `not_evaluated`，脚本健康检查不代替用户体验验收。
