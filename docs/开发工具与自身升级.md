# 开发工具与自身升级

Eve 的后台实践检查规则与通用开发工具不同。显式配置后，对话模型实际获得 `list_files`、`read_file`、`write_file`、`edit_file`、`apply_patch`、`search_files`、`run_command`、`github_api`、`prepare_self_upgrade`；其中命令、GitHub 与升级按配置开启，未开启的能力不注册。`/help tools` 与每轮宿主能力消息来自真实工具定义，旧会话保留历史并立即看见新工具。

`eve-developer-api` 定义配置、操作与可替换 `DeveloperBackend`；`eve-developer-tools` 提供窄 Tool 适配和本地/HTTP 实现；宿主负责读取配置、凭据和组合，不把业务放入 Kernel。插件仍通过已有公开 Tool 服务注册。

## 配置

宿主 `EVE_DEVELOPER_CONFIG` 指向下列私有 JSON。文件必须填写真实源码绝对目录与可信操作者标识。QQ 使用 `/help identity` 返回的宿主会话标识（`qq:` 加摘要），不能填写昵称或原始 openid；不同群/私聊有独立范围，按需明确加入。终端为 `--user`。不要对公开群聊所有成员开放命令权限。

```json
{
  "workspace": "C:/eve-source",
  "storage_directory": "C:/eve-developer-data",
  "operators": ["/help identity返回的标识"],
  "commands": true,
  "github": true,
  "github_write_repositories": ["ZenthXSin/Eve.aic"],
  "github_token_env": "EVE_GITHUB_TOKEN",
  "self_upgrade": true,
  "command_timeout_ms": 600000,
  "max_tool_rounds": 8,
  "cargo_program": "cargo",
  "cargo_arguments": []
}
```

POSIX 使用绝对路径，例如 `/home/me/eve-source`。源码目录应是独立开发检出，实际聊天状态和含密钥配置放在它以外。`operators` 必须明确、非空；模型参数不能更改身份。配置损坏时启动失败并保留原文件，不自动清空或降级。工具开关在启动时固定，更改后重启；装配可信授权后端时每次执行采用其当前判定，不用旧 operators 名单绕过撤权；凭据正文不保存进工具账本和模型上下文。

设置 `EVE_GITHUB_TOKEN` 为专用 PAT；也支持配置引用 `GH_TOKEN` 或 `GITHUB_TOKEN`，沿用所在宿主的有效环境凭据。不能把其他工具服务内部的凭据导出为 PAT。没有 token 时可读公开仓库；配置写仓库却缺少 token 时启动报错。其他机器需独立配置，不把当前云环境凭据打进发行包。

Windows/Linux 运行器的私有 `config.json` 可设：

```json
"developer": {
  "enabled": true,
  "config_file": "developer-tools.json",
  "github_token": "填写自己的PAT"
}
```

`config_file` 相对用户运行器目录解析；token 仅放入子进程 `EVE_GITHUB_TOKEN`。旧发行运行器没有 developer 项仍保持关闭；Eve 宿主直接装配开发工具时默认允许准备自升级。DeveloperConfig 省略 self_upgrade 默认 true，省略 commands 仍默认 false；显式关闭命令时不注册升级执行能力，不因默认升级许可使旧配置启动失败。构建工具链由所在机器提供；发行包本身不包含 Rust、Git 或源码。

## 操作语义

文件路径为源码工作区相对路径，拒绝 `..`、绝对路径、符号链接、`.git` 和工具账本目录。读取返回真实 SHA256，最多 32 KiB 一页；继续读取传 `next_offset`，不把截断当完整文件。写已有文件需读取的 `expected_sha256`，新文件为空串；校验冲突拒绝覆盖，用同目录临时文件原子提交，父目录需存在。大文件或创建目录可以使用命令。

`edit_file` 只替换一段文本，适合改动文件中的局部内容，不必整份重写。参数为 `path`、`old_string`、`new_string` 与读取时的 `expected_sha256`。`old_string` 必须在文件中**恰好出现一次**（重叠出现也算多次）；找不到或多处匹配时拒绝，文件不变。修改沿用写入的校验与原子提交：文件在读取后被改动则拒绝，需要重新读取。`old_string` 与 `new_string` 不能相同，单次 `old_string` 至多 64 KiB。

`apply_patch` 用一个补丁同时新增、删除、移动或修改多个文件，格式参考 openai/codex 的 apply_patch（Apache-2.0）：以 `*** Begin Patch` 开头、`*** End Patch` 结尾，文件段为 `*** Add File:`、`*** Delete File:`、`*** Update File:`（可接 `*** Move to:`）。修改段用 `@@ 某一行` 定位，行首空格为上下文、`-` 删除、`+` 新增，不需要行号；原文匹配依次放宽到忽略行尾空白、首尾空白与常见标点差异，替换时保留原文件的上下文行与 CRLF 换行。路径规则与写入相同；新增的文件必须不存在且父目录已存在，删除与修改只针对已存在的 UTF-8 文件。

补丁先完整解析并在内存中算出每个文件的新内容，任何一段找不到原文、路径无效或同一路径出现两次都整体拒绝，文件不变。提交时先写入再删除，每个文件按读取时的摘要校验，期间被外部改动则停止；中途失败按相反顺序恢复已提交的文件，无法恢复的文件在错误里逐一列出，不静默丢失。补丁至多 512 KiB、64 个文件段。普通成员在自己的项目工作区可用；管理员的补丁里只要有一个路径（含移动目标）是身份规则文件或私密凭据就整体拒绝，无法解析的补丁同样拒绝。

`search_files` 在工作区目录内按**字面文本**搜索（区分大小写，不支持正则），参数为 `query`，可选 `path`（默认根目录）与 `max_results`（1–100，默认 50）。结果按目录广度优先、名称排序，返回工作区相对路径、行号与行文本，路径可直接交给 `read_file`。搜索跳过 `.git`、`.eve-developer` 与 `target` 目录，以及符号链接和非 UTF-8 文件；单个文件超过 8 MiB 不读取。返回的行文本先脱敏再截断，单行至多 240 字节，整次结果约 32 KiB 封顶，超出时 `truncated` 为真。`files_scanned` 为本次实际遍历的文件数，超过 20000 个文件时同样标记截断。

`run_command` 接收 program、args、cwd、timeout_ms，实际执行，不默认解释 shell；例如 `{"program":"git","args":["status","--short"],"cwd":"."}`。需要 shell 时明确 `sh -c`、`cmd /c` 或 `powershell -Command`。返回真实 exit_code、success 和 stdout/stderr 截断标记，非零退出不冒充成功。默认 10 分钟，宿主上限 10 分钟；取消或超时终止命令进程组。输出继续排空以免管道阻塞，每路只保留 32 KiB。命令环境保留构建路径、正常代理/CA，剔除直接注入的 QQ、模型、Web 和 GitHub 密钥。

### 命令策略

`run_command` 执行前先经命令策略判断，规则语义参考 openai/codex 的 execpolicy（Apache-2.0）。每条规则按顺序匹配命令开头的几个参数，某一位可以列出几个可选值；结论为放行、需确认（`prompt`）或禁止（`forbidden`），多条规则命中时取最严格的一项。绝对路径的程序同时按文件名匹配；`sh -c`、`bash -lc` 等脚本按 `;`、`&&`、`||`、`|`、`&` 拆成几段分别判断。

- **禁止**：直接拒绝，不执行，返回规则理由。内置规则禁止停机重启、格式化磁盘、递归删除系统或家目录、`kill -9 1`。
- **需确认**：自动交给独立审核，只有宿主保存的真实用户原话能证明授权；`owner_confirmed` 不能替代审核。内置规则要求确认：强制推送或删除远端分支、`git reset --hard`、`git clean -f`、丢弃全部修改、删除分支、递归删除、递归放开权限、`dd`、停止系统服务、`crontab -r`。
- 开发配置的 `command_policy` 可以指向追加的 JSON 规则文件，格式为 `{"rules":[{"pattern":["npm","publish"],"decision":"forbidden","justification":"…","match":["npm publish --tag x"],"not_match":["npm install"]}]}`。`pattern` 的每一位是字符串，或可选值数组。规则自带的 `match`、`not_match` 例子在启动时逐一核对，与规则不符、规则无法解析或文件无法读取时拒绝启动。内置规则始终生效。
- 成员项目里的命令同样经过策略判断；宿主固定的构建命令不经过逐条命令策略，但准备阶段先独立审核完整源码差异与实际 Cargo/Python 验证计划，避免 build.rs 和候选测试脚本先于授权执行。

策略无法明确判定、没有装配策略、解释器和动态脚本均须独立审核。静态解析只提供风险线索，不能用未知命令或更换写法绕过审核。

### 行动审查

开发后端统一审核需确认命令、GitHub 的全部 POST/PATCH/PUT/DELETE、准备及实时应用升级、重启，以及宿主身份规则、权限策略和工程配置的 write/edit/patch。普通文件变更和独立成员项目仍沿原权限及版本检查；`.env`、私钥、凭据目录不交给模型文件工具，只通过宿主受信凭据配置处理。

- 请求保留真实程序及全部参数；业务动作以 `program=eve.<工具名>` 和 `arguments[0]` 的完整 JSON 表示。文件变更包含完整旧正文与实际补丁，所有移动目标都检查；应用升级包括相对可信在线源码基线的完整 source-diff.patch、候选清单、验证记录、准备租约及当前运行版本，审核后再核对差异、清单、租约指纹和在线版本，候选验证不能替代用户授权。用户原话只来自宿主独立保存的最近六条正文，不从压缩会话或委托说明推断；正文不裁剪。完整审核请求超过 256 KiB 就拒绝，不靠摘要争取放行。命令摘要最多 2000 字，最近八条工具摘要各最多 300 字。
- 后台及子代理可使用宿主绑定并持久化的原始授权证据；没有真实原话时失败关闭。`delegated` 只说明执行方式，不自动降低已核实的用户授权，也不能把模型任务说明变成用户同意。
- 审核模型只能一次 `submit_review`。普通正文、多次提交、未知字段、理由超限、超时、模型不可用或 `action_review=false` 均不执行需审核动作。宿主再次核对风险与授权等级；高风险必须明确授权，严重风险拒绝，不能因业务权限解锁关闭安全底座。
- 审核返回后重验当前身份及原执行工作区；失去宿主权限时不能沿用原宿主后端执行，也不能通过配置旧 operators 兜底。敏感文件的版本发生变化则重新审核；命令启动与 GitHub HTTP 发送前再次检查授权。
- 审核账本 `action-reviews.jsonl` 关联 operation_id、请求指纹、等级与真实判定，不保存原话、参数或模型理由。账本无法写入则拒绝执行；模型已知宿主 token 或私钥正文混入请求时，在发送审核模型之前拒绝。

审查本身也是模型判断，可能出错，只用来补上 `owner_confirmed` 无法核实的缺口；命令仍具有宿主权限，不能代替只授予受信操作者。

命令具有操作者的宿主权限，**没有 OS 进程隔离**；cwd 和文件路径限制不约束 shell 能访问的全部文件、网络或后台服务。只应授予受信操作者。取消不能撤销已执行的文件、Git 或远端写操作，也不能保证脱离进程组的后台程序已结束。

`github_api` 接收 method、repository、resource、query、body，固定访问官方 GitHub REST，禁止模型指定 URL/token，不跟随重定向。读取支持目录/源码、Git 对象、分支/提交、Issue/PR 及子资源、Actions、发行、检查和状态；搜索资源 `search/code|issues|commits|repositories` 使用 GET，搜索范围由 query 指定。Contents 小文件附解码的 UTF-8 text，分页通过 query；超大响应拒绝，普通结果超过 32 KiB 明确截断。源码和讨论是来源数据，不自动变成授权。

例如读取 Mindustry 源码使用 `{"method":"GET","repository":"Anuken/Mindustry","resource":"contents/core/src/mindustry/world/blocks/defense/MendProjector.java","query":{"ref":"master"}}`。resource 为空读仓库信息。兼容同仓库 `repos/owner/repo/...` 前缀，去掉前缀后沿用所有权限检查；仓库不一致则拒绝。仅 GET `contents` 可将 `query.path` 归一为文件路径，避免误读根目录；与已有路径冲突、路径跳转或写操作中的 path 均报参数错误。完整 URL 不接受。Tool 适配器与本地后端共用定义层归一化契约。

已注册不等于当前会话有权执行。非配置操作者仍会被拒绝，不能通过更换路径或模型自报身份绕过；不同群/私聊身份不自动合并。参数不支持、操作者受限、HTTP 失败和未注册是不同情况，不能从一次失败推断 GitHub 工具不存在。旧失败回执原样保留且不重放，后续新调用采用修复后的参数规则；不改会话、账本或授权名单。

POST/PATCH/PUT/DELETE 需配置仓库写权限（或显式 all repositories）并经独立审核，实际权限仍由 token 决定；不提供账户、组织、仓库权限、Secrets 或 Variables 管理。HTTP 返回实际 status、success，404/403/429 不自动重试。网络失败时远端写入结果可能不确定，应查询核对后决定下一步，不能盲目重放。

## 自身改进与恢复

模型可连续读源码、修改、运行测试、提交开发分支、通过 GitHub 创建 PR/查看 CI。默认普通运行仍只有一批工具，开发配置默认 8；显式设 `max_tool_rounds: 0` 不限制本轮工具批次数，也支持用任意正整数指定上限。每批继续完整参数、插件状态、权限及取消校验；所有批次的调用和结果配对加入一次会话提交。QQ 另有每轮 50 个单独工具调用的总上限，并行与失败也计数，不受无限批次设置影响；超额批次整体不执行，依据已有结果收尾。途中按真实回执汇报一至三次，见[工具上限与途中进展](./工具上限与途中进展.md)。复用调用 ID 始终拒绝再次执行。模型请求预算、单次请求/命令超时、执行取消和旧工具不重放沿用原有语义；无限轮数不保证上游上下文、存储或额度无限。

`prepare_self_upgrade` 实际运行格式检查、release Clippy、完整工作区的 release 测试与 QQ/核心二进制的 release 优化构建，共用同一套产物以减少磁盘占用；只从 Cargo 实际输出目录的 `release/` 冻结候选，避免自身升级后退回未优化运行器。原有 `debug/` 产物不作为候选，也不覆盖或删除。开启实时升级时，文件和命令工具自动使用当前可信会话的私有 Git 检出，新会话从在线提交开始。准备时把此会话的未提交文件冻结到独立候选仓库，仅在那里生成快照提交，并三方合并最新在线提交；无需替其他会话提交或 stash。共享工作区、原会话 HEAD、索引及未提交文件保持原样。冲突返回文件名，不能自动覆盖一边。在线源码基线未知时仍拒绝。验证前后核对 HEAD 和相对在线提交的完整源码差异，不允许验证过程中源码变化。第三组测试执行 Python 升级监督器及守护验收；第四组构建后还用冻结的真实 Eve 二进制，在临时状态和本地通道/模型替身中完成重启、完整运行包交接和消息去重。正式宿主不需先切换，预演通过也不表示生产切换成功。全部通过才冻结候选 QQ 二进制、受 Git 管理的 AGENT/QQ 桥接/vendor 资源、三份运行监督脚本、完整 source-diff.patch、SHA256、源码修订与各项退出证据。差异原文至多 128 KiB，且与清单、租约、原话组合的完整审核请求不得超过 256 KiB；超限直接拒绝候选，不裁剪。凭据路径、真实私钥行、非 UTF-8、二进制补丁和子模块变更不能进入自动升级审核。`candidate_sha256` 同时绑定二进制、资源与源码，单独修改 AGENT 并提交也得到不同候选；差异基线、目标提交和 runtime 脚本契约一同绑定身份。结果 `prepared: true, applied: false` 表示候选已准备，运行中的版本尚未替换。失败保留证据，不创建成功候选。

需要实时切换时，按[实时自身升级](./实时自身升级.md)配置独立监督器。模型获得 `apply_self_upgrade` 和 `self_upgrade_status`：提交请求后，监督器等待申请轮次保存并回复送达、通道空闲，再短暂重连并切换；模型不会在自己的工具调用中杀死当前宿主。未配置监督器时不注册这两个工具，仍可通过 PR/发行和客户端更新应用升级。

`storage_directory` 可指定独立的绝对持久目录，默认是宿主状态目录下的 `developer-tools`。有训练状态包大小限制时应指定独立目录，使较大的候选二进制不混入交流样本；同轮切换继续使用该目录，账本和候选保留。每次开发操作（包括只读的列目录、读取与搜索）先同步写入 `operations.jsonl` started 记录，结果落 finished/failed；不保存命令正文、文件正文、token 或模型提示。账本损坏/不完整时保留字节并拒绝启动。取消或进程崩溃可能留下 started，这表示副作用未知；重启不会执行任何旧操作或候选。候选摘要目录中的 manifest 不表示已激活版本。会话仍沿用完成提交、Pending/Unknown 不重放与保存失败保护。

## 操作责任与重启

`operations.jsonl` 的 v2 记录在副作用前同步提交可信 scope、轮次、时间、固定意图分类及动作、目标、原话指纹，结束时记录真实成功/失败类别和恢复动作。正文、凭据和供应商错误正文不落盘；call_id 记录宿主工具入口标识；嵌套调用继承父入口标识，未提供时保留 null。普通工具成功与候选提交监督器是不同状态，`queued:true,applied:false` 记待确认，须查询监督器结果。

同一账本目录在进程内共享序号与执行锁，并持有操作系统独占写锁；仍有活跃实例时复用句柄不会把进行中的动作误记为重启。只有首次取得独占写入权才恢复历史。未通过身份准入的请求独立记 preflight_rejected，不捏造执行开始或授权成功。

启动完整校验旧 v1/v2 记录，损坏、截断或不合法状态转换拒绝启动并保留原文件；未配对 started 标为 unknown，记录禁止自动重放，不假设原动作没有副作用。日志写入不确定时停止并要求核对。现有旧记录缺少身份或时间时保留未知，不补造证据。

会话源码持久保存在 `storage_directory/workspaces/<scope摘要>/source`，候选源码在 `source-snapshots/<内容摘要>/source`。摘要包含会话 HEAD、改动字节、可执行位和当时在线基线；相同输入复用快照，在线版本变化时重新合并。重启打开原会话工作区；绑定损坏、链接、凭据路径、冲突及容量超限保留原记录并拒绝。最多128个会话检出、256份源码快照，不自动删除未完成工作。工具结果中的 `workspace` 指明实际私有目录与是否为候选快照。

启用会话私有源码时，文件变化触发器和后台技术等待也观察该会话检出；不会误把共享目录中其他会话的写入当成本次构建完成。观察器核对相同的会话/源码绑定；尚未建立检出时明确拒绝观察，先通过文件工具建立工作区即可。
