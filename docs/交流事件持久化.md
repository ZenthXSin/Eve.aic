# 交流事件持久化

QQ 与 Web 把 `ConversationStore` 装配到 `TrainingPlugin`，复用状态目录的 `training-expressions.sqlite3` 和原身份标记。原表达统计表与身份不变；新增交流表以一个事务完成初始化，`PRAGMA user_version=1` 标记迁移完成。已标记的数据库缺表或结构损坏时拒绝打开，不重建空库。SQLite 使用 `journal_mode=DELETE`、`synchronous=FULL`，没有额外 WAL 文件需要单独补采。

## 公开契约

`ConversationMessage` 保持原消息编号、匿名说话者、角色与完整正文，新增可选 `metadata`。宿主首次观察时间和平台实际提供的时间分别保存；旧消息没有时间就保持未知。回复对象、任务轮次、来源类别、工具活动与附带材料只有通道实际提供才填写。存储分配当前范围内递增的 `sequence`，重投不改变它。

实时显式发送及前台自然分条的 `activity` 是该条交付通道前观察到的执行状态，`observed_at_ms` 则是收到真实发送回执的宿主时间，两者不能当成同一时刻。自然分条逐条读取原控制代和轮次的活动，不沿用整组领取时的阶段；原轮已结束、状态不可得或控制代已变化时不填写活动，也不借用下一轮的状态。已经保存的历史元数据保留，不根据当前状态回写。

`append` 将去重凭据和原事件原子提交。幂等核心是范围、原消息编号以及正文、角色和说话者；同编号内容冲突报错。元数据采用首次持久版本，重投时的时钟或活动变化不会覆盖原记录。完整正文上限 32,768 字节，附带材料上限 8,192 字节；代码、链接、引文与长短消息不按表达统计的筛选规则剔除。附件消息可以正文为空，但必须有真实的通道材料。引用与附件材料不冒充说话者正文，不能作为真人原话摘录。

`ConversationStore` 只提供事件追加、读取、旧数据幂等导入和检查点比较交换；学习状态机仍在 `training-plugin`。替换存储必须遵守同事务提交与未知结果语义。没有装配该存储的旧插件实现继续使用原有界 JSON 兼容路径，不具备完整事件积压能力。

## 表与消费位置

| 表 | 内容与不变项 |
| --- | --- |
| `conversation_metadata` | 交流存储版本和旧 `conversation.v1` 原字节摘要 |
| `conversation_scopes` | 每范围 `revision`、`next_sequence`、版本 2 JSON `checkpoint` |
| `conversation_events` | 每个完整事件的稳定序号、原编号和 `message_json`，不被学习窗口覆盖 |
| `conversation_seen` | 原编号和稳定内容摘要，暂停、重置后仍用于去重 |
| `conversation_revisions` | 每次经验版本的独立序号、稳定经验编号和原证据 |
| `conversation_batches` | 已完成、明确失败、暂停、重置和中断的固定批次归档 |

检查点的 `cursor` 是下一条尚未完整消费的事件及正文、附带材料的 UTF-8 字节偏移。`next_sequence` 是下一次追加时将分配的序号。正常批次四条新事件触发；少于四条时，持久等待起点满六十秒也会处理尾部。长事件和未完成分片无需再等四条。没有新事件时，不为轮转历史版本单独调用模型。

本次最多取十六条消息，可附带最近十二条已消费消息作为语境；原事件日志独立保存，不删掉窗口之外尚未消费的事件。领取固定批次和其结束位置先写入检查点，成功后再原子推进 `cursor`、更新当前经验、追加经验版本和完成归档。

队列与学习器共用 `conversation_prompt_json`，按真实序列化后的 65,536 字节预算分批，包含元数据、当前经验、历史版本和反馈配对。内部 `evaluated_message_ids` 不进入模型输入。通常二十四条当前经验全部参与；极端情况下按持久游标分页，待验证、有效与停用经验都能轮到。历史版本也按序轮转，最多四条，保留原证据。

一条事件因 JSON 转义或旧经验占用无法完整装入时，按 UTF-8 边界投影带区间的 `fragment`。原编号和序号不变，数据库正文仍完整。只有明确完成本分片后才推进字节偏移，不将两个分片当成两条独立真人证据，不截断后半段或越过该事件。

## 经验更新

新独立观察可以修改原经验的适用场景、回应原则和例外，并保留相同编号。明确反例停用旧经验；普通观察不能清除已有反例，只有真实直接纠正可以解除。证据必须逐字出现在该固定批次正文中；直接纠正或反例还要求引用对应真人消息最近的前序 Eve 发言。相同原消息的重复窗口或分片不增加支持。

每次修改保存修改前与修改后版本。当前二十四条容量满时，轮换出的经验保存 `capacity` 归档，原证据不删除；后续批次可以从历史版本用原编号提出有新证据的更新。明确重置则建立事件与版本边界，重置前编号不复活，新交流可以形成新经验。

## 暂停、重启与失败

暂停保留未领取积压和已学经验，暂停期间只存去重凭据，不采集正文。恢复后继续尚未领取的事件，不补学暂停期间同编号的重投。已领取但结果未知的批次在暂停或重启时归档并越过该已尝试范围，不自动重调模型；未领取的后续事件仍待消费。

只有宿主明确记录的模型或输出失败允许有限重试，同一固定批次最多三次。检查点包含 `retryable`，重启不把普通 `inflight` 当成可重试。第三次失败归档并结束该批，完整来源仍可核查；不会因此重放聊天、消息发送或工具执行。

存储提交返回 `State` 错误表示结果可能未知，该实例停止后续读写，不能再次 `fail` 或用旧检查点覆盖。重新打开时只采用实际持久结果。格式拒绝或失效批次属于 `Task`，不冒充数据库损坏。比较交换冲突不提交任何版本或消费位置。

旧 `conversation.v1` 校验后只导入现存窗口、固定批次、去重凭据和经验；原 JSON 字节不改写、不清空。旧 `inflight` 在同一导入事务中完整归档为 `interrupted`，不转成新请求，也不要求满足新请求的字节预算。现存窗口无法补回以前已丢掉的原文或时间。再次启动核对原来源摘要，不能把变化的旧快照回填到新数据库。备份与回退保留整个数据库、身份标记和旧状态来源。

## 验证范围

`training-sqlite/tests/conversation_flow.rs` 覆盖超过旧窗口的积压、完整长文与转义分片、尾部期限、明确失败与未知请求、暂停重置、提交确认丢失、旧 JSON 迁移、经验持续修订与容量归档、极端经验分页预算。存储与检查点完整性测试另覆盖 SQLite 身份、序号、表丢失、事务原子性和篡改拒绝。这些测试不要求调用真实模型或发送真实消息。
