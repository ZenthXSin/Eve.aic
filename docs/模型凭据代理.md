# 模型凭据代理

`eve-llm-api` 定义 `ModelCredentials`、`CredentialLease` 和用途类型；`eve-model-credentials` 提供原生进程内 `CredentialBank`；应用组合层声明允许的引用并注入启动时读取的凭据。代理本身不读环境、不访问磁盘或网络，不向普通工具或服务注册表发布取密钥接口。

| 消费者 | 空引用的选择 | 允许的显式引用 |
| --- | --- | --- |
| 选择 primary 的对话、摘要、审核等用途 | 宿主主模型凭据 | `env:EVE_OPENAI_API_KEY` |
| 选择 auxiliary_small 的对话模型用途 | 宿主显式绑定的辅助用途凭据，CLI 绑定启动主密钥 | `env:EVE_OPENAI_API_KEY` |
| Jev 判断与记忆相关性 | 宿主独立 Jev 凭据 | `env:EVE_JEV_API_KEY` |
| embedding | 宿主主模型凭据 | `env:EVE_OPENAI_API_KEY` 或 `env:EVE_SEMANTIC_API_KEY` |

这些字符串选择宿主已声明的绑定，不是动态环境变量读取语法。`env:OTHER_KEY`、跨用途引用和缺少的独立凭据均失败，不能借用别的密钥。凭据正文必须为不含空白或控制字符的可打印 ASCII，最多 8192 字节。诊断只给固定错误类别，不回显正文或未知引用值。独立 embedding 端点与既有期限保持不变。

每次主模型、辅助模型或 Jev 解析都先取得并核验用途、引用、非零版本，再考虑复用客户端；代理不可用或返回错误用途/引用时拒绝本次解析，不采用缓存客户端。原生管理句柄可按预期版本 CAS 替换已有非空绑定，成功后版本加一；重复绑定、过时版本和无效正文不能覆盖旧凭据。客户端缓存同时核对配置快照及凭据版本。

一轮开始后已冻结的提供方保留自己的认证头，凭据替换不改变在途请求。下一次解析采用新版本。语义提供方仍在启动时捕获，不因此增加向量热切换。原生替换接口不作为 QQ、模型或 Web 工具开放；现有进程启动路径仍从环境读取一次，不监听环境变化，也没有新增修改宿主密钥的命令。可替换代理须遵守同一绑定正文变化时递增版本的契约。

租约不实现 Debug 或序列化，最后一份租约释放时清理其密钥缓冲区；这不保证提供方 HTTP 头、调用者原字符串及操作系统的所有副本都已擦除。普通配置、会话、便笺和数据库均不新增密钥正文。版本只在当前代理实例内有效，不是跨进程持久身份。

重启时重新注入凭据并重建客户端；会话和配置沿用原恢复流程，不恢复正在执行的网络请求，不重跑已记录工具。缺少启动必需主凭据仍在创建会话状态前失败。外部凭据库、加密落盘、轮换管理界面、撤销在途请求仍需后续实现。

验收使用合成凭据和本地 HTTP 替身：用途/引用隔离、缺失绑定、并发替换只有一个成功、无效和过时替换保留原值；实际主模型客户端核对旧/新/旧三个认证头，证明已捕获提供方不随替换变化；代理不可用或返回错误绑定时不能复用已缓存客户端；终端跨两次独立进程恢复历史，显式引用生效且原始状态与输出不含合成密钥。Jev 和语义的既有独立凭据、端点与失败前拒绝验收继续运行。具体结果以提交对应日志和 CI 为准。

主/辅租约的用途不同，即使引用名称相同也须分别绑定。原生 CLI 组合层显式把同一启动主密钥绑定给两种用途；可信替换代理可为辅助用途注入独立正文并单独轮换，不能返回主用途租约。辅助路由与配置发布规则见《模型配置》；缺失绑定、关闭角色和不匹配租约不能使用已缓存的主 Provider 回退。
