# 运行版源码自动同步

这是源码部署的宿主更新器，与便携包定时下载 Release 的启动器独立。它不调用模型，不占 Eve 的工具步数或自主消息预算，不在群里发送检查提示。

## 启用与立即检查

在状态和 Eve 开发工作区之外保存宿主配置（不写密钥）：

```json
{
  "version": 1,
  "enabled": true,
  "repository": "ZenthXSin/Eve.aic",
  "branch": "main",
  "data_directory": "/srv/eve/source-updates",
  "interval_seconds": 3600,
  "cargo_program": "cargo",
  "cargo_arguments": [],
  "jobs": "auto",
  "timeout_seconds": 600,
  "minimum_free_bytes": 1073741824
}
```

运行已有升级监督器时追加 `--auto-update-config /srv/eve/auto-update.json`（在最终 `--` 之前）。使用 `scripts/eve-service.py` 管理服务时，在私有服务记录加入绝对路径 `auto_update_config`，之后的启动与自启动会继续传入此参数。监督器的 `source_update.py`、`build_resources.py` 与 `self_upgrade_runtime.py` 放在同一目录，监督器自身仍由宿主管理。

```sh
python3 scripts/source_update.py --directory /srv/eve/upgrade check
python3 scripts/source_update.py --directory /srv/eve/upgrade status
```

启动后检查一次，此后按间隔检查；手动 `check` 可立即检查并重试同一失败修订。检查正在进行时不会启动另一份构建。`enabled: false` 热停用后不再检查或应用，正在运行的检查进程会被取消，当前聊天继续。配置改变后，旧配置准备的候选不会被直接应用。

## 更新与权限边界

更新器只从宿主指定的 GitHub 仓库和分支取得源码，不接受模型传入 URL、令牌或切换命令。默认公开仓库无需 GitHub token。运行自动构建意味着信任该分支代码；不接收私信、群原话、模型或普通成员提出的任意更新源。

源码检出与缓存均在独立 `data_directory`，不修改 Eve 正在开发的工作区。自己的检出存在本地修改时拒绝覆盖；已经激活的源码有未提交改动、与上游分叉、上游回退时拒绝自动覆盖，需要宿主核对。抓取的确切提交依次通过：

1. `cargo fmt --all -- --check`
2. 先构建 release 全工作区库，再做全 target Clippy，警告当错误
3. 先编译 release 完整工作区测试（`--no-run`），再执行测试
4. 从 Cargo 元数据取得 Eve 二进制列表，逐个构建，避免多个程序同时链接

`jobs` 默认 `"auto"`。每个阶段开始前重新读取 CPU 亲和性、Linux 容器各级 CPU/内存配额、可用内存和系统负载，Windows 读取进程亲和性与可用物理内存。为其他业务预留约四分之一 CPU 与内存（内存至少 512 MiB），按阶段的单作业内存估算选择 Cargo 并发；系统负载高时再降低并发。无法确定可用内存时使用单作业。整数 `jobs` 仍兼容，作为自动分配的上限。测试线程采用相同预算，编译子进程降低优先级，运行中的 Eve 不改优先级和预算。

状态中的 `stage`、`stage_index`、`stage_count`、`effective_jobs`、`resources` 显示当前阶段、并发和资源依据，逐阶段日志也保存同样的信息。各阶段严格串行并复用同一个 Cargo 缓存；四项候选验收回执按组收拢子阶段，不删减原有检查。

资源不够启动一个作业时显示 `deferred`，保留旧版并在一分钟后重新检查；不会把暂时的内存压力永久记成该提交失败。命令运行中每秒检查内存，低于 128 MiB 时停止自己的编译进程，再等待重试。并发在阶段边界调整，不在正在编译的 Cargo 中途增加作业。内存估算不替代操作系统资源隔离。

子进程不继承 QQ、模型、Web、GitHub 密钥变量；代理、证书和构建工具链路径保留。开始前检查剩余空间，检查过程中出现磁盘压力或超时会终止本次命令，保留旧版及失败日志。冻结前预留二进制与资源的复制空间；切换前按实际状态目录大小预留备份和下一次原子提交空间，空间不足时保持旧进程在线。构建缓存可重复生成，不删除用户数据换空间。

成功后冻结二进制、AGENT、QQ 桥接和 vendor 资源及其 SHA-256，沿用现有候选协议。宿主自动请求使用单独的 `auto-request.json`，不能作为 QQ 工具请求伪造送达证明；QQ 的 `request.json` 仍必须核对确切真实轮次和 Sent 回执。

等当前对话、后台任务、正在执行的唤醒、文件及主动消息投递全部空闲并经过稳定窗口后，沿用监督器切换。已结束但遗留且未变化的未知 QQ 回执不阻塞，不修改、不重放。候选实际 QQ 就绪并稳定后才报告 `applied`；只准备好时显示 `waiting`，不能宣称已更新。相同已激活源码不重新构建或重启。

## 持久化、失败与恢复

- `auto-update.json` 是检查、验证、等待、应用及错误状态；`check-updates.json` 是显式立即检查标记，不保存会话原文或凭据
- 数据目录的 `logs/` 保存每个提交的真实命令结局；`source/` 和 `target/` 是独立检出及可再生缓存，候选仍存原候选目录
- 格式错误、损坏清单、资源散列不符、磁盘不足和验收失败均保留现有在线版本，失败提交在定时检查中不反复构建；新提交或显式 `check` 可重新检查
- 服务重启不执行遗留应用请求：记录中断，重新拉取并验收；不重放工具或 QQ 消息
- 切换前保留旧程序和状态快照。候选启动失败只回退二进制，保留实际状态，不用旧快照覆盖新消息。旧程序也无法读取实际状态时停止并保留现场
- 状态、配置和候选格式没有因自动同步改变；群记录、长期记忆、权限及 Eve 的开发修改不被清空或重写

资源探测与预算验收在 `python3 scripts/test-build-resources.py`。本地真实 Git 与真实进程验收在 `python3 scripts/test-source-update.py`；默认使用合成 Cargo 测试控制流程。设置 `EVE_TEST_REAL_CARGO` 为 Cargo 可执行路径可额外验收小型真实 Rust 工作区的库、测试及多个二进制分步编译，`EVE_TEST_REAL_TOOLCHAIN` 可选择已安装工具链。生产构建仍实际执行上述四组 Cargo 检查。QQ 完整交接与回退另由既有监督器及 `live_upgrade_test.py` 验收。
