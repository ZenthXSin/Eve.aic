# 本轮分支集成与验收

本轮将开放 PR #228、#230–#246 的原提交合入同一集成分支，再通过 PR 合入 main，保留各分支的提交历史。#229 已在 main，不重复引入。功能依赖按原 PR 顺序处理；#244、#245、#246 分别依赖可选委派上下文、任务检查点、压缩期限与提示，最终版本一起验收。

## 合并时的兼容处理

- 升级候选的稳定窗口结束后再次检查进程，避免机器繁忙时跨过整个检查间隔、把已退出的候选误记为升级成功。
- 保留公开 GitHub 的显式宿主配置：`github_all_users=true` 时仅允许 `github_api` 通过 QQ 普通用户入口，后端继续检查仓库写范围、参数和凭据。默认关闭；文件、命令、后台任务和其他管理能力不随之开放。
- 带参数的只读命令（例如 `/mind ID`、`/recall 关键词`、`/memory-decision ID`）也按只读查询处理，底层继续核对会话归属；管理动作仍要求管理员。
- 管理权限收紧后，旧业务正例不再默认把普通聊天用户视作管理员。测试在自己的临时状态目录写入可信平台绑定；显式设置开发配置或绑定密钥的权限负例保持原配置，两个旧业务测试角色 user-1、user-2 使用测试管理员身份，其他角色仍为普通用户；权限负例继续使用显式配置。SQL 进程测试采用相同原则。
- 文件与原始消息能力已成为 QQ 的基础工具，旧验收显式计入 `send_file`、`read_attachment`、`read_raw_message`，同时保留对子代理不能再次编排的完整工具集合断言；不隐藏额外工具来使测试通过。
- 旧后台任务重启测试明确构造“没有检查点”的历史记录，保留未知操作不自动重放的断言；新任务的同 ID 自动接续、预算与期限保留、在途工具拒绝重放由独立恢复验收覆盖。
- 历史窗口性能基准显式关闭主动压缩，单独验证 16 轮窗口；主动压缩的全历史选择、150k 阈值、五分钟期限、提示和重启复用由专门用例验证。

## 运行和恢复边界

- 任务账本 v2 支持读入 v1；不允许回退到不能读取 v2 的旧二进制。
- 不清理或重置历史、不为未知工具补造回执；压缩失败保留原始工具回执并报告失败。
- 后台恢复验收等待完成通知的实际送达回执后再关闭桥接，避免业务已完成但通知仍在途时提前断开测试进程。
- 同轮压缩开始只提示一次“正在进行上下文压缩，请稍等”；为最终答复保留平台发送名额。
- 此集成不改变主工具预算 50、子代理并发上限 10 或普通用户的默认管理权限。
