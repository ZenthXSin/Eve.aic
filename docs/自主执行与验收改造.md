# 自主执行与验收改造

更新日期：2026-11-10。本页记录已实现的范围与剩余问题；提示词改动、隔离验证和线上启用是不同状态，不能用方案或候选源码代替实际启用证明。

目标是减少没有收益的固定流程，让 Eve 根据目标判断路径、分工、验证和交流时机。身份、权限、隐私、停止与资源限制继续由宿主守住；真实回执说明实际做过什么，不用模型自述填补证据缺口。

## 本轮已修改的提示

主对话执行原则和编程分工已把以下要求改为按需判断：

- 是否委派、是否并行：考虑工作独立性、上下文成本与收益，不再按复杂度标签强制派发，也不为并行制造任务。
- 交接上下文：优先给目标、相关文件、已有结果和必要限制；完整历史确有帮助且符合原可见范围时才使用 `include_context=true`。
- 进度登记和经验保存：用于有恢复价值的阶段、实际阻塞与值得复用的经验，不要求每个多步任务固定登记开头、收尾或保存经验。
- 结果接收：按目标判断已有真实回执是否足够，不例行翻完全部执行记录或重做仍适用的验证。

持续目标的单次推进提示也已去掉“每次依次检索、比较、拆解、修复、保存经验、提炼固定流程”的要求，改为根据目标、已有结果和实际变更选择行动。有合适的新候选时仍可提出；提出候选不增加原预算。该处只修改任务说明，没有改变持续目标规划协议、验收 schema 或自主探索规则。

人格与自然表达规则保留。没有新增固定开场、强制分条或固定汇报间隔，也没有一律禁止自主复查。Eve 可根据交流及行动进展作自己的判断；是否表达和何时表达仍遵循真实状态与当前交流需要。

同步修改了后台执行、叶子子代理、恢复任务、coding 角色和 `task_progress` 工具说明，避免后注入的规则重新要求固定起止登记。已经登记的 `in_progress`、技术等待和明确阻塞仍须如实更新；这些状态不会因文案精简而消失。

实际 Rust 宿主连接本地模型与 QQ 替身完成了 20 项进程验收。新增用例在 coding 可用时由主线程直接读取、修改、复读文件：3 次真实工具调用、4 次主模型替身请求、0 次编码模型请求、0 个子代理或后台任务，没有额外进度登记或重复复读。其余用例保留双模型路由、并行会话隔离、失败回执，以及旧合同失配修复和重启边界；另有 8 项对话工具测试、格式与严格 Clippy 检查通过。

这些测试证明宿主允许直接执行路径并保留原协议，不证明真实模型已稳定采用新策略，也不能据此宣称聊天效果、耗时或线上工具调用数已改善。

## 历史回执已能传递，当前有效性尚未接通

[PR534](https://github.com/ZenthXSin/Eve.aic/pull/534) 对应提交 `0cf725f2` 提供子代理历史验收回执摘要：`run_subagent` 返回时自动附带 `receipt_evidence`，之后也可在原可信范围内只读查询同一摘要。接收者获得这份摘要不需要额外工具或模型调用；查询不启动原任务，也不重放原操作。

报告区分历史匹配、不符、缺失和未知，明确 `current_artifact_validity=not_checked`。它能说明原冻结检查的真实观察，尚不能证明当前源码、依赖、产物或环境仍与检查当时相同。失败或未知不会被查询升级为成功，原结果、证据及记录保留。接口、状态和读取失败语义见[验收证据复用](./验收证据复用.md)。

旧 `kind=receipts` 合同仍要求 `require_final_batch=true`。本轮没有静默迁移旧任务，没有把历史回执摘要直接用作父任务或后台的新完成凭证，也没有改变恢复预算、未知效果或任务结算规则。提示词明确保留冻结合同，避免文字允许但执行器仍拒绝的误导。

## 仍未完成的工作

“测试已经成功，之后只登记进度又被要求重复测试”的宿主验收问题仍未解决。要解除最后批次限制，还需要可靠的对象与环境绑定、相关变化失效判断，以及完成验收、策略学习、认知投影对同一证据的共同消费。没有这些事实，不能把查询到的历史成功当成当前产物通过；也不能声称已经避免过期证据、并发变更或外部环境变化造成的错误接受。

聊天表达、蒸馏实际采用和自然分条仍有未验收部分。既有真实模型对照没有证明新经验带来表达提升；发送通道成功只能说明发送链路，不能扩大为自然分条或任务交流时机通过。本轮提示简化不替代这些验收，也不以固定台词或强制分段凑效果。

本文不声明上线、精确提速比例或重复调用已全部消除。后续交付应引用已有且仍适用的真实验证，补充缺口；只有候选版本实际启用并确认就绪，才能报告线上状态。回退须保留原始回执与未知副作用记录，不因切回实现而重放外部操作。
