# Jev 消息关系经验

QQ 使用 `--message-judge jev` 时，明确命令仍由宿主规则处理；自然语言先交给 Jev，低置信度、含混、超时或协议错误时，在同一次判断总期限内回退主模型。`primary` 模式直接使用主模型，`off` 不装配经验库。主模型使用 JSON 专用入口和明确的数据分类提示，一次请求不调用工具、不重试，不改变原有步数、置信度或时间预算。

“然后记得去除末尾句号”这样的补充无需标签。判断器结合当前任务识别补充、更正和独立新任务；真正含混时简短询问，不再发送要求选择固定格式的长菜单。私信可直接文字回答当前会话、当前代际尚未解决的问题，不要求平台提供引用功能。显式引用其他问题、过期代际或没有当前问题时不会把答复硬套到旧问题；重启不恢复旧代际的待答问题。

## 保存和检索

`jev-experience.sqlite3` 保存在状态目录。公开契约位于 `eve-message-api`，SQLite 实现独立于模型、路由和 QQ；宿主把同一份存储注入判断链。

- 主模型输出通过原文范围和当前置信度检查后，保存任务原文、最新消息、意图与逐字片段、简短依据及模型来源。此来源是分类观察，未经用户确认，不表示任务成功或客观事实。
- 用户明确指定“这是补充”等关系时，绑定当前未决的原消息，记录为用户澄清来源；相同任务与原话的冲突分类优先使用用户明确指定的版本。
- 只积累补充、更正、新任务、继续和无关等可复用关系。含混、取消、暂停、恢复、协议错误或超长案例不积累，也不从模型输出创建工具权限。
- 用户与会话共同隔离。SQLite FTS5 按中文双字片段检索，最多读取 128 个相关候选，选择至多 4 个示例；不是只扫描最近 128 条，因此较早的相关经验仍可检索。原文长度和示例总量有界；上下文不足时减少示例，不截断当前真实输入。
- 示例同时提供给 Jev 和主模型，明确标成历史分类数据；不额外附带宿主路由 ID、账号或代际标识，不直接复用旧控制动作。新消息仍须重新判断，并经过原文绑定、取消竞争、代际、权限和副作用保护。

`runtime.messages.experience_enabled` 默认开启，可通过配置面板或启动环境变量 `EVE_MESSAGE_EXPERIENCE_ENABLED` 关闭后续请求的读取与积累。关闭不删除已有记录。该库不设“满后停止学习”的全局条数上限；单条案例最多约 16 KiB，检索结果和当前请求始终有界。

## 持久化与恢复

案例和全文索引在同一事务中提交，作用域内消息 ID 去重。相同来源重复保存不新增记录；同一来源出现不同内容时保留原记录、停用本次进程的经验读写，并记录不含正文的错误，继续使用新的模型判断。写入或读取失败同样不会使用旧缓存掩盖错误，不重试写入、不清空库。

已有空文件、损坏数据库、未知版本或缺表均拒绝启动并保留文件，不自动修复。新状态目录首次创建格式 1 的数据库。备份、迁移应在停止宿主后连同状态目录完整复制；经验库不是工具执行日志，不参与旧工具重放。数据文件被人为删除后无法恢复其中的经验，应从备份还原。

验收覆盖持久保存、去重、跨用户和会话隔离、较早案例检索、用户纠正优先、事务失败与损坏文件保留；实际 QQ 宿主验证主模型回退积累、重启后提供给 Jev，以及私信无引用回答当前问题。真实模型验收使用合成补充、更正、新任务和私信答复，不能把这些场景的通过解释为所有语义判断都正确。
