# 原生 TypeScript 脚本与动作回执

这批把示例 echo 工具替换的正式脚本候选接通：模型侧只看到 `execute_script`，手机等能力
在脚本里的 `tools` 类型接口调用。当前已经实现手机、脚本任务查询/取消/结果页；文件操作、
命令执行、便签、提醒和上下文操作还未实现，不把这批当作所有基础工具完成。

## 调用与类型

原生工具参数是 `code`、可选 `mode` 和 `timeoutMs`。code 是异步函数正文，可写 await/return；
参数名 tools，类型 ScriptApi。默认异步先持久写入任务并返回 jobId；选择 sync 时等待脚本
终态。脚本开始之前使用当前契约源码做 Deno 类型检查；不支持的参数或错误类型先告诉 Eve，
不带着错的参数发送。类型检查本身不调用模型，也不另做审查器。

`composition/script-docs.ts` 直接把当前 phone/script 契约原件组成稳定说明；检查也导入同一
份契约，不另抄一份接口。生成器已验证，但正式意识流还未加载此说明，不能宣称模型已经
学会这些工具。当前 ScriptHostApi 给宿主用；tools 只含 ScriptApi 的 phone 与 scripts。

脚本源码按持久编号保存，在已有原件不匹配时拒绝覆盖。检查后再次核对源码，运行时传入
请求保存的不可变代码，而不是再次从可变路径加载。检查器读取类型依赖期间仍可能受到外部
并发修改影响；当前没有为整个依赖图建冻结快照，不能称全依赖字节绑定验收已经完成。

每份脚本一个 worker。脚本通过窄接口转发能力，不直接读手机密钥或原件；类型检查进程仅
显式获得 Deno 可执行路径，插件清单增加 run 字段，原插件未配置时仍无执行进程权限。
目前脚本 worker 不具备直接文件/网络/命令操作，基础能力要继续以类型接口接入。没有按
请求人增加审批流程。独立子代理通过 agents 能力运行，使用共享模型预算；其私信会话、工具回执和恢复语义见《子代理会话》。

## 脚本、动作与回执

原模型工具调用编号由宿主提供并持久保存为 requestId。同 requestId 与相同代码/执行期限
只对应原脚本；代码或执行参数不同拒绝冲突。sync/async 是等待方式，不是新动作。正式
意识流仍需把真实调用编号命名并存下，不能单靠模型重用某个短 tool_call_id 就保证全局唯一。

手机发送 actionId 由脚本宿主从 jobId 与嵌套调用序号产生；脚本不填写另一个 actionId。
转发前保存具体动作 started，拿到实际工具结果后当场保存 completed/failed/unknown。结果
由 phone 返回的平台事实决定；脚本命令成功不等于消息已送达，须看实际送达状态。

脚本账本在脚本运行目录的 ledger/，独立于内核插件状态和换版快照；插件回滚不回滚这些
事实。持排他写锁，JSON文件与父目录同步后才返回持久成功。存盘失败不放行新动作，损坏
或未完成临时文件保留并报错。当前账本全量读取和整体提交，读取上限128MiB，适合测试规模，
尚未提供大规模索引或长期分段存储。

脚本终态和具体动作终态不同。取消/期限结束可以终止忙 worker，但已经转发的外部动作
可能继续：脚本保留 unknown，迟到的真实动作回执仍保存。查询 receipts 得到少量动作摘要，
receipt 按页展开原参数/结果/错误，phone.action 查询实际发送账本。结果页上限8192码点，
默认1024；通知与动作摘要每页8条。

脚本退出之前未 await 的动作也等待实际返回；若脚本报错或被取消时动作尚在执行，则保留
未知。脚本取消不盲目撤销已经完成的发送，不把平台未知结果改成“未执行”。宿主整体中断
后：已有完成动作保留；未完成动作改为待核对；原脚本不自动重跑。完成记录只新增一次，
查询不删除记录，宿主须先把通知附加到意识流后再保存领取游标。

worker 自身执行与宿主等待有分别的期限。异步不会把长期运行的模型或工具拆成多个脑子；
这只是一个耐时的工具任务。没有固定间隔叫模型检查，不把超时当作用户答案。超长期限用
分段计时，避免系统定时器整数溢出而立即取消。

## 验证与剩余范围

真实 kernel worker、回环 QQ 平台、Deno 类型检查子进程及真实 SIGKILL 已覆盖：

- 唯一原生工具、两次嵌套并行发送、每个动作单独落盘、同调用并发及重启只发一次。
- 参数类型错误未发送、修正后真实执行；默认异步、忙 worker 取消、期限前后及长定时器。
- 发送中取消、迟到平台回执、只发一个完成通知、恢复继续采用原动作。
- 强制终止宿主后，前一个 completed 和后一个 unknown 同时保留，恢复查询真实发送事实。
- 第二写者被拒、损坏和未完成文件保留、存盘失败不发新动作。
- 实际插件换版健康失败并回滚，原脚本与动作回执仍采用，不重新执行。

本批完整回归102项通过，fmt、lint、类型检查通过。保留最初类型错误、测试读取旧状态路径
错误及独立子进程缺显式 worker-options 开关的失败证据。没有真实模型请求或真实 QQ 聊天
发送。不能把本地脚本链路通过说成自然表达、蒸馏增益或缓存率通过。

正式单脑意识流、持久提示器、资源统计、275k/500k处理、管理入口和独立守护所有权仍待
接通。目录写锁不等于全局所有权令牌；目前不能用这批新旧并行写线上状态。发送未知时
可以查原动作，但没有平台审核查询等补偿机制，也不会主动换编号重试。

主人身份与手机已读策略仍等待 Issue548；测试上线许可已收到，不重复征求，但还没有真正
上线。完成私信真实联调和主体运行后，由 Eve 经手机发一条通知，取得真实回执再报告。
