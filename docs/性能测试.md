# 自动性能测试

[自动性能测试工作流](https://github.com/ZenthXSin/Eve.aic/actions/workflows/performance.yml) 在相关 Rust、QQBot、依赖、AGENT 或自身工作流变更的 PR，以及 main 推送时运行，也可手动启动。它独立构建 Rust 1.89 Release 版 Eve，使用 Node 22，不需要 Secrets，不调用真实模型或 QQ API。

## 测量场景

- Node 通道：先预热 500 条，再测 5 组各 5000 条。实际生产 createBridge 与 consume 完成 C2C/群交替消息归一化、不透明 ID、JSONL 回复解析和原路投递；QQ SDK facade 为本地替身。每条输入/输出正文为 256 个 ASCII 字节。
- Eve 新状态：预热一轮后，测 3 个独立进程，每次连续处理 40 条同会话 C2C 消息；每 10 条调用一次真实 echo 插件。模型使用 loopback Chat HTTP，QQ 使用生产 Node 桥接加本地 SDK 替身。
- Eve 恢复状态：每个新状态样本后启动第二个进程，读取同一状态，再处理 40 条新消息；确认此前完成历史进入首个模型请求、旧工具不重放、回执全部 Sent、会话修订及 Completed 数量正确。回复负载为 256 字节，工具输入另带 echo: 前缀。

预热不计入报告。Node 流有界预读，解析和发送顺序执行；Eve 沿用当前串行会话装配。数据是合成负载，状态目录和本地替身在结束后清理，生产实现没有新增基准开关。

## 报告与口径

每次运行在 Actions Summary 显示对照表，并保存 eve-performance artifact 中的 acceptance.json，保留 30 天。报告只含版本、构建/平台、负载和指标；不含凭据、QQ ID、正文或状态文件。

记录 p50/p95/p99/max 延迟、中位吞吐、整轮时间、CPU、采样峰值 RSS，以及 Eve 启动至首个模型请求的时间和状态文件大小。百分位使用全部测量消息的最近秩，中位吞吐按各独立运行计算。

Node 延迟从归一化前到本地 SDK 成功 delivery 帧；Eve 延迟从 Node 发出输入消息帧到本地 SDK 成功 delivery 帧，包含 Rust 队列、Control、HTTP、echo（如触发）、Session 提交及 ReplyPending 保存。最终 Sent 保存、启动和退出计入 Eve 整轮吞吐，不包含在单条 delivery 延迟。Eve CPU 为被等待的 Eve/Node 子进程树用量，不含 Python 模型替身和采样器。Eve RSS 为 Linux /proc 的 VmRSS/VmHWM 采样高值，Node RSS 单独报告；它们不能相加当作同一时刻的整树峰值。

此基准反映当前小负载下的通道、核心和持久化开销。托管 Runner 的 CPU/磁盘会波动，外部模型延迟、QQ 网络、生产容量和并行最大吞吐需另行实测；真实 QQ 收发结果见 [QQBot 通道](./QQBot通道.md)。

## 性能预算与失败

版本化[负载及预算](../connectors/qqbot/test/performance-budget.json)固定样本数和初始宽松阈值：Node p95 5 ms、吞吐 5000 msg/s；Eve p95 1000 ms、吞吐 5 msg/s、启动 5000 ms；单进程 RSS 512 MiB。

预算超限生成 GitHub warning 和 performance_status=warning，报告保留实测值与阈值；按当前优先保证运行的要求，不因性能波动阻断工作流。以后积累同负载/平台历史报告，再调整预算；这些初始预算不是经过测量的历史基线，也不自动与另一台 Runner 的一次结果作严格回归比较。

消息丢失、工具结果不符、历史未恢复、状态未提交、凭据进入输出、进程失败或超时都让工作流失败，不能作为性能通过。Eve 每轮上限 120 秒、Node 基准 60 秒、整个 job 20 分钟；即使失败也尽量保存无正文失败报告。

本地运行：

```sh
cargo +1.89.0 build -p eve-app --bin eve-qqbot --release --locked
python3 connectors/qqbot/test/performance.py \
  --binary target/release/eve-qqbot --output /tmp/eve-performance.json
```

首次实际工作流结果将在运行后记录。
