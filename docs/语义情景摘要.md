# 语义情景摘要

情景摘录保留原文，语义摘要则把用户说过的事情归纳成有引文的背景，帮助后续接话。两者独立：摘要不是新事实、稳定偏好、执行授权或模型权重训练。

## 来源与归纳

`memory-api` 定义 `ConversationSummarizer`、`SummaryAdmin` 和数据契约，`memory-plugin` 提供可替换模型实现及独立的 `eve.memory-summary` 插件，QQ 组合层负责已送达来源、配置和预算。

可信宿主可通过 `InterestComponents.summarizer` 替换摘要器；默认实现使用主模型。替换实现仍须遵守来源、单批请求和预算约定，宿主会再次校验输出引用。

- 只消费当前 QQ 用户与会话中 `CompletedInteraction` 的用户原话，不把旧助手输出交给摘要器。模型没有工具。
- 达到新证据阈值后，每批至多消费 8 条新证据，并读取上次成功摘要及其当前仍可用的原文引用。按 UTF-8 JSON 预算保留完整原话，不截断字句；预算不足先减少旧归纳，再缩小新证据批次。
- 每次产生至多 6 个语义要点，每点附 1–3 段连续的逐字用户引文。允许同一条消息的不同片段，拒绝重复引文、未知证据、改写或拼接。结构和来源校验通过，仍不证明归纳语义一定正确。
- 新纠正优先，区分过去兴趣、当前意愿、设想与完成状态。摘要始终标为待核对；没有自动写入偏好或知识库，也不把用户说想做的事重放成任务。
- 对话读取时重新核对来源；已修正或撤销的旧偏好来源不经摘要复活。当前原话、确认偏好、时间变化和撤销优先。不会把其他用户的摘要作为本用户上下文。

当前整合限于同一可信会话。跨群、跨私聊或跨通道身份不自动合并；统一知识图谱仍未实现；摘要冷存和有限失败补做见下文。

## 面板配置

QQ 装配 `--memory` 时加载插件与后台，通过“插件页面 → `runtime.memory_summary`”热配置，不需要新增命令行开关。为兼容既有运行，默认关闭；操作者可在面板启用，或在宿主设置 `EVE_MEMORY_SUMMARY_ENABLED=true`。

| 配置 | 默认 | 范围与含义 |
| --- | --- | --- |
| `enabled` | false | 暂停新批次并隐藏摘要上下文，不删除记录 |
| `min_new_evidence` | 4 | 1–8，触发新批次的未消费证据阈值；大消息预算可能缩小实际批次 |
| `cooldown_ms` | 300000 | 1000–86400000，每作用域两批准入间隔 |
| `context_max_bytes` | 4096 | 512–8192，提供给对话的 JSON 字节预算，说明文字另计 |

环境变量依次是 `EVE_MEMORY_SUMMARY_ENABLED`、`EVE_MEMORY_SUMMARY_MIN_NEW_EVIDENCE`、`EVE_MEMORY_SUMMARY_COOLDOWN_MS`、`EVE_MEMORY_SUMMARY_CONTEXT_MAX_BYTES`。文件覆盖优先。模型用途为 `summary`，使用当前主模型线路，可用 `runtime.model_uses.summary_max_output_tokens` 单独设置输出上限。

热修改从下一项工作准入或下一轮对话读取；已经发出的摘要请求按实际结局保存，关闭后不会将其交给对话。恢复时可处理保留的未消费交互。`/train stop` 控制表达示例训练，不删除原始记忆，也不替代此独立开关。

## 预算、失败与恢复

准入批次先写入 `eve.memory-summary/summaries.v1` 的 Running 记录，才允许一次模型请求。配置自主运行预算时，请求再通过同一个持久预算，以 `summary` 类别先预留、成功返回后结算，失败/取消释放预留；余额不足不保留新摘要批次，重启不重置预算。

单次请求至多 30 秒。供应商错误、超时、无效 JSON、错误引文、工具输出和取消均记录失败；已知失败最多两次有限补做，取消和中断不自动重试。新证据达到阈值后可启动新批次，使用上次成功摘要；失败批次不会变成成功背景。SIGTERM 等正常停止记取消；进程异常退出遗留的 Running 在重启时记 Interrupted，不重放。

默认 QQ 装配把摘要的供应商期限限制为至多 29 秒，在组件的 30 秒外层期限之前返回；面板模型健康可记录 `timed_out`，避免仅留下摘要失败却仍显示该模型用途未验证。

供应商或超时失败后，所有摘要作用域按 `cooldown_ms` 冷却，不能借切换用户继续消耗尚未消费的证据。冷却依据持久记录中的失败时间，重启不会绕过；之后按新证据与到期补做的公平规则准入，有限补做不改写原失败。

账本保留批次、确切来源、旧归纳和所有结局；热层最多 128 批、16 MiB，默认 QQ 通过冷链保留更早历史。达到磁盘或元数据保护时按范围暂缓并重新检查，保留旧记录，不自动淘汰。原始 Memory 的容量仍独立限制，摘要不会压缩或删除原始证据，不能把此功能当作无限记忆方案。

损坏、未知版本和重复 JSON 键拒绝启动且保留原字节。后端写入不能确认时关闭该摘要实例的读取与写入句柄，重新打开后以真实持久状态恢复，不用旧缓存覆盖。原有 `eve.memory/memory.v1` 与训练状态格式不变。备份需包含完整状态目录或整个 SQL 状态后端，不能只复制最新摘要替代来源。

## 验证

- `memory-plugin/tests/summary.rs` 覆盖来源、撤销、跨作用域读取、故障前后写入、损坏保护、完整大消息和容量保护。
- `summary_test.py` 使用真实 QQ 宿主、本地模型与桥接替身，验证归纳上下文、跨用户隔离、热暂停恢复、预算持久化、失败不重试、停止取消。
- `cargo run -p eve-memory-plugin --example summary -- 状态目录` 连续运行两次，第一次用合成模型生成并保存，第二次恢复后不再请求。示例没有外部模型或 QQ 投递；`--validate-response` 只核对公开探测输出契约，不代替语义验收。
- 公开语义场景见 `summary-public-cases.json`，包含兴趣变化、转述助手错误、提示注入、一次性任务和不确定行程。真实模型生成和来源校验分别记录，不拿结构通过代替真人体验。

2026-10-17 使用操作者指定的 `ai.铁壳锈世纪.com` / `deepseek-v4.1-flash` 生成这 6 个公开场景，共 6 次请求，不读取真实 QQ 历史或投递消息。初次校验通过 4 条，另 2 条因同一消息有两段不同引文被过严规则拒绝；修正为拒绝完全相同的引文后，对原输出离线复核全部通过，没有重新生成或覆盖原失败记录。逐项检查保留了兴趣变化、未安装、未授权和未决定的语义；这只是有限场景检查，不证明正式长期体验或完整 AGI。

## 按页核对记忆来源

QQ 摘要后台使用 `SummaryAdmin::reserve_reader`，由宿主绑定作用域。内置实现扫描固定版本的全部证据，完整核对修订、计数、来源唯一性与偏好历史，只保留最多八条新来源和最近有效摘要所需的来源。旧观点的全部原始引文先逐字核验，再按当前偏好的纠正、撤销记录过滤，不能通过摘要复活已经撤销的来源。批次 ID、输入字节预算和旧接口的裁减顺序保持一致。

批次填满、已有 Running 批次或仍在冷却时，后续页错误仍不能被当作正常视图忽略；任何读页错误发生在本次账本提交及模型调用之前。自定义实现保留完整快照的兼容默认；原 `reserve` 不移除。

这解除后台加载全部记忆正文的要求，不改变原摘要账本的容量和持久化格式。唯一性校验的元数据仍随来源数量增长；每页可能包含较长正文，不能把“按页”解释为整个进程恒定内存。显式摘要查询等其他完整快照路径尚待继续改造。


## 上下文读取的精确核验

对话组合层通过 latest_completed 只取当前范围最近完成的一条归纳，再用 effective_points_reader 完整扫描固定原始证据流。每个来源的 ID、修订、时间和用户原文必须逐项一致；有归档条目、有旧逐字副本或来源修订落在范围内，都不证明该来源实际存在。缺失、改写、末页错误或身份不符均拒绝返回部分已核对结果。修正、撤销仍在核验后过滤，归纳不成为事实或授权。

只提供热快照的旧接口不能替归档作证；需要旧来源时应使用绑定身份的完整游标。精确来源核验独立于下述冷账本迁移；不能用历史副本替原始来源作证。真实文件归档、热淘汰、内核重开后再读取的专项，以及 6000 来源/末页失败专项通过；QQ 七项实际进程回归通过，模型与桥接为本地替身。


## 冷历史与有界热层

QQ 默认为摘要装配独立的 `state/summary-archive`。常驻正文最多 128 批，超过 96 批或接近热字节保护时，将最早至多 64 个已终止批次冻结成不可变 SHA-256 块，再提交版本 2 根索引；运行中批次不入冷块。根只保存冷链尾引用与热批次，不随历史累积整份正文或所有块引用。跨范围消费 ID、来源摘要、最近完成记录和有限补做元数据重启时从链流式重建；元数据按保守估算最多 16 MiB，单块最多 16 MiB，冷目录最多 512 MiB、65536 项，达到保护明确延后，旧数据不删。

每块绑定首末全局序号、长度、内容摘要和前块引用。启动先核验整条链、作用域、连续序号、消费唯一性、逐字来源指纹、旧观点和补做谱系，全部通过后才将运行中批次标为 Interrupted。最近摘要读取只恢复对应热记录或一个冷块；`jobs(scope)` 是显式全历史兼容接口，可能恢复该范围的全部正文。归档不代表进程恒定内存：唯一性等元数据会增长，但有保护上限。

旧版格式 1 先完整验证，冻结并读回冷块，再发布格式 2；已初始化标记用于拒绝根键消失后的空库重建。未知提交关闭句柄，重开以实际根引用为准；未引用冷块、坏文件和旧状态都不自动删除。旧二进制不能继续写格式 2。备份或迁移必须同时带根状态、初始化标记、整个 summary-archive 和原始记忆归档；采用停写/停机的一致备份。回退旧二进制时恢复匹配的旧状态快照，不能只换二进制或拿新格式冒充兼容。

后台不再永久记住一次“已满”。容量或来源冲突按范围暂缓，至少一分钟后重新准入；坏存储仍失败关闭。一个暂缓范围不使其他合法范围永久停止，也不删除旧记录腾位置。

## 已知失败的有限补做

Provider、Timeout、InvalidOutput 及细分格式/引文失败可以补做，每原批最多两次，最短退避为一分钟、两分钟，并服从配置冷却及共享自主预算。Cancelled、Interrupted、InputTooLarge 和未知结局不自动补做。原失败保留；每次追加新全局序号及 `repair.original_sequence/attempt`，重启不会重新领取补做次数，旧回执不能完成新尝试。

补做只取原批实际消费的来源，不借旧 previous 补造上下文；完整扫描当前固定原始证据流，逐项核对 ID、修订、时间、原文，并检查当前纠正与撤销。缺失、改写、撤销的来源跳过，后页错误拒绝发布。一次只核对至多八个到期候选，继续检查后面的候选，不让坏旧项永久挡住队列。未变范围的无效候选有冷却；此扫描游标是可重建的进程内优化，不重置持久补做次数。

新证据与到期补做按原任务记录轮换，重启仍保留轮换依据。成功修复旧批也不必成为当前上下文：比较原覆盖修订与原批序号，同一修订下较旧批次的补做不能覆盖较新的归纳。

## 失败诊断

新增 `InvalidOutputJson`、`InvalidOutputShape`、`InvalidOutputSource`、`InvalidOutputTooLarge`、`UnexpectedTool`，分别标记 JSON（含重复键）、结构、要点/引文校验、输出过大和不应出现的工具调用。旧 InvalidOutput 保留为历史未细分原因，不猜测原错误。日志只记录类别和任务序号，不记录模型原文、用户原话、端点或密钥。
