# 子代理调用与上下文增长

Chat 兼容模型可能每轮都返回
`call_1`。子代理保留多任务历史，旧请求构造器却要求整个请求中的调用编号唯一，导致工具已经执行后，下一步模型请求在本地报
`request`。请求构造器现在按当前 assistant
批次配对回执，只在发送时稳定区分跨轮重复编号，保持原始记录和已发送历史前缀；同批重复、缺失和多余回执仍拒绝。不会重放旧任务或已完成的工具。

子代理的完成通知使用顶层 `jobId/status`，脚本完成通知使用 `job`
对象。接续任务索引此前只读脚本格式，140 个已经终结的子代理任务仍被记为
queued；每次接续状态变化又追加完整旧任务表，近期接续快照累计约 18.8
万字符。初始化与在线接收现在都更新子代理终态，迟到的 queued
回执不会复活任务。上下文组成统计兼容结构化宿主通知，并分别列出子代理等来源。

提醒线为 200,000 token，整理线为 270,000 token；整理后仍建议保留约 100,000
token。自动历史投影的应急线同步上移到 300,000 token，且至少预计释放 30,000 token
才执行。普通追加保持缓存前缀，压缩后的首次请求同步固定投影。工具说明、生成提示、运行状态和管理面板同步这些数值。

`invalid_response` 现在给出无正文的结构类别，例如
`json_syntax`、`json_envelope`、`tool_call`；不会仅用这个笼统错误判断 API
或密钥不可用。检查通用子代理连接时应采用当前持久模型选择，而非启动配置的初始模型。

生产更新必须核对 `systemctl show ... -p ExecStart` 及实际进程命令行。旧机器多个模型更新 drop-in
按文件名排序覆盖较新的配置，执行服务实际仍运行旧控制源码。发布时归档重复的源码启动覆盖项，只留一份当前源码配置，并核对服务恢复、实例
sourceCommit 与真实派工终态，不能把升级入队当成完成。

回归覆盖 Chat 和 JSON
工具编号复用、多步工具、同实例追问、重启不重放、子代理终态同步，以及提醒、完整压缩边界、固定投影前缀和用量图。

启动控制期限也必须覆盖插件依次恢复的时间：脚本 enable 最长 300 秒，Eve 默认最长 300
秒，监督器此前却只等 180 秒，导致仍在恢复时被暂停并失去租约。现在 activate 使用 Eve 配置的启动期限加
360 秒（脚本恢复与加载窗口），默认 660 秒；停止期限与其他控制请求的期限保持各自语义。
