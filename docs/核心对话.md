# Eve 核心对话入口

`eve-app` 是独立组合层，`eve` 二进制装配 AGENT、普通配置、可替换协议的主模型、Runtime、Session、工具与 Control。Kernel 和通用定义层不依赖此应用。

## 启动

在仓库根目录配置宿主环境：

```powershell
$env:EVE_OPENAI_API_KEY = "<宿主凭据>"
# 默认模型与协议；可通过环境或配置文件覆盖：
$env:EVE_OPENAI_MODEL = "deepseek-v4.1-flash"
$env:EVE_OPENAI_PROTOCOL = "chat"
cargo run -p eve-app --locked -- --state-dir ./.eve --agent ./AGENT.md
```

核心默认 deepseek-v4.1-flash / chat，API 根地址沿用 https://ai.xn--rhqr8xvr4ahqsgka.com，实际请求 /v1/chat/completions。provider.openai 的 protocol（EVE_OPENAI_PROTOCOL）可显式选择 chat 或 responses；不根据模型名猜测或失败切换。库的 OpenAiConfig::new 仍默认 Responses，Chat 使用 OpenAiConfig::chat。

EVE_OPENAI_BASE_URL 接受 API 根地址、版本路径或完整所选协议 URL；生产 HTTPS、本地 loopback HTTP。完整端点与协议不符明确失败。普通 provider.openai 配置含 model、protocol、base_url、reasoning_effort、timeout_seconds（默认 120）、max_output_tokens（默认 2048）；配置文件覆盖环境，环境覆盖默认。空模型/未知协议拒绝启动，能力子集见[OpenAI 接入](./OpenAI接入.md)。reasoning_effort 普通配置默认空，核心 Chat 将空值映射为 none，Responses 空值不发送；显式非空值覆盖。Chat 最大输出映射为 max_tokens。

### 显式选择主模型角色

默认使用 provider.openai 的模型设置。将 model_role（EVE_OPENAI_MODEL_ROLE）设为 primary 后，终端与 QQBot 的共享装配改用 runtime.models.primary；同时注册四角色 Schema，并在每轮开始时通过公开快照与 ModelRolesConfig 校验。

```powershell
$env:EVE_OPENAI_MODEL_ROLE = "primary"
$env:EVE_MODELS_PRIMARY_ENABLED = "true"
$env:EVE_MODELS_PRIMARY_PROVIDER = "openai"
$env:EVE_MODELS_PRIMARY_MODEL = "deepseek-v4.1-flash"
$env:EVE_MODELS_PRIMARY_TIMEOUT_MS = "30000"
$env:EVE_MODELS_PRIMARY_MAX_OUTPUT_TOKENS = "512"
```

角色中的 model、timeout_ms 和 max_output_tokens 优先；base_url、protocol 和 reasoning_effort 沿用 provider.openai。角色输出限制为 0 时不发送 Provider 输出上限，期限支持 1–600000 ms。当前入口仍串行，max_concurrent_requests 不会提高实际并行度。空 credential_ref 继续使用宿主 EVE_OPENAI_API_KEY；非空引用尚待凭据代理，明确拒绝，不忽略引用或改用别的凭据。

显式 primary 关闭、模型配置无效、未知 Provider（当前只装配 openai）、未知角色或不支持的期限时，启动失败并保留原配置与状态，不退回默认模型。全部角色仍按已有快照契约校验；启动时先预检，随后每轮开始时捕获 provider.openai 与 runtime.models。两个命名空间必须来自同一配置修订；持续变动时最多重读四次，仍不一致则拒绝新轮。每轮及其工具往返固定使用该模型、期限与输出上限；配置服务的 Immediate/NewRequests 更新只影响下一轮模型选择，不改写在途选择。无效的新选择在 Session begin 前失败，不创建 Pending 或改写完成历史，修正配置后可提交新轮；不使用旧缓存隐式回退。终端对确认未开始、未执行工具的配置错误报告本轮失败并继续接收输入；保存失败、未知状态或不完整报告仍停止。具体字段见[模型配置](./模型配置.md)。宿主通过已有 ConfigAdmin 接口更新；首个切片没有添加终端/QQ 配置编辑命令、文件监听或环境变量热重载。修改环境、AGENT 或宿主凭据仍需重启。

每个 UTF-8 非空行是一轮，上限 32768 字节；超大行完整丢弃并提示，不截断。普通输入按顺序排队，最多 16 条待运行，满时明确拒绝；读取通道另有一个有界暂存。请求和工具仍串行/受既有批次并发上限约束，当前只显示保存后的完整回复。stream 配置明确拒绝。

## 取消与退出

| 输入 | 行为 |
| --- | --- |
| /help | 本地帮助，不调用模型 |
| /cancel | 清空已有待处理输入，精确取消当前代，等待工具析构和会话终态；允许后续新输入 |
| /quit | 清空队列，取消当前代并等待，再停止插件和刷新日志 |
| Ctrl+C | 与 /quit 共用收尾；标准输入未关闭也能退出 |
| EOF | 不再接收输入，处理完已接收的有效队列及当前轮次，再停止 |

批量管道输入用 EOF 完成全部轮次；末尾 /quit 现在表示立即退出，可能取消尚未完成的请求。重复取消幂等；没有在途任务时只提示。取消请求与实际取消完成分开显示；如果完整历史已经保存，保留 Completed 和实际回复，不因稍晚取消改写成功历史。旧代只通过绑定原 GenerationKey 的 wait 取得报告，终端不直接展示异步增量/工具事件。

宿主复用 eve-control-api / eve-control-plugin / SessionControlRunner；cancel 仅发信号，wait 才确认收尾，下一轮在此前不会启动。输入/信号/输出失败也先 cancel/wait，再停止 Kernel。当前没有自动判断自然语言取消、暂停/恢复或强制终止同步工具；本地收尾不证明远端停止、计费撤销或工具副作用回滚。

标准输入由独立线程读取，不使用会阻碍 Runtime 退出的 Tokio stdin 阻塞任务。读线程不持有 Kernel、控制服务、凭据或状态；退出关闭消息接收端，不等待阻塞的 stdin 读线程。停止控制插件后卸载它，释放执行器持有的 Kernel 引用，状态目录可在同一进程重新打开。

## 身份、状态与失败

默认明确加载本次工作目录的 AGENT.md，可用 --agent 指定；装配时只读一次，模型轮次和工具往返复用固定身份，重启读取新版本。坏身份在状态目录打开前失败，不创建或回退身份。

--session 默认 default、--user 默认 owner；相同目录与标识恢复完成历史。用户绑定是逻辑隔离。state.json 保存插件字节状态，普通配置位于 configuration/config.json；仅读取默认/环境值不自动创建配置文件。坏文件拒绝启动，不清空；独占和原子替换沿用既有契约。

Context 提供空资料/记忆/历史；Session 是唯一会话历史来源。echo 只本地回显 text，不访问文件/网络，参数、权限和插件状态由 Runtime 校验；当前至多一个工具批次。完整配对工具历史恢复时只传给模型，旧工具不重放。身份和凭据不作为会话历史保存；凭据仅从宿主环境进入 Provider。

Provider 失败或取消保存为 Failed，不加入 Completed 历史；没有自动重试。取消保存失败、最终保存失败或状态未知保留原 Pending/完整控制报告并停止后续输入。报告包括已生成文本、transcript、工具回执、已开始工具数、提交状态和真实错误。终端尽力展示未保存回复；组合 API 返回 ChatRunError，输出/停止/卸载/日志失败同时保留在 AppFailure。不能重新执行模型或工具修复保存；重启 Pending → Interrupted 不代表没有副作用。

终端写入或刷新失败时，组合 API 的 ChatOutputError 同时保留原始 IO 错误与完整 ControlReport（回复、transcript、工具回执和提交状态）。已保存的 Completed 不因显示失败变为 Failed 或 Pending；取消/执行失败的原报告也保留。下一条排队输入不会继续执行，不自动重试模型或工具；宿主可在处理输出故障后重新打开相同目录恢复历史。保存/任务失败同时遇到输出错误时，AppFailure 以 ChatRunError 保留原报告，并另存 IO 错误。

组合 API 的输入需为可转移到线程的 Send + 'static BufRead；输出仍由调用方提供。身份、宿主凭据、Runtime 并发和非流式策略仍在进程装配时固定；模型与 Provider 设置按每轮捕获配置服务的当前值。相同有效配置复用客户端，配置关闭/失效或新值无效时仍先拒绝，不因命中缓存绕过校验。

## 验收与下一步

```powershell
cargo test -p eve-app --locked
cargo run -p eve-app --locked -- --help
```

测试实际启动 eve 进程和 loopback HTTP：Responses/Chat 连续聊天、工具往返、恢复、坏状态保护；在模型等待期间取消，清空满队列后新输入和重启；工具已返回后退出而不重放；开放 stdin 下 /quit；输入失败收尾；取消记录/最终保存失败保留 Pending；同一进程连续两次打开目录。Unix 实际发送 SIGINT，Windows 验证命令取消/退出及相同收尾路径；真实 Windows 控制台 Ctrl+C 尚未人工验收。Chat 三轮和新进程恢复沿用同一主模型验收流程，验证默认 DeepSeek 配置、工具回执与 revision 4→6；截断 Chat 回复零工具执行。函数测试检查完成/取消竞争、写入/刷新故障及完整失败报告；故障验收实际连接 loopback Responses 完成 echo，检查原报告、已保存历史、后续队列零执行及同进程重开后的旧工具零重放。Runtime 既有测试继续验证工具析构/保存收尾。
