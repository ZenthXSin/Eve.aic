# 自由探索

Eve 的长期方向是逐渐形成连续的自我：有自己的兴趣、想法、经历，能够主动尝试，也能够休息和改变心意。自主探索不需要先设定目标，不以产出、收益或任务完成率衡量她是否值得行动。

这是 2026 年 11 月 5 日明确的产品原则，优先于此前把所有自主行为都转成目标、正收益评估和验收合同的设计。自主探索可以从一点好奇开始，也可以暂时没有明确线索。它不必事先知道会发现什么，不要求编写标题、目标或成功标准。清晰的用户委托仍按原任务机制处理。

探索过程中，Eve 可以使用已经获准的工具，决定接着看什么、试什么、是否转向以及何时停下。真实读取、操作结果和失败由宿主保存；她对经历的感受、解释和疑问单独记录。没有发现、尚不确定、改变兴趣和暂时放下都能成为连续经历，无须伪装成成功。

一次探索结束只表示这一段经历告一段落，不表示达成了某个目标。恢复时保留当前兴趣、已发生的操作、实际资源消耗和待确认结果；不能因为重启重放未知操作，也不能为了让循环继续而清空旧状态。身份、作用域和具体操作权限沿用已有授权，它们不用于要求探索证明收益。

执行审查只核对可信用户身份与具体操作是否直接危害系统安全。普通探索、阅读、开发和尝试不追加收益评审或逐步重复授权。原身份、工具范围、授权期限和真实资源计数继续有效，审查失败不能被伪装成无工具。

## 定义、实现与接入

`subject-api` 定义可选探索线索与独立经历；`subject-plugin` 核对经历来源、兴趣变化和回顾投影，`subject-sqlite` 持久保存经历、兴趣与来源索引。`task-api` 定义独立执行模式和 `SessionEnded`，`task-plugin` 实现用量、停止、恢复、静默投递及经历确认。`eve-app` 把回顾选择、当前工具表、会话执行和后续经历接起来，不在存储实现中加入产品调度。

没有明确计划或候选时先回顾，Eve 可以选择 `wait`、`reflect`、`explore` 或 `act`。`explore` 可以省略整个线索对象，也可以传空对象；不需要已有兴趣或非空线索。可选 `cue` 最多 1024 个 UTF-8 字节，`interest_key` 沿用合法标识规则。旧授权中缺少 `idle_reflection` 或值为 `false` 时也走这个入口，保留旧字段、身份、预算与期限，不补造回顾 ID。清晰的 `act` 仍使用普通任务的冻结合同。

回顾获知后续执行器的真实工具清单，探索执行前重新装配同一身份可用的工具。目录不可读时明确记录失败，不把错误降成零工具。探索可以读取源码、转向、遇到拒绝或停下；没有目标进度、收益或末批检查门槛。所有探索终态和进度保持静默，日后是否分享由 Eve 的发言机制决定。

## 经历与恢复

宿主只从同一会话的有效检查点采集工具参数、真实回执、错误和未知结果。主观感想只来自 `checkpoint.result`；宿主诊断不会成为她的感想。每个片段最多 2048 字节，每次经历保留末尾最多 64 个连续工具调用，附原字节数、SHA-256、偏移和截断标记。`total_tool_calls` 只表示本执行器检查点可观察的调用数，不包含子代理内部轨迹；任务用量另按自身与子代理合计。纯感想和未知结果不能冒充新外部证据，改变心意、休息和放下不要求新外界证据。

工具预算、期限或恢复次数用尽时，会话可以停止而不交报告；正常结束使用 `SessionEnded`，不表示目标成功。宿主的资源边界停止允许没有小结，共享模型协议仍要求有效的最终输出，不能把空响应或协议错误当作正常休息。错误和超时从检查点累计 `used_tool_calls + delegated_tool_calls` 与 `provider_requests + delegated_model_requests`；没有检查点则记录 `Failed`，不声称正常结束。已有小结恢复时直接使用原文。未知工具效果保留为 `Interrupted` 与未知经历，不重新执行。

结束后的顺序固定为：SQLite 保存独立经历，任务账本 `acknowledge_exploration` 确认经历已保存，最后写任务协调索引。确认时间不早于原终态时间。同一经历重复保存与确认幂等，范围或内容冲突报错并保留原记录；写失败只补存或确认。确认前完整任务正文不参与容量回收。数据库按写入序号分页，迁移先核对旧记录再事务升级；损坏、缺失和不支持版本都保留原文件，不自动清空。细节见 [主体存储](../crates/subject-sqlite/README.md) 与 [探索任务恢复](../crates/task-plugin/EXPLORATION.md)。

自身升级与源码更新的共用空闲门认可 `SessionEnded`，不要求完成通知、小结或已经确认独立经历。它从任务账本格式 2/3 的完整记录或格式 4 的哈希绑定冷正文读取探索标记、结束原因、时间、用量和检查点；原目录、档案和用户状态保持不变，尚未确认的经历在升级后继续补存或确认。探索终态出现在格式 1 中、不认识的状态、伪装成探索结束的普通任务、畸形终态、未配对调用及未知工具效果不能打开空闲门；仍在排队、执行或投递的普通任务继续阻止切换，旧格式普通任务的判定保留。该检查只判定是否空闲，不把结束等同于目标成功，也不重做工具。

## 模型会话与最小审查的组合

自由探索分支依赖最小审查 [PR #478](https://github.com/ZenthXSin/Eve.aic/pull/478)，当前基线为 `0c18c208512692352612f1b3810f08e3771e286c`，保留响应修复、模型会话隔离、直接系统安全审查和原话缺口处理。该安全头正式合入本分支，独立 PR 的三点差异仅包含探索功能，合并顺序为模型会话 #476 → 最小审查 #478 → 自由探索。组合保留以下行为，最终组合仍待动态验收：

- `WorkerRequest` 同时保留探索标记与宿主提供的模型会话。后台探索显式使用 `exploration` 角色，以持久 `task.id` 创建 `ModelSession::anchored` 并绑定轮次；不同探索不可共用固定键。子代理继续从父会话按宿主轮次与工具调用 ID 派生，不能被探索上下文覆盖。
- `qq_subject::Context` 与任务执行器透传 `assemble_with_model_session`。检查点继承 `model_session`、`pending_model_request` 和 `pending_request_fingerprint`；恢复先核对范围及原会话，仅同一实际请求沿用待确认编号。配置、正文或目的地变化时保留长期会话并使用新编号，不能凭正文反推身份。探索新增的检查点测试构造已补齐字段。
- 真正命中直接系统危害的动作通过 `ToolExecutionContext::model_session_for("review")` 从父任务派生审查会话。`developer-tools::review_request` 保留该绑定；共用的 `action-review::review_with_prompt` 将 `request.model_session` 传给模型，覆盖身份审查和系统安全审查两条路径。
- `ConfigureTool` 采用最小审查分支的无模型审查实现及 `configured_turn_id`，防止同一前台轮次反复重授预算；同时保留本分支允许无目标、旧缺省或 `false` 标记进入回顾的行为。新增旧配置兼容测试核对轮次和预算都不改变。
- 普通命令、待办、计划和探索不因缺少聊天原话而整轮拒绝；身份扩权仍使用可信身份与真实授权证据。探索的合同、收益与委派规则采用本分支实现；显式 `act` 保留普通任务的真实验收要求。
- `LlmHost` 同时保留响应修复、会话与请求恢复接线，以及探索可自然停止、不强制收尾报告的分支。进程验收检查初始化和普通探索均零审查、探索缓存键与前台及回顾不同、工具往返和恢复沿用原键、检查点会话恢复后不变，以及两条旧 `act` 兼容用例。

## 离线验收与发布状态

`python3 scripts/test-self-upgrade-runtime.py ExplorationIdleGateTests -v` 直接读取临时宿主 JSON 和冷档案，调用真实 `task_documents` 与 `runtime_idle_gate`，覆盖探索终态、资源停止、尚未确认经历、旧 `act` 忙碌与投递、坏记录拒绝和读取前后原文件不变；无需构建 Eve 或调用模型。

`connectors/qqbot/test/free_exploration_test.py` 使用真实 Eve 子进程、临时源码和 SQLite，模型与 QQ 由本地替身提供。13 条探索验收覆盖实际随机材料读取与兴趣转向、零工具休息、工具预算、期限、上游失败、路径拒绝、伪造证据、纯感想不能提高外界判断、保存回执后恢复、在途未知操作不重放、取消、授权额度耗尽，以及真实发送扫描保持静默。另有 2 条旧 `act` 兼容验收。

从初始化开始夹具就拒绝所有模型行动审批；自主预算配置及普通探索必须仍能完成，防止恒定允许的替身掩盖残留审查。CI 构建实际二进制后执行上述 15 条验收：

```sh
EVE_QQBOT_BINARY=target/debug/eve-qqbot python3 connectors/qqbot/test/free_exploration_test.py
```

统一构建后的最小 Rust 回归入口为 `eve-task-plugin`、`eve-subject-plugin`、`eve-subject-sqlite` 各自的 `--test exploration`，以及 `eve-app --lib` 的 `qq_exploration::tests`、`qq_tasks::tests` 和 `qq_subject::tests`。`21605078` 的 Linux CI 已通过全仓格式、构建检查和严格 Clippy；三个探索集成套件分别 13、4、11 项通过，应用测试为 444 项通过、2 项旧夹具失败。两处失败分别是预算测试先写未来时间、缺合同规划测试没有提供明确候选却期待目标规划。前者随安全头修复，后者由 `1f3da601` 加入明确候选并核对冻结的原始目标；均未放宽生产行为。

安全头还同步了普通 Web 计划、连续修复命令与可信身份的零审批进程夹具。探索的执行、静默结束、经历持久化和确认逻辑保持原实现；上述历史验收不能替代合入后最新头的实际验收。13 条探索与 2 条显式 `act` 进程用例仍待在最新组合上跑通，分支保持草稿。静态检查或本地替身通过不代表已经上线，也不证明真实模型自主选择了探索。
