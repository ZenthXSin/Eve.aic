# QQ 与 Web 共宿主接线

启用本地 Web 面板后，HTTP 对话使用同一任务、主体、权限、工具服务及独立的 Web 会话身份。宿主依据可信会话范围选择 Web 的记忆、经验和偏好工具，工具参数不能改变通道；上下文包含实际任务状态、主体状态、权限说明及注册工具目录。

审核原文在 QQ 平台入口和已认证 HTTP 入口分别持久化。每次运行携带宿主冻结的消息或请求编号，原文源按精确编号读取，缺失或编号变化不回退到聊天历史或最新消息。后台唤醒的文字不会由共宿主原文源当成用户授权。

Web 前台失败后的恢复任务只能继承失败记录中专门保存的完整审核原文。原文账本读取失败或旧记录缺少该字段时，不从普通 Session 历史补造授权，也不自动派发恢复任务；会话与故障记录保留，已有原文不会被截短。没有副作用回执不能作为已完成证明。

文件和进程条件观察使用实际开发后端公布的规范化工作目录与命令开关。没有已装配后端或后端未声明观察能力时，不依据环境变量猜测目录或开放进程观察。每次观察都重新核对管理身份与业务许可；运行中撤权或急停优先于启动时的静态操作者名单，重启后由持久授权账本继续约束。

Web 通知由宿主每秒收集，不依赖浏览器连接。任务和触发器结果先写入本地收件箱，再按稳定事件编号结算为本地保存；不冒充 QQ 平台送达或用户已读。仅装配任务或仅装配触发器时分别处理已有服务。重启恢复原收件箱和结算记录，不清空损坏文件。容量满保持待报告状态并允许登录面板标记已读；读写损坏或后台异常则进入宿主统一停止准入与保存收尾。

对应自动验收位于 `qq_review_source`、`qq_web_context` 和 `qq_web_notifications` 测试模块，覆盖原文精确分流、伪造工具参数无法切换通道、缺少配对定义拒绝启动、没有浏览器的任务通知及通知后台异常结束。完整进程与部署验收由统一验证任务记录，本说明不把未执行检查记作通过。
