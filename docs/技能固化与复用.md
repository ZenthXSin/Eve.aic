# 技能固化与复用

这是[首个自主学习目标](./自主学习首个目标.md)（#134）的第四个切片。[实践验证](./实践验证.md)通过后，Eve 把这次做法提炼成一个带参数的技能。技能要先在实际运行环境中用新参数再验证一次，通过后才启用。之后同一用户的独立任务可以直接选用它，每次调用的结果都以实际运行证据为准。

技能是参数化的产物模板，只含数据文件与探测项；参数值只能是标识、整数或固定选项。实例化只做受限的文本替换，不执行任何代码；实例仍要经过实践的通用检查、运行器的结构检查和实际运行。技能不会给 Eve 增加新的执行权限，它只生成交给同一运行器的数据草稿。所以验证通过后，在宿主既有授信范围内自动启用。

## 启用

```bash
./target/debug/eve-qqbot --state-dir .eve-qqbot --interest-learning \
  --practice-mindustry-server /opt/mindustry/server-release.jar --skill-learning
```

- `--skill-learning` 必须同时指定 `--practice-mindustry-server`，默认关闭。
- 提炼与选择复用主模型配置和 `EVE_OPENAI_API_KEY`。
- 开启后，之前已验证、还没提炼过的实践也会按完成时间依次提炼。

QQ 命令：
- `/skills`：列出自己的技能，包括启用版本、版本数，以及调用次数和其中验证通过的次数。
- `/skill 技能ID`：查看每个版本的模板说明、参数、来源实践、验证参数与探测结果，以及启用记录和最近的调用。
- `/skill disable 技能ID`：停用。
- `/skill enable 技能ID 版本`：启用某个已验证版本。
- `/skill rollback 技能ID`：回退到当前启用版本之前的已验证版本。

技能只属于来源用户；其他用户看不到，也不能更改。未启用时回复“技能固化未启用。”。`/practice` 中使用技能实例的尝试会注明技能和版本。

## 固化：提炼与验证

每次已验证的实践至多提炼一次，同一时间只提炼一个；技能实例验证通过的实践不再提炼，避免重复造技能。

| 阶段 | 先保存 | 再执行 |
| --- | --- | --- |
| 准入 | Running 提炼、来源实践与尝试、来源草稿副本、运行器声明 | 一次无工具的提炼请求 |
| 提案 | 提案与宿主检查结果；通过的进入 Verifying，并写入宿主选取的验证参数 | 在全新目录中实际运行验证实例 |
| 验证 | 运行证据与结论；通过时同一次提交写入技能版本与启用记录 | — |

提炼请求只含已验证的产物、那次运行的证据、运行器声明与同一用户已有的技能，不含用户原话或学习目标描述。提炼规则与领域无关。提案可以是：
- 不可复用：没有通用方法，或已被已有技能覆盖；
- 新技能；
- 已有技能的新版本（`extends`）。同名新技能会被拒绝，要求作为新版本，不另造一个。

宿主的检查（任一不通过即记为“已拒绝”，不运行）：
- 模板形状：1～8 个参数；整数 `min < max`；选项 2～8 个；占位符 `{{参数名}}` 都有对应参数；探测属性在运行器声明中；**每个参数都出现在某项探测的对象或期望值中**，这样实际运行才能说明参数确实生效。
- 忠实性：用原参数实例化，必须逐字还原来源草稿的全部文件与探测。
- 验证参数由宿主按固定规则选取，不由模型决定：每个参数都取与原值不同的值。标识加后缀，整数取边界值（原值不是上界时取上界），选项取第一个不同项。验证实例还要通过运行器的结构检查。

验证实例在全新目录中实际运行，只有已加载、没有警告且全部探测通过才形成技能版本。声称的取值范围过宽、边界值实际不可用时，记为“未验证”，保留证据，不形成技能。

## 启用、停用与回退

- 新版本验证通过即自动启用，并记录“验证通过后自动启用”。
- 用户停用后，之后验证通过的新版本保持停用，直到用户重新启用。
- 启用某个版本或回退只改变启用版本并留下记录；所有已验证版本都保留，不可修改。
- 停用的技能不会提供给选择器。

## 复用：后续任务的调用

开启技能固化后，实践第一次尝试前，若该用户在同一运行器下有已启用的技能（至多 8 个），先保存一条 Running 选择，再发出一次无工具的选择请求：
- 选定技能且参数合规：宿主实例化模板，作为第一次草稿交给实践流程，不再请求草稿器；
- 没有适用技能、选择请求失败，或选定的版本不在候选中、参数不合规：如实记录（不适用、失败或已拒绝），任务照常草稿；
- 使用技能后结构检查不通过或运行未验证：后续尝试照常由草稿器依据证据修正。

调用结果不另行运行。实践结束后、以及每次启动时，宿主依据实践账本中那次尝试的结局写入结果：已验证、未通过、结构检查未通过、放弃，或因进程退出中断。

## 持久化与恢复

技能账本 `eve.skill/skill.v1` 经公开 StateStore 保存，文件与 PostgreSQL 后端语义相同。账本包含：
- 技能：版本与启用记录；
- 提炼：来源、提案、检查问题、验证参数与证据；
- 选择：候选、选定、问题与调用结果。

| 情况 | 行为 |
| --- | --- |
| 保存准入、提案、证据、选择或启用变更失败 | 不执行下一项请求或运行；关闭账本句柄，下次打开读到实际提交结果 |
| 重启发现 Running 提炼或选择 | 记为 `Interrupted`，保留到达的阶段，不重放；这次实践不再提炼 |
| 选定技能后进程退出 | 实践同样记为中断；启动时依据实践账本把调用结果写为中断，不补写证据 |
| 提炼请求失败或输出不合规 | 记为 `Failed`，不重试 |
| 服务停止或提炼超过 10 分钟 | 终止验证运行，记为放弃，结果未知 |
| 提炼记录 32、技能 32、选择 64 条已满 | 停止新的提炼，或这次照常草稿；不淘汰旧记录 |
| 账本损坏、重复键、版本未知，或模板不能还原来源、验证参数不符合规则、“已验证”却缺证据或带警告、版本指向不存在的提炼等不一致 | 拒绝启动，保留原字节，不清空 |

技能不写认知状态、知识或实践记录；调用的产物与证据保存在实践账本中，技能账本只引用实践 ID。

## 分层

| 层 | 内容 |
| --- | --- |
| `eve-skill-api` | 参数、模板、提案、提炼、技能版本与启用记录、选择与调用结果；可替换的 `SkillAdmin`、`SkillDistiller`、`SkillSelector`；纯函数 `template_issues`、`instantiate`、`holdout_arguments`、`proposal_issues` |
| `eve-skill-plugin` | 持久账本与启动核对；`ModelSkillDistiller`、`ModelSkillSelector`（各一次无工具请求、严格 JSON）；串起提炼、检查与验证运行的 `Consolidator`；包装任一草稿器的 `SkillAwareDrafter`；依据实践账本结算调用的 `settle` |
| `eve-app` | 在 QQ 实践后台中先固化再实践，提供 `/skills`、`/skill` 与参数校验；`InterestComponents` 可替换提炼器与选择器 |

`eve-practice-api` 新增不依赖任务资料的 `validate_artifact`，供技能实例与验证实例核对产物形状。

## 验收边界

- **确定性替身**：
  - Rust 测试覆盖模板与参数校验、忠实性与验证参数、账本的阶段持久化与提交失败、范围过宽未验证、停用保持与回退、选择失败或参数不合规时照常草稿、重启中断与依据实践结算，以及损坏与不一致账本的拒绝。
  - 真实 `eve-qqbot` 进程测试 `connectors/qqbot/test/skill_test.py` 使用模型替身与服务端替身，覆盖：一次普通聊天到技能启用；重启后另一项独立任务调用技能并验证通过；命令显示、他人不可见；停用后不选用、新版本保持停用、启用与回退；不忠实的模板不运行；提炼途中强杀记为中断且不重放；默认关闭与参数拒绝。
- **真实运行**：CI 的“Mindustry 真实运行验收”在 v160.7 服务端上运行同一进程测试：验证实例 `sample-wall-b` 的生命值 2000，以及后续任务实例 `sturdy-wall` 的生命值 1200，均实际加载且全部探测通过。
- **未覆盖**：提炼与选择没有接入真实模型，模板质量未经评估；技能不跨用户共享，跨用户共享需要先有去除个人内容的授信设计。生成新的工具插件与反馈学习属于 #134 后续步骤；主动邀请见[主动交流与邀请](./主动交流与邀请.md)。
