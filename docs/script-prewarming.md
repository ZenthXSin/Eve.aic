# 脚本预热与轮次准备

脚本运行时启用时保留一个不含用户代码的隔离 worker。持久接纳任务后取用待命 worker；没有可用 worker
时，其空载启动与原有 `deno check` 并行。类型检查成功、源码复核和 running
事实持久提交后才交付不可变的用户模块。每个 worker
最多执行一个任务，用后销毁；待命数量上限为一个，不共用任务全局状态，不增加模型请求。

worker 仅能读固定契约、协议和引导模块；用户模块来自已检查的不可变 data URL，无脚本目录读权限。空载
worker 需报告 ready；启动失败或 10 秒未就绪即销毁，任务按真实状态失败。取消和关闭同时销毁所持
worker，终止检查进程；未决动作保持 unknown，不自动重跑。

任务摘要可携带 timing：prewarmed 表示使用预先创建的空载 worker，checkMs 为检查进程耗时，workerWaitMs
为检查后等待 ready 的剩余时间，preparationMs 为接纳后至运行状态提交前的准备耗时，executionMs
为交付用户代码至终止开始的耗时。并行阶段不能直接相加；原有 startedAt/finishedAt
和动作回执继续提供完整事实。

默认及 sync 的前台等待上限仍为 5 秒；async 立即返回原
jobId。前台结束等待不取消后台任务，也不表示任务完成。

轮次在工具批次结束、实时通知应用及暂停/预算检查后，并行准备记忆与自我便签；两者全部结束后再投影上下文，错误也需等待另一项结束，避免迟到准备污染下一轮。通知读取保持并行、事实应用次序保持不变。model_start.runtimeTiming.noticeReads
细分预算、手机、脚本、命令、mind 和子代理读取耗时；总 noticesMs 还包含通知应用和相关事实提交。

无 import/export 或 reference 指令的脚本用内容寻址的稳定临时模块 URL 做检查；Deno
仍在每次调用时校验其原生缓存和依赖变化，不自行跳过检查，也不缓存动作结果。包含导入或 reference
的脚本保留原检查路径。临时模块最多保留 64
份空闲原件，并发检查持有的文件不清除；运行时关闭后清理，原任务源码仍保留。
