# 消息关系判断与动作映射

#29 第二切片。eve-message-api 定义输入、多意图判断、UTF-8 文字范围、公开判断/路由服务及结果；eve-message-plugin 提供可替换判断插件和消息路由插件。模型调用继续由内置宿主实现，Kernel 不持有消息语义。通道先用 ControlService 开始任务，再提交绑定完整 GenerationKey 的新消息。

判断输入来自控制服务当前代快照（真实输入、阶段、取消状态及已知工具开始数），并携带本代最近澄清的 ID、原消息和可见问题，调用方不能伪造原任务。判断器仅返回标签、0–100 置信度及原消息字节范围；新请求只采用原消息文字，不把判断器生成的要求当作用户指令。输出校验完整绑定、范围边界/重叠、标签数及可见依据。默认规则仅识别明确命令，不声称理解任意自然语言：每行 /add、/correct、/answer、/new 后带文字；/cancel、/continue、/unrelated、/pause、/resume 无参数。未知或格式不完整返回模糊判断。

补充/纠正可以多行并存，按原消息顺序组合：基准是控制服务当前代实际输入，更正优先于基准，补充与澄清答复追加条件。新代使用同 task_id；/new 使用 message_id 作为新 task_id，且不携带旧未完成任务的输入。只有完成历史从 SessionService 继续提供；失败输入不伪装成已完成历史。/answer 必须引用当前代最近一次由路由器发出的 question_id，结合该问题原消息与本次原文答复；不引用问题的答复只澄清，不取消。

继续/无关消息保持当前任务；取消只 cancel/wait；明确新任务或补充/纠正先停止目标并等待工具析构/最终提交，再原子比较完整代际并提交新代。补充/纠正若已发生或未知工具副作用则只返回澄清和原报告，不自动重跑原要求；/new 明确开启独立请求。完成/取消竞争如实保留已提交历史。低置信度、冲突、多种互斥控制意图、未知判断、超时/异常及不支持的暂停/继续状态恢复返回可读澄清，不自动取消。没有把 Future 当成可无损挂起状态。

分类完成后及取消收尾后都校验完整目标代际；ControlService.submit_if_current 在同一临界区比较并提交，避免“检查后新任务完成，旧分类又覆盖它”的竞争。Pending/Unknown 为 Blocked，保存失败不触发替代或重试。控制报告保留副作用及完整输出，路由报告独立于事件展示。正常新消息无意图变更时不制造额外进度事件。

配置来自独立配置插件 runtime.messages：confidence_threshold 默认 80（1–100）、judge_timeout_ms 默认 2000（1–60000）、max_input_bytes 默认 65536（1–1048576）、max_tracked_messages 默认 256（1–65536）。文件覆盖环境 EVE_MESSAGE_*，环境覆盖默认。每次提交 begin_request，分类期限/初始大小和记录容量在接受时固定；执行动作前 read_request 重新读取阈值与组合大小，遵守立即替换/仅新请求语义。

接受后执行 Future 由路由插件持有，丢弃等待 Future 不撤销动作。同一用户/会话 message_id 以完整输入进行本进程去重，改变目标/文字/回复引用拒绝覆盖。最多保留配置数量的记录，满时拒绝新消息，不驱逐旧报告后假装未执行。消息记录/澄清不持久化，重启后不能自动重放消息或继续旧判断；真实历史仍由会话插件管理。停止关闭新准入并取消未完成判断，已准入的取消收尾保留原报告；不会在停止后开启替代代。仍需先取消/等待在途模型再停止 Kernel。

本切片采用规则和确定性 Mock，未接 Jev、内置 LLM 语义判断、自动步骤依赖图失效、暂停检查点或远端副作用回滚。标签含暂停/恢复只用于明确回退，后续先定义恢复语义再实现。


## 动作约定

| 明确命令/组合 | 动作 |
| --- | --- |
| /continue、/unrelated | 保持当前代，无额外模型请求 |
| /cancel | 取消并等待，返回原报告 |
| /new 原文，可带 /cancel | 取消并等待，创建独立 task_id |
| /add、/correct，可并存或带 /continue、/cancel | 取消并等待；工具数明确为 0 才提交同任务修订 |
| /answer 原文 | 先验证当前代最新 question_id；再按修订处理 |
| /new 混合修订、修订混合 /unrelated | 澄清冲突，保留当前代 |
| /pause、/resume | 明确澄清不支持，不挂起 Future |
| 未知文字、异常、非法输出、低置信度 | 澄清，不取消 |

通过 RelationPlugin::new 注入公开 RelationJudge；独立实现插件可发布自己的 RelationServiceHandle，并以 MessageRouterPlugin::new(PluginDependency, ServiceId) 配置依赖范围和服务 ID。判断与路由分属不同 PluginId，避免同插件依赖。此处的用户身份由通道/宿主提供，仍不构成认证或不可信插件沙箱。

RouteOutcome 区分 Unchanged、Clarify、Cancelled、Replaced、Blocked、Stale、ControlFailed、Stopped。取消后过时或有条件提交失败仍携带 prior；调用方不可将旧报告当成新代完成结果。事件必须沿用 ControlService.accepts 在展示时检查，不依赖分类时的快照。实际示例与回归步骤见[执行书](./执行书.md#消息关系与重规划验收)。
