# 客户端自动更新

Windows、Linux 和 macOS 的 x64 / ARM64 便携包共用随包 Node 启动器。第一次安装包含自动更新的新版仍需完整解压；旧版启动器不会自动获得此能力。后续保持原安装目录，使用 Start-Eve 或 Start-Console 启动即可。

## 使用

默认在启动后后台检查 GitHub 公开的最新稳定 Release，此后每六小时检查一次。只下载对应系统及 CPU 的包，完成全部校验后提示“下次启动自动启用”。当前聊天进程继续运行；退出并正常重启时再切换，不会为更新强行中断训练。下载失败继续使用原版本，到下一次检查重试。

可在 `config.json` 设置下列可选项；没有这些字段的已有配置沿用默认值，启动器不会为补字段重写配置。

```json
"updates": { "enabled": true, "check_interval_hours": 6 }
```

检查间隔支持 0.25 至 168 小时。`enabled: false` 关闭后台检查和待安装版本的自动切换，已经启用的版本继续使用。命令行 `--no-update` 只对当前启动生效；`--no-check-updates` 停止网络检查，但仍可启用已经下载的版本。Windows x64 的 PowerShell 包装器对应参数为 `-NoUpdate` / `-NoCheckUpdates`。

双击 Windows 的 **Update-Eve.cmd** 可立即检查，不需要配置 QQ 或模型凭据。在终端中还可查看状态或安排回退：

| 平台 | 立即检查 | 查看状态 | 下次启动回退 |
| --- | --- | --- | --- |
| Windows x64 | `Update-Eve.cmd` | `Update-Eve.cmd -Status` | `Update-Eve.cmd -Rollback` |
| Windows ARM64 | `Update-Eve.cmd` | `Update-Eve.cmd --status` | `Update-Eve.cmd --rollback` |
| Linux | `./Update-Eve.sh` | `./Update-Eve.sh --status` | `./Update-Eve.sh --rollback` |
| macOS | `./Update-Eve.command` | `./Update-Eve.command --status` | `./Update-Eve.command --rollback` |

回退前退出正在运行的实例。回退只改变下次启动的程序选择，不倒退对话和训练数据；没有上一更新版本时返回最初解压的随包版本。需要持续使用旧版时同时关闭自动更新，否则之后仍会检查最新稳定版。手动检查不受自动检查间隔限制，也能重试失败的候选版本。

## 文件与恢复

原目录的 `config.json`、自定义 `AGENT.md` 和 `data/qq`、`data/console` 始终作为用户文件使用。新版程序、Node、QQ 桥接和依赖保存在 `.eve-updates/versions/` 的独立目录；不会把发行包中的 AGENT 覆盖到用户身份上。安装索引 `.eve-updates/installation.json` 原子提交当前、上一及待启用版本，保存清单散列与最近检查结果。

下载不完整、散列不符、空间不足或程序自检失败都不会成为可启用版本。启动时重新检查候选目录、全部文件、五个运行器的帮助、Node、启动器语法和当前配置；通过才提交切换。损坏候选保留证据并继续旧版；损坏的当前更新版本优先返回上一完整版本，其次返回随包版本。无法解析的索引保留原字节并提示，使用随包版本启动，不自动清空。

同一安装目录的更新器独占运行，正常退出释放锁；确认进程已退出的旧锁可恢复。恢复者也相互排斥，防止误删另一个新启动器的锁。极少数情况下，进程在恢复旧锁的几条文件操作之间崩溃，可能留下 `recovery-*.lock`；先退出所有 Eve 实例，保留索引及锁的备份并核对记录 PID 已退出，才可移走该恢复锁后重试。不能把删除配置、记忆或训练状态当作恢复方式。

强制断电留下的未引用暂存目录或版本目录不会执行，也不会清除用户数据。当前版本保留上一版本供回退；历史版本暂不自动删除，因此需预留下载和解压空间。手动整理时先退出 Eve 并备份索引，只清理索引未引用的版本及暂存目录。仍建议定期备份用户文件。

## 契约与发行边界

`update-contract.mjs` 定义平台、版本、路径和清单契约，`update-archive.mjs` 与 `Updater.mjs` 实现解码、下载及安装，`Launch.mjs` 组合启动流程。实现可在代码层替换传输；正式启动器固定使用本仓库的 GitHub HTTPS 公开发行，不接受任意更新源或明文网络开关，也不向更新服务传输 QQ、模型密钥或交互记录。

只接受数值递增的稳定 `v主.次.补丁`；草稿、预发行、降级或错误平台拒绝自动安装。GitHub 的资产 SHA-256 必须存在且与下载相符，包内清单必须逐文件相符；压缩包限 160 MiB，解压文件合计限 512 MiB、12000 个文件。不接受链接、特殊文件、目录穿越、未登记文件、用户配置或训练数据。完整性信任来自 GitHub HTTPS 资产摘要与包内清单；程序目前未签名。

清单 `updater_protocol: 1` 与 `state_schema_generation: 1` 表明更新协议及数据代际兼容。改变不兼容的状态格式时维护者必须提升代际；当前客户端拒绝该新版，迁移改用明确的手动流程，不能修改这些字段来绕过检查。回退也要求数据代际兼容。

原安装目录的引导程序保持可用，之后的后台检查由已选择的新版启动器负责。直接运行原目录的单个 exe 不经过此选择流程；需要随升级切换的聊天客户端应使用 Start-Eve / Start-Console。

## 验收

`node scripts/test-client-update.mjs` 验证六平台资产选择、实际 ZIP/tar 解码、SHA-256、路径和代际拒绝、并发恢复、取消、坏索引保留、跨实例启用与回退。`python scripts/test-portable-package.py dist` 对实际原生包进行下载断线、重试、下次启动启用新版和回退；实际运行五个程序及随包 Node，并确认 Web、两条 QQ 替身回执、恢复零重放、配置、自定义身份及训练样本保留。

六个平台都执行此原生验收，发布脚本要求对应结果全部通过才公开 Release。验收使用合成凭据及回环替身，不连接正式 QQ 或外部模型。
