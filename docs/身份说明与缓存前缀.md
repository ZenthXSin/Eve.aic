# 身份说明与缓存前缀

QQ 人名资料和身份卡原先把固定使用说明与逐轮变化的 JSON 放在历史之后。跨轮增加历史时，即使说明一字未变，也不能作为历史之前的稳定前缀复用。

本次在资料来源处拆分：`qq_people::Context` 将原有人名说明放入当轮 `pinned`，`IdentityContext` 将原有身份说明放入同一字段。主对话和自主发言已有的装配器会把它们放在历史之前。共移动原文 749 字符，不新增交流规则。动态 JSON 保留简短数据标记。

## 动态事实和兼容性

姓名、称呼来源、主人绑定、身份角色、来访信息、个人印象及画像仍由原代码按当轮范围读取，资料修订摘要仍只对应数据。未保留旧身份，不按昵称授权，也未扩大个人资料或原文的跨会话可见范围。群观察内部会话和无作用域调用仍在原位置提前返回，不注入个人资料及其解释。

`pinned` 是每次组装重新产生的快照字段，不是持久授权。授权状态变化会更新已有授权说明；连续相同授权下固定前缀才可保持一致。持久存储格式、历史记录和恢复路径没有变化。停用此补丁可还原两处说明位置，不迁移数据、不删除证据、不重放发送或部署。

身份 JSON 的 `kind=eve.identity.v1` 和字段保持原样。进程验收改为按 `kind` 读取数据行，避免把前缀中的固定说明误当作身份卡。

## 验收范围

使用既有实际 QQ 宿主进程验收，本地模型和 QQ 桥接替身，覆盖姓名纠正、群范围、重启、印象来源与删除、共享暂停、画像失效，以及主人账号热绑定和撤销。增加同一授权连续轮前缀不变、来访次数更新、两段说明只在固定前缀出现一次、群观察不注入个人说明的断言。

对基线与候选的同一五轮绑定场景保存实际请求，比较完整工具定义、人名资料、身份卡与固定前缀。只忽略独立进程自然不同的精确来访时间戳；不忽略身份、权限或资料内容差异。

2026-11-11 本地实测：7 项人名资料进程用例及 2 项群观察用例通过；上述五轮各增加 751 个前缀字符（原说明 749 字符及两处换行）、1781 个 UTF-8 字节。身份卡逐字段相等，工具定义相等，人名资料除上述时间戳外相等；同授权连续轮前缀相等，来访次数仍递增。基线使用已保留的 PR540 候选，未重新构建它。完整合成请求与比较脚本保存在独立工作区的 `validation/`，没有向真实模型或 QQ 发送请求。

3 项相关 Rust 单元测试、格式检查和 `eve-app` 库及 QQ 入口的严格 Clippy 通过。五轮比较只覆盖绑定场景的所列字段，并非完整请求逐字段等价；群观察通过进程日志证明，未加入五轮请求比较。测试中的未绑定和解绑账号仍有夹具预置的管理员身份，断言其不再是主人，不表示删除全部管理员权限。

该比较测量的是实际请求结构，不能将字符数等同为缓存 token。上游是否报告命中、分配到哪个缓存节点及其内部序列化不由此验收决定。历史之后仍有其他动态上下文，不能据本补丁承诺跨轮高命中率。固定说明与当前数据距离增大也可能影响模型行为；结构与权限回归不证明表达完全等价或蒸馏效果通过。

## 原效果任务

自然分条、长任务中途交流及经验实际采用继续独立验收。已有六次正向组织提炼对照没有显示新增提示规则的必要增益，因此本补丁不加入该候选说明，也不改变表达策略或模型。已保存经验、发送成功和请求前缀优化分别支持不同结论，不能互相代替。
