# 集成测试分支

`codex/integration-testing` 用于组合验收尚未合并的功能。它从 main 建立，保留各 PR 的提交历史；集成不关闭原 PR、不改变其目标分支，也不代表这些功能已经进入 main。该分支对应的 PR 保持草稿状态，供审阅测试结果。

## 离线验收

需要 Rust 1.89+，在仓库根目录执行：

```bash
cargo fmt --all -- --check
cargo check --workspace --all-targets --locked
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo test --workspace --locked
cargo +1.89.0 check --workspace --all-targets --locked
cargo run -p eve-runtime --locked
cargo run -p eve-runtime --example lifecycle_operations --locked
cargo run -p eve-runtime --example llm_tool_loop --locked
cargo run -p eve-runtime --example configuration --locked
```

全量测试保持默认并行执行。最后两个示例分别验收模型工具闭环和配置生效；当前 LLM Host 仍使用构造时的配置，没有自动接入配置服务。

需要验证独立进程配置恢复时，选用一个不存在的独立目录，将同一路径连续传给两次 `configuration` 示例，并设置 `EVE_LLM_MAX_PARALLEL_TOOL_CALLS=10`。第一次应输出并发 10 → 12，第二次应从文件恢复 12 并更新到 14；文件修订依次为 2、4，第二次保留 4 个备份。

CI 在 Ubuntu 和 Windows 运行完整测试、Mock 工具闭环、配置两次独立进程恢复及状态恢复，并在 Ubuntu 检查最低 Rust 版本。

## 真实 API 的后续验收

此快照没有 OpenAI Provider，`llm_tool_loop` 使用确定性的无网络 Mock。普通配置插件拒绝敏感/加密字段；密钥库、密钥引用与凭据代理尚未交付。

真实验收需要继续实现独立 OpenAI Responses 适配器，以及由宿主提供凭据的测试入口；先以本地 HTTP 夹具验证请求、函数调用、错误和脱敏，再在用户提供 API 地址、模型及凭据后，执行一次文本请求和一次插件工具往返。测试凭据不写入仓库、PR、Issue 或日志，也不通过普通配置字段保存。

真实验收结果须记录实际接口类型、模型、测试场景和成功/失败边界，不能以 Mock 或仅 HTTP 连通性代替真实模型工具闭环。
