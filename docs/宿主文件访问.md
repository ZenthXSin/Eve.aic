# 宿主文件访问

开启开发配置 `host_filesystem: true` 后，Eve 的工作区是默认工程位置。已授权操作者可以直接读写、搜索工作区外的普通文件，在指定绝对目录运行命令，并等待外部文件发生变化。工具与 AGENT 提示词按实际能力说明这些用法，不要求把文件搬进工程。

## 范围与路径

`list_files`、`read_file`、`write_file`、`edit_file`、`apply_patch`、`search_files` 接受绝对路径，`run_command.cwd` 接受绝对目录。相对路径、默认 `.` 和自升级源码选择继续指向当前工程。绝对操作不要求目标是 Git 仓库，也不为只读外部文件创建私有检出。

宿主在审核之前解析链接并绑定规范目标；读取、搜索与写入回执给出可继续使用的路径。审核和执行复查实际目标及当前身份，管理员不能用普通文件名的链接别名改写主人专用规则。补丁检查全部来源和移动目标，混合相对、绝对写法指向同一文件时整体拒绝。

修改外部文件仍需要真实用户原话和独立行动审查，审核包含完整旧正文和具体变更。原文件摘要不匹配、审核期间目标变化、当前身份被撤销都会拒绝执行。替换和补丁移动保留已有文件权限，Unix 保留属主、属组；不能保留就拒绝提交。新文件采用保守默认权限。

`protected_paths` 可配置额外受保护的绝对文件或目录，子路径同样受保护。开发配置自身、凭据、Git 管理目录、工具账本、候选与源码快照、升级队列，以及进程内存和设备路径不提供模型文件访问。保护规则也适用于相对路径、搜索遍历和文件等待；链接不能绕过。命令仍由实际宿主账号运行，经既有命令策略和行动审查，文件工具保护列表不是 OS 沙箱。

普通成员继续在自身隔离工程开发。配置 `ordinary_access` 不会把绝对宿主路径授予成员，后台和委托调用也使用当前可信身份。升级准备继续冻结当前会话源码，外部文件不因此混入源码快照。

## 持久化与恢复

`host_filesystem` 缺省为 false，`protected_paths` 缺省为空，旧配置保持原范围。配置在启动时读取，实际工具定义和观察服务从同一后端取得能力；替换后端不以旧环境配置猜测权限。

文件操作沿用 `operations.jsonl` 的 started/finished/failed 记录。崩溃留下的 started 表示结果未知，不自动重放；既有文件校验冲突、损坏账本和不可恢复部分都保留并明确报告。文件内容不写入操作审计。

文件等待继续保存原始 path 和 SHA256 或 missing，不改变已有条件、回执 ID 和去重参数。重启后重新核对宿主能力、操作者权限和保护路径；权限拒绝或无法读取明确失败，不解释成文件删除。别名条件每次观察该路径当前目标，固定目标可使用读取工具返回的规范路径。条件满足只提供事实，由 Eve 决定下一步行动与是否开口。

后台任务的固定验收合同也可记录绝对 `read_file.path` 和测试命令的绝对 `cwd`，保存时不改写原参数。合同只定义要观察的结果，执行仍经实际开发工具授权；被拒绝的读取或命令不能生成成功证据，不能靠合同取得新权限。

验收覆盖真实进程的工程外写入、搜索、读取、命令与重启；后台任务跨进程等待外部文件后完成原合同。Rust 覆盖默认目录、混合补丁、链接绑定、搜索和观察保护、权限撤销、普通成员项目以及 Unix 权限和属主保留。
