# Linux 完整迁移与重要业务隔离

交接包面向 Linux x86_64，要求 glibc 2.28 及以上；不支持 ARM 或 Alpine/musl。包含原迁移目录、所有原工作区与历史改动、Git 数据、状态与记忆、管理员绑定、运行配置、工具及缓存；新增的临时构建产物不作为运行依赖。明文包包含凭据和私密会话，只能通过用户指定的私有附件交付，不上传公开仓库。

基础分卷与增量分卷独立校验，增量保留此次新增源码、所有升级候选、日志证据，以及 Python/Node/Java/Git 等依赖。运行器使用包内的私有 Linux 动态加载器；不覆盖系统 libc，不安装系统服务，也不修改全局代理、CA 或用户环境。云会话平台认证不属于 Eve 的配置，不迁出。

下载全部分卷与启动 ZIP 到同一目录，解压启动 ZIP，执行其中 restore.sh。先校验全部分卷 SHA-256，再还原到全新目录；拒绝覆盖已存在安装。还原不会连接 QQ。进入安装目录后依次执行 `./eve doctor`、`./eve start`；状态使用 `./eve status`，停止使用 `./eve stop`。启动器对进程绑定启动时间与系统启动标识，避免根据旧 PID 终止无关进程。

Python、Node、Java 和主运行器随包携带，Rust 工具链继承原工具目录。源码自编译仍需要 Linux 的 C 编译工具链；doctor 会检查，Debian/Ubuntu 可由机器管理员安装 build-essential、pkg-config。GitHub 等外部令牌的有效性由服务方决定，包内保存的配置不保证令牌永久有效。

搬迁只重定位配置、Git 管理路径和候选路径，不重写会话原话或执行证据。旧升级 request/processing 不在新监督器目录重放；历史未知回执完整保留，使用修复后的门禁。候选文件收发版本与其源码保留，默认运行已验证的稳定二进制，不自动激活尚未评审的候选。

重要业务服务器上，完整开发配置不是隔离沙箱：

| 已确认的风险 | 影响与部署要求 |
| --- | --- |
| 管理员命令、构建和自升级与 Eve 同 UID | 可以访问该用户拥有的其他目录、进程和网络资源。不得以 root 或业务账户运行；优先放独立 VM，不能挂载业务目录、数据库凭据或 Docker socket |
| ordinary_access 的文件名判断未保护所有执行链源码 | 普通用户可改写部分脚本/源码，再影响未来管理员构建。完整开发工作区不得与业务代码共用；对外服务需分离产物工作区与受保护应用源码 |
| 子代理并发 10 不是 CPU/内存上限 | 需要 VM 或 cgroup 的 CPU、内存、进程数限额；应在实际服务器压测后设置，不能用空闲 RSS 推算峰值 |
| 构建缓存、候选、备份和日志会持续增长 | 需要独立磁盘/卷的容量上限、告警和人工可核对的保留策略；不要自动清理未知回执或唯一历史证据 |
| 普通过程组终止不能拦住主动脱离进程组的程序 | 必须依靠专用 VM/容器或 systemd KillMode=control-group 在服务停止时回收，不授予宿主权限 |
| Chromium 实践参数含 --no-sandbox | 有静态输入校验，但浏览器本身没有沙箱。重要业务宿主上不启用此运行器，或仅在专用隔离环境运行 |
| 未上线附件候选的下载在收完响应后才检查体积 | 超大响应可能造成内存压力，且默认重定向扩大网络访问范围。保留源码与候选供修复，不将其视为已通过服务器安全验收 |

现有正向边界包括文件相对路径及符号链接检查、写入 SHA 比较、命令环境白名单、调用总预算、可取消工具、回环 Web 面板认证与有界输入。它们不替代操作系统隔离。服务器配置再充足，也需要为重要业务划分独立账户、目录、资源和网络边界。

本次已检查实际离线日志、持久状态、运行器源码与资源限制；未进入或改变用户服务器，没有对重要业务进行任何攻击或压力测试。Linux 本地依赖自检与离线桥接验收只证明迁移包可加载和接话，不构成对任意服务器部署的安全保证。
