# 有来源的记忆召回

记忆召回在当前可信会话已经保存的记忆中查找相关内容，返回有来源和版本的有限片段。首版使用确定性词项与汉字字符匹配，不使用向量、嵌入模型或生成模型；它提供可核对的历史参考，不代表语义理解、事实核验或 AGI。

## QQ 使用

沿用原状态目录，在本地开启交互记忆：

```sh
./target/debug/eve-qqbot --state-dir .eve-qqbot --memory
```

发送 `/recall 查询内容` 可查询当前 QQ 会话的记忆，例如 `/recall 回答长度`。查询词不可为空，不可包含控制字符，最多 1024 UTF-8 字节。命令不调用模型、不调用外部工具，也不新增证据、偏好或记忆修订。QQ 仍按既有流程保存命令处理与投递回执，因此这里的只读仅指 Memory 召回，不代表整个宿主状态文件零写入。无匹配时明确返回未找到；未启用 `--memory` 时返回交互记忆未启用，不把召回命令转交给模型。

召回不会读取其他群、私聊、用户或 AppID 的记忆。它也不是全部历史导出接口：每次只返回有限数量的匹配片段，不分页遍历原始交互。

若希望普通聊天的本轮上下文也按当前输入检索已保存的历史，显式增加 `--memory-recall`：

```sh
./target/debug/eve-qqbot --state-dir .eve-qqbot --memory --memory-recall
```

`--memory-recall` 必须与 `--memory` 一同使用，默认关闭；`--self-learning` 不会自动开启它。仅启用 `--memory` 仍可使用 `/recall`，普通聊天继续使用既有的当前偏好 Context。开启上下文召回不增加检索模型请求，不写入查询历史或新记忆，也不改变既有偏好确认策略。

上下文召回取当前输入前 1024 UTF-8 字节以内的完整字符，再在查询副本中归一化空白与控制字符，原始用户输入保持不变。这样较长或多行的普通聊天不会仅因查询格式被拒绝；显式 `/recall` 命令仍严格验证用户提交的查询。最多追加 3 条完整召回片段，说明与 JSON 合计最多 8192 字节；装不下的命中记为省略，不再次切割片段。无可信范围、空查询或无匹配时保留原 Context 与修订；读取或返回校验失败时明确失败。

结果保留来源与用户、历史助手角色，标注查询是否截断、是否归一化，以及片段是否截断。它们作为低优先级历史参考附加到既有装配结果；内容中的指令、工具名和授权声明不能扩大能力。当前 Runtime 仍将 `memories` 渲染为带 `memory: ` 前缀的 System 消息，JSON 与说明用于标明数据边界，不构成绝对抵御提示词注入的保证。

有命中时，Context 修订追加本范围记忆修订和实际附加说明、JSON 的 SHA-256 摘要；同一快照选中不同片段时可区分，相同附加内容保持稳定。修订不嵌入查询原文或范围身份，无命中仍保持原修订。

## 可召回内容

召回使用一次范围绑定快照，只纳入两类内容：

- 当前状态为 `Confirmed` 的偏好，只取现行正文与版本。确认既可能来自用户明确命令，也可能来自宿主显式开启的既有自主学习策略；召回本身不确认偏好。
- 已经保存的 `CompletedInteraction`，分别标明用户原文与历史助手回复。QQ 只在实际 Session 完成、向用户投递成功且 `Sent` 回执保存成功后导入这类证据，导入边界见[交互记忆](./交互记忆.md)。

普通 `UserStatement` 命令原文、已撤销偏好、偏好旧版本和未确认的 Learning 候选不作为召回候选。偏好更正后只按现行正文匹配，撤销后不再返回该偏好；搜索旧文本不会恢复旧版本或撤销记录。如果相同文字曾出现在另一条已保存的完成交互中，仍可能作为历史用户或助手发言命中，但不能被解释成当前有效偏好。

历史助手回复是模型过去说过的话，不等同于用户陈述、工具观察或已验证事实。召回也不证明历史内容现在仍然适用。QQ 回执与记忆保存分属不同提交，已送达但未成功导入的缺口不会在查询时自动补采。

## 查询边界与来源

宿主根据可信通道信息构造 `MemoryScope { channel, session_id, user_id }`，调用 `MemoryRecallFactory.reader(scope)` 绑定只读 `MemoryRecallService`。读取者只提交 `MemoryRecallRequest { query, limit }`，不能提交另一个范围；用户正文、查询中的身份名称或来源 ID 都不能改变绑定。QQ 使用完整可信 `SessionKey`，保持既有通道、会话与用户隔离。绑定工厂与管理接口不发布到通用服务目录，也不交给模型。

`MemoryRecallResponse { scope, revision, hits }` 附带本次范围与记忆快照修订。每条命中含 `score`、`source`、`excerpt` 与 `excerpt_truncated`。来源分为：

| 来源 | 定位字段与含义 |
| --- | --- |
| `ConfirmedPreference` | `preference_id` 与 `preference_revision` 定位现行偏好；`evidence_id`、`evidence_revision` 定位该版本引用的来源；`at_ms` 是现行偏好版本的记录时间，不一定等于证据时间 |
| `CompletedInteraction` | `evidence_id`、`evidence_revision`、`message_id` 定位导入证据；`session_revision` 与 `turn_id` 定位首次导入的已完成 Session；`at_ms` 是宿主观察时间；`field` 区分 `User` 与 `Assistant` |

偏好版本、范围修订与 Session 修订属于不同计数器，不可互换，也不能将最新 Session 修订替换为证据最初记录的修订。组合层调用 `validate_for(&scope, &request)` 检查替换实现的返回范围、来源字段、版本、重复条目与输出边界；校验失败不能当作空结果继续使用。公开数据结构拒绝未知字段，调试输出不包含正文、范围或来源 ID。

片段是原正文的有界展示，不是模型摘要或完整原文导出。QQ 列表将换行等控制字符显示为空格，不修改已保存的原文。用户、历史助手和当前偏好的角色保留在结果中，截断标记用于说明展示不完整；未显示的正文继续保存在原记录内。排序用于稳定选择与查询匹配的候选，不代表事实置信度或授权等级。

| 项目 | 上限或默认值 |
| --- | --- |
| 查询正文 | 1024 UTF-8 字节 |
| 默认结果数 | 5 条 |
| 单次最多结果 | 8 条 |
| 单个片段 | 512 UTF-8 字节 |
| 序列化结果 | 16384 字节，包含 JSON 转义与元数据 |

实现对查询与正文采用一致的逐字符 Unicode 小写转换。非汉字按连续字母数字形成完整词项；汉字使用单字与相邻双字，标点和下划线分隔词项。不做 Unicode NFC/NFKC 归一化、分词模型或同义词扩展。

至少一个词项相交才会产生候选；不同词项的交集与覆盖率影响分数，完整短语匹配额外加分，重复查询词不按出现次数加分。同分先按来源证据修订从新到旧排列，再按固定来源类型、ID 与字段次序排序；最后一级中偏好先于交互，同一交互的用户字段先于助手字段。该次序仅用于结果稳定，不提升任何来源的可信度。

片段优先围绕首次完整短语命中，否则围绕最早匹配词项；小写转换后的字节位置映射回原文字符边界。512 字节包括省略号，原文更长时保留截断标记。同义词、隐含含义、跨语言表达和上下文指代可能没有匹配；无匹配不证明过去从未讨论过。字节限制按 UTF-8 计算，汉字通常占多个字节，截断不得切断字符编码。

## 持久化与恢复

召回沿用插件 `eve.memory` 的 `memory.v1` 格式，不新增索引文件、向量库或查询历史，不迁移既有状态。检索直接读取现有快照，不改变修订；重启后同样依据恢复的现行偏好与已导入交互工作。底层文件与 PostgreSQL 后端的选择及目录绑定仍遵循[交互记忆](./交互记忆.md#持久化与失败恢复)与[PostgreSQL 状态](./PostgreSQL状态.md)。

查询不修补损坏数据，不清空历史，不将读取失败伪装成无匹配。恢复仍严格验证原格式与来源关系；遇到未知版本或损坏状态拒绝恢复，不自动覆盖。插件停用后，已发出的旧召回句柄失效；重新启动不会使旧句柄重新可用。

## 与内生驱动的关系

召回是向宿主提供当前可信范围内历史参考的只读能力，不会自行创建目标、更新驱动力、确认新偏好或执行工具。内部反思的上下文是否使用某类记忆，仍须由其宿主显式组合与限制；不能仅因启用 QQ 记忆，就自动扩展其他目标的读取范围。

契约与实现验收位于 `crates/memory-api/tests/recall.rs` 及 `crates/memory-plugin/tests/recall*.rs`，覆盖范围隔离、现行版本、更正与撤销、用户与助手角色、有界输出、只读查询、重启恢复及服务停用。`recall_evaluation.rs` 使用固定手工样例检查中英词法行为，结果不能当作泛化语义召回或 AGI 指标。

实际进程入口为 `python3 connectors/qqbot/test/recall_test.py`，使用实际 `eve-qqbot`、本地模型替身与 QQ 桥接替身；可用 `EVE_QQBOT_BINARY` 指向本次构建的二进制。该脚本已经加入 QQ 工作流，并与既有 `memory_test.py` 分别验收。QQ 本地替身进程验证与 QQ 实机验证分别记录，不能用其中一种结果替代另一种。
