# 自主运行预算

这是[认知能力路线](./认知能力路线.md)第 4 项“长期目标与资源分配”的第一部分：长期运行预算不能因为重启、重复事件或自造目标而被放大。

以前各个后台学习组件分别限次。例如每个目标修订至多研究一次、每次实践至多三次草稿、反思每次启动至多 32 项。但这些限制没有跨重启的总量：进程每重启一次，或者后台每自造一个新目标，就可以再发一批模型请求。自主运行预算给后台学习组件加了一个持久的总量：在固定时间窗口内，它们合计至多发起多少次模型请求。

## 启用

```bash
./target/debug/eve-qqbot --state-dir .eve-qqbot --interest-learning \
  --research-source https://example.org/docs/ \
  --autonomy-budget 200 --autonomy-budget-window-hours 24
```

- `--autonomy-budget 次数` 默认关闭，范围为 1 至 1000000，需要同时开启 `--interest-learning`。
- `--autonomy-budget-window-hours 小时` 默认 24，范围为 1 至 720，需要同时指定 `--autonomy-budget`。
- 窗口按 Unix 时间对齐：开始时刻为当前时间减去它对窗口长度取余的部分（24 小时窗口即 UTC 零点）。
- QQ 中发送 `/budget` 查看本窗口的上限、已用、剩余、按用途的用量、重置时间，以及上一个有用量的窗口。回复不含任何用户正文；未启用时如实说明。
- 也可以直接问 Eve，例如“后台预算还剩多少？”。聊天模型调用只读工具 `show_budget`，按实际快照回答。查看不记账、不写状态；未启用预算时不注册该工具。

## 计入哪些请求

以下后台组件的模型请求按用途记账：

| 用途 | 组件 | 开始一项工作前要求的余额 |
| --- | --- | --- |
| `interest` | 兴趣观察 | 1 |
| `research` | 受控研究：选来源、提取知识 | 2 |
| `practice` | 实践草稿（每次实践至多 3 次草稿，另加 1 次技能选择） | 4 |
| `skill` | 技能提炼与选择 | 1 |
| `forge` | 工具锻造 | 1 |
| `outreach` | 撰写邀请、判断时机、判断回应 | 1 |
| `clarify` | 撰写问题、判断时机（见[请求澄清](./请求澄清.md)） | 1 |
| `summary` | [用户情景语义摘要](./语义情景摘要.md) | 1 |
| `impression` | 人物印象学习、引用来源的画像整理 | 1 |
| `phrase` | 训练原话的说法学习 | 1 |
| `sticker` | 已下载图片的表情包审看 | 1 |

以下请求不计入：
- **回复用户消息**：对话本身。
- **`/plan propose`**：用户为自己的待办明确请求的计划建议。计划确认后，由研究和实践后台执行的步骤仍然计入。
- **反思、偏好提炼与语义索引**：它们仍然受各自原有的限制。

人物印象、画像、说法和表情包后台在取出待学批次前检查余额；预算耗尽时保留待学材料。请求前仍以同一预算账本原子扣减，跨后台并发不会超额。预算存储不可用时停止该后台，不把失败当作新额度。

## 语义

- **先记账再请求**：模型解析器按用途包装（`BudgetedResolver`）。每次请求发出前，先把计数持久化到 `eve.budget/usage.v1`，然后才发出。余额不足时请求不发出，以模型失败返回。
- **准入**：后台在开始一项工作前核对余额，不够时不开始。具体是：不保留观察批次，不开始研究或实践，不撰写邀请或问题、不判断回应，本条消息不判断时机也不附带邀请或问题。所有已保存的记录都不变，证据留在记忆中，窗口重置后继续。准入只是估算：工作开始后，如果实际请求仍超出余额，这次请求就按模型失败记入对应账本，不重试，和其他模型失败一样处理。
- **不退还**：进程在计数后、请求前退出，或者请求失败、超时、被取消，计数都不退还。预算宁可少用，不能多用。
- **技能纠正**：宿主拒绝候选后允许的一次独立纠正也是新的 skill 请求，另计一次；只是在开始前估算一项工作需要的余额，绝不绕过每次请求前的总量核对。详见[技能固化与复用](./技能固化与复用.md#有界纠正)。
- **重启不清零**：重启后读取同一账本，同一窗口内的用量不变。调整上限立即作用于当前窗口；改变窗口长度时，当前窗口进入历史，按新长度重新计数。
- **时钟回拨**：当前时间落在已记录窗口之前时，沿用已记录的窗口继续计数，不会因为回到旧窗口而重新获得额度。
- **历史**：保留最近 14 个有用量的窗口，新的在前；没有用量的窗口不记录。
- **计划步骤会等待**：余额用尽期间，计划步骤请求的研究或实践也不会开始。步骤超过自己的期限后按计划规则失败，见[多步计划](./多步计划.md)。

## 持久化与恢复

账本是 `eve.budget` 插件的 `usage.v1`，内容是：格式版本、当前策略、当前窗口（开始时间、合计、按用途计数），以及历史窗口。

- **严格读取**：读取时拒绝重复键、未知字段、版本不符，也拒绝不一致的记录，例如合计与按用途之和不等、用途标识无效、计数为零、历史顺序错误或历史不早于当前窗口。
- **损坏时拒绝启动**：遇到上述问题时宿主拒绝启动，原字节保留，不清空、不重置。
- **写入失败**：写入可能已经提交，也可能没有。此时预算实例关闭，之后的请求和准入一律失败，相应后台随之停止，宿主停止准入。重新启动后从账本核对实际用量。

## 分层

- **定义层**：`eve-budget-api` 规定窗口策略、用途标识、快照，以及 `AutonomyBudget` 契约（`snapshot`、`reserve`）。
- **实现层**：`eve-budget-plugin` 提供持久账本（`BudgetPlugin`），以及按用途记账的模型解析器 `BudgetedResolver`。
- **组合层**：QQ 宿主负责参数、按用途包装后台模型、各后台的准入核对、`/budget` 命令，以及把预算交给对话工具 `show_budget`（只读取快照）。

预算句柄只交给可信宿主，不发布到通用服务目录，模型和不受信插件拿不到它。账本实现和记账方式都可以替换。

## 尚未覆盖

- 反思、偏好提炼与语义索引仍按各自原有的限制运行，后续可以接入同一契约。
- 预算按请求次数计，不按 token 或费用计。
- 面板入口另行推进。

## 高频用途的分项上限

QQ 群关系整理最多使用一个预算窗口总额度的四分之一（向下取整，至少 1 次），与主动接话、兴趣等用途共用原总上限。分项用尽只拒绝该用途；总上限不变，不自动补充余额。`/budget` 展示分项用量和上限。并发准入在账本同一把锁内核对，总用量与分项用量一起持久化，再发模型请求。

分项策略来自可信宿主配置，现有版本 1 账本继续保留真实历史；上线、重启或调低分项上限不清零已用计数。已超过上限的用途等待原窗口重置。日志 `EVE_BUDGET` 给出用途、总额度/分项额度耗尽原因和重置时间，不记录消息正文；QQ 判断失败日志区分预算拒绝与模型错误。
