# 提醒

用户在私聊里像对人说话一样说“半小时后提醒我喝水”“明早 9 点提醒我交作业”“不用提醒我关火了”，Eve 就会记下、到时提醒，或者取消。这里没有任何命令：聊天模型调用提醒工具，工具成功后才说“记下了”。

## 启用

```bash
./target/debug/eve-qqbot --state-dir .eve-qqbot --reminders --reminder-utc-offset +08:00
```

- `--reminders` 默认关闭，不依赖其他能力。
- `--reminder-utc-offset ±HH:MM` 设置用户所在地的本地时间，默认 `+08:00`，范围 `-12:00` 至 `+14:00`。它是固定偏移，不处理夏令时。只给它而不开启 `--reminders` 时，宿主拒绝启动。

## 对话里怎么成立

**只在私聊里成立。** 会话是私聊还是群聊，由 QQ 通道在提交每一轮前登记（`QqConversations`），不从用户的文字或模型的输出推断。

私聊时，本轮请求里多一条 `eve.reminders` 上下文记忆，内容是：

- 当前本地时间（精确到分钟）与时区；
- 这位用户还在等待的提醒，最多 10 条，按到期时间排列，每条有 ID、内容和本地到期时间。

数据前注明这是数据，不是指令，并要求没调用成功就不能说已经记下或取消。本地时间每分钟变化，上下文修订也随之变化。

模型可调用两个工具：

| 工具 | 参数 | 作用 |
| --- | --- | --- |
| `set_reminder` | `text`，加上 `in_minutes`（多少分钟后）或 `at`（本地时间 `YYYY-MM-DD HH:MM`）二选一 | 记下一条提醒，返回 ID 与本地到期时间 |
| `cancel_reminder` | `reminder_id`（取自上下文） | 取消这位用户自己一条还没到时间的提醒 |

规则：

- **时间范围**：须在一分钟之后、九十天之内。
- **内容**：非空，500 字节以内。
- **数量**：同一用户同时至多 20 条等待中的提醒。
- **群聊**：工具返回“只能在私聊里设置”，群聊不交给模型提醒数据。
- **其他用户**：别人的提醒在上下文里看不到；按 ID 取消也如同不存在。
- **失败时**：工具返回原因，由模型如实告诉用户。

## 到时怎么提醒

提醒是用户自己要的，不经时机判断，也不计入自主运行预算。

1. **主动私聊一次**：到期后，通道空闲时每 2 秒询问一次，发出“提醒你：……”。私聊路由只取自已确认的私聊回执。每条提醒至多主动私聊一次；没有路由时，这一次记为未发送。到期时用户恰好在私聊，提醒也可能先随那次回复附带。
2. **随下一条回复附带**：主动私聊被平台拒绝或没能发出时，提醒回到等待状态。用户下一条私聊的回复会以第二段附带“对了，你让我提醒你：……”，以平台回执为准。同一条消息只附带一次；没送达的话，下一条再试。
3. **过期**：到期 7 天仍未送达，或投递尝试满 6 次，记为过期，不再投递。

## 持久化与恢复

账本是 `eve.reminder` 插件的 `reminders.v1`，记录每条提醒及其每次投递尝试（渠道、开始与结束时间、结果）。

- **先保存再执行**：创建先保存，工具才返回成功，模型随后回复。投递前先保存“发送中”，再写出消息，拿到平台结果后记录结局。
- **幂等**：提醒 ID 由主人和这次工具调用的 ID 派生。同一次调用重复执行时，返回原记录，不另建。
- **重启**：发送中的提醒记为结果未知。不重发，不随回复附带，也不当作已送达。
- **严格读取**：读取时拒绝以下情况：
  - 重复键、未知字段、版本不符；
  - ID 与主人和来源不一致；
  - 时间不在范围内；
  - 主动私聊超过一次，或同一条消息附带两次；
  - 状态与尝试记录不一致，例如已送达却没有成功回执。
- **损坏时拒绝启动**：遇到上述问题时宿主拒绝启动，原字节保留，不清空。
- **写入失败**：提交可能已经完成，也可能没有。此时实例关闭：工具返回失败，私聊轮次因读不到提醒记录而报错（不回退到没有提醒的上下文），投递停止；重新启动后按账本核对。
- **容量**：至多保存 512 条。满了时删除最早结束的一条（已送达、已取消或已过期），等待中、发送中与结果未知的记录从不删除；没有可删的就不再新增。
- **会话登记**：只在内存中，至多 4096 个会话。重启后会话的下一条消息提交时重新登记，登记之前那个会话不能设置提醒。

## 分层

- **定义层**：`eve-reminder-api` 规定提醒、投递渠道与结果、状态及 `ReminderAdmin` 契约。
- **实现层**：`eve-reminder-plugin` 提供持久账本。
- **组合层**：
  - QQ 宿主提供两个对话工具、`eve.reminders` 上下文与通道投递适配；
  - 投递适配与主动交流、请求澄清共用通道投递点，按 ID 前缀 `remind-` 分流结果，提醒最先投递；
  - QQ 通道提供只读的会话类型登记。

账本可以替换；会话类型登记来自通道的公开接口。

## 尚未覆盖

- 重复提醒（每天、每周）与“推迟十分钟”。
- 每位用户各自的时区；目前整个宿主共用一个固定偏移。
- 终端与其他通道。
- 真实模型对时间说法的理解，需要正式 QQ 环境的体验验收。
