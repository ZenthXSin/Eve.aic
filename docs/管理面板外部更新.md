# 从 Git 独立更新管理面板

管理面板完整源码随 Eve 仓库提交，入口为 `services/admin/main.ts`；页面、实时投影、服务端与协议分别在
`services/admin/view.ts`、`live.ts`、`server.ts`、`contracts.ts`，测试为 `tests/admin*_test.ts`。
没有另放在服务器私有目录、需要手工复制回仓库的前端源码。页面由 TypeScript 直接提供，更新不需要
Node、npm 或前端构建产物。Deno 版本及基础运行说明见 [运行部署](./运行部署.md)。

面板与 Eve 实例是独立进程。只更新面板时不需要修改 Eve 实例的源码、运行配置、模型、QQ 通道或监督状态。
面板新增的想法显示能力需要 Eve 使用支持 `thought` / `write_thought` 的版本才会产生新记录；旧记录仍可读。

## 更新现有宿主

以下示例适用于已经安装 `eve-rebuild-admin.service` 的宿主。先查看该服务的 `ExecStart`、`User`、
`WorkingDirectory` 与私有配置参数，沿用本机原值，不用文档中的示例路径覆盖现有配置。
将 `PANEL_COMMIT` 替换为已经审核、推送的完整提交号；不要使用会漂移的分支路径作为运行源码。

```bash
# 在 Eve 仓库执行；提交必须能从 origin 获取。
git fetch origin
PANEL_COMMIT='<完整提交号>'
git cat-file -e "${PANEL_COMMIT}^{commit}"
PANEL_RELEASE="/opt/eve-rebuild/admin-releases/${PANEL_COMMIT}/source"
sudo install -d -m 0755 "${PANEL_RELEASE}"
git archive "${PANEL_COMMIT}" | sudo tar -x -C "${PANEL_RELEASE}"
```

应展开完整提交，不能只复制 `view.ts`。面板引用仓库中的 SDK、契约及随记投影 helper；完整固定提交也便于回退和核验。
发布目录仅存源码，管理员配置、口令、IPC 密钥、连接文件和运行数据继续留在仓库外。
若相同提交的目录已存在，先核验其内容，直接复用；不要在已运行的发布目录上覆盖文件。

检查候选入口，然后备份当前服务定义。使用独立测试缓存，并在检查结束清理本轮缓存。

```bash
# DENO_BIN 使用本机已安装的 Deno 绝对路径。
DENO_BIN='/absolute/path/to/deno'
PANEL_CHECK_CACHE=$(mktemp -d)
DENO_DIR="${PANEL_CHECK_CACHE}" "${DENO_BIN}" check "${PANEL_RELEASE}/services/admin/main.ts"
rm -rf -- "${PANEL_CHECK_CACHE}"
systemctl cat eve-rebuild-admin.service
```

更新该服务的 `ExecStart` 源码入口及 `WorkingDirectory` 指向新发布目录，其余账号、配置参数、权限和
安全设置保持现有值。例如已有安装的入口形态为：

```ini
WorkingDirectory=/opt/eve-rebuild/admin-releases/<完整提交号>/source
ExecStart=/absolute/path/to/deno run --allow-read --allow-write --allow-net=127.0.0.1 services/admin/main.ts /etc/eve-rebuild/admin.json
```

上述是入口示例，不是替换现有 unit 的完整模板。若使用 systemd override，覆盖 `ExecStart` 前须先写一个
空的 `ExecStart=` 清除旧命令；同时核对原服务的 `ReadOnlyPaths`、`ReadWritePaths` 等限制允许读取候选源码。
只重启管理面板：

```bash
sudo systemctl daemon-reload
sudo systemctl restart eve-rebuild-admin.service
systemctl is-active eve-rebuild-admin.service
```

通过原 HTTPS 域名重新登录，检查总览、“此刻”、最近记录和原件读取；确认数据来自当前实例，暂停画面跟随
只影响浏览器。重启会清空内存登录会话，重新登录属正常行为。检查服务日志时不要把私有配置或密钥复制进问题报告。
无需触发暂停、恢复或发送 QQ 来验收一次页面更新。

如失败，将入口与工作目录恢复为上一个固定提交，再只重启该面板服务。保留当前和上一份必要的发布源码；
清理本轮测试缓存及可验证重复的展开副本，确认没有进程引用后再删除，并检查磁盘剩余空间。
配置结构、域名代理与会话保护见 [管理面板](./管理面板.md)。
