# 从 Git 独立更新管理面板

管理面板完整源码随 Eve 仓库提交，入口为 `services/admin/main.ts`；页面、实时投影、服务端与协议分别在
`services/admin/view.ts`、`workspace-view.ts`（手机工作台视图）、`live.ts`（意识流投影）、
`workspace.ts`（应用与真实操作投影）、`server.ts`、`contracts.ts`；脚本原件的只读观察器为
`sdk/script-observer.ts`，测试为 `tests/admin*_test.ts` 与 `tests/qq_admin_readonly_test.ts`。
没有另放在服务器私有目录、需要手工复制回仓库的前端源码。页面由 TypeScript 直接提供，更新不需要
Node、npm 或前端构建产物。Deno 版本及基础运行说明见 [运行部署](./运行部署.md)。

面板与 Eve 实例是独立进程。已完成下述首次兼容升级后，后续只更新页面、样式或前端交互时可独立更新面板，
不需要修改 Eve 实例的源码、模型或监督状态。首次启用手机工作台的数据接口不属于纯前端更新。
面板新增的想法显示能力需要 Eve 使用支持 `thought` / `write_thought` 的版本才会产生新记录；旧记录仍可读。

## 首次启用手机工作台

首次发布应使用同一个已验证固定提交更新以下基础服务，然后更新面板；不要只重启面板就期待旧后端提供新数据。

- `supervisor/main.ts`：新增仅管理员可用的 `workspace`、`qqConversations`、`qqHistory` 查询。操作账本路径只从当前
  实例的可信私有配置读取，浏览器不能传入路径；更换实例后观察器跟随当前实例。
- `adapters/qq/admin.ts`、`service.ts`、`main.ts`：专用管理密钥开放只读会话列表与历史，复用同一个 `QqPhone` 的规范化原件。
  不开放 `phone.open`，不移动 Eve 阅读水位，不开放前端发送或工具执行。
- `services/runtime/admin.ts`：源码明确拒绝上述外部资源，防止它们误落入本地记忆查询。已运行版本若原有资源白名单
  已拒绝这些查询，且新监督器已先行截获，则不必仅为该 guard 重启执行实例；发布前核验实际版本的行为。
- `sdk/script-observer.ts`：直接只读核验脚本账本近期提交、摘要链和内容寻址原件，不初始化第二个写入者；
  每次最多观察 128 条提交、12 个变动任务及 64 个动作。脚本窗口超过 750,000 个 UTF-8 字节时压缩参数/结果预览，
  保留全部动作标识、状态与来源并标记部分数据，避免超出监督 IPC 的 1 MiB 限制。未包含的历史或不可读原件显示为缺失/部分数据。
  QQ 只读分页维持原有 128 KiB 编码字节上限，异常超大原件明确返回不可用，不截断标识或跳过消息。

沿用宿主已有的固定发布、暂停排空、健康检查和回退流程更新基础服务；保留现有私有配置和独立身份/密钥。
执行服务恢复大量历史可能需要较久，应完成本机既定恢复等待与就绪检查后，再恢复实例；不要把短暂连接就绪当作恢复完成。
监督与 QQ 适配器不会因为只更新页面自动换版。若只部署面板且后端较旧，意识流可继续显示，工作台应用会明确显示数据不可用。

中间应用高亮依据真实脚本动作的命名空间及时间；不会从脚本源码推断文件、终端或网页行为。QQ 跟随屏显示 Eve 实际查看
操作保存的消息回执；管理员手动读取会话另行标注，不代表 Eve 看过。出站气泡保留发送回执状态，送达未知不显示成已送达。
工具目录覆盖 52 个脚本方法及 5 个原生方法；其中 3 个原生方法仅适用于升级观察上下文，并明确标注。
所有真实命名空间均保留，包括未来新增的工具；没有专用窗口时使用通用参数/结果预览。原生调用采用运行时规范化后的调用 ID
关联开始与回执，不使用可能复用的供应商 ID；缺少开始原件的回执显示为名称未知，不补造工具名。
原生来源序号与脚本账本来源序号分开标记；长代码、结果、深层对象或被省略的预览均明确标记部分数据。
目前没有独立浏览器工具契约，浏览器窗口在没有结构化原件时显示空状态。右侧“想法”仅呈现 Eve 实际留下的文字/随记，
不生成额外思考，也不把同一随记的成功工具回执再当一条文字重复显示；工具列表仍保留调用状态，并引用原始随记来源。
QQ 长文读取单独显示有起始偏移的文本片段，不替换此前真实查看的消息屏幕。

## HTTPS、WebSocket 与登录会话

私有配置的 `admin.publicOrigin` 应是浏览器实际访问的完整 HTTPS origin，例如 `https://eve.example.com`，不带路径或末尾 `/`。
反向代理保留该 Host 与原始 Origin，仅代理到面板的 loopback 端口。需要允许 WebSocket 升级，例如：

```nginx
# map 放在 http 级；宿主已有同名 map 时直接复用，不要重复定义。
map $http_upgrade $connection_upgrade {
    default upgrade;
    '' close;
}

server {
    listen 443 ssl;
    server_name eve.example.com;
    # 沿用已有 TLS 证书设置。
    location / {
        proxy_pass http://127.0.0.1:21875;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header Origin $http_origin;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_read_timeout 75s;
    }
}
```

页面登录后建立 `wss://eve.example.com/api/live/ws`，使用 HttpOnly、SameSite=Strict、Secure 登录 cookie；浏览器原生
`WebSocket` 会自动携带同源 cookie，不需要把管理员密码、CSRF 值或任何后端密钥写进 URL、query、localStorage 或消息。
服务端要求精确同源 Origin 与有效登录；会话有效期为 8 小时，退出登录或到期会断开连接。重启面板也会清空内存会话，需重新登录。

每 3 秒由服务端共享读取并广播一次快照，多浏览器复用同一读操作和历史水位缓存，断线后页面自动退避重连。
帧为 `{ "type": "snapshot", "value": { ... } }`，包含原有实时字段及 `workspace`；读取异常为 `type: "error"`。大快照在 1.5 MB 后压缩预览，硬帧限制为 2 MB；不会为了显示而扩充 IPC 限制。
连接仅推送只读数据，浏览器不能通过 WebSocket 执行工具或控制；已有管理操作继续走登录/CSRF 保护的 HTTP 接口。
单会话最多 4 条实时连接、总计最多 32 条；慢连接超过背压上限会断开，重新连接后取得新快照。

## 更新现有宿主

以下示例适用于已经安装 `eve-rebuild-admin.service` 的宿主。先查看该服务的 `ExecStart`、`User`、
`WorkingDirectory` 与私有配置参数，沿用本机原值，不用文档中的示例路径覆盖现有配置。
将 `PANEL_COMMIT` 替换为已经审核、推送的完整提交号；不要使用会漂移的分支路径作为运行源码。

```bash
# 在 Eve 仓库执行；提交必须能从 origin 获取。
git fetch origin
PANEL_COMMIT='<完整提交号>'
git cat-file -e "${PANEL_COMMIT}^{commit}"
PANEL_RELEASE="/opt/eve-rebuild/admin-releases/${PANEL_COMMIT}/source"
sudo install -d -m 0755 "${PANEL_RELEASE}"
git archive "${PANEL_COMMIT}" | sudo tar -x -C "${PANEL_RELEASE}"
```

应展开完整提交，不能只复制 `view.ts`。面板引用仓库中的 SDK、契约及随记投影 helper；完整固定提交也便于回退和核验。
发布目录仅存源码，管理员配置、口令、IPC 密钥、连接文件和运行数据继续留在仓库外。
若相同提交的目录已存在，先核验其内容，直接复用；不要在已运行的发布目录上覆盖文件。

检查候选入口，然后备份当前服务定义。使用独立测试缓存，并在检查结束清理本轮缓存。

```bash
# DENO_BIN 使用本机已安装的 Deno 绝对路径。
DENO_BIN='/absolute/path/to/deno'
PANEL_CHECK_CACHE=$(mktemp -d)
DENO_DIR="${PANEL_CHECK_CACHE}" "${DENO_BIN}" check "${PANEL_RELEASE}/services/admin/main.ts"
rm -rf -- "${PANEL_CHECK_CACHE}"
systemctl cat eve-rebuild-admin.service
```

更新该服务的 `ExecStart` 源码入口及 `WorkingDirectory` 指向新发布目录，其余账号、配置参数、权限和
安全设置保持现有值。例如已有安装的入口形态为：

```ini
WorkingDirectory=/opt/eve-rebuild/admin-releases/<完整提交号>/source
ExecStart=/absolute/path/to/deno run --allow-read --allow-write --allow-net=127.0.0.1 services/admin/main.ts /etc/eve-rebuild/admin.json
```

上述是入口示例，不是替换现有 unit 的完整模板。若使用 systemd override，覆盖 `ExecStart` 前须先写一个
空的 `ExecStart=` 清除旧命令；同时核对原服务的 `ReadOnlyPaths`、`ReadWritePaths` 等限制允许读取候选源码。
只重启管理面板：

```bash
sudo systemctl daemon-reload
sudo systemctl restart eve-rebuild-admin.service
systemctl is-active eve-rebuild-admin.service
```

通过原 HTTPS 域名重新登录，检查总览、“此刻”、最近记录和原件读取；确认数据来自当前实例，暂停画面跟随
只影响浏览器。重启会清空内存登录会话，重新登录属正常行为。检查服务日志时不要把私有配置或密钥复制进问题报告。
无需触发暂停、恢复或发送 QQ 来验收一次页面更新。

如失败，将入口与工作目录恢复为上一个固定提交，再只重启该面板服务。保留当前和上一份必要的发布源码；
清理本轮测试缓存及可验证重复的展开副本，确认没有进程引用后再删除，并检查磁盘剩余空间。
配置结构、域名代理与会话保护见 [管理面板](./管理面板.md)。
