# 持续集成

工作流定义在 [`.github/workflows/ci.yml`](../.github/workflows/ci.yml)，通过 GitHub Actions 验证 Rust 工程和实际运行示例。

## 触发与权限

- 任何目标分支的 PR 都触发检查，包括以另一个功能分支为基础的依赖 PR。
- `main` 收到推送时重新检查；支持在 Actions 页面手动运行。
- 工作流只申请 `contents: read` 权限，检出代码后不保存凭据；不发布构建、不部署服务、不合并 PR。
- 同一工作流和分支或 PR 有新运行时，取消尚未完成的旧运行。
- 每个任务限时 15 分钟；一个 Stable 平台失败不会提前取消另一个平台的任务。

工作流在 PR 中可供审查，不代表已合并进入默认分支。实际是否触发、是否通过，以对应提交的 Actions 记录为准。此配置也不会自动启用分支保护或“必须通过检查才能合并”的仓库规则。

## 平台与 Rust 版本

| 任务 | 环境 | 检查范围 |
| --- | --- | --- |
| Stable | `windows-latest` | 格式、全目标编译、Clippy、测试、协作示例、跨进程恢复示例 |
| Stable | `ubuntu-latest` | 与 Windows 相同 |
| 最低支持版本 | Ubuntu，Rust `1.89.0` | 使用锁定依赖检查工作区所有目标 |

Stable 通过 `rustup` 安装当前稳定版及 `rustfmt`、`clippy`。最低版本检查与工作区声明的 `rust-version = "1.89"` 对应，用于发现新语法、标准库接口或依赖对最低版本的影响；它不替代 Stable 的完整测试。

仅使用官方 `actions/checkout`，固定为经 GitHub API 核实的 v7.0.1 提交 `3d3c42e5aac5ba805825da76410c181273ba90b1`。该版本使用 Node.js 24，要求 Actions Runner 至少为 2.327.1；当前采用 GitHub 托管的 `latest` 镜像。Rust 工具链直接由 `rustup` 安装，不依赖额外第三方安装或缓存 Action。

## 检查命令

在项目根目录执行：

```powershell
cargo fmt --all -- --check
cargo check --workspace --all-targets --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo run -p eve-runtime --locked
```

`--locked` 要求沿用仓库中的 `Cargo.lock`，不能在检查时隐式修改依赖解析结果。格式检查不改写文件，Clippy 将警告视为失败。

最低版本可在本地另外检查：

```powershell
rustup toolchain install 1.89.0 --profile minimal
cargo +1.89.0 check --workspace --all-targets --locked
```

## 实际运行与持久化验收

协作示例验证插件依赖、事件和服务交互、前后台任务、自定义任务与调度、日志、失败回滚和只读诊断。

恢复示例在每个平台的 `RUNNER_TEMP` 下使用同一临时目录，先后启动两个独立进程。CI 检查退出码，并精确断言首行输出：

```text
恢复前值：无；写入后值：1。
恢复前值：1；写入后值：2。
```

每个进程退出后还读取实际 `state.json`，断言快照版本为 `1`，且 `entries["demo.state-recovery"]["starts"]` 分别严格为字节数组 `[49]`、`[50]`，即 UTF-8 文本 `1`、`2`。缺少文件、JSON 无效、字段类型或内容不符都会使检查失败，不能仅凭终端输出判定恢复成功。

第一个进程退出后，第二个进程必须从磁盘恢复计数。目录包含运行 ID 和重试次数，不与旧运行复用；两个示例进程之间保留该目录，不用删除状态来绕过恢复检查。Windows 与 Ubuntu 使用相同 PowerShell 脚本。

持久化测试还会实际建立跨进程文件锁，验证占用期间拒绝打开、释放后可重新打开，以及写入失败和损坏快照不被静默清空。符号链接测试会创建有效及悬空的 `state.json` 链接，确认拒绝打开且链接与目标保持不变。创建链接失败会使测试失败，不会跳过后声称通过；Windows 运行环境需要具备创建符号链接的能力。

这些检查覆盖当前文件后端的正常进程恢复和文件系统行为，不证明断电、硬件故障或网络文件系统上的持久性。具体提交、锁和恢复语义见 [状态持久化](状态持久化.md)。
