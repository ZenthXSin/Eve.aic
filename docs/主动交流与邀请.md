# 主动交流与邀请

这是[首个自主学习目标](./自主学习首个目标.md)（#134）第五步的第一个切片。学习目标有了实际验证的进展后，Eve 依据账本中的事实写一条邀请，在合适的时候告诉用户自己做成了什么，并请用户说出自己的想法。

本切片只交付“撰写 → 择时 → 投递 → 真实回执”。用户回应后的反馈学习（是否有帮助、时机是否合适、把想法接到技能与计划上）属于下一个切片。

## 启用

```bash
./target/debug/eve-qqbot --state-dir .eve-qqbot --interest-learning \
  --practice-mindustry-server /opt/mindustry/server-release.jar --skill-learning --outreach
```

- `--outreach` 必须同时指定 `--practice-mindustry-server`，默认关闭。撰写与时机判断复用主模型配置。
- `--outreach-cooldown-ms`：同一用户两次送达的最短间隔，默认 24 小时。
- `--outreach-proactive-after-ms`：开启主动私聊。邀请在被动窗口等待超过这个时间仍未送达时，主动私聊一次；不提供时不主动私聊。
- QQ 命令：
  - `/outreach`：查看最近的邀请、投递方式与平台回执。
  - `/outreach off`：请 Eve 不再主动提起；`/outreach on` 恢复。
- 未启用时回复“主动交流未启用。”。

## 撰写：只用账本中的事实

每个学习目标只邀请一次（“不每轮重复问同一件事”）。目标有了已验证的实践后，Eve 整理事实：
- 用户自己说过的话：兴趣的原话，至多 3 条；
- 实际运行验证过的进展：运行环境版本、产物文件、探测项与实际值；
- 由这次实践固化并启用的技能（若有）。开启技能固化时，先等这次实践的提炼结束，至多等 15 分钟。

撰写器发出一次无工具请求，规则与领域无关：只能使用给出的事实，不夸大、不编造，用一个开放的问题邀请用户。撰写前先保存邀请，撰写结果再写入账本。

## 择时与投递

邀请撰写完成后等待投递，取用顺序以等待最久的为先。下列任一情况都不投递：
- 用户要求安静；
- 同一用户有邀请正在判断或发送；
- 距上次送达未过冷却期。

投递只有两条路：

1. **随被动回复附带（默认）**：用户下一次在私聊里找 Eve、Eve 写好普通回复后，时机判断器看用户这条消息与这条回复，判断此刻是否合适：
   - 用户在说不再感兴趣、正忙、情绪低落、要求安静，或在谈严肃的事时，判断为“此刻不合适”，回复照常发出，邀请继续等待；
   - 判断为“邀请”时，邀请作为最后一段，随同一条消息的被动回复发出，原回复不变；
   - 判断器每次一个无工具请求，先保存再请求。每条消息只判断一次，每条邀请至多判断 12 次。通道最多等 30 秒，期间不投递其他回复，超时或失败都当作此刻不合适；
   - 以下情况不附带：群聊、命令确认和控制消息；回复本身已超过 3 段时（平台较新的单聊被动回复上限是每条消息 4 次）也不附带。
2. **主动私聊（操作者开启）**：通道空闲时每 2 秒询问一次。邀请等待超过设定时间仍未送达时，主动私聊一次：
   - 不带消息 ID，平台的配额与用户的“允许主动发送”开关照常生效；
   - 发送目标只取自通道已确认的私聊回执，宿主拿不到也不能指定 openid；
   - 每条邀请至多主动尝试一次；被平台拒绝时记下 HTTP 状态与错误码，邀请继续等待被动窗口。

每次投递都先保存尝试，再交给通道。结果以平台回执为准：
- 送达：记录平台消息 ID；
- 平台拒绝：记录错误码，邀请回到等待；
- 没有写出（前面的回复片段失败、回复已过期、没有可用路由）：邀请回到等待；
- 每条邀请至多尝试 6 次，用尽即停止。

送达后 7 天内，这条邀请会作为数据（不是指令）交给同一用户后续的对话，Eve 因此知道用户接下来的话可能是在回应它，也不会重复邀请。

## 持久化与恢复

邀请账本 `eve.outreach/outreach.v1` 经公开 StateStore 保存，文件与 PostgreSQL 后端语义相同。账本包含：
- 邀请：事实、正文、时机判断、投递尝试与回执；
- 用户的安静偏好。

| 情况 | 行为 |
| --- | --- |
| 保存准入、撰写结果、判断或投递尝试失败 | 不发请求、不发送；关闭账本句柄，下次打开读到实际提交结果 |
| 重启发现撰写中的邀请 | 记为 `Interrupted`，不重放 |
| 重启发现进行中的时机判断 | 该消息记为中断，不重放；邀请继续等待下一条消息 |
| 重启发现发送中的邀请 | 记为 `Unknown`：可能已经送达，不重发，也不当作已送达 |
| 停止时邀请段尚未写出 | 记为没有写出，邀请回到等待 |
| 学习目标被取消或结束（例如用户撤回兴趣） | 取消尚未送达的邀请；正在发送的不能取消 |
| 撰写失败或输出不合规 | 记为 `Failed`，不重试 |
| 邀请 128 条已满 | 停止新的邀请，不淘汰旧记录 |
| 账本损坏、重复键、版本未知，或已送达却没有成功回执、被动附带没有对应的“邀请”判断、同一用户同时发送多条等不一致 | 拒绝启动，保留原字节，不清空 |

## 分层

| 层 | 内容 |
| --- | --- |
| `eve-outreach-api` | 事实、里程碑、邀请、时机判断、投递尝试与回执、安静偏好；按宿主策略取出可投递邀请的纯函数；可替换的 `OutreachAdmin`、`InvitationComposer`、`TimingJudge` |
| `eve-outreach-plugin` | 持久账本与启动核对；`ModelInvitationComposer`、`ModelTimingJudge`（各一次无工具请求、严格 JSON） |
| `eve-qqbot-plugin` | 通道契约 `QqOutreach`：私聊回复投递前的时机判断与附带、空闲时的主动私聊，以及真实回执；桥接协议新增 `push` 命令与 `delivery {push:true}` 回执 |
| `eve-app` | 进展识别与撰写的后台、两个投递点的策略适配、把送达的邀请交给后续对话的上下文装配、`/outreach` 与参数校验；`InterestComponents` 可替换撰写器与判断器 |

## 验收边界

- **确定性替身**：
  - Rust 测试覆盖：投递策略；账本的阶段持久化、判断与附带的对应、主动只尝试一次、尝试上限；重启中断与未知；取消、安静偏好与提交失败；损坏与不一致账本的拒绝；邀请段的拼接规则。
  - Node 测试覆盖：主动私聊不带消息 ID，只发往给定私聊目标，失败回执不泄漏正文。
  - 真实 `eve-qqbot` 进程测试 `connectors/qqbot/test/outreach_test.py` 使用模型、桥接与服务端替身，覆盖：
    - 一次普通聊天到下一条私聊回复附带邀请，带平台回执，同一目标不再邀请，后续对话带上已送达的邀请；
    - 说不再感兴趣的那条消息判断为不合适、撤回后取消；
    - 安静后不附带、恢复后附带；
    - 主动私聊送达，以及被拒绝后改由被动窗口送达；
    - 发送中强杀后记为未知且不重发；
    - 默认关闭与参数拒绝。
- **未覆盖**：
  - 撰写与时机判断没有接入真实模型，表达与判断质量未经评估；
  - 主动私聊没有在正式 QQ 上验收，平台配额、用户开关与互动召回能力只能在正式环境确认；
  - 用户回应后的反馈学习尚未实现。
