# 主动交流与邀请

这是[首个自主学习目标](./自主学习首个目标.md)（#134）第五步。学习目标有了实际验证的进展后，Eve 依据账本中的事实写一条邀请，在合适的时候告诉用户自己做成了什么，并请用户说出自己的想法；送达后识别用户怎样回应，据此调整之后的时机；用户提出具体想法时，按这个想法继续创作，做成后再告诉用户。

已交付“撰写 → 择时 → 投递 → 真实回执 → 回应识别与时机反馈 → 按用户的想法继续创作”。

## 启用

```bash
./target/debug/eve-qqbot --state-dir .eve-qqbot --interest-learning \
  --practice-mindustry-server /opt/mindustry/server-release.jar --skill-learning --outreach
```

- `--outreach` 必须同时指定实践运行环境（`--practice-mindustry-server` 或 `--practice-browser`），默认关闭。撰写、时机判断与回应识别复用主模型配置。
- `--outreach-cooldown-ms`：同一用户两次送达的最短间隔，默认 24 小时；用户连续表示不方便或不需要时加倍。
- `--outreach-proactive-after-ms`：开启主动私聊。邀请在被动窗口等待超过这个时间仍未送达时，主动私聊一次；不提供时不主动私聊。
- QQ 命令：
  - `/outreach`：查看最近的邀请、投递方式、平台回执与识别出的回应；提出想法后显示按想法继续创作的进展（正在做、已验证、未验证、做不了或中断）。
  - `/outreach off`：请 Eve 不再主动提起；`/outreach on` 恢复。
- 未启用时回复“主动交流未启用。”。

## 撰写：只用账本中的事实

每个学习目标只邀请一次（“不每轮重复问同一件事”）。目标有了已验证的实践后，Eve 整理事实：
- 用户自己说过的话：兴趣的原话，至多 3 条；
- 实际运行验证过的进展：运行环境版本、产物文件、探测项与实际值；
- 由这次实践固化并启用的技能（若有）。开启技能固化时，先等这次实践的提炼结束，至多等 15 分钟。

撰写器发出一次无工具请求，规则与领域无关：只能使用给出的事实，不夸大、不编造，用一个开放的问题邀请用户。撰写前先保存邀请，撰写结果再写入账本。

## 择时与投递

邀请撰写完成后等待投递，取用顺序以等待最久的为先。下列任一情况都不投递：
- 用户要求安静；
- 同一用户有邀请正在判断或发送；
- 距上次送达未过冷却期。

投递只有两条路：

1. **随被动回复附带（默认）**：用户下一次在私聊里找 Eve、Eve 写好普通回复后，时机判断器看用户这条消息与这条回复，判断此刻是否合适：
   - 用户在说不再感兴趣、正忙、情绪低落、要求安静，或在谈严肃的事时，判断为“此刻不合适”，回复照常发出，邀请继续等待；
   - 判断为“邀请”时，邀请作为最后一段，随同一条消息的被动回复发出，原回复不变；
   - 判断器每次一个无工具请求，先保存再请求。每条消息只判断一次，每条邀请至多判断 12 次。通道最多等 30 秒，期间不投递其他回复，超时或失败都当作此刻不合适；
   - 以下情况不附带：群聊、命令确认和控制消息；回复本身已超过 3 段时（平台较新的单聊被动回复上限是每条消息 4 次）也不附带。
2. **主动私聊（操作者开启）**：通道空闲时每 2 秒询问一次。邀请等待超过设定时间仍未送达时，主动私聊一次：
   - 不带消息 ID，平台的配额与用户的“允许主动发送”开关照常生效；
   - 发送目标只取自通道已确认的私聊回执，宿主拿不到也不能指定 openid；
   - 每条邀请至多主动尝试一次；被平台拒绝时记下 HTTP 状态与错误码，邀请继续等待被动窗口。

每次投递都先保存尝试，再交给通道。结果以平台回执为准：
- 送达：记录平台消息 ID；
- 平台拒绝：记录错误码，邀请回到等待；
- 没有写出（前面的回复片段失败、回复已过期、没有可用路由）：邀请回到等待；
- 每条邀请至多尝试 6 次，用尽即停止。

送达后 7 天内，这条邀请会作为数据（不是指令）交给同一用户后续的对话，Eve 因此知道用户接下来的话可能是在回应它，也不会重复邀请。

## 回应识别与时机反馈

邀请送达后 3 天内，后台从交互记忆读取同一用户之后的私聊（附带邀请的那条消息本身除外），每次至多 3 轮，交给回应识别器：
- 识别器一次无工具请求，规则与领域无关，结论为：提出了具体想法、有兴趣、不需要、此刻不方便，或没有回应；
- 除“没有回应”外，必须逐字引用用户某一轮的原话，宿主核对引用确实出自那一轮的用户消息（不能取自邀请或 Eve 的回复），否则记为不合规输出；
- 识别前先保存确切输入（交互证据 ID、消息 ID 与时间）；每轮对话只识别一次。“没有回应”时等后续对话再识别，每条邀请至多 3 次；得出回应后不再识别。

反馈只按账本中的结论确定性地改变策略，不调用模型：
- 用户最近连续表示“不需要”或“此刻不方便”时，同一用户的冷却期每次加倍，至多 8 倍；
- 同时不再主动私聊，只在用户自己找 Eve 时再判断时机；
- 用户再次表示有兴趣或提出想法后恢复原策略；没有回应的邀请不影响计数；
- 用户对最近 3 条邀请的回应与原话作为数据交给之后的时机判断，用户说过不方便的情形再次出现时判断为此刻不合适。

## 按用户的想法继续创作

用户在回应中提出具体想法（例如“那就加一个会发光的墙吧”）时，派生器把这条原话确定性地变成一个后续创作目标，不调用模型：
- 每条邀请至多派生一个目标，重启或重复同步不另建；
- 目标来源记为推断（“提出想法”是模型识别的类别，不是用户下达的指令），描述中逐字引用用户原话、之前的邀请与上一目标的背景，等待原因中保存最初学习目标的标记；
- 优先级 40，高于兴趣派生的学习目标（30），低于用户待办（50）。

后续创作沿用已有的流程：
- [实践验证](./实践验证.md)按这个目标做出产物并实际运行验证，沿用最初学习目标研究得到的知识，不另行研究；
- 开启技能固化时，草稿器可以选用已验证的[技能](./技能固化与复用.md)，调用结果同样以实际运行为准；
- 验证通过后撰写一条新邀请，引用用户提出想法时的原话，经同样的时机与投递规则告诉用户；
- 用户对这条邀请再提出想法时继续派生，仍沿用最初的学习目标。

最初的学习目标关闭（例如用户撤回兴趣）时，仍在等待的后续创作目标一并取消，尚未送达的邀请随之取消；已有结论不改写。

## 持久化与恢复

邀请账本 `eve.outreach/outreach.v1` 经公开 StateStore 保存，文件与 PostgreSQL 后端语义相同。账本包含：
- 邀请：事实、正文、时机判断、投递尝试与回执、回应识别的输入与结论（引用用户原话）；
- 用户的安静偏好。

| 情况 | 行为 |
| --- | --- |
| 保存准入、撰写结果、判断或投递尝试失败 | 不发请求、不发送；关闭账本句柄，下次打开读到实际提交结果 |
| 重启发现撰写中的邀请 | 记为 `Interrupted`，不重放 |
| 重启发现进行中的时机判断 | 该消息记为中断，不重放；邀请继续等待下一条消息 |
| 重启发现发送中的邀请 | 记为 `Unknown`：可能已经送达，不重发，也不当作已送达 |
| 重启发现进行中的回应识别 | 这批对话记为中断，不重放；之后的新对话仍可识别 |
| 识别失败、超时或引用不出自用户原话 | 记为失败，这批对话不再识别 |
| 派生后续创作目标时认知状态修订冲突或容量已满 | 暂缓，下一轮重新核对；不重复创建 |
| 同名目标来源不符，或等待中的后续创作目标缺少标记 | 后台报错停止，不改写该目标 |
| 停止时邀请段尚未写出 | 记为没有写出，邀请回到等待 |
| 学习目标被取消或结束（例如用户撤回兴趣） | 取消尚未送达的邀请；正在发送的不能取消 |
| 撰写失败或输出不合规 | 记为 `Failed`，不重试 |
| 邀请 128 条已满 | 停止新的邀请，不淘汰旧记录 |
| 账本损坏、重复键、版本未知，或已送达却没有成功回执、被动附带没有对应的“邀请”判断、同一用户同时发送多条、回应识别早于送达或指向附带邀请的消息、结论不指向所识别的对话、得出回应后又识别等不一致 | 拒绝启动，保留原字节，不清空 |

## 分层

| 层 | 内容 |
| --- | --- |
| `eve-outreach-api` | 事实、里程碑、邀请、时机判断、投递尝试与回执、安静偏好、回应识别、后续创作目标的来源与标记；按宿主策略与反馈取出可投递邀请的纯函数与引用核对；可替换的 `OutreachAdmin`、`InvitationComposer`、`TimingJudge`、`ResponseJudge`、`RequestGoalDeriver` |
| `eve-outreach-plugin` | 持久账本与启动核对；`ModelInvitationComposer`、`ModelTimingJudge`、`ModelResponseJudge`（各一次无工具请求、严格 JSON）；`RequestGoals` 派生器（经公开认知契约提交，零模型请求） |
| `eve-qqbot-plugin` | 通道契约 `QqOutreach`：私聊回复投递前的时机判断与附带、空闲时的主动私聊，以及真实回执；桥接协议新增 `push` 命令与 `delivery {push:true}` 回执 |
| `eve-app` | 进展识别、撰写、回应识别与后续目标同步的后台、两个投递点的策略适配、把送达的邀请交给后续对话的上下文装配、`/outreach` 与参数校验；实践后台同时实践后续创作目标；`InterestComponents` 可替换撰写器、判断器与识别器 |

## 验收边界

- **确定性替身**：
  - Rust 测试覆盖：后续创作目标的派生、连续派生沿用学习目标、关闭后取消、重复同步零写入与来源冲突；投递策略与反馈后的冷却加倍、主动私聊暂停与恢复；账本的阶段持久化、判断与附带的对应、主动只尝试一次、尝试上限；回应识别的输入约束、引用核对、一次结论与中断；重启中断与未知；取消、安静偏好与提交失败；损坏与不一致账本的拒绝；邀请段的拼接规则。
  - Node 测试覆盖：主动私聊不带消息 ID，只发往给定私聊目标，失败回执不泄漏正文。
  - 真实 `eve-qqbot` 进程测试 `connectors/qqbot/test/outreach_test.py` 使用模型、桥接与服务端替身，覆盖：
    - 一次普通聊天到下一条私聊回复附带邀请，带平台回执，同一目标不再邀请，后续对话带上已送达的邀请；
    - 说不再感兴趣的那条消息判断为不合适、撤回后取消；
    - 安静后不附带、恢复后附带；
    - 主动私聊送达，以及被拒绝后改由被动窗口送达；
    - 发送中强杀后记为未知且不重发；
    - 送达后用户说“在上班”被识别为此刻不方便并引用原话，重启不重放；
    - 无关闲聊之后继续识别，直到用户提出想法；
    - 负面反馈后加倍的冷却期过去也不再主动私聊，下一条邀请在用户找 Eve 时附带，时机判断收到先前反馈；
    - 用户提出想法后派生后续创作目标，实际运行验证通过，再经邀请引用用户原话告诉用户；开启技能固化时后续创作选用已验证的技能；
    - 撤回兴趣后后续创作目标取消，不再告诉用户；
    - 默认关闭与参数拒绝。
- **未覆盖**：
  - 撰写、时机判断与回应识别没有接入真实模型，表达、判断与识别质量未经评估；
  - 主动私聊没有在正式 QQ 上验收，平台配额、用户开关与互动召回能力只能在正式环境确认；
  - 后续创作的实践仍受运行环境的能力限制（目前只验证数据文件模组），超出时如实记为不适用；
  - `/practice` 只按兴趣查看学习目标的实践，后续创作的实践进度目前经下一条邀请告知。
