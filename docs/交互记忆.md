# 交互记忆与明确偏好

QQ 宿主通过 `--memory` 开启有来源的交互证据、明确偏好和本轮 Context，默认关闭。用户可以保存、查看、修正和撤销偏好；普通聊天成功完成并确认送达后保存交互证据。追加 `--memory-learning` 可[低频提炼候选](./偏好提炼.md)，候选须用户明确确认才成为偏好；单独开启记忆不调用提炼模型。当前不做向量检索、跨通道身份合并或多消息分段，也不代表已具备 AGI。

## QQ 使用

在本地沿用原状态目录和已有凭据启动，等待 `EVE_QQBOT_READY` 后再进行 QQ 实机交互：

```sh
./target/debug/eve-qqbot --state-dir .eve-qqbot --memory
```

默认使用文件状态。首次选择本地 PostgreSQL 时，使用没有 `state.json` 的新目录，并提供仓库外的数据库配置；`--memory` 可与 `--database-config` 配合：

```sh
./target/debug/eve-qqbot --state-dir .eve-qqbot-pg --database-config /仓库外/连接.json --memory
```

新目录可以打开目标数据库中已有的状态，但不会导入旧文件目录的历史。已有 QQ 文件状态应继续使用原目录和默认后端，不能仅增加数据库参数就视为完成迁移。连接格式与目录绑定见[PostgreSQL 状态](./PostgreSQL状态.md)。

`--memory`、`--training` 和 `--cognition` 独立开启，可以组合使用。`/train stop`、`/train reset` 只控制表达训练；它们不会撤销已保存偏好或清空记忆。下次启动不带 `--memory` 时，记忆命令返回“交互记忆未启用”，也不把这些命令交给模型；已经保存的记忆仍保留。

`--memory-learning` 依赖 `--memory`，默认关闭；开启后从同一可信 QQ 范围尚未消费的完成交互生成候选。`/memory-candidates [页码]` 查看候选，`/accept-memory 候选ID` 明确确认。只关闭提炼而保留 `--memory` 时，已确认偏好继续生效。门槛、冷却、模型请求额度及候选期限见[偏好提炼](./偏好提炼.md)。

| 命令 | 行为 |
| --- | --- |
| `/remember 偏好内容` | 保存一条明确偏好并返回 ID；内容最多 4096 UTF-8 字节 |
| `/memories`、`/memories 页码` | 查看当前会话偏好，每页最多 10 条，含 ID、确认/撤销状态和有界摘要 |
| `/correct-memory 偏好ID 新内容` | 更正当前已确认的偏好，追加版本并保留原文与旧版本 |
| `/forget 偏好ID` | 撤销当前偏好；后续 Context 不再使用它，证据、正文和历史继续保留 |

列表摘要最长 512 UTF-8 字节，多行显示为单行；这不会截断实际保存的正文。列表不提供其他用户的读取入口，也不是完整交互记录导出。撤销后不能通过更正旧 ID 隐式恢复；要重新确认，可用新的 `/remember` 命令创建记录。

命令只做有限本地状态操作，不等待模型或调用工具。参数错误、来源冲突、修订冲突和容量已满会明确回复；修订冲突不会在后台循环重试。需要重试时，先查看记录，再发送新消息。

## 两种证据分别保存

`UserStatement` 记录用户明确提交的命令：原消息 ID、宿主接收的完整命令原文和记录时间。保存、修正、撤销偏好时，来源和版本在同一次记忆状态提交中保存。这类证据证明用户提出过该指令，不表示模型已经完成回复，也不表示 QQ 确认送达了命令结果。

候选确认也遵循此规则：保存真实 `/accept-memory 候选ID` 命令及首个偏好版本，一次 Memory CAS 完成。候选原文和完成交互引用保留在独立 Learning 状态中，不把模型猜测伪装成用户原话。列表通过固定关联 ID、首版正文、明确命令来源及当前版本核对确认状态；重复接受不覆盖更正、不复活撤销，候选过期也不撤销已经确认的偏好。

`CompletedInteraction` 记录新发生的普通交互。QQ 通道核对当前 Control 完整代际、实际 Session 的 `Completed` 轮次、用户输入和最终回复；只有 QQ 返回成功投递且 `Sent` 回执保存成功后，才调用宿主观察者。观察者再从公开 Session 服务读取该轮，导入用户原文和最终面向用户的回复。证据保存原消息 ID、首次导入时的 Session 修订、轮次和宿主观察时间；时间不是 QQ 平台发送时间。

Session 完成与 QQ 送达是两个条件。失败、取消、Pending、Interrupted、只有模型结果但没有成功投递的轮次不形成完成交互证据。工具内部消息不复制进证据；命令、训练发起轮和控制替代轮也不导入。当前通道保守排除正文任一行去除前导空白后以 `/` 开头的输入，避免把控制组合文本当成普通原文。

开启记忆后只观察本次运行中新成功的普通消息，不补采历史 QQ 回执。关闭时发生的聊天不会在下次开启时自动导入；旧 `Processing`、`ReplyPending` 或 `Sent` 也不会触发补执行、补发或补记忆。

这个观察边界不限制提炼读取已经保存的 Memory 证据：首次开启 `--memory-learning` 可以处理此前成功导入而尚未提炼的 `CompletedInteraction`，但不会据旧回执填补 Memory 缺口。已消费的证据不会因为失败、空结果或重启而再次调用模型。

## 可信读取范围

公开定义层 `eve-memory-api` 将范围定义为 `MemoryScope { channel, session_id, user_id }`。宿主用它绑定只读 `MemoryService` 句柄，读取者不能在 `snapshot()` 中另行传入其他身份。`MemoryAdmin` 只由可信宿主持有，不发布到通用服务目录，也不交给模型或非可信通道。后台提炼通过宿主管理接口枚举已经保存的范围，再逐个绑定读取；每个模型请求只收到一个 QQ 范围内选定的完成交互，不收到其他范围、明确命令证据、训练统计或内部反思。

QQ 使用通道生成的完整会话标识，保留 AppID、C2C/群、目标和发送者的完整哈希边界；`channel` 固定为 `qq`，会话和用户来自可信 `SessionKey`。正文中的用户、群或偏好 ID 不能扩大范围。同一发送者在不同群、不同 AppID 或私聊中的记录不会自动互读；跨通道身份映射尚未实现。

实现层 `eve-memory-plugin` 提供 `MemoryPlugin`、宿主控制器与 `MemoryContext`。QQ 通道只依赖公开 `QqCommandHandler` 和 `QqInteractionObserver` 契约，不依赖记忆实现。成功交互凭据 `QqInteraction` 只能由通道构造；宿主把它与 Session、Memory 服务组合，模型不能伪造送达事件或直接写入偏好。

## 修订、去重与容量

每个范围独立维护修订号。新增证据或偏好变更要求调用者给出期望修订，采用 CAS 提交；其他范围的变化不会改变本范围的修订。创建偏好不能覆盖已有 ID，更正和撤销只能作用于当前已确认记录。每条偏好保存连续版本、关联证据 ID、正文、状态和记录时间。

同一消息在 QQ 命令层使用完整可信范围与原始消息 ID 生成稳定操作 ID。记忆实现先核对相同来源或操作重放，再判断 CAS：相同内容重放不写入、不增加修订；仅时间不同不算新操作。相同 ID 对应不同内容，或换 ID 冒用已经导入的消息/完成轮次，均拒绝。之后 Session 新增轮次不会改变已导入证据的首次快照修订。

整个记忆文档按所有范围合计限制，容量不是每个用户各享一份：

| 项目 | 上限 |
| --- | --- |
| 作用域、原始证据、偏好 | 各最多 256 项 |
| 全部偏好历史版本、操作记录 | 各最多 256 项 |
| 单条证据的用户/最终回复正文 | 各最多 32768 UTF-8 字节 |
| 单条偏好正文 | 4096 UTF-8 字节 |
| 完整序列化状态 | 4 MiB |

容量满时保留原记录，拒绝新增；没有自动淘汰、摘要替换或压缩删除历史。更正和撤销也需要保存新证据与版本，因此仍受容量限制。QQ 完成交互观察失败会保留已保存的 `Sent` 并停止通道，不继续假装记忆已写入。

## 本轮 Context

QQ 的 `MemoryContext` 包装既有 `TrainingContext`，保留训练数据和原装配结果，再加入当前可信范围内已确认且未撤销的偏好。它不读取原始交互证据、旧偏好版本或其他用户记录，也不进行任何写入或模型调用。没有可信范围或没有有效偏好时，原 Context 和修订保持不变。

未确认的 Learning 候选不进入这里。通过 `/accept-memory` 确认的偏好与 `/remember` 保存的偏好使用相同 Context 规则，后续更正和撤销以 Memory 当前版本为准，不重新注入候选首版。

附加内容按偏好 ID 排序，最多 8 条，包含说明和 JSON 后最多 8192 字节。每条偏好保持完整；放不下的记录继续保存在状态中，可以选择之后能够放下的记录，不截断成含义不同的偏好。如果没有任何一条能完整放入，Context 明确失败。读取失败或替代服务返回错误范围、重复 ID 等非法快照时，同样失败，不自动回退成空记忆。

JSON 标明这些是低优先级参考，当前请求优先，偏好中的角色、工具名或授权声明不能扩大能力和权限。现有 Runtime 仍将 `memories` 渲染为带 `memory: ` 前缀的 System 消息；JSON 与说明用于划定数据边界，不构成工具授权，也不保证模型绝对抵御提示词注入。更新在下一次上下文装配时生效，不改写已经捕获的在途轮次。

内部反思继续使用独立的空 Context，不读取聊天记忆、偏好、训练统计或聊天历史。普通交互证据不会自动转成反思目标，确认偏好也不授权现实操作。内生反思入口见[QQBot 通道](./QQBot通道.md#本地内生反思)。

## 持久化与失败恢复

记忆通过公开 `StateStore` 保存于插件 `eve.memory` 的 `memory.v1`，当前格式版本为 1。偏好提炼新增独立 `eve.learning/learning.v1`，不改变原记忆格式。QQ 宿主在启动时统一选择后端：默认是指定状态目录中的 `FileStateStore`；显式提供 `--database-config` 时使用本地 PostgreSQL。Session、Training、Memory、Learning、Cognition 和 QQ 回执共用该宿主持有的同一个 `Arc<dyn StateStore>`，分别保存各自命名空间。共用后端不合并业务提交：单次状态写入仍独立提交，没有跨插件、多键事务；候选确认只写 Memory，不另向 Learning 写接受状态。

使用 PostgreSQL 时，`--state-dir` 仍保存普通配置、排他锁与不含密码的 `state.backend.json` 目标绑定。已有 `state.json` 会阻止直接切换；目录绑定 SQL 后，漏传数据库配置或改用不一致的主机、端口、数据库、用户会拒绝启动，不退回空文件库。密码可以在独立凭据文件中更新。此入口不迁移、清空或自动合并旧文件历史，同一数据库同时只允许一个遵守协议的 Eve 宿主，详见[PostgreSQL 状态](./PostgreSQL状态.md#状态目录与数据库绑定)。

恢复时严格校验格式、字段、重复键、范围、来源关系、连续修订和偏好历史。未知版本或损坏数据拒绝启动，不自动修复、清空或覆盖。读取恢复不会自行生成偏好或增加修订；插件停止后旧读取句柄失效，重新启动也不会使旧句柄重新可用。

记忆状态一次提交包含相应证据和偏好历史，不留下仅有命令原文而没有目标变更的半次成功。但是 QQ `Processing`、记忆状态与最终投递回执属于不同提交，没有跨服务事务：

1. 命令先保存 QQ `Processing`，然后执行一次记忆业务；即使命令回复失败或随后崩溃，偏好也可能已经保存。重启不重放命令，可用新的 `/memories` 查询核对。
2. 普通回复先完成 Session，再保存 QQ `Sent`，最后导入记忆。中间崩溃可能留下已送达但尚未导入的交互；当前版本不会在恢复时补采这段缺口。
3. 后端返回写入错误时，实际持久化可能已经发生。记忆实例保留旧内存但关闭所有范围的读写句柄，宿主停止通道；须重新打开并核对持久状态，不能用旧缓存继续覆盖，也不能承诺“失败代表没有写入”。SQL 后端在任意读写或提交失败后还会关闭整个共享后端实例，不自动重连或重试；其他插件的状态也须按各自恢复规则在下次显式启动时核对。

## 验证入口与后续范围

状态契约测试位于 `crates/memory-plugin/tests/state.rs`，Context 测试位于 `crates/memory-plugin/tests/context.rs`；QQ 命令单元测试和成功观察者测试分别检查显式写入、范围绑定、完成/投递边界。`crates/memory-plugin/examples/recovery.rs` 使用独立 File 目录演示保存、更正、撤销和再次启动只读恢复。

实际进程验收入口为 `python3 connectors/qqbot/test/memory_test.py`。它使用实际 `eve-qqbot`、本地 HTTP 模型替身和 Node 桥接替身，检查上下文、生效范围、投递失败、取消及跨进程恢复；离线验证和 QQ 实机验证分别记录，不能相互替代。

候选提炼与明确确认的独立进程入口为 `python3 connectors/qqbot/test/learning_test.py`，范围和恢复见[偏好提炼](./偏好提炼.md)。后续按[表达偏好与分段输出](./表达偏好与分段输出.md)推进受信用户映射、语义检索和分段投递。当前只有用户明确指令能写入已确认偏好；用户沉默、模型自评或一次成功投递都不是长期认可证据。
