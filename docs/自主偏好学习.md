# 自主偏好学习

`--self-learning` 接通“成功交流 → 提炼候选 → 自动确认 → 后续表达 → 新反馈修正”的闭环，同时开启 QQ 记忆、偏好提炼和分段投递。称呼、语气、长度等偏好进入后续聊天 Context；明确分段和停顿要求直接参与发送，无需逐条执行 `/accept-memory` 或 `/segment adopt`。

## 内容生成学习

内置提炼器 v3 同时关注接话、信息选择、结论与依据顺序、解释和举例、情绪回应及追问时机。用户明确要求长期采用的内容写法、反复纠正和改写示范可以形成带适用场景的候选；示例里的具体事实、一次性答案、助手自述和沉默不作为长期原则。内容原则与发送节奏分别提炼，仍受证据门槛和候选容量约束。

确认后，Memory Context 将适用的原则交给下一轮主模型，让它围绕当前话题重新生成内容。正文先生成，再由分段器决定发送断点；规则不复制历史答案，不强加不适用的场景，当前明确任务优先。训练提示 v4 也引导直接接话和使用改写原则。统计用户消息长度、问号或口语标记只能提供表达示范，不能证明用户希望收到什么内容。

内容偏好沿用既有查看、修正、撤销和范围隔离；升级只变更新提炼批次版本与 Context 修订，Memory/Learning 状态格式仍为 1，旧批次原样保留、已消费证据不重提炼。进程验收使用本地模型替身验证新主题生成请求、实际回复、重启、修正和撤销；真实模型的内容质量由正式交流另行验证。

```sh
./target/debug/eve-qqbot --state-dir .eve-qqbot --self-learning
```

凭据沿用[QQBot 通道](./QQBot通道.md)。可组合 `--training` 主动提问、`--cognition` 内生反思；这两个开关保持独立。已有 PostgreSQL 目录继续提供原 `--database-config`，不自动迁移历史。

## 持续学习与自动确认

每个可信范围独立积累至少三条未消费、确认送达的完成交互；每批最多八条，仍只有一次无工具模型请求。默认同范围间隔五分钟，可用 `--learning-cooldown-ms 0至86400000` 调整；这是提炼间隔，不是 QQ 段间停顿。自主模式持续接收新证据，不再用完四批后等待重启。普通 `--memory --memory-learning` 保留四批启动额度和手动确认行为。

内置 `EvidenceConfirmationPolicy` 自动确认未过期、模型自评至少 80、至少引用两条本批完成交互的候选。宿主再次核对范围及当前 Memory 中的完整证据。模型自评和引用数量是准入条件，不能证明语义正确；助手自述、沉默、引用及一次性任务不能按提炼规则冒充长期偏好。未达门槛的候选保留在 `/memory-candidates`，可手动确认。

自主流程先保存带来源和策略版本的四态决策，再用一次 Memory CAS 尝试新建或更新；首版直接引用真实完成证据，不伪造用户命令。决策记录仅表示意图，列表核对 Memory 历史后才标明实际保存状态。有限规范化后的重复正文不新建；已关联候选不覆盖纠正或复活撤销记录。新 ID 的候选也不能重新自动保存已撤销记录的当前或历史等价正文；需要恢复时用户可明确 `/remember`。完整规则见[学习决策与冲突](./学习决策与冲突.md)。

## 反馈与分段

自主 Context 在八条、8192 字节预算内优先最新来源修订，不依赖时钟先后。新聊天反馈可成为新偏好；明确单项节奏反馈在唯一目标、全部历史来源均为真实完成交互且证据更新时，可更新原偏好并保留历史。手动纠正和撤销优先。

混合已知节奏或发送端可识别的较宽写法，只有完整不超过 8 个子句、同字段数值一致且所有字段都没有相关历史时，才可首次确认。例如没有相关历史时仍可保存“回复最多分成两段，段间不要停顿”。存在任何相关历史就暂缓，保留手动与撤销屏障；这类候选永不自动更新已有偏好。已知节奏混合未知子句或同字段值矛盾也暂缓。现阶段没有通用语义冲突合并器，模型仍可能误判；用户可明确纠正或撤销。

自动节奏采用[规则建议器](./表达偏好与分段输出.md#qq-已确认偏好的节奏建议首版已实现)，只解析支持的完整明确句子，不把“更像人”编成段数。发送前读取当前有效偏好，按来源从旧到新逐字段应用，再叠加手动设置。派生过程只读，不把学习结果复制到第二份持久设置。

| 命令 | 自主模式行为 |
| --- | --- |
| `/self-learning status` | 查看模式、候选关联情况及范围容量提示，零模型调用 |
| `/memory-candidates`、`/memories` | 查看候选、来源、当前偏好和历史状态 |
| `/memory-decision 候选ID` | 查看当前会话最近决策、理由、来源及真实保存状态，零模型调用 |
| `/correct-memory ID 内容` | 修正来源；后续 Context 和自动节奏读取新版 |
| `/forget ID` | 撤销来源；下一次装配与投递不再自动使用它 |
| `/segment`、`parts`、`pace`、`on`、`off` | 查看有效节奏或保存优先于学习结果的手动选择 |
| `/segment reset` | 清除手动选择，恢复跟随当前有效学习偏好；没有学习节奏时跟随宿主默认 |
| `/segment adopt ID 版本` | 将该建议固定为手动选择；来源撤销后这份手动选择仍保留，需另行 reset |

停用自主学习时不再提供自动确认和节奏叠加。已保存偏好只要仍开启 `--memory`，就继续用于聊天；停用开关不删除历史。分段只切分原回复，不改写或补生成内容，回执、代际检查和重启不补发保持既有契约。

## 持久化、恢复与替换

Memory、Learning 与手动分段设置均沿用格式 1，新增独立格式 1 决策文档 `learning.decisions.v1`。旧目录缺少该键时视为空历史，零迁移、零补写。完成候选已保存而记忆提交尚未执行时，重启重新检查并可进行本地处理，零重复提炼请求。决策保存与 Memory 提交没有跨插件事务，重启核对真实 Memory 历史；已关联、手动纠正、撤销或过期记录不因旧意图重写。CAS 修订冲突留到下一次扫描重新核对；容量满保留候选及历史。持久化错误可能已提交，实例关闭、宿主停止，重启核对实际状态；不清空损坏数据。

Learning 批次文档全局仍限 128 批、4 MiB；决策文档另限 1024 条、4 MiB。Memory 原始证据和偏好历史也有全局上限，不自动淘汰。自主模式持续运行不代表无限容量；达到上限暂停相应新增操作，已有查询和普通交互仍按各自容量契约处理。`/self-learning status` 提供当前范围计数，不能据此推断其他范围的全局剩余额度。

`eve-learning-api::AutoConfirmationPolicy` 定义带版本的纯判断契约，`eve-learning-plugin::EvidenceConfirmationPolicy` 提供四态实现。可信 Rust 宿主可通过 `run_qqbot_with_learning_policy` 替换策略和提炼器；关闭自主模式时不调用策略。自评至少 80、至少两条引用属于内置门槛，替换策略可以选择不同门槛；宿主仍保留候选期限、完整来源、冲突屏障及目标版本复核和持久化边界，策略不能跳过这些限制。`LearningOptions` 可在组合层替换，QQ 命令不把管理能力或写能力交给模型。

本地真实 Eve 进程使用 HTTP 与 QQ 桥接替身验收：自动确认、待确认批次恢复、低自评/单来源保留、超过四批、从新聊天更新偏好、最新 Context、实际多条发送、手动覆盖、纠正撤销及新 ID 不复活。PostgreSQL 验证原始证据不变、撤销保留和空重启逐字节不写状态。实机体验和真实模型语义质量须另行评估。

这交付的是基于记忆和规则的自主偏好学习，不是模型权重微调或完整 AGI。长周期目标规划、世界模型、环境反馈、自改实现及独立能力评估仍按[开发计划](./开发计划.md)推进。
