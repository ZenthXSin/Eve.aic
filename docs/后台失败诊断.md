# 后台失败诊断

后台工具失败时，结果包含具体失败类别、可读原因和最近执行记录。例如先写文件再运行不存在的程序，会保留 `write_file：已返回结果` 与 `run_command：失败（程序无法启动）`，不会只返回“未确认副作用”。命令正常返回非零退出码时列出退出码和有界错误摘要，不把工具协议成功等同于业务成功。

`list_background_tasks` 返回 `execution_steps`、`step_total`、`remaining` 等字段。指定任务默认查看最近 12 步；提供 `step_offset` 与 `step_limit` 可逐页读取已有步骤，每页最多 25 步，`next_step_offset` 为下一页位置。仅任务所属用户可以查询。

普通卡片仅生成最近 3 步，指定任务的默认预览仅生成最近 12 步，显式分页只生成所需窗口；不再先格式化所有历史步骤。回执索引也只保留窗口内调用的引用，完整记录仍用于总数计算。失败通知只格式化最近 3 步，同时报告完整记录数。原字段、顺序、偏移、脱敏与未知状态语义保持；分页查询不修改或截断检查点，也不增加执行预算。

`steps_used` 是共享预算中累计消耗的工具步数，包含父执行者和全部子代理；检查点与已记录用量同时存在时取较大值。失败回执的 `remaining_tool_steps` 用同一计数扣减，不会因子代理消耗或较旧检查点而多报剩余额度。`step_total` 是当前执行者保存的调用记录条数，不展开子代理内部步骤，因此可以小于共享消耗。没有任何用量依据时 `steps_used` 仍为空，不伪造为零；修正只影响展示，不重新分配预算。

显式任务查询先读取完整轻量目录；列表只逐条读取最新十个目标并生成小预览，按编号只读取一个目标，不先复制整本任务正文。保持同用户其他会话的原管理权限；读取使用目标原始完整身份并核对编号、来源和创建记录，其他用户正文不读取。列表中的合法已回收记录跳过，指定的已回收编号仍返回不存在；后续读取失败或目录与正文不符时拒绝整次查询，不返回部分结果。

步骤来自原有持久检查点，保留全部原始调用与回执；展示时不输出命令参数、文件内容或完整标准输出，并隐藏宿主凭据和疑似凭据行。摘要有界不代表删除原记录。重启仍能查询；在途工具只标记未确认，不推断它成功或失败，不自动重跑。

中断报告分别指出没有回执、工具异常、恢复次数用尽、总期限到达或检查点缺失。超时也从检查点保留已知步骤。未知结果仍要先核对，不因为错误文本更详细而放宽恢复条件。

验收使用实际 Eve 进程：成功写入文件后令下一条命令启动失败，检查失败通知、分页查询、重启保留及零重放；另覆盖非零退出码与诊断脱敏。

通知轮询使用单独的投递目录，只包含编号、完整身份、来源、创建/结束时间及至多六次投递尝试，不复制任务说明、委派上下文、检查点和结果正文。原生实现直接从已校验账本提取；旧替换实现保留完整快照转换的默认方法。旧快照与新目录共用通知选择逻辑，目录与账本共用通知状态校验。到期、同用户在途互斥、已主动尝试及同条消息已附带的选择规则保持。

真正发送前仍先持久化认领，再核对返回任务与目录的编号、完整身份、来源和创建记录。不匹配时不向通道提交正文；不把认领异常改成成功或自动重试。重启时的未知投递仍不重发。目录不是身份认证或额外授权，策略学习对账的完整快照路径另行处理。
