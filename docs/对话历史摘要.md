# 对话历史摘要

QQ 现默认按[上下文主动压缩](./上下文主动压缩.md)在约 150k 估算 token 时主动调用此摘要服务，并复用持久摘要。关闭主动模式后，使用本文原有的窗口省略和后台生成方式。

[会话历史窗口](./会话历史窗口.md)只把最近的完整轮次交给模型。QQ 宿主在此之上把被省略的较早轮次压缩成摘要：模型拿到“第 1 至 C 轮的摘要 + 最近的原文”，而不是只知道有内容被省略。原始轮次始终完整保存在会话账本里，摘要不替换、不删除任何记录。

## 怎样生成

- 某轮对话的历史超出窗口时，运行时把被省略的原文交给摘要服务，取回覆盖开头若干轮的摘要。查找只读磁盘，不请求模型。
- 被省略但尚未覆盖的轮次达到 `min_uncovered_turns` 时，登记该会话。后台每次处理一个，把上次摘要与紧随其后的新轮次（JSON 预算 `max_input_bytes`，至少一轮）交给模型，合并成新摘要。单条消息超过 2000 字、工具结果超过 400 字时，只在摘要输入里截断并标明。
- 摘要至多 12 个要点，每点注明来源轮次，例如“用户说最喜欢蓝色（第 1 轮）”。请求使用 JSON 对象模式，格式或要点无效时至多纠错一次，与首次请求共用期限；仍无效的结果不保存。纠错只重新摘要同一份数据，不执行原记录中的工具。
- 交给对话模型时标明：摘要是归纳而非原文，可能遗漏细节；需要原话先查记忆；不得据摘要重放旧工具。尚未压缩的轮次会写明“第 C+1 至 N 轮尚未压缩”。

## 面板配置

“插件页面 → `runtime.history_digest`”，保存后下一轮生效：

| 字段 | 环境变量 | 默认 | 范围 |
| --- | --- | --- | --- |
| `enabled` | `EVE_HISTORY_DIGEST_ENABLED` | true | 关闭时不提供也不生成摘要，已存摘要保留 |
| `min_uncovered_turns` | `EVE_HISTORY_DIGEST_MIN_UNCOVERED_TURNS` | 4 | 1–64 |
| `max_input_bytes` | `EVE_HISTORY_DIGEST_MAX_INPUT_BYTES` | 49152 | 4096–262144 |

模型用途为 `digest`，使用主模型线路，可用 `runtime.model_uses.digest_max_output_tokens` 单独设置输出上限，面板就绪页单独记录其请求结局。摘要服务于对话本身，与主对话一样不计入自主运行预算。单次请求按模型设置、至多 180 秒；请求失败或超时后暂停新请求 60 秒，不重试同一批，等该会话下一轮再次登记。

## 持久化与恢复

- 摘要存放在 `状态目录/history-digest/`，每个会话作用域一个 `scope-<SHA-256>.json`（格式 1），保留最近写入的两个版本。先写临时文件并同步，再原子改名。备份与迁移须连同此目录。
- 每个版本记录被覆盖轮次原文的 SHA-256。使用前重新计算，不一致就不用；窗口调大、省略的轮次少于覆盖轮数时，退回覆盖较少的版本，都不适用时只提示省略。
- 摘要是可由会话原文重新生成的派生数据。文件数超过 4096 时淘汰最久未写入、能完整解析的文件。
- 文件损坏或版本不受支持时原样保留，不覆盖、不删除；该会话退回省略提示，后台生成失败并在标准错误写出 `EVE_HISTORY_DIGEST` 行。对话本身不中断。
- 待生成登记只在内存中，至多 64 个会话；重启或登记已满时丢弃的项会在该会话下一轮重新登记。生成中的请求在停止时取消，不写入。

## 扩展

定义层是 `eve-llm-api::HistoryDigests`，运行时通过 `LlmHost::with_history_digests` 装配。`eve-history-digest` 提供文件存储、查找服务与可替换的 `HistoryDigester`（默认 `ModelHistoryDigester`），替换实现须通过 `validate_points` 校验。

## 验证

`cargo test -p eve-history-digest` 覆盖增量生成、指纹核对、版本回退、关闭、无效输出、输入预算和损坏保留；`cargo test -p eve-runtime --lib history` 覆盖摘要注入与各种不适用时的回退。`connectors/qqbot/test/history_digest_test.py` 用实际 QQ 宿主验证摘要生成、注入、重启后沿用、热关闭和损坏文件保留。
