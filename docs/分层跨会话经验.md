# 分层跨会话经验

QQ 启用交互记忆时，同步启动独立的经验账本。契约位于 `eve-memory-api`，持久化与词法检索位于 `eve-memory-plugin`，QQ 组合、工具与公开实践适配位于 `eve-app::subject_memory`。模型无需主动检索：每轮真实用户输入都会经过 `ExperienceContext`，只追加本轮相关的最多三条经验；中文按双字与完整词匹配，英文按完整词匹配。检索分数表示相关性，不表示事实置信度。

## 三层范围

- `Subject`：Eve 可以跨窗口复用的公共实践经验，来源必须是宿主确认可公开的 `PublicArtifact`。
- `Principal`：个人经验，只有宿主通过 `save_personal` 确认可信身份和跨场景分享意图后保存。QQ 的 `PrincipalResolver` 只接受面板明确配置的主人绑定或 `identity_groups`，不按昵称或两个 openID 相等猜测身份；AppID 纳入身份域，绑定名单变化也切换身份域，新的主人不能继承旧主人的个人经验。群里读取个人经验还必须打开 `share_private_to_groups`，默认关闭。没有可信绑定返回 `None`。
- `Scope`：原通道、原会话、原用户，三者完全一致才可读。私聊、群聊、群成员之间不能通过文字声明共享。

原话仍由既有 `MemoryService` 按 scope 保存，归档原话依然可由完整快照检索。经验来源只保存回执或草稿引用，不将用户原话提升为主体公共知识。个人偏好继续使用既有明确偏好及 continuity 授权，不从经验草稿推断偏好。`ExperienceRecall` 与 `ExperienceMemoryAdmin` 分离；上下文只依赖读取契约，并校验替换实现的命中范围、来源与状态。

## 模型保存工具

`experience_memory` 支持 `save`、`correct`、`revoke`、`archive`、`recall`。模型参数没有 channel、session、principal、公开发布或验证开关；作用域和持久轮次来自可信执行上下文。保存和更正一律为本 scope 的 `Unverified` 草稿，来源标为 `model-draft-操作-turn-N`，不能冒充真实执行回执。草稿在下一次相关请求自动召回，并明确说明尚未验证。更正、撤销、归档使用保存时的逻辑 ID 或召回返回的 ID；其他会话的 ID 不能取得管理权限。

宿主可通过 `publish_public` 保存明确批准的公共经验，通过 `revise_public` 校验、更正或撤销公共经验。这两个接口不直接交给模型。

## 实践结果自动接入

真实实践的 `PracticeAdmin` 由 `PublicPracticeRecorder` 包装。`record_evidence` 先写入实际实践账本，随后确认返回的完整 `PracticeRun` 与持久账本一致、运行状态为 `Verified`、草稿形状有效、实际 `RunEvidence.validate` 和 `verified` 都通过，再匹配宿主批准的公开产物。

批准名单来自宿主环境变量 `EVE_PUBLIC_PRACTICE_ARTIFACTS`，内容为 JSON 数组：

```json
[{"runner_id":"public-runner","draft_sha256":"完整序列化PracticeDraft的64位小写SHA256","summary":"宿主批准公开的可复用实践经验"}]
```

`practice_draft_fingerprint` 按实际序列化草稿计算指纹。匹配包括运行器与完整草稿指纹，不能仅凭同用户、相似任务或成功状态批准。未配置名单时实践照常进行，但不公开用户资料。保存到公共经验的仅为宿主批准的 `summary`、日志 SHA256 引用、尝试版本和完成时间；不会复制 task.brief、owner、文件内容、运行日志。相同批准产物只归集一次，更正、撤销或归档后不会被后续实践自动恢复。

## 来源、版本与故障恢复

每条经验保留连续版本、操作 ID、时间、来源及状态。更正后的正文必须重新标为 `Unverified`，不能继承旧版的 `Verified`；验证操作须保持正文不变。撤销与归档立即退出召回，旧正文、来源和全部历史仍保留，终结状态不能隐式恢复，需新建新 ID。

经验状态以插件命名空间 `eve.memory-experience` 下的 `experience.v1` 保存。格式版本与内容严格校验，重复 JSON 字段、未知格式、损坏记录均拒绝启动，保留原始字节；不清空或跳过错误。写入采用整体持久提交及快照 CAS，成功确认后才切换内存状态。提交确认丢失时关闭当前服务，禁止继续读写；重新打开后读取真实持久结果，不能自动重放可能已提交的实践。实践成功但经验归集失败会显式返回存储错误，原实践仍已保存，可重启后仅重新归集，不重跑实践。

容量为 256 条经验、1024 个历史版本及 4 MiB 状态上限；为活动记录预留一次撤销/归档版本与字节余量。满额拒绝新增且保留原记录。这里的归档是停止召回并保留审计资料，不释放历史容量或删除原文；它不替代既有原话的文件归档。持久化后同操作 ID、同记录与完全相同版本可幂等重放；不同内容使用同操作 ID 拒绝。

## 验收

`eve-memory-plugin/tests/experience.rs` 覆盖跨窗口公共复用、私聊/群聊隔离、个人可信绑定、禁止scope来源提升公开、验证失效、更正/撤销/归档、容量、实际文件重启、提交确认丢失及损坏状态保留。`eve-app::subject_memory` 测试直接执行真实保存工具并检验后续轮次自动召回、无关请求与跨群负例、伪造身份/验证参数拒绝，以及已持久化真实实践账本的公开经验自动归集与私有资料排除。
