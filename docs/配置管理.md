# 配置管理插件（Issue #32，第一切片）

本切片交付普通配置的定义、读取、更新、备份、回滚和文件恢复。密钥库、主密钥管理、密钥引用、凭据代理、2FA、插件信任和检查工作流继续由 #32 后续切片实现；当前实现明确拒绝 Schema 中标记为 `sensitive` 或 `encrypted` 的字段，不把敏感值写入普通 JSON。不要用普通字符串字段保存 API 密钥。

## 分层与启动

- `eve-config-api`：Schema、版本化 DTO、结构化错误、`ConfigService` 读取接口和单独的 `ConfigAdmin` 管理接口；不依赖 Kernel、文件系统或 Tokio。
- `eve-config-plugin`：内置 `eve.config` 插件，以文件存储实现公开契约。组合层只提供目录和所有消费者声明的 Schema，不解析业务配置。
- `eve-example-plugins::ConfigConsumerPlugin`：仅依赖 `config-api` 和 `plugin-api`，Manifest 声明 `eve.config` 的 `^0.1` 依赖，启动时取得 `eve.config.read.v1`。
- Runtime：选择实现、收集 Schema、注册插件。消费者由既有依赖解析自动先启动配置插件；服务不可用、Schema 版本不兼容或读取失败会使消费者启动失败，不静默回退到硬编码。

Schema 在配置插件启动前统一装配，本切片没有运行时 Schema 注册和迁移。命名空间使用 `runtime.llm` 或 `plugins.<插件ID>`；每段只接受小写 ASCII、数字、下划线或连字符。字段不包含点。命名空间、字段和环境变量映射必须唯一，Schema 版本为正整数。升级不兼容的 Schema 时明确拒绝旧文件，保留原数据供迁移。

普通消费者获得 `ConfigServiceHandle`；管理句柄仅由宿主从 `ConfigPlugin::controller()` 显式取得，不随读取服务发布。这个分离不等于可信静态进程内代码的安全沙箱。

读取接口采用同步的请求/回复 DTO，快照、请求上下文和错误可序列化；未来传输适配器可实现同一契约。当前只通过进程内 Service Registry 装配，没有交付外置动态加载、IPC 或不可信插件隔离。文件更新是同步 I/O，需要避免在对延迟敏感的执行器线程上高频调用管理接口。

## 类型与来源

首版支持布尔、字符串、带可选上下界的有符号整数；字段声明默认值、必填、明确环境变量名、重启要求及敏感/加密标记。Schema 的默认值本身也必须有效。

来源优先级固定为：`默认值 < 环境变量 < 配置文件`。每个字段先选文件值，再选环境值，否则取默认值；被文件遮盖的低优先级无效文本环境值不参与解析。环境变量在每次插件启动时采集一次，不修改进程环境；测试可显式注入环境映射。未知命名空间、字段、文件 Schema 版本、类型错误、越界和缺少必填字段全部报错。类型错误只报告字段路径，不回显原始值。

`runtime.llm.max_parallel_tool_calls` 默认 `10`，环境变量为 `EVE_LLM_MAX_PARALLEL_TOOL_CALLS`，仅接受正整数；消费者用 `LlmRuntimeConfig::try_from(&snapshot)` 获取类型化配置。本 PR 不修改未合并的 LLM Host，也不宣称已将配置接入真实 Provider；待 #34 合并后由组合层在请求边界使用此配置。

## 请求与更新

`snapshot(namespace, schema_version)` 返回当前配置的独立快照。`begin_request` 返回请求开始时的快照与本次服务会话标识；后续 `read_request` 依据更新模式读取：

| 模式 | 在途请求后续读取 | 新请求 |
| --- | --- | --- |
| `NewRequests` | 保留开始时的快照 | 使用新配置 |
| `Immediate` | 使用最近一次立即替换产生的快照 | 使用新配置 |

例：请求 A 在并发 10 时开始，更新为 11（仅新请求），A 仍读到 10；再立即替换为 12，A 后续读到 12；接着仅新请求更新为 13，A 仍读到 12，新请求读到 13。已经取出的独立快照不会被原地修改。`ConfigRequest` 携带公开配置数据，是读取上下文，不是权限或身份凭据。

服务停止后拒绝旧句柄读写；恢复时生成新的会话标识，旧请求交给新服务会返回 `StaleRequest`。服务停止显式释放目录锁，外部仍持有旧 Arc 不会阻止重启。已经脱离服务的纯数据快照仍可离线读取。

管理接口 `replace(expected_revision, overrides, mode)` 是替换整份文件覆盖值，不是局部 patch。删除的覆盖项重新使用环境或默认值；必填值仍需满足。期望修订号不匹配时返回 `RevisionConflict`，避免并发管理员丢失修改。全部命名空间在同一次提交中更新。

标记 `restart_required` 的字段提交到磁盘并在结果中列出，但当前服务继续使用启动值，直到配置插件重新启动。无论选择哪种更新模式都不绕过重启要求；其他字段正常更新。回滚也是带期望修订的新提交，返回新修订号，不倒退当前修订序列。

## 持久化与备份

目录固定为规范化的绝对路径，通过独立的 `config.lock` 持有排他锁。只有最终 `config.json` 不存在才按默认值/环境启动；坏 JSON、重复键、未知格式/Schema 版本、非法历史、链接或目录均拒绝恢复，不清空原文件。缺失文件不会仅因读取而自动写入。

`config.json` 把当前文件层覆盖值和历史备份放在一个版本化文件中，例如：

```json
{
  "format_version": 1,
  "current": {
    "revision": 1,
    "namespaces": {
      "runtime.llm": {
        "schema_version": 1,
        "values": { "max_parallel_tool_calls": 7 }
      }
    }
  },
  "backups": [
    { "document": { "revision": 0, "namespaces": {} }, "pinned": false }
  ]
}
```

每次修改把旧文件层配置加入备份；保留最近 20 个自动备份，手动固定的版本另外保留。解除固定后立即按自动保留规则整理。备份不复制环境变量或 Schema 默认值；回滚以当前 Schema 与本次启动环境重新解析备份覆盖值。

提交在互斥锁下校验完整候选配置，写同目录临时文件、同步临时文件，再原子替换主文件；成功后才更新内存。备份和配置共同提交，错误不会出现只修改一方的半提交。同步临时文件不承诺突然断电后的目录项持久性。

在线修改使用管理接口，才能执行校验、自动备份和生效策略；直接编辑文件应先停止配置插件。本切片不监视外部文件变化。

## 实际验收

```bash
cargo test -p eve-config-plugin --locked
cargo run -p eve-runtime --example configuration --locked
```

无参数示例使用临时目录，展示消费者依赖启动、两种生效模式和停止/重启恢复。可给一个独立目录连续运行两次，第二次恢复上次修订和配置；不要将验收指向在用配置目录：

```bash
cargo run -p eve-runtime --example configuration --locked -- /tmp/eve-config-demo
cargo run -p eve-runtime --example configuration --locked -- /tmp/eve-config-demo
```

自动测试覆盖来源优先级、类型/范围/版本校验、敏感字段拒绝、混合模式、重启字段、CAS 并发写入、失败保持、备份上限与固定、回滚恢复、损坏/重复键拒绝、目录排他及生命周期失败回滚。CI 在 Ubuntu 和 Windows 运行示例，并检查两次独立进程的文件修订；Rust 1.89 检查所有目标。


## 四类模型角色

`eve-config-api` 新增 `model_roles_schema()` 和 `ModelRolesConfig`，在单一 `runtime.models` 命名空间承载主模型、辅助小模型、Jev 与语义模型。宿主显式注册 Schema，消费者通过公开 ConfigService 一次捕获四角色快照；详细字段、跨字段校验、更新与恢复边界见[模型配置](./模型配置.md)。Provider 装配、Jev HTTP、向量请求与凭据解析仍为后续切片。
