# 显式取消与代际隔离

对应 #29 第一切片。定义层 eve-control-api，内置实现 eve-control-plugin，Runtime 的 SessionControlRunner 将公开执行器契约连接到 SessionLlmHost。Kernel 不持有模型业务状态。通道与后续判断插件只依赖 ControlService。

每次提交返回包含用户、会话、task_id、随机 controller_epoch 和 generation 的 GenerationKey。epoch 每次插件启动重新生成；generation 单调递增，持久化 turn_id 由会话服务分配。任务 ID 是调用方标识，本切片不实现同任务恢复或幂等去重。ID 是逻辑隔离，不等于认证。

同一会话只允许一代在途，包括取消后的析构与状态提交；其他会话可并行。已经开始的同 session_id 不允许更换用户。begin 前被拒绝或取消的提交不永久占用用户归属，持久化会话仍由 SessionService 校验用户。cancel 精确校验完整标识，只发信号；wait 返回实际终态、提交状态、工具开始数量及已收集结果。重复取消幂等，取消完成代返回 AlreadyFinished，撤销排队事件的展示资格，不改写执行报告或已完成历史。保存已经完成后才收到取消时，结果可能为 Completed 或 Delivery；取消请求不等于执行结果。

显式取消关闭代际事件接收器，宿主观察 closed，终止网络读取并等待本地工具 Future 析构，再保存 Failed/Cancelled。控制器不直接 abort 轮次，不自动重跑工具。Context 装配和生命周期准入等待也观察关闭信号；尚未开始会话时不会创建轮次。同步 begin/最终提交不能被中途取消，最终报告如实反映落盘结果。

事件先附完整 GenerationKey 再发送。取消后的接收器拒绝继续转发；已进入通道队列的事件仍可能晚到，因此消费者在实际展示时必须调用 accepts，并串行处理检查/展示与取消/切换。新代启动后旧增量、工具结果、完成及 SessionSaved 均被拒绝。终态报告通过 wait 单独取得，不能因过时事件被抑制而丢失已发生的工具副作用。正常完成代的已排队事件可以继续显示，直至取消或新代替换。

完整回复保存失败、失败记录保存失败或执行器异常时，控制器进入 Blocked；不自动释放会话或启动替代轮次。提交失败留下的原 Pending 保留，恢复仍按会话插件的 Pending → Interrupted 语义，不能据此断言工具未执行。保存完成但通知失败保留完整文本与 Completed，不得重跑原工具。控制状态不持久化；磁盘历史仍由 SessionService 唯一管理。

Tokio 执行器关闭会直接丢弃已准入 worker，包括尚未首次轮询的 worker。控制器在 worker 析构时发布 Unknown / Blocked 报告，保留已知 turn_id 和用户取消标记，撤销全部旧事件展示资格，并唤醒所有 wait 调用方；同一控制器中的 submit 与 submit_if_current 均拒绝替代请求。started_tools 为 None，不能据此宣称工具执行数为零、取消已经完成或副作用已回滚。Unknown 只表示原执行结果不可用：通用控制器无法同步等待 runner 派生的任意任务，报告可能在工具 Future 尚未析构时已经返回。正常返回的已知报告仍要求 runner 先等待工具收尾及最终提交；正常报告不会被析构报告覆盖，已持有的旧代 wait Future 仍返回原报告。停止会回收已退出的控制 worker 句柄并使旧控制服务失效，该句柄回收也不能代替工具退出确认。

内置 SessionLlmHost 的租约析构会尝试保存 Failed / Cancelled，工具开始数量同样为未知；该磁盘记录不代表控制执行器已正常返回取消结果，控制报告仍为 Unknown。取消记录保存失败时保留原 Pending，重新装配会话服务后才转为 Interrupted；保存成功的失败记录和此前已完成历史均原样保留。重启不重放工具，必须按实际持久化状态显式决定后续任务，不能因为更换控制器而自动重试中断任务。再次打开同一状态目录前，需释放所有状态后端引用；宿主若保留控制服务或组合层执行器，还需停止并卸载控制插件、释放这些句柄。

每个会话仅保留最新代控制报告，避免每轮堆积；调用方应在替换前调用 wait 取得/持有旧代 Future，之后它仍返回原报告。停止使旧控制服务失效，取消并等待控制 worker；Kernel 的停止准入仍等待在途轮次与内置工具持有的准入句柄。正常取消应先 cancel/wait 再停止，Unknown 则仍需确认派生任务已退出；不能在轮次回调内等待同 Kernel 停止。受信任执行器必须协作观察 closed；同步阻塞、外部副作用及远端请求无法保证立即停止或回滚。

本切片不引入消息关系分类、自动纠正/补充重规划、暂停/继续、Jev 或内部推理输出。接着实现可替换消息关系判断服务及确定性动作映射。

## 结果映射与实际验收

| 执行结果 | commit | 完整输出 | 下一代 |
| --- | --- | --- | --- |
| begin 前关闭/拒绝 | NotStarted | 无 | 允许有效新请求 |
| 失败记录成功（含取消） | Failed | 工具开始数量/已知结果 | 允许新任务 |
| 完整历史提交成功 | Completed | 文本、完整 transcript 与回执 | 允许新任务 |
| 保存成功但通知失败 | Completed + Delivery | 完整输出 | 允许新任务，不重跑原任务 |
| 完整历史/失败记录提交失败 | Pending | 保留已有完整输出/诊断 | Blocked |
| 执行器异常或 Tokio 执行器关闭 | Unknown | 工具开始数及副作用未知 | Blocked |

```bash
cargo test -p eve-runtime --test control --locked
cargo test -p eve-runtime --test control_executor_recovery --locked
cargo run -p eve-runtime --example controlled_session --locked
cargo run -p eve-runtime --example controlled_session --locked -- <独立状态目录>
cargo run -p eve-runtime --example controlled_session --locked -- <同一状态目录>
```

无目录时用临时磁盘；指定同一目录连续独立启动后，历史 4 → 8、持久化 turn_id 2 → 4，每次工具执行 1、模型请求 3、旧事件接受 false。控制生成代每次 1/2，epoch 每次不同；旧工具不重放。CI 在 Windows/Ubuntu 实际检查 state.json 中四轮完整记录。本切片使用确定性 Mock，没有重新调用真实 API；接口取消仍不保证远端已停止。

执行器中断回归使用独立 Tokio 执行器 A / B：A 在首次轮询前、模型请求中或工具执行中关闭，B 的多个等待者仍取得同一 Unknown 报告。真实工具的析构屏障验证 B 可以先获得 Unknown，但此时工具尚未退出且会话仍 Blocked；释放屏障、等待 A 关闭后才检查工具析构完成。回归同时检查旧事件失效、替代请求阻塞、正常完成报告保持、任务与服务句柄释放，以及真实状态目录重开后保留失败记录或将未提交的 Pending 恢复为 Interrupted。


消息路由使用 snapshot.input_text 获取本代真实输入，并调用 submit_if_current(expected, input, sink)。该方法在同一控制临界区验证完整旧代，再执行与 submit 相同的所属用户、Busy、Blocked 和计数检查；它不会隐式取消。路由必须先 cancel/wait，有外部新代介入时返回 StaleGeneration，即使新代已经完成也不能覆盖。具体消息行为见[消息关系](./消息关系.md)。
