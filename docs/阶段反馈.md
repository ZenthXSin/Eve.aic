# 阶段反馈

Eve 默认在执行任务期间汇报小阶段，而非只在结束时回复。模型通过 `send_message` 说明开始计划、已核实的发现、失败原因和下一步；普通聊天直接答复。没有阶段文字时，宿主可在首次实际工具批次开始后补发活动说明，并按真实模型或工具事件报告等待状态，不披露内部推理、参数或密钥，不用进度宣称业务目标成功。

配置位于 `runtime.progress`，可在面板热修改：`stage_updates` 默认开启，`min_interval_ms` 默认 15000，`slow_after_ms` 默认 45000。对应环境变量为 `EVE_PROGRESS_STAGE_UPDATES`、`EVE_PROGRESS_MIN_INTERVAL_MS`、`EVE_PROGRESS_SLOW_AFTER_MS`。关闭阶段反馈后保留旧的可选工具里程碑与每轮一次慢步骤提示；纯聊天不会额外产生开始消息。

阶段文字优先使用 `send_message`，每条最多 250 个 Unicode 字符，以符合 QQ 进度正文的 1024 字节上限。模型必须依据真实回执，正常至少间隔 15 秒，不能逐工具刷屏。过快请求返回未送达，不能自动重试。宿主每收到约四次新工具回执或经过 30 秒可产生阶段事件，通道再按间隔过滤；慢步骤达到阈值且没有更近的阶段消息时，继续说明当前正在等待什么。每轮最多 64 条中途消息，失败即停止该轮后续进度，工具和最终回复仍继续。

前两条使用原消息的被动回复额度，之后或任务已接近被动窗口期限时使用原会话的主动发送。主动消息取原消息的群与发送者，不允许模型提供目标；每条群消息艾特触发者。私聊与群平台仍可能拒绝主动发送，实际回执决定送达状态，不承诺一定成功。主动消息不占用原消息的最终被动分段额度。Node 再独立检查序号、总上限与至少一秒的主动发送间隔。

所有中途消息先保存 `Sending`，收到平台回执后变为 `Sent` 或 `Failed`，取消或替代抑制旧代未发送的消息。首次主动进度把 QQ 回执格式升级为 8，并保存 `proactive: true`；只使用旧被动消息的记录继续使用原格式。读取仍严格校验主动/被动配额，进度不进入成功交互或偏好训练。监督器同步支持格式 8，存在当前不确定投递时不能自升级切换。重启保留未知发送，不自动补发、不重放工具。回滚必须使用兼容格式 8 的程序，或在停机且核对新记录后恢复匹配的完整备份；不得把新记录交给旧程序后清空。

验收包括实际 Eve 进程连续六阶段、一个长命令多次真实等待、主动与被动配额、失败后继续工作、取消及独立进程重启；Node 验证原路艾特、主动窗口、频率及最终分段；回执单元测试和监督器真实进程测试覆盖格式 8、未知状态和升级切换条件。测试只使用本地模型与 QQ 替身，不等同于真实平台主动消息权限验证。
