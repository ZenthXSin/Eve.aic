# 行动审核工具协议

审核模型只看到本次审核上下文，并且只能提交一次 `submit_review`：风险、授权、放行/拒绝和最多 300 字理由。该工具只返回判定数据，没有文件、命令、网络或执行能力。动作由原宿主在复核权限、审核等级和有效授权后执行，不能由审核模型直接执行。

普通文本、未知工具、多次提交、缺字段、未知字段或越界输出均视为审核失败；不把“审核通过”等自然语言当作授权，不从失败回退到默认放行。最近六条用户正文继续完整保留，工具轨迹仍有界。

健康面板在协议核验完成后记录结局：合法的拒绝也表示审核服务正常，HTTP 成功但输出无效计为协议失败。日志只记录固定类别和风险、授权等级，不输出供应商错误正文。

上游必须保留系统和工具指令。内容拦截应返回错误，不能通过删除审核规则重试。网络发送日志区分 DNS、连接、TLS 和超时；结果不确定的 QQ 消息仍不自动重发，避免重复投递。

开发工具的 GitHub 写入/删除/合并及宿主身份、权限、工程配置变更共用此协议。真实动作始终完整保留：命令为 program/arguments，业务动作以 eve.<工具名> 和完整 JSON 参数表示；敏感文件附完整旧正文。审核返回后复核权限及文件版本，失权或变更均不执行。审核关闭、缺少宿主原话、超容量或审计失败均失败关闭。后台继承宿主绑定的原始授权证据，不使用模型撰写的派发说明授权。

操作账本 v2 记录可信身份、时间、动作指纹及真实结果；独立审核记录关联 operation_id。重启把未完成记录标为 unknown 并禁止重放；排队升级不冒充已上线。凭据路径及已知宿主密钥不发送审核模型。

应用升级审核附相对可信在线提交的完整源码差异；候选清单将差异文件、基线、目标提交与监督脚本契约绑定到内容摘要和租约。旧候选缺少此证据只能用于监督器历史恢复，不能作为新的应用升级请求绕过审核。源码或原话超限均拒绝，不使用裁剪摘要代替必要上下文。
