# 受控产物行动：导出当前规划草稿

本切片在“文件观察 → 目标修订 → 当前反思草稿”之后增加一种真实本地行动：由操作者明确选择输入文件和一个尚不存在的输出文件，把当前版本已完成的反思导出为产物，再独立回读并核对完整字节摘要。模型不选择路径，也不获得 shell、网络、覆盖文件或修改被观察文件的权限。

产物完成只证明本次指定内容已经写出并通过回读校验。原用户目标继续保持 Waiting，文件中的陈述与模型草稿仍未得到现实验证；此能力不等同于建议正确、任务完成或 AGI 已实现。

## 使用

先按[本地文件观察](本地文件观察.md)创建目标并运行规划，用 `show` 查看当前目标修订、文件观察摘要和当前已完成草稿：

```bash
cargo run -p eve-app --bin eve-cognition -- --state-dir .eve-observe show --id report
```

将 `INPUT_SHA256` 设为当前文件观察中的 64 位小写 SHA-256，将 `GOAL_REVISION` 设为当前父目标修订。输出文件所在目录须由操作者提前准备，文件本身须尚不存在：

```bash
cargo run -p eve-app --bin eve-cognition -- --state-dir .eve-observe export-plan \
  --id report --revision "$GOAL_REVISION" \
  --observe-file ./progress.txt --input-sha256 "$INPUT_SHA256" \
  --output ./exports/report-plan.json
```

`--user` 默认 `owner`；创建目标时指定了其他用户，导出时也须匹配。每次执行都重新显式绑定输入文件与输出路径，不能用上次命令留下的路径授权替代本次参数。此命令不发起新的模型请求，需要已有属于当前父修订的 Completed 反思。

命令退出码为零表示完成了处理并返回结构化结果；只有 `action.record.status == "completed"` 才表示产物完成。被取消、写入失败或恢复封存的行动可以正常返回 `blocked` 及失败类别，不能仅用退出码判断写入成功。准入或持久化错误会返回非零退出码。

目标修订或文件摘要变化时，先重新观察和规划，再查看新的修订与摘要。不能通过反复提交旧参数让旧草稿适用于新输入。命令与 QQ、其他本地进程仍须遵守状态目录独占约束；不会自动停止现有服务。

## 准入和作用范围

宿主组合公开行动契约、持久化实现与文件产物实现。行动记录不保存原始输入、输出路径；路径只存在本次绑定实例内，持久状态用稳定来源摘要和作用范围摘要关联执行。摘要不是访问凭据，也不承诺隐藏可猜测的路径。

| 层 | 职责 |
| --- | --- |
| `eve-action-api` | 定义有界提案、行动日志、前置条件、产物能力及实际回读回执 |
| `eve-action-plugin` | 保存一次性行动生命周期；宿主管理句柄不向模型或普通服务消费者开放 |
| `eve-artifact-file` | 绑定本地输出，执行不覆盖的新建写入和独立回读 |
| `eve-app` | 校验用户、当前草稿及观察证据，组合显式路径绑定和有限执行 |

准入要求同时满足：

- 父目标属于当前主体和用户，是有效且未过期的 Waiting 本地用户目标，修订与命令一致。
- 草稿由当前父修订派生，已通过原反思流程完成，并且关联的实际会话结果存在且符合草稿协议；不能只相信模型的“已完成”文字。
- 该父目标最近的文件观察来源与此次显式绑定一致，观察摘要与命令一致；重新读取的文件完整字节摘要也一致。
- 输出作用范围由宿主明确绑定，待写正文及其字节数和摘要确定；预算允许本次唯一的一次写入尝试。

输入沿用本地文件观察边界：最大 65536 字节、无 NUL 的 UTF-8 普通文件。产物正文最大 16384 字节，模型请求预算为零，只允许一次文件创建和写入尝试。输出使用 `create_new`，存在的文件、符号链接或其他已有路径不会被覆盖。

重新读取前置条件和随后写入是两个操作。检查后其他进程仍可能改变输入、目标或目录；此实现不声称跨认知存储与文件系统的原子事务，也不提供对敌对文件系统的完整目录沙箱。30 秒期限是协作式截止时间，不能硬中断操作系统文件调用；已开始的宿主 I/O 必须收尾后才能返回，不把仍在后台运行的写入当作已取消。

## 持久化、回读与恢复

行动先保存 Executing，成功保存后才允许创建文件。写入结束后由独立读取核对产物字节数与 SHA-256，只有校验匹配并成功保存结果，记录才成为 Completed。执行记录把父目标修订、草稿、观察来源及摘要、授权范围、预期产物与实际回读证据关联起来。

取消请求在执行阶段之间检查。写入或回读已经开始时，等待本次操作结束再保存阻塞结果；不能借助提前返回隐去可能已经发生的副作用。最终结果的持久化提交开始后，取消不再逆转这个提交，宿主等待并返回实际保存的终态。即使请求取消或期限已经到达，也可能收到刚刚持久化的 Completed，不能据此再次执行。

行动 ID 由父目标修订和当前草稿等稳定身份确定，不由调用次数或输出路径决定。`export-plan` 每次仍须通过当前目标和输入的准入校验；前提未变且相同绑定的重复提交返回已有结果，不再次写入。输入或目标已经变化时，命令拒绝旧请求，不承诺返回历史重复结果。改换路径或其他作用范围不能把同一草稿变成一次新的授权，会报冲突。产物在执行后被外部移动、删除或改写，不会触发自动补写，历史回执也不保证文件永久保持原样。

| 情况 | 状态与本地文件语义 |
| --- | --- |
| 准入失败或 Executing 保存失败 | 不开始文件创建，保留已有状态 |
| 输出已存在或写入失败 | 保存失败结果；不覆盖、删除或自动重试 |
| 已写出但回读不匹配 | 不标记完成，保留实际文件和诊断结果 |
| 已有副作用但结果保存失败 | 返回持久化错误，保留 Executing 等不确定状态；不据此宣称没有副作用 |
| 重启发现 Executing | 恢复为 Blocked/Interrupted，保留历史与可能存在的产物，不重放行动 |

`show --id ID` 在返回 `actions` 时也会打开行动日志并执行恢复，因此它是恢复性读取：发现遗留 Executing 会先保存为 Blocked/Interrupted。没有遗留执行时，查看不会改写行动记录。需要了解失败原因时，核对 `actions` 中的 `status`、`failure` 和既有回执。

写入失败可能留下空文件或部分文件，系统不会擅自删除。中断、超时和不确定结果也不会自动解除阻塞。操作者须核查实际文件和行动记录，再决定后续目标反馈及新一轮规划；反复运行原命令不能绕过一次性执行语义。损坏或不一致的持久数据直接报错，不自动清空状态。

导出正文是模型生成的草稿，可能包含用户目标、文件内容摘要或其他会话信息。选择输出位置即表示操作者要把该草稿写到那里；状态中的路径脱敏不会使导出正文自动脱敏。正文中的命令或路径只是数据，文件能力不会执行它们。

## 后续范围

此切片提供了一次有前置条件、有持久执行记录、有实际副作用和独立字节校验的本地行动。尚未自动执行草稿建议，也未验证建议是否能实现用户目标。更丰富的工具能力、现实效果验证与 QQ 实机交互需要分别定义授权范围、预算和验收条件；流程正确性与模型规划质量分别记录。
