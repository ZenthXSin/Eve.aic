# 优化版上线修复（2026-10-19）

用户要求上线 #218 的优化运行器。上线前发现旧 QQ 实例已经非零退出并归档：在成功回复后的交互采集阶段，全局证据数恰好达到 256，下一次导入触发容量错误，通道按未知采集失败的保护约定关闭。会话与已送达回执保留，不能通过清空记忆恢复。

本次将全局原始证据上限扩展为 4096，保持作用域上限 256、偏好/历史/操作上限 256、序列化总量 4 MiB，不淘汰任何旧证据，不补采旧 Sent，不重放工具。旧格式 1 仍直接读取；旧程序遇到超过自身容量的新快照会拒绝读取，不能将其当作空库。扩容只是有界余量，不代表 #197 的分块归档已经实现；任一剩余上限达到时仍明确失败并保留数据。

另修复 #217 新增格式 3 进展回执与升级监督器的兼容：接受已收尾的 Sent / Failed 进展，Sending 仍阻止切换，非法状态拒绝。原生测试验证完整申请轮次、最终投递及重启不重放。性能夹具现在识别真实进展而不把它当作最终答复或新的用户输入，并处理采样时进程刚好退出的竞争。

内存全局容量边界测试改为一次装载合法满容量快照，继续检查满容量重放只读、溢出原子拒绝及已存在证据可用于偏好，避免扩大限额后为边界测试重复写入数千份整库快照。新增原生场景从 256 条旧证据恢复，证明新交流、重启与继续采集正常，原始证据前缀和偏好均保持。

上线使用实际 release 产物和真实模型/embedding/TypeSafe/30 工具预检。保留旧非零退出记录和加密状态包；只在旧控制器已退出、所有轮次与平台回执收尾、监督器停止后接续同一训练状态，原始 24 小时截止时间不重置。最终部署证据以同环境 `active.json` 及其关联 proof 为准。

本地验证：memory-api / memory-plugin 79 项、监督器 10 项、原生容量恢复 / 实时升级 / 工具进展 8 项全部通过；正式桥接性能套件通过（Node 25000 条，Eve 新建 / 恢复各 120 条），workspace 严格 Clippy、格式检查通过。性能套件使用本地模型夹具，不代表上游模型实际耗时。
