# 结构化工具回执

模型上下文统一使用 `eve.tool_receipt.v1` JSON，HTTP 消息 content 仍为字符串。

- `callId` / `tool`：原调用身份。
- `callStatus`：工具调用返回状态；缺失时为 `unreported`，不猜测成功。
- `task.jobId` / `task.status`：脚本任务的独立状态。调用 completed 不等于脚本完成。
- `receipt`：完整回执字段。只解码已知原生工具约定的 JSON output。
- `receipt.output.result.value`：完整、从零开始的脚本结果页所编码的 JSON 值，仅解码一次。
  返回字符串仍为字符串，任意正文、嵌套 text/output 不再猜测解析。
- `task.inspect` / `task.continuation`：直接读取同一任务的入口与下一页游标。
- `original`：通过 tools.records.text 分页读取原始记录。

节选、后续页、普通文本保留原文与全部分页元数据，不把可解析的节选误认为完整 JSON。
unknown 保持未知，不自动重试业务动作。外部工具未声明的 output 保持原样。
主机通知使用 `eve.host_notice.v1`，保留原封装与读取原件入口；普通用户消息不修改。
显式 raw 回执保留原样。日志、管理面板原件、RPC 和恢复契约没有迁移。

原生 `read_script({jobId,startChar?,limit?})` 直接调用脚本宿主的 status，完成时再读取 result。
它不启动脚本、不编译沙箱、不执行业务动作；未完成和 unknown 仅返回原状态。
重复读取是只读查询，不能用它重试原动作。默认每页8192字符，沿原 jobId 和 nextChar 翻页。

本次需求来自实际意识记录：30023、30049、30056 反复提到查回执慢，
30005/30012/30016 等为读取旧任务结果又新建脚本。新增入口去掉这层执行开销。
Windows agent 离线、OCR 语言包缺失与未独立验收的内存候选在日志中也有记录，
这些属于独立依赖与验收事项，不能仅凭 Eve 的摘要判定已经修复或适合上线。
