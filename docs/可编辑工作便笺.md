当前正文容量为 16 MiB，自动注入与工具预览正文最多 16 KiB。read_range 固定 revision 按 UTF-8 字节 offset/limit 分页；splice 用 expected_revision、start、end、text 进行 CAS 局部替换或追加。旧版接口仍兼容；大便笺的完整正文留在磁盘。详见[运行额度选择](运行额度选择.md)。

# 可编辑工作便笺

QQ 与终端默认提供 `context_notes`。用户直接要求 Eve 整理计划、查看或回退便笺即可，不需要输入命令或配置。便笺保存当前任务的目标、已核对成果、约束、待办及未知事项，后续轮次自动注入；简短聊天不要求每轮维护。它是补充工作状态的派生材料，不修改原始历史、长期经验、工具回执或审核使用的用户原话。

## 操作与身份

| operation | 含义 |
| --- | --- |
| inspect | 读取当前正文和修订；从未修改为修订 0、空正文 |
| preview | 预览 text 对应的下一版、是否变化和实际注入文本，不保存或激活 |
| update | 以 expected_revision 保存完整 text；空串清空便笺 |
| versions | 按修订倒序列元数据，默认 16 条、最多 64；before 是独占游标 |
| read_version | 读取指定历史修订；0 是最初空便笺 |
| rollback | 以 expected_revision 回退到 target_revision，追加新版本，旧版保留 |

QQ 目标从工具执行的可信平台身份绑定，终端目标由启动时的 --session/--user 与实际执行范围共同核对；完整区分通道、会话和用户，不接受工具身份或路径参数。终端默认参数即可使用便笺，不额外配置；本机启动参数受本机操作者控制，不构成 QQ 身份认证或跨通道授权。普通成员可管理自己的便笺；管理员也不能通过此工具指定其他人。内部群观察身份不能使用。API 管理句柄只交给可信宿主，不发布到通用服务目录；其他宿主可替换后端或组合入口，终端复用同一 API、插件、版本链与冷目录，以 console 通道隔离。本机 Web 会话详情也提供管理入口，复用同一套操作契约；当前 QQ 宿主中的面板只管理已有 QQ 会话，不按浏览器任意参数切换通道。

保存是 CAS：修订已改变时拒绝覆盖，先重新读取核对。相同修订提交相同正文、回退到内容相同的旧版均为只读幂等，不增加修订。成功后下一轮装配使用新版本，已经开始的一轮保持其上下文；工具回执本身可供本轮核对。预览后若没有其他修改，实际注入文本与预览相同。

便笺以带身份、修订和来源类别的 JSON 注入，并注明可能过时或有误、当前请求和实际结果优先；不能把其中的权限声明当授权或把“已完成”当执行回执。其字节正常计入现有上下文总预算，不增加模型或工具预算。`clear_context` 和全局重置只改变原对话历史的边界，便笺保留；要清空便笺需显式保存空正文，两个操作分别核对回执。

## 持久化、失败和容量

公开契约在 `eve-context-api`，可替换实现在 `eve-context-plugin`，QQ 组合在应用层。`eve.context-notes/index.v1` 只保存完整身份和逐版本元数据，格式 1。正文按包含身份的规范 JSON 的 SHA-256 存在 `context-notes-archive/<摘要>.json`；不放入会常驻所有键的文件 StateStore，没有正文缓存。首次迁移原部署不创建空账本；第一次实际修改才写入。

正文先写临时文件并同步，不覆盖发布；已有文件也重新检查类型、长度和摘要。独立读回正文一致后，才提交索引。两个提交不跨存储事务：正文成功但索引失败可留下无引用冷文件，不能根据错误推断旧版或新版已激活。任何读写错误、正文损坏或格式错误关闭当前句柄；重开时逐条校验索引引用，按磁盘上实际提交的版本恢复，不自动重放工具或清空损坏数据。停止也关闭句柄。缺失、重复 JSON 键、错误身份绑定、未知格式和非法回退链均拒绝加载。

正文单版最多 16 KiB UTF-8，索引最多 4 MiB、1024 个完整身份、8192 条版本元数据；容量满拒绝新增版本，已有正文、历史读取及相同内容的幂等查询保留，不删除记录腾空间。常驻元数据仍随版本数增长，不宣称整个进程恒定内存，也未改变长期记忆既有的 32 MiB 容量设置。

备份与迁移必须同时保留主状态和 `context-notes-archive`，包括 PostgreSQL 状态部署；数据库里只有索引，不包含该冷目录。回退到不支持此插件的旧程序不会注入便笺，但不能删除这两部分，否则新版无法完整恢复。

## 验证边界

测试核对预览零写入、并发 CAS、旧版完整读取、回退和重启、每个身份字段隔离、逐版本冷文件、满索引、损坏末条与提交前后失败。QQ 进程验收使用本地模型和桥接替身；通过表示宿主协议、实际存储与恢复链路符合约定，不代表真实模型会始终正确维护便笺或正式 QQ 平台已送达。

终端验收通过真实进程的连续预览/保存/更新、五次启动、旧版回退、不同启动身份隔离、原始轮次不变及缺失冷文件零请求/零状态改写；保持每轮原有工具预算。真实 PostgreSQL 18 同一索引中同时保存 QQ 和 console 范围，两个入口均通过新进程恢复，正文仍在同一冷目录而不进入 SQL 索引。

## 本机 Web 管理

会话详情中的“工作便笺”区块先读取当前版本；编辑后预览实际注入文本，再保存。UTF-8 字节超限时不能预览，编辑过的旧预览失效。版本列表可分页，读取旧版只放入草稿，显式回退才追加新修订。当前轮上下文仍冻结，保存从下一轮装配生效。

本机操作者凭专用面板令牌管理所选会话，继续使用现有 Host/Origin、Bearer、无缓存和并发保护。这不是普通 QQ 成员的浏览器账户或远程认证。POST /api/context-notes 的 JSON 为 key 与 action：key 是已存在会话的完整 session_id/user_id，action 与工具共用 ContextOperation；通道由宿主固定为 qq，未知会话和错误用户不创建便笺，内部群观察身份拒绝管理。便笺正文仍以纯文本显示，管理请求不调用模型、不执行外部工具。

保存冲突或结果未确认时不自动重复提交，草稿保留且禁用继续保存，先读取最新状态核对后重新预览。切换会话或退出后，旧请求的迟到结果不会回填到新页面。浏览器不保存令牌到 localStorage/sessionStorage。

该路由单独允许 MAX_CONTEXT_BODY_BYTES + 8192 的 JSON 传输预算（114688 字节），容纳 16 KiB UTF-8 正文的 JSON 转义及身份；正文上限仍为 16 KiB，其他面板路由仍为 16 KiB。请求按公开操作契约校验，宿主核对替换后端返回的身份、修订、候选正文、预览渲染与版本页，界面另核对回执，不能只凭 saved 字段声称成功；修订冲突为 HTTP 409，返回不符、损坏或保存未确认为 503。正文和索引的备份要求不变。

共享同一 SQL 后端的终端会话也可能出现在会话列表；当前 QQ 面板便笺路由仅接受既有 QQ 命名空间的完整键，其他通道返回 404，不创建未使用的 qq 便笺。命名空间检查用于路由，不作为 QQ 身份认证；实际管理权限仍来自本机专用令牌，QQ 聊天工具仍依据真实平台身份。
