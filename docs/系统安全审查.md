# 系统安全审查

用户在 2026 年 11 月 6 日明确要求大幅减少审查，只核对用户身份以及 Eve 的动作是否直接危害系统安全。自主探索没有任务目标、收益或验收合同也有效；这些条件不能被审查器重新变成执行门槛。

开发执行先由宿主核对可信身份、实际路径、权限与取消状态。普通文件读写、开发配置修改、构建测试、脚本和未知程序不再额外请求审查模型。GitHub 的普通仓库写入同样直接执行；修改访问控制、webhook、运行权限或自动执行配置才检查具体系统影响。没有新用户指令或来自委派都不构成拒绝依据。

源码阅读和搜索不再把 `Cargo.toml`、普通隐藏目录以及包含 `secret`、`credential`、`config` 的源码文件名当作凭据。宿主配置的身份权限仍有效，真实凭据文件、Git 管理目录和工具账本继续受保护；凭据识别按明确路径处理，不把所有 `hosts.yml` 或 `auth.json` 当作密钥。

明确停机、格式化或删除系统根目录仍被规则拒绝。凭据位置、提权、修改关键系统路径、停止关键服务等具体行为进入 `review_system_safety`；它只判断凭据外泄、身份绕过、关键文件/状态破坏或服务持续不可用。一般不确定性不等于危害。实际危害不能靠用户说同意就消除；受监督器保护的正常短暂重启可以是影响有界的操作。

`prepare_self_upgrade` 保留源码快照与实际验证，不再先请求模型批准。`apply_self_upgrade` 在切换前检查候选是否引入直接危害，候选摘要、租约、状态保留与回退仍由监督器实现。修改审查实现本身不被当作危险；判断它有没有移除可信身份边界或引入具体危害。

`ActionReviewer` 保留旧 `review` 供身份与跨会话隐私边界使用，新增系统安全入口；生产日志包装器显式转发，避免新调用又回到旧的逐步授权提示。系统安全结论不使用兼容字段 `authorization`，也不重复发送最近六条用户原话；原话仍保存在宿主原始账本。权限解锁的明确当前原话由宿主核对，不依赖模型；撤销或急停后的模糊解除仍须核实真实用户意图，不能由 Eve 自己抹掉。

命令规则是对可见参数的具体危险筛查，不是完整 shell 或源码证明；动态构造行为可能不能静态识别。调用者仍须按真实动作和宿主边界执行，不能把 `Allow` 描述成无条件安全保证。

普通命令和自升级检查共用启动器。Cargo 默认只运行一个构建任务，并继承宿主明确设置的 `CARGO_BUILD_JOBS`，避免宿主按 CPU 数自动并行构建造成内存耗尽。这个默认值不等于内存硬上限；显式参数仍由命令处理，宿主需要按实际资源配置进程限制。

已有操作账本保持原样，普通动作仍保存开始、结局和未知回执，减少模型审查不会重放旧动作。新的审查记录增加 `review_scope=direct_system_harm`，旧记录无需迁移，不删历史或清空损坏状态。
