# 群上下文可信消息锚点

普通群回复的自动上下文现在截止于本轮实际准入的 QQ 消息，而不是生成上下文时全群最新的二十条消息。消息处理变慢、相同正文重复发送、纯附件或其他成员后来发言，都不能让本轮错接后来的话题。

## 身份与序号管道

桥接器在普通消息实际提交给控制服务之前，将原始 `Message` 的平台 ID 绑定到 `QqConversations` 的当前轮次锚点。合并连发消息时，绑定整个真实批次，最后一条为主消息；合并后的输入正文不会产生新 ID。绑定验证每条消息有效、全部属于同一 SessionKey、同一群且 ID 不重复。不同成员共用群观察记录，但不能共用当前轮次锚点。

锚点与路由目录独立。新消息到达只更新路由身份，不修改正在生成的轮次。控制服务忙而原批次重新排队时，只要真实主消息 ID 相同就保留完整批次。完成、取消收尾和准入失败清理对应主 ID 的锚点，避免后来的内部任务继承旧轮次。

`qq_group::Context` 在等待其他上下文之前先冻结可信锚点。观察 ID 由 AppID、可信群标识与平台消息 ID 共同计算，与写入观察库时完全一致。不比较正文，不解析附件提示，也不把平台时间戳当可靠排序。

## 窗口存储契约

新增公开契约 `GroupObservationStore::window_ending_at` 以及 `GroupObservationWindow`。SQLite 在同一事务中读取各个真实锚点的持久插入序号，以主消息序号作为包含式截止位置。只读取当前群且序号不超过截止位置的记录，按序号从旧到新排列。

窗口总量至多二十条，优先保留全部合并批次消息，再补最近背景。即使两条合并消息之间已经插入超过二十条其他成员消息，也不会丢掉第一条合并消息。输出包含每条序号、本轮消息标记、主消息截止序号与真实锚点集合。纯附件消息正文保留为空，不补造图片或文件内容。

来源不存在、跨群、重复或顺序错误的锚点都明确报错。可替换存储默认返回不支持，不能悄悄退回 `recent(20)`。组合层还验证命中群、序号顺序、上限、完整锚点集合和锚点的真实成员；失败时不附加猜测的群原话。没有可信准入锚点的内部轮次不自动附加全群最新消息。插话引擎已有自己的目标窗口，不再额外叠加全群最新观察。

这是自动上下文窗口的边界。用户明确请求更早资料时，既有 `recall_group_messages` 和 `group_digest` 仍按可信当前群读取历史，不把历史话题变成当前要求。

## 未知发送结局

群主动发送收到 `QqOutreachResult::Unknown` 时，调用新的 `finish_unknown`，将账本保留为 `unknown`。它不会写成 `failed` 或 `sent`，不会创建已确认送达的问答记录，也不会再次领取或自动补发。重启保留这一结局。

## 验收

SQLite 实测覆盖相同正文的两条不同 ID、纯附件空正文、主消息之后二十五条后发消息、跨群拒绝，以及被三十条其他成员消息隔开的合并批次。QQ 身份目录测试覆盖可信批次绑定、后到同文不改锚点、跨成员拒绝、忙后批次保留和完成时清理。未知投递测试直接核对数据库的 `unknown` 状态，并确认没有已送达问答和重启重发。
