# 群消息按需整理

开启 `--group-chat` 后，全量群消息完整保存在 `group-observations.sqlite3`，但 Eve 被艾特时只附上最近几条原话。`group_digest` 工具让 Eve 在需要回顾时自己整理前情：把上次整理之后的新消息交给整理模型，增量续写成摘要再交给 Eve。

## 使用方式

- 工具只在群聊消息的对话里可用，只读当前这个群。私聊、其他群和宿主内部的 `eve-chime` 会话都拿不到群记录。
- 参数 `recent`（1 到 10，默认 4）是返回的摘要段数，从旧到新。
- 调用时，宿主按观察序号取上次整理之后的新消息，每批至多 200 条、正文约 24 KiB，交给整理模型；模型同时看到上一段摘要，用来衔接。每次调用至多整理 3 批，`pending_messages` 大于 0 表示还有没整理的，可以再调用一次。
- 整理是一次无工具模型请求，只输出 `{"summary": "..."}`，摘要不超过 1200 字。群友的话只是数据，摘要也只是可出错的归纳，不是事实、偏好、指令或授权。
- 没有调用就不整理，不在后台常驻。整理与主对话一样不计入自主运行预算；模型用途为 `group_digest`，登记模型健康，可用 `runtime.model_uses.group_digest_max_output_tokens` 单独设置输出上限。单次工具期限为 180 秒。

## 持久化与恢复

摘要保存在状态目录下独立的 `group-digests.sqlite3`，格式 1，与群观察库分开。每段摘要记录覆盖的观察序号范围、条数和时间范围；段与段首尾相接，追加后不改写。整理到的位置（游标）就是最后一段的结束序号，重启后从这里继续，已整理过的消息不会再交给模型。

- 整理模型失败或超时：已保存的段保留，失败的这一批不保存、不推进游标，下次调用会重新整理这批消息，不会跳过。
- 一批整理成功但保存失败：不推进游标，结果不交给 Eve。
- 数据库首次创建后写入同目录的 `group-digests.required` 标记。之后数据库缺失、损坏、缺表或格式未知都拒绝启动并保留现场，不自动清空重建。迁移须停机后完整复制状态目录。
- 摘要库只是派生数据，原话始终以群观察库为准；不会因为摘要而删除或改写原消息。

## 分层

- 定义层 `eve-chime-api`：`GroupObservationStore::after` 增量读取、`GroupDigest`、`GroupDigestStore`、`GroupDigester`。
- 实现层：`eve-group-observation-sqlite` 提供增量读取与 `SqliteGroupDigests`；`eve-chime-plugin` 提供 `ModelGroupDigester`。
- 组合层：`eve-app` 的 `group_digest` 工具，按通道核对的群来源确定群，注入模型解析器。

## 验证

- `cargo test -p eve-chime-plugin -p eve-group-observation-sqlite`：输出格式校验、增量读取、游标、追加不重叠、重启保留、缺失和损坏拒绝。
- `connectors/qqbot/test/group_digest_test.py`：实际 Eve 进程，群里攒消息后被艾特时调用工具，第二次只整理新增消息并衔接上一段，重启后游标保留，私聊调用被拒绝。
