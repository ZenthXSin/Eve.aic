# Web 主动通知与恢复

Web 的“主动通知”来自真实后台任务、条件触发器及任务进度账本。宿主后台采集，不依赖浏览器打开；登录后从持久收件箱恢复历史和未读数。页面每次轮询只读取已有记录，不执行模型或重跑任务。QQ 与 Web 依据完整会话身份分流，Web 编号不会被当作 QQ 收件人。

任务完成、失败、阻塞、中断和取消保留实际结果；触发器保存每个周期的结局。每个范围的任务进度提醒间隔至少 30 分钟、滚动 24 小时最多 48 次，读取已有检查点和状态，没有新进展时明确说明；提醒不代表目标完成。相同阻塞批次不反复催促，具体准入由后台任务账本控制。

## 定义与接入

`eve-web-panel-api::WebInbox` 定义分页与已读操作，`PanelService` 的默认实现返回不可用，未装配时不能以空列表冒充已经支持。`eve-app::web_notifications::Inbox` 从 `TaskAdmin`、`TriggerAdmin` 读取和结算；HTTP 只调用公开面板契约。

QQ 宿主可仅装配任务或仅装配触发器，采集器通过可选句柄处理已有能力；未装配能力的历史去重记录与待结算动作继续保留，重新装配后补结算。缺少句柄不等于账本为空，也不会清掉另一类待通知数据。

- `GET /api/notifications?before=序号&limit=25`：新的在前，单页 1 至 100 条，返回全局未读数和更早页游标。
- `POST /api/notifications/read {"id":序号}`：显式打开正文后标为已读。重复已读返回 `updated:false`，不存在返回 404。

接口沿用面板专用 Bearer、精确 Host/Origin 和请求体限制，不能指定其他身份、平台路由或执行命令。正文以纯文本显示，最多 8192 字节并明确标记截断。已读只表示操作者打开过正文，不作为授权、业务完成或平台送达证据。

## 持久化与崩溃窗口

状态目录保存 `web-notifications/state.json`、不删除的独占锁文件和外部初始化标记 `web-notifications.initialized.v1`。每次提交先写同目录临时文件、同步文件、原子替换并同步目录；句柄存活期间独占目录。备份时须与任务、触发器及各自冷正文在同一停机窗口一起备份。恢复不能只回退其中一份账本。

每条通知有稳定来源、事件摘要和单调显示序号。任务事件包含完整 owner、任务 ID、创建与结束批次；结束时间下界 `TaskExecution.last_finished_at_ms` 在接续中保留，保证同毫秒完成或时钟回拨不会复用上一批次。触发事件包含完整 owner、触发器 ID 与周期，进度事件使用任务账本的递增序号。

提交顺序如下：

1. 收件箱原子保存正文、去重事件和待结算动作。
2. 任务账本以完整身份和结束批次比较，写入 `LocalInbox` / `StoredLocally`；触发器按身份与周期写入 `StoredLocally`。进度使用独立序号结算。
3. 收件箱将待结算标为已记录。

两份账本不是同一事务。中途退出后先恢复已保存待结算动作；专用本地接口接受同一事件重复结算，不经过平台 `Sending`，不会因重启把已存通知误变为未知发送。旧任务已接续或旧触发周期已推进时，旧记录保留并记为被新批次取代，不能结算新的执行。平台发送中或未知结果不会被本地回执覆盖，也不伪造平台消息 ID。触发器本地保存已了结后可以推进下个有限周期，错过的周期不补跑。

收件箱最多保留 2048 条正文，容量不足时仅移出最早的已读且已结算记录，未读和待结算不静默丢弃。仍存在的任务/触发器保留去重事件，防止已读清理后旧通知再次出现；去重事件最多 65536 个，总编码最多 32 MiB。容量耗尽返回独立的 `Capacity`，已有通知仍可读取和确认已读，宿主保留业务运行并稍后再试；未入箱事件不提前结算。磁盘提交失败与容量不足分开处理；读取坏数据、初始化后目录或文件缺失、重复键、未知结构、身份/序号不一致均拒绝打开，保留原文件，不自动清空。存储提交失败后实例关闭写入，须重新打开核对实际落盘状态。

浏览器退出清除令牌和当前通知视图；再次登录重新读取服务端记录。关闭浏览器不会撤销任务、确认完成、清空未读，或自动把消息标为已读。
