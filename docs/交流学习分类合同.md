# 交流学习分类合同

交流学习的 `assessment` 决定宿主如何处理原则与证据，不能只看返回了新文字或 `saved=1` 就认为经验已有效更新。

此前合成案例 C 中，真人明确要求修改旧接话方式，并保留适用条件。两份真实模型输出都写出了条件化的新原则，却选择 `counterexample`。宿主按既有合同增加反例、停用旧经验，保留旧正文；新文字没有进入有效经验投影。原提示对“明确纠正”和“反对旧表达”的定义重叠，这是本次澄清的直接问题，不是存储丢字或并发更新失败。

三类处理含义如下：

- `observation`：至少两条独立真人消息支持的弱观察；不把送达、沉默或旧经验复述当新支持。
- `correction`：真人在对应 Eve 发言之后明确肯定，或给出有原文依据的替代方式、适用条件修订。同一反馈既否定旧做法又支持可采用的修订时，沿用原 `lesson_id`，输出完整修订原则，保留未被否定且仍适用的内容。
- `counterexample`：真人明确反对已有原则产生的表达，但证据尚不足以支持替代或条件修订。它记录反例并停用旧经验，不应用新正文；按现有格式保留所指旧原则文字。不能把模型自行想出的替代当真人认可，也不把所有反对强制改成 `correction`。

证据门槛保持不变：纠正与反例都须引用对应 Eve 发言及其后的直接真人反馈。每个 draft 中同一 `message_id` 最多出现一次，即使 quote 不同也不能重复；每项 quote 是一个连续逐字片段。完整原消息仍供理解多个要点，无需为每个子句重复列证据。此前案例 B 的一份输出正是因为重复引用同一消息 ID 被拒绝，宿主不会静默去重或放宽来源校验。
