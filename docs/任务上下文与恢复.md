# 任务上下文与恢复

`dispatch_background_task` 与 `run_subagent` 增加可选布尔参数 `include_context`，默认 `false`。开启后，宿主捕获当前工具批次执行前、经过既有历史窗口和压缩策略处理的完整模型消息：系统背景、记忆、摘要、当前输入及此前工具回执。不会重新读取窗口外原文，也不会包含当前尚未执行批次的调用或后来收到的消息。

快照与可信会话、用户绑定，模型不能直接提供正文或身份。接收者将它作为历史 JSON 数据阅读，系统指令、工具集合、可信身份及每次工具鉴权仍独立装配；历史工具调用不会执行。后台任务先将快照与任务原子持久化再返回成功，排队、重启不会改用最新对话。列表只返回是否携带，不展示快照正文。单份快照上限 2 MiB，账本总上限仍为 4 MiB；超限明确拒绝，不截断或静默关闭共享。

账本读取旧版 v1，首次新写入升级为 v2。旧程序遇到 v2 必须拒绝打开；不能直接将已有新账本交给旧二进制。损坏或未知格式不清空、不降级。迁移和回滚须同时保留匹配的二进制和状态副本，不能用旧快照覆盖上线后已产生的任务、命令或发送回执。

复杂工作应善用后台任务和子代理：短而独立的核查可并行，有依赖的先等待实际结果；耗时完整任务派到后台，必要时由主会话订阅 `task_finished` 接续验收。执行者不递归编排，预算与并发上限均保持原配置。

新后台任务默认自动恢复：在模型请求前、工具执行前后与最终结果产生后持久化检查点，保存工具回执、已用预算和 task_progress。安全边界上的重启及临时网络、超时、5xx、429 故障合计最多自动恢复 3 次，等待 2/4/8 秒，沿用首次执行的总期限与剩余步数。执行中的旧任务没有检查点，不能凭空恢复；旧排队任务首次在新版开始时会启用检查点。

工具批次尚在执行、工具超时/取消/执行异常或发送结果不明时，不自动重放；已明确取消、权限撤销和不可重试错误也不接续。最终结果已存入检查点而任务结局尚未提交时，启动直接提交完成及通知，不再请求模型。通知投递仍沿用原有未知结果不重发的语义。更多边界见[后台任务与子代理](./后台任务与子代理.md)。

工作区 `list_files`、`read_file`、`search_files` 的只读读取失败返回已确认无业务副作用的拒绝，模型可以根据错误纠正路径或输入；不再把“搜索目标是文件而非目录”等错误当作写操作结果未知。取消、超时及修改文件、执行命令的异常仍保持停止保护，旧失败任务不会因此自动重跑。

后台任务和子代理的模型请求照常在 150k 上下文触发压缩，恢复检查点另行保留完整调用与回执，不能用模型请求里的摘要覆盖历史批次。恢复时从完整日志核对原步数并重新构造请求，完成操作不重放。单份检查点的 2 MiB 和任务账本的 4 MiB 容量保持不变，达到真实容量仍明确停止，不静默丢弃数据。

后台新任务默认最大允许 5000 次工具调用，未指定步数使用默认 100 次，前台每轮为 100 次；并发、期限和显式批准的既有任务预算不变。旧任务继续使用创建时批准的预算。新旧文档格式相同，但旧二进制只接受最多 500 步的任务；已有 5000 步任务时回滚必须使用匹配版本和备份，不能让旧程序清空或强行降级新账本。

## 只读任务目录与定向装载

可信宿主可以用 `TaskAdmin::summaries_for(owner)` 读取完整身份匹配的轻量目录；目录含标题、原始任务说明、状态与创建时间，不携带委派上下文、检查点正文、结果或通知回执。`get_owned(owner, id)` 只恢复一条完整任务，未知 ID 和其他身份的任务均不返回；这两个方法不创建任务、重领预算或改写状态。原 `snapshot()` 保留完整管理语义，可替换后端的默认实现仍走兼容完整快照。

内置后台任务插件在锁内先按身份/ID 过滤再复制。分层工作集先用目录排序，再读取实际选中的任务，保持约束原话、Unknown 调用、原预算和绝对授权期限；两次读取之间已结束任务可能依原容量策略移出，此时不伪造旧记录。按 `task:` 引用读取和执行日志恢复也走定向读取；执行日志直接移动已读取任务中的检查点，不再额外复制一份。全局派发/通知管理仍使用原接口，尚未改造为冷任务账本或整机恒定内存。
