# QQ 官方协议来源

Eve 使用独立持久发送账本和所有权控制。本次按腾讯官方
[qqbot-nodejs 1.0.5](https://github.com/tencent-connect/qqbot-nodejs/releases/tag/1.0.5)
更新协议；固定上游提交为 `429a0f1b798f3b0fcef3679e207dbc0469a1df2d`。
`adapters/qq/official/upstream.json` 记录来源、保留的 MIT 许可与本地适配。
官方纯路由模块直接保存在源码中，无运行时下载。

认证使用 `https://bots.qq.com`，API 使用 `https://api.sgroup.qq.com`，网关发现使用
`/gateway`。认证、普通 API 和上传分别使用 10、30、120 秒期限。
文件上传发送经过清理的文件名，不暴露本机完整路径。

网关 4004 会刷新凭据再连接；4008 至少冷却 60 秒。 快速 READY
后断连也累计退避，连续三次快速断连采用平台冷却。 明确的 HTTP 鉴权拒绝会使下一次发送尝试刷新凭据。
22009 和 HTTP 429 归为限流，遵守有界 `Retry-After`。 40034031
暂无已核实的官方释义，仍保留平台失败事实。

发送仍由 Eve 的账本串行处理同一会话：第一条未成功就保持屏障， 超时重试沿用原动作、正文、平台消息 ID
和序号。 不会采用官方示例中的随机新序号来重试，也不会在被动回复失败后擅自改成主动发送。
永久失败或尚未尝试的等待项可通过手机队列接口明确取消；取消保留原件，
不表示平台送达。进行中和送达未知的动作不能取消。

本次更新接入选定的官方路由与协议规则，并未安装整个 OpenClaw 插件。
入站引用兼容原生引用字段和历史文字标记，旧日志恢复保持原身份与原件不变。

群全量消息 `GROUP_MESSAGE_CREATE` 的 `mentions` 中，只有明确的 `scope: "single"` 且 `is_you: true`
才补充为单独 @Eve 的提醒。 `GROUP_AT_MESSAGE_CREATE`
和私聊继续提醒，@全体、其他人的提及和正文中的名字不推断为提醒。
补充判断仅作用于可再生手机视图，不改历史入站原件、消息身份或部署通知边界摘要；
已读水位、静音和通知分页仍生效，系统已接管的模型指令不重新亮屏。

## 新文字消息使用 Markdown

按主人要求，新准入且不带附件的文字动作固定 `format: markdown`，发送
`msg_type: 2, markdown: { content }`，正文不删改或截断。 依据上述固定官方 SDK 的
`src/protocol/api/messages.ts`：Markdown 不带 `message_reference`；被动回复的 `msg_id/msg_seq` 或
`event_id` 不变。 本机引用事实仍记录，不伪造 QQ 的引用展示；新 Markdown 消息可能没有原来的引用卡片。

格式在准入时持久化并参与指纹。旧账本没有 format 的动作仍按纯文本解释，
重入和超时尝试不会改格式或序号，不迁移既有动作；附件维持媒体类型7。 平台不允许 Markdown
时保留真实失败，不自动降级纯文本、换序号或主动重发。 Markdown
权限和实际客户端渲染需要平台实证；本地协议测试不代表已开通或送达。
