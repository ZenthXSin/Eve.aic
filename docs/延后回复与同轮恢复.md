# 延后回复与同轮恢复

模型临时超时、网络连接失败或返回 HTTP 408、429、500、502、503、504 时，宿主可以保留当前轮次，稍后继续请求模型。Eve 已经得到的源码、命令结果和发送回执仍在同一上下文里，工具执行和模型请求计数不会重置。它可以在有结果后给出完整回答；等待本身不生成“收到”“处理中”等消息，表达内容和是否发言仍由 Eve 决定。

这是完整响应模式的接续。HTTP 使用 SSE 接收时，也必须完整解析响应后才把工具调用交给运行时；对外公开文字增量的 Stream 模式不启用这层重试，避免把已展示的半段回复重复展示。HTTP 400、401、403、402、协议错误、配置错误、工具执行错误不属于临时模型故障，不盲目重试。

`runtime.deferred_reply` 在启动时捕获，默认关闭；正式部署可设置 `EVE_DEFERRED_REPLY_ENABLED=true` 开启。配置页面保存时标记需要重启，不能声称在途任务已经采用新设置。

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| `enabled` | `false` | 启用同轮延后接续 |
| `max_retries` | `3` | 整轮共享的额外请求次数，成功执行一个工具批次后也不重置 |
| `initial_delay_ms` | `5000` | 首次等待，后续按倍数增长 |
| `max_delay_ms` | `30000` | 单次等待上限 |
| `recovery_window_ms` | `600000` | 首次可恢复失败之后，等待与额外请求的总期限 |

其余环境变量分别为 `EVE_DEFERRED_REPLY_MAX_RETRIES`、`EVE_DEFERRED_REPLY_INITIAL_DELAY_MS`、`EVE_DEFERRED_REPLY_MAX_DELAY_MS`、`EVE_DEFERRED_REPLY_WINDOW_MS`。这些限制与每次模型请求自身的超时、现有工具额度同时生效。恢复窗口用尽时中止等待中的模型请求；恢复成功后正常业务工具不受这一网络恢复窗口限制，但再次网络失败仍使用最初的恢复截止和剩余次数。内层传输重试仍共用单次请求期限；需要每次 HTTP 尝试都计入同轮额度时，可显式关闭 `EVE_OPENAI_TRANSIENT_RETRIES`。

等待不占用模型的并发槽。取消或通道关闭可结束退避；同会话的新输入照常接收、保存并合并，在下一次模型请求前消费，新的授权限制先于后续工具执行。不会为了重试把旧输入重新登记为一条用户原文，也不会执行已经完成的工具或自动重发已经投递的消息。

普通对话的这段退避保存在正在运行的轮次中，不是跨进程的定时任务。进程重启后沿用会话和 QQ 回执既有的中断语义，保留原记录，不自动重放结果未知的操作；已经正常完成的轮次和已确认发送的消息不会重复执行或投递。带 `TurnJournal` 的后台任务继续由自己的持久检查点恢复器处理，不叠加这一层重试。重试耗尽后仍保存原来的失败类型和工具证据，由已有失败处理链处理。

诊断事件 `EVE_DEFERRED_REPLY` 只记录重试序号、等待时间、轮次、已确认工具数、模型请求数和 HTTP 状态，不输出凭据、请求正文或工具结果。`deferred_reply_test.py` 通过真实 Eve 进程注入服务繁忙、超时和中途补充，验证完整回复、命令只执行一次、发送回执不重放、重试耗尽与参数拒绝；运行时测试另核对恢复总期限、跨批次计数和取消。

群聊长轮合入新输入后，显式回复使用该真实入站消息的独立窗口，仍归入原轮回执。窗口保留、额度、重启与拒发原因见[群聊长轮回复窗口](./群聊长轮回复窗口.md)。模型恢复成功与消息送达是两个独立事实，必须分别核对。
