# 手机设备与附件

手机仍只显示预览。`open` 持久推进本机会话的通知水位，未展示的历史不冒充读过；`history`、`search`、`message`、附件读取不推进这个水位。

`phone.settings({conversationId, muted?, pinned?, draft?})` 只修改明确提供的字段，省略字段时读取。免打扰屏蔽该会话亮屏与未读通知标记，不删除消息；置顶会话先显示，内部按最近消息排序，游标继续沿置顶和非置顶两段翻页。草稿最多 65536 字节，留在设备里，发送须另行明确调用。会话列表只显示 `hasDraft`，不会把全部草稿带入上下文。设备设置追加记录、带校验链，独立于手机 worker 保存，重启和插件回滚不会清空。

`phone.download({handle,index})` 才开始下载附件。资源地址和平台签名不交给模型，仅从收到该消息的原始事件定位；下载只跟随平台资源域名的 HTTPS 跳转。平台没给地址、拒绝请求、链接过期都明确报错。下载流式写入独立设备存储，完成且同步后保存路径、实际大小、SHA-256 和发件人/会话/消息/附件的来源。完整回执保存后复用原件，不擅自重复下载；损坏或孤立文件保留现场并拒绝假称成功。下载不设置总文件大小限额，连接有期限。

`phone.file({handle,index,offsetBytes?,limitBytes?,encoding?})` 读取附件的一页，单页最多 65536 字节，支持 `utf8` 和 `base64`；返回原下载来源、哈希及下一页位置。不需要把设备下载目录开放给普通工作空间。

`phone.image({handle,index,mode?})` 下载后检查真实文件签名，支持 PNG、JPEG、GIF、WebP。Eve 可自由选择两条链路：默认 `mode:"describe"`，手机插件把原图交给相同配置的模型做一次独立客观描述，再仅返回 `{selectedMode:"describe",description,provenance,download}`；明确选择 `mode:"original"` 则直接返回 `{selectedMode:"original",image,provenance,download}`，原图进入 Eve 的本轮图像输入，不调用描述服务。描述请求按来源与内容哈希持久去重，描述失败时报错，不自动切换为原图。生产设置 `phone.describeImages:true` 强制依赖默认描述服务，不禁用 Eve 明确选择原图。单图最多 8 MiB；更大的原件仍下载保留，可由 Eve 明确缩放后再用。两路实际模型费用计入同一份共享预算，不能从文件字节数伪造 token 花费。（2026-11-12 用户最新决议：两路任选，默认描述。）

`phone.sendFile({conversationId,path,kind,text?})` 支持本机图片或文件，统一主动发送。脚本宿主提供稳定动作编号，先保存动作，再上传取得平台 `file_info`，最后提交媒体消息。上传使用 `srv_send_msg:false`，上传阶段超时尚未提交消息，记为 failed/attempted:false 并按序重试。只有消息编号才表示 `sent`，缺回执、审核或断线保留 `unknown`，同动作不重复上传/发送。平台不支持某种文件时保留真实拒绝。语音/视频转写没有启用。

适配器不能以 root 身份读取任意发送路径。组合层配置 `qq.mediaRoots`、`qq.mediaIdentity:{uid,gid}` 和可选 `qq.mediaRuntime:{denoBinary,workerPath,cacheDirectory}`，通过独立非 root 子进程完成实际读取，清除组和 capabilities，读权限只授予工作目录。缺配置时拒绝本机文件上传，文字发送仍可用。上传完整文件读取默认 20 MiB、最多 32 MiB；超过时明确拒绝。自身下载目录只允许已保存完整回执、哈希仍一致的原件转发。QQ 进程因此需要启动低权限子进程的 `--allow-run` 权限。

所有设备、下载、图像、文件浏览和发送 RPC 均经过独立所有权出口；交接后旧号码不能改草稿、下载、消费消息或发送附件。

`phone.connectionFile` 指向公开的 `{phone:{adapterUrl}}` 文件。适配器独立重启换端口后，运行中的手机 worker 每次调用重新读取地址，网络权限限于 `127.0.0.1`，URL仍严格验证协议、路径和无凭据。公开文件只能更新接入点，不能覆盖实例私有桥接密钥或主人身份映射。无需重启在线意识流即可恢复连接。

附件 `index` 与屏幕显示一致，从 1 开始；直接把 `message.attachments[n].index` 传给 `download`、`image` 或 `file`。

首次投运可显式启用 `qq.captureActivationBoundary:true`，默认关闭。独立适配器在入站原件恢复、进入 connecting 后，开放 RPC 前，用实际手机时间线捕获 `${qqDirectory}/activation-boundary.json`，形状为 `{schema:1,capturedAt,throughSeq,count,notificationCount,digest}`。`count` 包括快照内全部入站/出站条目，`notificationCount` 仅计其中带 notify 事实的条目，不表示未读；`digest` 只对该边界前的 `seq/key/conversationId/notify` 元信息做指纹，不输出旧正文、图片或回执内容。新脑仅从此 `throughSeq` 开始接收新通知，不导入上线前聊天经历。边界不修改真实已读/免打扰/草稿、不删除入站/出站；她之后仍能主动翻阅。首次保存后，适配器重启只核对原边界、不前移；损坏或未完成提交保留原件并报错，不猜一个新的边界。
