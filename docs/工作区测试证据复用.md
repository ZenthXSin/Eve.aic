# 工作区测试证据复用

本次增加一种显式验收合同：`workspace_node_test`。它用于已有工作目录中的小型纯 JavaScript 测试，采用实际冻结输入上的运行回执，并在子代理收尾时重新读取目录确认输入仍匹配。测试之后的只读查询或进度登记不再因为处于最后一个工具批次而要求重复运行测试。

这是已完成本地验证、尚未上线的候选实现说明。回归与真实宿主进程的结果如下；模型及 QQ 为本地确定性替身，不能当作真实模型自主选择或线上效果。该功能不证明聊天表达、蒸馏效果、线上 QQ 送达、部署或整个用户目标已经完成。

## 启用与使用范围

只有可信宿主完整配置运行时并装配实际开发后端时，才注册 `run_workspace_node_test` 工具，并为 `run_subagent` 的 `verification` 增加新合同入口。四项配置全部不存在时保持关闭；缺项、空值、非法路径、摘要失配或后端缺失明确报错，不静默降级为宿主命令，也不下载运行时或依赖。

| 环境变量 | 含义 |
| --- | --- |
| `EVE_WORKSPACE_NODE_ROOTFS` | 可信宿主提供的完整 Node 运行时目录，使用宿主绝对路径。 |
| `EVE_WORKSPACE_NODE_ROOTFS_SHA256` | `FrozenNodeRuntime::bundle_sha256` 定义的运行时结构摘要，包含指定 Node 相对路径、目录、文件字节与执行位；不是压缩包文件的普通 SHA256。 |
| `EVE_WORKSPACE_NODE_BINARY` | 运行时目录内 Node 的普通相对路径，例如 `runtime/node`。不能由待测项目选择。 |
| `EVE_WORKSPACE_NODE_BWRAP` | 可信 bubblewrap 启动器的宿主绝对路径。 |

宿主启动时完整复制并核对运行时，将发布源、私有运行时快照、启动器和宿主可执行文件加入开发工具的受保护路径。每次执行仍核对固定运行时及启动器身份。受保护路径约束直接文件工具；主人获准执行的宿主命令仍有原有权限，这不是面向宿主管理员的文件系统隔离，也不能宣称消除了宿主写入与启动之间的全部竞争。沙箱使用私有输入和运行时，不挂载待测目录的实时内容，不提供网络或工具 RPC。首版仅支持已核对的 Linux x86_64/aarch64 路径；Node 权限策略关闭原生插件、额外进程、worker 与 WASI。所有依赖必须随输入提供。

新合同只接通本轮同步子代理的执行与收尾。普通后台任务入口仍不接受该合同，不能用它替换后台的旧合同或把未知后台结果改成完成。直接调用测试工具会产生真实回执，但不会凭一次工具成功自动把主线程或其他任务标为完成。

## 模型参数与宿主冻结

派发时 `verification` 只填写以下对象，目录和入口均相对当前身份实际工作区：

```json
{
  "kind": "workspace_node_test",
  "directory": "project",
  "entry": "test.cjs",
  "args": []
}
```

`directory` 默认 `.`，`args` 默认空数组，`entry` 必填且扩展名为 `.js`、`.cjs` 或 `.mjs`。不接受绝对路径、父目录跳转、非规范路径或身份与摘要字段。参数最多 16 项、合计 4096 字节，不含 NUL。所选目录在派发时必须已存在；测试入口可以由子代理随后创建。

宿主先核对可信开发后端返回的真实身份、工作区根目录和所选目录，冻结工作区身份摘要、目录、入口、参数、运行时摘要与命令策略摘要。此时没有把尚未完成的源码固定成验收目标，也不构造空文件来伪装预注册输入。模型不能自行填写这些摘要，更不能通过 JSON 赋予回执可信来源。

执行工具使用对应选择器：

```json
{
  "directory": "project",
  "entry": "test.cjs",
  "args": []
}
```

工具名为 `run_workspace_node_test`。每次明确调用都先采集当时的完整目录输入，再交给真实冻结运行器。执行不是 `npm test`、自动依赖安装或通用构建；需要完整系统环境、原生扩展、网络或写入源码的测试不属于本子集。沙箱输入只读，临时写入仅允许 `/tmp`。

## 输入范围与有效性

开发后端以当前真实身份和原执行上下文采集输入，重复检查文件读取权限、取消与期限。文件描述符锚定、元数据复核和两次完整扫描用于发现可观察的并发变化；它们不提供整个活工作区统一的原子时点。采集异常或无法证明完整时拒绝，不接受裁剪视图。

测试输入包含选定目录树的全部普通文件、空目录、路径和执行位。`.git`、`.eve-developer` 管理元数据明确排除，沙箱也无法读取它们；凭据或其他受保护路径不是静默排除以继续执行，而是拒绝采集。符号链接、设备、套接字等特殊对象不支持。

开发快照和测试 bundle 有各自的容量限制。实际测试最多接受 64 个文件、8 MiB 文件字节与 4096 个目录树条目；上游采集即使容许更多内容，运行器仍整体拒绝超限输入，不截断为可通过的小包。

有效性使用**整个选定输入树**的摘要。新增、删除或修改文件、空目录或执行位均会改变摘要。只有目录树之外的变化，以及明确排除且运行不可见的管理元数据变化，不进入该测试输入。首版没有源码依赖影响分析；即使人判断选定树内某文件与测试无关，它仍使旧证据失效。可以选择恰当的实际项目子目录来限定目标，不能在采集时随意忽略不利于匹配的文件。

三个摘要不能混用：

- 工作区身份摘要绑定可信身份、实际工作区根目录与所选目录，区分来源。
- 开发快照摘要描述采集视图及排除说明，不作为运行器输入摘要直接使用。
- 测试输入摘要由实际传给运行器的完整 bundle 计算；收尾使用相同转换重新计算，确认与真实运行字节一致。

旧 `FrozenNodeTestBundle::new(files)` 的摘要与旧合同语义保留。新目录输入使用独立摘要域，显式保留空目录与执行位；沙箱落盘也恢复相同执行位，避免摘要描述与实际运行内容脱节。

## 真实回执、收尾与复用

执行回执记录原身份、模型会话、调用编号、参数与工具结果摘要、实际输入、运行时、命令策略和真实退出状态。可信见证只来自适配器持有的 `FrozenNodeTestReceipt`，不通过解析模型输出里的 `exit_code`、`verified` 或成功文字产生。检查点保存时将匹配的见证写入持久子代理记录。 工具执行的模型请求序号与整轮检查点序号可以不同；宿主按同一真实身份、会话、子任务和轮次关联原调用，再核对参数与完整结果摘要。仅此关联忽略请求序号，原请求及运行回执的身份仍保留，不能借此跨轮、跨子任务或换调用编号复用。

子代理交回候选结果后，宿主沿用原身份、取消状态、共享预算和期限，仅重新读取同一目录并形成 `WorkspaceObservation`。观察绑定最终检查点摘要和宿主观察时间，不启动 Node。随后以冻结合同、真实历史见证和该次当前观察判断：

| 情况 | 结果 |
| --- | --- |
| 同一目标最近一次真实测试成功，最终观察输入一致 | 该测试合同可通过，无须让测试位于最后工具批次。 |
| 成功后只读日志、读取文件或登记进度，实际输入未变 | 原回执可复用。 |
| 最近匹配测试非零退出，或最终输入已变化 | 合同失配，不能借用更早成功。 |
| 没有真实见证、缺少当前观察、观察不可读取或检查点不符 | 保留待核验，不升级模型自述。 |
| 某次测试结果未知或取消 | 保留未知或取消，不借旧成功掩盖，不自动重放。 |

命令退出为零只证明这个完整冻结输入在固定运行策略下的测试结果。测试断言是否充分覆盖实际需求仍需判断，合同通过不能被扩大为部署完成、文件送达或其他未覆盖交付。

同一原调用在适配器和运行器实例内只准入一次。采集失败、取消、执行未知或 future 丢弃不退还该调用的重放资格。后续明确发起的新测试仍受原任务权限、资源与停止机制约束；证据复用不发放新预算。当前适配器和运行器单实例各累计最多 1024 次准入，失败与取消也占位，尚无安全回收机制；到达上限明确拒绝新测试。该限制仍需后续改进，不能称为无限期可用。

## 持久化、历史读取与回退

子代理 SQLite 记录保存冻结合同、检查点、真实见证、收尾观察与原结局。主线程可直接引用子代理交回的同份历史证据；只读查询不重跑测试、不恢复中断执行，也不重新核对当前磁盘。历史观察仅证明记录时间的匹配，后来读取不能把它改写成当前版本仍有效。

旧 `receipts` 合同继续保留原有 `require_final_batch` 语义，`text` 和预注册 `frozen_node_test` 也不被静默改成新模式。现有任务不会批量迁移为已完成；新合同只能在显式入口且具备可信运行能力时建立。

停用四项运行时配置会使新工具和派发入口关闭，但不删除 SQLite 中的新合同与证据。支持新 tag 的当前二进制仍可以保留并只读呈现历史记录。

若回退到不认识 `workspace_node_test` tag 的旧二进制，相关记录反序列化可能失败，旧程序并不因此具备读取新合同的兼容能力。应保留数据库及回退前证据，不删除新记录、不把 tag 改成旧合同、不自动重放外部操作。恢复支持该 tag 的二进制后再读取与处理待核验记录；不能通过清空历史来掩盖降级错误。底层存储版本并不等于合同枚举向旧程序兼容。

## 本批验证状态

本批使用真实 Node、bubblewrap、SQLite 和 Eve QQ 宿主验证；没有调用外部模型或线上 QQ。各过滤测试存在交叉，不累加为独立用例总数。初次失败日志保留：目录深度栈溢出、执行位测试夹具误判以及实际宿主的请求序号错绑均定位并修复。

| 覆盖项 | 实际结果 |
| --- | --- |
| 目录完整采集、二进制、空目录、执行位、取消、权限撤销与并发变化 | 工作区快照 10 项通过；最终开发后端全部 84 项回归通过，包含保护集合与宿主候选流程。 |
| 真实 Node、私有运行时、输出、隔离、取消、未知与共享预算 | 原运行器 15 项真实进程回归、新输入及结算 4 项单元测试通过。 |
| 最后批次不强制、伪回执拒绝、旧合同、后台拒绝和源码变化 | 合同 8 项通过；应用工作区 16 项通过。 |
| SQLite 原子保存、旧记录、重开、错误观察、预算与取消 | 子代理记录 31 项回归通过。 |
| 工具实际请求序号与整轮检查点不同 | 2 项适配器测试通过，覆盖请求 2 对检查点 1；跨轮与跨子任务仍拒绝。 |
| QQ 宿主正常实现、测试、后续读取、主线程直接发送 | 实际进程通过：主线程 3 次、子代理 4 次本地请求，Node 仅执行 1 次；收尾输入与原测试相同。 |
| 测试成功后修改源码 | 实际进程通过：仍只有 1 次 Node，回执保留，收尾返回 `workspace_changed_since_test`。 |
| 同状态重启且停用运行时 | 实际进程通过：原记录和返回证据相同，Node 累计仍为 1 次；历史当前有效性仍为 `not_checked`。 |
| 未配置运行时 | 实际进程通过：不展示工具及合同，拒绝派发。 |

正常、源码变化和未配置共三种场景，含成功场景的重启共四个宿主进程，19 次本地供应者请求。两项修复后进程测试合计 8.087 秒，包含三个宿主的启动和退出；未配置场景复用首轮已通过结果。没有相同目标的旧版端到端耗时基准，不能据此承诺提速比例。只证明本场景没有重复 Node 测试，不证明真实模型以后都自行选择此路径。

进度登记后复用由合同及 SQLite 测试覆盖；实际宿主场景测试后使用读取文件。取消恰好落在收尾观察返回附近的竞争只有源码核对及分层测试，未用独立进程专门注入。旧二进制不认识新 tag 的完整降级启动未执行，保持前述读取限制；不把停用配置后的新二进制读取说成旧版兼容。

新增宿主进程测试已接入 Stable、QQ 工作流及 Debian 发布验收列表。本机使用 Rust 1.99.1，仓库 CI 的 Rust 1.95.0 结果另行记录，不能相互替代。

本次不自动部署候选、不修改在线运行时配置、不扩大个人资料投影，也不把一个小型 JS 测试的证据复用推广为所有语言、所有工作区或所有后台任务均已消除重复验收。
