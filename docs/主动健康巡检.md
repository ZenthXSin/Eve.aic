# 主动健康巡检

开启 `--health-watch` 后，QQ 宿主在通道空闲时检查本地状态，默认至少间隔 30 秒。检查不请求模型、不增加模型额度，不需要每轮重新开启。模型可用 `inspect_runtime_health` 读取已保存的发现和通知状态，再结合日志、代码及现有工具自行核验和修复。

当前检查范围：模型用途连续失败至少 3 次、状态盘可用空间不足 2 GiB 或不足 5%、交流未保存、回执容量拒绝、自主预算耗尽或不可读、QQ 终止错误。模型刚启动未请求不算失败；历史失败恢复后不继续报错。磁盘余量使用 Unix 的只读系统接口，非 Unix 平台省略该检查。阈值由宿主环境 `EVE_HEALTH_CHECK_MS`、`EVE_HEALTH_MIN_FREE_BYTES` 配置，不接受模型传入。

同一问题持续出现只通知一次；恢复后再次出现才形成新事件。只向宿主绑定的主人已有会话通知，优先私聊，无私聊则原群艾特对应主人；昵称或管理员身份不能成为主人路由。尚无主人路由时保留待发记录，不凭空选择收件人。普通成员不能查询宿主健康记录。

定义层为 `Finding`、`HealthSource`；独立实现 `HealthWatch` 保存巡检与投递状态；QQ 组合层读取宿主统计并完成路由。健康账本 `health-watch.json` 格式 1，先原子保存发送状态再交给通道；中断时发送结果记为未知、不重发，坏数据不清空。最多保留 128 次通知，满时只淘汰最早已明确送达或失败的记录；待发及未知不静默丢失。达到容量后保留记录并返回错误。

巡检只报告已知异常，不自动删除文件、增加预算或重跑失败命令。进程完全退出时由现有监督器与服务管理器恢复；本组件不能在自身已停止时发送通知。需要用户选择的修复遵循先问一次原则。
