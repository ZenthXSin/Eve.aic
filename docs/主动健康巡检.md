# 主动健康巡检

开启 `--health-watch` 后，QQ 宿主在通道空闲时检查本地状态，默认至少间隔 30 秒。检查不请求模型、不增加模型额度，不需要每轮重新开启。模型可用 `inspect_runtime_health` 读取已保存的发现和通知状态，再结合日志、代码及现有工具自行核验和修复。

当前检查范围：模型用途连续失败至少 3 次、状态盘可用空间不足 2 GiB 或不足 5%、交流未保存、回执容量拒绝、自主预算耗尽或不可读、QQ 终止错误。模型刚启动未请求不算失败；已确认恢复的历史故障不再作为待发事件。磁盘余量使用 Unix 的只读系统接口，非 Unix 平台省略该检查。阈值由宿主环境 `EVE_HEALTH_CHECK_MS`、`EVE_HEALTH_MIN_FREE_BYTES` 配置，不接受模型传入。

同一问题持续出现只通知一次；恢复后再次出现才形成新事件。一个事件中的问题分别结算：例如 A、B 同时异常，A 恢复后只保留 B 为候选，原始发现和 A 的恢复记录仍在；A 复发时得到新的事件编号，旧事件里的 A 不会重新激活。候选在认领和沉默时原子核对事实，生成回复期间发生部分恢复或转为未知时，旧候选不能占用变化后的事件。候选版本只随事实变化，不随巡检时钟或持续失败次数改变。

只向宿主绑定的主人已有会话通知，优先私聊，无私聊则原群艾特对应主人；昵称或管理员身份不能成为主人路由。尚无主人路由时保留待处理记录，不凭空选择收件人；后续确认恢复仍正常退役。普通成员不能查询宿主健康记录。

定义层为 `Finding`、`Observation`、`HealthSource` 和 `NoticeCandidate`；独立实现 `HealthWatch` 保存事件与投递状态；QQ 组合层读取宿主统计并完成路由。`HealthSource::observe(previous, checked_at_ms)` 的默认实现沿用完整 `inspect`，有缺失探针或进程内计数的替换实现应显式返回 `unknown`。`recovered` 可以与当前异常重叠，用来区分两次检查之间已成功、随后又达到失败阈值的新事件。

`active` 是最近巡检确认的异常；`unknown` 保存尚无有效恢复观测的旧问题，不能独自触发发言。宿主首次检查忽略上个进程的检查间隔，先实际观测再生成候选。模型计数重启清零、刚登记而尚未请求、未成功且只有一两次新失败，都不算恢复。记录到实际成功后才结束旧模型事件；如果成功后又连续失败至少三次，则同时结束前任并创建新事件。交流、回执和通道的进程内计数缺失或清零也保留为未知。磁盘读取失败不能据此结束旧的空间不足事件；预算读取失败不能据此结束旧的额度耗尽事件。

健康账本 `health-watch.json` 写入格式 3，兼容读取格式 1、2。每条通知保留原始 `findings`，增加逐项 `resolutions: [{code, at_ms, reason}]`；实际恢复的原因是 `{"kind":"recovered"}`，旧格式中已有同类后继事件时记为 `{"kind":"superseded","notice_id":"health-N"}`。后者证明前任已经被替代，不声称中间曾有成功观测。全部项结束的 `Pending` 变为 `Retired`，保持 `owner: null`，不调用发言模型、不制造发送或沉默回执。只剩未知的 `Pending` 保留待处理状态，后续观测可以继续处理同一事件。

旧格式迁移只整理尚未认领的前任，按递增事件编号定位同类后继，写入每项替代原因；没有后继也没有恢复观测的记录不会在打开文件时被删除或当作恢复。一次检查或迁移先完整校验，再写临时文件、同步并原子替换，写失败保留旧内存和旧文件。未知格式、旧版本混入新字段、非法恢复记录或坏数据均拒绝打开，不自动清空。

发送前持久化 `Sending` 再交给通道；中断时转为投递结果 `Unknown`，不自动重发。恢复结算不修改 `Sending`、`Unknown` 或已有 `Sent`、`Failed`、`Suppressed` 回执。这里的投递 `Unknown` 与健康观测的 `unknown` 是不同事实。最多保留 128 次通知，满时可回收最早的 `Sent`、`Failed`、`Suppressed` 或 `Retired`；不能回收未结 `Pending`、`Sending` 或 `Unknown`，无可回收记录时返回错误并保留原账本。后继记录被正常回收后，前任的替代原因仍保留原编号。

格式 3 被写入后旧二进制会拒绝读取，不能手动把版本号改回 1 或 2，也不能用旧备份覆盖升级后继续产生的业务状态。恢复采用支持格式 3 的同一新二进制：必要时先以 minimal 组合保留现有状态，再恢复完整组合。健康账本不属于当前启动屏障对任务、说法和回执的精确连续性证明范围；minimal 组合未开启巡检时原样保留文件，完整组合重新开启后由本组件校验、迁移并做首次实际观测。启动屏障通过不能单独证明健康事件已经恢复或投递。

巡检只报告已知异常，不自动删除文件、增加预算或重跑失败命令。Eve 可使用现有工具读日志、查源码并开展普通修复，执行审查仅核对可信身份和操作是否直接危害系统安全。进程完全退出时由现有监督器与服务管理器恢复；本组件不能在自身已停止时发送通知。
