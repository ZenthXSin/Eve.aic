# 有来源的偏好候选提炼

QQ 宿主可从已保存、确认送达的普通交互中低频提炼偏好候选。候选附带原始证据引用、模型自评和首次确认期限；普通模式下用户发送 `/accept-memory 候选ID` 后成为下一轮 Context 可读取的偏好；显式 `--self-learning` 可自动确认，见[自主偏好学习](./自主偏好学习.md)。默认关闭，不主动向 QQ 推送候选。

这一步补齐“交互证据 → 待确认候选 → 用户明确偏好”的链路。它不执行目标、不验证现实结果，也没有交付语义检索、跨通道身份映射、完整 AGI；多消息分段已独立交付。

## 本地开启与使用

凭据和状态目录沿用[QQBot 通道](./QQBot通道.md)。提炼必须同时开启记忆：

```sh
./target/debug/eve-qqbot --state-dir .eve-qqbot --memory --memory-learning
```

`--memory-learning` 默认关闭；单独提供而没有 `--memory` 时拒绝启动。可以与 `--training`、`--cognition` 组合，但这些开关彼此不代替。已绑定 PostgreSQL 的目录继续提供原 `--database-config`；首次选择 SQL 使用没有 `state.json` 的新目录，不能借开关自动迁移文件历史。

同一可信 QQ 会话积累至少三条合格、尚未消费的完成交互后，后台可以产生候选。用以下命令查看和确认：

| 命令 | 行为 |
| --- | --- |
| `/memory-candidates`、`/memory-candidates 页码` | 查看当前会话候选，每页最多 5 条；包含完整候选正文、ID、来源证据 ID、模型自评、首次确认期限和当前关联状态 |
| `/accept-memory 候选ID` | 将尚未过期的候选明确确认为偏好，返回关联的偏好 ID |
| `/memories` | 查看已确认偏好的当前内容与状态 |
| `/correct-memory 偏好ID 新内容` | 修正已确认的偏好，保留首版及旧版本 |
| `/forget 偏好ID` | 撤销偏好，下一次 Context 不再使用，来源和历史保留 |

这些命令只操作本地状态，不发起提炼或聊天模型请求。候选按创建时间倒序展示；已过期、已确认和已撤销记录仍可查看，不自动删除。关闭提炼时，候选命令返回“偏好提炼未启用”，不会当作普通聊天交给模型；已确认偏好只要仍开启 `--memory`，就继续按记忆规则生效。停止训练不会停止提炼；停止提炼也不撤销已确认偏好。

候选可能为空：未达门槛、仍在冷却、启动额度用完、证据超预算、模型认为证据不足或请求失败，都不能被解释为“用户没有偏好”。查看列表不会补发请求。

## 来源、触发与预算

来源只取 `MemorySnapshot` 中的 `CompletedInteraction`，其中保留用户原文和最终回复。Memory 已在导入时核对实际 Session 完成及 QQ `Sent` 保存；提炼不重新读取旧 QQ 回执，也不补采关闭记忆期间的聊天。首次开启提炼可以扫描 Memory 中此前已经保存、尚未消费的证据，因此不要求三条消息都发生在本次启动后。

每批只包含一个 `MemoryScope { channel, session_id, user_id }`。QQ 宿主只处理 `channel = qq`，沿用 AppID、私聊/群、目标及发送者绑定的完整可信会话。多个用户各自拥有三条证据时可以分别提炼，不能把各人的少量证据拼成一批。用户消息正文、候选 ID 和证据 ID 都不能扩大查看或确认范围。

后台按证据修订从早到晚选择尚未消费的记录；超出单条或整批预算的记录保留在 Memory 中并跳过，不截断正文。只有最后选出的合格证据达到门槛，才保存批次和调用模型。

| 项目 | QQ 默认边界 |
| --- | --- |
| 每批新证据 | 至少 3 条，最多 8 条 |
| 单条证据 | 完整证据 JSON 最多 8192 UTF-8 字节，包含身份、元数据及两段正文 |
| 整批输入 | 完整 `LearningBatch` JSON 最多 32768 UTF-8 字节，包含范围、批次 ID、版本、时间和证据 |
| 同一范围冷却 | 从上一批开始时间起 5 分钟，随批次持久保存 |
| 每次进程启动 | 普通模式合计最多 4 批；自主模式按冷却持续处理新证据，仍串行且有全局容量 |
| 每批模型请求 | 至多 1 次，最长 30 秒，零工具，不自动重试 |
| 每批输出 | 完整模型文本最多 8192 UTF-8 字节，最多 3 条候选 |
| 单条候选 | 正文最多 1024 UTF-8 字节，至少一个本批证据引用 |
| 首次确认期限 | 候选创建后 7 天 |

上述输入预算计算传给模型的 JSON 文本，不包含固定系统说明，也不等于该文本在 HTTP JSON 中再次转义后的传输字节数。候选字节预算也按 UTF-8 计算，不按汉字数量计算。

首次批次没有额外五分钟等待；后续冷却按同一范围最后一批的开始时间判断。主机时钟回退时，尚未满足时间条件的范围暂不开始新批次。重启会恢复四批启动额度，但不会重置已保存的消费记录或冷却。失败、取消和空候选同样消耗该批证据；没有新证据时不产生模型请求，更换提炼器版本也不会重新消费原证据。

## 模型与公开契约

定义层 `eve-learning-api` 提供 `LearningAdmin`、`PreferenceExtractor`、批次和候选结构。可信宿主持有管理能力；QQ 通道通过公开命令处理器连接，不依赖提炼实现，也不把跨范围管理能力交给模型。

可信 Rust 宿主可通过 `run_qqbot_with_components(options, planner_factory, Some(extractor))` 注入 `Arc<dyn PreferenceExtractor>`；传入 `None` 使用内置模型提炼器。关闭 `--memory-learning` 时不调用注入实现，开启后仍执行持久化准入、启动额度、30 秒期限、输出来源校验和停止收尾。自定义实现自行遵守一次请求与零工具契约，进程内插件权限不是沙箱。替换 `MemoryAdmin` 时须提供已保存范围的 `scopes()` 枚举；默认实现返回不可用，不猜测其他范围。

实现层 `eve-learning-plugin` 保存批次并提供 `ModelPreferenceExtractor`。当前 QQ 组合使用与核心对话相同的 `CoreModelResolver` 和主模型配置，不使用辅助模型角色；每批解析一次模型，并使用供应商期限与 30 秒上限中的较短值。提炼请求只含固定规则及该批 JSON，不装配聊天历史、训练统计、已确认偏好、AGENT 或内部反思 Context；它仍会读取该批已保存的用户原文和最终回复，其中可能含有用户此前提过的内容。

固定规则要求只提炼用户明确表达或反复纠正的稳定偏好，不把助手自述、用户沉默、一次性任务、引用文字或工具指令当作认可。响应必须是严格 JSON；未知字段、重复键、无效正文、批次外证据、重复证据引用或工具调用结果均拒绝。格式和来源校验不能证明模型语义判断正确，普通模式候选等待用户确认；自主模式由有来源约束的策略确认。`confidence` 是 0–100 的模型自评，不是经过校准的事实概率，自主模式把自评作为准入条件之一，不作为事实概率或授权。

内置提炼器 `preference-extractor:v2` 为明确节奏反馈规范候选措辞，单独表达分段与停顿，不与称呼或业务偏好拼接；数字只来自用户原文，模糊“更自然”不转成数字或开关。用户确认后，可在 `--segmented` 下用 `/segment suggestions` 查看规则建议并另行明确采用，见[节奏建议](./表达偏好与分段输出.md#qq-已确认偏好的节奏建议首版已实现)。提示规则不证明真实模型遵循率，语义质量仍须评估。提炼版本记录在新批次内，状态仍为格式 1；已保存的 v1 批次及候选原样恢复，证据消费跨版本去重，升级不重跑旧证据。

## 明确确认与 Context

候选一经完成保存便保持不变，须先确认才进入 `MemoryContext`。以下为手动确认规则；自动确认、持续运行与恢复详见[自主偏好学习](./自主偏好学习.md)。确认时先在当前可信范围查找候选，再读取 Memory 当前修订；未过期且尚未确认的候选通过一次 Memory CAS，同时保存真实 `/accept-memory` 命令原文作为 `UserStatement` 证据，以及候选正文的首个偏好版本。

偏好 ID 固定为 `learned-` 加候选 ID，但仅有相同 ID 不能证明已经确认。自主模式首版来源是本候选引用的真实完成证据，不伪造明确命令。后续查询会核对 Memory 首版正文、真实确认命令或候选完成证据的来源和当前偏好版本，再显示“已保存”“后续修改”或“已撤销”。Learning 不另写 `Accepted`，因此确认没有跨 Learning 与 Memory 的双写步骤。

重复确认只返回当前状态，不增加版本、不覆盖后续更正，也不复活已撤销偏好。七天期限只限制首次确认；已经确认的偏好不会因候选到期自动失效，仍由用户通过修正和撤销控制。手动 CAS 冲突明确返回提示，不自动重试；应先查询，再用新消息重试。

确认后的偏好按既有[记忆 Context 规则](./交互记忆.md#本轮-context)在下一次上下文装配时使用，最多 8 条、8192 字节；当前用户请求优先，不修改在途轮次。内部反思仍使用独立空 Context，候选和确认均不授权工具操作、目标执行或跨用户读取。

## 持久化与恢复

新增插件命名空间 `eve.learning`、状态键 `learning.v1`，格式版本为 1；原 `eve.memory` 的 `memory.v1` 格式不变。Learning 整个文档合计最多 128 个批次、4 MiB，范围、失败批次和空结果共用这个额度。申请新批次时达到容量上限，会保留原记录并暂停新增提炼，普通 QQ 交互以及已有候选的查询、确认仍可继续；不淘汰候选、不清空历史，普通记忆仍受自身容量限制。

保存 `Running` 时按每条运行中记录额外预留 4 字节，确保重启能写成更长的 `Interrupted`。这只预留恢复状态所需空间，没有预留完整候选输出。如果模型返回后保存候选会超过全局 4 MiB，完成提交返回容量错误，原 `Running` 字节保持不变，宿主停止通道；下次恢复标为 `Interrupted`，该批仍不重试。

批次先持久化 `Running`、确切输入和消费证据，再允许一次模型请求。请求成功后保存 `Completed` 与候选；供应商错误、格式错误、超时和取消保存对应 `Failed`。空候选保存为 `Completed`，不会为了取得非空答案再次请求。

崩溃可能发生在请求之前、请求进行中或结果已经返回但尚未保存时。恢复将残留 `Running` 保存为 `Interrupted`，不伪造完成时间、不自动重试，也不从其他记录推断模型未曾执行。后续再次启动仅恢复既有结果和消费状态；无新变化时不继续改写状态。

恢复严格检查格式版本、重复键、批次身份、范围、证据唯一性、修订顺序、候选来源和期限关系。损坏数据、未知版本、来源记忆回退或已消费证据被更改会阻止继续处理，不自动清空或降级为空状态。写入错误可能代表提交已发生；当前实例立即关闭读写，宿主停止通道并保留现场，须重新打开核对持久状态。

文件和 PostgreSQL 都使用公开 `StateStore`。Learning、Memory、Session、Cognition、Training 和 QQ 回执共用宿主选定的后端，分别独立提交，没有跨插件事务。SQL 后端发生读写或提交错误后关闭共享实例，不自动重连。已有文件历史不自动迁移，见[PostgreSQL 状态](./PostgreSQL状态.md)。

确认命令在 QQ `Processing` 保存后写 Memory，再保存和投递回复，因此用户未收到确认不代表偏好未保存。重启不重放旧 QQ 命令；新 `/memory-candidates` 会通过不可变候选与 Memory 首版、当前版本对账，`/memories` 可核对当前偏好。正常停止取消并等待在途提炼，保存取消结局；突发退出保留的 `Running` 则按上述恢复规则处理。

## 验证入口

状态及模型契约测试分别位于 `crates/learning-plugin/tests/state.rs` 和 `tests/extractor.rs`；QQ 确认命令测试位于 `crates/eve-app/src/qq_learning_commands.rs`。独立进程恢复示例位于 `crates/learning-plugin/examples/recovery.rs`，检查候选保存、Running 中断和再次只读恢复。

`crates/eve-app/tests/qq_learning_component.rs` 通过公开宿主入口验证替代提炼器：恢复真实 Session/Memory 证据、请求前已保存 Running、关闭时零调用、无模型连接、非法来源关闭通道及 Node 进程回收。

```sh
cargo test -p eve-learning-plugin --locked
cargo test -p eve-app qq_learning_commands --locked
cargo build -p eve-app --bin eve-qqbot --locked
python3 connectors/qqbot/test/learning_test.py
```

自主策略契约测试另见 `tests/confirmation.rs`。实际进程测试使用真实 Eve 程序、本地 HTTP 模型替身和 Node 桥接替身，覆盖三条交互门槛、先保存后请求、未经确认不进 Context、一次确认及修正撤销、范围隔离、冷却和启动额度、失败/取消/崩溃后不重试，以及与训练和内部反思的输入隔离。这些入口用于离线复验，不代表真实 QQ 认证、消息送达或模型候选质量已通过实机验收；真实交互仍在本地就绪后单独测试。
