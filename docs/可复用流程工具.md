# 可复用流程工具

宿主开启一次 `--workflow-tools` 后，模型可以在授权操作者的会话中使用 `save_workflow_tool` 保存常用步骤、用 `list_workflow_tools` 查看定义和执行记录、用 `run_workflow_tool` 再次调用。配置跨对话有效，流程定义和回执跨重启保存，不需要把流程写进固定系统提示。当前 QQ 组合层只向主人和管理员开放流程管理，未扩大普通成员的工具权限。

例如保存“写入报告、运行校验、发送报告”的步骤，在 JSON 参数位置使用 `{"$param":"path"}` 引用调用时传入的参数。只替换完整 JSON 值，不进行命令字符串拼接。流程 ID 属于当前用户和会话，同名不同内容必须提供当前 `expected_revision` 才能更新，执行时也必须指定版本，避免静默切换定义。保存不执行、不宣称已经验证。

定义层为 `WorkflowDefinition`，持久实现为 `WorkflowStore`，QQ 组合层只注入已做身份检查的叶子工具。调用时先校验全部展开参数，再依次执行原有工具，保留命令审核、文件权限、取消和共享预算。流程本身及每个内部工具都扣除步数；预算不足不开始。流程不能递归调用、管理身份、升级进程或派发任务。封装不授予新权限。

每步执行前先保存未确认状态，收到结果后再保存回执。非零退出码或拒绝停止后续步骤；超时、取消、执行异常或回执保存失败保留未知结果，不能自动重跑。进程重启不执行已保存流程，只能由新的调用启动；未结束记录保持可查询，不能把它当成功。`run_id` 可查询具体执行记录。损坏账本或版本不符时拒绝打开并保留原文件。

流程先用于已经验证过的重复步骤。模型自行选择何时复用和何时检查新情况；目标、参数、授权存在关键不确定时先问一次，不以保存流程代替澄清。
