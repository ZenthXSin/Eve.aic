# EVE.AIC 开发计划

## Phase 0：文档与边界

目标：确定项目原则、内核边界和插件契约。

- 建立文档目录
- 确定 Rust Runtime
- 确定单进程优先
- 确定可信静态插件模式
- 确定 `plugin-api` 与 `kernel` 的边界

## Phase 1：Plugin API

目标：定义不依赖 Runtime 内部实现的插件接口。

- `Plugin`
- `PluginManifest`
- `PluginContext`
- `PluginInfo`
- `PluginDependency`
- `Permission`
- 句柄类型和错误类型

完成条件：插件只能通过 Context 访问 Runtime 能力。

## Phase 2：Kernel Runtime

目标：实现最小插件运行内核。

- Runtime 状态
- Plugin Registry
- Dependency Graph
- 生命周期状态机
- Plugin Scope
- 自动资源清理
- 启动失败处理
- 反向停止顺序

完成条件：一组互相依赖的插件可以稳定启动和停止。

## Phase 3：基础服务

目标：让插件能够真正协作。

- Event Bus
- Service Registry
- State Store
- Task Manager
- Logger
- Permission Checker

完成条件：插件可以通过事件、服务、状态和任务完成协作。

当前进度：上述六项均已提供抽象接口和默认实现，日志额外提供内存后端，任务支持自定义类型与调度。已有运行示例及自动化验收，进入 Phase 4。

## Phase 4：恢复与诊断

目标：验证长期运行基础。

- 状态持久化
- Runtime 重启恢复
- 插件状态查询
- 任务查询
- 错误诊断
- 清理错误汇总
- 基础回归测试

完成条件：Runtime 停止后重新启动，插件状态和运行结果可以恢复。

当前进度：文件状态后端、独立进程恢复、插件清单和任务查询、结构化停止错误汇总均已实现并有实际验收。恢复范围是字节状态，插件负责重建订阅、服务和任务。Windows、Ubuntu 的完整 CI 及 Rust 1.89 编译检查已接入；启动与清理 panic 复用错误收尾路径，已准入的生命周期操作由宿主独立持有，取消等待后继续执行并保留可查询结果。

## Phase 5：插件扩展边界

已开始实现插件扩展的基础契约：清单版本采用 SemVer，依赖范围在注册和启动前校验，为后续插件发现、更新和版本化协议提供共同验证入口。

后续再评估：

- WASM 插件
- 独立进程插件
- 版本化插件协议
- 插件安装和更新
- 沙箱和资源配额
