# 持久化与恢复

这份文档说明内核现在实际实现的持久化语义。只写已经实现并有测试覆盖的行为。

## 存了什么，存在哪

内核启动时指定一个数据目录，下面有五个子目录：

| 目录                   | 内容                                             |
| ---------------------- | ------------------------------------------------ |
| `state/<插件>.json`    | 插件的当前状态，带写下它的插件版本和状态格式版本 |
| `snapshots/<插件>/`    | 每次换版前拍的状态快照                           |
| `failed/<插件>/`       | 被回滚的版本写下的状态，留作查看                 |
| `receipts/swaps.jsonl` | 每次换版的结果，一行一条                         |
| `calls/<编号>.json`    | 带幂等键的动作记录，独立于插件状态与回滚快照       |

代码和数据分开：换版只换代码目录，不动数据目录。

## 写入

- 插件调用 `setState` 后，内核把整份状态写到 `state/<插件>.json`；返回的 Promise 等实际保存完成才成功。
- 状态和动作记录先写独立临时文件、同步文件、改名，再同步父目录。中断可能留下临时文件，正式文件不会被半截内容覆盖。
- 同一个插件的写入按顺序排队，不会乱序覆盖。
- 处理器和生命周期成功返回前会收齐已发出的状态提交，即使旧插件省略 `await`。写入失败会传播给调用和停止；本次实例不再跳过错误继续保存。
- 轮次循环在一轮成功结束时才提交历史；中途失败的那一轮不进入历史。
- 主循环入口串行处理输入，并发到达的两条输入不会分别覆盖同一份旧历史。尚未实现中途轮次恢复与持久入站队列。

## 带幂等键的动作

- 编号绑定调用方、契约、方法与幂等键，参数另有摘要；同一个键换参数会被拒绝。宿主与插件的编号空间分开。
- 内核先保存 `started` 才执行，执行前记录保存失败就不调用插件；真实返回后保存 `completed` 或 `failed`。插件终止导致结果未知时保存 `unknown`。
- 等待超时只结束调用方的等待，原执行仍受跟踪。相同键继续等待原执行；迟到结果仍会保存，不再执行第二遍。
- 重启后，已完成结果可直接读回；只有 `started` 或明确未知时返回未知，不自动重放。`callStatus` 可查询宿主动作的现有记录，不触发执行。
- 记录不随插件状态快照回滚；已经发生的动作不能靠换版抹掉。
- 以上仅适用于显式传入幂等键的调用；没有键的调用没有持久去重。记录不能证明任意外部服务实现了恰好一次执行，也不代替平台送达回执。

## 启动与恢复

- 启动时读取每个插件的状态文件，交给插件。没有文件就是没有状态。
- 状态文件读不懂（不是合法
  JSON，或格式不对）时，启动失败并报错，文件原样保留。内核不会清空或覆盖它。已经启动的插件按逆序停止。
- 状态格式版本与插件要求的不一致时，由插件的 `migrate` 转换；插件没有提供 `migrate`
  则加载失败，状态不动。

## 换版

1. 契约兼容检查和类型检查不通过时，换版被拒绝，旧版本没有中断，也不拍快照。
2. 通过后，暂停对这个插件的新调用，等在途调用排空，收齐状态，拍快照，再停旧版本。
3. 新版本拿到快照里的状态启动。
4. 新版本确认成功之后，状态文件就是新版本写的内容。

在途调用没能在期限内排空时，它们的调用方会收到"是否已执行未知"的错误，换版回执里会写明这一点。

## 回滚

新版本在就绪、健康探测、首批真实调用任何一段失败或超时，都会回滚：

1. 终止新版本。
2. 把新版本写下的状态复制到 `failed/<插件>/`，不丢弃。
3. 把状态文件恢复成快照时的内容。
4. 用快照里的状态重新启动旧版本。

已经发生的外部副作用回不去。触发回滚的那次调用，调用方会收到真实的错误，不会被改写成成功。

保存失败状态、恢复快照或重启旧版本任一阶段失败时，结果记为
`rollback_failed`，插件标记为失败，快照和失败版本的状态都还在磁盘上。
保存失败副本本身失败时保留原状态，不继续覆盖；门控始终释放，后续调用会明确报不可用。

## 回执

每次换版不论结果是确认、拒绝、回滚还是回滚失败，都往 `receipts/swaps.jsonl`
追加一条，包含：从哪个版本到哪个版本、到达了哪些信号、原因、快照路径、失败状态的留存路径，以及过程中需要说明的情况。

## 还没有覆盖的

- 进程在换版中途被杀：重启后以状态文件为准，快照和回执不会自动用于恢复。
- 未带幂等键的调用、主循环中途退出、外部动作的查询与重连恢复。
- 多内核进程并行访问数据目录；外部守护与所有权令牌尚未实现，本版本不能作为多进程共享状态运行。
- 快照、失败状态和回执目前只增不减，没有清理策略。
