# 架构决策记录

## ADR-0001：核心 Runtime 使用 Rust

状态：已确定

原因：适合长期运行、异步任务、并发、资源控制和后续沙箱边界。

## ADR-0002：采用 Everything is a Plugin

状态：已确定

Memory、Personality、Learning、World Model 等业务能力优先设计为插件。LLM 模型请求与工具调用循环由 Eve 宿主内置能力提供；模型供应商适配、上下文、记忆、认知、工具和通信通道仍通过公开契约接入。

## ADR-0003：第一版采用单进程可信插件

状态：已确定

第一版插件静态编译进 Runtime，通过 Rust Trait 接入。暂不实现任意动态 Rust ABI。

## ADR-0004：Context 是插件唯一运行时边界

状态：已确定

插件只能通过 Context 访问 Runtime 提供的公开能力，不能访问内核私有结构。

## ADR-0005：Service 与 Plugin 分离

状态：已确定

插件是生命周期单元，Service 是插件提供的能力。消费者依赖 Service，不直接依赖其他插件的具体类型。

## ADR-0006：外部插件以后使用协议接入

状态：方向已确定，具体方案待定

候选方案：WASM、独立进程、版本化消息协议。



## ADR-0007：插件生命周期采用 Tokio 异步模型

状态：已确定

第一版 Plugin::start 返回可发送的异步 Future，Runtime 在依赖满足后等待启动 Future 完成，再将插件标记为 Active。插件作用域中的 Cleanup 也是异步动作，停止时按注册逆序逐个等待；启动失败会清理当前插件资源，并回滚本次请求中新启动的依赖。

## ADR-0008：后台任务停止采用可配置的等待期限

状态：接口与 Tokio 实现已完成

停止插件时，先通知其后台任务收尾、退出，再等待任务结束。默认等待 5 秒，允许通过配置调整。

超过等待期限后，尝试取消异步任务，并报告超时及未正常退出的任务。发出取消请求不等于任务已经退出；单进程内的阻塞操作不能保证被强制终止。

此决策规定后台任务的停止行为；`TaskManager` 已支持前台与后台的立即、延迟、指定时间、有限重复任务，以及后台无限重复任务。异步 Cleanup 仍按注册逆序逐个等待。

## ADR-0009：State Store 采用抽象接口并支持多种实现

状态：接口、内存实现与 JSON 文件实现已完成

Kernel 只依赖 State Store 抽象接口，不绑定具体存储介质。不同 Runtime 宿主可以按需求选择或替换实现，插件通过统一的 Context API 读写状态。

第一版默认使用 `MemoryStateStore` 内存实现，文件持久化通过同一接口提供 `FileStateStore`，具体提交与恢复语义见 ADR-0019。

## ADR-0010：Service Registry 采用字符串标识与类型安全双重约束

状态：接口与内存实现已完成

每个 Service 同时具备稳定的字符串 ID 和具体 Rust 类型。字符串 ID 用于发现、配置、日志和未来的跨边界协议；类型约束用于服务获取时的编译期表达和运行时校验。

字符串 ID 冲突时拒绝注册，类型不匹配时返回 `ServiceTypeMismatch`；缺失时返回 `Ok(None)`。插件不直接依赖其他插件的具体实现，只依赖 Service ID 与服务契约。

## ADR-0011：Event Bus 采用抽象接口并支持多种投递实现

状态：独立接口与同步广播实现已完成

插件只依赖统一的 Event Bus 抽象接口，Kernel 和 Runtime 不绑定某一种投递机制。当前 Kernel 已提供同步广播实现：按注册顺序调用监听器，一个监听器失败不会阻止其他监听器执行，同时返回错误结果。独立的 `EventBus` 接口已从 KernelHooks 拆出，宿主通过 `KernelServices` 注入 `SyncEventBus` 或其他实现。

后续可以在同一接口上增加异步队列、优先级、重试和持久化等实现。监听器属于插件作用域，插件停止时自动注销。

## ADR-0012：所有功能分离定义层与实现层

状态：已确定

所有 Runtime 能力先定义稳定的抽象接口、数据类型、错误和协议，再由独立实现提供具体行为。插件只能依赖定义层，不能依赖 Kernel 或某个实现的内部结构。

定义层负责契约；实现层负责 Kernel、Event Bus、Service Registry、State Store、Task Manager、Permission Checker、Logger 等具体实现；组合层负责选择、配置和替换实现。

一个能力可以拥有多个实现。默认实现用于第一版最小闭环，其他实现可以在不修改插件契约的情况下增加或替换。

## ADR-0013：权限系统采用抽象检查接口

状态：接口与声明检查实现已完成

定义层提供 `PermissionChecker` 抽象接口，插件通过 Manifest 声明权限，并通过 Context 请求检查。第一版只实现权限声明和检查，不把文件、网络或进程访问直接写入内核。

文件、网络、进程等资源访问以后通过独立适配器接入实现层。适配器按契约执行权限检查。对于当前可信、单进程、静态编译的 Rust 插件，经由 Context 访问资源是编码约定，无法阻止插件直接调用系统 API；不可绕过的访问控制留待 WASM 或受沙箱约束的独立进程边界实现。

## ADR-0014：第一版 Runtime 暂不提供完整 CLI

状态：已确定

第一版保留可编程 Runtime 宿主和最小运行示例，不提前引入插件发现、配置、安装和更新所需的完整 CLI。CLI 属于组合层，等插件加载协议、配置模型和安装流程稳定后再设计。

这不会限制后续 CLI 接入；未来 CLI 只负责调用稳定的 Runtime 和插件管理接口，不把命令行逻辑写入 Kernel 或插件定义层。

## ADR-0015：第一版采用插件协作闭环作为验收场景

状态：已实现，可通过 `cargo run -p eve-runtime` 运行

第一版验收场景由两个插件组成：提供者插件注册 Service 并发布 Event，消费者插件声明依赖、获取 Service、订阅 Event，并在收到事件后写入 State。

验收流程为：启动消费者并自动启动提供者；验证 Service 获取、Event 投递和 State 写入；停止 Runtime 时先停止消费者，再清理监听器和 Service；最后验证插件启动失败时资源和新启动依赖能够回滚。

持久化 State 和 Runtime 重启恢复不属于本阶段验收，待对应能力实现后单独增加验收场景。任务停止已有独立回归测试。

## 当前接口语义

- `StateStore`、`ServiceRegistry`、`EventBus` 和 `PermissionChecker` 在定义层独立声明，默认实现在 `kernel::backends`，宿主通过 `KernelServices` 按项替换。
- 状态读取和服务获取返回 `PluginResult<Option<_>>`，区分缺失、类型错误、后端错误和已关闭 Context。
- 状态按插件 ID 隔离，失败回滚只清理生命周期资源，不撤销已写入状态；内存后端不提供跨进程恢复。
- 同步事件允许嵌套发布；监听器返回错误不会阻止后续监听器。停止不会强制中断已准入的回调，尚未调用的监听器通过 Scope 检查跳过。
- 停止后服务不可再发现，但消费者已持有的 `Arc` 不会被强制撤销。
- 启动失败时，`Rollback` 错误保留原始失败及新启动依赖的清理错误。

## ADR-0016：任务模型分离模式与调度

状态：已实现

任务定义由 `TaskMode`、`TaskSchedule` 和 `TaskAction` 组成。前台任务由插件显式等待，后台任务归属插件 Scope；调度支持立即、延迟和固定间隔，可设置有限执行次数。后台任务停止先发出 `TaskSignal`，在配置期限内等待，超时后请求 Tokio 取消，再等待最多 100 毫秒确认退出（可配置）。无限重复任务只能作为后台任务。

任务停止首先禁止新增资源，协作收尾期间允许已有任务保存状态，最后关闭 Context 并执行 Cleanup。每次重复完成后才开始计算下一次间隔；指定时间在登记时换算，过期只执行一次。报告区分超时和未退出；未确认退出时插件进入 Failed。前台等待取消不应留下脱管任务。

## ADR-0017：任务类型与调度策略开放扩展

状态：已实现

任务行为通过 `Task` Trait 定义，插件使用自己的 Rust 类型与类型化参数，通过 `TaskSpec::from_task` 接入；`TaskTypeId` 是开放的命名空间标识，供查询和结果报告使用，不用于内核按名称分派具体实现。简单任务继续支持闭包。

触发策略通过 `TaskScheduler` Trait 定义。`TaskSchedule::Custom` 为每个任务提供独立的调度器工厂，支持异步事件等待、动态间隔和自然结束；执行器统一负责延迟、串行执行、次数上限、错误隔离与取消。自定义前台调度须声明正数执行上限。查询描述 `TaskScheduleInfo` 与可执行对象分开，不保留插件闭包。

新增业务类型或调度规则无需修改 Kernel，也不要求更换整个 `TaskManager`。定义层继续不依赖 Tokio；默认执行器负责具体运行方式。自定义模式沿用当前可信静态插件边界，动态加载、持久化任务描述和跨进程协议另行设计。

## ADR-0018：日志使用可替换接口与宿主附加的来源信息

状态：已实现

定义层提供 `Logger`、`LogLevel`、`LogEntry`、`LogRecord`，不绑定日志库或全局单例。插件通过 Context 提交内容，Kernel 附加 Manifest 中的插件 ID 与当前时间；内容字段不能覆盖来源元数据。后端由 `KernelServices::logger` 注入。

第一版提供同步 `WriterLogger<W>` 和按条数限制的 `MemoryLogger`；默认 `StderrLogger` 输出 Info 及以上记录。输出后端逐条串行写入并转义控制字符，内存后端满后淘汰最旧记录并统计淘汰数。后端错误显式返回，插件自行决定是否传播到业务流程。

协作停止期间允许已有任务记录收尾日志，Scope 关闭后拒绝新投递；已准入的同步投递可能与停止重叠。宿主停止日志生产后显式调用 `Kernel::flush_logs`，不把插件停止、Drop 或 flush 视为持久化保证。异步队列、文件轮转和远程收集可通过替代后端扩展。

## ADR-0019：文件状态按单次写入提交并严格恢复

状态：已实现

`StateStore` 接口不变；可选 `FileStateStore` 使用版本化 JSON 保存按插件隔离的字节状态。目录规范化后固定访问位置，独立锁文件持有排他锁，禁止同目录多后端并行打开。锁文件不随析构删除。

每次 set 在同一互斥锁下构造候选快照、写入同目录临时文件并同步，原子替换成功后才更新内存。失败返回明确错误并保留旧内存；只有最终快照不存在时视为空库，坏 JSON、未知版本、重复键或非法格式均拒绝恢复，保留原文件供诊断。

恢复范围是插件字节状态；宿主重新注册插件，插件从检查点重建业务资源。不恢复 Future、服务句柄或订阅，不提供多键事务、原子读改写或恰好执行一次语义。同步整份快照适用于少量状态；目录元数据不做断电持久性承诺。

文件锁使用 Rust 1.89 起提供的标准库接口，项目声明最低 Rust 版本 1.89；当前实际验收使用 Rust 1.98.1。

## ADR-0020：只读运行时诊断与分阶段停止错误汇总

状态：已实现

定义层提供 `RuntimeInspector`、`PluginStatus` 与 `PluginState`，Kernel 实现只读查询并兼容原有状态类型导出。插件清单按 ID 排序，不等待生命周期锁；读取逐项状态而非全局事务快照。未知插件的任务查询仍返回错误。

`PluginError::Shutdown` 保存按实际停止顺序产生的 `PluginStopError`，区分任务停止、资源清理、退出确认与生命周期阶段。依赖递归保留真正失败的插件归属，同一插件不同阶段失败不去重。Scope 内多个 Cleanup 回调的错误仍以阶段字符串汇总，回滚继续保留原始启动错误及逆序停止错误集合。

任务退出检查失败或仍有未退出任务时，停止必须返回错误并把插件设为 Failed；任务已退出但 Cleanup 报错时仍设为 Stopped，并返回清理错误。重复停止不会重新执行已完成清理或重试 Failed 插件的残余任务，宿主应查询状态与任务确认，不把重复调用成功当作退出证明。

## ADR-0021：隔离启动与清理回调的 unwind panic

状态：已实现

Kernel 在 `Plugin::start` 与每个 Cleanup 回调的调用和 Future 轮询边界捕获 Rust unwind panic，转为带阶段及载荷信息的错误。字符串载荷保留原文，其他类型使用明确的非字符串说明。捕获时不持有 Kernel 的同步锁，不改变公开插件契约，也不新增执行器依赖。

启动 panic 复用启动失败路径：禁止新增资源、停止任务、关闭 Context、逆序清理资源，再回滚本次新启动的依赖。插件内部对象可能已经部分修改，因此进入 Failed，不自动重启。已在本次请求之前 Active 的依赖仍保留。

Cleanup panic 记录为清理阶段错误，继续执行剩余回调及其他插件；回调仍然只调用一次。失败回滚保留原始启动原因和所有回滚错误，不能用清理 panic 覆盖原始原因。

这不是进程隔离：默认 panic hook 仍可输出诊断；`panic=abort`、双重 panic、Future/载荷析构中的 panic 不承诺恢复。事件监听器和任意自定义后端的 panic 不纳入本边界，后端应通过 Err 报告失败。宿主取消生命周期等待的语义由 ADR-0022 定义。

## ADR-0022：生命周期操作独立执行与显式结果确认

状态：已实现

定义层提供宿主专用 `RuntimeLifecycle` 接口及请求、操作 ID、状态与结果快照。Kernel 先等待全局串行准入锁，随后在同一次轮询中登记记录并将操作和 owned 锁移交 Tokio worker。未准入前取消无副作用；准入后取消等待不会丢弃启动、依赖回滚或停止清理 Future。

显式提交后，`wait` 可由多个调用方重复获取终态快照；操作成功或失败不自动移除记录，由宿主 `acknowledge` 确认。已取得记录的等待者不受其他调用方确认的影响；确认之后新建的等待返回不存在。原有 start/stop 四个便利入口正常返回时自动确认结果，等待被丢弃则保留报告。报告只存内存，默认容量 128；满时拒绝新操作，不淘汰未确认的错误。

worker 尚未开始便被执行器丢弃时，只记录 Interrupted，不修改插件。已经开始后意外中断时，记录 Interrupted、隔离 Kernel，关闭所有 Scope 并把原本运行或过渡中的插件标记 Failed；这表示 Runtime 已不能安全继续，不等于所有插件自身都发生错误。未执行 Cleanup 的捕获值可保留到旧 Runtime/Context 释放，不在中断 guard 中执行用户代码或承诺异步清理完成。

正常运行需要 Tokio 持续调度，启动和 Cleanup 不能同步阻塞或永久等待。调用方的超时只取消等待，不是操作执行期限；需要等待停止终态后刷新日志，再关闭执行器。记录确认、等待取消和失败均不自动撤销已经成功提交的 StateStore 字节状态。

## ADR-0023：插件清单使用 SemVer 依赖契约

状态：已实现

`PluginManifest.version` 使用严格的 Semantic Versioning 格式，`PluginDependency.requirement` 使用标准 SemVer 版本范围。清单在注册时统一校验，拒绝非法版本、自依赖、重复依赖和非法范围；依赖启动前再次检查已注册依赖的实际版本。

依赖范围缺失表示接受任意合法版本。版本不满足时返回结构化 `DependencyVersionMismatch`。本记录原先对“不执行部分启动”的承诺不能仅靠逐个检查并启动依赖实现；完整的预检范围和无启动副作用边界由 ADR-0025 明确。校验入口位于 `plugin-api`，后续插件目录、更新流程和外部协议复用同一入口，避免不同组合层产生不一致的版本语义。

## ADR-0024：插件卸载保留状态并要求退出确认

状态：已实现

宿主通过定义层 `PluginRegistry` 卸载插件。卸载与注册、生命周期操作共用串行准入锁，只允许 `Registered`、`Stopped` 或已完成收尾的 `Failed` 插件；运行中的 Scope、未完成的生命周期操作或未确认退出的任务都会使卸载失败。

卸载只移除 Kernel 注册表中的插件对象，不删除 `StateStore` 中按插件 ID 保存的字节状态。重新注册同一 ID 可以继续读取检查点。卸载前的任务清单和状态检查失败会原样返回，不能通过删除注册表条目掩盖资源未释放。

## ADR-0025：启动前预检本次请求的完整依赖图

状态：已实现，实际验收见执行书

启动操作在同一生命周期准入锁内先完成只读预检，再执行启动。`Start` 检查目标及其可达依赖，`StartAll` 在启动任何插件前检查全部根节点；检查依赖缺失、版本不匹配、依赖环和不可启动状态。预检失败不调用任何 `Plugin::start` 或 Cleanup，不修改插件生命周期状态。生命周期操作报告仍按 ADR-0022 记录结果。

共享节点只需完成一次节点检查，但遍历到的每条依赖边的版本要求都必须独立校验。已 `Active` 的节点不再展开其既有依赖、也不重复启动；新消费者指向它的版本要求仍须检查。运行中清单不能替换，停止提供者时会先停止其消费者。预检与执行之间不释放准入锁，注册与卸载不能在此间改变清单或依赖图。预检不暂停现有插件及其后台任务。

通过预检仅表示依赖图和启动状态可接受，不保证插件实际启动成功。执行期间的启动错误或 panic 仍按既有协议收尾，并逆序停止本次新启动的插件；请求前已运行的插件不受该回滚影响。成功写入的字节状态和已经发生的外部副作用不会撤销，因此该流程不是业务事务，也不包含版本替换或状态迁移。
## ADR-0026：LLM 调用由宿主提供，业务能力保持插件化

Issue #27 明确了全局边界：Eve 宿主负责模型请求、响应处理和工具调用循环，LLM 调用不作为普通业务插件暴露。Memory、Context、Cognition、Tools、Channels 等可独立替换的业务能力仍通过 `plugin-api` 的公开契约实现；宿主只负责选择和装配它们。Issue #24 负责后续最小 LLM 工具闭环，不改变该分层。

## ADR-0027：静态插件工厂与目录属于组合层

`PluginFactory` 与 `PluginCatalog` 定义在 `plugin-api`，默认进程内目录由 Kernel 提供实现。目录登记可信静态工厂并保存经校验的清单快照，按 `(PluginId, Version)` 精确查找，允许同 ID 多版本共存。目录不会自动选版、求解依赖、启动插件、注册 Runtime 资源、下载更新或持久化工厂；创建结果由宿主显式交给 `PluginRegistry` 管理。工厂回调在目录锁外运行，实例清单必须与登记快照完全一致，漂移或 panic 返回结构化错误且不污染目录。

## ADR-0028：最小 LLM 工具循环使用独立协议与 Runtime 宿主

状态：Mock 与真实 Responses 闭环已验收；会话恢复见 ADR-0031，流式输出后置

LLM 的厂商无关协议定义在独立的 `eve-llm-api` crate，而不是通用 `plugin-api`。它声明 `LlmProvider`、请求与响应消息、`ContextAssembler`、`Tool`、工具调用和结构化错误。`eve-llm-api` 可以依赖 `plugin-api`；Kernel 不依赖它，以免生命周期内核被模型协议、网络客户端或厂商格式耦合。

Runtime 是唯一执行模型请求和工具调用循环的宿主。Provider 是可替换适配器，负责把 Eve 内部协议映射到厂商 API；无法无损表达调用 ID、工具名、参数或工具结果时必须报 `Unsupported`。Context、Memory、Tool 和 Channel 仍是插件能力，通过带大小的 `ContextService`、`ToolService` 包装 trait object 注册到既有 Service Registry。Runtime 使用静态配置的工具绑定，不扫描 Registry；工具定义按名称稳定排序。

首版一次模型响应只能是非空最终文本或一个非空、调用 ID 唯一的工具调用批次，`max_tool_rounds` 固定为 1，至多两次 Provider 请求。批次内每项独立校验和收集结果，结果保留模型返回顺序并以调用 ID 关联。Runtime 对每次 Provider 请求和每项工具调用施加正数超时，不自动重试。结构正确但未通过工具参数校验的调用生成失败结果；坏 JSON、非对象参数、空或重复调用 ID 属于协议错误。装配预检失败不请求 Provider；调用期服务不可用、未知工具、权限拒绝和工具失败则以公开失败码回传。后端读取错误不能伪装成缺失，完整分类以[LLM 工具调用](./LLM工具调用.md)为准。

为了复用 `PermissionChecker`，在 `RuntimeInspector` 新增 `plugin_manifest(&PluginId) -> PluginResult<PluginManifest>` 返回只读快照，并在 `PluginError` 新增 `PluginNotFound` 表示未注册。宿主显式接收与 Kernel 共享同一内部状态的 Kernel 克隆、Registry 与 PermissionChecker，按工具所有者清单检查所有所需权限。固定规则与输出格式来自宿主配置，Context 只提供带版本的档案、记忆和历史；一轮复用同一配置、工具定义与动态快照。

工具定义以 `ToolConcurrency` 显式声明并发策略：`ParallelSafe` 可以与其他调用同时执行；`Serial { scope }` 在同一非空作用域内使本地 Future 按模型顺序互斥；未声明采用全局默认串行作用域。它不是远端资源锁，超时或取消后的外部副作用仍由工具自行保证幂等、互斥或补偿。Runtime 在所有可运行调用之间实施正数 `max_parallel_tool_calls`，默认值为 `10`，不从业务名称或参数推断依赖；组合层从配置服务取得并校验值后，为每轮固定快照，配置服务的接口与自举由 #32 定义。工具期限自取得执行槽位并即将首次轮询 Future 起计算，排队时间不计入；期限优先于同一轮询点的正常完成。超时先设置协作式取消标记并在正数收尾窗口继续轮询，窗口结束后才丢弃 Future、释放本地串行作用域并回传 `TimedOut`；工具在初始期限内主动确认取消时回传 `Cancelled`。批次结果与调用一一对应，单项失败、超时或工具确认的取消结果不得抹除其他调用；遇到晚发的致命宿主后端错误时，取消已开始调用、移除排队调用并终止整轮，不发送不完整批次。调用者取消整轮会使所有未完成 Future 收到取消标记后立即被丢弃，并停止整轮，不能生成不完整批次或发起第二次 Provider 请求。Provider Future 在首次轮询起计时，超时或整轮取消均丢弃本地 Future。以上均不承诺停止远端工作、撤销计费或回滚副作用。

检查 Active 与持有服务 Arc 不是执行租约；每轮开始前，相关插件必须已注册并处于 Active 状态。每次整轮调用持有 Kernel 共享的运行准入锁，启动、停止等异步生命周期操作等待整轮结束，注册和卸载在整轮期间返回错误；运行请求持共享读准入，生命周期与注册变更持独占写准入；整轮被取消后，工具任务仍保留准入引用直到本地 Future 析构。Provider 和工具不能在整轮内等待同一 Kernel 的生命周期操作，以免形成重入等待。工具 Future 由宿主直接等待，不自动受 TaskManager 管理。调用者丢弃整轮后，随后的生命周期操作不代表远端副作用已终止。返回值携带成功或失败诊断，不自动持久化，不回滚副作用。消息打断仍由 #29 跟踪。

## ADR-0029：首个 OpenAI 适配器采用 Responses 与独立 HTTP 实现

状态：文本/函数调用适配器、本地 HTTP 与真实模型工具回传已验收

选择 Responses API；Rust 侧在 `eve-llm-openai` 中用 `reqwest` 与 `serde`/`serde_json` 实现窄适配层，映射和传输分别测试。厂商类型、模型配置与密钥留在适配器内，替换实现只需满足 `LlmProvider`。实现使用锁定的 `reqwest 0.12.28` 与 Rust 1.89 可编译依赖；转换 fixture、本地 HTTP 和 Runtime 组合均有测试；2026-09-30 已使用用户指定的 gpt-5.6-sol 验证真实文本和插件工具回传。组合层通过配置插件读取普通 Provider/Host 配置，凭据仍由宿主独立提供。

首版限定非流式的纯文本/函数调用批次可无损子集，使用 `call_id` 关联每项工具与结果，请求显式开启 `parallel_tool_calls`，完整保留调用批次及其顺序。参数 Schema 不静默改写，采用显式非 strict 模式并保留工具本地校验。需要 reasoning 续传、混合文本和调用、内置工具或其他无法无损映射的输出必须返回 Unsupported；后续支持时另行定义适配器私有续传边界，不把厂商对象下沉 Kernel。

每次发送完整消息并设置 `store: false`，不使用服务端响应链替代 Eve 的状态恢复；该选项不等于零数据保留。真实模型由宿主选择并通过兼容 smoke test 验证，密钥不进入仓库或日志；实现时按 OpenAI 官方文档复核字段、模型支持和数据控制。final_answer 消息映射为 Eve Final，并在 assistant 文本历史中保留该 phase；commentary 与未知 phase 拒绝。选择理由、映射和实际验收见[OpenAI 接入](./OpenAI接入.md)。

## ADR-0030：普通配置由独立内置插件提供版本化快照

状态：第一切片已实现；敏感配置和凭据代理后续实现

`eve-config-api` 定义公开 Schema、可序列化快照/请求上下文/错误、读取服务和单独管理接口；`eve-config-plugin` 提供内置实现，Kernel 不承担业务配置规则。组合层指定目录和消费者 Schema，Manifest 依赖保证配置服务先于消费者启动，服务缺失或配置无效使消费者启动失败。普通消费者只依赖定义层，不依赖实现类。

文件覆盖环境，环境覆盖默认值；环境按启动采集，Schema 与文件版本明确校验。请求快照区分立即替换与仅新请求；最近一次立即替换更新已开始请求的后续读取，之后仅新请求更新不污染该请求。需要重启的字段保留启动值，提交结果列出待重启项。配置服务重启使旧请求上下文失效。

配置与备份同属一个原子文件提交，磁盘提交成功才更新内存，修订号比较防止丢失并发修改；备份保留最近 20 个自动版本，手动固定额外保留，回滚产生新修订。停止或启动回滚使旧服务句柄失效并显式释放目录锁。格式错误、重复键、未知版本或非法历史不视为空库。

首版支持普通标量字段，拒绝敏感或加密字段。加密密钥库、主密钥、密钥引用、凭据代理、外部查看 2FA、插件授信/检查仍按 #32 继续。Serializable DTO 为后续传输适配保留边界，当前没有交付 IPC、动态外置插件或沙箱。细节与实际验收见[配置管理](./配置管理.md)。


## ADR-0031：会话历史由独立插件提供，失败不自动重放

`eve-session-api` 定义 SessionService、版本化会话快照与轮次引用，`eve-session-plugin` 通过 StateStore 提交整份会话文档。`SessionLlmHost` 持续调用内置 LlmHost，业务定义与实现不进入 Kernel。每轮先提交 Pending；只有完整 User、配对工具调用/结果与最终 Assistant 成功提交后才成为可回放 Completed。失败输入保留分类和已开始工具数，但不加入完成历史。

同 session_id 绑定用户且一个在途轮次，不同会话可并行；同一 LlmHost 跨会话共享工具并发上限与串行作用域，取消排队项不能绕过在途项；用户 ID 来自通道或宿主，不作为认证。会话模式拒绝 Context 的非空历史，保持固定规则/工具在前、动态档案/记忆/历史/输入在后的稳定槽位。保存失败返回生成输出或执行失败及保存错误，保留 Pending，不能自动重试工具。取消记录保存失败投递脱敏诊断；Pending 恢复为 Interrupted，原输入保留但不自动执行。损坏与未知格式启动失败，不清空数据。

Kernel 的准入机制采用公平读写锁：运行共享、生命周期独占。整轮保存和工具任务析构均受保护，停止等待后才使旧会话服务失效。准入不保证远端停止、幂等或恰好执行一次；回调禁止重入同一 Kernel 生命周期。同步全量文档适用于小规模验证，异步数据库、历史裁剪、记忆分析、Jev、流式/reasoning 续传继续后置。验收与存储格式见[会话恢复](./会话恢复.md)。


## ADR-0032：流式事件采用异步接收器，终态与持久化分离

定义层增加 ModelTextSink、TurnEventSink、ResponseMode 与自有轮次事件。Provider stream 只发布暂时文本，返回经验证的完整 ModelResponse；不支持的 Provider 明确返回 Unsupported，默认配置 complete，不静默降级。Responses SSE 字节解帧、增量组装和终态一致性验证留在适配器，厂商类型不进入 Kernel。

组合层逐次 await 事件接收器，不创建队列；通道插件桥接有界通道，断开返回 Cancelled，并提供 closed 信号用于取消网络/工具等待。投递有期限，Provider 期限含读取与背压；外层 Future 取消仍受整轮准入和工具任务析构语义保护。TextDelta、ResponseCompleted、TurnCompleted、SessionSaved 分别表示暂时显示、单请求完成、整轮生成和成功持久化。提交失败保留最终输出与 Pending，成功提交后的通知失败通过 Delivery 返回已保存输出，不能作为重试依据。

两种模式共用工具循环和固定提示前缀。函数参数片段不发布给执行层，完整终态后才做权限/参数预检及执行。工具进度按原调用顺序报告已收集的结果；新消息关系判断、Jev、旧回复抑制、reasoning 续传另行设计。协议和验收见[流式输出](./streaming.md)。

## ADR-0033：显式取消由独立控制插件持有，代际过滤在展示时执行

控制公开契约在 eve-control-api，eve-control-plugin 持有任务 Future 与 watch 取消信号；Runtime 的 SessionControlRunner 只适配内置会话宿主。宿主仍处理模型调用、工具析构和持久化，Kernel 不接收模型状态。组合层显式声明执行器需要的插件依赖。

GenerationKey 同时包含 SessionKey、task_id、每次启动的随机 epoch 和单调生成代；cancel 校验完整标识且幂等，wait 返回真实提交状态及工具副作用诊断。取消控制器不直接 abort 轮次，以免丢失工具开始数量和失败记录。Context 与生命周期准入等待同时观察 closed。

正常完成的排队通知在本代仍有效；显式取消立即关闭转发及接受资格，新代替换后拒绝旧代所有事件。通道必须在展示时过滤队列，并串行处理展示与取消/切换；仅发送时过滤不能解决晚到事件。wait 报告独立于回复展示，完成/取消竞争不改写已落盘的 Completed。

保存失败保留完整生成 transcript、工具回执和 Pending，控制器禁止替代轮次；未知执行器异常也阻止自动重试。磁盘版本和恢复规则不变；控制报告只保留每个会话最新代，既有 wait Future 持有旧代结果，停止使旧服务失效。任务 ID 不提供幂等去重或自动恢复；身份认证、远端取消、副作用回滚与消息关系判断后续实现。


## ADR-0034：消息关系判断与执行动作分离，重规划绑定完整代际

判断契约、多意图标签、UTF-8 原文范围与配置 Schema 位于 eve-message-api，判断实现和消息路由分属独立插件；组合层注入 RelationJudge 或自定义插件依赖/服务 ID。Kernel 不接收模型语义，主模型和工具执行仍走内置 LlmHost。明确命令规则作为首个可运行判断器；自然语言、Jev 与 LLM 回退另行实现。

分类输入采用当前控制快照的真实请求/阶段；输出必须匹配完整 GenerationKey 与 message_id。多项标签逐项校验置信度和原文范围，动作只复制用户原文，不执行分类器生成的要求。补充/纠正/澄清答复形成结构化修订；独立新任务不携带旧未完成输入。答复仅绑定本代最近澄清，低置信度、冲突、异常或不支持的暂停恢复均先澄清。

路由持有已接受动作，丢弃等待不撤销执行；分类后重新检查目标，取消后等待真实提交及工具析构。ControlService.submit_if_current 将代际比较与提交置于同一临界区，防止旧分类覆盖后来已完成的新任务。收尾后遇到代际变化或提交失败，仍返回原代副作用和提交报告。Pending/Unknown 阻止替代；修订若已有工具执行或副作用未知，只澄清，不自动重跑或回滚工具。

消息 ID 在当前进程、用户/会话范围内按完整输入去重；容量满时拒绝新消息，不驱逐已执行记录。消息记录及澄清引用不持久化、不跨重启宣称恰好一次；会话插件仍提供真实完成历史与失败恢复。业务配置通过 runtime.messages 版本化快照读取，分类期限在接收时确定，动作门槛和组合大小在执行前按立即/仅新请求语义重读。协议和实际验收见[消息关系](./消息关系.md)。

## ADR-0035：语义判断由内置 Provider 适配，插件组合受限回退

LlmRelationJudge 位于 Runtime，使用公开 LlmProvider 做一次非流式分类；eve-message-plugin 只组合规则、可选 RelationJudge 与宿主提供的回退实现。模型请求、工具循环和 Kernel 边界不变。默认规则装配不发模型请求；语义判断需显式选择，Jev 适配尚未交付。

确定性规则优先；格式错误的显式命令保持澄清。可选判断最多占判断期限一半；失败、panic、低置信度、模糊或非法输出交给一次内置回退。链内读取独立配置请求快照，路由仍持有消息准入期限和动作门槛，不由判断器延长或直接变更任务。

模型只返回标签、整数置信度和原文片段；完整代际在本地绑定，UTF-8 范围由唯一片段查找产生。重复片段、重叠、生成文字、工具请求、重复字段、未知结构及超大请求明确失败，不修复或重试模型结果。输入不附带身份标识、完整历史、工具参数/结果；当前任务文字仍按实际内容发送。分类期限/取消停止本地 Future，不承诺远端撤销。

TypeSafe 官方 SDK 的 choice 是一个窄问题的单选概率；不能直接冒充多意图与原文范围。先交付内置回退和确定性验收，再单独接 Jev 并做同样本质量/延迟对比。未校准的 LLM confidence 和 Mock 样本不代表真实质量；失败最终澄清，代际、副作用和保存保护仍由既有路由/控制器执行。详细输入、上限、快照和恢复范围见[消息关系](./消息关系.md#可选判断与内置-llm-回退)。
