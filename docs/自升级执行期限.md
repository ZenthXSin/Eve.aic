# 自升级执行期限

Eve 已具备读源码、编辑、执行命令、准备候选、请求切换和查询切换状态的工具。`prepare_self_upgrade` 实际运行格式、Clippy、工作区测试和优化构建，核对前后源码指纹并冻结候选；`apply_self_upgrade` 排队后由监督器等待本轮回复送达和通道空闲，再切换到新进程。切换失败保留状态并回退，未知操作不重放。

升级准备包含四次连续 Cargo 检查，不能用单条命令的外层超时包住全部流程。组合层现在为 `prepare_self_upgrade` 单独设置 `4 × command_timeout_ms + 240 秒`，额外时间供前后指纹、元数据和候选保存；每条命令仍受原有配置期限、用户取消和父任务总期限限制。其他工具的期限不变。

真实进程回归使用四次真实 Cargo 验收，每次增加可控延迟，确认总耗时超过旧外层期限仍能完成候选准备。进程切换与失败回退由独立监督器验收覆盖。准备成功仅代表候选完成，不能宣称已经上线。

该累计期限回归在计时前用相同的受限构建环境预热真实格式、Clippy、测试和构建，并记录组件版本与预热耗时；CI 显式选择已安装的 Rust 1.89.0，避免意外使用 runner 镜像默认工具链。正式准备仍重新运行四项真实检查，每项保留 11 秒人工延迟和 13 秒单命令期限；首次组件启动不再误占仅剩两秒的检查预算。prepare 外层 292 秒及测试进程 90 秒期限保持不变，失败现场保留各阶段和原始工具结果。
