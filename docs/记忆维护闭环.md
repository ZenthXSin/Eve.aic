# 记忆维护闭环

本功能在现有交互记忆和偏好提炼上实现，不另建一套五层目录，不依赖模型记得执行脚本。原始 Session 和 Memory 记录仍由宿主持久保存；提炼只读取当前 QQ 会话及发起人的已确认送达交互。普通聊天没有因此获得跨范围读取权限。

## 处理与恢复

1. 原始交互提交成功后才可进入提炼。宿主按证据 ID 集合记录消费进度，而不是把一个最大修订号当作连续完成游标；被跳过的超长证据仍计入积压。
2. 继续遵守已配置的批量、冷却和执行次数限制。证据不足一批时，最早一条积压满 24 小时也可整理，避免低频会话永久等不到处理。检查使用时间差，不绑定机器本地的固定钟点。
3. 调模型前先保存 Running、确切输入和尝试代数；请求没有工具能力。一次请求同时生成偏好候选与可选反思草稿。反思包括观察、行动、结果、经验、下一步查证和本批次来源 ID；没有依据可写“未记录”，没有新经验可不产生反思。
4. 候选与反思在同一次账本提交中保存。提交成功才报告 Completed；这只证明提炼提交完成，不证明语义正确、偏好确认或外部操作成功。偏好继续经过原有确认、纠正、撤销规则；反思不自动成为长期规则。
5. 只对明确网络、HTTP 429/5xx、超时和进程中断的无工具提炼补做。每批最多追加两次，至少隔 30 分钟，使用原有模型预算与启动执行额度；认证、余额、普通请求拒绝、未知 Provider、取消、格式错误不自动补做。底层 Provider 如另有重试，其自身上限仍适用，本层上限统计提炼尝试。
6. 原尝试的状态和时间保留，新的尝试代数拒绝迟到回执。重新读取来源并逐条核对；来源变化、提炼器版本变化、存储损坏或状态不可确认时不擅自续写。重启先持久标记 Interrupted，再按上述条件补做，不重放业务工具。

默认模型提炼器版本变为 v4。v3 的已有完成记录继续可读；v3 失败记录不会无提示切换成 v4 重跑。未启用自动学习时仍受原有每次启动次数限制，不在后台无限补额度；启用自主总预算时，提炼和补做均使用 memory-maintenance 分项。尚未启用总预算时仍保留原组件次数、冷却及持久容量约束，不声称存在未配置的总 token 上限。

## 查询与上下文

`memory_maintenance` 是当前可信身份的只读工具，不接受用户、群、路径或执行命令参数：

- `status`：实际记忆修订、原始证据数、待处理和超长积压、各状态批次数，以及最近提交/失败回执。偏好记录数不冒充当前有效偏好数。
- `journal`：按关键词查当前范围反思草稿，每次最多八份，使用 offset/next_offset 分页，返回来源 ID 与提炼版本；草稿不能当授权或已验证事实。
- `source`：用批次 ID 和证据 ID 获取对应原文。摘要不能代替缺失原文。

每轮自动加入小型维护索引，仅包含批次数和最近批次状态；正文仍按需读取。索引变化参与上下文修订。用户问“记忆更新了没”时根据真实工具结果回答，不固定开场自报、不每小时打扰。没有启用提炼时明确显示未装配；损坏状态报错，不假装空记忆。

## 边界

当前提供按持久批次记录的反思日志，不强行生成每天一份空日记，不为“长期记忆一个月没变”编造新经验。来源 ID 校验只证明引用属于输入，不能自动证明模型总结正确；当前纠正、撤销和原始证据优先。

本批不改变原学习账本 128 批次 / 4 MiB、决策 1024 条的容量上限，也不删除或覆盖旧批次来腾空间；容量不足保留原文并停止新准入。这是后续冷归档工作的边界，不能称为无限长期运行。日常维护不会扫描并导出不可访问的模型内部推理。命中、引用、有用性未实现的指标不伪报。

合并顺序：本分支基于自主候选 PR #365，先合并 #365，再合并本批。GitHub 主线同步基准 b091ee8；其他尚未合并的功能 PR 未混入。

新增反思、尝试历史与失败类别属于新版本账本字段。旧版本二进制不保证能读取新写入记录；回退应使用匹配的状态快照，不能删掉新字段或清空账本来伪装兼容。
