# 模型请求前缀诊断

本诊断记录兼容 OpenAI 适配器最终请求的摘要、关联标识和提供方用量，用来定位稳定前缀在哪一层变化，以及同一次请求究竟有没有报告缓存。它只增加默认关闭的诊断，不调整提示顺序、模型、温度、路由、缓存键或重试策略，也不证明上游缓存收益已经改善。

## 启用与覆盖范围

在宿主启动环境中设置 `EVE_TRACE_MODEL_PREFIX=1` 或 `EVE_TRACE_MODEL_PREFIX=true`，通用模型构造路径创建的 `OpenAiProvider` 会启用 `with_wire_diagnostics()`。未设置或其他值均关闭；判断区分大小写，不自动去除空白。该开关独立于 `EVE_TRACE_DIALOGUE_TIMING`，无需打开阶段计时。

开关由宿主构造提供方时读取，不加入持久化模型配置，也没有状态迁移。已缓存的提供方不会因修改另一个进程的环境而热切换；后续按既有宿主重启或提供方构造流程应用启动环境即可。本说明不表示需要立即重启线上服务。

覆盖兼容适配器的普通 Chat Completions 与 Responses 请求。Codex 原源码适配器没有改动，不产生这些诊断，不能把兼容适配器的观测推广到 Codex 路径。`idle_small` 直接构造提供方，绕过通用构造，本开关也不覆盖它；独立 `describe_image` 识图、嵌入接口、其他独立客户端及 `/models` 目录查询也不据此认定已覆盖。

## 日志与数据边界

诊断使用以下三个日志标记，每条附带格式版本和关联信息：

| 标记 | 用途 |
| --- | --- |
| `EVE_MODEL_WIRE_FINAL` | 每次 HTTP 尝试开始、实际发送前，记录已组装请求体、配置部分、工具清单及逐消息项目的摘要和长度；不证明请求已被上游接收 |
| `EVE_MODEL_WIRE_HEADERS` | 收到响应头后记录 `http_status`，以及 `x-request-id`、`x-oneapi-request-id` 的摘要；不证明响应正文有效或模型执行成功 |
| `EVE_MODEL_WIRE_USAGE` | 模型响应通过既有完整校验、可选用量尾流处理结束后，记录既有解析器得到的用量；失败或取消的尝试不会因此补出用量记录 |

记录带 `schema_version=1`、`domain`、`process_nonce`，以及 `call`、`request`、`attempt`、`role` 和 `protocol`。未登记的用途不会回显原值，而是 `role=null`。逐消息详情最多 512 项，逐工具详情最多 128 项，超出分别以 `messages_truncated`、`tools.truncated` 明确标示；缺少后续逐项记录不表示请求中没有它们。整体 `body`、`input` 与 `tools` 摘要仍覆盖完整内容。长度是诊断对象的 JSON 字节数，不是上游 tokenizer 的 token 数。`config` 摘要排除 `messages`、`input`、`tools` 与 `prompt_cache_key`，其余最终请求字段参与计算，不输出字段名或值。

`FINAL.destination` 保存客户端已配置端点的进程 HMAC 与 JSON 字符串字节数，不输出 URL。它用于避免把不同客户端目标合并比较；相同摘要只说明客户端目标相同，不证明转站内部选中了同一后端、同一上游密钥或同一缓存分区。凭据不参加此摘要，不能用它判断凭据是否轮换。

请求体、消息、工具与配置内容使用进程随机密钥的 HMAC 摘要，密钥不写入日志。只有相同进程和相同诊断域内的同类摘要可直接比较；重启后摘要变化不能证明提示发生了变化。同一进程共用诊断密钥，持有多个会话日志的人可以判断同类内容是否相等，但不能据此读取原文或扩大访问权限。不要用普通 SHA256 去反推或匹配这些内容摘要，也不持久化密钥以获得跨进程内容追踪。随机源初始化失败时诊断保持关闭，不影响原模型请求。

会话、线程、缓存和客户端请求的 opaque 标识使用 SHA256，允许持有转站日志的可信运维者对同一标识计算摘要进行关联；固定允许的响应请求标识也只记录摘要。缺失、多个同名头、超过 1024 字节或缓存键类型错误时只记录固定状态，不回显内容；多值或超限标识不生成摘要。此处不输出标识原值、消息正文、工具参数、工具描述、图片内容、端点 URL、认证头或凭据。标识摘要用于关联，不能充当身份认证或授权，也不扩大日志和会话数据的访问范围。

## 如何判断问题所在

先按协议、用途和会话或缓存标识的摘要找到可比较请求，再按调用、请求、尝试编号区分同次重试与后续请求。配置、工具清单变化会影响请求的可比较性；消息逐项摘要能指出第一处完整项目差异。一个消息内部只有末尾变化，也会导致整个项目摘要变化，因此不能由该摘要算出项目内部仍相同的 token 前缀。

随后利用固定响应请求标识摘要，与 NewAPI 中对应请求的标识、状态及提供方用量核对。关联不到时保留未知，不能凭相近时间、同一模型或总请求数断定是同一条。NewAPI 自身是否保留或转发这些标识须以该次记录为准；宿主日志不证明中转站或后端采用了传入的缓存键。

用量中 `cached_input_tokens=null` 表示既有解析器没有得到可用的缓存输入报告，`0` 表示明确解析到零命中；两者不能合并。`usage_reported=true` 仅表示至少一个用量字段被解析到，不代表缓存字段存在，也不保证所有计数已通过计费比例校验。本日志不保留所有上游原始用量字段及其来源名称，不能用它判断未支持字段是否存在。这里观测的是 Eve 从直接 HTTP 对端实际收到、经既有解析器处理的用量。NewAPI 可能透传已有用量，也可能因格式转换重建字段，或在上游未报用量时生成本地估算尾帧；因此收到明确零也不独立证明模型供应商原始报告为零。账单 DTO 的默认零是否影响下游 JSON，应按当次响应路径另行核对。Chat 的用量尾流结束可能是正常完成，也可能因期限、大小或传输问题结束；已有完整模型结果不会因此被改为失败，用量可能仍缺失。没有对应记录时，不能自行补零或声称请求已经成功。实际命中比例须另外校验有效输入与缓存输入 token，不能用 HMAC 相同、HTTP 200、请求头稳定或本地前缀估算代替。

这里补的是定位证据，不是一般缓存修复。是否存在稳定前缀、上游是否接受会话标识、上游是否报告缓存、实际命中是否提高，分别保留结论。已有统计解释见[模型健康与就绪状态](./模型健康与就绪状态.md)，请求身份契约见[模型会话与缓存隔离](./模型会话与缓存隔离.md)，既有前缀调整见[上下文前缀与缓存](./上下文缓存.md)。

## 离线分析

使用 `scripts/analyze-model-prefix.py` 读取已有日志，不联网、不调用模型。省略 `--log` 时从标准输入读取；可选 `--newapi-safe` 接收事先准备的安全 NewAPI JSON，不接受数据库地址或凭据。例如在仓库根目录执行：

```bash
python3 scripts/analyze-model-prefix.py --log /path/to/eve-wire.log
python3 scripts/analyze-model-prefix.py --log /path/to/eve-wire.log --newapi-safe /path/to/newapi-safe.json
```

日志记录必须以三个 `EVE_MODEL_WIRE_*` 标记之一开头，标记后为单行 JSON；附有时间或服务名前缀的日志需先保留原记录另行提取，脚本不会猜测前缀位置。不匹配标记的行计为忽略。输入要求 `schema_version=1`、固定诊断域、有效进程标识和正整数调用/请求/尝试编号；拒绝重复 JSON 键、无效数值、身份冲突以及内容冲突的重复事件，完全相同的事件去重并计数。无记录或无分组仍可能正常完成解析，`status=ok` 不代表缓存效果通过。

两份输入共用上限：总计 64 MiB、200000 行、20000 条诊断或外部记录，单行最多 1 MiB。超限或格式错误返回固定错误类别并以状态码 2 结束，不输出输入正文或文件系统错误详情；成功输出白名单 JSON，不写回输入文件。

分组要求完整请求记录、已登记用途、存在的目标端点摘要，以及非空 session/thread/cache 三个标识摘要。分组键包含进程、用途、协议、客户端目标和这三个身份摘要；缺项保留为未分组，不能把缺失身份的请求归到同一个公共会话。客户端请求 ID 用于单次关联，不作为稳定分组键。组内按本进程请求编号比较相邻记录，保留每次重试，并分别输出输入、配置和工具是否一致。跨进程内容 HMAC 不比较。

`common_complete_items` 和 `common_complete_item_bytes` 表示从开头相等的完整消息项目及其 JSON 字节总和，不是 tokenizer 前缀或 token 数。逐项列表截断或摘要不可用时只给下界；整个输入摘要相等也不能补出未观测到的逐项数量。配置或工具是否相同另列，不把相同消息自动认定为整个请求可缓存。

安全 NewAPI 输入可以是 `current-cache.json` 形状的 `groups[].rows[]`，或仅含 `request_id_sha256`、`input_tokens`、`cached_input_tokens`、`output_tokens` 的记录数组。前一种读取 `input`、`output`、`cache_present` 和 `cache_tokens`；`cache_present=false` 时缓存数保持未知。缺少请求 ID 摘要的行跳过并计数，不能从时间、模型或其他正文推测它。

外部关联仅接受 `oneapi_request_id.sha256 = request_id_sha256` 精确匹配，不回退到 `upstream_request_id`、客户端请求 ID 或时间近似。没有响应标识记为 `missing_header`，有标识但未匹配记为 `unmatched`，未提供外部文件记为 `not_supplied`。相同外部 ID 的冲突记录，或同一个外部请求被多个本地尝试关联，都会拒绝，避免重复计数。标识由哪一层产生仍需结合真实转站记录确认。

本地用量与外部用量分别统计，不相互填补。缓存字段缺失或 `null` 均保持未知，明确 `0` 且输入为正才是有效零命中；输入为零另列，非法计数或缓存数大于输入数列为无效。加权比例只使用有效请求的缓存输入总量除以输入总量，并同时报告未知、无效及零输入条数。没有有效输入时比例为 `null`，不能把有效子集比例当作全部请求的总体命中率。

## 关闭、持久化与验收

删除开关或设为不启用的值后，新构造的提供方停止输出这些记录。诊断没有新的数据库、后台任务、模型调用或请求重放，不修改现有会话状态；进程随机密钥不会恢复。已由宿主日志系统保存的记录仍遵循原有保留策略，不由开关自动删除。

启用会增加摘要计算和日志开销，应把诊断期间的耗时单独看待。摘要通过流式写入 HMAC 计算器完成，不另复制整份正文；但完整请求及其分项会被多次遍历，每次重试都会计算，CPU 成本随请求字节数增长。512/128 的限制只约束单次日志的逐项元数据，不限制被哈希的请求体大小，也不是进程累计日志配额。日志同步写入标准错误，慢日志接收端仍会影响耗时，轮转和总磁盘限额由现有宿主日志系统负责。本页只说明实现与使用边界，不声明本地测试通过、线上已经启用、NewAPI 零命中原因已经确认或真实缓存率已经改善；这些结论需要对应候选和请求的实际证据。
