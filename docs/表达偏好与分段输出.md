# 表达偏好与分段输出学习

已交付[内置表达训练](./主动提问训练.md)：从用户原文确定性提取简短程度、自然段、问号和有限语气标记，持久保存数值示范并用于后续 Context；支持查看、停止和重置。[交互记忆与明确偏好](./交互记忆.md)通过 `--memory` 开启，以显式命令保存、查看、修正和撤销有来源的偏好。本轮增加[低频偏好候选提炼](./偏好提炼.md)：追加 `--memory-learning` 后，从已保存交互生成候选，经用户明确确认才进入后续 Context。本轮交付[同一轮回复的分段投递](#首版分段投递已实现)：`--segmented` 按自然段把已保存的完整回复分成至多 3 条消息，段间有上限的停顿；分段偏好与节奏学习仍待实现。

训练策略 v3 从用户自然表达学习可观察的写法，结合本会话历史理解回答与明确纠正；当前任务和要求优先。数值不能证明语义、态度、偏好或真人满意度；训练统计与用户明确确认的偏好分别保存，没有跨通道用户映射，统计本身不决定是否分段。

状态：2026-10-05 已实现可信会话隔离、明确偏好及历史、CAS、失败恢复与 Context 包装，并接入有预算、来源和确认期限的模型候选提炼。QQ 只观察新成功且确认送达的普通交互，不补采旧回执；提炼可以处理 Memory 中已经保存、尚未消费的证据。首版规则分段与 QQ/终端投递已实现，但不从交互中学习分段或节奏；跨通道用户映射与语义检索尚未实现。内生反思及可替换规划契约已随 #82、#83 合入；这份计划定义进一步交互学习的范围，不代表已具备 AGI。

## 目标与学习产物

Eve 从有来源的交互记录和用户反馈中学习更自然的表达：语气、称呼、回复长短、先给结论还是先解释、术语密度、举例和提问习惯。同时学习输出组织：是否分段、每段长度、信息分组、停顿位置、何时等待回应，避免所有内容总是挤在一条长消息中。

首个学习产物是有版本和证据的表达偏好及分段策略。统一 Eve 保留共同的身份基线，具体偏好绑定用户；通道只提供格式、长度和投递能力约束。跨通道复用须由受信宿主确认用户映射，不能把两个通道里的同名用户自动当成同一个人。

当前用户请求优先于已保存偏好。用户明确说“简短一点”“别这样称呼我”“先发结论，细节再分段”时，记录原文和范围；用户可以查看、修正、撤销明确偏好，或在下次启动时关闭提炼。模型候选附带自评、证据和首次确认期限，不能把一次回复或用户沉默当作长期认可。模型自评不是经过校准的事实概率；到期不自动撤销已经确认的偏好。

## 交互记忆与更新

学习使用已完成会话中实际保存的用户消息、面向用户的回复及明确纠正，保留 Session、轮次、来源、用户、通道、时间和访问范围。工具内部记录、失败或 Pending 输出不冒充成功交互；模型推断与用户明确偏好分别保存。

先建立事实/经历持久化与基本查询，再交付表达学习。当前记忆通过公开存储接口保存版本化文档，QQ 默认使用 FileStateStore；`--memory`、`--memory-learning` 可与 `--database-config` 配合选择本地 PostgreSQL。Session、Training、Memory、Learning、Cognition 和 QQ 回执共用已选后端，但各自独立提交，没有跨插件事务。数据库入口拒绝静默迁移已有 `state.json`，应选择新目录；已经绑定 SQL 的目录缺少连接参数或更换目标时拒绝启动，详见[PostgreSQL 状态](./PostgreSQL状态.md)。用户明确命令保存为 `UserStatement`；普通交互须实际 Session 完成且 QQ 确认送达，保存为 `CompletedInteraction`。修正和撤销保留原始证据及偏好版本。当前支持 CAS 和失败恢复，未知版本拒绝启动；完整来源检索、迁移和偏好重建仍待后续实现。

显式偏好命令先走确定性规则。QQ 模型提炼按同一可信范围新增的完成交互批量触发：至少 3 条、最多 8 条，完整输入 JSON 最多 32768 字节，同范围冷却 5 分钟，每次进程启动合计最多 4 批，每批最多一次 30 秒无工具请求。批次先保存 Running 和消费证据；失败、空结果及中断都不重试原证据，无新证据时零请求。候选最多 3 条，每条 1024 字节、首次确认期限 7 天；所有候选都须 `/accept-memory` 明确确认，自评高低不会绕过这一步。输入边界、容量与恢复见[偏好提炼](./偏好提炼.md)。

## 定义、实现与组合

已实现的定义层提供可替换交互记忆读取和偏好提炼契约。明确偏好保存适用范围、版本和确认来源；模型候选另保存来源证据、自评和首次确认期限。分段计划契约 `eve-segment-api` 已实现：计划只包含原回复中的有序字节范围、规划器标识和段前停顿，关联的回复、轮次和代际由通道持有；表达策略契约仍待实现。

实现层分别负责持久化与检索、规则/模型提炼、表达和分段规划；模型角色不独立形成另一套人格。组合层按用户和通道选择本轮偏好，作为受限 Context 数据装配，保持稳定 AGENT 前缀和当前轮快照。偏好更新从下一轮生效，不能改变已在途的工具往返或改写事实、目标及权限。

## 同一轮回复的分段投递

优先按语义组织内容，例如“结论 → 必要解释 → 下一步”，允许整体输出、少量自然段或先给一段后等待回答。用户纠正和反馈同时训练分段偏好，不靠固定字符数机械切碎每句话；代码块、命令和紧密关联的信息保留完整边界。

分段属于同一轮回复，不能当作多轮新输入再次调用模型或工具。Session 保留完整回复，投递记录另保存每个片段的顺序和回执；片段不复制成新的执行事实。交付方式可按通道选择完整生成后分段或已有流式输出，但分段策略、模型流事件和通道投递分别使用公开契约。

每轮限制片段数、总字节、队列容量和总投递时间，节奏建议受宿主期限约束。取消、用户纠正和新代回复沿用 Control/Message 代际；每次发送前检查完整代际，关闭后续旧片段并等待在途发送收尾。部分发送失败保留已发/未发/不确定回执，重启不自动重发已确认片段，也不凭缺失回执继续旧输出；与现有 QQ 的 Pending/Unknown 保护一致。

## 首版分段投递（已实现）

`eve --segmented` 与 `eve-qqbot --segmented` 显式开启，默认关闭；未开启时输出与回执格式完全不变。

```sh
./target/debug/eve --state-dir .eve --segmented
./target/debug/eve-qqbot --state-dir .eve-qqbot --segmented --memory
```

**定义层** `eve-segment-api`：`SegmentPlanner` 只返回原文断点与段前停顿。`SegmentPlan::validate` 要求片段按序覆盖全部非空白内容、片段之间只有空白、首尾不含空白、首段停顿为 0，不切开围栏代码块，并满足本轮片段数、单段字节和停顿上限。计划无法改写、补写或删除回复。`plan_or_single` 在规划器失败、panic 或计划无效时降级为整条发送，并给出告警类别。

**实现层** `eve-segment-plugin` 的 `ParagraphPlanner`（`paragraph-v2`）是确定性规则：按空行分块；整段没有空行时只在两行普通句子之间断开。代码块、相邻列表项、单独的标题、分隔线和以冒号结尾的引出句与后文保持在一起；只有标点或表情的块并入前一段。默认不设最小字数门槛，短回复含多个自然段时也分别发送，例如“好。”和“你先说，我听着。”分成两条；单个自然段仍整条发送。自定义组合可以显式设置 `min_chars`，让低于阈值的回复整条发送。超过预算时优先合并中间解释，尽量保留单独的开头结论与结尾下一步。段前停顿为 400 ms 加每字 25 ms，不超过上限。

**组合层**：终端与 QQ 默认最多 3 段、单段不超过 32768 字节、停顿最长 2.5 秒。QQ 平台对同一消息的被动回复次数有限，插件拒绝超过 5 段的预算。只有已完成并保存的模型回复会分段；命令确认、控制提示与训练开关回复整条发送。

### QQ 投递顺序

1. Session 完成后保存回执 `ReplyPending`、完整回复和片段表，首段标为 `Sending`，再次核对代际后写出首段。
2. 每段等待 QQ 回执：成功标为 `Sent`；失败标为 `Failed`，剩余片段标为 `Skipped`，整条回执 `Failed`，不重试。
3. 段间停顿期间可以接收新消息；剩余片段等路由与命令收尾后才继续。写出前两次核对完整代际，`/cancel`、`/add`、`/correct` 或训练开关使旧代失效时，剩余片段标为 `Skipped`，回执 `Failed`，并通知桥接释放该消息。
4. 全部片段 `Sent` 后整条回执才为 `Sent`；交互记忆此时才导入完整回复，部分送达不形成 `CompletedInteraction`。

已发出的片段无法撤回。普通新消息在剩余片段发完或被关闭后才开始新轮。

### 持久化与恢复

片段只保存为完整 `reply` 中的 UTF-8 字节范围及状态，不复制正文。新回复记录规划器 `paragraph-v2`；已有 `paragraph-v1` 记录按原来的断点和状态加载，不重新规划或补发。没有分段记录的回执文档仍为格式 1；一旦出现片段记录写为格式 2，旧版本程序会拒绝读取，不会忽略片段状态。加载时严格校验：片段数 2–8、范围合法且不切开代码块，状态必须是“已发送前缀 + 至多一个当前片段 + 同类剩余”，并与整条状态一致：

| 整条回执 | 片段状态 | 含义 |
| --- | --- | --- |
| `ReplyPending` | `Sent…`，可选一个 `Sending`，其余 `Pending` | 投递未完成；`Sending` 表示是否送达不确定 |
| `Sent` | 全部 `Sent` | 完整送达 |
| `Failed` | `Sent…`，可选一个 `Failed`，其余 `Skipped` | 发送失败或旧代关闭剩余片段 |

违反规则视为损坏，拒绝启动且保留原字节。停止或崩溃后，`ReplyPending` 回执原样保留：已确认片段不重发，未发片段不补发，`Sending` 不被猜测为成功或失败。相同消息 ID 再次到达只结束桥接条目，不重新生成或投递。分段回执与 Session、Memory 仍各自提交，没有跨插件事务。训练窗口统计接受格式 1 与 2，只按整条状态计数。

### 终端

终端先保存完整回复，再显示首段，其余片段按停顿依次显示。显示期间 `/cancel` 停止剩余片段并提示完整回复已保存；`/quit`、Ctrl+C 直接丢弃剩余显示。下一条输入在显示结束后才开始；EOF 会先显示完已保存回复。显示队列不持久化，重启不补显示。

### 验收

- 定义层 5 项与规划器 7 项单元测试：内容遗漏、改写、乱序、首尾空白、代码块切分、预算与降级。
- Node 桥接 4 项新增测试：按序发送原目标、拒绝乱序/重复/越界/混用、失败即止、段间与发送中的结束请求。
- 8 项实际 `eve-qqbot` 进程验收（`connectors/qqbot/test/segment_test.py`）：默认关闭、按序与停顿、记忆只见完整回复、短回复与命令整条、段间取消、段间纠正、片段失败、发送中停止后重启零重发、损坏进度拒绝启动且不清空。
- 2 项实际 `eve` 进程验收：分段显示与完整历史、显示中取消后新输入正常。

替身模型原样返回输入，验证的是投递与恢复边界，不代表真实模型回复的分段质量或用户体验。真实主模型与 QQ 实机效果需要在本地单独评估。

## 分阶段交付与验收

1. 已实现交互证据、明确偏好及查看/修正/撤销入口，验证范围包括跨用户隔离、原文保留、修订竞争和重启恢复；跨通道用户映射与完整来源查询后续交付。`/forget` 撤销偏好但保留历史，不等于物理删除。
2. 已接入低频候选提炼、用户确认及本轮 Context 快照；验收检查未确认不注入、显式纠正和撤销生效、同一证据零重复请求、无新交互零请求。真实模型候选质量和用户表达体验仍需本地 QQ 交互评估，结构化候选与离线用例不证明语义正确。
3. 已接入规则分段规划并装配终端和 QQ；验证段落连贯、代码块完整、片段预算、段间取消、旧代过滤、部分发送失败和恢复零重放。下一步从用户明确反馈和偏好中学习是否分段、段长与停顿，并提供会话级查看、修正和关闭。
4. 以同任务的表达对照、用户明确反馈和可复验场景评价自然程度、打断次数及任务完成质量；不以模型自评“像人”或多发几段消息作为 AGI 能力证明。

具体实现按独立 `codex/` PR 交付。已有反思记录保留为带来源的内部记录；内部反思使用独立空 Context，不读取聊天训练或明确偏好。当前可从普通交互生成待确认候选，确认只写一次 Memory，不另改写 Learning 接受状态；候选不会自动成为用户偏好；分段由宿主开关和规则规划决定，暂不读取偏好。
