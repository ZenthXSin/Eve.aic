# 子代理持久恢复

`AgentService.initialize()` 在准入前重放同一业务目录的事实日志，重建会话、任务、消息、
通知、未读/待处理计数与已读水位；正文仍是 `bodies/<sha256>.json` 原件，按需读取。
重放、事实投影、原件验证与 transcript 游标位于 `services/runtime/agent-restore.ts`，
与实时提交共用一份投影，不新增契约字段或修改旧事件格式。

## 续跑规则

- 已有 `reply` 的任务不再运行；已有 `cancelled` 但未提交回复的任务只补取消回复。
- 未取消且没有回复的任务自动加入原会话的 FIFO 链，不同会话可以并行。 恢复任务与新消息共用队列；重复
  `resume()`/相同 jobId 的 `send()` 共用同一在途任务， 不重复提交 `accepted`。
- 模型上下文包含原任务消息、之前已完成任务的上下文及当前已保存的全部 transcript。 游标按 assistant
  轮次及依次配对的工具回执定位，只执行没有回执的工具后缀。 模型编号仍是
  `<jobId>_model_<轮次>`，工具编号仍是 `<jobId>_tool_<轮次>_<索引>`。
- 最终 assistant 的 `step` 已提交但 `reply` 未提交时，直接从该原件补回复，不再调用模型。
  若模型响应已在宿主账本保存而 assistant step 未提交，优先复用该响应。
- `RuntimeEngine` 先用 `initialize(false)` 恢复子代理及可补的回复，再对账宿主动作回执； dispatch
  就绪后才 `resume()`，避免续跑被启动期间的 unavailable 错误终结。
- 所有已提交正文和步骤先验证再补写或续跑；缺失、篡改、工具回执错配均报错并保留原件。
  初始化失败后的关闭不会把尚未验证的任务批量标成取消。

## 边界

已记录回执的工具不重执行。工具已经发生但其 step 尚未提交的窗口，仍依赖宿主相同动作
编号的账本去重；没有独立动作账本的自定义 hooks 不提供跨该窗口的 exactly-once 保证。
宿主已准入但没有真实结果的原动作继续保持 unknown，不冒险重发；因此恢复任务可能得到 unknown
工具回执或以模型 unknown 结束，而不是保证每个任务必然成功。

这是同一持久业务目录上的代码重启/换版恢复，不迁移目录、不重发已完成或取消的任务。 现有显式取消及
`close()` 的取消语义不变；旧版本已经写下终态 unknown/cancelled 回复的 任务不会被追溯复活。

## 回归

`tests/agent_restore_test.ts` 覆盖 admission/started/各工具回执前缀/最终 step 的中断点、
稳定动作编号、已存模型响应、重复恢复与发送、FIFO/并行、配置快照、已读水位、已完成和 已取消任务，以及
RuntimeEngine 就绪后续跑与 unknown 动作对账。 `tests/agents_test.ts`
同时保留原长文、工具配对、RPC、原件篡改及最终回复补交回归。
