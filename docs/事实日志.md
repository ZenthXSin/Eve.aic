# 事实日志的长期保存与分页

`FactJournal` / `ConsciousJournal` 的 `events/0000000000000001.json` 等原件只追加保存。
启动逐条检查序号、摘要及前一份摘要，不把全部正文留在内存；常驻索引每条仅保存 32 字节摘要，
按 4096 条分配区块。目录遍历只计数，不累积文件名列表；缺号、断链、未知文件、未完成临时文件、
符号链接或原件过大都会拒绝恢复，并保留现场。恢复仍需逐条读取验证，耗时随历史增长。

旧调用的 `journal.events` 保持数组读取行为：支持长度、下标、迭代、`slice`、`filter` 等。
每次取记录都会读取原件并对照启动时的摘要索引，修改返回值不会改动原件；直接改数组会拒绝。
这消除了日志对象长期持有全部正文的问题。调用方主动 `filter`、`map` 或展开整个数组时，
结果仍会占用对应内存，长历史调用应改为分页或逐条处理。

```ts
const first = journal.readPage(); // 默认从序号 0 后读取，最多 8 条。
const next = journal.readPage(first.nextSeq, 8, first.throughSeq);
```

`throughSeq` 固定当前分页快照上界；之后追加的记录留到下一轮快照读取。
每页最多 128 条，正文合计以 8 MiB 为目标；超过此大小的单份原件独占一页。
单份记录最多 12 MiB，可完整保存允许的 8 MiB 二进制原图展开后的 base64，仍小于 RPC 的
16 MiB 上限。因此不能假设每页总能达到要求的条数。
使用返回的 `nextSeq` 继续读取，并以 `hasMore` 判断是否到达快照末尾。

单写文件锁覆盖恢复和提交。已接收的提交依次落盘后，关闭才释放锁；关闭开始后不再接收新提交。
若下一份目标原件意外存在，提交会失败并保留该文件，不会将其覆盖。

远端意识流在实例目录的 `remote-mirror/` 保存经过验证的镜像，使用同一只读惰性数组。
`importOriginal` 保留稳定出口原始的序号、时间和摘要，先检查前件，重复原件幂等，历史冲突拒绝。
首次启动逐页导入；重启先重读镜像尾锚验证远端未落后或分叉，再导入缺失增量。
远端成功提交后才写本地镜像；未知回执或镜像写失败会停止本实例继续提交，重启从稳定出口原件恢复，
不会重新执行那些已经发生的事实。损坏镜像或未完成临时文件保留并拒绝启动。
