# 本机 Web 控制面板

本切片将面板从后续计划推进为可启动入口。`eve-qqbot --web-listen 127.0.0.1:8765` 在同一个受信 QQ 宿主中启动面板，默认关闭。先在宿主环境设置独立 `EVE_WEB_TOKEN`（32–256 字节可见 ASCII），浏览器访问启动输出的 `EVE_WEB_READY` 地址并输入令牌。令牌不是模型或 QQ 密钥，不放在 URL、命令参数或页面源码中。

面板首版提供 QQ 通道状态、接收/完成/发送/失败计数、当前任务分页、持久会话分页与轮次正文，以及针对完整代际的取消准入。任务列表包括已经准入但尚未建立 Session 的任务；会话列表包括已有历史。会话详情默认最近 25 轮，最多每页 50 轮，每段正文最多显示 8192 字节并标记截断，原始记录不改动。当前 SessionService 仍返回完整快照，面板随后做有界投影；读取成本会随该会话历史增长，分页不会缩小后端整份快照的复制。只展示用户输入与最终助手文字，不返回工具调用参数、工具结果、系统上下文或底层错误正文。

## 本机访问与配置

```bash
# 先在当前环境中设置专用 EVE_WEB_TOKEN；不要在共享日志中打印令牌。
cargo run -p eve-app --bin eve-qqbot -- --state-dir .eve --web-listen 127.0.0.1:8765
```

QQ 和主模型仍需要原有宿主配置。`--web-listen` 只接受环回 IP，支持 IPv4/IPv6 和端口 0（系统分配），不接受通配地址或域名；访问时使用输出的精确 IP 与端口。本服务校验 Host 与 Origin，无跨域授权，不跟随代理头、不提供公网绑定。远程用户需在实际机器上自行建立受控的本地转发并保持相同 Host；公网 TLS、账户/权限和多用户部署未在本切片实现。

页面静态资源可在未登录时加载，所有 `/api/` 都需要 `Authorization: Bearer`。令牌仅保存在当前页面内存，退出、401 或页面卸载后清除，刷新页面需要重新输入。面板服务保存随机密钥及 HMAC 标签作校验，不另外保留令牌正文，不把令牌写入日志、状态或 Node 桥接环境；重启需重新提供宿主环境中的令牌。所有响应禁止缓存，页面不加载 CDN、外部字体或第三方脚本，动态文字通过纯文本节点显示。

API 设置 5 秒异步请求期限、16 个同时处理请求和 16 KiB JSON 请求体上限；响应投影有分页与正文界限。同步 PanelService 调用期间不能被异步期限抢占，替换实现须及时返回。这是可信本机管理入口，不构成对恶意本机进程的资源隔离或防拒绝服务系统。整个浏览器会话拥有该宿主可见的会话管理权限，尚未提供按 QQ 用户分配的浏览器账户。

## 公开契约与组合

- `eve-web-panel-api::PanelService` 定义无 HTTP 的状态、分页、会话详情与精确代际取消契约。
- `eve-web-panel` 实现环回 HTTP、令牌与来源检查、静态页面和自身停止，不调用模型或直接操作 Kernel。
- `eve-app` 在 QQ 宿主中组合已有 `SessionService`、`ControlService` 和通道状态；不旁路读取数据库，不从 HTTP 创建 Provider 或执行工具。
- `SessionService::list_keys` / `ControlService::list_keys` 为兼容现有自定义实现新增默认不可用方法。内置实现按 `session_id` 字典序、独占游标、每页 1–100 项枚举完整可信身份；`BTreeMap.range` 有界读取，不将单页读取描述为跨页事务快照。停止后旧服务不可用。

接口为 `GET /api/status`、`GET /api/sessions?after=...&limit=25`、`GET /api/tasks?after=...&limit=25`、`GET /api/judgments?before=...&limit=25`、`GET /api/goals?after=...&limit=25`、`GET /api/goal?id=...`、`POST /api/memory/scopes {after?,limit?}`、`POST /api/memory/scope {scope}`、`POST /api/memory/evidence {scope,id}`、`POST /api/memory/learning {scope}`、`POST /api/session {key,before?,limit?}` 和 `POST /api/cancel {target:GenerationKey}`。错误使用固定类别，不带密钥、输入或原始 Provider 报错。提交取消必须携带浏览器所见的完整会话、用户、任务、启动 epoch 和代号；代已变化时返回冲突，不偷换成最新任务。

## 实时判断诊断

“判断诊断”页显示本进程启动后消息关系判断器的最近 128 次实际调用。只有任务进行中到达的消息才会进入判断；空闲时的新消息不调用判断器，因此不会出现在列表中。三种 `--message-judge` 方式都记录：`off` 只有明确命令规则阶段，`primary` 和 `jev` 还包括辅助/主模型阶段、本地调用尝试与回退原因。

- 定义层：`PanelService::judgments(before, limit)` 新增默认不可用方法，旧实现继续编译并返回 503，不以空列表冒充“没有判断”。HTTP 每页 1–50 条，`before` 是上一页给出的序号，必须大于 0；未知或重复参数返回 `invalid_query`。
- 实现层：`eve-message-diagnostics::RecordingRelationJudge` 包装任意判断器，为每次调用建立独立有界收集器，同时把事件转发给外层观察者；`RecentRelationJudgments` 是有界内存环，超出容量移出最早记录并计数。
- 组合层：`RelationPlugin::with_judge_decorator` 让宿主在启动时包装最终判断器；包装位于停止检查之内，停止后仍不可用。`eve-qqbot` 只在开启 `--web-listen` 时安装记录器，面板只读不写。

结果分三类：“已判定”表示判断器返回通过校验的决定，最终动作仍由路由器按当前代际、取消状态和置信度决定；“判断失败”给出不可用、格式无效、超时或内部异常；“已丢弃”表示调用方在判断结束前丢弃了它，例如明确 `/cancel` 抢先、期限或停止，不代表远端已停止。步骤按开始顺序列出，缺少终态时显示“未观察到结束”；观察不完整、溢出或判断器不支持观察时计数为空，页面不显示伪造的零。调用尝试不是网络请求、token 或费用。

记录只含序号、本机结束时间、本机耗时、意图/失败枚举、阶段、调用尝试与回退原因；不含会话、用户、任务、消息 ID、正文、模型解释、模型名、URL 或密钥。记录只在内存中，不写 StateStore 或文件，进程重启后清空并从 1 重新编号，旧记录不补写、不重放判断。写入只在短锁内复制内存；锁中毒时停止记录且读取返回不可用，不会影响业务判断。

## 认知目标只读页

“认知目标”页查看 `--cognition` 保存的待办、目标状态、来源记录，以及当前和历史反思草稿。没有以 `--cognition` 启动时两个接口返回 503，页面提示未开启，不以空列表冒充“没有目标”。

- 定义层：`PanelService::goals(after, limit)` 与 `goal(id)` 为默认不可用方法。列表按目标 ID 升序、独占游标、每页 1–100 项；详情不存在返回 404。目标 ID 与认知契约规则一致，空、超过 256 字节、首尾空白或控制字符返回 `invalid_query`，不进入宿主读取。
- 组合层：`eve-qqbot` 启动认知后，用管理句柄为面板绑定一个 `ReadAccess::Internal` 读取句柄；面板只持有 `CognitionReader` 和已有 `SessionService`，没有 `replace` 等写入能力，不能新增或修改目标、提交反馈、唤醒规划或重试执行。每次请求读取一次当前快照，各页不是同一事务快照，页头给出读取时的认知状态修订。
- 列表只显示顶层目标；内生反思子目标放在父目标详情中。父目标已不在状态中的反思子目标仍单独列出并标明所属父目标，不被隐藏。列表正文最多 512 字节，详情最多 8192 字节，并标注截断。

详情给出状态、来源、可见范围、优先级、预算、有效期、等待/阻塞原因、执行记录与执行反馈，以及与该目标直接关联的最近 20 条来源记录（每条摘要最多 2048 字节，更早记录只给数量）。用户反馈和文件片段是保存时的外部数据，页面注明未经验证。可见范围为单个用户时显示宿主绑定的用户摘要标识（与会话页一致，如 `qq:` 加 SHA-256），不显示平台原始 ID。

反思草稿列出以该目标为父目标的全部子目标，“当前草稿”在前，其余按对应父目标修订从新到旧。“当前”只由 `current_reflection` 按父目标当前修订与原子派生证据精确判定；派生记录残缺或矛盾时详情标为 `inconsistent`，不把任何草稿标为当前，也不退回旧草稿。对应父目标修订从派生输入记录读出，记录不可用时显示未知，不猜测。草稿正文只从子目标执行轮次中最终助手回复解析：子目标已完成且满足结构校验才显示“草稿已保存”；会话结果缺失、读取失败或格式不一致显示“草稿正文不可用”，不显示正文，也不视为已保存。草稿仍是模型建议，子目标完成不代表父目标或现实目标完成，页面始终标注“尚未验证”。

面板读取不写 StateStore；重启后从持久认知状态与会话历史重新读取。认知或会话状态损坏仍按原有规则在启动时显式失败，面板不清空或修复数据。

## 记忆偏好只读页

“记忆偏好”页查看 `--memory` 保存的偏好、版本历史与来源。没有以 `--memory` 启动时三个接口返回 503，页面提示未开启。

- 定义层：`PanelService::memory_scopes(after, limit)`、`memory(scope)` 与 `memory_evidence(scope, id)` 为默认不可用方法。作用域含 channel、session_id、user_id 三个字段，因此三个接口都用 JSON 请求体；未知字段、空值、超过 256 字节、首尾空白或控制字符均被拒绝，不进入宿主读取。
- 组合层：宿主把记忆管理句柄包进只暴露“枚举作用域”和“读取作用域快照”两个方法的 `MemoryView` 后交给面板；确认、更正、撤销与导入交互不在其中。记忆实现对未知作用域返回空快照，面板先确认作用域已持久保存，不存在时返回 404，不把输错的作用域显示成“没有记忆”。
- 作用域列表按 (channel, session_id, user_id) 升序、独占游标、每页 1–100 项，给出该作用域修订、来源数、已确认与已撤销偏好数，不含正文。各页不是同一事务快照。

作用域详情按偏好 ID 列出全部偏好（数量受记忆存储上限约束）：当前正文（最多 4096 字节）、状态、最新修订、是否生效，以及按修订从新到旧的历史版本。每个版本给出状态、时间、正文预览（最多 512 字节）和引用的证据 ID 与类型；证据已不在快照中时标为“来源记录缺失”。只有最新且已确认的版本会进入对话上下文；撤销与更正都保留历史和来源，页面如实标注。

来源正文需操作者在某个版本上单独点“查看来源”才读取，与 `eve-memory evidence --include-content` 的显式查看一致。来源区分“用户明确声明”和“已完成对话”：对话来源把当时的用户输入和助手回复分列，每段最多 2048 字节并标注截断；助手回复是历史内容，不是已核实的事实。来源同时列出引用它的偏好版本（最多 50 条，另给总数）。接口不返回平台消息 ID；作用域标识与会话页一致，是宿主绑定的 `qq:` 摘要。

### 学习候选

以 `--memory-learning` 或 `--self-learning` 启动时，记忆详情下方显示该作用域的偏好提炼批次、候选与学习决策；未开启时 `POST /api/memory/learning` 返回 503，页面注明未开启。宿主把学习管理句柄包进只提供快照与决策读取的 `LearningRead`，面板不能记录决策、预留批次或确认候选。

- 与 QQ `/memory-decision` 共用同一组核对函数和读取顺序：先固定记忆快照，再读只追加的决策账本与学习快照，校验候选属于本作用域批次、只引用批次内真实已完成对话、账本序号连续且与候选一致。任一校验失败时整体返回 503，不显示部分结果。
- “实际保存”只按记忆真实历史核对：首版正文与来源须对应真实用户确认命令，或自主模式下候选所引用的已完成对话；更新类决策还须在目标偏好中找到对应的后继版本。决策记录只是提交前的意图，有确认决策但记忆中没有对应历史时仍显示“未保存”。
- 每个候选给出正文（受学习契约上限约束）、模型自评（0–100，不是校准概率）、引用对话数、生成时间与首次确认期限；未保存且已过期限标为“已过期”。决策新的在前，最多 8 条，给出动作、理由、策略版本与读取时的记忆修订，另给总数。
- 批次只显示状态、失败类别、时间与证据/候选数量，不显示提炼输入正文。页面注明当前是自主学习还是需用户 `/accept-memory` 的手动模式。

记忆页同样只读，不写 StateStore，重启后从持久记忆状态重新读取；记忆状态损坏仍在启动时显式失败。偏好撤销、训练开关等管理操作需单独的公开管理契约、陈旧版本检测与确认流程，未在本页提供。

## 控制和恢复语义

取消返回 HTTP 202 只表示准入或已经准入/结束，不能据此声称模型已停、工具已析构、历史已保存或副作用回滚。面板随后刷新已有 Control 状态，显示 `Cancelling`、`Finished`、`Blocked` 及已知提交状态；工具数未知就显示未知。现有控制契约的 `CommitState::Failed` 表示失败轮次已经保存，页面显示“失败记录已保存”；提交失败留在 `Pending`，显示“提交未完成，需处理”，不能混淆执行失败与保存失败。读详情和重复取消不会自动开始新代。面板没有新任务、重试、删除状态、重置训练或停服务器按钮。

面板本身没有业务持久化，关闭浏览器不停止 QQ；宿主退出时先撤销 HTTP 准入、等待服务器收尾，再按原 QQ 路径取消轮次、等待保存并停止桥接，最后停止 Kernel。面板只管理自己持有的异步服务任务，不读取 PID 文件或向进程组发信号。HTTP 启动失败或运行异常会让宿主走既有统一收尾，不留无控制的后台实例。

重启后面板从 Session 服务读取已保存历史，旧 Control 代不会恢复，旧页面携带的 epoch 不再有效；旧 Pending/未确定状态沿用原恢复语义，不补发 QQ 回复、不重放工具或自然判断。文件/SQL 损坏仍显式失败，不清空状态。

## 后续顺序

本机状态、会话、取消操作、实时判断诊断、认知目标与记忆偏好只读页已交付；接下来推进偏好撤销等范围明确的管理操作与受控配置编辑。判断置信度数值与模型健康状态尚未进入公开观察契约，页面不显示。远程认证授权、事件流和人工批准任务执行在其后实现；不把未实现的暂停恢复、重试或模型健康数据画成可操作按钮。

验收由专门子代理执行真实环回 HTTP、实际 Eve+QQ 替身子进程和浏览器交互，结果记录在 PR 中。正式 QQ 实机测试仍在本地进行，本切片不通过工作流连接真实 QQ 或真实模型。
