# 消息判断诊断

定义层 `eve-message-api` 新增 `RelationObserver`、`RelationObservation`、`RelationStage`、`RelationAttempt`、`RelationOutcome` 和 `FallbackReason`，以及兼容方法 `RelationJudge::judge_observed(input, observer)`。现有实现只实现 `judge` 仍可运行；默认观察方法发出 `Unsupported`，不假装具备测量能力。包装实现必须转发观察方法，`ActiveJudge` 和宿主 `JevRoleJudge` 已接线。

实现层 `eve-message-diagnostics` 提供 `RelationObservationGuard` 与 `BoundedRelationDiagnostics`。每个调用创建独立收集器，最多 64 条事件；溢出、未知覆盖或开始/终止不匹配时计数为 null。正常结束显式记录结果，Future 丢弃时 guard 记录一次 Dropped；观察器 panic 由公开发送函数隔离，不返回到业务判断，不将 panic payload 收集到诊断事件。进程已有的 panic hook 仍可能输出 payload，本契约不替换或屏蔽该 hook。回调必须短时、非阻塞，不得在其中执行 I/O 或等待业务结果。

规则阶段由 `RulesJudge` 记录；`FallbackJudge` 只记录 Auxiliary/Primary，避免重复。辅助判断的回退原因按实际分支记录，优先级为判断失败、非法决策、含混、低置信；直接主模型模式没有失败回退事件。阶段耗时为本地开始至结果/丢弃的经过时间，单位微秒，不表示服务端计算时间。

`ClassifierCall` 是 Jev 通过本地 HTTP 客户端发送并读取有界结果的一次调用；并发槽满或发送前配置/输入失败时不增加。Jev 显式禁用重定向和 reqwest 重试。`ModelProviderCall` 是一次公开 `LlmProvider::complete` 调用；它可能由自定义 Provider 在本地实现，也可能内部发起多个网络请求。其 Completed 只表示 Provider 返回，后续消息 JSON 校验仍可能失败，最终结果看外层阶段。两类调用都不能当作网络请求、远端收到请求、token 或计费计数；准确网络指标需未来单独接入传输层契约。

超时层级须分别阅读：FallbackJudge 半期限超时会产生 Auxiliary Timeout，同时内层 adapter guard 因 Future 被丢弃记录 Dropped。外层总期限也可能先丢弃 Primary。不得将这些终态相加作为失败任务数，也不得从 Dropped 推断远端停止。每例最终错误仍由评估报告的 `error` 表示。

诊断事件仅含有限枚举、计数和时间，无会话、用户、任务、消息 ID，无正文、模型解释、模型名、URL 或密钥。收集器没有全局状态、磁盘文件或恢复动作。宿主只在显式评估调用中生成报告；不自动启用 QQ 判断或真实模型，不重放历史判断。报告版本 2 与样本版本 1 分开演进。
