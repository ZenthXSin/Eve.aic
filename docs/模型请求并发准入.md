# 模型请求并发准入

显式选择 `primary` 或 `auxiliary_small` 的核心解析器现已执行对应 `runtime.models.<角色>_max_concurrent_requests`，默认值为 1。同一配置服务实例、同一角色的对话、摘要、后台和子代理共享通道，不能因创建另一个用途解析器、换模型或轮换凭据而另领并发。不同角色和不同配置实例独立；未选择角色的旧 OpenAI 直接装配保持原有行为。子代理槽位、工具步数和自主预算仍分别约束。

## 契约、实现与组合

公开 `LlmProvider` 契约不变。`eve-model-concurrency` 提供原生 `ConcurrencyGate` 装饰器，完整转发普通、JSON 和流式接口；应用组合层按可信配置服务身份绑定主/辅角色。只有结构有效的 Provider 和凭据选择才能更新共享限额，坏候选不能放宽旧队列。目录只保存弱引用，没有在途调用或客户端持有时可回收。

准入按排队顺序进行，不根据用户正文建立新通道。等待仍包含在调用方原期限内，不建立额外请求、不重领或退回预算。取消排队时移除该项，不调用底层 Provider；正常返回、错误、取消、流式中断或 Provider panic 均释放位置。准入在前缀探针外，尚未进入 Provider 的等待不会被记录成已发送的请求前缀。

## 变更与失败

新有效解析采用更高配置修订的限额。降低上限不强杀在途调用，必须等活动数低于新值才能进入；提高后唤醒等待者。旧选择不能用旧修订重新放宽限制，同一修订给出不同限额直接报错。模型、端点、协议和凭据仍沿原轮次快照，不因限额更新而切换在途客户端。

零限额、编号耗尽和内部状态不可用明确失败；不把请求说成完成。等待期限到达沿原调用方超时结局处理，不追加传输重试、工具调用或自动恢复预算。提供方原有有界重试可以占用已准入的位置，计数表示未结束的 Provider 调用，不是 TCP 连接或供应商收费统计。

队列仅为进程内请求准入，不另建持久任务。停止时由原宿主取消调用，队列不重放 HTTP；重启恢复原配置并建立空的准入状态，目标、会话、检查点和预算恢复仍由各自账本负责。

## 诊断

本机管理面板的各模型用途显示当前配置模型、共享角色、已准入数、等待数及上限。只读接口 `/api/readiness` 的 `roles[].admission` 分别给出有效配置修订与观测修订，缺少观测时返回空计数，不伪造为零。读取不创建队列、不修改限额或保存配置；不返回请求内容、用户身份、端点或密钥。不同用途展示同一角色共享计数，不能将它们相加。

Jev、embedding 和自定义宿主沿各自现有并发契约；本功能不声称限制其他进程、任意插件 HTTP 或所有外部服务。

## 验证

原生测试覆盖公平排队、队首取消、在途取消、排队超时、限额增减、旧修订、错误及 panic 释放、流式生命周期、JSON 协议和四线程 100 次突发。组合测试核对配置身份/角色隔离、弱引用回收及无效候选不改变旧限额。

实际 QQ 宿主验证三个子代理在限额 1 时一项在途、两项等待，释放后只发出预期五次请求；另验证显式限额 10 和旧装配均可十个子代理并行。诊断读取不写配置，桌面及手机浏览器检查显示和宽度。所有模型和平台均为本地替身，不代表正式 QQ 或真实供应商质量。
