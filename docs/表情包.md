# 表情包

参考 MaiBot 的表情包收集与发送，但融入 Eve 已有的识图与分段回复：表情包只从用户**直接发来**的图片里收集，经视觉模型审看确认是表情包才收下；对话中模型觉得合适时用 `send_sticker` 按心情挑一张，跟在回复文字后面作为图片发出。默认关闭，用 `--stickers` 开启，并且需要同时开启识图（`runtime.vision.enabled`）。

## 收集与审看

识图下载成功、不超过 512 KiB、且是消息本身附带（不是引用消息里）的图片，交给表情包库。库按 SHA-256 去重，待审看至多 20 张、收下至多 500 张，满了就不再收。后台逐张请视觉模型（模型用途 `sticker`）判断：是不是网络上流传的梗图、动图、贴纸或反应图；个人照片、自拍、截图、文档、证件、二维码以及含个人信息或不当内容的图都不算，拿不准也不算。是表情包时记下简短描述和 1 到 3 个心情（开心、赞同、无语、惊讶、难过、生气、害羞、疑惑、加油、晚安），否则**立即删除图片字节**，只留摘要，以后不再收这张图。审看输出不合格按“不是表情包”处理；模型暂时不可用时图片留在待审看里，冷却 60 秒后再审。

## 发送

开启后对话里多一个工具 `send_sticker(mood)`。它从这个心情的表情包里挑用得最少的一张，记在本轮；没有对应心情时返回 `chosen=false`，模型照常回复。回复文字全部送达后停顿 0.8 秒，通道把这张图作为**同一条用户消息的被动回复**上传发出（与正文共用 QQ 被动回复条数，带邀请时不附带）。表情包失败不影响已送达的文字，也不重发、不改走主动消息；正文失败时表情包不发。

热配置 `runtime.stickers`：`collect`（`EVE_STICKER_COLLECT`）控制收集与审看，`send`（`EVE_STICKER_SEND`）控制是否允许发送，默认都开启。

`send_sticker(action="status")` 只查询实际收集/发送开关和待审、已收下、已拒绝数量，不发送图片，也不修改图片使用次数。审看请求显式使用 JSON 对象模式，审看规则同时随图片提供；对话工具说明明确宿主具备自动收集、审看和保存能力，不能因库为空断言无法收藏。

## 持久化与恢复

- 表情包库在状态目录 `stickers/`：`index.json` 记录每张图的编号、摘要、媒体类型、状态（待审看、已收下、已拒绝）、描述、心情与使用次数，图片字节在 `blobs/`。索引先写临时文件、同步后原子改名；收下新图时先写字节再写索引，删除时先写索引再删字节，中途退出只会留下没有索引的孤立文件。索引损坏、字段不合格或版本不兼容时拒绝启动，原文件保留。
- 本轮挑选的表情包只在内存里等这条回复带走，进程退出即失效。
- QQ 回执新增 `sticker`（路径与状态），用到时回执写**格式 5**。写出前先记为发送中，送达或失败写回结局；重启后待发或发送中的表情包都不补发。监督器认识格式 5，表情包待发或发送中时不视为空闲。只认识格式 1–4 的旧程序读到格式 5 会拒绝启动并保留原字节；开启过 `--stickers` 后降级需先升级回来。

公开契约在 `eve-sticker-api`（`StickerLibrary`、`StickerReviewer`），默认实现 `eve-sticker-plugin`（`FileStickerLibrary`、`ModelStickerReviewer`），QQ 组合在 `qq_stickers`；通道只通过 `QqStickers` 取本轮选好的本地路径。
