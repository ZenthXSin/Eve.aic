# 兴趣观察与学习目标派生

[首个自主学习目标](./自主学习首个目标.md)（#134）的第一个切片：用户只在普通聊天里随口说一次兴趣，Eve 记下有来源的兴趣，并派生一个低优先级、可解释的后台学习目标。本切片只交付“观察 → 记忆 → 派生 → 后台反思”。领域知识、实践验证、技能固化与主动跟进属于后续切片；派生目标的反思只保存草稿，不代表已经学会或完成任何事。

## 启用

```bash
./target/debug/eve-qqbot --state-dir .eve-qqbot --interest-learning
```

`--interest-learning` 默认关闭，开启后同时开启 `--memory` 与 `--cognition`。同一会话的观察默认间隔 5 分钟，可用 `--interest-cooldown-ms 0..86400000` 调整。观察请求复用主模型配置与 `EVE_OPENAI_API_KEY`。

- `/interests`：查看本会话记录的兴趣、最近一句原话及学习目标状态。
- `/forget-interest 兴趣ID`：撤回兴趣并取消对应学习目标。

关闭时两条命令都回复“兴趣观察未启用。”，不读写任何状态。

## 观察什么

只观察已经送达用户、并保存在记忆中的 `CompletedInteraction`；`/` 命令、取消或投递失败的轮次不会进入。每个作用域有新交互时，宿主先把批次保存为 `Running`，再发起一次无工具请求，期限不超过 30 秒。批次包含至多 8 条交互和至多 16 个已记录的活动兴趣（用于关联与撤回）。

观察器只能记录用户本人明确说出的四类陈述：

| 类别 | 含义 |
| --- | --- |
| `interest` | 对某个主题、活动或领域的兴趣 |
| `experience` | 相关经验或现有水平 |
| `difficulty` | 遇到的困难或不会的地方 |
| `withdrawal` | 对已记录兴趣明确表示不再感兴趣 |

宿主逐条核对：

- 每条引用必须是所引交互**用户原文**的连续片段，只忽略空白差异，不能改写、拼接或取自助手回复。不合规的整批输出记为 `InvalidOutput`，不保存任何兴趣。
- 新兴趣至少含一条 `interest`。撤回只能针对批次列出的已有兴趣，且不夹带推断。
- 模型对“用户可能需要什么帮助”的推断单独保存为 `inferences`，在目标描述中标注“未经用户确认，不是任务”。它不能冒充用户指令。
- 同名新主题（忽略空白与大小写）并入当前活动兴趣，不另建记录。

观察规则与领域无关，系统提示不含任何游戏名或固定关键词。Mindustry 只是首个验收场景；测试同时用水彩画等留出领域验证同一契约。

## 学习目标

派生器读取兴趣记录，确定性地同步认知目标，不调用模型：

- **来源与身份**：目标 ID 由主体与兴趣 ID 确定。来源为 `Inference / interest.learning / 兴趣ID`，可见范围为该用户，验证标记为 `interest-learning:v1`。它不是用户待办，不出现在 `/goals`，用户也不能对它提交 `/goal-feedback`。
- **描述**：使用固定结构，写明“由兴趣观察派生，不是用户下达的任务”、派生原因（用户明确表达的兴趣或困难，以及 Eve 尚未登记该主题的已验证知识或实践），并逐字列出原话及来源证据 ID。
- **状态**：优先级 30（低于用户待办的 50），状态为 Waiting，零工具预算。
- **新陈述**：兴趣有新陈述时，更新描述并提高目标修订，由反思重新规划。
- **撤回**：兴趣撤回时，等待中的目标转为 Cancelled；未派生过目标的撤回兴趣永远不派生。已取消、阻塞或完成的目标结论不改写。
- **冲突**：同 ID 但来源不符的目标被视为冲突，派生器拒绝改写，后台停止，并保留状态。
- **后台推进**：开启兴趣学习时，QQ 宿主把 `Inference / interest.learning` 加入反思准入范围。派生目标与 `/goal` 待办一样，可在用户之后不发消息时由后台反思一次，受 `--cognition-max-executions` 预算约束。反思结果只是草稿。

## 持久化与恢复

兴趣账本 `eve.interest/interests.v1` 经公开 StateStore 保存，文件与 PostgreSQL 后端语义相同。它保存观察批次（输入、状态、模型输出与逐条应用结果）和兴趣记录（陈述、推断、修订、状态）。

| 情况 | 行为 |
| --- | --- |
| 保存 `Running` 失败 | 不请求模型 |
| 已请求模型但结果保存失败 | 报错，关闭账本句柄；下次打开读到实际提交结果 |
| 重启发现 `Running` 批次 | 记为 `Interrupted`，先保存再公开，不重放，不伪造完成时间 |
| 观察失败、超时、取消或空结果 | 这批交互已消费，不重试 |
| 已关联的兴趣在保存结果前被撤回 | 该更新记为 `Rejected/NotActive`，不复活兴趣 |
| 单条兴趣普通陈述达 15 条 | 新陈述记为 `Rejected/StatementLimit`；保留第 16 个位置，保证撤回总能保存 |
| 兴趣总数达 64 或批次达 128 | 新兴趣记为 `Rejected/InterestLimit`，或停止新观察；不淘汰旧记录，已有兴趣继续同步目标 |
| 兴趣已保存、目标尚未同步时退出 | 下次启动先核对一次并补齐；目标 ID 确定，不会重复派生 |
| 认知修订冲突或事件容量不足 | 本次暂缓，下一轮重新读取再核对，不调用模型 |
| 记忆回退或已观察的交互被改写 | 视为冲突，后台停止，不把旧交互当新输入 |
| 账本损坏、有重复键、引用无法在原交互中找到、版本未知 | 拒绝启动，保留原字节，不清空 |

撤回命令按“会话 + 消息 ID”生成证据 ID。重放同一命令或撤回已撤回的兴趣都零写入。兴趣保存与目标同步分属两个插件，没有跨插件事务；同步以兴趣账本为准，重启后自动补齐。

## 分层

| 层 | 内容 |
| --- | --- |
| `eve-interest-api` | 批次、陈述、兴趣记录、更新结果与容量；可替换的 `InterestObserver`、`InterestAdmin`、`InterestGoalDeriver`；纯函数 `validate_updates` |
| `eve-interest-plugin` | 持久账本与启动恢复；`ModelInterestObserver`（一次无工具请求，严格 JSON）；`LearningGoalDeriver`（只改写兴趣来源的目标） |
| `eve-app` | QQ 后台扫描与派生、命令、反思准入扩展；`run_qqbot_with_interest_observer` 可替换观察器 |

## 验收边界

- 账本、派生器与观察器有 Rust 测试。
- 真实 `eve-qqbot` 进程测试（`connectors/qqbot/test/interest_test.py`）覆盖：
  - 一次普通聊天 → 有来源兴趣 → 学习目标 → 后台反思；
  - 重启不重放，作用域隔离；
  - 聊天撤回与命令撤回；
  - 留出领域；
  - 不合规输出与 Provider 失败；
  - 中断不重放；
  - 默认关闭。

以上全部使用确定性模型替身和本地 fake bridge，只证明宿主契约与恢复语义，不代表真实模型的观察质量，也不是正式 QQ 体验验收。领域知识与受控研究见[受控研究与领域知识](./受控研究与领域知识.md)；#134 的其余验收项（真实模组、技能、主动邀请）尚未开始。
