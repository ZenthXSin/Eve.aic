# 本地文件观察驱动重规划

已有内生循环现在可以观察一个由本地操作者明确指定的文本文件。文件内容变化后，宿主保存 Environment 来源证据、提高关联目标修订，再由原规划循环产生新草稿；运行期间无需发送新的用户消息。父目标仍是 Waiting，草稿完成只表示反思记录通过结构校验。

## 使用

沿用主模型配置，在独立状态目录创建目标和可提供给模型的文本文件：

```bash
cargo run -p eve-app --bin eve-cognition -- --state-dir .eve-observe add --id report --text '根据进度文件调整报告整理计划'
printf '%s\n' '资料已收集，图表尚未整理。' > progress.txt
cargo run -p eve-app --bin eve-cognition -- --state-dir .eve-observe run --seconds 60 --max-executions 4 --observe-goal report --observe-file ./progress.txt
```

运行期间在另一终端编辑 `progress.txt`，文件的新内容会进入后续反思。运行结束后查看：

```bash
cargo run -p eve-app --bin eve-cognition -- --state-dir .eve-observe show --id report
```

`--observe-goal` 与 `--observe-file` 必须成对，只接受于 `run`；目标必须是同一状态中的有效 Waiting 本地用户目标。`--observe-user` 默认 `owner`，创建目标时使用其他用户则须指定相同用户。每次启动重新显式绑定文件，绑定关系不自动持久化；不读取模型输出中的文件路径。

每 250 毫秒最多读取一次，运行窗口仍是 1 至 600 秒，本次派生与执行上限仍是 1 至 32 项。相同内容不提高修订、不产生新事件或额外模型调用。已耗尽执行/派生名额时仍保存观察，后续启动再评估当前版本；变化快于执行时允许中间版本没有完成草稿。

状态目录独占语义不变，不能与现有 QQ 进程共用打开的目录。此切片接在本地 `eve-cognition`，QQ 目前继续使用 `/goal-feedback`，没有自动读取聊天中的文件路径或启动文件监视。

## 证据与分层

| 层 | 能力 |
| --- | --- |
| `eve-cognition-api` | 严格版本化的 `FileObservationInput`、`FileObservation`、服务与回执；无文件路径 |
| `eve-file-observer` | 宿主绑定规范路径，读取有界普通文本文件，计算完整字节摘要与有限片段 |
| `eve-cognition-plugin` | 校验主体、目标所属用户与修订，通过一次 CAS 保存观察事件和父目标修订 |
| `eve-cognition-loop-plugin` | 核对来源、版本、事件摘要与因果记录，在提示中区分文件内容、用户反馈和模型建议 |
| `eve-app` | 解析显式参数，组合观察服务、规划与原执行循环，统一停止和错误收尾 |

文件上限 65536 字节，必须是无 NUL 的 UTF-8 普通文件。完整字节计算 SHA-256；片段保留最多 4096 UTF-8 字节的前缀，为满足 JSON 转义预算可能更短，`text_truncated` 明示缺失。空文件也可成为一次有效观察。

来源标识是规范路径的摘要 `file-source:<sha256>`，观察事件保存文件内容摘要、完整字节数、有限片段、观察时间和目标前后修订，不保存原路径。路径只用于本次宿主绑定；同一规范路径被原子替换后仍属于同一来源。启动时的符号链接解析到规范路径，之后末级符号链接替换被拒绝。来源摘要不是访问凭据，也不承诺隐藏可猜测的文件名。

读取前后核对文件类型、长度、修改时间；Unix 还核对设备、inode 与 ctime，并使用非阻塞、拒绝末级符号链接的打开方式，避免替换为 FIFO 后卡在打开操作。检测到读取中变化则失败。这是有界本地读取，不提供对敌对文件系统的原子快照或目录沙箱承诺。

新事件类型为 ExternalInput，来源为 Environment，通道 `cognition.file-observation`，与 User 来源反馈独立。它只证明宿主在记录时间读取到这些字节，文件中的陈述和指令都属于未验证外部内容。片段会进入已配置的规划模型输入，不能作为新权限、用户指令或现实目标成功回执。文件发生变化但未再次读取时，旧观察不代表当前文件现状。

## 持久化、并发与失败

观察和目标新修订通过一次全局 CAS 保存。原目标 description、预算、权限和执行 feedback 不变；wait_reason 保存最新结构化观察。与该目标最近一次文件观察的来源和内容均一致时，直接幂等返回原观察结果，即使之后有用户反馈，也不覆盖该反馈。内容回到更早版本或本次显式绑定不同来源均算新变化，需要当前目标修订；从 A 切到 B 再切回 A 也会产生新观察，使规划采用本次绑定的来源。

规划读取匹配事件中的最近一次文件观察，同时保留有界的近期用户反馈。用户反馈在观察之后提交时，新规划仍可看到最近的文件证据及其原始时间/修订。提示总长保持 8192 字节，缩短和历史省略均带标记，原持久事件不因提示截断而改写。

读取、编码、容量、权限、存储或数据完整性失败时，当前 `run` 报错并沿用取消/保存/关闭收尾；保留先前已提交状态，不发布本次读取为有效观察。CAS 冲突在下一轮重新读取和评估。不会清空状态、自动解除阻塞或重放不确定执行。

观察保存与后续派生/执行是独立提交。观察已经保存、规划尚未开始时退出，重启可以继续评估；相同内容不新增修订。旧 Ready 草稿失效，旧 Executing 草稿在原预算内收尾，历史终态保留；只有绑定当前父修订的草稿为 current。新启动不重复已完成版本的模型调用。Ctrl+C/SIGTERM 沿用原宿主收尾，读取失败也走相同退出路径。

`run` 成功报告新增 `observation`：目标 ID、来源摘要、成功读取次数 `reads`、已保存变化次数 `saved`、相同内容次数 `duplicates`。CAS 冲突后的读取计入 reads，因此后两者之和可能小于 reads；不会返回路径或文件正文。`show` 是操作者显式查看持久内容的入口。

本切片提供可核对的环境输入，尚未执行模型建议、修改被观察文件或验证现实任务结果。下一步把建议连接受控行动、前置条件和独立效果验证，质量评估须与确定性流程测试分别记录。
