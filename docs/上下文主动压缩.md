# 上下文主动压缩

QQ 主对话、后台任务和子代理默认使用自适应上下文：只配置 **200000 个估算 token 上限**。上下文随交流和工具结果自然增长，不再使用 60k 闲聊阈值。每次模型请求前检查系统提示、历史、召回资料、当前输入、工具定义及已完成工具往返的合计大小。

接近上限时，宿主先计算必须保留的固定开销，再动态确定压缩目标：为后续输入预留剩余空间的四分之一（至多 8192 个估算 token），把可压缩部分大约减半。固定开销越大，保留的任务与用户原文越多；不为追求一个不可能达到的固定目标反复压缩。只有有原始历史或完整工具批次需要归纳时才发出压缩开始通知。固定资料与当前输入本身已达上限时停止并保留原文，不偷偷删除必需内容。

当前估算按整个内部请求的 JSON 计数：ASCII 每四字节一个 token，非 ASCII 每字符两个 token，包含协议元数据。这是保守近似，不是提供方的精确计费分词。上限约束输入上下文，单次输出预算仍由模型配置独立控制。

## 触发与继续

1. 原始会话、完整工具调用和结果始终保存。每轮先按原文 SHA-256 核对已有摘要，匹配时复用已压缩的历史前缀，避免每轮重新压缩同一批。
2. 达到阈值后，优先压缩最早的完整历史轮次。历史不足以释放空间时，继续压缩本轮已完成的工具批次；调用与对应结果一起处理，不能拆开工具协议。当前用户输入、系统提示、工具定义和当前任务控制对象保留。
3. 摘要要求保留用户目标、限制、纠正、已完成事项、关键路径与标识、真实验证结果、阻塞及待办。主动摘要输入每条用户或助手文字最多 8192 字符，工具参数和结果分别最多 2048 字符；超大轮次会进一步收紧片段长度，保证单轮也不突破单批输入预算；截断会显式标记。摘要是归纳，不是原文，需要细节时查原记录。
4. 压缩后从下一次模型请求继续，已执行工具的 ID、执行次数、取消状态、任务连续执行标记及工具预算不重置。原始 transcript 不受请求副本缩减影响，不重放已有操作。

只压缩必要的最早完整单元，保留所有轮内 User 引导。工具批次可以位于后续引导之前，不能因新引导改变位置而遗漏可压缩的旧工具结果。压缩后仍达到总上限则停止本次请求并保留记录，不无限循环或悄悄删掉当前输入。

## 旧固定阈值模式（兼容）

仅在 `adaptive_limit_tokens=0` 时使用旧模式。本轮还没有调用工具时，使用闲聊预算：估算达到 **60000 token** 就主动压缩，尽量降到 **40000**。本轮一旦调用工具（包括恢复的后台任务带来的旧调用），后续请求改用上面的主阈值（150000 → 100000），工具回执不会因为闲聊预算被提前压缩。

- 仍然按阈值整块压缩，不是每轮滑动窗口：压缩后历史前缀保持不变，直到再次达到 60000，提示缓存可以持续复用。
- 已保存的摘要按原文 SHA-256 复用，闲聊与做事两种阈值共用同一份摘要，不会来回重新压缩。
- 固定提示或当前输入已超过闲聊压缩目标时，提前回到主阈值，不再每轮归纳一点点历史。
- 闲聊阈值只在比主阈值小、且主动压缩开启时生效。

## 配置

面板“插件页面 → `runtime.history`”，保存后下一轮生效，同轮工具往返固定使用开始时捕获的设置：

| 字段 | 环境变量 | 默认 |
| --- | --- | --- |
| `adaptive_limit_tokens` | `EVE_CONTEXT_ADAPTIVE_LIMIT_TOKENS` | 200000 |
| `compact_at_tokens` | `EVE_CONTEXT_COMPACT_AT_TOKENS` | 150000 |
| `compact_to_tokens` | `EVE_CONTEXT_COMPACT_TO_TOKENS` | 100000 |
| `casual_compact_at_tokens` | `EVE_CONTEXT_CASUAL_COMPACT_AT_TOKENS` | 60000 |
| `casual_compact_to_tokens` | `EVE_CONTEXT_CASUAL_COMPACT_TO_TOKENS` | 40000 |

`adaptive_limit_tokens` 非零时只使用这一总上限，其余固定阈值是旧模式兼容设置，不参与本轮决策；设为 0 才启用它们。

旧模式中，`casual_compact_at_tokens` 为 0 时关闭闲聊预算，闲聊也按主阈值；其目标必须小于自身触发阈值。触发阈值为 0 时关闭主动模式，恢复原有 `max_turns` / `max_bytes` 历史窗口。非零阈值必须大于目标，保存时校验。主动模式下不再提前按默认 16 轮、64 KiB 裁剪历史。未装配摘要服务的独立运行时仍使用既有窗口；终端入口目前没有主动摘要服务。

主动模式依赖 `runtime.history_digest.enabled=true`。关闭摘要服务时不会伪造摘要；如需关闭主动模式，应先将 `adaptive_limit_tokens` 设为 0，再将 `compact_at_tokens` 设为 0。摘要模型沿用 `digest` 用途与输出配置，和主对话一样不计自主学习预算。

## 持久化与失败

历史摘要沿用 `状态目录/history-digest/` 的带指纹版本文件，主动压缩分批增量保存，重启后复用。本轮工具摘要仅作用于当前请求，不写入其他会话的历史摘要文件；完整回执仍在原轮次中。

压缩总期限 300 秒，单次摘要请求遵循所选模型的分阶段流式期限，内部等待器最多 301 秒（含 1 秒诊断与取消余量），不能越过宿主的 300 秒总期限。取消会立即取消压缩请求。模型失败、输出无效、摘要文件损坏或压缩未完整覆盖目标原文时，停止当前轮次并保留已有工具回执，不重试已经执行的操作。已成功保存的增量摘要仍可在下一次请求中核对使用。损坏文件不覆盖、不清空。日志 `EVE_CONTEXT_COMPACTION` 仅包含估算前后值和阈值，不记录正文或密钥。

摘要请求显式启用供应商的 JSON 对象模式，并在历史数据之后再次要求只做摘要。普通聊天文字、字段或要点不合格时，只根据同一份原始数据重新生成一次；两次摘要请求共用原来的期限，不重置五分钟压缩时限或工具预算。仅完整包住一个 JSON 的代码围栏可去除，仍严格校验要点长度、数量和来源。失败回复不写入摘要，也不带入纠错请求。再次无效时明确提示“上下文压缩未能完成”，保留原文、已保存的摘要和工具回执，不能误报为业务工具协议错误。

## 验收

- Runtime 测试覆盖 149999 / 150000 / 150001 边界、本轮工具结果压缩后继续、执行次数不变、失败保留回执和不可压缩输入保护。
- 摘要服务测试覆盖多批生成、同毫秒版本顺序、重启复用、原文变更失效、临时作用域不落盘及损坏文件保留。
- `connectors/qqbot/test/context_compaction_test.py` 用实际 QQ 宿主、本地模型替身及隔离桥接验证 150k 触发、连续执行、完整落盘和重启复用，不连接正式 QQ。

## 压缩期限与会话提示

主动压缩从开始到所有分批摘要完成的总期限为 5 分钟；保留已完成批次的摘要检查点和全部原始记录。压缩模型沿用流式首包、空闲和总期限策略，不再被旧的 120 秒完整响应超时截断；该用途的请求总期限不超过 5 分钟，内部等待器只留 1 秒取消与诊断余量，不能延长宿主的 5 分钟总期限。工具调用预算仍为 50。

需要主动压缩时，原会话自动收到一次“正在进行上下文压缩，请稍等”。同一轮后续分批不重复提示。提示与其他进展共用已持久化的发送回执和取消核验，未知投递不重发；开启主动压缩时最多两次工具里程碑加一次压缩提示，为最终回复保留第四个私聊投递名额。未触发阈值、仅复用已有摘要时不会发提示。

## 压缩模型被拒绝访问

压缩阶段的 HTTP 失败保留为有类型的 `ContextCompactionFailed`，记录固定失败类别与状态码，不保存供应商原始错误正文、地址或凭据。会话失败仍归为 Context，受限证据中保留 HTTP 401/403 等状态，模型健康按压缩用途记录，不能算成一次主对话调用。

QQ 对权限拒绝明确显示 HTTP 状态并提示检查密钥或中转分组权限；只有确认本轮尚未执行工具且失败记录已保存时，才省略“核对工具结果”的要求。已经执行工具、执行情况未知或保存失败时仍保留核对要求。认证或分组权限被拒绝不能通过增大压缩期限、清空历史或绕过压缩来解决。服务恢复后，后续输入从已保存的摘要进度继续处理，不重放失败轮的业务工具、不清空原始记录；存储格式不变，权限失败不会自动修改压缩预算。
