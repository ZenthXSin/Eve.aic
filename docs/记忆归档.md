# 记忆归档

交互记忆原本把全部原始证据放在一份热层文档里，受全局 4096 条与 4 MiB 上限约束。满了以后新交流无法记入，QQ 通道会停止。2026-10-19 正式实例就因此退出过一次。

装配归档存储后，热层只保留近期的、或仍被偏好引用的证据。较早的完成交互**无损压缩**进不可变分块，不删除、不改写、不摘要替换任何原文。

归档只是存储形式，不把记忆切开：回看历史的功能读[完整记忆](#完整记忆)，旧原文照常能被召回、归纳、提炼和观察。

## 什么会被归档

热层证据超过 1024 条或 2 MiB 时触发。每次写入最多归档一个分块：

- **选哪一批**：最早的一批合格完成交互，按作用域写成一个分块，最多 256 条、1 MiB。
- **不会归档的**：
  - 偏好命令（`UserStatement`）。
  - 任何偏好版本引用的证据，含已撤销的偏好。
  - 每个作用域最近 8 条完成交互。
  - 8 天内的记录。学习候选有效期是 7 天，这样候选确认时它的来源仍在热层。
- **容量压力下**：热层接近硬上限（3840 条或 3 MiB）时，不再看年龄，一条也可以成块；每个作用域只保留最近 1 条完成交互。否则作用域一多，各自保留的 8 条加起来就会超过硬上限，热层再也降不下来。偏好引用的证据仍不归档。
- **分块顺序**：同一作用域的分块修订段严格递增；更早的残留留在热层。

归档不改变作用域修订号。快照新增 `archived_evidence`，表示已移出热层的条数；它的修订仍计入作用域修订。

## 持久化与提交边界

- **分块位置**：`状态目录/memory-archive/evidence-序号-SHA256.json.zz`（zlib 无损压缩的分块 JSON；本功能之前写出的未压缩分块是 `.json`，照常读取）。SHA256 针对文件实际字节。用 PostgreSQL 状态后端时分块同样在状态目录内，备份和迁移须连同此目录。
- **写入顺序**：分块先写入临时文件并同步，原子改名后同步目录，然后才提交热层索引。热层索引是唯一提交点。
- **提交前失败**：热层不变，分块成为“未被引用的分块”。保留不删；下次归档同一批时内容一致即复用。
- **提交结果不确定**（后端已写入但确认丢失）：按原有规则关闭实例；重开后以实际持久的状态为准。两种结果下证据都不丢。
- **分块写入失败**（磁盘满、权限）：热层原样提交，`last_error` 记录原因。仍在硬上限内时照常记入新交流；到硬上限后拒绝新增，QQ 通道只跳过这次采集并计数，不停机（见[交互记忆](./交互记忆.md#修订去重与容量)）。
- **格式兼容**：
  - 从未归档的文档写格式 1，与旧版本逐字节兼容；
  - 只有未压缩分块的文档写格式 2（本功能之前的归档），升级后原样保留，直到写入第一个压缩分块；
  - 出现压缩分块后写格式 3。旧程序读取更高格式时按未知版本拒绝启动，不会当成空记忆。
  - 已有的未压缩分块不改写、不重新压缩。

## 恢复与损坏

- **启动时**：核对热层索引；核对索引引用的每个分块都存在。缺块拒绝启动，不把缺失的历史当作不存在。
- **已有归档却未装配归档存储**：拒绝启动，并提示“未装配归档存储”。
- **读取时**：先核对文件长度与 SHA256；压缩分块再解开，解开后超过 4 MiB 视为损坏（防止解压膨胀）；然后按解开的原文重算条数、修订段与轮次范围，与索引逐项比对，并核对序号、作用域和每条证据的格式。不依赖压缩器逐字节一致，升级压缩库不会让旧分块被误判。任何不一致都返回损坏，不跳过、不修复。之后停止新建分块，保留现场等待人工核对。新记忆写入还必须证明来源身份未被旧归档占用；无法核验坏块时拒绝写入，保留原 Memory 字节和 Session 中待采集的完成交互，修复分块后可重新采集。
- **同一轮次再次导入**：如果它已被归档，会读取对应分块核对。来源相同视为已保存；其他情况都是冲突。
  - 证据 ID 与消息 ID 别名检查覆盖同一作用域的热层及所有归档分块，新轮次也不能复用旧来源身份。当前写入会扫描归档，不代表已实现常数成本的身份索引。

## 读取

- 宿主通过 `MemoryService::archived(after_revision, limit)` 按修订升序逐页读取本作用域的归档原文，每页最多 64 条。
- `MemoryAdmin::archive_status()` 返回热层条数与字节、分块数、归档条数与字节、未被引用的分块和最近错误。
- 只读命令：

```sh
eve-memory --state-dir 状态目录 archive-status
eve-memory --state-dir 状态目录 --channel qq --session 会话 --user 用户 archived [--after 修订] [--limit 64] [--include-content]
```

## 完整记忆

`MemoryService::complete_snapshot()` 返回一个作用域的完整记忆：热层与全部分块的证据按修订升序合并，`archived_evidence` 为 0，看起来与从未归档一样。

- **一致读取**：热层与分块索引在同一把锁下取得，读取途中发生的归档不会让证据重复或遗漏。
- **完整视图**：不对合并结果套用热层写入的 4 MiB 上限；每条来源校验、单分块解压上限与召回输出上限继续生效。默认分页实现检查游标前进、条数与全局证据 ID 唯一性，损坏页不能造成无限读取。
- **缓存**：解开的分块按最近使用缓存在内存中，至多 16384 条证据，只影响读取速度。
- **失败**：任何分块缺失或校验失败都返回损坏，不跳过；同时停止新建分块，保留现场。

读完整记忆的功能（语义召回同样覆盖归档证据，向量写在独立分段里）：

- `/recall`、每轮的记忆召回上下文、跨会话续接；
- 对话里的记忆查询工具；
- 情景语义摘要（选新证据与核对引用）、偏好提炼、兴趣观察。归档前还没处理的交流同样会被处理，不会因为被归档而跳过。

仍读热层的：偏好与偏好上下文（被引用的证据从不归档）、最近交流的情景摘录、交流采集的修订核对。
