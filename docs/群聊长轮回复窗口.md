# 群聊长轮回复窗口

群聊任务执行较久时，原入站消息的被动回复窗口可能已经过期。同一用户在同一群的新消息会并入当前轮，但它拥有自己的平台消息编号、接收时刻和回复额度。工具执行继续原轮，显式发言可以使用模型已经消费的新消息窗口；不能把原窗口的时间归零，也不能用其他用户或其他群的消息补额度。

宿主先保存新消息为 `Merged`，记录 `merged_into` 指向当前原消息，并推进同一会话的审核锚点。成功接入运行轮次后，发送 `finish` 的 `keep_live_reply: true` 与 `parent_id`。桥只接纳仍在运行、身份与目标相同的父消息，保留子消息收到时的真实路由、年龄和额度。此窗口与私聊的前台自主发言窗口独立。

后续 `progress` 的 `id/index` 仍关联原轮的投递回执，`based_on_message_id` 指向实际采用的新入站消息。只有显式群聊表达可以使用已绑定的新窗口。发送前再次核对父轮、最新消息、有效期及额度；新输入、取消或父轮结束使旧选择失效。窗口缺失、过期或额度用尽时返回明确拒发原因，不改用其他路由，也不转成无消息编号的主动群发。

账本的 `Progress.reply_anchor` 保存实际回复窗口；缺省表示原入站消息。使用新锚点时写入版本 10，按各真实消息分别检查最多三条被动进度，同时保留每轮的总进度上限。版本 10 一经写入，即使相关记录全部归档也不降级。完整热账本核对新锚点对应同一身份的 `Merged → parent` 关系，单条归档校验形状与各窗口额度，归档组保留原始父子记录。新版继续兼容旧账本；写入新格式后，旧二进制不具备读取能力，恢复必须使用支持该格式的发布版本。

`send_message` 继续以 `sent=true` 且有平台消息编号表示已送达。`not_sent` 可以附带固定的 `failure_kind`，例如窗口过期、窗口不存在、被动额度耗尽、相同正文已记录或总进度已达上限；不透传 SDK 原始错误。`Completed` 和 `Handled` 只表示内部处理结束，不能证明对方收到正文。

同一窗口内已经尝试的相同正文不会自动重放；已送达、发送中或结果未知的正文也不会因为新窗口出现而重发。只有本轮已经明确记录为 SDK 调用前窗口拒绝、且后来出现新的合法窗口时，模型的新显式调用才可以再次选择相同正文。普通 HTTP 失败不自动认定为确定未送达。进程重启不会重建平台窗口，不自动续发旧表达，保留原回执和未知结果。

验证包含固定逻辑时钟的 Node 桥测试、Rust 通道与实际 Node 桥的进程交互，以及账本与只读消费者的恢复用例。进程夹具替换外部模型与 QQ 平台，使用已有工具上下文，不代表真实 QQ 投递或模型审核原话时序已经通过；这些事实须分别验收。
