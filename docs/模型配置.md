# 模型角色配置与核心主模型接线

主模型、辅助小模型、Jev 模型和语义模型现在有独立的类型化配置入口。公开契约位于 `eve-config-api`，沿用 `eve-config-plugin` 的普通配置文件、环境变量、CAS、备份、回滚和生命周期；Kernel 不解析模型配置。

定义层交付配置读取和校验；核心组合层现可显式选择 primary，装配已有 OpenAI 兼容 Provider 到终端与 QQBot，支持原 Chat/Responses 协议和会话恢复。未选择角色时沿用原模型配置。Jev HTTP、embedding/rerank、四角色统一路由、能力探测和实际质量评估仍待实现。接线方式与边界见[核心对话](./核心对话.md#显式选择主模型角色)。

## 角色与字段

所有角色放在 `runtime.models` 的 Schema 版本 1 中。一次 `ConfigService.snapshot` 捕获全部角色，避免分别读取四个命名空间时混入不同修订。

| 角色 | 字段前缀 | 用途 |
| --- | --- | --- |
| 主模型 | `primary_` | 对话、复杂推理、规划、工具编排和最终回复 |
| 辅助小模型 | `auxiliary_small_` | 分类、抽取、摘要、路由和记忆压缩 |
| Jev | `jev_` | 候选判断、消息关系和意图修订 |
| 语义模型 | `semantic_` | embedding 或 rerank；不要求生成文本 |

各角色共用以下字段；例如主模型字段为 `primary_model`：

| 后缀 | 默认值 | 约束 |
| --- | --- | --- |
| `enabled` | false | 布尔；关闭返回 None |
| `provider` | 空字符串 | 启用时必须提供；为宿主装配标识 |
| `model` | 空字符串 | 启用时必须提供；为模型标识 |
| `credential_ref` | 空字符串 | 可选的宿主管理引用；不解析、不保存密钥正文 |
| `timeout_ms` | 30000 | 正整数 |
| `max_concurrent_requests` | 1 | 1 至 u32::MAX |
| `max_output_tokens` | 0 | 仅前三类角色；0 表示不指定 Provider 输出上限 |

环境变量名为 `EVE_MODELS_` 加完整字段名的大写，例如 `EVE_MODELS_AUXILIARY_SMALL_MODEL`。沿用默认值 < 环境变量 < 文件的优先级。模型和引用标识不能含空白或控制字符，允许厂商使用的斜杠、冒号等字符。相同 Provider/model 可用于多个角色，期限与并发仍各自配置。

语义模型额外提供 `semantic_operation`（默认 embedding）与 `semantic_dimensions`（默认 0）。启用 embedding 时维度必须为正；rerank 时必须为 0，类型化结果为独立的 Rerank 选项。语义角色没有 `max_output_tokens` 字段。实际返回向量的长度校验由后续语义 Provider 完成，不能仅凭配置认定模型能力。

## 类型化读取与失败

`ModelRolesConfig::capture(&dyn ConfigService)` 完成一次快照读取和全部角色语义校验，保留同一 revision；`profile(role)` 返回可选角色，`require(role)` 对关闭的角色明确报错。没有隐式回退，也不会因为辅助模型关闭而自动使用主模型。

定义层校验分两步：通用 Schema 在存储入口验证字段、类型和数值范围；类型化消费者验证启用字段组合、标识和语义操作。普通存储可以保留标量类型正确但角色语义不完整的配置，例如启用 embedding 而未设维度；消费者必须在装配或模型请求开始前调用类型化校验并处理错误，不应直接逐字段读取后调用 Provider。失败返回字段路径，不回显原始值，不清空配置或自动替换旧数据。

`ModelRolesConfig` 是消费者持有的独立配置值。捕获后即使配置服务采用 Immediate 更新，该值仍保持旧修订；新请求重新 capture 得到最新修订。直接使用 `ConfigRequest/read_request` 的通用服务仍按自身的 Immediate/NewRequests 规则工作。模型适配层后续必须把一次捕获的值用于整轮请求和工具往返，不得中途重新读取模型选择。

配置文件恢复沿用 format_version 1 和原有备份规则。加入 `runtime.models` 不修改现有 `runtime.llm` Schema；宿主显式注册新增 Schema。角色语义无效的文件可以恢复为普通配置，但消费者持续拒绝使用，保留原数据供修正。跨进程不恢复 Provider、密钥或正在运行的请求。

## 示例和验收

```bash
cargo test -p eve-config-api -p eve-config-plugin --locked
cargo run -p eve-runtime --example model_roles --locked -- ./model-config
cargo run -p eve-runtime --example model_roles --locked -- ./model-config
```

示例使用真实配置插件、公开 Service Registry 和文件存储，不访问模型。首次创建四个角色后捕获修订 1，即时更新到 2，旧快照仍为 primary-1；第二个独立进程恢复修订 2 后更新到 3，旧快照仍为 primary-2。其他角色保持原配置。Windows/Ubuntu CI 实际运行两次并读取 config.json 校验修订、四角色与备份。

测试覆盖四角色独立启用/复用、标识和边界校验、缺失/未知字段、版本不符、embedding/rerank、环境与文件优先级、即时/仅新请求更新、固定捕获快照、旧服务失效、重启、回滚与错误数据保留。工作区格式、Clippy、构建与测试结果以本 PR 的 CI 为准。

## 每轮模型解析

公开 LlmModelResolver/ModelSelection 位于 eve-llm-api，仅描述固定 Provider 与请求期限，不依赖配置插件或具体厂商。Runtime 的 LlmHost 可显式设置解析器，原固定 Provider 构造路径兼容；普通 Host 和 Session Host 每轮恰好解析一次，Session 在创建 Pending 前解析。解析异常、零期限或无效配置不开始会话轮次。冻结后的 Host 保留相同的工具并发槽位、串行队列与固定 AGENT 身份，整轮工具请求不重新解析。

核心组合层的 CoreModelResolver 读取 provider.openai 与显式 primary，比较同一 ConfigDocument 修订后校验；不一致最多重读四次，避免组合旧协议设置和新角色模型。最新有效配置与缓存相同才复用客户端；错误、未启用、无法解析凭据引用或旧配置服务停止均拒绝，不落回缓存。模型、协议、API 地址、reasoning、期限和输出限制按该轮快照固定；宿主密钥仍只在启动时交给解析器。取消后新代重新捕获，重启恢复已完成历史和配置，不恢复正在执行的 Provider 或重跑旧工具。

本切片通过现有 ConfigAdmin 更新配置服务；未增加终端/QQ 配置命令、文件监听或环境变量热重载。模型选择始终使用整轮快照，配置服务 Immediate 不在工具往返中重新读取。辅助角色、Jev、语义与四角色统一路由尚未执行；按用户最新要求 Jev 继续 TODO。

验收实际使用共享核心装配、ConfigController、Control/Session、文件状态和 loopback HTTP：Chat/Immediate 与 Responses/NewRequests 都在首轮工具执行前更新 A→B，后续请求保持 A，下一轮使用 B；无效新 Provider 零请求且 state.json 字节不变，修正后继续并重启恢复旧工具历史。另检查取消后采用新模型、旧配置服务不能使用缓存，以及不同修订有界拒绝。Runtime 测试检查解析错误/panic/零期限在 Pending 前失败、每轮一次解析及所选期限实际超时。实际检查结果以本切片 PR 的 CI 为准。
