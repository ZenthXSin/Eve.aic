# 模型会话与缓存隔离

模型会话由宿主显式绑定。主聊天、动作审查、每个后台任务、探索和子代理分别保有自己的长期会话；同一任务的工具往返、传输重试和恢复继续沿用原绑定。Provider 不从提示词、模型名字、每请求随机数或全局配置猜测用户和任务。

## 身份来源与分层

`ModelSession` 位于 `eve-llm-api`。通道的 `ContextScope.session_id`、`ContextScope.user_id` 来自宿主验证和持久化的会话范围；后台任务使用账本的任务 ID，内部业务作业使用已经核对的所有者与持久作业 ID。字段经过版本域、用途域和长度分帧的 SHA-256 派生，不把明文用户、通道、任务或轮次 ID 放进模型会话请求头。相同原文不会使两个任务共享会话。

模型会话标识只负责关联与缓存分区，不承担认证或授权。哈希也不代替对宿主元数据、状态目录和凭据的访问控制。`validate_scope` 要求显式父会话仍属于当前可信范围；模型参数自报的用户、任务或子代理名字不能覆盖它。

| 层次 | 来源 | 何时变化 |
| --- | --- | --- |
| 长期 session | 可信范围、角色，以及可选的持久任务锚点 | 用户、通道、角色或独立任务变化 |
| thread | 长期 session 的独立领域派生 | 长期 session 变化 |
| prompt cache key | 长期 session 的独立领域派生 | 长期 session 变化；正常换轮保持 |
| turn | 同一会话内的持久轮次、入站事件或作业批次 ID | 进入新轮次或新批次 |
| client request ID | session、turn 与宿主逻辑请求序号 | 产生新请求；相同实际请求的重试保持 |

`fork(role, anchor)` 从可信父会话派生独立用途，保留范围约束并分离轮次。工具内审查必须先从父任务派生，不能只按用户范围创建：同一用户的两个后台任务也需要两个审查会话。没有父会话的旧入口才可使用明确的可信范围回退。

## 宿主用途

| 用途 | 长期绑定 | 轮次或独立任务锚点 |
| --- | --- | --- |
| 主聊天 `main` | 通道范围与用户 | 会话服务分配的持久 turn ID |
| 后台 `task`、回顾 `idle-review`、主体计划 `subject-plan` | 范围与持久任务 ID | 原任务 ID；恢复重用 |
| 探索 `exploration` | 范围与独立探索任务 ID | 探索执行器装配时显式选用该角色 |
| 子代理 `subagent` | 父会话、父 turn 与宿主绑定的 call ID | 一次独立委派；不用参数中的 `agent_id` |
| 动作审查 `review` | 当前主会话或后台任务的独立派生 | 父 turn 与本次宿主 call ID |
| 进展 `progress`、发言判断 `speech`、识图 `vision` | 通道范围与各自用途 | 可信入站消息或事件 ID |
| 历史摘要 `history-digest` | 后台按历史范围；临时主动压缩从父任务派生 | 已覆盖轮数，或父轮次内的摘要分批序号 |
| 上下文选择 `context-selector`、查询向量 `embedding-query` | 父任务的独立用途；旧接口可按真实范围绑定 | 沿用父轮次；查询文字不作为会话身份 |
| Jev 关系、群关系、群召回 | 可信会话范围或群 conversation ID，与各自用途 | 入站 message ID；分片单独编号 |
| 学习、偏好、兴趣、情景摘要与人物印象 | 各自真实范围、参与者与独立用途 | 宿主持久批次 ID、序号或修订 |
| 人物画像整理 | 当前父会话的独立用途 | 当前宿主轮次；旧独立画像接口见兼容边界 |
| 知识、计划、技能、练习、工具生成与主动联系 | 业务账本的真实 owner、作业或邀请 ID，与各自用途 | 持久 run、entry、attempt 或收到的响应 ID |
| 后台向量索引 `embedding-index` | 哈希范围、按顺序的持久来源 ID 与来源修订 | 固定批处理用途，正文指纹只判断索引是否过期 |

探索组合功能与会话定义是独立改动。仅具备 `ModelSession` 的通用派生能力不代表该工作树已经装配探索入口；合并探索执行器时必须显式保留 `exploration` 角色。

`ContextAssembler::assemble_with_model_session`、`HistoryContextPlanner::plan_with_model_session`、记忆召回与 embedding 接口传递同一宿主元数据。组合装配器继续向下传递，叶子组件只为自己的模型用途派生；纯本地叶子可以沿用默认实现。排入后台队列时克隆绑定，出队时不重新猜测身份。

## 实际请求

OpenAI 兼容 Chat Completions 与 Responses 的普通、JSON、流式和内部流式完成路径统一发送：

- HTTP `session-id`、`thread-id`、`x-client-request-id`。
- JSON `prompt_cache_key`。

元数据不进入提示词正文，不发送 `temperature`。显式配置的思考强度继续按原协议传递；本地协议验收覆盖 `high`。本次不切换线上默认模型或 Chat/Responses 配置。

识图经过相同会话编码。Jev SystemOne 和 OpenAI embeddings 保留自己的请求 schema，仅添加三个 HTTP 头；它们的正文不加入聊天专用的 `prompt_cache_key`。

服务可能忽略自定义头、拒绝扩展字段或不报告缓存计数。这里定义的是宿主发送契约，不宣称所有中转站均支持同一能力。无法从本地前缀重复或发送 cache key 推断 NewAPI、后端模型的真实缓存命中，更不能补造 `cached_tokens`。

## 重试与请求编号

长期 session、thread 和 cache key 不因重试改变。`x-client-request-id` 对应一次逻辑模型请求，不是一次 TCP 连接，也不是权限凭据或供应商承诺的幂等键。工具往返产生的新模型请求使用新序号；Provider 内的 429/503 等传输重试复用同一正文和请求头。

后回复机制会在重试前接纳新的用户补充，恢复会重新读取当前宿主提示与工具定义，压缩也可能改变模型输入。为避免不同正文复用旧请求 ID，`LlmProvider::request_fingerprint` 在发送前只读计算实际请求的指纹，不能发起网络或模型调用，也不能修改 Provider 状态。该指纹只判断请求是否相同，绝不派生会话身份。

OpenAI 实现复用真实发送的编码路径，对完整 JSON 正文和目的地计算版本化 SHA-256；模型、思考强度、输出上限和流式选项在正文中参与比较。凭据和客户端请求编号不进入指纹。并发、健康、前缀诊断包装器透传，表达包装器执行同样的正文转换后计算。会动态请求模型再添加内容的包装器，或旧 Provider，默认返回 `None`。

只有当前与待重试请求都提供相同指纹时，Runtime 才复用原序号。配置、工具、steering、压缩结果变化，或旧接口无法证明相同，都会在原长期会话中分配新序号。摘要器的格式修复会追加新的修复说明，因此本身是新的逻辑请求；其底层传输重试仍原样重复。

## 持久化与恢复

`ModelSession` 保存版本为 1 的不透明 session、可选 scope hash、可选 turn 与请求序号；thread、cache key 和 client request ID 在反序列化时重新派生。未知版本、非法标识和未知字段拒绝读取，不尝试从原文补造。

`TurnCheckpoint` 在原 v1/v2 上增加三个可选字段：

- `model_session`：本任务的宿主绑定。
- `pending_model_request`：已准备请求、尚未提交完整结果的逻辑序号。
- `pending_request_fingerprint`：该实际请求的正文与配置摘要，不保存第二份正文。

新版本能读取缺少这些字段的旧 v1/v2 记录。旧记录的模型会话只由相同可信范围和任务 ID 重建；缺少请求指纹时，恢复使用新请求序号。新字段并不保证旧二进制可读取新记录：旧实现使用 `deny_unknown_fields`，回滚前必须考虑这一格式边界，不能删字段、清空日志或忽略损坏来强行启动。

恢复入口先只读加载、校验检查点和核对可信 scope、任务会话、轮次、待执行工具及宿主消息头，再允许上下文组装器、历史规划器或主 Provider 请求模型。身份错配、未知结果的工具、损坏或超限记录都会拒绝恢复并保留原记录。检查点只适用于有可信范围的独立任务。

每次发送前先持久保存 pending 序号和指纹；完整模型结果到达后，在下一次结果或工具批次提交中清除 pending。工具执行前仍先保存待执行调用，完成后保存真实完整回执。恢复保留调用与回执，不重新执行已完成工具；存在未知副作用的待执行批次不能自动重放。系统提示、工具清单、选择后的模型输入可以更新，所以恢复不是整个 HTTP 正文的无条件字节回放。

这不承诺远端恰好执行一次、计费去重或进程退出时远端停止。已完成结果尚未持久提交的窗口仍可能再次请求模型；请求 ID 连续只提供可追踪关系。文件和数据库提交的不同失败语义见[状态持久化](./状态持久化.md)。

## 本地缓存与兼容边界

本地前缀诊断把长期 cache key 纳入比较，同一用户不同用途或任务不再被记为前缀复用。后台查询向量缓存按模型、维度、精确输入与长期会话分区；同任务的新轮次可以复用同查询，不同任务即便 query 完全相同也会分别请求。缓存仍仅在内存中，重启不重放尚未完成的查询。

后台向量索引每次远端批次只包含一个可信范围，仍扫描并核对全部范围。某范围不足一批的尾部会单独发送，可能增加请求次数或降低批处理吞吐；不能为了凑满批次混入其他范围的数据。

OpenAI 的旧 `ModelRequest.session = None` 入口仍能调用，不添加全局或正文推导的假会话。真正无范围的旧本地入口和无父会话的临时压缩也保留 `None`。旧独立人物画像接口能按参与者建立长期会话，但没有宿主持久 turn，不能承诺不同批次的请求编号唯一；QQ 的实际排队入口已从父会话传入轮次。新增调用方应显式传 metadata，不使用这些兼容退路。
