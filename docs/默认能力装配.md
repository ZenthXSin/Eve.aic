# 默认能力装配

`eve-qqbot` 产品入口默认装配交互记忆与召回、偏好学习、兴趣观察与认知、提醒、后台任务、子代理、条件触发、等待、流程工具和健康巡检。用户直接聊天使用这些能力，无需逐一打开功能参数。主体调度随后台任务运行；执行、审核、持久预算、可信身份和隐私范围仍由各业务契约检查。

`QqBotOptions::parse_product` 实现产品入口；`Default` 与 `parse` 保留供受信 Rust 宿主逐项组合的语义。`--minimal-profile` 是显式隔离与调试模式，保留按参数装配的行为，不是产品默认。测试旧有单项能力时显式选择该模式，默认产品验收不使用它。

发行 QQ 启动器省略 `features.autonomous_tools` 或设为 `true` 时使用产品默认；已有配置显式设为 `false` 时选择最小组合并保留其它明确的功能设置，不把旧关闭意图解释成授权重新开启。

启动只在当前目录及二进制所在目录的 `vendor/eve-portable-knowledge` 查找随包资料。资料根目录、清单和内容路径不接受符号链接，内容须为长度受限的普通文件。整份资料须通过 `CorpusSourceFetcher` 的格式、长度和 SHA256 校验才装配为本地研究入口；不添加公网默认种子。用户提出网页读取任务时沿用实际的 `read_source` 工具及网络边界。

实践环境先使用宿主明确指定的运行器；未指定时从 PATH 的绝对目录发现 Chromium，并限时完成离线页面探测。每次最多探测三个候选，每个五秒；不下载资源，探测目录与浏览器配置临时隔离，不访问外部页面。文件存在、工具注册或模型声称能运行都不是实践验证证据。条件账本中此前取得并验证的 Mindustry 服务端也可在启动时恢复，恢复时再次核对真实文件长度、SHA256 和路径边界；文件缺失保持待补齐，篡改则保留账本并拒绝冒充已验证环境。

只有实际装配实践运行器后才开启技能生成、策略学习、工具锻造、对应计划和实践邀请。没有运行器时，已有技能及锻造工具账本仍可查看和管理，`use_skill`、实践执行和实践检查工具不会冒充可执行。`inspect_capabilities` 从最终工具注册表返回清单，并单独列出缺少的运行条件。主人或管理员可使用既有开发工具、`acquire_condition` 补齐资源；仍须通过真实验证，之后重启装配。

自动发现失败不会删除、覆盖或清空资料，也不会阻止其它聊天能力启动。明确指定的无效运行环境、损坏的持久业务账本仍按原契约失败关闭，防止把状态丢失当成全新启动。自动装配不改变持久任务、提醒、技能和预算的恢复语义；重启不把不确定执行或未经验证的结果记为成功。

验收入口为 `connectors/qqbot/test/default_capabilities_test.py`：使用实际产品进程、隔离目录和本地传输替身，不传功能开关；核对真实注册工具、默认提醒保存和重启投递、后台结果证据、缺运行器的明确报告。它验证宿主行为契约，真实模型的自然语言理解质量仍由模型交互验收单独覆盖。

2026-11-03 集成构建已通过该脚本全部 4 项真实进程验收，包含默认开发工具注册；启动器全部 11 项测试、本地资料加载器全部 26 项测试通过。提醒用例检查初始到期时间确为 30 分钟，并在进程停止后等量前移账本时间测试到期恢复，不伪称实际等待了 30 分钟。默认能力模块的独立 Rust 测试与全仓库门禁仍由统一验证执行，发布状态以交付验收台账为准。
