# 跨平台运行包与自动 Release

`跨平台构建与发布` 是同一个工作流：主分支提交生成已验收 Actions 产物；推送 `v主版本.次版本.补丁版本` 标签时，在六个平台全部通过后自动创建 GitHub Release。`v0.1.0-rc.1` 等预发布标签生成 prerelease；手动运行也可针对既有版本标签恢复未完成的草稿发布。

| 包 | 原生构建环境 | 运行要求 |
| --- | --- | --- |
| Windows x64 | windows-latest / MSVC | Windows 10/11 x64 |
| Windows ARM64 | windows-11-arm / MSVC | Windows 11 ARM64 |
| Linux x64 | Ubuntu 24.04 | 相容 glibc 与 x64 CPU |
| Linux ARM64 | Ubuntu 24.04 ARM | 相容 glibc 与 ARM64 CPU |
| macOS x64 | macos-15-intel | macOS 11+ / Intel |
| macOS ARM64 | macos-15 | macOS 11+ / Apple Silicon |

五个 Eve 入口、内嵌 Web、固定 Node 22.22.0、锁定 QQ SDK 与无密钥配置模板随包提供。用户无需 Rust、Node、Python 或前端构建工具。Windows 使用 ZIP，x64 启动器采用系统 PowerShell 5.1，ARM64 使用随包的原生 Node；Linux/macOS 使用保留执行权限的 tar.gz，启动脚本调用随包 Node。默认功能、凭据和数据保持本机配置，见 [Windows 说明](../packaging/windows/使用说明.md) 与 [Linux/macOS 说明](../packaging/posix/使用说明.md)。

## 标签发布

在已合并且验收的提交上推送一个尚未发布的版本：

```bash
git tag v0.1.0
git push origin v0.1.0
```

工作流先在对应 CPU/系统原生构建 Rust 1.89 release，再复核固定官方 Node ZIP/tar 散列、安装锁文件依赖，实际运行每个入口帮助。解压实际发行包到中文和空格目录后，验证启动器、Web 鉴权、记忆/学习页、两段 QQ 替身回执、关闭与恢复零重放。只访问回环替身，不使用仓库 QQ/模型 Secrets，不连接正式 QQ。

发布作业仅在版本标签运行，只有它具有 `contents: write`。六个平台任何一个失败都不会公开部分 Release。下载产物后重新核对源码提交一致、六种平台完整、文件 SHA-256 和实际验收记录，再上传六个包、汇总 `SHA256SUMS.txt` 及 `release-verification.json`。先以草稿上传全部文件，最后公开；失败草稿可重跑补齐，已经公开的版本不覆盖，应推送新标签。

PR 和主分支构建产物保留 30 天，公开 Release 资产没有该自动过期期限。每个包的 `build-info.json` 保留源码提交、树、目标、Node 版本和逐文件散列；发行包不含用户密钥、配置文件、历史交流或训练样本。程序尚未进行 Windows 签名与 macOS 签名/公证。
