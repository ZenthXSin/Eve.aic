# 跨平台运行包与自动 Release

`跨平台构建与发布` 是同一个工作流：主分支提交自动生成六平台运行包，在原生验收和同一提交的 CI 成功后自动递增补丁版本、创建标签并公开 GitHub Release。例如已有 `v0.1.0` 时，下一个主线版本为 `v0.1.1`，无需手动推送标签。版本标签由本工作流的发布作业创建，直接在同一作业发布，不依赖 GITHUB_TOKEN 创建标签再触发另一次工作流。

PR 只构建验收，不发布。手动运行 main 可恢复失败发布；同一提交重跑复用已有标签，不产生新版本。手动推送 `v主版本.次版本.补丁版本` 标签仍可指定发行版本，`v0.1.0-rc.1` 等预发布标签生成 prerelease。发行版本记录在包名与 `build-info.json`，与 Rust workspace 的 crate/API 版本分开。

| 包 | 原生构建环境 | 运行要求 |
| --- | --- | --- |
| Windows x64 | windows-latest / MSVC | Windows 10/11 x64 |
| Windows ARM64 | windows-11-arm / MSVC | Windows 11 ARM64 |
| Linux x64 | Ubuntu 24.04 | 相容 glibc 与 x64 CPU |
| Linux ARM64 | Ubuntu 24.04 ARM | 相容 glibc 与 ARM64 CPU |
| macOS x64 | macos-15-intel | macOS 11+ / Intel |
| macOS ARM64 | macos-15 | macOS 11+ / Apple Silicon |

五个 Eve 入口、内嵌 Web、固定 Node 22.22.0、锁定 QQ SDK 与无密钥配置模板随包提供。用户无需 Rust、Node、Python 或前端构建工具。Windows 使用 ZIP，x64 的 PowerShell 5.1 包装器与 ARM64 的命令脚本都委托随包 Node；Linux/macOS 使用保留执行权限的 tar.gz，启动脚本调用随包 Node。启动器默认检查稳定版更新、后台校验下载并在下次启动切换，用户文件留在原目录，详见[客户端自动更新](./客户端自动更新.md)。默认功能、凭据和数据保持本机配置，见 [Windows 说明](../packaging/windows/使用说明.md) 与 [Linux/macOS 说明](../packaging/posix/使用说明.md)。

## 自动发布与恢复

工作流先选择全部稳定版本标签中的最大版本并递增 patch；已有草稿也占用其标签。若同一提交已有稳定标签，则复用它。自动发布等待精确 main 提交的 Rust CI，以及该提交实际触发的 QQ、PostgreSQL、性能工作流；失败或超时不创建标签、不公开 Release。新主线提交会取消旧主线构建；发布前再次核对 main，过期运行不公开旧提交。

六个平台共同使用选择出的发行版本。只有全部验收通过才进入发布作业；该作业具有 `contents: write`、`actions: read`，构建和 PR 仅有读取权限。发布作业串行处理，已有标签指向其他提交时明确失败，不移动标签。

上传失败保留同一版本草稿，可从 Actions 重跑，或手动对该标签运行工作流。所有远端资产的名称、大小和 SHA-256 与本地完整验收产物一致后才公开；上传期间 main 更新则保留草稿，最新提交的运行接续分配版本。已经公开且完整的同一提交版本重跑只读返回；公开版本不覆盖，不完整的公开版本需使用新版本修复。

## 指定标签版本

在已合并且验收的提交上推送一个尚未发布的版本：

```bash
git tag v0.2.0
git push origin v0.2.0
```

工作流先在对应 CPU/系统原生构建 Rust 1.89 release，再复核固定官方 Node ZIP/tar 散列、安装锁文件依赖，实际运行每个入口帮助。解压实际发行包到中文和空格目录后，验证启动器、Web 鉴权、记忆/学习页、两段 QQ 替身回执、关闭与恢复零重放。只访问回环替身，不使用仓库 QQ/模型 Secrets，不连接正式 QQ。

主线和标签发布均重新核对源码/发行版本一致、六种平台完整、文件 SHA-256 和实际验收记录，再上传六个包、汇总 `SHA256SUMS.txt` 及 `release-verification.json`。每个平台还实际验证更新下载断线与重试、下一启动切换、回退和用户文件保留；缺任一验收结果拒绝发布。先以草稿上传全部文件，最后公开；任何平台失败都不会公开部分 Release。

PR 和主分支构建产物保留 30 天，公开 Release 资产没有该自动过期期限。每个包的 `build-info.json` 保留源码提交、树、目标、Node 版本和逐文件散列；发行包不含用户密钥、配置文件、历史交流或训练样本。程序尚未进行 Windows 签名与 macOS 签名/公证。
