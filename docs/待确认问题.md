# 待确认问题

Phase 4 的恢复与诊断已完成。外部插件形式留到 Phase 5，根据实际隔离需求再选择，当前优先稳定现有核心。

## 已解决的问题

1. Plugin Trait 生命周期：采用 start(&mut self, ctx) -> PluginFuture<'_, Option<Cleanup>>。
2. 插件启动和停止：使用 Tokio 异步流程，依赖按顺序启动，停止时先停止消费者，再等待所有异步 Cleanup。
3. 启动失败回滚：当前请求中新启动的依赖会按逆序停止；失败插件进入 Failed，不自动重启。
4. 后台任务停止：已实现先通知收尾，默认等待 5 秒且可配置；超时后取消异步任务并报告未正常退出的任务。任务模型支持前台、后台、延迟和固定间隔调度，详见[ADR-0008](./决策记录.md#adr-0008后台任务停止采用可配置的等待期限)和 ADR-0016。
5. State Store：采用抽象接口并支持多种实现；第一版先提供内存实现，后续可接入 JSON 文件等持久化后端，详见[ADR-0009](./决策记录.md#adr-0009state-store-采用抽象接口并支持多种实现)。
6. Service Registry：采用字符串 ID 与 Rust 类型安全的双重约束；字符串用于发现和配置，类型用于安全获取，详见[ADR-0010](./决策记录.md#adr-0010service-registry-采用字符串标识与类型安全双重约束)。
7. Event Bus：采用抽象接口并支持多种投递实现；独立接口与可替换同步广播实现已完成，后续可扩展异步队列、优先级、重试和持久化，详见[ADR-0011](./决策记录.md#adr-0011event-bus-采用抽象接口并支持多种投递实现)。
8. 总体分层：所有功能分离定义层、实现层和组合层；插件只依赖定义层，Runtime 负责装配实现，详见[ADR-0012](./决策记录.md#adr-0012所有功能分离定义层与实现层)。
9. 权限系统：定义 `PermissionChecker` 抽象接口，第一版只做权限声明和检查，文件、网络、进程访问以后通过独立适配器实现，详见[ADR-0013](./决策记录.md#adr-0013权限系统采用抽象检查接口)。
10. Runtime CLI：第一版暂不提供完整 CLI，保留可编程宿主；待插件发现、配置和安装机制稳定后再设计，详见[ADR-0014](./决策记录.md#adr-0014第一版-runtime-暂不提供完整-cli)。
11. 第一版验收场景：已实现可运行的提供者插件和消费者插件协作闭环，覆盖依赖、Service、Event、State、Cleanup 和失败回滚；任务管理已有独立验收，持久化和重启恢复留到后续阶段，详见[ADR-0015](./决策记录.md#adr-0015第一版采用插件协作闭环作为验收场景)。
12. 任务扩展：插件可自行实现任务行为与调度策略，详见 ADR-0017。
13. 日志：采用可替换 `Logger` 接口，提供同步输出流与有限条数内存后端，自动附加来源和时间，详见 ADR-0018 和[日志接入](./日志接入.md)。
14. 状态持久化：可选版本化 JSON 文件后端，每次 set 同步提交，同目录独占访问；损坏或未知版本拒绝打开且保留原件。实际独立进程恢复验收已完成，详见 ADR-0019。
15. 宿主诊断：只读抽象查询插件与任务，停止错误保留插件、阶段和阶段错误，退出确认失败不会伪装成成功，详见 ADR-0020。
