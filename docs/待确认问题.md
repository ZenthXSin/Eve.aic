# 待确认问题

## 当前最高优先级

1. `Plugin` Trait 的最终生命周期签名是什么？
2. 插件启动和停止是否完全异步？
3. `ServiceRegistry` 第一版使用字符串 ID、类型 ID，还是双重 ID？
4. Event Bus 第一版支持哪些投递模式？
5. State Store 第一版使用内存、JSON 文件，还是抽象存储接口加 JSON 实现？
6. 任务取消时是否等待任务退出？
7. 插件启动失败时，已启动插件如何回滚？
8. 权限系统第一版只做声明和检查，还是同时做文件和网络访问封装？
9. 第一版 Runtime 是否需要 CLI？
10. 第一个完整验收插件场景是什么？

## 已解决的问题

1. Plugin Trait 生命周期：采用 start(&mut self, ctx) -> PluginFuture<'_, Option<Cleanup>>。
2. 插件启动和停止：使用 Tokio 异步流程，依赖按顺序启动，停止时先停止消费者，再等待所有异步 Cleanup。
7. 启动失败回滚：当前请求中新启动的依赖会按逆序停止；失败插件进入 Failed，不自动重启。
