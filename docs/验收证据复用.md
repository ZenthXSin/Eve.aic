# 验收证据复用

目标是让主线程、子代理和后台采用已有的有效结果，减少同一产物重复验证。权限、取消、预算、未知副作用和结果真实性继续由宿主约束；普通工作的路径、分工和表达不需要围绕验收模板安排。

## 第一切片：传递与查询历史真实回执

`run_subagent` 正常返回时，宿主自动附上 `receipt_evidence`，内容与查询同一 run 的证据简表一致。父执行者直接拿到原检查及回执摘要，无需为获取这份摘要再调用工具或模型。需要之后查询时，可使用 `list_subagent_runs` 的显式历史证据入口：

```json
{"run_id":"原子代理返回的记录 ID","evidence":true}
```

宿主从当前可信用户、会话范围内的原始持久记录读取冻结合同、调用及配对回执，返回 `TaskReceiptEvidenceReport` 的结构化摘要。它回答“原合同的这些检查，当时有怎样的真实结果”，供接收者定位已经做过的事及证据缺口。模型自述成功、最终答复和分页详情中的脱敏字符串都不是证据来源。

摘要保留原 run、检查和调用的关联，以及参数和回执的摘要；不在新报告中复制参数、输出正文或聊天原文。它不扩大既有记录的可见范围。`evidence=true` 必须指定单个 `run_id`，且不能同时传 `offset`；不带 `evidence` 的普通列表和详情查询保持原返回。

查询在 `runs` 中返回证据简表：`evidence_kind=historical_tool_receipts`，`current_artifact_validity=not_checked`，`report` 为历史报告，`run_status` 表示已保存的执行生命周期，另带 `effects_unknown`。简表内 `verification` 只用固定分类 `verified`、`mismatch`、`unverifiable`、`blocked` 或 null，不携带原分类中的原因正文；旧记录保存为 Verified，但生命周期、已保存结果或检查点一致性不支持该状态时，显示 `inconsistent`，不改写原存储。不能生成报告时 `report` 为 null 并说明固定 `reason`，不伪造通过结果。简表不带原任务、消息、步骤或最终结果正文。记录及外层均标明 `automatic_resume=false`。

自动附带摘要时若持久证据读取失败，`receipt_evidence` 只保留记录关联与 `report=null`、`reason=saved_evidence_unavailable`、`current_artifact_validity=not_checked` 等缺口信息，原子代理结果仍交回，不因摘要缺失丢弃结果，也不把原验收状态升级为通过。显式查询的存储错误仍按原只读接口报错。

| 状态 | 含义 |
| --- | --- |
| `historical_match` | 已有真实调用与回执满足冻结检查的历史观察条件。 |
| `historical_mismatch` | 已有真实观察与冻结检查不符，不能称该项当时通过。 |
| `missing` | 没有工具名和完整参数精确匹配冻结检查的历史调用。 |
| `unknown` | 来源不唯一、回执断配、缺少观察字段、工具失败或执行效果未知，不能确定该检查的结果。 |

每项按冻结合同的检查顺序返回，选取最近一个包含精确匹配调用的批次，不用较早的成功盖过后来的不符。同批有多个匹配调用时保留未知；后续不匹配的工具调用不会遮掉原历史来源。存在待完成调用或未知副作用时，报告保留可定位的已配对来源，但整体及各项均标为未知。聚合状态按未知、不符、缺失、全部匹配的顺序确定。

这些是历史证据状态，不是任务完成状态。即使报告全部为 `historical_match`，也不表示当前源码、依赖或环境仍与当时一致，更不表示用户的整个目标已完成。没有冻结回执检查的旧任务，不能从文字成功说明反推验收合同。

查询只读，不运行原工具、不派发子代理、不恢复任务、不补发消息，也不重置预算。重启后继续读取已持久化的同一记录；存储损坏或来源校验失败仍明确报错，不清空数据。发送、部署或执行结果未知时保留原状态，不能借查询自动重放。

## 已接通与尚未接通

本切片接通的是“原子代理持久记录 → 冻结检查的真实回执 → 自动附带或按需查询的结构化历史报告”。它让接收者直接取得原证据摘要，不要求先翻完全部执行日志或例行再查列表。实现与测试结果须以对应变更的实际记录为准，本文不代表已上线。

以下路径仍未接通，不能据此宣称已经消除重复测试：

- 普通测试命令的源码、依赖、产物和执行环境绑定，以及绑定的当前有效性核对。
- 父任务或后台把子代理历史报告直接用于自身冻结合同的完成验收。
- 完成验收、策略学习与认知投影共用同一份当前有效证据结论。
- 旧任务合同迁移，以及新的证据复用验收策略。

现有 `kind=receipts` 合同仍要求 `require_final_batch=true`，验收器、修复调度和相关消费者继续遵守原语义。本切片既不把该字段改为 false，也不把历史任务批量改成完成。因而“测试通过后又登记进度导致最后批次失配”的重复验收问题仍待后续改造；历史报告只能把原检查结果如实保留下来并供查询。

## 后续复用的边界

后续采用历史证据证明当前结果前，宿主必须能把原回执绑定到被测对象和必要条件，并判断相关变化是否使其失效。文件内容摘要只证明相应字节；命令退出码为零只证明该次命令成功；两者都不能单独替代当前产物、完整测试覆盖或真实送达。

优先复用已有受信快照与回执，不让模型填写一套新的证据表。无法确定依赖范围、并发写入或外部环境时，应保留待核验及具体缺口；不要把缺少绑定误报为实现失败，也不要默认重跑全部操作。能可靠确认无影响的后续动作，才可越过机械工具批次位置复用原结果。

新策略须显式启用并保留旧合同语义；回退保留历史证据，不能重放未知外部效果。取消、撤权和资源限制在查询与后续执行各自的授权范围内持续有效。
