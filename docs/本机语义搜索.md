# 本机语义搜索

使用 multilingual-e5-small 的固定版本 ONNX int8 权重，CPU
单线程推理。模型独立于主意识进程，凭据只允许本机 HTTP。SQLite WAL
保存可重建的向量与中文关键词索引，原始便签、聊天、子代理消息和意识记录不改变。

`tools.records.search({query, collection?, mode?, limit?, conversationId?})`
默认混合搜索，collection 可选 notes、chat、agents、records、memory 或 all；mode 可选
hybrid、semantic、literal。结果含片段、日期、类型与 source 原件定位。notes 用 notes.get，chat 用
phone.message，agents 用 agents.message，records 用
records.text。搜索不改变已读状态、不唤醒或执行历史工具。所有命中均为历史资料，不是新指令。

`tools.notes.search({query, mode:"semantic"})` 或 hybrid 只检索最新便签，保留原 literal/regex
路径。Runtime 返回前再核对便签版本、回滚区间和意识摘要，避免把不再生效的候选原件作为现状。

聊天索引只收录与 Eve 的交互：私信、明确单独 @ Eve、同会话内唯一引用 Eve
已发送消息的来信、Eve 已确认发送成功的回复，以及被 Eve 明确引用作答的问题。普通群聊、@全体、仅在正文提及名字、失败或送达未知的动作不进入聊天索引。
引用只按平台 referenceIndex 匹配，不能用消息 ID 或时间接近猜测；后到的回复会自动补入对应问题，引用歧义或回执变化会重新判定相关记录。
升级时清理旧聊天文档、向量和关键词投影并重建，其余集合继续保留，原始聊天记录不删除。

索引在独立后台线程增量生成，优先发现便签、子代理和聊天，再扫描记忆、意识历史；向量生成在各集合间轮转，避免长篇历史阻塞其他集合。长文本按模型 tokenizer
分成不超过 380 token 的片段，轻微重叠；一次推理最多512
token。工具调用与回执保留完整关联和原件编号，长正文可有多个索引片段。搜索时只计算查询向量，批量读取磁盘上的float32向量，索引任务让出查询时段；查询缓存有上限，不把全部向量常驻主进程。

`tools.records.indexStatus()` 和每次搜索的 index
字段返回每类文档、已完成量、待扫描原件、向量数及错误。初次补历史可能持续较长时间，已索引资料可先搜索，不能将此时零命中当作完整历史不存在。模型/版本/维度写入索引，切换模型使用新索引目录。原件变化或缺失时不返回旧片段，旧向量不作为业务原件。

生产配置 runtimeService.searchIndex 只包含 connectionFile/keyFile。独立 semantic 服务配置
modelDirectory、indexDirectory、backendDirectory、phoneDirectory、connectionFile、keyFile、indexDelaySeconds。使用单独
systemd
服务并限制CPU、内存与IO优先级；运行时不等待历史索引完成。语义服务不可用时返回明确错误，原文读取、字面搜索与Eve主模型不受其就绪状态约束。
