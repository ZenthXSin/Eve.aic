# 脚本事实账本

脚本账本保留每份请求、动作开始、真实回执和完成通知，插件快照及升级回滚不会回滚这些事实。
原脚本执行结果未知时不会重跑；宿主重启后的判断仍由 `ScriptRuntime.initialize` 完成。

v2 使用 `index.json` 小格式标记、`commits/` 摘要链提交日志和 `objects/` 内容寻址原件。
提交先写入并同步所需内容对象，再把小引用提交到日志；日志持久完成后才向运行时返回成功。
账本不再把全部历史和原图收集进一个 `index.json`，也不再受整个旧索引 128 MiB 的限制。

大字符串、元数据节点和长数组按内容寻址保存。相同原图在动作回执、脚本结果或多个任务中出现时共享一份内容原件，
读取状态、回执目录或修改其他字段不会解开原图正文。任务及完成记录是数组兼容的惰性视图，
`change(callback)` 提供独立草稿，提交只保存有变化的对象引用。编号索引只保留任务编号与位置，
不缓存所有任务正文；`job`、`findJob`、`jobIndex` 可用于定位任务，避免反复扫描旧元数据。

单个内容对象上限 64 MiB；长数组以每 256 个元素分块，账本总历史没有对应的单文件总量限制。
这仍要求内存容纳调用方实际请求的一份大值；调用方主动展开全部历史或大值时也会产生相应内存。

旧 `schema:1` 索引会以原始字节保留为 `legacy-index.json`，内容导入后才建立 v2 标记。
若迁移在重命名后或提交后中断，重启会对照旧原件摘要验证恢复，已有迁移提交不重复导入。
旧原件缺失或更改、内容对象缺失或摘要不符、未知/临时文件、符号链接、提交断链都会拒绝启动并保留现场。
运行中读到损坏原件会使账本不可提交，不能把损坏数据当成空账本开始执行。

交接必须复制完整账本目录，包括 `index.json`、`commits/events/`、`objects/` 和存在时的
`legacy-index.json`；各层 `writer.lock` 属进程锁，不复制。旧对象及失败提交留下的原件属于事实或诊断证据，
不是可直接清理的编译缓存。

原生工具 `execute_script` 同步完成时，在任务摘要旁返回 `result` 原件文本页，最多 8192 个字符。
该页的 `text` 是脚本 `return` 值的 JSON；`truncated` / `nextChar` 明确指示分页。
异步任务完成后可用 `return await tools.scripts.result({jobId, startChar, limit})` 读取原件，
其返回页同样可通过原生回执看到，避免只得到新的任务编号而不断递归查询。原件和动作回执保持独立留存。
