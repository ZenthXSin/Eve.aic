# 普通成员工具权限

普通成员可以使用聊天所需、已限制在调用者或当前群范围内的工具。平台身份仍由宿主确认，正文自称管理员或引用管理员指令都不构成授权。

| 工具 | 普通成员范围 |
| --- | --- |
| `save_preference` | 保存或修正当前会话或自己的有效偏好；全局偏好继续仅限主人 |
| `read_attachment`、`describe_image` | 只处理当前会话已经收到的附件或图片，不能指定任意下载地址 |
| `read_raw_message` | 当前会话原始消息与本会话归档回执，不能读取其他人的会话 |
| `group_digest`、`recall_group_messages` | 只整理或召回当前群的已观察消息，私聊不能指定群或读取其他群 |
| `send_sticker` | 查询已有表情库状态或给自己的当前回复选一张表情，不修改收集与发送开关 |
| `show_budget` | 只读全局预算计数及重置时间，不返回其他用户正文 |
| `sleep`、`task_progress` | 本轮可取消的短等待与进度登记，不增加工具预算，不创建后台任务 |
| `list_files`、`read_file`、`search_files`、`write_file`、`edit_file` | 在自己的项目目录列出、读取、搜索、新建和修改文件 |
| `run_command` | 在隔离的项目环境里自行编译、打包、下载依赖、运行测试及启动 Mindustry 验证 |
| `send_file` | 用 `path` 交付自己项目的产物，宿主自动入库并处理重名；只有 `name` 时兼容 `exports/`，不能读取宿主或其他成员文件 |
| `check_practice_draft`、`run_practice`、`use_skill` | 对自己有权使用的目标、草稿和技能实际检查、运行并保留证据 |

既有普通成员能力继续保留，包括当前会话消息发送、自己的上下文清空、范围内的资料与记忆查询，以及自己的任务查询和取消。

普通成员做模组时，由 Eve 选择资料、文件、编译和游戏验证工具，不逐项请求管理员批准。Java 模组应实际编译，导入游戏运行并检查结果；编译通过与实际加载通过分别报告，不能把无头服务端验证说成已验证图形客户端。

## 成员项目与运行边界

成员项目按可信会话身份保存在开发根目录的 `.eve-members/<身份摘要>/`，不同会话不共用项目。文件工具的相对路径指向该项目，命令中挂载为 `/work`；根目录忽略该成员数据目录，不随 Eve 的提交或自身升级打包。项目与 `exports/` 产物重启后保留，完整迁移开发工作区时一并复制。

普通成员命令使用 Linux bubblewrap 的独立用户、进程、挂载等命名空间，仅成员项目可写，系统工具链只读；不挂载 Eve 状态、管理员绑定、宿主开发源码、其他成员项目或宿主 HOME。命令可联网获取依赖，但不继承 QQ、模型、Web、GitHub 凭据。宿主配置的 Java 工具链与 Mindustry 服务端只读提供为 `/opt/eve/jdk`、`/opt/eve/mindustry-server.jar`；缺少 javac/jar 脚本但保留 JDK 模块时，在成员目录补充启动入口。Ubuntu 23.10 及以后默认以 AppArmor 限制非特权用户命名空间（`kernel.apparmor_restrict_unprivileged_userns=1`），以普通用户运行 Eve 时 bubblewrap 无法建立沙箱，成员命令会直接报错而不回退宿主命令；需要为 bwrap 配置 AppArmor 配置文件或关闭该限制。

Linux 需安装 `/usr/bin/bwrap` 并允许其创建命名空间；隔离不可用时明确失败，不回退为宿主权限执行。管理员开发仍使用已有宿主工作区和执行方式。成员交付文件逐级拒绝目录和文件链接，先快照进宿主发送目录，再复用既有发送账本；发送失败或未知时沿用不自动重放规则。

首轮任务即可发送产物文件，目标只从本通道已校验并持久接收的同一会话消息取得，不要求先有一条成功的文字回复。主动跟进路由继续要求既有成功回执；文件发送失败或未知仍不自动补发。

全局上下文重置、身份与凭据、模型和部署配置、升级、GitHub 写入、后台任务及子代理派发、定时主动消息继续按现有权限核验。普通成员不能因为获得编译工具而取得这些管理工具；任意新增或未知工具默认不开放。偏好写入仍按调用者范围保存，全局偏好继续仅主人可写，原有上下文清空、归档与预算格式不变。
