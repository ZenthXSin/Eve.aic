# 主动提问训练

Eve 根据当前会话已完成的真实历史，一次主动提出一个关于称呼、语气、回复长短或分段习惯的问题，等待回答再追问。用户可以跳过、纠正或处理实际任务；当前明确请求优先。本模式采集后续[表达偏好与分段学习](./表达偏好与分段输出.md)的证据，不更新模型权重、不改写 AGENT 身份，不宣称已实现长期学习或 AGI。

训练策略 v2 先回应当前内容，按需最多追问一件事，不要求每轮都有问题；根据真实历史理解简短回答，采用本会话明确反馈，不重复已回答的调查。用户转入实际任务或拒绝追问时，优先处理当前意图；普通拒绝按对话历史回应，持久关闭模式仍使用 `/train stop`。短回复可用一个自然段，按信息分组拆段，保留代码和命令完整。

## 使用与边界

私聊发送 `/train start`；群聊需 **@机器人** 后发送。SDK 订阅 `GROUP_AND_C2C = 1 << 25`，只接纳官方 `GROUP_AT_MESSAGE_CREATE` 群事件，不监听未 @ 的普通群消息，不接纳机器人消息。QQ 开放平台控制台须已开通群聊能力，机器人须加入目标群；沙箱运行还需将测试群加入沙箱范围。代码不能代替平台授权。

| 命令 | 行为 |
| --- | --- |
| `/train start` | 先保存开启开关，取消并等待本会话旧代，再以命令原文开始第一轮提问 |
| `/train stop` | 先保存关闭开关，取消在途问题，丢弃本会话排队回答和未发旧回复，保留完成记录 |
| `/train status` | 查看开关，不调用模型 |
| `/train` | 显示帮助，不调用模型 |

AppID、范围、目标与发送者共同确定可信会话。不同群和发送者的开关与历史隔离，不从用户文字推断身份。`--training` 默认启用新会话，持久化 stop 优先于重启默认选项；普通聊天仍可继续。已送交 QQ 的消息无法撤回，命令仍受通道容量上限约束。

训练每轮仍发送一条关联原始 QQ 消息的回复，可以在同一条文字中自然分段；多条语义片段及发送节奏学习仍待长期记忆阶段。一次一个问题属于上下文策略，报告中的问号指标不等同严格语义保证。

## 契约与持久化

`eve-training-api` 定义服务、句柄及命令；`eve-training-plugin` 提供持久开关与 `TrainingContext`，后者可组合其他公开服务实现；QQ 插件可选接线，`eve-qqbot` 负责组合。Kernel 不含训练业务。LLM `ContextAssembler::assemble_scoped` 默认委托原 `assemble`，兼容既有装配器；Session 宿主提供经验证的 `ContextScope`，完整历史仍只来自 Session。训练规则属于本轮上下文，不改写用户原文，启停服务不作为模型工具发布。

插件命名空间保存 `modes.v1`（版本 1），最多 256 个作用域、256 KiB。修改先保存再更新内存/确认，失败保留原模式；容量满拒绝新增，不淘汰旧开关。损坏、未知字段、重复作用域或不兼容版本拒绝启动，不清空。停止后旧句柄拒绝读写，重启读取开关。Session 与 QQ 回执沿用[原有恢复语义](./QQBot通道.md#去重提交与恢复)，Processing/ReplyPending 不自动重放。

## 六小时 Actions 测试

[专用工作流](https://github.com/ZenthXSin/Eve.aic/actions/workflows/qqbot-training.yml) 仅 main 运行。先在无凭据的构建任务准备同一提交的运行包，再在上限 360 分钟的训练任务启动真实 QQ SDK 和主模型。默认窗口 21300 秒（约 5 小时 55 分），预留就绪、取消保存及报告上传；真实 ready 后计时，同时受进程启动后的任务预算约束。

Secrets 使用 `QQBOT_APP_SECRET`、`EVE_OPENAI_API_KEY`，AppID 1904159860 和 deepseek-v4.1-flash。按用户指定的正式群，默认 `sandbox=false`，连接 `https://api.sgroup.qq.com`；沙箱须显式选择。合入本轮 `.github/qqbot-training-request.json` 按用户授权启动一次，此文件后续变更代表新训练请求，普通源码更新不启动窗口。手动入口可选 60 至 21300 秒。

训练任务使用同机器人并发组串行运行。切换时可在请求或手动入口显式提供 `replace_run_id`：控制任务仅使用当前仓库的 Actions 写权限，核对目标为 main 上的本训练工作流，停止指定运行并等待其结束后才构建、启动新窗口；身份不符、停止失败或超时均拒绝启动。未指定目标则沿用排队。控制任务位于并发组外，避免被待停止的旧窗口阻塞。取消保留已经上传的 artifacts；旧 runner 尚未上传的临时交流记录无法保证恢复，不自动宣称已保存。

“确认实际网关就绪”步骤成功才表示 SDK 已连接，`eve-qqbot-training-ready` 保存无正文的环境标记、开始与预计结束时间。ready 不证明实际群收发，最终报告分开统计私聊与群 @ 发送。默认训练开启，第一条普通文字即可引导问题，也可 `/train start` 明确开始。

窗口结束发送 SIGINT，最多等待 120 秒收尾。未完成生成取消并保留状态；进程、分析或保存失败明确标记。正常结束但零交流仍报告 `interaction_ok=false`。可在 Actions 取消；极端硬终止可能来不及上传，runner 临时目录不永久保存。

最终 `eve-qqbot-training-results` artifact 保留 7 天：公开 `training-summary.json` 只含时间、进程状态、接收/完成/发送及失败计数、群 @ 计数、问题/段落等指标。`training-state.enc` 保存完整 Session、QQ 回执、训练开关和 `training-report.json`。只把 Completed 且 Sent 的模型问答作为成功证据，控制确认、失败、中断及未确认投递单列；反馈关键词仅是待复核候选。原始诊断不上传，正文及路由 ID 不写日志或公开摘要。

正文包使用本轮 `QQBOT_APP_SECRET`：OpenSSL AES-256-CBC、PBKDF2 200000 次，再用独立盐和派生密钥计算 HMAC-SHA256，先认证再解密。密钥不进入参数、文件或报告；GitHub artifact 不承担正文保密。轮换 QQ Secret 前须保留本轮解密凭据。解密到不存在的新目录，拒绝覆盖或不安全归档成员：

```sh
# 下载结果包后，在本地环境提供本轮 QQBOT_APP_SECRET。
python3 connectors/qqbot/training-window.py --decrypt training-state.enc --output ./training-review
```

后续依据报告中的用户原文、实际回复和分段反馈调整策略，长期偏好提炼另行 PR。不能把问号减少、沉默或一次同意当成已学会偏好。

## 公开场景验收

追加真实记录复核因自动审批拒绝而未执行：审批指出再次发送解密交流到外部主模型缺少该目的地的明确授权。因此本次恢复请求文件为 main 原文，并移除真实复核的自动 push 触发，仅保留手动入口，保留已完成结果；候选新版接入采用[公开场景工作流](https://github.com/ZenthXSin/Eve.aic/actions/workflows/qqbot-policy-benchmark.yml)。该入口只读取仓库中独立新写的 12 个公开场景、AGENT 身份及新旧提示词，不下载 artifacts、不读取状态目录、不认证解密，也不读取 QQ Secret。

公开场景覆盖短答、普通闲聊、明确反馈、实际任务、拒绝追问和代码完整段落；使用相同 512 token 生成、固定枚举评审、36 次请求上限、600 秒期限与零重试，并要求完整覆盖、提问判断无不确定、所有问题指标不变差。公开摘要包含场景与候选文本 SHA256，用于核对接入版本；不保存模型正文。请求文件 `.github/qqbot-policy-benchmark-request.json` 只触发公开场景对照，不启动 QQ。此结果只能说明公开场景表现，不能当作修正版真实交流回放或用户满意度验收；正式群 @ 与长期学习仍未覆盖。
