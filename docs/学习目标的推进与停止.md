# 学习目标的推进与停止

用户提过的兴趣会派生一个学习目标，后台按它研究、实践，必要时问用户，学到东西后邀请用户。以前，这个目标在用户撤回兴趣之前一直处于“等待”。即使研究和实践的次数早已用完、再也不会有任何进展，它也还是“等待”。用户问“你那个学得怎么样了”，Eve 说不清接下来会做什么。

现在，Eve 按记录对每个学习目标判断接下来是**继续**、**请求澄清**、**等待**还是**停止**：

- 判断会交给对话和 `/interests`，用户问起时能如实回答。
- 开启 `--learning-stop` 时，确实没有事可做的目标会被标为已取消，并记下原因。这正是学习目标自带的停止条件“学习预算耗尽”。

## 启用

```bash
./target/debug/eve-qqbot --state-dir .eve-qqbot --interest-learning \
  --research-source https://example.org/docs/ \
  --practice-mindustry-server /opt/mindustry/server-release.jar \
  --agenda-context --learning-stop
```

- 只要开启兴趣学习，`/interests` 就会显示判断；开启 `--agenda-context` 时，判断也会交给对话。判断只读记录，不改变任何状态。
- `--learning-stop` 默认关闭，需要同时开启 `--interest-learning`。不开启时，判断为停止的目标仍保持等待，只是如实说明“不再推进”。

## 判断规则

判断只看宿主读取的记录，不调用模型。按下表**从上到下**取第一条成立的规则：

| 顺序 | 情况 | 判断 |
| --- | --- | --- |
| 1 | 没有开启研究或实践 | 等待（没有能力） |
| 2 | 当前版本的研究或实践正在进行 | 继续（正在做） |
| 3 | 当前版本还没研究，且研究还有次数 | 继续（准备研究）；预算不够时等待预算重置；研究记录已满时转第 9 条 |
| 4 | 研究对当前版本已有结局（或研究次数已用完），当前版本还没实践，且实践还有次数 | 继续（准备实践）；同上 |
| 5 | 请求澄清正在准备或发送 | 请求澄清 |
| 6 | 邀请正在准备或等待时机 | 继续（准备告诉用户） |
| 7 | 已经问了用户或发了邀请，仍在回应窗口内 | 等待（等用户回复） |
| 8 | 当前版本卡住（实践尝试用尽未验证或做不了；只开启研究时为没找到可引用的资料），且这个版本还没问 | 请求澄清 |
| 9 | 实践曾经验证通过，且还没邀请过 | 继续（准备告诉用户） |
| 10 | 用户回应邀请时提出的后续创作还在进行 | 等待（后续创作） |
| 11 | 第 3、4 条因记录已满而没有开始 | 等待（需要操作者处理） |
| 12 | 研究与实践的次数都已用完 | **停止**（学习次数已用完） |
| 13 | 兴趣已记不下新的陈述 | **停止**（记不下新的想法） |
| 14 | 其余情况 | 等待（等用户提到新的想法或情况） |

几点说明：

- **次数**：每个学习目标至多研究 3 次、实践 2 次，跨版本累计，重启不清零。用户每次提到新的想法，学习目标就有一个新版本，每个版本至多各做一次。
- **失败不算卡住**：模型失败、超时或中断，不算卡住，也不会对同一版本重试。这些情况落到最后一条，等新版本。
- **停止的前提**：只有在没有任何正在进行的事、没有在等用户、也没有后续创作时，才会停止。
- **记不下新的陈述**：兴趣的普通陈述至多 15 条。只有目标已同步到兴趣的最新修订时，才按“记不下”判断。
- **只判断兴趣仍有效的目标**：兴趣已撤回时，原有同步会把目标取消，这里不判断。

规则是可替换的公开契约 `PursuitPolicy`，默认实现为 `RulePursuitPolicy`（版本 `pursuit-rules:v1`）。

## 用户看到什么

- **`/interests`**：等待中的学习目标会显示“后台学习中（接下来：……）”，例如“准备动手实践”“等你回复”“能做的都做了，等你提到新的想法或情况”“学习次数已用完，不再推进”。已停止的目标显示“已停止：学习次数已用完”。
- **议程上下文**：每条兴趣多一个 `next` 字段，例如：
  - `{"verdict":"continue","step":"practice","started":false}`
  - `{"verdict":"wait","reason":"new_input"}`
  - `{"verdict":"stop","reason":"learning_budget_spent"}`
  - 已停止的为 `{"verdict":"stopped","reason":"learning_budget_spent"}`。

  数据前的说明会告诉模型各值的含义，并要求不要承诺 `next` 之外的后续。

停止不会另外通知用户；用户问起时，Eve 会按上面的数据如实说明。

## 停止怎样写入

开启 `--learning-stop` 时，后台每 0.5 秒核对一次。对判断为停止的目标，执行**一次**认知状态替换：

- 目标从“等待”改为“已取消”，等待原因清空，其余内容不变。目标版本加一，作为终态不再改动。
- 同时追加一条事件：
  - 来源为 `Internal`/`eve.pursuit`；
  - ID 由目标与停止时的版本确定；
  - 摘要是 `pursuit-stop:v1` 记录：原因、停止时的目标版本、研究与实践已用次数、规则版本，并注明不是用户指令；
  - 不含用户原话。
- 兴趣本身保留，仍可用 `/forget-interest` 撤回。

## 持久化与恢复

- **没有新的账本**：判断每次重新计算；停止只写认知状态，状态与事件在同一次替换里一起生效或一起不生效，重启后没有中间状态需要补齐。
- **冲突与稍后再试**：做判断后，目标如果有了新版本（例如用户又提到了这个兴趣）就不停止，下一轮重新判断。认知状态正被其他组件更新、或事件记录已满时，不写入，下一轮再试。
- **写入失败**：认知状态写入失败时，后台结束，宿主停止准入并保留状态，与其他后台一致。原记录的损坏处理不变，不会自动清空。
- **兼容**：只用到已有的状态与事件格式，旧版本程序可以照常读取停止后的状态。

## 分层

- **定义层**：`eve-pursuit-api`，包括：
  - 事实 `PursuitFacts`、判断 `Verdict` 与可替换的 `PursuitPolicy`；
  - 停止记录 `StopRecord` 与相关常量。
- **实现层**：`eve-pursuit-plugin`，包括：
  - 默认规则 `RulePursuitPolicy`；
  - `stop_goal`：一次替换标为已取消并追加事件；
  - `stop_record`：只认本来源、本格式、ID 与版本一致的事件。
- **组合层**：`qq_pursuit`，负责：
  - 从兴趣、研究、实践、请求澄清、主动交流与预算记录整理事实；
  - 把判断交给议程上下文与 `/interests`；
  - 开启 `--learning-stop` 时运行停止后台。

## 尚未覆盖

- **长时间无进展**：目标没有新输入、长期停在“等待”时，不会按时间自动停止；它不消耗预算。
- **停止后恢复**：停止后，用户再提到这个兴趣也不会重新开始。重新开始需要新的预算设计。
- **面板显示**：Web 面板尚未显示推进判断。
