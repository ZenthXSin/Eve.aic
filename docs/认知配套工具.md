# 认知配套工具

`eve-memory` 提供本地记忆检查入口，认知场景评估运行真实 `eve-cognition` 子进程。两者都不需要外部模型凭据。它们分别回答“保存了哪些来源、哪些偏好仍有效”和“这次构建是否正确执行了限定流程”；测试通过不代表已经具备通用智能。

## 只读查看已有记忆

先构建入口：

```sh
cargo build -p eve-app --bin eve-memory
```

状态目录必须显式指定并已存在，作用域必须同时给出通道、完整会话 ID、用户 ID。QQ 的完整会话 ID 包含通道生成的路由信息，不能拿显示昵称代替；可信本地管理员可以用 `scopes` 查已有作用域。

```sh
target/debug/eve-memory --state-dir /path/to/existing-state scopes --page 1 --page-size 20
target/debug/eve-memory --state-dir /path/to/existing-state \
  --channel qq --session FULL_SESSION_ID --user USER_ID status
target/debug/eve-memory --state-dir /path/to/existing-state \
  --channel qq --session FULL_SESSION_ID --user USER_ID list
target/debug/eve-memory --state-dir /path/to/existing-state \
  --channel qq --session FULL_SESSION_ID --user USER_ID show --id PREFERENCE_ID
target/debug/eve-memory --state-dir /path/to/existing-state \
  --channel qq --session FULL_SESSION_ID --user USER_ID evidence --id EVIDENCE_ID
target/debug/eve-memory --state-dir /path/to/existing-state \
  --channel qq --session FULL_SESSION_ID --user USER_ID recall --query 资料来源 --limit 5
```

`status` 给出当前作用域的证据、偏好、确认、撤销和历史版本计数。`list` 按偏好 ID 排序，`show` 的历史按修订升序排列。列表和历史默认每页 20 条，`--page-size` 范围为 1 至 50；超过总页数会明确失败，空列表仅允许第一页。每份报告带 `format_version: 1`、命令和只读标记；有作用域的报告还带完整作用域及该作用域的修订。

默认输出不包含偏好、用户消息或助手回复正文。`list`、`show`、`evidence` 显式加 `--include-content` 才返回每段至多 512 UTF-8 字节的预览，并标出原始字节数和是否截断。`recall` 同样需要 `--include-content` 才显示命中片段，但它只知道片段字节数，不声明原文总长度。整份 JSON 至多 256 KiB，过大时拒绝输出。偏好 ID、消息 ID 和作用域标识仍会出现在默认报告中，命令只供有权读取该状态目录的本地操作者使用。

有效状态以最新偏好版本为准：撤销的偏好和旧修订保留来源，但 `current_effective` 为 `false`。`show` 给出每个历史版本的证据 ID、来源类型和引用是否存在；原始来源正文仍需通过 `evidence --include-content` 单独读取。`evidence` 把用户声明与已完成交互区分开，并将交互中的用户输入和助手回复分列。助手回复是历史交互内容，不因此成为已核实事实。反向引用最多显示 50 条，另有总数和截断标记。

`recall --query 关键词 [--limit 5]` 通过公开 `MemoryRecallFactory` 绑定同一个完整作用域，执行有界词法检索。查询为 1 至 1024 UTF-8 字节且不含控制字符，至少包含一个文字或数字，不能只有标点或符号；返回上限为 1 至 8 项。默认报告只列出来源、词法排序分数、`excerpt_bytes` 与 `excerpt_truncated`，不回显查询或命中正文。来源分别指向仍有效的当前偏好版本，或已完成交互的用户/助手字段；更正前、已撤销的偏好不作为当前偏好召回，但同样文字若存在于独立的已完成交互中，仍可能作为明确标注来源的历史内容出现。分数不是概率、可信度或事实正确性判断，召回不会新增记忆。实现与范围限制见[记忆召回](记忆召回.md)。

入口通过 `MemoryPlugin` 的公开读取能力加载状态，不直接解析记忆数据库记录，不导入会话、不确认偏好、不调用模型。读操作不提高记忆修订，也不重写文件快照。状态目录继续使用后端的排他锁，因此运行中的宿主占用目录时命令会失败；不会停止宿主或绕过锁。后端可能创建或打开锁文件，这不属于记忆写入。

PostgreSQL 必须使用已绑定目录并提供匹配的 `--database-config`；只读连接要求已有状态 schema，拒绝初始化、迁移和状态写入。普通对话入口原有的显式初始化行为不变。文件或数据库状态损坏、版本不支持、绑定不符、锁冲突和读取失败都会返回非零退出码，保留已有状态，不自动清空或改用空库。

## 可重复的认知流程评估

现有 `benchmarks/cognition/evaluate.py` 使用临时目录、合成输入和回环 HTTP 模型替身，实际启动编译后的 CLI。评估覆盖反思持久化、来源隔离、预算、无效模型产物、禁止工具调用、中断恢复，以及文件变化后重规划、保留用户约束、同源去重和重启不重放。

```sh
cargo build -p eve-app --bin eve-cognition
python3 benchmarks/cognition/evaluate.py \
  --binary target/debug/eve-cognition \
  --output /tmp/eve-cognition-evaluation.json \
  --source-sha "$(git rev-parse HEAD)"
```

`--scenario NAME` 可以重复提供以选择单独场景，未知名称会报错；不提供时运行全部场景。例如：

```sh
python3 benchmarks/cognition/evaluate.py \
  --binary target/debug/eve-cognition \
  --output /tmp/eve-cognition-file-evaluation.json \
  --scenario file_changes_replan_and_restart_deduplicates \
  --scenario file_observation_preserves_user_constraints \
  --scenario file_sources_and_owner_isolation
```

报告 `format_version: 2` 保留执行的场景、流程维度、真实观察到的 HTTP 请求数、CLI 运行计数、失败检查名，以及二进制和评估脚本的 SHA-256。`--source-sha` 接受空值或 7 至 64 位十六进制摘要，报告中的 `declared_source_sha` 仍是构建者声明，不能单凭它证明二进制来自该提交。报告不保存请求正文、记忆正文或临时目录路径。`functional_ok` 仅表示本次选中的场景全部通过。

文件场景等待真实持久状态和模型请求门控后再继续，不把模型返回了一段固定文本算成现实任务完成。停止测试时仅操作本评估创建并持有的子进程；没有 PID 文件查找、全局进程名终止或正式 QQ 服务操作。

固定模型替身评估的是流程正确性，`real_model_evaluated` 与 `semantic_quality_evaluated` 都为 `false`。反思的事实准确性、规划质量、跨任务泛化、真实模型效果、真实 QQ、PostgreSQL 和外部行动效果仍需单独验收；本报告不提供 AGI 分数。
