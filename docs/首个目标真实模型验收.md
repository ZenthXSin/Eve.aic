# 首个目标的真实模型内部验收

`connectors/qqbot/first-goal-acceptance.py` 驱动真正的 `eve-qqbot`，通过本地 QQ 协议替身输入普通对话，调用操作者明确选择的真实模型，并把产物交给真实游戏或浏览器。它不使用正式 QQ 密钥，也不代表正式 QQ 已完成投递验收。

脚本是需显式启用的实验，不进入常规 CI 的外部模型调用。模型可能失败，脚本不补字段、不修改模型答案、不降低验证标准，也不把模型声称完成当作通过。请先确认使用的模型允许接收这些合成对话、公开文档与生成产物，并自行设置调用预算。

## 准备和运行

需要 Python 3、Node.js、已编译的原生程序、可用的 HTTPS Chat Completions 服务，以及 Java 与 Mindustry 服务端 jar，或可用的无头 Chromium。模型凭据通过私有环境变量 `EVE_OPENAI_API_KEY` 提供，不放在命令行、报告或仓库中。每次实验必须使用全新输出目录；脚本不会清空已有结果。

```bash
cargo build --locked -p eve-app --bin eve-qqbot
python3 connectors/qqbot/first-goal-acceptance.py --help
python3 connectors/qqbot/first-goal-acceptance.py --real-model \
  --output /tmp/eve-goal-trial-001 \
  --endpoint https://openrouter.ai/api/v1/chat/completions \
  --model '<已授权的模型标识>' \
  --mindustry-server /opt/mindustry/server-release.jar \
  --source https://mindustrygame.github.io/wiki/modding/1-modding/ \
  --opening '我喜欢 Mindustry 的模组，但不知道怎么创作。' \
  --follow-up '请沿用刚才验证过的方块做法，做一份模组名为 bronze-workshop、方块名为 bronze-wall 的模组，其他属性不变。' \
  --expect-argument bronze-workshop --expect-argument bronze-wall \
  --withdrawal '我现在对 Mindustry 模组没兴趣了，先停下，也别再主动提这件事。'
```

留出领域使用相同流程，将运行器替换为 `--browser /opt/chromium/headless_shell`，入口换为公开 CSS 文档，开场、后续任务与撤回也换成网页设计。后续任务应要求不同参数，例如更改标题字号，并用 `--expect-argument` 核对实际使用的新值；参数必须是这次生成技能能够表达的内容，脚本不预置领域答案或技能模板。浏览器须能在当前环境独立运行；无法启动、超时或非零退出均不算通过。

## 实际断言

脚本先在本轮私有输出目录复制并固定二进制，后续构建不会改变本轮程序。四次独立原生进程依次完成：

1. 一次兴趣表达后，等待逐字来源知识、真实实践与技能泛化验证，以及主动邀请的协议投递记录；逐字引文必须能在保存的原文中找到，实践必须引用实际资料。
2. 回应邀请提出新任务，等待带新参数的技能调用或选择实际验证通过，以及完成跟进的协议投递记录。
3. 无新输入重启，核对知识、实践、技能和邀请账本保持一致，没有重放已结束的操作。
4. 用普通话表达撤回兴趣，核对非空兴趣记录全部转为撤回。

真实运行通过要求环境确认已加载、没有产物警告、全部探测通过。技能先逐字还原来源，再由宿主改变参数实际运行验证；允许的单次纠正另存记录，保留原拒绝，不能循环重试或越过标准。研究推测与来源原文仍分开，实践佐证也不证明原文每一句正确。

`--stage-timeout` 控制单阶段等待期限，`--max-requests` 限制代理转发的实际请求数量。它们不代替模型平台的费用上限。任一阶段失败返回非零退出码，保留已有证据，不自动重跑。

## 证据和边界

`result.json` 保存模型、源提交、源码是否有改动、差异摘要、二进制与运行器摘要、请求计数、最后阶段及各项结论。`requests.json` 默认仅保存请求类别、HTTP 状态与耗时；显式使用 `--record-text` 才保存模型正文。原生状态本身仍含合成对话和生成产物，整个输出目录应按私有实验资料管理。

本地模型代理需要独立随机令牌，真正的外部模型密钥只在代理转发时使用；子进程不继承真实 QQ 或模型环境变量。开发工具只绑定新建的合成工作目录，关闭命令执行和 GitHub 工具，不读取正式训练状态。脚本停止自己启动的子进程，不启动正式 QQ 适配器。

通过只说明所记模型、代码和运行器在该合成场景下完成了闭环。它不证明所有模型都可靠，也不证明任意新领域、真实 QQ 长期节奏、长期偏好学习或完整 AGI 已验收。失败记录应与成功记录一同保留；公开报告只公布合成用例、源码版本和必要结论。
