# 后台发言事件与用户输入

任务完成、条件唤醒、健康检查会产生各自的宿主事件。QQ 保存的最后一条入站用于确认收件人和读取会话语境，不能因为它仍是最后一条消息就将它再次作为新用户请求。

此前所有自主发言请求都在最后的 User 数据中提供 `current_user_message`，要求结合当前原话回复。因此一条“晚安”只入站一次，后续多个独立后台事件却会继续回答它；模型故障期间积压的事件恢复后还会集中发生。

现在只有 `foreground-input` 和锚点仍对应原入站的 `host-reply` 具有 `trigger=user_input`。后台事件使用 `trigger=background_event`，末尾请求只带本次 `event_id` 和 `host_event`；最后收到的完整原话移到当前资料的 `latest_user_message` 中，不再作为新的对话输入。重新绑定了最新入站的旧命令结果也属于后台事件。原话中的纠正、取消或暂不打扰仍可参与交流判断，不能扩张业务授权。

同一个 Eve 的人格、记忆与真实发言记录仍作为上下文使用。发言记录提供来源、关联入站和更新时间，区分已发、失败、在途与结果未知；这不是逐条比较回复正文的过滤器。不同事件仍可自主选择说、等待或沉默，不要求每次交付工作成果，也不因两次文字相同而拦截新表达。

本次调整不修改持久数据格式、历史事件编号、平台回执或重试身份。已送达和未知状态不重新入队，等待与沉默继续按现有账本恢复。健康事件是否仍有效、条件任务是否已经决定结束交流、前台和主线程怎样承接同一入站，分别由对应来源的生命周期处理。

验证包括请求结构与缓存前缀测试，以及实际 Eve 子进程的本地模型和 QQ 替身验收：一次真实入站后产生三个独立后台事实、跨进程恢复不重开旧输入、不同事件仍可选择相同文字。没有调用生产模型或发送真实 QQ 测试消息。
