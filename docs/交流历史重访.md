# 交流历史重访

本机维护入口让 Eve 在正常交流学习 worker 中重读真实历史，并将可修正经验写回同一训练库。它不创建聊天输入，不重发消息，不执行历史工具，也不清空既有经验。普通实时学习仍使用原来的自主预算；每次明确投递的维护请求最多允许 4096 次模型尝试，领取前持久计数，只有一个请求在途。重访每批最多 128 条、实际 JSON 最多 65536 字节，长消息按原身份分片；普通批次仍为 16 条。

交流学习使用独立的有限时间预算，不再被主模型的请求期限或旧的普通 59/60 秒、维护 180/182 秒限制提前取消。`runtime.model_uses.conversation_learning_timeout_ms` 默认 180000 毫秒，`conversation_maintenance_timeout_ms` 默认 300000 毫秒；两者保存后下一批解析生效，已发出的请求保持原配置。显式设置更短的学习期限仍被遵守，不改变所选模型、思考强度、输出上限、完整来源、旧经验或重访批次大小。

流式学习首个非空响应块可等待本次完整预算；`runtime.model_uses.conversation_learning_stream_idle_timeout_ms` 默认 90000 毫秒，实际取不超过本次总预算的值。以上三个字段均允许 1000 至 600000 毫秒，也可通过对应 `EVE_MODEL_USE_` 加字段大写名的环境变量配置。学习不继承对话的 `EVE_MODEL_*TIMEOUT_MS` 流式限制。空闲检测针对相邻非空传输块，心跳或推理数据不证明语义进展，也不能延长总期限。非流式学习采用同一独立总预算。完整结果已收到后，统计尾流仍按适配器现有有限收尾处理，不因尾流停顿把成功改为超时。

SSE 模型调用的外层比传输预算多一秒；学习器的实际期限包含等待模型并发槽。worker 另设最大可配置预算加两秒的 602 秒硬上界，只防自定义学习器无限等待，不会再用固定短期限覆盖每批解析出的配置。普通与维护继续使用同一交流学习用途和原范围会话标识，不创建新的用途或请求会话。取消立即释放当前请求，保留原在途记录供既有恢复逻辑处理，不通过取消重试来切换学习类别。调度交替只作用于两批之间；新消息仍满足普通学习的条数或等待期限以及已有预算。

在 QQ 状态目录创建 root 持有、组和其他用户不可写的 `conversation-maintenance` 目录。先写入 `events.jsonl`（建议 0600），每行是 `ConversationHistoryRecord`：`scope` 为原可信 `session_id/user_id`，`event` 为原来源 `sequence` 与完整 `ConversationMessage`。沿用原消息 ID、speaker、human/eve 角色和原文，只把实际接收与有 Sent 证据的发送作为发言。历史只有偏序时，metadata.ordering_uncertain 设为 true；未知时间保持缺失。导出者应按原范围内可证顺序排好，并对同一消息身份去重。只剩摘要而无原文的历史不能恢复成消息，须在覆盖报告说明。

最后原子投递 `request.json`，包含 `version:1`、稳定 `id`、`source:"events.jsonl"`、文件 `sha256` 和行数 `records`。最多 250000 行、源文件 512 MiB。入口验证源摘要后按公开持久契约导入；原 ID 正文冲突会停止维护请求并保留原记录，已见而未保存正文的事件可在原摘要一致时补全。`plan.json` 保存原范围和导入后事件序号的冻结顺序，独立重访游标按此顺序消费，正常增量游标不回拨。真实新消息可继续写入；已重访的事件不会因夹入新消息再进入增量模型请求。

`status.json` 包含导入行数、范围数、总事件数、成功处理数、剩余数、经验更新数、失败/未知批次数以及已领取模型请求数。`confirmed_new_events` 是已确认保存的新增事件计数下界：若数据库已提交而状态文件未写入时重启，幂等重投不会虚增计数。`completed` 表示已消费全部冻结来源；`completed_with_failures` 明示其中存在失败、未知结果或旧记录无法确认的部分；`budget_exhausted` 表示有限额度已用完，不能当作全部成功。

`progress.message_counts` 提供完整原消息的终态计数：`failed` 表示至少一片最终失败且没有未知片段，`unknown` 表示至少一片结果未知。`processed` 只统计全部分片都已确认成功的原消息，只有越过原消息结尾才累加一次；未知优先于失败。当前消息尚未读完的分片结局随检查点持久保存，`partial`、`partial_failed`、`partial_unknown` 都是 `remaining` 的子集，不能重复加进终态数量。前两次明确失败仍按原批次重试，不提前计为消息失败；第三次失败才消费该片。终态批次数与消息数含义不同。

旧检查点缺少逐片累计结果时，不扫描全部批次归档来猜测成功：已消费的原消息计入 `unclassified`，原 `processed` 保留在 `legacy_processed` 供核对；旧的未完成分片按未知累计。原消费游标、原文、经验版本和 `covered` 都保留，下一次正常状态提交才保存迁移后的统计。旧 `status.json` 缺少 `message_counts` 时该字段为未知，不能把旧 `processed` 当作全部分片成功。新统计满足 `total = processed + failed + unknown + unclassified + remaining`，`legacy_processed` 不参与相加。

同一请求 ID 和来源清单重投幂等，旧请求 ID 留存，内容变化拒绝。模型在途时退出，恢复后原批次标记 interrupted，保留完整记录并继续后面的消息，不自动重发未知请求。已用过的旧证据可以支持原则措辞修订，但不会增加支持数或清除原反例；宿主通过完整历史版本核对证据身份。缺少可比时序的历史不会被冒充成真人纠正。

`covered` 表示该维护请求已经消费的原事件，包含最终失败与未知，不表示成功。普通学习与维护按批次交替领取；普通游标只越过当前和已归档维护请求的冻结事件集合，继续读取夹在历史之间或后来到达的新输入，不回拨、不使用最大来源序号越过未纳入重访的消息。同范围仍只保存一个在途批次；已明确失败的批次等待原来的重试退避，新输入不能抢占它。4096 次额度耗尽后，普通领取可将已明确失败且等待重试的维护批次本地结算为失败，归档 `budget_exhausted`，保留原批次和 attempt，不增加模型次数、不触碰尚在途的未知请求。尚未处理的冻结来源仍留在维护队列，不能因普通游标越过而假报成功或自动重新投递。

重访满批边界也可保留一条最近 Eve 发言，为下一批开头的真人纠正提供前文。检查点可选字段 `successful_context_from` 记录当前冻结来源中最近连续、完整且成功处理的后缀起点，使用从一开始的来源位置，最多保留十二条资格；原事件序号可以非单调，不能用数值大小替代冻结顺序。背景仅从该成功后缀寻找，完整背景与第一条完整新消息同时符合预算才预留；总数仍不超过 128，背景不推进消费位置、不重复写入 `covered` 或成功计数。

后缀按整条消息所有分片的合并结局更新，失败或未知会切断它；后续新的完整成功消息可以重新积累，不重试已经未知的旧来源。当前未完成分片不作为完整背景。旧检查点缺少此字段时保守保持未知，不从 `covered` 或聚合成功数倒推来源资格。已领取的旧无背景批次继续有效，新带背景批次在恢复时逐字段核对冻结来源中的真实最近 Eve，跳过背景后再核验新消费区和结束位置。字段结构或原件不一致时保留记录并报错。

该检查点扩展支持新程序读取旧状态；旧程序使用严格字段校验，不能保证读取新增字段。回退须保全实际数据库和身份，不得删除字段或用旧备份覆盖新增学习记录来强行启动。

维护额度耗尽后的状态每 60 秒最多只读刷新一次，只有进度变化才重写文件，让普通领取产生的本地结算可见；不会重新开放维护或增加模型请求。其他终态在每次启动时成功刷新一次。旧 `completed` 记录若无法确认完整成功，降为 `completed_with_failures`，原终态不会被重开。

导入或排程发生错误时保留原 phase 与 error，正常服务仍运行。修正外部问题后，root 可原子投递 `resume.json`（同 `id` 和 `sha256`），入口会归档为 `resume.accepted.json` 并从持久状态继续。不能修改源文件来绕过摘要；来源修订需要新请求。当前入口一个目录只管理一个请求；完成后需保全归档整个目录，并重启后投递新请求目录，不能删除旧账本或回拨游标。
