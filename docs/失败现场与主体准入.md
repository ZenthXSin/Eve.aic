# 失败现场、隔离复现与主体准入

本能力接入真实 QQ 宿主工具和执行入口。本地验收使用模拟模型/桥接及真实隔离脚本进程；没有启动正式 QQ、部署或修改生产进程。

## 最小失败现场

启用后台任务后提供 `manage_failure_reproduction`，动作包括 `capture`、`inspect`、`export_summary`、`replay`、`verify_candidate`、`resume_original`。

首版可执行范围是 Python/JavaScript 纯脚本：没有宿主工具、依赖、持久状态字段，输入仅包含有界数字、布尔、null、数组和对象，不含字符串或敏感名称的字段。支持原脚本发送 return 协议消息后异常退出这一明确可观察故障。回执保存 `failure_diagnostic.stage=after_return` 和实际进程退出码；不保存 stderr，也不把同一退出码说成已经证明内部根因相同。旧回执缺少诊断、未知结果、外部工具、状态型脚本、依赖链和其他阶段明确返回 unsupported，不退回真实环境重试。

采集参数示例：

```json
{"action":"capture","call_id":"原脚本工具调用ID","arguments":{"value":7},"task_id":"task-原任务ID"}
```

宿主读取同一真实用户及精确会话的既有回执，核对 arguments 与原 request_digest。可选 task_id 必须有实际检查点调用证据：同一调用 ID、工具名、版本及参数。任意字符串、摘要或模型自称授权均不能替代这些证据。省略 task_id 可单独诊断脚本，不能接续其他任务。

失败包具有 schema=1、内容摘要、真实范围、输入、原版本/源码摘要、回执摘要、失败指纹、原任务关联及七日有效期。源码保留在原有不可变脚本仓库，只保存版本引用，不复制聊天、环境变量、宿主文件或凭据。原仓库不可读时明确失败，因此这不是脱离原安装即可运行的完整源码归档。摘要导出只返回受限元数据，不导出原文、源码、输入或回执结果正文。

同一状态库最多32包、512 KiB账本及256条审计；满额拒绝，审计不会静默覆盖。过期包立即不可读，在下一次采集时回收；不是后台定时物理擦除。所有查阅、导出、重放意图和完成均写入审计。损坏 schema、摘要或账本阻断操作并保留原文件。通过 StateStore 持久化，重开同一文件状态库可恢复。摘要用于完整性核对，不是外部导入包的授权签名；工具不提供任意包导入入口。

`replay` 建立全新临时 ScriptStore，复制允许的不可变版本，初始化空状态，并通过原隔离后端实际运行相同输入。宿主工具派发器一律拒绝；本地隔离后端禁止网络、凭据环境和宿主根目录访问。结束清理临时文件及局部产物。脚本运行仍消耗调用链原共享预算和期限；不产生新额度。若隔离不可用就失败，不使用原生 exec。

先取得原失败的相同可观察指纹，才能 `verify_candidate` 验证同一脚本的候选版本。候选成功表示这个 fixture 的运行完成；不证明完整业务正确。原活动版本、原状态、原失败回执保持不变，工具不自动激活候选。

`resume_original` 仅在候选隔离通过后，把宿主生成的诊断附回已绑定的原 Blocked 任务。使用既有 `resume_blocked`，保留任务ID、原说明、步数、委派用量、期限和最多三次恢复上限；未知副作用、无安全检查点、过期、预算耗尽、取消或通知正在发送都拒绝。子代理/委派上下文不能调用这个接续动作。失败包内容不是新用户发言，不授权发送、数据库写入、升级或扩大任务范围。候选是否应用及真实交付仍由原任务在原授权内执行和验证。

## 同一主体真正控制准入

普通会话 `ControlService::submit`、控制/取消消息的路由受理、后台任务 `TaskAdmin::start`、条件唤醒、原任务接续及群主动插话，均在实际提交前通过同一持久主体队列领取短租约。`claim_filtered` 只允许指定入口领取全局最高优先级事件；最高事件属于另一入口时返回等待，不能跳过它领取低优先级工作。优先级为停止/取消、用户工作、恢复/事件、自主探索。

租约只覆盖同步受理，不覆盖模型、工具执行或平台发送。实际提交前持久化 EffectPending，取得明确受理结果后立即释放；多个窗口的长任务继续各自执行。普通聊天准入完成仅表示已交给控制器，不表示业务成功或已送达。控制报告另记生命周期，投递仍以 QQ 回执为准。范围只含可信会话身份与来源标识，不汇总不同窗口原话。

明确 Busy 可交回安全队列等待；Blocked/Unavailable保留Unknown与EffectPending，不误写明确拒绝或安全重放。群观察未获准入时撤销本次排队意图，不重新播放旧群消息。未知受理结果不重放。启动时先撤销丢失本地请求的旧排队准入，已进行的 EffectPending 按主体恢复规则变为 Unknown；不删除现场、不把旧消息重建成新请求。取消精确排队事件不会取消其他窗口。停止/取消仍沿原控制器执行，调度租约不等待长任务收尾。

## 固定自主预算与期限

`configure_subject_autonomy` 保持真实主人原话审查和每范围独立授权，新增 `expires_in_seconds`，默认24小时、最短30分钟、最长7天。总工具额度仍是 `max_goals × steps_per_goal`；每个候选目标消耗一个原有目标槽位，候选发现不授予新额度。相同原话证据不刷新预算、代数或期限。

`TaskAdmin::create_bounded` 在同一持久提交中创建任务及 `authorization_deadline_at_ms`，避免先创建再缩短的竞态。执行器取任务总期限和授权绝对期限的较早值，检查点不能延长该期限。等待、周期检查、恢复和重启均不暂停期限。到期或旧授权没有期限时，原政策保留并标记 Blocked，等待真实主人授权，不自动追加预算。

已有闭环继续在每30分钟检查原范围关注及真实任务结果；前一目标成功后才从已发现候选/既定兴趣选择下一目标。失败或未知结果阻断，不自动重建任务。执行任务可在原权限中检索、验证、保存经验和提出后续候选；公开经验仍由既有可信验证产物入口审核，不能把未经验证的脚本输出或群聊原文自动升为公共经验。
