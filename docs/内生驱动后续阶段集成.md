# 内生驱动后续阶段集成

本批接续实践策略 PR #276，将通用任务经验、长期推进、环境能力与统一经历按契约、插件和宿主组合分别实现。没有修改正在运行的 QQ 服务，也没有增加主代理或子代理步数预算。

## 四条实现线

| 实现 | 实际入口 | 当前边界 |
| --- | --- | --- |
| 通用任务策略 | `TaskStrategyPlugin`、`PairedTaskStrategyPolicy::with_training_cases`、`QqBotOptions.task_strategy_policy` | 训练来源执行前固定；真实纠正轨迹提出候选；两组独立配对任务验证后使用；不自动创建试验任务 |
| 长期目标推进 | 既有 `--learning-stop` 与研究、实践后台 | 24小时停滞暂停、已同步新外部证据恢复、目标公平排序；已取消目标不复活；共享预算与历史尝试数不清零 |
| 环境与能力模型 | `WorldModelPlugin`，任务策略装配时由 `TaskCognition` 连接 | 执行前预测，固定工具字段独立评价；按身份、环境和验收条件统计，未知结果不算成功 |
| 统一经历与泛化评价 | `UnifiedMemoryPlugin`、既有记忆连续性读取器 | 显式定向跨通道授权、可撤销、保留来源；固定语料与版本的召回保留集评价，不把私聊自动带入群 |

细节见[通用任务策略与独立评价](./通用任务策略与独立评价.md)、[长期目标持续推进](./长期目标持续推进.md)、[环境与能力模型](./环境与能力模型.md)、[统一经历与保留集评价](./统一经历与保留集评价.md)。

## 宿主装配

普通 QQ `--memory` 启动时打开独立统一记忆账本，默认没有跨通道授权。原有 QQ 同人识别与隐私热配置继续适用，统一记忆只追加明确授权的跨通道来源。每次读取重新核对授权；模型不能创建身份绑定。

嵌入 Rust 宿主可实现公开 `CognitiveServices` 并放入 `QqBotOptions.cognitive_services`。`memory_ready` 收到 `Arc<dyn UnifiedMemoryAdmin>`，可依据已经认证的同一主体与来源授权登记定向绑定，或固定保留集。`world_ready` 收到 `Arc<dyn WorldModelAdmin>`，可记录宿主真实观测及执行前预测。管理操作失败会使启动失败；不能把这两个管理句柄直接交给模型。

通用任务策略仍要求宿主提供 `TaskStrategyPolicy`：动态运行指纹、固定验收工具与合同，以及互不污染的训练与留出目录。`TaskCognition` 将其与独立世界账本组合，不修改原任务身份、授权、取消、步数与期限。能力统计只作经验数据附加，不能单凭成功率跳过独立检查。

## 恢复与部署

所有新增持久化能力保留损坏状态并拒绝继续写入；提交无法确认时关闭句柄，重新打开核对。暂停、候选、对照、预测与记忆授权各自的恢复规则见相应文档。跨账本没有全局事务，组合层允许依据已保存证据补结算，不允许补造执行前预测、重放工具或增加历史预算。

本批源代码与运行版分离。没有自动部署、重启 QQ、发测试消息或调用收费模型。测试使用临时状态和固定工具回执；其通过只证明对应协议和恢复行为，不证明真实模型的长期效果、任意跨领域泛化或正式 QQ 体验。

## 验证记录

由独立验证代理在 Rust 1.89 下验证，使用离线依赖及临时状态。为避免构建缓存占满磁盘，关闭构建调试信息和增量编译；没有删除运行数据。

- 八个能力 crate（task、cognition、memory、pursuit 的 API 与 plugin）全测试：172 项通过，0 失败、0 忽略
- 应用层库测试：138 项通过，其中8项任务与世界模型组合回归覆盖真实字段投影、环境变化、恢复不补预测、非任务预测隔离、容量、冲突记录、多字段检查与控制/试验提示隔离
- 上述九个 crate 的 `--all-targets` 严格 Clippy（`-D warnings`）通过
- 本批变更 Rust 文件的 `rustfmt --check --config skip_children=true` 通过，没有声称全工作区格式检查
- `cognition_state` 示例独立进程连跑3次，执行中恢复为阻塞且再重启不变；记忆 `summary` 与 `recovery` 示例各连跑2次，第二次不再请求模型、撤销和修订保持；共7次示例进程通过

复现核心命令：

```sh
cargo test --offline -p eve-task-api -p eve-task-plugin -p eve-cognition-api -p eve-cognition-plugin -p eve-memory-api -p eve-memory-plugin -p eve-pursuit-api -p eve-pursuit-plugin
cargo test --offline -p eve-app --lib
cargo clippy --offline -p eve-task-api -p eve-task-plugin -p eve-cognition-api -p eve-cognition-plugin -p eve-memory-api -p eve-memory-plugin -p eve-pursuit-api -p eve-pursuit-plugin -p eve-app --all-targets -- -D warnings
```

初次默认调试构建因磁盘容量中止，属于构建资源失败；清理可重建缓存后用 `CARGO_PROFILE_DEV_DEBUG=0`、`CARGO_PROFILE_TEST_DEBUG=0`、`CARGO_INCREMENTAL=0` 重跑通过。独立代码审查还修复了误结算其他模块预测、恢复范围冲突、多字段预测碰撞、伪造召回评价、撤销空间不足、停滞暂停竞态和双臂提示变量污染。没有通过修改正式状态或放宽验收来消除失败。

## 部署前追加验收

部署前检查远端 CI，修复了新版 Stable Clippy 的 `manual_checked_ops`、中间 PR 的 QQ 参数接线位置，以及全功能窗口在兴趣观察持久化前关闭的测试时序。学习停止测试现在按 `pursuit-stop:v1` 区分停止事件与进展事件，没有改变原预算、次数和停止效果断言。

Release 二进制另外通过20项真实进程用例：全功能启动与加密状态续接1项、长期学习1项、记忆权限4项、后台任务8项、中断恢复6项。正式主模型 `deepseek-v4.1-flash` 在隔离桥接中实际调用 `echo` 并成功完成回复，没有向正式 QQ 发送测试消息。现有运行数据的副本以全部原参数启动成功、正常退出，未请求外部模型。

新增仅用于隔离验收的 `examples/task_strategy.rs` 和 `task_strategy_process_test.py`：本地模型协议替身通过完整 QQ/任务执行器实际调用文件读取、编辑工具，执行1个纠正训练任务与2对留出任务，共15次工具调用、20次本地模型请求。宿主重新计算候选为 Active、paired_successes=2，5条世界预测均经真实回执通过；再启动后账本、开发操作记录及文件内容不变。该宿主要求本地端口、合成凭据、固定测试桥和临时工作区标记，拒绝生产配置。

普通正式 `eve-qqbot` 仍通过既有 `--learning-stop` 开启长期推进，随 `--memory` 打开统一记忆基础。跨通道授权默认空。通用策略与任务世界预测仍需可信宿主提供目录，本次不为生产用户编造训练/留出或验收标准；隔离宿主的通过不等于这些能力已在普通 CLI 中启用。
