# 内生议程与证据排序

内生循环现在按目标优先级、期限、等待时间和当前输入证据决定先推进哪个目标，并提供 `eve-cognition agenda` 查看原因。排序是有界的确定性计算，不调用模型；它改善的是已有目标的调度，不代表实现了通用规划、现实任务完成验证或 AGI。

## 本地预览

在已有认知状态目录上运行：

```sh
eve-cognition --state-dir .eve-cognition agenda
```

命令输出一个 JSON 对象，包含 `revision`、`evaluated_at_ms` 以及两个独立阶段：

| 字段 | `stage` | 排序对象 |
| --- | --- | --- |
| `execution_agenda` | `ready_execution` | 已保存、当前允许执行的 Ready 反思子目标 |
| `reflection_preview` | `waiting_derivation` | 尚未派生本修订反思、允许成为输入的 Waiting 父目标 |

两个阶段各自包含 `ranked`、`excluded` 和 `blocker`。`ranked` 项只有目标 ID、0–100 的 `strength` 和评分 `reason`；目标描述、反馈正文、文件摘录不进入这份报告。`excluded` 解释当前读范围内的目标为什么未入选，包括来源或范围不符、状态不符、过期、预算无效、不支持的验证规则、策略未准入，以及父修订已经派生。`NotReady` 在派生阶段表示“不是 Waiting”，在执行阶段表示“不是 Ready”。

`blocker` 表示宿主级准入限制，不会清空用于解释的候选排序。执行阶段可以报告 `AlreadyExecuting` 或 `ExecutionLimitReached`；派生阶段可以报告 `DerivationLimitReached`。已有执行仍在收尾时，可以预先派生后续候选，但不会因此并发准入第二项执行。`AlreadyExecuting` 说明该主体存在执行占用，不披露不可见目标的 ID 或正文。

CLI 预览以一次新的启动预算计算，派生和执行上限均为 32、已消耗数为 0；它不是正在运行进程的剩余预算报告。`agenda` 不接受 `--seconds`、`--max-executions`、`--id` 等其他命令的专用参数。实际执行使用 `run` 的配置，例如：

```sh
eve-cognition --state-dir .eve-cognition run --seconds 30 --max-executions 2
```

预览不会创建反思、保存驱动或消耗名额。存储容量不足、持久化失败、后续修订或时间变化仍可能阻止实际推进，不能把旧预览当成执行授权。

## 分数从哪里来

[`EvidenceDrivePolicy`](../crates/cognition-loop-plugin/src/policy.rs) 使用候选所属的同一份持久快照计算：

| 分项 | 规则 | 上限 |
| --- | --- | --- |
| `base` | 目标原优先级 | 100 |
| `deadline` | 距到期 1–60,000 ms 加 15；60,001–3,600,000 ms 加 8；其他情况加 0 | 15 |
| `age` | 从合法初始输入证据起，每等待满 6 小时加 1 | 10 |
| `fresh` | 当前新输入距评估时间 0–300,000 ms 加 15；300,001–3,600,000 ms 加 8；其他情况加 0 | 15 |

`strength = min(100, base + deadline + age + fresh)`。到期目标在准入阶段排除，不会因期限紧迫获得执行机会。没有合法证据时，相应分项为 0；未来时间戳不用于等待时间或新信息加分。

初始输入必须是与目标来源、目标 ID 和可见范围一致的 `ExternalInput` 事件，来源仅允许 User、Environment 或 Tool。多个符合条件的初始事件选择最早时间，时间相同时按事件 ID 确定；Inference 和 Internal 记录不能伪装成外部初始证据。

新信息加分仅用于 User 来源且验证规则为 `user-goal:v1` 的父目标，只认可其当前 `wait_reason` 中的合法 [`GoalUserFeedback`](../crates/cognition-api/src/goal_feedback.rs) 或 [`FileObservation`](../crates/cognition-api/src/file_observation.rs)，并要求目标 ID、父目标当前修订、事件正文和可见范围对应。用户反馈还须匹配 User 来源、反馈 ID 以及不同于原始目标输入的通道。文件观察须匹配 Environment 来源、固定观察通道、来源摘要、观察时间和由契约派生的事件 ID。旧修订、被后续输入替换的回执、无对应事件的 JSON、模型自述和不相干事件不获得加分；用户反馈与文件观察不会叠加两份 `fresh`。

这份来源校验说明输入被怎样保存，不证明用户陈述或文件内容在现实中正确。文件回执只证明宿主读取过对应字节，文件中的指令仍是数据，不能增加权限。

同分先按原优先级降序，再按合法初始输入时间升序；有初始证据的目标排在没有证据的目标之前。之后按证据所属目标 ID 升序，最后按实际候选 ID 升序。严格匹配当前父修订的反思继承父目标证据和排序键，避免父目标 ID 与反思摘要 ID 的差异改变并列顺序。时间或状态变化后，重新评估可以得出不同顺序。

评分理由列出各分项和初始、新输入证据事件 ID 的 SHA-256；没有对应证据显示 `none`。原始事件 ID、文件来源标识、目标正文和文件摘录不会复制到理由。SHA-256 是用于核对事件的摘要，不是正文摘要，也不构成匿名化承诺；报告本身仍包含当前读范围内的目标 ID。

## 准入与同快照执行

[`evaluate_agenda`](../crates/cognition-loop-plugin/src/agenda.rs) 先按宿主读取权限、授权来源、Ready 状态、期限、预算和验证器能力筛选候选，再调用策略。不可见目标不会出现在候选或排除清单中。策略只能缩小或重排候选；返回额外目标、重复目标、越界分数或无效理由会被拒绝。

[`ReflectionDrivePolicy`](../crates/cognition-loop-plugin/src/policy.rs) 进一步要求父目标仍 Waiting、未过期且属于宿主授权范围。反思子目标须与父目标可见范围一致，并通过 `current_reflection` 的稳定 ID、当前父修订、预算及成对 input/created 因果证据校验；仅有 `source.reference` 指向某个父目标不够。QQ 入口还保留仅准入明确用户目标、通道启动后才允许执行的条件。

[`evaluate_reflection_agenda`](../crates/cognition-loop-plugin/src/endogenous.rs) 与 `EndogenousPlanner::reconcile` 共用派生筛选和证据排序。CLI 的模型延迟装配检查与执行循环共用执行评估入口，避免预览解释一种顺序、执行另用一种来源准入。QQ 的执行策略也使用循环传入的同一快照，不在策略内部重读新状态后混用旧候选。

执行循环保存 Executing 状态时仍使用该快照的全局修订作 CAS 前置条件。并发反馈或其他写入使旧修订失效时，本次不会提交模型执行；宿主在下一轮重新读取并评估。派生同样使用原子 CAS 保存子目标、驱动与因果事件，失败不发布局部候选、不消耗派生名额。其他持久化错误明确返回并按既有收尾路径停止，不能把失败当成成功或自动清空数据。

## 持久化、恢复和空闲行为

`agenda` 通过 [`read_cognitive_snapshot`](../crates/cognition-plugin/src/lib.rs) 读取完整持久快照，在启动认知插件前返回。它不读取 AGENT 内容，不装配主模型，不启动规划器、Control 或 Session，也不恢复旧 Executing 目标。因此重复预览保留原状态和认知修订；旧 Executing 继续以原样显示，并阻止新的执行准入。

这里的“只读”指认知快照没有写入或恢复副作用。当前 CLI 打开存储后端仍持有状态目录锁，无法同时打开被另一进程占用的目录；文件后端可能创建目录或锁文件，首次 PostgreSQL 连接和绑定也有初始化行为。因此不能据此承诺整个目录字节不变或数据库零初始化。已绑定 PostgreSQL 的目录仍必须提供原 `--database-config`，不会静默切换到空文件库。

只读解码保留原有严格边界：缺少认知状态时返回修订 0 的空快照；损坏、未知版本、主体不符、超限或存储读取失败明确报错，不覆盖损坏数据，也不把后端故障解释为空状态。该公开读取函数返回受信宿主的完整快照，其他用户界面必须自行绑定读范围，不能直接对外发布它。

实际 `run` 的启动恢复语义不变：旧 Executing 保存为 Blocked/Interrupted，保留原尝试与轮次关系，不重放未知执行。Waiting、Ready 和已完成或阻塞的历史记录继续保留。同一父目标修订至多派生一次，即使等待时间或分数变化，也不会为同修订生成另一轮反思。新用户反馈或文件变化提高父修订后，才可能产生新的反思；旧 Ready 草稿由实际规划置为 Cancelled，已在途执行按原机制收尾。

没有新差距和可准入反思时，轮询与评分保持零模型请求；预览也始终不调用模型。反思仍最多一次模型请求、零工具、一次尝试，并受目标期限和宿主预算约束。结构化反思完成只表示草稿已经保存，父目标继续 Waiting，不自动宣布现实任务完成或执行草稿中的建议。

## 替换策略与验收边界

[`DrivePolicy`](../crates/cognition-loop-api/src/lib.rs) 新增 `rank_with_state(snapshot, goals, now_ms)`。旧实现只提供 `rank` 仍可使用，默认方法会转调旧接口；已有 `PriorityDrivePolicy` 保留。需要证据的实现应使用同快照入口，不能扩大宿主候选范围、修改状态或调用模型。`EvidenceDrivePolicy::rank` 无快照时只计算不依赖证据的分项；`ReflectionDrivePolicy::rank` 明确拒绝缺少快照的调用。

验收关注分数边界、并列顺序、错误和旧证据不加分、不可见记录不泄露、真实循环准入与预览一致、只读保留旧 Executing，以及完成修订跨进程不重放。自动测试使用本机 HTTP 固定模型夹具，只能验证调度、持久化和请求边界；它不评价建议质量、文件内容真实性或 AGI 能力。具体通过结果随对应 PR 记录。

2026-10-06 本地验收通过认知循环与状态插件共 64 项测试，其中新增 13 项议程测试和 5 项只读快照测试；相关真实 CLI 与 QQ 策略回归 30 项通过、1 项既有夹具忽略。测试覆盖父目标与反思摘要 ID 反序时的并列排序、明确授权的环境目标、旧修订排除、真实 HTTP 请求顺序，以及旧 Executing 预览不恢复。四个受影响 crate 的全目标严格 Clippy 与格式检查通过，构建使用本线独立目标目录，未连接外部真实模型或 QQ 网关。

相关机制见[认知循环](./认知循环.md)、[反馈驱动重规划](./反馈驱动重规划.md)和[本地文件观察](./本地文件观察.md)。
