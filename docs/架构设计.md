# EVE.AIC 第一版架构设计

## 1. 总体分层

所有功能都先定义抽象契约，再提供独立实现。插件只依赖定义层，Runtime 负责选择和装配实现层。

```text
定义层：Plugin API、Trait、数据类型、错误和协议
                         ↓
实现层：Kernel、Event Bus、Service、State、Task、权限和日志实现
                         ↓
组合层：Runtime Host 选择实现并注册插件
```

分层规则：

- 定义层不依赖具体实现。
- 实现层实现定义层的 Trait，可以有多个实现。
- 组合层负责配置、替换和装配实现。
- 插件不能绕过 Context 访问实现层内部结构。

## 2. Plugin API

`plugin-api` 只定义插件可以看到的稳定契约：

- Plugin
- PluginManifest
- PluginContext
- PluginDependency
- ServiceId
- EventId
- StateHandle
- TaskId / TaskSpec / TaskSignal
- Permission
- PluginError
- RuntimeInspector / PluginStatus / PluginStopError（宿主只读诊断）
- RuntimeLifecycle / LifecycleRequest / LifecycleOperation（宿主生命周期控制）

插件不应依赖 `kernel` 的内部结构。`PluginManifest` 在注册前统一校验 SemVer 版本、依赖范围、自依赖和重复依赖；启动依赖前再次检查已注册版本。

## 3. 实现层与 Kernel

`kernel` 负责：

- Runtime 生命周期
- Plugin Registry
- 依赖图和启动顺序
- 插件状态机
- Context 创建
- Service Registry
- Event Bus
- State Store
- Task Manager
- Permission Checker
- 资源清理
- 错误和诊断

这些能力都应通过独立接口定义，再由 Kernel 提供默认实现。当前 `EventBus`、`ServiceRegistry`、`StateStore`、`PermissionChecker`、`TaskManager`、`Logger` 已在 `plugin-api` 定义，默认实现位于 `kernel::backends`，通过 `KernelServices` 装配。任务使用 Tokio 默认实现；日志提供输出流和内存两种实现，不依赖进程全局单例。状态提供默认内存后端与可选文件后端，插件接口保持不变。

任务扩展进一步分离行为与触发策略：插件实现 `Task` 定义带参数的新类型，实现 `TaskScheduler` 定义新的等待和调度规则；默认执行器通过统一契约管理这些对象，无需按业务类型增加分支。前后台模式与上述扩展组合，Scope、取消、错误报告和资源回收仍由内核统一负责。任务查询只保存 `TaskTypeId` 和 `TaskScheduleInfo` 等描述，不保留执行闭包。

## 4. Plugin 生命周期

```text
Registered
    ↓
WaitingDependencies
    ↓
Starting
    ↓
Active
    ↓
Stopping
    ↓
Stopped
```

启动失败进入 `Failed`。插件是否启用是配置，不单独作为生命周期状态。

## 5. Context 边界

插件只能通过 `PluginContext` 使用 Runtime 能力：

```text
PluginContext
├── emit / on：事件发布与订阅
├── provide_service / service：服务注册与获取
├── state_get / state_set：命名空间状态
├── check_permission：权限声明检查
├── spawn_task / run_foreground / tasks：任务创建、前台等待与查询
├── log：携带插件身份与时间的结构化日志
└── cleanup：异步资源清理
```

禁止插件获取 Runtime 内部可变结构。

宿主通过 `PluginRegistry` 注册和卸载插件，通过 `RuntimeInspector` 查询插件清单和任务，契约位于定义层。卸载与生命周期操作共用串行准入边界，只移除已完成收尾的注册表条目，不删除状态字节。查询不等待生命周期锁，可观察启动中和停止中的状态；清单是逐项快照。停止失败按插件与阶段汇总为 `PluginError::Shutdown`，退出检查失败不能返回停止成功。详见[运行时诊断](./运行时诊断.md)。

宿主通过 `RuntimeLifecycle` 提交启动或停止操作、等待终态、查询和确认报告。准入后由独立执行任务持有操作，取消等待仍继续收尾；意外中断保留错误，不伪装成停止成功。该控制接口不注入插件 Context，详见[生命周期操作](./生命周期操作.md)。

插件注册与生命周期操作共用串行准入边界。启动或停止操作执行期间，`register` 会返回错误；操作完成后才能注册新插件，避免 `start_all` 或 `stop_all` 的插件快照遗漏并发注册。

以上为当前接口。插件只依赖 `plugin-api`，`example-plugins` 提供可执行的示例，`runtime` 负责装配。具体语义见[插件开发](./插件开发.md)和[日志接入](./日志接入.md)。

## 6. 第一版插件形式

第一版采用：

```text
Rust
单进程
静态编译
可信插件
Box<dyn Plugin>
```

暂不加载任意 Rust 动态库。未来的不可信或外部插件使用 WASM 或独立进程协议。
