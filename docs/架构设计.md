# EVE.AIC 第一版架构设计

## 1. 总体分层

所有功能都先定义抽象契约，再提供独立实现。插件只依赖定义层，Runtime 负责选择和装配实现层。

```text
定义层：Plugin API、Trait、数据类型、错误和协议
                         ↓
实现层：Kernel、Event Bus、Service、State、Task、权限和日志实现
                         ↓
组合层：Runtime Host 选择实现并注册插件
```

分层规则：

- 定义层不依赖具体实现。
- 实现层实现定义层的 Trait，可以有多个实现。
- 组合层负责配置、替换和装配实现。
- 插件不能绕过 Context 访问实现层内部结构。

## 2. Plugin API

`plugin-api` 只定义插件可以看到的稳定契约：

- Plugin
- PluginManifest
- PluginContext
- PluginDependency
- ServiceId
- EventId
- StateHandle
- TaskHandle
- Permission
- PluginError

插件不应依赖 `kernel` 的内部结构。

## 3. 实现层与 Kernel

`kernel` 负责：

- Runtime 生命周期
- Plugin Registry
- 依赖图和启动顺序
- 插件状态机
- Context 创建
- Service Registry
- Event Bus
- State Store
- Task Manager
- Permission Checker
- 资源清理
- 错误和诊断

这些能力都应通过独立接口定义，再由 Kernel 提供默认实现。Event Bus、State Store、Task Manager、Permission Checker 和 Logger 不应把具体实现写死在插件 API 中。

## 4. Plugin 生命周期

```text
Registered
    ↓
WaitingDependencies
    ↓
Starting
    ↓
Active
    ↓
Stopping
    ↓
Stopped
```

启动失败进入 `Failed`。插件是否启用是配置，不单独作为生命周期状态。

## 5. Context 边界

插件只能通过 `PluginContext` 使用 Runtime 能力：

```text
PluginContext
├── RuntimeHandle
├── EventBusHandle
├── ServiceRegistryHandle
├── StateHandle
├── TaskManagerHandle
├── Logger
└── PermissionSet
```

禁止插件获取 Runtime 内部可变结构。

## 6. 第一版插件形式

第一版采用：

```text
Rust
单进程
静态编译
可信插件
Box<dyn Plugin>
```

暂不加载任意 Rust 动态库。未来的不可信或外部插件使用 WASM 或独立进程协议。
