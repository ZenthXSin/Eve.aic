# 会话历史与恢复

会话是可替换插件能力。`eve-session-api` 定义 `SessionService`、用户/会话键、轮次引用、快照和错误；`eve-session-plugin` 是内置 `eve.session` 实现，通过 `StateStore` 持久化。`SessionLlmHost` 只组合该服务与内置 `LlmHost`；Kernel 不依赖会话或模型协议。

## 装配与消息顺序

宿主先启动 Context/Tool 插件和 Session 插件，再用 `SessionBinding` 指定公开服务 ID 和预期所有者。默认绑定为 `eve.session.history` / `eve.session`。服务缺失、类型错误、所有者不符或未 Active 均拒绝模型请求。消费者插件应在 Manifest 中声明提供者依赖，仅依赖定义层。当前示例由宿主显式启动，不使用会话业务控制 Kernel。

通道或组合层提供可信的 `SessionKey { session_id, user_id }`。ID 必须非空、无边缘空白/控制字符且至多 256 字节。同一 `session_id` 绑定一个用户，其他用户读取或请求返回 `OwnerMismatch`；这是逻辑隔离，不是认证或不可信插件沙箱。

请求保持既有顺序：固定系统规则、输出格式、排序后的工具定义，然后 Context 修订/档案/记忆、已完成历史、当前 User。会话模式要求 ContextAssembler 的 `history` 为空，防止历史重复；会话插件是该模式的唯一历史来源。排序稳定不保证缓存必然命中，动态档案或修订仍会改变相应前缀。

`TurnOutput.transcript` 只包含本轮 User、可选完整 Assistant 工具批次/Tool 结果批次、最终 Assistant。完整批次保留参数、调用 ID、模型顺序以及成功值/结构化失败。不保存系统提示、档案、记忆、旧历史。每轮必须完整配对，拒绝缺少结果、重复调用 ID、顺序错配和混入 System。首版仍至多一个工具批次；工具失败、超时或自行确认取消若最终收到正常回复，可作为 Completed 的失败结果保存。

## 状态与提交

| 操作或状态 | 语义 |
| --- | --- |
| `begin` / Pending | 输入先提交到存储，成功后才请求 Context/Provider；同会话一个在途轮次，否则 Busy |
| `complete` / Completed | 完整本轮消息持久化成功后才报告会话完成 |
| `fail` / Failed | 保存失败分类及已开始工具数；失败输入不加入成功历史 |
| Interrupted | 插件重建时把原 Pending 标为中断，保留原输入和旧 Completed；不请求模型或重放工具 |
| `history()` | 仅按轮次顺序拼接 Completed 消息 |

每个会话轮次 ID 从 1 递增。每次 begin 和终态提交各加一次 revision；Pending 恢复为 Interrupted 也加一次。`TurnLease` 标识已开始轮次，不是持有运行期锁的能力；提交必须匹配用户、最后轮次 ID 和 Pending。重复完成、旧轮次或恢复后的引用返回 StaleTurn。停止后旧服务返回 Unavailable，启动重建后必须重新发现服务。

内置插件把所有会话作为 `format_version: 1` 的 JSON 文档保存在插件命名空间 `eve.session` 的 `sessions.v1` 字节键。文档按会话 ID 排序；候选文档成功提交后才替换内存。默认全量复制及同步整份写入适合最小验证，尚未实现分页、裁剪、压缩、数据库后端或容量配额。`FileStateStore` 继续独占单宿主目录并原子替换外层 state.json；跨会话写入在短提交阶段串行，模型请求可以并行。

## 失败、取消与诊断

- begin 提交失败：不新增内存会话、不调用模型，原字节保持。
- 最终保存失败：`SessionRunError::Commit` 保留已生成的 `Box<TurnOutput>` 和保存错误；原 Pending 保留。不能当作成功持久化，不能自动重新执行模型或工具。调用方可查询快照确认轮次，再明确重试本地 `complete`；状态丢失时由人工处理副作用。
- 执行失败且失败记录写入失败：`FailureRecord` 同时保留原 `TurnFailure` 与保存错误，Pending 保留；析构不得以 Cancelled 覆盖它。
- 丢弃正在执行的会话 Future：丢弃 Provider Future、取消/abort 本地工具任务；守卫尝试提交 Failed/Cancelled。`started_tools: None` 表示数量未知，不能推断没有副作用。取消记录失败保持 Pending，投递 `session.cancel_commit` Error 日志；字段仅含 turn_id，不包含用户、会话 ID、输入或底层错误。宿主通过 `with_logger` 复用日志后端；投递也失败时向 stderr 输出固定说明。

运行期使用共享读准入，生命周期/注册操作使用独占写准入。不同会话可并行，同会话由插件返回 Busy。同一 LlmHost 的工具并发上限与串行作用域跨会话共享；取消排队项只移除其队列位置，不能越过在途项。多个独立 Host 不共享该调度器，插件若跨宿主共享资源须自行协调。启动、停止等操作等待整轮及最终写入完成；已排队写操作阻止后续读准入。工具任务持有同一准入引用直到 Future 真正析构，外层取消不会提前允许停止。Provider、Context、Tool 和同步存储回调不得在本轮内部等待同一 Kernel 的生命周期操作或再嵌套准入，避免重入等待。

本地取消或 Interrupted 都不证明远端请求停止、不会计费或工具副作用被撤销；不能提供“恰好执行一次”。持有 Pending 后的显式新请求必须先处理该轮状态，不能绕过 Busy。

## 严格恢复

坏 JSON、任意层重复键、未知格式版本、未知 DTO 字段、会话键/轮次/修订错误及不完整工具配对使插件启动失败；错误不带原始内容，不清空或覆盖数据。恢复 Pending 的写入也须成功后才发布服务。写入失败时原文件仍保留 Pending，Kernel 实例进入 Failed；解除故障后显式 unregister、重新创建并注册插件，不能自动 restart 失败实例。内置实现不做跨版本迁移。

## 实际验收

```bash
cargo test -p eve-session-plugin --locked
cargo test -p eve-runtime --test session_host --test session_http --locked
cargo run -p eve-runtime --example session_recovery --locked -- <独立目录>
cargo run -p eve-runtime --example session_recovery --locked -- <同一目录>
cargo run -p eve-runtime --example session_recovery --locked -- <同一目录> --leave-pending
cargo run -p eve-runtime --example session_recovery --locked -- <同一目录>
```

每次 cargo run 都是独立进程。示例使用确定性本地 Provider，输出单行 JSON：

| 运行 | turn_id | history_messages | interrupted | tool_executions | provider_requests |
| --- | --- | --- | --- | --- | --- |
| 首次完成 | 1 | 0 | 0 | 1 | 2 |
| 重启继续 | 2 | 4 | 0 | 0 | 1 |
| 留下 Pending | 3 | 6 | 0 | 0 | 0 |
| 重启后新请求 | 4 | 6 | 1 | 0 | 1 |

最后磁盘会话 revision 为 8；原第三轮输入仍保留为 Interrupted，却未送入模型。示例在 Provider 入口逐消息核对恢复历史，检查第一轮调用 ID 与本地回执，拒绝额外模型请求或旧工具执行；CI 在 Ubuntu/Windows 还解析实际 state.json 中的内层文档。

Runtime HTTP 测试重新打开 FileStateStore、重建全部插件后发送 Responses 请求，验证旧工具参数、回执和失败结果配对，assistant 文本的 final_answer phase，以及系统/工具前缀稳定；不调用外部模型。会话功能尚未重新进行真实 API 多轮验收。流式的生成/持久化分离、取消及跨进程恢复已有本地验收，见[流式输出](./streaming.md)。真实流式 API、reasoning 续传、记忆检索、用户建模与消息打断继续后置。

显式任务控制通过 SessionControlRunner 复用此宿主，详见[任务控制](./任务控制.md)。关闭信号现在也覆盖生命周期准入和 Context 装配；begin 前取消返回 NotStarted，不创建 Pending。受管取消等待工具析构与 Failed 提交，报告完整生成输出/工具结果；保存失败保留 Pending 并阻止替代轮次。保存完成后的取消仍报告 Completed/Delivery，不改写成功历史。
