# 会话历史与恢复

会话是可替换插件能力。`eve-session-api` 定义 `SessionService`、用户/会话键、轮次引用、快照和错误；`eve-session-plugin` 是内置 `eve.session` 实现，通过 `StateStore` 持久化。`SessionLlmHost` 只组合该服务与内置 `LlmHost`；Kernel 不依赖会话或模型协议。

## 装配与消息顺序

宿主先启动 Context/Tool 插件和 Session 插件，再用 `SessionBinding` 指定公开服务 ID 和预期所有者。默认绑定为 `eve.session.history` / `eve.session`。服务缺失、类型错误、所有者不符或未 Active 均拒绝模型请求。消费者插件应在 Manifest 中声明提供者依赖，仅依赖定义层。当前示例由宿主显式启动，不使用会话业务控制 Kernel。

通道或组合层提供可信的 `SessionKey { session_id, user_id }`。ID 必须非空、无边缘空白/控制字符且至多 256 字节。同一 `session_id` 绑定一个用户，其他用户读取或请求返回 `OwnerMismatch`；这是逻辑隔离，不是认证或不可信插件沙箱。

请求保持既有顺序：固定系统规则、输出格式、排序后的工具定义，然后 Context 修订/档案/记忆、已完成历史、当前 User。会话模式要求 ContextAssembler 的 `history` 为空，防止历史重复；会话插件是该模式的唯一历史来源。排序稳定不保证缓存必然命中，动态档案或修订仍会改变相应前缀。

`TurnOutput.transcript` 只包含本轮 User、可选完整 Assistant 工具批次/Tool 结果批次、最终 Assistant。完整批次保留参数、调用 ID、模型顺序以及成功值/结构化失败。不保存系统提示、档案、记忆、旧历史。每轮必须完整配对，拒绝缺少结果、重复调用 ID、顺序错配和混入 System。首版仍至多一个工具批次；工具失败、超时或自行确认取消若最终收到正常回复，可作为 Completed 的失败结果保存。

## 状态与提交

| 操作或状态 | 语义 |
| --- | --- |
| `begin` / Pending | 输入先提交到存储，成功后才请求 Context/Provider；同会话一个在途轮次，否则 Busy |
| `complete` / Completed | 完整本轮消息持久化成功后才报告会话完成 |
| `fail` / Failed | 保存失败分类及已开始工具数；失败输入不加入成功历史 |
| Interrupted | 插件重建时把原 Pending 标为中断，保留原输入和旧 Completed；不请求模型或重放工具 |
| `history()` | 仅按轮次顺序拼接 Completed 消息 |

每个会话轮次 ID 从 1 递增。每次 begin 和终态提交各加一次 revision；Pending 恢复为 Interrupted 也加一次。`TurnLease` 标识已开始轮次，不是持有运行期锁的能力；提交必须匹配用户、最后轮次 ID 和 Pending。重复完成、旧轮次或恢复后的引用返回 StaleTurn。停止后旧服务返回 Unavailable，启动重建后必须重新发现服务。

未注入冷存储的兼容模式把所有会话作为 `format_version: 1` 的 JSON 文档保存在插件命名空间 `eve.session` 的 `sessions.v1` 字节键。文档按会话 ID 排序；候选文档成功提交后才替换内存。写入仍全量复制并同步保存；新增只读分页不改变这个路径，StateStore 可由文件或 PostgreSQL 后端实现，后者的连接和恢复按独立存储契约配置。`FileStateStore` 继续独占单宿主目录并原子替换外层 state.json；跨会话写入在短提交阶段串行，模型请求可以并行。

## 失败、取消与诊断

- begin 提交返回错误：不调用模型，不使用未确认的内存候选。后端可能已经提交 Pending，因此立即关闭当前全部会话读写句柄，不能据旧缓存复用轮次 ID 或覆盖其他会话。
- 最终保存返回错误：`SessionRunError::Commit` 保留已生成的 `Box<TurnOutput>` 和错误；实际持久结果可能仍是 Pending，也可能已提交 Completed 但确认丢失。当前句柄关闭，不能自动重新执行模型/工具，也不能用旧缓存直接补交 complete。须显式重新打开并核对；原 Pending 只恢复为 Interrupted，已提交 Completed 保留，旧轮次引用不能再次完成。
- 执行失败且失败记录写入返回错误：`FailureRecord` 同时保留原 `TurnFailure` 与保存错误，当前会话服务关闭；重新打开后按实际持久结果核对，析构不得以 Cancelled 覆盖它。
- 丢弃正在执行的会话 Future：丢弃 Provider Future、取消/abort 本地工具任务；守卫尝试提交 Failed/Cancelled。`started_tools: None` 表示数量未知，不能推断没有副作用。取消记录无法确认时关闭旧会话句柄并保留持久现场，投递 `session.cancel_commit` Error 日志；字段仅含 turn_id，不包含用户、会话 ID、输入或底层错误。宿主通过 `with_logger` 复用日志后端；投递也失败时向 stderr 输出固定说明。

运行期使用共享读准入，生命周期/注册操作使用独占写准入。不同会话可并行，同会话由插件返回 Busy。同一 LlmHost 的工具并发上限与串行作用域跨会话共享；取消排队项只移除其队列位置，不能越过在途项。多个独立 Host 不共享该调度器，插件若跨宿主共享资源须自行协调。启动、停止等操作等待整轮及最终写入完成；已排队写操作阻止后续读准入。工具任务持有同一准入引用直到 Future 真正析构，外层取消不会提前允许停止。Provider、Context、Tool 和同步存储回调不得在本轮内部等待同一 Kernel 的生命周期操作或再嵌套准入，避免重入等待。

本地取消或 Interrupted 都不证明远端请求停止、不会计费或工具副作用被撤销；不能提供“恰好执行一次”。持有 Pending 后的显式新请求必须先处理该轮状态，不能绕过 Busy。

## 严格恢复

坏 JSON、任意层重复键、未知格式版本、未知 DTO 字段、会话键/轮次/修订错误及不完整工具配对使插件启动失败；错误不带原始内容，不清空或覆盖数据。恢复 Pending 的写入也须成功后才发布服务。写入失败时原文件仍保留 Pending，Kernel 实例进入 Failed；解除故障后显式 unregister、重新创建并注册插件，不能自动 restart 失败实例。内置实现不做跨版本迁移。

## 实际验收

```bash
cargo test -p eve-session-plugin --locked
cargo test -p eve-runtime --test session_host --test session_http --locked
cargo run -p eve-runtime --example session_recovery --locked -- <独立目录>
cargo run -p eve-runtime --example session_recovery --locked -- <同一目录>
cargo run -p eve-runtime --example session_recovery --locked -- <同一目录> --leave-pending
cargo run -p eve-runtime --example session_recovery --locked -- <同一目录>
```

每次 cargo run 都是独立进程。示例使用确定性本地 Provider，输出单行 JSON：

| 运行 | turn_id | history_messages | interrupted | tool_executions | provider_requests |
| --- | --- | --- | --- | --- | --- |
| 首次完成 | 1 | 0 | 0 | 1 | 2 |
| 重启继续 | 2 | 4 | 0 | 0 | 1 |
| 留下 Pending | 3 | 6 | 0 | 0 | 0 |
| 重启后新请求 | 4 | 6 | 1 | 0 | 1 |

最后磁盘会话 revision 为 8；原第三轮输入仍保留为 Interrupted，却未送入模型。示例在 Provider 入口逐消息核对恢复历史，检查第一轮调用 ID 与本地回执，拒绝额外模型请求或旧工具执行；CI 在 Ubuntu/Windows 还解析实际 state.json 中的内层文档。

Runtime HTTP 测试重新打开 FileStateStore、重建全部插件后发送 Responses 请求，验证旧工具参数、回执和失败结果配对，assistant 文本的 final_answer phase，以及系统/工具前缀稳定；不调用外部模型。会话功能尚未重新进行真实 API 多轮验收。流式的生成/持久化分离、取消及跨进程恢复已有本地验收，见[流式输出](./streaming.md)。真实流式 API、reasoning 续传、记忆检索、用户建模与消息打断继续后置。

显式任务控制通过 SessionControlRunner 复用此宿主，详见[任务控制](./任务控制.md)。关闭信号现在也覆盖生命周期准入和 Context 装配；begin 前取消返回 NotStarted，不创建 Pending。受管取消等待工具析构与 Failed 提交，报告完整生成输出/工具结果；保存失败保留 Pending 并阻止替代轮次。保存完成后的取消仍报告 Completed/Delivery，不改写成功历史。

提交不确定性专门验收覆盖 begin、complete、fail 在“实际提交后确认丢失”的情况：全部旧读写/枚举/重置入口拒绝继续，其他会话不能通过旧缓存覆盖已提交记录；重新打开保留 Completed/Failed，只有真实 Pending 变为 Interrupted，后续轮次 ID 不重用。运行时验收直接核对持久字节和保留下来的生成输出，不提供绕过已关闭服务的运行期读取回退。

## 固定轮次的分页读取

SessionService 新增 scan_turns；旧实现默认先取得并校验快照，再按页返回。内置实现创建游标时只固定可信会话身份、修订、轮次数和唯一可变的末尾 Pending，不复制全部历史；终结前缀在该服务内不可修改，之后的完成和追加只对新游标可见。每页最多 16 轮，单个大轮次仍完整返回，因此这不是严格字节上限。

停止或提交不确定后，旧游标和旧句柄都不可恢复；内存中已关闭的历史缓存被释放，后端原始记录不删除。重新启动创建新实例，旧游标不会绑定到新实例。公开 snapshot 和运行时 begin 的完整历史接口保持兼容；默认宿主已启用下节的正文冷存储，不提供归档实现的自定义插件仍沿用格式 1 的完整内存账本。

read_context_record 改为逐页遍历本会话，搜索只保留最新八条命中，按引用读取只保留目标正文；完成全部页面、轮次计数、修订、消息结构与范围核对后才返回。即使前页命中，后页失败也拒绝返回部分结果。引用摘要、原始 JSON、UTF-8 字节偏移和每次 8192 字节的返回边界保持一致。多 User 引导消息仍按原分组规则读取，不扩大身份权限。

## 会话正文冷存储

QQ 与终端组合入口默认启用 `EVE_SESSION_COLD_ARCHIVE=true`。`sessions.v1` 的格式变为 `format_version: 2`：仅保存会话身份、revision 和逐轮正文的 SHA256/字节长度。正文位于状态目录的 `session-archive/<SHA256>.json`，不可变，不在服务中长期缓存。自定义 `SessionPlugin` 仍可不提供归档实现；公开 `SessionArchiveStore` 契约允许替换后端。

启动逐条读取、校验摘要、身份索引、轮次顺序、协议和 revision。全部校验通过之后，才将 Pending 标记为 Interrupted，并一次提交新索引；不重放工具。旧格式迁移也先完整验证，再生成冷正文，最后提交索引。迁移期间错误保留原索引，可能留下未引用正文，不自动清理。格式 2 不兼容旧版插件；回滚必须一起还原匹配的状态和冷目录备份。设为 false 不能将已有格式 2 自动转回格式 1。

追加新轮次或终结轮次只写本轮正文，更新索引，不加载其他会话；列出会话、重置上下文只操作元数据。原文游标固定正文引用，后续完成、追加和重置不修改已固定版本。每页最多 16 轮，声明正文合计最多 32 MiB（单轮上限也是 32 MiB）。文件缺失、摘要不符、解析错误时，旧服务和已发出的游标全部失效，原文件保留。索引提交报错可能实际成功，因此同样关闭旧服务，重开核对，不能自动重试工具。

内存边界：常驻索引最多 32 MiB；这是序列化索引保护值，不是进程 RSS。页内解析、协议校验有临时分配；索引提交仍复制/序列化元数据。旧格式首次迁移需加载原账本。兼容的 `snapshot` 接口仍完整加载一个目标会话；新一轮的 `StartedTurn.history` 仍按原契约构建该会话可见历史，之后由宿主上下文规划处理。冷正文解码并校验后，完整消息直接移交给本轮历史，不再另外复制一份正文与工具回执；失败记录仍只注入原输入和宿主失败说明，取消/中断输入不回放，原工具结果留在档案核对。不能据此宣称整个长上下文链已实现恒定内存。

备份文件后端须包含状态目录（含 state.json、上下文边界和 session-archive）；PostgreSQL 模式须同时备份数据库和这份状态目录，单独复制数据库不是完整迁移。目录中没有垃圾回收和自动删除，避免误删仍被固定游标或历史索引引用的正文；磁盘增长仍需监控。

升级监督器同样认识冷索引格式 2：空闲与回复送达门禁逐轮核对冷文件长度、SHA256、轮次、状态及最终回复，完整扫描时核验 revision。冷文件缺失、损坏或最终文件为符号链接时不切换，保留原字节；备份包含 session-archive。文件戳是缓存提示，等待期间每秒重新核对一次门禁，避免相同文件元数据使 SQLite WAL 中已完成的投递永久保持忙碌判断。最终切换仍再次核对空闲和投递，不凭缓存直接停机。

## 对话内核对上一轮运行证据

默认原文工具 `read_context_record` 新增 `action=recent`：按当前可信用户与会话返回最近已结束的 Completed、Failed、Interrupted 轮次，排除仍在执行的 Pending。`limit` 默认 3、最多 6；用返回的 `next_before_turn` 作为下一次 `before_turn` 向前翻页。不能传其他用户或会话标识；跨群、跨私聊和另一用户的引用不会绕过原身份边界。

每条只返回输入短预览、状态、已保存的失败类别、提供方类别/HTTP 状态、工具开始数与回执数量、少量工具名和至多三条脱敏失败预览。数量没有保存时为 null，不能认作零；Completed 只表示轮次保存完成，不等于业务已独立验收。原记录缺少的原因或参数不会补造，查询不重放工具，也不创建修复或后台任务。

返回的 `turn:<轮次>:<摘要>` 可继续用 `action=read` 核对完整逻辑记录，包括已保存的失败回执。按 `offset` 分页，每页最多 8192 个原始 JSON UTF-8 字节，`next_offset` 指向完整字符边界；所有页都给出整条序列化记录的长度及 SHA-256。失败引用不能改成另一个内容，活动轮次不能当作已结束记录读取。原有 history/task 引用仍有效；任务可能继续变化，跨页须核对摘要，不能混拼不同版本。

JSON 分页流式计数和哈希，不为读取一页另建整份转义正文。历史搜索仍保留单条序列化的兼容路径。游标继续校验所有页的身份、轮次、总数与修订，后页错误不返回之前找到的部分结果；每页之间让出执行器并检查原取消与期限，不因查询重领预算。原始记录、存储格式、历史边界和权限不改写。此工具读保存的会话证据，不是整个宿主的系统日志出口；历史文字不能成为新授权。

## 冷归档的重复写入校验

文件归档重复 put 相同摘要时仍完整核对已存在文件的普通文件属性、32 MiB 大小保护和 SHA-256；校验改用 64 KiB 缓冲，不为仅需要摘要的检查另读整份正文进 Vec。校验或同步失败仍报错，不覆盖或修复损坏原文；并发创建相同摘要后的复核也走同一流程，Windows 保留用于 FlushFileBuffers 的写句柄规则。原 get 接口仍返回完整正文，索引、原文和摘要格式未改。

Linux 的 scripts/session_archive_profile.py 可对照旧 4a54924 与当前 archive.rs：固定 32 MiB 合成 JSON 字符串，首次写入后再重复三次，输出字节数和 SHA-256 完全一致。独立归档进程峰值 66860 → 34116 KiB（约 49%），不是整版 Eve RSS，也不代表读取正文或每次提交都出现同样降幅；探针不使用真实会话、模型或网络。
