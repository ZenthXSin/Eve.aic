# 首个自主学习目标：Mindustry 模组创作

完整需求和验收清单以 [Issue #134](https://github.com/ZenthXSin/Eve.aic/issues/134) 为准；开发交接为 [#113](https://github.com/ZenthXSin/Eve.aic/issues/113)。本页记录用户于 2026-10-07 确定的目标。完整行为链已经接通，并有跨独立进程的端到端验收与另一个创作领域（静态网页）的留出场景验收；真实模型质量与正式 QQ 体验尚未验收，见下文“验收记录”。

## 用户场景

用户在普通聊天里随口说：“我喜欢 Mindustry 的模组，但是不知道怎么创作。”不使用 `/goal`，不重复提醒。

Eve 自然回应、记下兴趣和当前经验，之后自主研究并实际尝试制作，更新知识和实践记忆，固化技能或工具。在已有实质进展、适合交流时，主动告诉用户自己能如何帮助，并根据用户提出的想法继续创作。

预期行为示例：

> 你上次说想做 Mindustry 模组，我后来试着做了个新方块，已经加载成功了。你有什么想加进去的东西？告诉我，我帮你写。

## 行为与证据

| 阶段 | 行为 | 核验依据 |
| --- | --- | --- |
| 观察 | 识别明确兴趣、经验和困难，保留推断标记 | 原始交互、作用域、时间和修订 |
| 派生 | 发现自身知识/能力缺口并形成学习目标 | 目标来源、派生原因、步骤与预算 |
| 研究 | 阅读文档和实例，形成领域知识 | 来源、适用版本、结论及验证状态 |
| 实践 | 制作最小模组，加载并验证行为，分析失败 | 代码产物、游戏版本、实际日志与测试输入 |
| 固化 | 积累实践经验，形成可复用技能或工具 | 版本、验证证据、启用状态及后续实际调用 |
| 跟进 | 结合话题、进展和用户反馈主动邀请创作 | 决策原因、去重和真实投递回执 |
| 更新 | 接收纠正、撤销或具体需求后调整 | 新来源、修订与后续计划 |

用户记忆、领域知识、实践经验和技能/工具分离保存。领域资料不全部写为个人偏好，模型猜测不冒充用户指令。生成代码、编译成功、保存反思草稿和模型自述都不能替代实际运行验证。

机制应能迁移到其他游戏或创作领域：兴趣/需求 → 能力缺口 → 学习目标 → 研究实践 → 能力固化 → 主动帮助。Mindustry 是第一项验收场景，不使用固定关键词分支和固定邀请模板冒充自主学习。

## 验收与恢复

最低完整验收：用户仅提一次，之后没有提醒时仍能后台推进；形成有来源的知识，产出一个真实可加载且行为符合预期的最小模组，至少固化一项在独立后续任务中使用成功的技能或工具，再择机主动发起创作邀请。

主动时机结合当前话题、用户忙闲/静默偏好、近期主动次数和先前反馈；QQ 发送条件不满足时保留待投递。分段和表达方式沿用已学偏好。完整验收分别记录确定性替身、实际游戏运行与正式 QQ 体验，不能相互替代。

长期调度具有可配置间隔、模型/工具预算、尝试上限与停止条件；没有新差距或新进展时不空转请求模型。普通研究、工作目录内实验及已有授权内的学习直接推进，不引入逐步请用户批准的流程。作品发布或正式实例变更沿用对应宿主授信边界。

重启保留记忆、知识、待办、预算与证据。已完成步骤不重放；未知执行先核对结果。用户更正、撤销兴趣、要求安静，以及失败、预算耗尽和损坏状态，均须有明确行为并保留原数据。

## 接手实现顺序

1. 普通聊天兴趣观察、记忆与学习目标派生。首个切片已实现：`--interest-learning` 只保存可逐字核对的用户原话，模型推断单独标注，派生低优先级学习目标并后台反思；撤回即取消目标，见[兴趣观察](./兴趣观察.md)。本切片使用确定性替身验收，不勾选 #134 的完整验收项。
2. 独立领域知识和实践经历的契约、存储、召回与受控资料研究。领域知识与受控研究已实现：配置 `--research-source` 后，学习目标在入口页面范围内后台研究，知识附来源网址、抓取时间、版本与逐字引用，推测标为未验证，见[受控研究与领域知识](./受控研究与领域知识.md)。实践记录随第 3 步的真实运行证据一起定义。
3. 最小模组制作、运行验证、失败修正与效果反馈闭环。首个切片已实现：配置 `--practice-mindustry-server` 后，学习目标在研究之后做出只含数据文件的最小模组，用操作者提供的无头服务端在全新目录中实际加载并探测内容属性，依据警告与探测实际值至多修正两次；只有实际加载且全部探测通过才记为已验证，见[实践验证](./实践验证.md)。
4. 技能/工具生成、验证、授信范围内启用和跨任务复用。首个切片已实现：配置 `--skill-learning` 后，已验证的实践被提炼为参数化技能，宿主核对它能逐字还原原产物，再用自己选取的不同参数实际运行通过才自动启用；同一用户的后续独立任务可以选用技能，调用结果以实际运行证据为准，可停用、启用与回退，见[技能固化与复用](./技能固化与复用.md)。已启用的技能同时成为对话中可调用的工具，按会话身份调用、每次实际运行验证；`/gaps` 从实践记录推导反复遇到的能力缺口（运行环境做不了的目标与反复出现的问题）。配置 `--tool-forging` 后，重复出现且有失败与成功草稿对照的问题会锻造成声明式运行前检查，经账本草稿回放验证后自动启用，并用于后续独立实践，见[工具锻造](./工具锻造.md)；当前生成的是只读检查规则。
5. 主动投递、时机策略、表达和用户反馈学习。首个切片已实现：配置 `--outreach` 后，学习目标有了已验证的实践就依据账本事实撰写一条邀请，在用户下次私聊找 Eve 时先判断时机，合适才随被动回复附带，以平台回执为准；操作者可开启等待后的主动私聊，被平台拒绝时继续等待被动窗口；用户可用 `/outreach off` 要求安静；送达后识别用户的回应并逐字引用原话，连续表示不方便或不需要时放慢节奏、暂停主动私聊，先前反馈也交给之后的时机判断；用户提出具体想法时，原话派生为后续创作目标，沿用知识与已验证的技能实际做成后再告诉用户，见[主动交流与邀请](./主动交流与邀请.md)。
6. 完整端到端、独立进程恢复与其他领域留出场景验收。完整行为链、独立进程恢复与留出场景都已有验收（见下文“验收记录”）。

复用现有 memory/learning/cognition/cognition-loop/plan/action/plugin 公开契约。[多步计划](./多步计划.md)已提供 CLI 与 QQ 入口，模型建议经确认后由受控研究和实践后台推进；兴趣学习链沿用自身的自主准入。反思草稿保存与实际目标完成分别核验，实践和计划步骤仍需独立效果证据。

按独立 `codex/` 分支和 PR 交付，保持定义、实现、组合分层；每个切片同时交付恢复语义与实际验收。相关工作见 #122（内生计划）、#115（Web）、#27（插件）与 #32（配置）。

## 验收记录

`connectors/qqbot/test/journey_test.py` 用 5 个独立的 `eve-qqbot` 进程走完整条行为链，阶段之间进程退出再启动：

1. 用户在私聊里只提一次兴趣，之后不发消息：兴趣追溯到那一条交互；后台研究得到有来源、适用版本与验证状态的知识；实践实际运行通过；技能经宿主选参验证后自动启用；邀请撰写完成并等待时机。
2. 重启后用户闲聊：时机判断合适，邀请随被动回复附带，有平台回执；研究、实践、提炼与撰写都不重放。
3. 重启后用户提出想法：识别为提出想法，派生后续创作目标；草稿器选用技能，实际运行通过；撰写引用用户原话的新邀请。
4. 重启后用户再闲聊：新邀请送达；`/outreach` 与 `/skills` 显示回应、回执与调用记录。
5. 重启后用户撤回兴趣：学习目标与后续目标取消；已有知识、实践与技能记录完整保留。

结束时打印一份证据摘要：各类模型请求次数、实际运行次数与运行环境版本。

`connectors/qqbot/test/holdout_test.py` 是留出场景：用户只说一次“想给自己做个个人主页”。宿主换成 `--practice-browser`，不加任何领域分支，沿用同一组契约：
- 实践依据浏览器给出的实际字号修正一次后验证通过；
- 技能经宿主自选的留出参数在浏览器中验证后启用；
- 邀请附带送达；用户提出想法后，选用技能做出新页面并实际验证，再次邀请送达；
- 宿主交给模型的规则与数据里不出现首个场景的领域词。

真实模型验收由 `.github/workflows/learning-model-acceptance.yml` 手动触发（只在主线运行，消耗模型额度）：真实模型与真实 Mindustry 服务端走同一条行为链，QQ 平台仍为替身。`scripts/learning-model-acceptance.py` 记录各里程碑是否达成与用时，以及模型实际写出的知识、实践结果、技能、邀请正文与回应识别结论，作为报告上传。真实模型的结果不可预知，里程碑没有达成只如实记录；进程异常退出或违反宿主不变量（例如邀请指向未验证的实践）才算失败。

各层的通过不互相推广：确定性替身只证明宿主契约、持久化与恢复语义；真实 Mindustry 只证明产物在该版本服务端中的实际加载与探测结果；模型始终是替身，表达、判断与识别的质量需要真实模型另行评估；正式 QQ 的体验与平台限制只能在正式环境确认。
