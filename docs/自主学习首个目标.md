# 首个自主学习目标：Mindustry 模组创作

完整需求和验收清单以 [Issue #134](https://github.com/ZenthXSin/Eve.aic/issues/134) 为准；开发交接为 [#113](https://github.com/ZenthXSin/Eve.aic/issues/113)。本页记录用户于 2026-10-07 确定的目标，尚未交付完整行为链。

## 用户场景

用户在普通聊天里随口说：“我喜欢 Mindustry 的模组，但是不知道怎么创作。”不使用 `/goal`，不重复提醒。

Eve 自然回应、记下兴趣和当前经验，之后自主研究并实际尝试制作，更新知识和实践记忆，固化技能或工具。在已有实质进展、适合交流时，主动告诉用户自己能如何帮助，并根据用户提出的想法继续创作。

预期行为示例：

> 你上次说想做 Mindustry 模组，我后来试着做了个新方块，已经加载成功了。你有什么想加进去的东西？告诉我，我帮你写。

## 行为与证据

| 阶段 | 行为 | 核验依据 |
| --- | --- | --- |
| 观察 | 识别明确兴趣、经验和困难，保留推断标记 | 原始交互、作用域、时间和修订 |
| 派生 | 发现自身知识/能力缺口并形成学习目标 | 目标来源、派生原因、步骤与预算 |
| 研究 | 阅读文档和实例，形成领域知识 | 来源、适用版本、结论及验证状态 |
| 实践 | 制作最小模组，加载并验证行为，分析失败 | 代码产物、游戏版本、实际日志与测试输入 |
| 固化 | 积累实践经验，形成可复用技能或工具 | 版本、验证证据、启用状态及后续实际调用 |
| 跟进 | 结合话题、进展和用户反馈主动邀请创作 | 决策原因、去重和真实投递回执 |
| 更新 | 接收纠正、撤销或具体需求后调整 | 新来源、修订与后续计划 |

用户记忆、领域知识、实践经验和技能/工具分离保存。领域资料不全部写为个人偏好，模型猜测不冒充用户指令。生成代码、编译成功、保存反思草稿和模型自述都不能替代实际运行验证。

机制应能迁移到其他游戏或创作领域：兴趣/需求 → 能力缺口 → 学习目标 → 研究实践 → 能力固化 → 主动帮助。Mindustry 是第一项验收场景，不使用固定关键词分支和固定邀请模板冒充自主学习。

## 验收与恢复

最低完整验收：用户仅提一次，之后没有提醒时仍能后台推进；形成有来源的知识，产出一个真实可加载且行为符合预期的最小模组，至少固化一项在独立后续任务中使用成功的技能或工具，再择机主动发起创作邀请。

主动时机结合当前话题、用户忙闲/静默偏好、近期主动次数和先前反馈；QQ 发送条件不满足时保留待投递。分段和表达方式沿用已学偏好。完整验收分别记录确定性替身、实际游戏运行与正式 QQ 体验，不能相互替代。

长期调度具有可配置间隔、模型/工具预算、尝试上限与停止条件；没有新差距或新进展时不空转请求模型。普通研究、工作目录内实验及已有授权内的学习直接推进，不引入逐步请用户批准的流程。作品发布或正式实例变更沿用对应宿主授信边界。

重启保留记忆、知识、待办、预算与证据。已完成步骤不重放；未知执行先核对结果。用户更正、撤销兴趣、要求安静，以及失败、预算耗尽和损坏状态，均须有明确行为并保留原数据。

## 接手实现顺序

1. 普通聊天兴趣观察、记忆与学习目标派生。
2. 独立领域知识和实践经历的契约、存储、召回与受控资料研究。
3. 最小模组制作、运行验证、失败修正与效果反馈闭环。
4. 技能/工具生成、验证、授信范围内启用和跨任务复用。
5. 主动投递、时机策略、表达和用户反馈学习。
6. 完整端到端、独立进程恢复与其他领域留出场景验收。

可复用现有 memory/learning/cognition/cognition-loop/plan/action/plugin 公开契约；多步计划目前以 CLI 为入口，模型建议仍待确认，现有反思仅保存草稿。新增自主准入和实际能力执行必须给出独立效果条件；这些部分尚未因记录本目标而实现。

按独立 `codex/` 分支和 PR 交付，保持定义、实现、组合分层；每个切片同时交付恢复语义与实际验收。相关工作见 #122（内生计划）、#115（Web）、#27（插件）与 #32（配置）。
