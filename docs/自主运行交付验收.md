# 自主运行交付验收

本文件按用户提出的九项完整目标验收，不以已经写出的功能重新定义目标。当前是实现与验收中的检查表，**不是完成声明**。源码存在、测试文件存在、旧版本测试通过、工具返回成功、模型自述完成，均不能单独证明整项目标已经实现。

## 判定与证据规则

- **缺口**：当前代码或运行事实与要求矛盾，继续实现。
- **已见实现，待验收**：找到具体执行路径，但没有当前交付版本的完整运行证据，不能记通过。
- **通过**：在固定版本上真实运行相应场景，保存可复查的工具回执、状态与产物，并确认检查范围覆盖原要求。
- **不确定**：证据缺失或只间接支持，按未完成处理，继续核查。

本次文档审计没有运行 Cargo、应用进程、生产服务或真实平台收发。其他代理执行的检查应由主验收者读取原始结果后补入下方证据表。新增测试和已有 CI 配置只作为下一步验收入口。

“全部功能”包括默认聊天入口中的业务能力及其授权、查看、启停和恢复。QQ 与独立 Web 均应核对；某工具只在 QQ 注册、某功能依赖额外启动开关、或 Web 仅展示状态，不能证明自然聊天已经统一全部能力。可信部署凭据及身份必须由宿主管理，但不能要求普通业务使用者手改配置或输入内部命令才能完成本可自然表达的操作。

“持续推进”须保持用户原始目标及已授予预算。固定重试次数、超时、权限撤销和未知副作用保护属于安全要求；正确停止危险动作不等于完成原目标。对于可解除的技术阻断，还须有持续观察、恢复与修复路径。不能把“保存为 Blocked”或“等待用户下一句话”当作完整自主恢复。

## 当前必须继续解决的范围缺口

1. 默认自然能力装配与独立 Web 的完整组合；新启动的 Start-Web token 自动初始化。
2. 默认后台任务已有持久半小时提醒及 QQ 进程证据；继续验收它与真实模型自然长期目标、Subject 关注检查和正式平台投递组成的连续链条。
3. 可恢复技术阻断的自动观察与原任务接续；自动派发修复必须保持原目标、身份、授权证据和预算，未知副作用先核对。
4. 普通长期目标的完成标准覆盖原始要求；不能通过改成简单文本合同或只验一个文件来缩小目标。
5. 真实默认运行、自升级、生产状态迁移、最终 PR 合并及上线证据。代码内置能力、模拟测试与生产启用是不同待验收事项。

这些缺口不能仅通过修改说明文字或将其列为“已知限制”消除。安全停止且保留现场是必要行为，但被阻断的原目标仍须继续追踪。
