# 实时活动进度

QQ 实时模式在一段真实模型等待、上下文整理或普通工具等待持续较久时，可发一条以“系统进度：”开头的活动提示。它说明运行仍在进行，不代表 Eve 已得到结论或完成任务。宿主直接观察运行事件，不请求主模型或进度措辞模型；正式观点、发现和最终答复仍由 Eve 调用 `send_message`。

沿用 `runtime.progress.slow_after_ms`（默认 45000，0 关闭）和 `min_interval_ms`。阈值只是最早检查时机：相同正文不重复，活动没有变化就不会定时刷屏。每条提示发出前重新核对精确控制代、轮次、尚未结束的活动和可信消息锚点；收到全部工具结果、取消或结束会撤销尚未写出的提示。工具参数、输出和内部 final 不进入活动文字。

短轮次不发提示。明确要求不要进度、先不用回答或保持安静的输入，会在本轮保守抑制宿主提示；这是有限的文字识别，不声称理解所有自然语言偏好。`wait_for_input`、`send_message`、`send_sticker` 和 `task_progress` 本身不触发工具等待提示。新输入到来后不借旧消息继续发宿主提示；原轮引导和已有的长工具交流机会继续按原机制处理。

同一私聊轮次至多两条、群轮次至多一条；每次都使用原消息的被动窗口，不转主动发送。已排队的正式发言先处理，宿主提示为正式答复保留至少一个原被动进度额度。同目标已有消息发送时等待真实回执或独立超时，不并发抢占。提示失败或 unknown 后不重放，新的正式发言仍可正常尝试。

系统提示继续保存到既有 `progress` 回执，`decision_id` 为空，不增加持久格式版本；不计入 Eve 已发言正文、表达记忆或训练样本，也不单独建立后台补充窗口。写桥接前保存 Sending，写出后失去回执保持 unknown；尚未写出且活动失效的准备记录会撤销，不消耗 Node 序号。每条回执只结算对应序号及明确发言决定，迟到的系统提示回执不能完成另一条 `send_message`。

活动观察、已用被动窗口和计时只存在于本进程；重启不重建活动、不自动补发。已保存的实际投递和未知结果沿用原回执恢复规则。损坏状态继续按既有规则报错并保留，不清空。

本地 Node 测试覆盖额度、群限制、新输入和结束使未发送提示失效、失败去重、超时及迟到回执。Rust 的 `live_activity_progress` 通过真实通道与 Node `bridge-core`、替换运行器和平台出口，覆盖慢模型、慢工具、快速及安静轮次、等待输入、不调用进度模型，以及系统提示回执与正式发言隔离；它随远端 Rust CI 执行，不向真实模型或 QQ 发测试请求。
