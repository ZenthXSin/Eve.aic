# 运行额度选择

本轮按主人在开发会话中的额度选择调整源码默认值。最终明确的每目标工具步数是 550，覆盖之前的 100；自主授权目标数为 20。没有重置部署实例的用量、延长旧授权或在 QQ 身份下代为创建新授权。

| 项目 | 新默认值或上限 | 持久化与兼容 |
| --- | --- | --- |
| 自主探索 | 每目标默认及上限 550 步，每次授权默认及上限 20 个目标 | 保留旧授权已派发数、期限和授权证据去重 |
| 后台、子代理总时长 | 默认不设总时长，按共享工具步数结束 | 旧任务已保存的截止仍保留；授权到期、取消、单次模型/普通工具超时、有限恢复次数继续生效；可显式配置非零总时长 |
| 模型并发 | 角色默认 5，宿主主/辅用途合计最多 5 | 旧配置可读，角色实际并发取配置与 5 的较小值；前台、后台、子代理共用 |
| 单次模型输出 | 默认不指定 token 上限 | 0 表示不传该参数，保留显式配置；不突破服务端模型窗口或取消本地字节保护 |
| 偏好学习 | 默认及上限 15 次成功提炼 | 失败保留记录和有界补做限制，不消耗成功次数 |
| 动态上下文 | 默认上限 275000 token | 原始历史仍可分页召回，固定模式阈值独立配置 |
| 历史窗口 | 默认及可配置上限 16 MiB，仍最多 16 个完整轮次 | token 上限仍独立生效，不无条件注入所有历史 |
| 委派上下文、恢复检查点 | 各 16 MiB | 完整校验序列化字节，不静默裁剪后冒充完整上下文 |
| 原始记忆、任务逻辑账本、学习与决策热账本 | 各 16 MiB | 条数保护不变；旧合法学习账本仍按 32 MiB 读取，不误报损坏；写入超限保留旧记录并报告 |
| 语义分段缓存 | 16 MiB，最多 256 段 | 仅限制内存缓存，旧磁盘段继续兼容读取 |
| 会话冷记录、冷索引新写入 | 各 16 MiB | 旧 32 MiB 合法数据仍可读取；新提交超限失败关闭，不自动删除旧正文 |
| 工作便笺 | 每份正文及索引 16 MiB | 正文落盘、索引常驻；自动注入和工具预览最多 16 KiB 正文；固定版本分页读取及 CAS 局部修改 |

这里的 MiB 指 1024 × 1024 字节。JSON 转义、不可变历史版本、冷目录以及原子提交的临时副本有独立的物理容量保护，不把逻辑正文的 16 MiB 当成整个文件系统目录的总大小。

## 失败请求不消耗模型额度

模型请求先持久预留，预留占用可用余额，防止并发超支；适配器成功返回后结算。失败、取消释放自己的预留；跨窗口结算只影响原窗口，不冲抵新窗口。重启释放未确认成功的在途预留并记录 interrupted_requests；失败记录 failed_requests，均不记作成功。旧版没有结局证据的直接计数不追溯退款。结算失败关闭账本句柄，须重开核对，不猜测提交是否生效。

这个额度衡量模型请求是否成功返回，不证明工具、任务或后续业务验收成功，也不表示中转站不收取失败请求的费用。配额退还不会增加恢复次数、重试次数、授权目标数或工具预算。版本 2 预算账本不能交给旧版忽略预留的进程继续写；回退应同时恢复经过确认的匹配账本快照。

## 定期优化

沿用持久化的 30 分钟目标检查和既有授权，不额外启动无授权循环。优先从真实失败、阻塞、交互缺陷、内存与磁盘压力、重复工作中选值得解决的问题；比较收益、置信度、成本和风险，使用稳定 problem_key 去重。没有新问题就等待。可复用且验证过的流程形成经验或插件候选，仍须权限核对、预演和真实验收，不能把候选自报为已上线能力。
