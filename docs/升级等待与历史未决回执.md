# 升级等待与历史未决回执

自主发言模式使用 QQ 格式 9：申请绑定已完成 Control 轮次与主回执的 `control_turn_id`，`Handled` 可以表示本轮明确安静结束；每条已发送表达必须有有效平台回执，发送中状态仍阻挡切换。`speech.sqlite3` 和群观察格式 4 中正在审视或发送的记录也参与空闲门禁。等待或未认领的决定跨升级保留，未知不补发。完整备份须包含数据库、WAL 与 required 标记，恢复程序必须能读新格式，见 [Eve 自主发言](./Eve自主发言.md)。

线上迁移状态保留了两条旧 Processing 回执。此前监督器把所有 Processing、ReplyPending 和发送中的进展都视为当前任务；它们按恢复协议不能自动重放或改成成功，因此新升级请求即使已经完成并送达，也始终无法满足空闲门禁，最终报 `reply_or_idle_timeout`。

监督器现在在启动运行器之前，只读记录历史未决回执的完整 SHA-256 摘要。后续门禁仅在记录完全未变化时，排除它们对当前进程空闲判定的影响；原记录、未知结果和历史证据保持原样，不重发、不重做工具、不自动重试旧升级请求。

被排除的旧记录不能用来证明本次申请已经送达。申请仍需精确绑定宿主会话、用户和持久轮次，轮次必须 Completed，新回执必须 Sent 且回复一致，所有会话不得有 Pending 轮次。启动后新增的回执，以及内容、状态或发送进展发生变化的历史回执，仍须正常等待。损坏的历史进展记录仍拒绝升级，不能利用历史标记隐藏损坏。

历史摘要只存在于当前监督器内存；重启会重新从已持久化状态捕获，旧 request/processing 文件仍按既有中断协议归档而不重放。该判断依赖运行器对同一状态目录的独占锁；不会允许两个正式运行器共享写入状态。

已用真实子进程验证历史 Processing/ReplyPending/未知进展不再阻塞、新回执仍阻塞、历史变化恢复等待、申请未送达与损坏拒绝，以及切换、候选失败、二进制回退和重启不重放。线上状态的只读复现也确认：旧门禁为 false，修复后为 true，状态文件摘要不变。
