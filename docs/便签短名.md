# 便签短名

便签可以起一个唯一短名。永久 ID、全部历史版本和原动作回执照常保留；目录与搜索结果会显示短名。

```ts
await tools.notes.create({
  alias: "随手记",
  title: "随手记",
  content: "今天想做的事",
  sources: [{ kind: "experienced", at: new Date().toISOString(), description: "自己的计划" }],
});
await tools.notes.get({ id: "随手记" });
await tools.notes.update({ id: "随手记", content: "更新后的计划" });
await tools.notes.update({ id: "随手记", alias: "日常" });
await tools.notes.update({ id: "日常", alias: null });
```

`get`、`update`、`versions` 的 `id` 都接受永久 ID 或当前短名。改名或移除后，旧短名不再指向原便签；可以给另一张便签复用。短名区分大小写，长度为 1–64 个字符，不含空白、控制字符、斜线，也不能使用完整的 64 位十六进制 ID。便签标题可以相同，短名必须唯一。

更新可省略 `expectedRevision`：接口在进入写队列前读取当前版本，再按原有版本前件比较后追加新版本。读取到同一版本的并发修改会有一条被拒绝，需要重新读取；不会自动循环重试覆盖另一条修改。如果修改内容基于之前读取的正文计算，应继续传入那次读取的 `note.revision`，以保护从读取到提交的整个区间。

短名随便签版本记录，也遵守候选回滚隔离。如果回滚使历史短名恢复并发生冲突，按短名操作会明确报错；可以用永久 ID 改名或移除其中一个短名。原件始终保留，不根据短名猜测应该修改哪一张便签。语义检索仍为 TODO。
