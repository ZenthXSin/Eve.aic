# 同一输入的交流职责交接

长工具运行中收到私聊新输入时，原话继续进入主轮，前台可以先回答即时交流。两条路径使用同一个输入队列锁：主轮先取走输入，前台就不能再领取并发送；前台先领取，则先保存 Sending，再让主轮原子取到原话与该输入的交流交接事实。它解决的是同一输入同时被两条路径当成无人回应的新事件的问题，不靠正文查重，也不增加模型判断调用。

公开契约 `TurnSteering::take_update` 返回 `SteeringUpdate`，包含既有用户批次和逐条 `InputReplyHandoff`。每条交接带真实 `input_message_id`、原文、前台事件编号、拟发送正文及状态。同文不同编号仍是不同输入；多个子输入各自关联，不借用最新消息的身份。旧插件可以继续只实现 `take` 或 `take_batch`，默认没有交接事实。

前台在领取临界区核对原控制代、轮次和工具批次；业务线程消费输入与保存交接不能交错成半份状态。发送前再核对当前可信输入、原控制代、取消和已撤销事件。领取后主轮自然完成仍由前台发送已接手的即时交流；完成后明确撤销、换代或状态未知则不发送。主线程继续理解新问题、执行补充指令，并可以表达新的工作结果；已被前台领取的即时交流不再另作一份回应任务。

`sending` 只表示准备或发送中；有有效平台编号的 `sent` 才确认送达。`unknown` 保持未知且不自动重发；`failed`、`not_sent` 表示此次前台交流没有完成，主轮可在自然继续时回应。平台终态通过发送时保存的原轮弱句柄更新，即使前台窗口已移除也不会错投给后来的输入、另一用户或新轮次。

主轮只在原有模型请求边界追加宿主交接数据，不重建上下文，不改变稳定缓存前缀或长期模型会话。数据不进入用户授权原文或持久会话 transcript。终态本身不通知 `wait_for_input`，不丢弃模型已选好的业务工具，不触发额外模型请求，也不延长已结束的轮次。

输入与交接队列仅存在于当前轮次。发言账本继续负责发送状态持久化：保存失败时不发布交接，也不吞掉用户输入；写出后失去回执保持未知，重启不从轮内交接重放原话或发言。既有发言账本的恢复规则继续把无法确认的 Sending 处理为未知，保留损坏记录并报错，不清空数据。该变更没有修改旧表达回执的事件身份或持久格式。

运行时原子消费后立即把交接保留在 `TurnDiagnostics.input_replies`，随后才处理用户正文和上下文校验；按前台事件编号更新最新状态，校验同事件的真实入站编号、原文、发言和种类不变。前台失败时由 `SessionFailureEvidence.input_replies` 持久化，覆盖已消费输入在后续读取或模型请求失败时的恢复。单轮最多 64 条，完整 JSON 最多 512 KiB，拒绝重复身份、未知字段和无效状态；这是结构核验，不进行正文或语义审查。

失败自动转后台继承这些强类型事实，放在委派上下文独立的 System 数据 `eve.input_reply_handoffs` 中，不加入 `review_user_messages` 或伪造用户消息。后台仍处理原任务和补充业务；Sending 是失败时快照，恢复按结果未知解释，不改写为 Sent，也不据此重发。已持久 Sent 保留平台编号。晚到但未被主轮消费的回执不引发额外模型请求，保存的 Sending 已能保留交流归属。

旧会话记录缺失 `input_replies` 时读取为空，不从历史猜补；新增字段为空时不写出。新记录含该字段时旧二进制会因严格格式拒绝读取，回退必须保留匹配程序及完整状态，不能删字段强行降级。正常前台没有执行检查点，进程重启的 Pending 按现有规则中断，不自动重放；后台独立任务保持自己的检查点。公开 `with_turn_journal` 不支持同时带实时 steering 的会话轮次，执行前明确返回配置错误，未读取或覆盖原检查点；后台无会话 turn_id 的调用不受影响。

验收覆盖消费与领取两种顺序、保存失败及活动撤销、多输入同文、身份与轮次隔离、四类终态不会唤醒等待输入、自然请求中的授权与缓存隔离。`live_foreground_speech` 通过真实 Rust 通道、Node `bridge-core` 与长运行子进程验证一次输入一次消费、原轮正常完成后仍发送一次、完成后撤销或换代零发送，以及平台回执晚于前台窗口移除时仍归属于原轮。恢复验收经过实际 SessionLlmHost、文件状态和冷存档重启、失败转后台、任务重启与 Worker 执行，检查 Sending/Sent/Unknown 保留、补充业务执行、旧工具不重放和模型请求数不增加。模型和平台出口使用本地替身，不向生产服务发测试请求。

## 无追加输入的实际进度交流

私聊主轮在真实工具批次仍等待结果超过 8 秒时，也可以获得一次自然交流机会，无须用户再催问。同一份事实最多一次判断；之后确有子代理阶段变化才能再次审视，同一控制代至少间隔 60 秒且最多三次；近期显式发言和已排队发送优先。短工具不触发，固定系统进度播报保持关闭。Eve 可以决定 speak、wait 或 silence；wait 等下一份新的活动事实，不循环询问相同进展，延迟 speak 复用已存决定，不再请求模型。

宿主在开始判断前冻结当下事实：父工具仍在等待，以及绑定到该父调用的子代理工具提交数、返回数、失败数、未知数和工具名称。不会提供工具参数、结果正文或子代理推理；工具已返回不等于业务或编译成功。子代理的迟到、其他代或其他父调用事件不能覆盖主轮批次，观察回调不执行或重放工具，也不会每次子步骤都调用发言模型。

新增 `InputReplyHandoff.kind=progress` 表示实际进度发言，仍关联真实原消息及原文，但不生成、消费或领取新的用户输入；同一原消息可以有不同事件的进度事实。旧数据缺省为 `user_input`，默认值不序列化，原持久记录格式与字节不变。自然发言沿用持久发送认领和原轮弱句柄终态交接，主线程在原请求边界看到实际已发、失败或未知状态，不另起模型轮次。发送失败或未知的事实保留，不能因后续启动重新发送。

活动窗口复用原私聊收到消息后的实际平台期限与剩余额度，不提前结束原任务，不重置窗口年龄，不扩大四分钟回复期限；225 秒后不开新的自然交流机会。当前无追加输入的机会只对私聊启用。新输入、取消、换代、父工具结束或窗口失效会撤销尚未认领的旧决定；已认领发送仍需最后核验原控制代和取消，SDK 发送前再次检查平台窗口。
