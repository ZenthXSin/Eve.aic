# 实践验证与实践记录

这是[首个自主学习目标](./自主学习首个目标.md)（#134）的第三个切片。兴趣派生的学习目标在研究之后，由 Eve 自己做出一个最小产物，交给操作者提供的真实运行环境实际加载，再按受限的探测项核对行为。运行时的警告、探测实际值和日志会交回草稿器，用来修正下一次尝试。整个过程形成有版本、有证据的实践记录。

验证只认运行器的实际结果，草稿、编译成功或模型自述都不算。只有运行环境确认产物已加载、没有针对产物的警告，并且全部探测通过，这次尝试才记为“已验证”。首个运行器面向 Mindustry 内容模组：已用 v160.7 的无头服务端实测，类型写错时游戏只给警告、退回普通方块，仍报告“已加载”；运行器据此判定未验证。第二个运行器面向静态网页（留出领域），用无头 Chromium 实际打开 HTML/CSS 并探测计算样式，与 Mindustry 共用同一组契约，见下文“静态网页运行器”。

## 启用

```bash
./target/debug/eve-qqbot --state-dir .eve-qqbot --interest-learning \
  --research-source https://example.org/docs/modding/index.html \
  --practice-mindustry-server /opt/mindustry/server-release.jar
```

- `--practice-mindustry-server` 指向操作者自己下载的 Mindustry 无头服务端 jar，必须同时开启 `--interest-learning`。默认不实践，Eve 也不会自己下载运行环境。
- 也可以改用 `--practice-browser <Chromium 或 Chrome 程序>`，实践静态网页；两种运行环境一次只能选一个。
- 启动时读取 jar 并计算 SHA-256 摘要，写入每条记录的运行环境标识，用于复验。文件不存在或不是 jar 时，在通道启动前拒绝。
- `--practice-java` 指定启动程序，默认 `java`，需要 Java 17 及以上；`--practice-java-arg` 可重复，用作前置参数（例如包装脚本）。这两个参数必须与服务端 jar 一起使用。
- 草稿复用主模型配置与 `EVE_OPENAI_API_KEY`。
- 草稿请求经公开 `complete_json` 接口使用 JSON 对象模式，普通聊天不受影响。自定义 Provider 可沿用普通完成接口；宿主仍严格检查所有输出。后端不支持 JSON 模式时记录 Provider 失败，不自动重试或更换模型。
- 同时配置了 `--research-source` 时，要等该目标修订的研究结束（或研究次数用尽），再把有来源的知识作为资料交给草稿器：来源原文在前，未验证推测在后，至多 12 条。

`/gaps` 查看当前用户实践中暴露的能力缺口：运行环境做不了的目标（按运行器归类，附不适用的理由），以及多次实践反复出现的同一结构问题或运行警告（去掉数字、合并空白后归类，出现至少 2 次）。缺口由实践账本推导，不另行保存，是“需要新的运行环境或工具”的依据。

`/practice 兴趣ID` 查看实践记录，最多显示最近两次实践。每次尝试列出产物文件、运行版本、加载状态、警告，以及每项探测的期望值和实际值；使用技能实例的尝试注明技能与版本。只能查看当前会话自己的兴趣；未启用时回复“实践验证未启用。”。

## 一次实践的过程

每个等待中的兴趣学习目标，以及用户回应邀请时提出想法派生的后续创作目标（沿用最初学习目标的知识，见[主动交流与邀请](./主动交流与邀请.md)），每个修订至多实践一次，一个目标累计至多两次；同一时间只实践一个目标。用户待办、反思子目标、已取消或已完成的目标都不实践。一次实践至多三次尝试：

| 阶段 | 先保存 | 再执行 |
| --- | --- | --- |
| 准入 / 下一次尝试 | Running 实践与该次尝试（Drafting），含任务、运行器声明与草稿器版本 | 一次无工具的草稿请求 |
| 草稿 | 草稿与结构检查结果；通过检查的进入 Running | 在全新目录中实际运行 |
| 运行 | 运行证据与本次结论 | 已验证则结束；否则在仍有次数时开启下一次尝试 |

- **不适用**：草稿器判断运行器的领域与学习目标无关时（例如水彩画），记为“不适用”，不启动运行环境。
- **结构检查不通过**：同样不运行，问题交给下一次尝试修正。宿主还可以挂上运行前附加检查（`DraftCheck`，例如[工具锻造](./工具锻造.md)得到的检查）：运行器结构检查通过后再查一遍，发现的问题带 `[预检] ` 前缀记录，处理方式相同，且不计入能力缺口。多个检查按固定顺序组合（`DraftChecks`），问题依次合并，任一检查返回错误时不吞掉。
- **修正依据**：下一次草稿请求带着上一次的草稿、结构问题和实际运行证据，要求依据警告与探测实际值修正，已经正确的部分保持不变。

整次实践最长 15 分钟。

## 产物与运行的边界

草稿只能是纯数据文件。通用契约限制如下：
- 至多 8 个文件，单个不超过 8 KiB，合计不超过 24 KiB；
- 路径为相对路径，每段只含 `[A-Za-z0-9._-]`，不能是 `.` 或 `..`；
- 至多 8 项探测，每项由探测对象（小写字母、数字、`-`）、运行器声明的属性和期望值组成。

Mindustry 运行器在此基础上还要求：
- 根目录只有一个 `mod.hjson`，含 name 与 minGameVersion，且不得有 `main`、`java` 字段；
- 内容文件只能放在 `content/blocks|items|liquids|units/` 下，扩展名 `.hjson` 或 `.json`；
- 所有 `type` 只能是不带包名的类型名，行首、同一行 JSON 与嵌套对象中的都会检查；
- 不得包含 scripts 目录、`.js`、`.java`、`.class`、`.jar` 或贴图；
- 探测对象必须是本模组内容的完整名称。
- 物品、液体由所在目录决定类型，不填写游戏不识别的 `type: Item` 等字段；方块需要显式类型。新内容使用独特文件名，避免覆盖游戏原有内容而产生警告。

运行时的处理：
- **工作目录**：每次尝试使用状态目录下 `practice-work/<实践ID>/attempt-N` 的全新空目录，产物写入其中的 `config/mods/<mod 名>/`，运行结束即删除。
- **环境隔离**：子进程清空环境变量，只保留 PATH、JAVA_HOME（Windows 另保留 SystemRoot）；家目录与临时目录都指向工作目录。
- **资源上限**：最大堆 512 MB；启动 90 秒、查询 30 秒、退出 15 秒超时，超时即终止。
- **查询方式**：探测查询由运行器按已校验的标识拼出固定模板，只读取内容的存在、类型和字段，不执行草稿或模型提供的任何代码。

证据包含运行版本、退出方式（完成、超时、无法启动、中途退出）、是否加载并启用，以及启动阶段的全部警告和错误。每项探测都记录期望值、实际值和是否通过：数值按数值比较，布尔值不分大小写。日志摘录不超过 8 KiB，本地路径替换为 `<workspace>`；完整日志另记字节数和 SHA-256。

## 实践回写知识

独立的 `--strategy-learning` 可以从失败后修正成功的实践形成方法候选，经后续不同目标验证后晋升，效果退化时自动回退；它不额外请求模型，也不增加实践次数。详见[效果反馈与策略改进](./效果反馈与策略改进.md)。

研究得到的资料只说明来源这样写，并不说明照着做能成。每次草稿都要声明自己依据了哪些资料（`notes_used`，只能引用这次任务交给草稿器的资料），实际运行的结果就成了这些资料的佐证。

- **怎么计数**：按资料汇总引用它的草稿实际运行验证通过与未通过的次数，并记下最近一次通过的实践、尝试序号和运行环境版本。规则如下：
  - 只计实际运行过的尝试，即验证通过或未通过；结构检查不通过、不适用、草稿失败与中断的尝试不计；
  - 同一尝试重复引用同一资料只计一次；
  - 引用了没有交给草稿器的资料，不计。
- **含义有边界**：
  - 通过只说明引用它的草稿整体在运行环境中验证通过，不证明资料的每一句都对；
  - 未通过也可能是草稿其他部分有误，不据此否定资料；
  - 资料原本的来源状态（来源原文或未验证推测）不变。
- **用在哪里**：
  - **后续实践**：同一学习目标的新版本、由它派生的后续创作，都使用同一份知识。这些实践的草稿器拿到资料时，有实践佐证的排在最前，其次是来源原文，未验证推测在后。每条资料前标注"【实践佐证：引用它的草稿实际运行验证通过 N 次、未通过 M 次】"或"【引用它的草稿实际运行 M 次都未通过，可能有误】"。
  - **`/knowledge 兴趣ID`**：每条资料下显示"实践：引用它的草稿验证通过 N 次、未通过 M 次（最近通过：实践记录、尝试序号、运行环境版本、时间）"。
  - **对话工具 `list_knowledge`**：每条资料附 `practice` 字段（未开启实践时为 null）。
- **持久化**：这是派生数据，不单独保存，每次从实践记录重新计算，实践记录是唯一来源。实践记录的持久化、损坏与恢复规则不变，没有新增状态，也没有新的恢复语义。

## 持久化与恢复

实践账本 `eve.practice/practice.v1` 经公开 StateStore 保存，文件与 PostgreSQL 后端语义相同。它保存每次实践的任务、运行器声明、全部尝试的草稿（可复验的产物原文）、结构问题、运行证据和结论。

| 情况 | 行为 |
| --- | --- |
| 保存准入、草稿或证据失败 | 不执行下一项请求或运行；关闭账本句柄，下次打开读到实际提交结果 |
| 重启发现 Running 实践 | 记为 `Interrupted`，保留到达的阶段，不重放，不伪造完成时间；该修订不再实践 |
| 进程被强制结束时留下的工作目录 | 下次启动时整体清理；证据以账本为准，目录中没有需要保留的状态 |
| 草稿请求失败或输出不合规 | 记为 `Failed`（`Provider`、`InvalidOutput`、`Timeout`、`Cancelled`），不重试 |
| 服务停止或整次超时 | 终止运行中的进程，当前尝试记为放弃且结果未知，不补写证据 |
| 三次尝试都未验证 | 记为 `Unverified`，保留每次的证据 |
| 实践记录已满 64 条 | 停止新实践，不淘汰旧记录 |
| 账本损坏、有重复键、版本未知，或尝试顺序、结论与证据不一致（例如“已验证”却带警告） | 拒绝启动，保留原字节，不清空 |

实践不写认知状态，也不改写知识：知识的“来源原文”状态不会因实践而自动变化。实践次数持久计数，重启、重复事件都不会放大预算。

## 静态网页运行器

`--practice-browser` 让同一套学习、实践、技能与邀请流程用于另一个创作领域：只含 HTML 与 CSS 的静态网页。宿主不增加任何领域分支，只换运行器：
- **产物**：根目录必须有 `index.html`，其他文件只能是 `.css`，经相对路径的 `<link rel="stylesheet">` 引用。不得包含脚本、`on…` 事件属性、`javascript:`、`http(s):` 地址、`url()`、`@import`，以及 iframe、object、embed、form、base、img、svg、video、audio、source 等元素或 `src`、`srcset`、`http-equiv` 属性。
- **探测**：对象是 `index.html` 中元素的 id；属性可取 `exists`、`text`（合并空白后的文字）或 22 种白名单计算样式（如 `fontSize`、`color`），按浏览器计算后的值比较，忽略空白差异。
- **运行**：在全新目录写入产物，另生成一份末尾加入运行器自己探测脚本的页面，用 `--headless=new --dump-dom` 打开并读回结果。探测脚本只由已校验的 id 与属性拼成；草稿不能含脚本，所以页面中只有运行器的脚本。
- **隔离**：清空环境变量，只保留 PATH（Windows 另保留 SystemRoot）；家目录、用户数据目录与 TEMP/TMP 都在工作目录内。TMPDIR 保持系统默认，因为浏览器在其中创建单实例套接字，路径过深会无法启动。所有域名解析指向不存在，不访问网络；60 秒超时即终止。
- **输出与退出**：stdout/stderr 超出保存上限后仍继续读取，避免管道堵塞；超时终止并回收子进程，保留此前已收到的有限输出供诊断。非零退出记为中途退出，超时仍是不通过，不能因为已有部分 DOM 而算成功。
- **证据**：运行版本取自浏览器的 userAgent（如 `Chromium 141.0.0.0 (headless)`）；运行环境标识是浏览器程序的 SHA-256。样式表全部加载才记为已加载。没有取得探测结果时，日志摘录附上浏览器最后几行输出。

## 分层

| 层 | 内容 |
| --- | --- |
| `eve-practice-api` | 任务、运行器声明、草稿与探测、运行证据与“已验证”判定、尝试与结局；可替换的 `PracticeAdmin`、`PracticeDrafter`、`PracticeRunner`；纯函数 `validate_draft` |
| `eve-practice-plugin` | 持久账本与启动核对；`ModelPracticeDrafter`（一次无工具请求、严格 JSON、规则与领域无关）；串起草稿、结构检查、运行与修正的 `Practitioner` |
| `eve-practice-mindustry` | Mindustry 内容模组运行器：结构检查、工作目录与环境隔离、控制台协议、证据采集 |
| `eve-practice-browser` | 静态网页运行器：结构检查、工作目录与环境隔离、运行器自有探测脚本、证据采集 |
| `eve-app` | QQ 后台实践循环、`/practice`、参数校验；`run_qqbot_with_interest_components` 可替换草稿器与运行器 |

## 验收边界

- **确定性替身**：用 `connectors/qqbot/test/fake_mindustry.py` 模拟服务端，它按真实服务端的输出格式应答，只证明协议与恢复语义。
  - Rust 测试覆盖账本的阶段持久化、修正、用尽、不适用、放弃、中断与损坏处理，以及运行器的结构检查和替身协议。
  - 真实 `eve-qqbot` 进程测试 `practice_test.py` 覆盖：研究后实践、依据警告修正后验证、各阶段先保存、工作目录与家目录隔离、重启零重放、留出领域不适用、脚本被拒、草稿不合规、三次用尽、强杀中断后清理工作目录且不重放、默认关闭与参数拒绝。
- **真实运行**：CI 的“Mindustry 真实运行验收”工作流下载 v160.7 的 `server-release.jar`，校验 SHA-256 `f7b899a4…c0befd` 后运行两组验收。
  - Rust：正确模组验证通过；类型写错仍报告已加载，但因警告和类型不符判为未验证；引用不存在的物品时服务端报错退出。
  - `eve-qqbot` 进程：从一次普通聊天到真实服务端验证通过。
- **真实浏览器**：QQBot 离线验收工作流用 runner 上的 Google Chrome 运行 `eve-practice-browser` 的真实测试（正确页面通过、字号写错时给出实际值、引用不存在的样式表在检查中拒绝），以及留出场景 `holdout_test.py`。
- **未覆盖**：没有接入真实模型，草稿质量未经评估，也不是正式 QQ 体验验收。贴图、脚本和 Java 模组不在本切片范围内。技能固化见[技能固化与复用](./技能固化与复用.md)；主动邀请等 #134 其余步骤尚未开始。
