# 管理员绑定与管理权限

权限语义对齐旧 Eve `rules/RULE.md` 的 Authorization 段，并以当前宿主可信平台身份执行。旧包中的账号、路径和工具名不导入。昵称、自称、引用、历史助手回复不能授予权限。

| 身份 | 允许范围 |
| --- | --- |
| 主人 | 已装配的管理能力；可通过直接文件工具修改 AGENT.md、AGENTS.md、RULE.md、USER.md。仍受路径、配额、取消及通道限制 |
| 管理员 | 日常任务、部署、普通工作区操作、记忆和知识工作、定时与后台任务；身份规则文件的直接修改及私密凭据文件的直接操作只限主人 |
| 普通用户 | 正常聊天、Mindustry 问答、批准资料的只读查询和本会话状态查询；可取消自己已有任务。不能创建提醒、触发器、后台任务、子代理、修改工作区、操作 GitHub 或开启主动推送 |

旧规则中的代下载须经主人明确授权且不超过 500 MB。当前没有按次授权契约的通用文件发送工具不会因普通用户自称获得批准而开放；既有通道大小上限仍有效。

“默认放权”适用于已有授权的主人和管理员，不表示对普通群成员开放管理。开发后端 `ordinary_access` 默认 false；显式 true 也不能绕过 QQ 宿主的管理检查。工具定义、参数验证和具体后端路径、仓库限制继续生效；新增或未知工具默认按管理能力处理。

## 身份与绑定

主人由受信面板 `runtime.people.owner_principals` 配置，使用当前 QQ 会话主体。`owner_name` 只控制称呼。只有主人配置中的身份可获得 owner 标记；`/bind` 不能提升为主人。

宿主通过 `EVE_ADMIN_BIND_KEY` 提供管理员绑定密钥，不使用命令行参数，不将密钥交给模型。`/bind 密钥` 校验当前 QQ 平台身份，`/admin` 直接查询宿主判定，不请求模型。绑定标识为 SHA-256(AppID, c2c/group, 平台发送者 OpenID)，因此群聊绑定跨群有效；私聊和群聊身份分别绑定，不能通过相同昵称或 OpenID 字符串自动关联。旧 operators 会话标识继续有效。

绑定写入状态目录 `admin-bindings.json`，只保存版本和身份摘要。读取损坏、版本错误或写入不确定时显式失败，不清空、不自动重试。绑定容量 256，每个平台身份每分钟最多 5 次尝试；轮换密钥不撤销已有绑定。`/bind` 的持久回执脱敏，不进入训练、记忆或模型。

## 执行、恢复与投递

组合层给每个 QQ 工具加统一管理检查，后台和子代理复用同一工具服务；聊天管理命令同样检查身份。普通用户不能通过更换工具、命令、子代理或引用管理员话语绕过限制。身份文件和凭据限制是工具入口的规则；管理员的命令执行仍是受信宿主命令，不能当成操作系统沙箱。

触发器创建、后台执行前和主动消息投递前均重新检查当前授权。启动恢复时，普通用户旧有 Armed/Ready 触发器标记 Cancelled，保留条件、来源、原结果及历史；已完成但尚未发送的未授权触发结果记录投递失败，不发送。后台任务执行前授权失效则记录失败，用量为零，不请求模型、不运行工具。通道投递守卫覆盖提醒、后台结果和主动邀请，不把失败记成已送达。已发出的消息和未知回执不重放、不改写。

撤销权限不撤销已经发生的副作用。状态与管理员绑定损坏仍应停机核对，不自动重置。安全修复部署不能自动回滚到缺少管理检查的旧运行器。

## 验收

`connectors/qqbot/test/management_access_test.py` 使用真实 QQ 宿主和隔离模型、桥接，验证普通群成员伪称主人不能派发或排程、旧 ordinary_access=true 不能绕过、管理员与主人对身份文件的差异，以及撤权后旧触发器不执行、不发送。`admin_test.py` 保留绑定、脱敏与跨群身份验收。
