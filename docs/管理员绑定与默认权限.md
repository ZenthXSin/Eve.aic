# 管理员绑定与管理权限

权限语义对齐旧 Eve `rules/RULE.md` 的 Authorization 段，并以当前宿主可信平台身份执行。旧包中的账号、路径和工具名不导入。昵称、自称、引用、历史助手回复不能授予权限。

| 身份 | 允许范围 |
| --- | --- |
| 主人 | 已装配的管理能力；可通过直接文件工具修改 AGENT.md、AGENTS.md、RULE.md、USER.md。仍受路径、配额、取消及通道限制 |
| 管理员 | 日常任务、部署、普通工作区操作、记忆和知识工作、定时与后台任务；身份规则文件的直接修改及私密凭据文件的直接操作只限主人 |
| 普通用户 | 正常聊天、Mindustry 问答、批准资料的只读查询和本会话状态查询；可取消自己已有任务。不能创建提醒、触发器、后台任务、子代理、修改工作区、操作 GitHub 或开启主动推送 |

旧规则中的代下载须经主人明确授权且不超过 500 MB。当前没有按次授权契约的通用文件发送工具不会因普通用户自称获得批准而开放；既有通道大小上限仍有效。

“默认放权”适用于已有授权的主人和管理员，不表示对普通群成员开放管理。开发后端 `ordinary_access` 默认 false；显式 true 也不能绕过 QQ 宿主的管理检查。工具定义、参数验证和具体后端路径、仓库限制继续生效；新增或未知工具默认按管理能力处理。

## 身份与绑定

主人推荐由受信面板 `runtime.people.owner_accounts` 配置，填写 `/help identity` 的 `qq-account:` 账号标识；同一 AppID 的同一群聊账号跨群有效。旧 `owner_principals` 继续按原会话范围生效。`owner_name` 只控制称呼。只有主人配置中的身份可获得 owner 标记；`/bind` 不能提升为主人。

宿主通过 `EVE_ADMIN_BIND_KEY` 提供管理员绑定密钥，不使用命令行参数，不将密钥交给模型。`/bind 密钥` 校验当前 QQ 平台身份，`/admin` 直接查询宿主判定，不请求模型。绑定标识为 SHA-256(AppID, c2c/group, 平台发送者 OpenID)，因此群聊绑定跨群有效；私聊和群聊身份分别绑定，不能通过相同昵称或 OpenID 字符串自动关联。旧 operators 会话标识继续有效。

绑定写入状态目录 `admin-bindings.json`，只保存版本和身份摘要。读取损坏、版本错误或写入不确定时显式失败，不清空、不自动重试。绑定容量 256，每个平台身份每分钟最多 5 次尝试；轮换密钥不撤销已有绑定。`/bind` 的持久回执脱敏，不进入训练、记忆或模型。

## 自然聊天授权与急停

主人和管理员可以直接说“查看我的业务权限”“解锁当前会话全部业务权限”“撤销当前会话业务权限”或“立即急停当前会话并取消既有任务”。模型使用 `manage_business_permissions`，身份、精确会话范围和最近六条完整用户正文由宿主取得，工具参数不能提供身份、授权原话或确认标记。变更必须取得当前本人明确授权；后台与子代理不能授权。宿主完整核对最新正文为“急停”“立即急停”或上述明确撤销/急停句式时直接缩权并审计，保证审核模型故障时仍能停止；引用、否定、条件和疑问不会命中直接路径。其他表述和所有解锁通过行动审核。审核上下文超过上限时拒绝，不裁剪原话。

已有可信主人和管理员默认业务许可保持兼容。显式解锁允许使用全部已装配业务能力，具体动作仍经过敏感审核、预算、验证、路径和凭据边界；它不允许自行制造身份、关闭审计或绕过回滚。管理员可在显式解锁后申请固定自主预算，自主授权仍单独审核。

授权账本 `business-permissions.json` 保存精确作用域、签发人、签发时间、撤销时间、修订号、完整原话和审核回执；变更与审计原子提交并同步目录。初始化标记 `business-permissions.initialized` 防止丢失账本后回退默认许可。撤销与急停跨重启保留，不影响其他会话。旧授权原话不能在撤销后重放解锁，审核等待期间遇到其他授权变更也不提交旧结论。文件损坏、已初始化后缺失或原话摘要不一致拒绝启动，提交不确定则整个进程的业务许可失败关闭，保留文件供重启核对；容量达到上限时拒绝新变更，不自动清空或删除审计。

可信新正文明确要求缩权，但历史正文缺失时，不能补造“最近六条”授权证据；宿主保存 `business-permissions.failed` 故障标记，写明完整的新正文及历史缺口，本进程关闭业务，重启也拒绝恢复旧许可。需要可信维护核对原始消息与账本后处理故障标记，不能仅重启绕过急停。

急停先持久关闭业务并保存待取消标记，再取消本精确范围的后台任务、触发器和持续关注，分别报告取消请求和失败。启动在工作器激活前重试未完成取消；重新解锁也先核对原取消，未完成时保持急停，旧代取消回执不能清除新急停。已经开始的副作用可能完成，急停不声称撤回或回滚；新解锁不复活已取消任务。工具入口、开发后端、后台执行及主动消息投递重新检查当前许可。

主人还可以自然聊天查询管理员绑定并撤销指定可信绑定标识。撤销立刻影响当前运行进程，旧配置 `operators` 和旧绑定密钥不能覆盖撤销，重启后仍保留。该入口只能撤销管理员资格，不能变更主人身份；管理员标识来自可信目录，不能按昵称猜测。业务状态查询只返回当前范围，管理员目录仅向主人开放。

## 执行、恢复与投递

组合层给每个 QQ 工具加统一管理检查，后台和子代理复用同一工具服务；聊天管理命令同样检查身份。普通用户不能通过更换工具、命令、子代理或引用管理员话语绕过限制。身份文件和凭据限制是工具入口的规则；管理员的命令执行仍是受信宿主命令，不能当成操作系统沙箱。

触发器创建、后台执行前和主动消息投递前均重新检查当前授权。启动恢复时，普通用户旧有 Armed/Ready 触发器标记 Cancelled，保留条件、来源、原结果及历史；已完成但尚未发送的未授权触发结果记录投递失败，不发送。后台任务执行前授权失效则记录失败，用量为零，不请求模型、不运行工具。通道投递守卫覆盖提醒、后台结果和主动邀请，不把失败记成已送达。已发出的消息和未知回执不重放、不改写。

撤销权限不撤销已经发生的副作用。状态与管理员绑定损坏仍应停机核对，不自动重置。安全修复部署不能自动回滚到缺少管理检查的旧运行器。

## 验收

`connectors/qqbot/test/management_access_test.py` 使用真实 QQ 宿主和隔离模型、桥接，验证普通群成员伪称主人不能派发或排程、旧 ordinary_access=true 不能绕过、管理员与主人对身份文件的差异，以及撤权后旧触发器不执行、不发送。`admin_test.py` 保留绑定、脱敏与跨群身份验收。`owner_account_test.py` 验证主人跨群、新群重启恢复、群/私聊及 AppID 隔离、热撤销、同名无权限、旧绑定兼容和真实命令的宿主/成员边界。

`cargo test -p eve-app qq_business --lib` 覆盖完整原话、原话重放拒绝、审核期间撤销、跨重启许可、损坏与写入失败关闭、运行时撤销管理员，以及急停对真实任务和主体账本的精确范围取消。`cargo test -p eve-app qq_access --lib` 覆盖自然管理工具和个人主动消息设置的实际入口权限。
