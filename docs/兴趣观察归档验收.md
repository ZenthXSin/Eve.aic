# 兴趣观察归档验收记录

基线 main `2b05ecb5ceb65405d2a4d203db01ebf14dbb5026`。本切片独立于尚未合并的表达、经验投影和编程证据分支。仅本地隔离验证，尚未合并或部署。

## 问题与变化

旧账本把全部历史观察限制为 128 批，终态同样占据容量；QQ 首次遇到容量限制后永久停止观察。现在由 QQ 显式装配不可变归档，格式 2 的热层只保存 Running，所有终态保留完整原件及消费索引；旧格式完整校验后迁移，不重跑历史模型请求。

缺根但有归档或孤儿原件时拒绝初始化，未知提交关闭实例；新批次仍在模型请求前核对全部冷原件。空闲或冷却返回 None 时只核来源和已消费索引，零兴趣冷正文读取；这不代表冷库实时健康，也不消除原记忆扫描开销。容量限制后至少 60 秒复查，不自动清空或追加预算。Waiting 文字改为“等待后续推进”。

## 失败记录与修正

初次完整进程最后的聊天计数断言失败：旧夹具将历史摘要当聊天回显，实际为聊天 1、观察 1、摘要 2，第二次摘要是无效响应修复。改为明确分类与合法摘要后，实际共 3 次；迁移和零重放断言始终保留。首轮请求、状态、输出和失败日志未删除。

一次来源缺失负例自身违反记忆修订计数约束，提前被记忆层拒绝。修正为合法分页内缺失旧来源 ID，并先通过独立完整游标校验，再精确要求 Interest 返回 Conflict。首次严格 Clippy 报测试模块后仍有函数，将测试模块移至文件尾后通过；未以放宽断言或 lint 规避。

## 限制与发布边界

热任务 128、冷热合计 4096、根 4 MiB、单原件 128 KiB、文件目录 8192 项/512 MiB、来源元数据 262144 条，先达到的限制生效。没有无限容量或垃圾回收；物理磁盘不能预留。新观察提交与启动仍需线性校冷；普通空闲轮避免重复读取兴趣归档。

格式 2 不能直接换回旧二进制；完整备份必须包含根、记忆、归档、配置及相关认知状态，恢复不得重放未知副作用。既有升级检查未被宣称已覆盖新增目录，本批只交 PR，发布前还须核对完整备份与候选启动流程。详见[归档与恢复](./兴趣观察归档与恢复.md)。

本地替身证明链路与持久化，不证明真实模型会产生合格兴趣或正式知识，也不证明自然分条、聊天风格或蒸馏增益。没有改变模型、提示词、缓存参数、个人资料投影、原文访问边界或 Magpie。Issue 438 属于另一套语义摘要账本，不由本切片关闭；Issue 197/134 也尚未整体验收。
