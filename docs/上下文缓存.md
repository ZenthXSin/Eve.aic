# 上下文前缀与缓存

主对话按固定系统提示、排序后的工具清单与宿主资料、完整历史、动态记忆和修订、当前输入组成；轮内按原顺序追加调用和工具回执。时间、身份来访统计和工作集保持在历史之后。

完整历史同时满足现有轮数和字节窗口时，规划器直接保留全部完整轮次，不因本轮问题变化重选旧历史，也不请求相关性选择器。新轮次只追加原始消息，纠正过的原文仍按最新历史读取，不缓存旧正文。这样可能比旧版选取更多历史，但不提高窗口或模型上下文预算。超限时继续使用既有相关性选择、完整轮次边界、来源查询和压缩路径，不承诺超限后的前缀连续。

偏好提炼和情景摘要只改变模型输入中的对象字段顺序：先给作用域和提炼器版本，再给证据或来源与上次摘要，最后给批次号、时间和修订等易变元数据。全部字段、值和输入长度保留，反序列化仍得到原批次；持久化 JSON、归档、去重、修复、撤销及校验规则不变，不需要数据迁移。说法学习本来只发送 messages，进度请求也不加入主对话历史。

缓存诊断分为本地前缀重复估算和提供方报告的命中用量；前者不证明上游存在缓存，缺失缓存字段也不能认定为真实未命中。缓存token超过输入token的异常用量同样标为未报告，不截成100%命中；服务明确报告零命中则正常计入分母。OpenAI Chat/Responses 现按宿主绑定发送显式 `prompt_cache_key` 和会话请求头，按用户、用途与独立任务隔离；此契约不保证中转站或后端模型实际命中，不补造缓存 token、不改变计费、供应商或模型。标识来源、旁路协议、重试和恢复边界见[模型会话与缓存隔离](./模型会话与缓存隔离.md)。

交流学习请求同样先保留作用域和完整原话，把旧经验、反馈配对、批次编号和重试计数放在后面。重试或新批次元数据变化不会先打断证据正文的可复用前缀；全部字段和值保持不变，持久化格式不变。

当前真实模型验收使用 `gpt-6.1-sol`、`medium`，目标为全请求的服务商缓存输入 token / 输入 token 至少 85%；冷启动、后台学习和重启均保留在统计范围。稳定期与各用途可以另报，不能替代总指标。`scripts/conversation-model-acceptance.py --model gpt-6.1-sol --reasoning-effort medium --min-cache-hit-rate .85` 记录门槛；缺少缓存字段标为 `unverifiable` 并返回非零，不能算通过。保持交流质量、原话完整性和实际延迟，不通过重复填充提示提高比例。

回归核对换话题与追加历史时的原文前缀、精确字节边界、超大最新整轮拒绝、窗口溢出相关性退路、跨作用域原始记录读取，以及批次字段完整性和元数据变化后的重复正文前缀。实际进程验收使用会话副本、本地模型与 QQ 桥接替身；只能证明宿主组装与恢复，不代表付费上游缓存命中率。
