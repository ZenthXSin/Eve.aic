# 宿主内存测量

这里记录进程内存，不是模型 token。当前数据来自 Linux debug 构建，固定共享 target、两个构建任务、debug=0、incremental=0；基线提交为 `64f42b9`，优化补丁在同一工作区和配置测量。样本只连接本地模型和平台替身，不连接正式 QQ。

| 固定样本 | 优化前 | 优化后 | 含义 |
| --- | ---: | ---: | --- |
| 64 脚本版本、每版 128 KiB、八 scope，进程峰值 | 51,064 KiB | 35,316 KiB | 下降约 30.8%；账本均为 8,423,468 字节 |
| 同样本 64 版本阶段 VmRSS | 43,132 KiB | 27,348 KiB | 阶段采样，不是峰值 |
| 同样本重启后 VmRSS | 35,664 KiB | 27,504 KiB | 重启仍核验全部版本 |
| 6 MiB 模型响应提取 usage 的进程 VmHWM | 16,696 KiB | 10,632 KiB | 仅用量提取，不代表整个 HTTP 请求峰值 |

脚本事务只消除一次全账本复制与整份哈希序列化缓冲。独立事务候选仍保留，JSON 校验字节不变；旧版本、回执、CAS、Unknown 与工具步数上限均不变。账本仍全量常驻，这不是冷存按需加载。

模型用量提取通过结构化反序列化只保留 `usage` 字段，跳过 `choices/output` 的重复内存分配；之前的严格响应协议校验保持。未知字段依然必须是有效 JSON，原响应正文未截断；重复 usage 键保留旧 Value 解析器的最后一项覆盖语义，false/null 与坏 JSON 的结果也保持一致。固定响应为 6,291,551 字节，输入与输出 token 字段校验结果相同。

## 独立测量

- `memory_profile` 示例：64 个版本逐次发布、激活，关闭并重启；源码与数据只在本样本临时目录。峰值由独立子进程的 `getrusage(RUSAGE_CHILDREN)` 记录，耗时 28.76/28.79 秒。
- `rust_memory_profile` 示例：八 scope、32 次真实隔离 Rust 编译、激活及执行。流式哈希补丁后宿主峰值 11.24 MiB，32 项缓存 VmRSS 8072 KiB；编译和链接子进程合计峰值 142.63 MiB。耗时 42.45 秒，测量器在剩余磁盘低于 64 MiB 时停止新增编译；本次未触发，临时缓存已清理。没有修前对应样本，不声称 Rust 缓存降幅。缓存保留的是路径与磁盘产物，不能当作 32 份常驻二进制。
- `cargo test -p eve-llm-openai --lib large_response_usage_memory_profile -- --ignored --nocapture`：独立进程中的大响应 usage 读取，打印处理前后的 VmRSS/VmHWM；非 Linux 不提供这两个指标。
- 真实 QQ 宿主 76 轮、多 scope、原始档案引用与重启基线：第一进程峰值 104.0 MiB，退出前 20 个采样平均 102.9 MiB；重启进程峰值 90.1 MiB，末段平均 85.9 MiB。递归子进程峰值另为 123.2/117.7 MiB。此长程样本尚无同场景优化后对照，不能用上述局部改进比例外推。

主进程与子进程峰值分别记录，不能相加声称是同时总峰值。退出前采样平均不等同于静置空闲内存。分配器、操作系统与样本大小会影响数值；Windows 内存表现尚未实测。后续冷账本、Session 快照副本和召回加载应继续使用独立基线及相同样本验证，不能以删原文、减少工具步数或弱化 scope 校验换取占用下降。
