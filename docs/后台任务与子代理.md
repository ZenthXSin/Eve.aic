当前默认后台和子代理按共享步骤结束，不设独立总时长截止；原授权期限、旧任务已保存的截止、单次调用超时、取消和有限恢复继续生效。详见[运行额度选择](运行额度选择.md)。

# 后台任务与子代理

Eve 在对话里遇到需要多步、较长时间的事，可以自己决定派发到后台去做，做完私聊告诉用户；也可以把一件子任务委托给子代理，在同一轮里等它把结果交回，再继续回复。派发由聊天模型调用工具完成；错误恢复任务的追加预算须由用户在原会话用命令明确同意。

## 启用

```bash
./target/debug/eve-qqbot --state-dir .eve-qqbot --background-tasks --subagents
```

- `--background-tasks`：派发、查看、取消后台任务，以及后台执行与结束通知。
- `--subagents`：子代理工具。
- 两者默认关闭，可以只开一个。全功能体验（`training-window.py --profile full`）两者都开。

## 执行器

后台任务和子代理用同一个执行器：

- **独立的模型宿主**：系统提示与对话相同（AGENT.md），另加执行规则；最终回复先保存为实际输出，只有执行前冻结的验收条件通过才能报告任务完成。
- **工具**：后台执行者使用对话普通工具与宿主自检 `echo`，开启子代理时可调用 `run_subagent`；开启条件触发后可以用受限的 `register_task_wait` 登记当前任务的技术等待。仍不提供再次派发后台任务、通用触发器管理或角色管理。叶子子代理排除全部编排工具，不递归派生。
- **上下文可选**：默认只收到任务说明；显式设置 `include_context=true` 时带当前完整模型上下文冻结快照（含既有压缩摘要，不读取窗口外原文），作为历史 JSON 数据，不重放其中的工具。工具按派发者的可信会话范围执行，例如读取这位用户的记忆。
- **模型用途 `task`**：单独记模型健康，单次输出上限可在 `runtime.model_uses.task_max_output_tokens` 设置。不计入自主运行预算：这是用户（经 Eve）要做的事，不是后台自主学习。

### 步数预算

一步是一次工具调用，失败、被拒绝和并行批次里的每个调用都计数。

- 派发或委托时，模型可以给 `max_steps`，不给就用配置的默认值（初始 **100**）。
- 超过配置上限的请求直接拒绝，不保存。
- 步数用尽后宿主不再提供工具，再请求一次，让模型依据已有结果收尾，说明哪些没做完；若仍返回工具调用，仅再尝试一次独立的只读进度汇报，两批都不执行。自动恢复不补充工具预算，模型请求累计保存；检查点还限制宿主模型请求总数为步数加 16（不等同于 Provider 内部的网络重试次数）。
- 下一批调用超过剩余步数时整批不执行，与对话的 100 次上限规则相同（见[工具上限与途中进展](./工具上限与途中进展.md)）。

### 配置

命名空间 `runtime.tasks`，在 Web 面板的配置页修改，保存后下一次派发或下一轮执行生效：

| 字段 | 默认 | 范围 | 环境变量 |
| --- | --- | --- | --- |
| `default_steps` | 100 | 1–5000 | `EVE_TASK_DEFAULT_STEPS` |
| `max_steps` | 5000 | 1–5000 | `EVE_TASK_MAX_STEPS` |
| `max_running` | 2 | 1–8 | `EVE_TASK_MAX_RUNNING` |
| `task_timeout_ms` | 1800000（30 分钟） | 10 秒–2 小时 | `EVE_TASK_TIMEOUT_MS` |
| `subagent_timeout_ms` | 180000（3 分钟） | 5 秒–10 分钟 | `EVE_SUBAGENT_TIMEOUT_MS` |

`default_steps` 大于 `max_steps` 时配置无效：保存被拒绝；启动时由环境变量造成的话，宿主拒绝启动。

## 后台任务

### 对话里怎么成立

| 工具 | 参数 | 作用 |
| --- | --- | --- |
| `dispatch_background_task` | `title`（单行、≤120 字节）、`instructions`（≤8192 字节）、可选 `max_steps`、`include_context`（默认 false）、`verification` | 原子保存排队任务、原话和验收合同，返回任务 ID |
| `list_background_tasks` | 可选 `task_id` | 列出这位用户最近 10 个任务，或查看一个任务的完整结果 |
| `cancel_background_task` | `task_id` | 取消这位用户自己的任务 |

- 先保存再回复：账本保存成功，工具才返回，模型随后告诉用户已在后台处理。没有成功就不能这样说。
- 对话上下文 `eve.background_tasks` 列出这位用户进行中和一天内结束的任务，最多 5 个，带状态、用掉的步数和结果预览。用户问起时模型据此回答，要完整结果再调用查看工具。其他用户看不到。
- 群聊里也可以派发；结果仍私聊通知派发者。

### 执行前冻结验收

`verification` 由派发者依据完整目标提供，执行者不能在看到结果后更换条件。`kind=receipts` 的 `contract.checks` 绑定工具名、完整参数、回执 JSON pointer 和期望值，且 `require_final_batch=true`；所有检查必须在最后一个工具批次真实执行，不能先验证再修改产物，或混入未绑定的并行动作。`echo`、`task_progress`、再次委派及模型自报完成不能充当验证。宿主逐项核对真实回执；合同只证明其中明确覆盖的行为，不能把单个检查扩大成整个项目成功。

`kind=text` 仅用于纯文本产物，可以要求 `required_fragments`、`json_equals`、`valid_json` 和 `json_required_pointers`；执行器不提供工具。文本匹配不能证明文件写入、部署或消息发送。缺少合同的新任务保留为待核验，不能因最终答复非空而完成。子代理也采用同一规则，返回 `completed=false` 时由父执行者继续核验与整合。子代理工具另携带真实 `verification` 分类与原因：没有固定合同或证据暂时不可核验时为 `status=returned_pending_verification`、`blocked=false`，不表示目标完成；观察不符为 `status=verification_mismatch`，不能假称通过。只有真实 `task_progress`、剩余工作或明确阻塞才是 `status=blocked`、`blocked=true`。执行器内部的停止状态不替代这些分类，原始输出、用量与工具回执都保留。

固定条件与观察不符时，只有检查点安全、原工具预算和原期限尚足够才自动继续同一任务；网络恢复、重启接续和验收修复共用最多三次恢复额度，不重新派发来增加预算。修复通知、原合同、全部旧回执和累计用量一并持久化；待修复时重启不重复扣次数，也不重放已完成操作。明确等待用户、未知副作用、缺失已执行回执、预算或期限用尽均保留真实状态。最终文本已保存但结局未提交时，重启仍执行相同的验收规则，不能跳过检查直接完成。

QQ 的回执合同还校验真实观察字段：完整文件 SHA256；内容对比须同时绑定完整摘要和未截断状态；明确受限测试命令的真实退出码；已有投递编号对应的实际送达状态。任意命令打印、参数回显、发送排队均不能代替完成回执。固定测试命令退出成功只证明该命令的结果，不证明测试覆盖了目标之外的要求。支持明确固定 `cwd` 与完整参数的 `cargo test/check/clippy`、`python3 -I -m unittest`、`node --test`（可跟明确的 `.js/.mjs/.cjs` 测试文件）及 `npm test`、`npm run test`。npm 后可用 `--` 转发明确测试文件或关闭 watch、单进程测试等受支持参数，不能用 `--if-present`、列举测试、帮助或任意脚本执行绕过验证。npm 实际运行工程中的测试脚本，退出码不证明测试数量、覆盖率或脚本安全性；契约不会扩大原命令权限，安装和其他脚本入口仍不作为验收。

### 自行登记技术等待

后台任务可以单独调用 `register_task_wait`，登记当前工程内的文件变化或某个真实进程实例退出；开启 `host_filesystem` 的可信操作者也可用绝对路径等待工程外文件。固定验收合同的文件路径和测试命令目录支持相同写法，实际工具仍逐次核验权限。工具的任务编号和身份来自宿主，模型不能选择别的任务或增加预算。保存成功后，将回执的 `remaining` 原文交给单独一次 `task_progress(status=blocked)`，再结束当前轮次。宿主等实际条件满足并核对最后两条配对回执后接续原任务；随后追加工具、改成等待用户决定、工具结果未知或授权失效都不能自动恢复。

等待条件、进程实例、原任务和来源同时保留在持久账本。条件可以先就绪，等待后台保存 `Blocked`；重启后仍使用同一任务、同一验收条件、原授权原话、原步骤额度和最早截止时间。无原截止的等待最多保留七天。登记成功不表示条件已经成立，也不表示原目标完成。

### 执行与通知

1. 后台每 0.5 秒检查一次，按派发顺序取排队任务，同时至多 `max_running` 个。
2. 先保存“执行中”，再开始执行；结束后保存结局、结果与用量（步数、模型请求数）。超过 `task_timeout_ms` 记为失败。
3. 完成、失败与中断的任务各有一条结束通知：主动发送至多一次，发不出去时仍可随用户下一条私聊补充。实时对话先完成当前回复，再把同一会话的待通知结果交给 Eve 自己决定是否表达及怎么说；补充只使用真实入站消息剩余的被动窗口和额度，见[自主发言](./Eve自主发言.md)。旧兼容通道继续直接附带固定通知。结束 7 天仍未送达或尝试满 6 次，记为过期，不再通知；unknown 不重发。
4. 用户取消：排队中的直接取消；执行中的先记下取消请求，后台停下执行器，再以“已取消”结束。已经做了的操作不撤销。用户取消的任务不再通知。

调度循环自身使用 `TaskAdmin.scheduling_snapshot` 的完整轻量目录，只有编号、完整身份、来源、创建/结束时间、状态、取消标记和恢复计数/时间，不包含任务说明、委派上下文、检查点或结果。原生实现直接读取账本元数据；旧自定义实现可用默认的完整快照转换。目录错误或重复编号停止本轮调度，不当作空目录。此管理能力仅交可信宿主，不作为聊天工具公开，元数据本身也不构成用户授权。

开始任务仍先持久化 Running。安全接续先按完整身份读取单个任务，核对编号、来源、创建记录及最新取消/恢复状态，再执行；结算只读取正在运行的目标记录，不恢复全任务正文。原排序、共享预算、绝对期限、准入优先级和关闭取消规则不变。策略结算和通知适配仍有各自的完整快照读取，当前改动不代表所有后台路径都已按需装载。

对话中的后台任务卡片同样先筛选轻量目录，再逐条按完整身份读取最多五个目标、生成原有小预览并释放正文。保持原可见规则：仅当前用户，恢复任务限原会话，普通任务的同用户跨会话显示保持兼容；进行中和一天内结束的任务按最新创建顺序显示。其他用户、过期和未选中的正文不读取。目录与正文身份、来源或创建记录不符，或后续读取失败，拒绝整组卡片；合法回收后已不存在的记录跳过，不借用其他身份或旧缓存。此入口不改变原始账本、任务权限和执行预算。

### 限制

- 每位用户同时排队或执行中的任务至多 4 个，24 小时内至多派发 20 个。
- 账本至多 128 个任务。满了时删除最早了结的一个（已结束且通知已了结）；进行中和通知未了结的从不删除。
- 结果至多保存 16 KiB，失败原因至多 512 字节，更长的截断并注明。
- 私聊通知受通道的 2048 字节上限约束，截断部分可以让 Eve 查看完整结果。

## 错误自动转后台

启用 `runtime.tasks.auto_recover_failures=true`（环境变量 `EVE_TASK_AUTO_RECOVER_FAILURES=true`，默认 false）后，已授权操作者的前台任务在错误结束且失败记录已保存时，自动派发一条恢复任务。`--no-error-recovery` 可作为兼容兜底，仅停用新的自动交接，继续读取任务账本、执行既有后台任务和处理原会话的追加批准。每条恢复任务最多 100 次工具调用，受 `max_steps` 的更小上限限制。派发成功才在原失败提示中返回任务 ID；同一会话和失败轮次的来源确定，同一次失败不会重复派发。

模型超时、服务拒绝或配置错误发生在任何工具启动之前，且没有工具回执时，不再派发后台恢复任务。前台模型已有原期限内的有界重试，转后台不能修复同一个模型服务，反而会重复复制历史、消耗任务存储。原始请求和失败记录继续保存在会话中，之后可接着处理；重启不补派这些失败轮，也不删除已有任务。已经执行工具并保存可核验回执的任务继续按原恢复规则交接。`auto_recovery_test.py` 以实际进程覆盖超时、HTTP 400/503、重启保留，以及真实命令执行后超时仍能交接且不重跑。

恢复上下文包含原任务、已验证的历史摘要和未覆盖历史、失败类别及已确认的工具回执；总计超过 16 MiB 时明确拒绝，不静默截断。工具额度用尽不属于自动交接条件：先走宿主的无工具收尾和只读进度汇报，不创建新任务绕过 100 步额度；汇报不受此处委派快照的 16 MiB 限制。后台以原身份和权限执行，不能继续派发后台任务或形成恢复链；可在同一个剩余预算内委派叶子子代理。取消、结果提交未确认、工具回执缺失、工具超时或其他未知副作用不自动交接。任务数量、每日派发量和存储上限照常生效。

100 步仍未完成时，停止执行、保留检查点，并向**原会话**发送剩余工作和 `/tasks approve 任务ID` 申请。只有原会话的授权用户发送该命令后，才创建最多 100 步的接续任务；接续数据包含上一阶段已执行调用与回执，仅作为历史，不重放操作。重复批准同一个父任务只返回原接续任务，不重复追加。后台执行者不能批准自己的预算。

结果已保存、预算仍不足而结局尚未提交时重启，保持“待追加步数”语义，不误报任务完成、不补充步数。数据仍使用任务账本格式 2，未增加字段或清空旧记录。自动恢复任务的结果和申请按原会话路由；普通手动派发任务继续沿用原先的私聊通知方式。主动发送失败时保留真实投递状态，不改投其他会话。

## 子代理

| 工具 | 参数 | 作用 |
| --- | --- | --- |
| `run_subagent` | `task`（≤8192 字节）、可选 `agent_id`、`max_steps`、`include_context`（默认 false） | 执行一件子任务，结果作为工具结果交回当前这一轮 |
| `list_subagent_runs` | 可选 `run_id`、`offset`；指定 `run_id` 时可用 `evidence=true` | 只读查询当前会话子代理记录；显式证据查询返回冻结检查的历史真实回执摘要 |

- 子代理须在 `subagent_timeout_ms` 内做完，超时或失败时工具返回原因，由模型如实告诉用户。对话宿主把这个工具的执行期限放宽到配置上限（10 分钟）加 10 秒，其余工具的期限不变。
- 群聊的被动回复窗口约 5 分钟，子代理期限调长会有回复送不出去的风险；更长的事应派发到后台。
- 本轮被取消时子代理一并停下。
- 委派本身计一步，子代理的全部调用继续扣父任务共享池；缺省继承剩余步数，显式 `max_steps` 只能收窄自己的上限。角色与恢复格式见[子代理角色与共享预算](./子代理角色与共享预算.md)。
- 子代理不进入后台任务账本；宿主另行持久保存原 run、冻结条件、检查点、真实回执和结局，结果同时作为当前轮工具结果交回。重启可查询原记录，查询不自动恢复或重跑子代理。

`run_subagent` 正常返回自动附带 `receipt_evidence`，让父执行者无需额外工具或模型调用即可取得历史检查摘要。之后可用 `list_subagent_runs({run_id, evidence:true})` 读取同一简表；该模式必须指定 `run_id`，不能同时传 `offset`。简表区分 `historical_match`、`historical_mismatch`、`missing` 与 `unknown`，带固定的 `run_status` 和不含原因正文的 `verification` 分类；保存状态与生命周期或检查点不一致时显示 `inconsistent`，原记录保留。简表不带原任务、消息、步骤或最终结果正文，明确 `current_artifact_validity=not_checked`，不证明当前产物仍有效，不改变旧合同的最后批次要求，也不直接完成父任务或触发补跑。自动附带摘要读取失败时返回 `report=null` 和固定缺口原因，原子代理结果仍保留，验收状态不升级。不加 `evidence` 时原查询返回保持兼容。当前接通范围及剩余工作见[验收证据复用](./验收证据复用.md)。

## 持久化与恢复

后台任务账本是 `eve.task` 插件的 `tasks.v1`。QQ 默认装配格式 4 冷索引及状态目录中的 `task-archive`，字节压力下按需升级为格式 5；未装配归档的替换宿主继续使用格式 2（存在 Blocked 任务时格式 3），兼容读取旧格式 1。运行工作集按原编码计算至多 16 MiB，上下文、检查点、单条正文、冷索引仍各受原 16 MiB 上限保护，收尾预留和任务数限制保持。

格式 5 为每项显式保存布尔 `archived`。仅当整个候选超出运行工作集字节预算时，按结算时间及任务 ID 顺序，把 `settled_at()` 有值的记录转为历史；目录、完整正文、摘要、来源、身份、创建时间、进度与结束通知一并保留。新任务可以在未达 128 条时释放已结算正文的工作集占用，来源去重、每日创建数、进度额度以及 subject/strategy 的原任务证据仍能读取历史。探索只有独立经历已经确认后才可转为历史，不要求目标、收益或成果。排队、运行、通知或进度未结算、探索经历未确认的记录不能归档。

运行与历史的全部冷正文引用合计最多 64 MiB，目录仍至多 128 项；达到条数上限时原先的已结算淘汰与最近二十四小时进度保护保持，不扩大删除范围。历史保留不是无限的。显式复活或修改归档任务先取消归档位，重新通过工作集检查；仍已结算的更新结果可再次入历史。写入按未结算任务的最大收尾正文 `M` 准入，并为每项保留 `2M−当前长度` 的物理空间，覆盖增长与整批恢复替换；结果转义、通知回执和严格任务修复消息也计入。全部容量和索引检查先于本批第一份正文写入。细节见[任务工作集与历史归档](../crates/task-plugin/WORKING_SET.md)。

任务插件首次打开全新状态时，先提交合法空账本，再写同一插件命名空间的 `tasks.initialized.v1` 初始化标记；旧账本完整校验后补标记，未发生恢复时不改写原账本。已有标记而账本缺失、标记损坏或账本损坏都拒绝启动，保留原始数据，不当空库重建。初始化及补标记保存失败也不返回可用控制器。

这两个键没有跨键事务：只有已提交的合法账本而尚无标记时，下次按旧账本完整核对后补齐标记；标记不会先于新空账本提交，避免制造只有标记的初始化中间态。恢复 Running/Delivering 按原状态规则构造整批候选，统一预检后一次提交索引，不重放未知操作。备份应保留整个 `eve.task` 命名空间；如果账本和标记同时丢失，无法仅靠这两个键区别全新存储与整组丢失，不宣称能检测这种情况。

新增和变更采用借用的完整任务序列编码：变更只复制目标任务，其余任务的上下文与检查点不再随整本账复制；编码预算扣除进行中任务的收尾预留，超过预算立即停止，不先生成整份超额 JSON。只有后端确认保存后才替换内存记录；提交错误可能已生效，整个管理句柄关闭，须重开核对实际记录。容量不足属于提交前拒绝，保留旧字节且句柄仍可使用。

执行检查点校验借用已有消息检查协议，不复制完整消息；大小校验按 JSON 实际转义后的 UTF-8 字节流计数，不再生成整份 JSON 副本。原 16 MiB 上限保持，恰好上限可接受，多一个字节拒绝。待执行调用、回执配对、共享步数、模型请求数、版本和恢复安全检查均保持原规则，不因减少分配而放宽校验。

QQ 现在把完整任务写为不可变 SHA-256 冷文件，索引与内存只留目录和通知元数据，不携带委派上下文、恢复检查点、结果和失败正文；任务说明仍用于目录。完整读取、显式全快照和冻结证据视图才恢复需要的正文。目录本身不是完整 Task，不能拿它覆盖冷正文。未装配归档的替换实现保持旧路径；底层 StateStore 仍可能复制其他状态，兼容全快照仍可读取全部任务，不宣称整版恒定内存或全功能 RSS 降幅。

格式 4/5 启动逐条完整核对全部冷文件、摘要、大小、目录绑定和原有任务约束，格式 5 另核归档资格及实际工作集/全部引用上限。随后暂存所有变化的完整恢复候选，整批预检后才写正文；末条损坏或整批超额不会先写前面的任务。最大收尾正文与物理预留属于写准入，原合法状态仍可只读打开。旧格式第一次迁移完整读取旧账，先保存冷文件，再提交冷索引，确认后才切换内存。格式 4 没有字节压力时不改写为格式 5，已有格式 5 不自动降回格式 4。缺失、损坏或提交无法确认时关闭句柄并保留原文件，重开核对，不自动重放。

文件归档持有目录独占锁，最后一个所有者释放；该目录只能供同一个任务索引使用。索引确认后才回收无引用且摘要有效的标准旧正文；历史仍被引用，不会回收。确认未知时保留新旧文件；提交后清理前崩溃留下的正文，在下一次容量预检不足时先按已确认索引验证并回收，再做整批预检。未知名字、链接、备份和损坏现场不删除。回收失败不能撤销已确认的结果。64 MiB 物理配额按平面目录条目的 symlink_metadata 长度计量，最多 8192 项，不递归计子目录，也不等于整个磁盘空间；外部填盘或 I/O 故障仍可能拒绝后续写入。替换归档须实现真实物理预检，默认不支持，不能假装有收尾空间。

备份必须在停写或一致性快照下同时保留整个 eve.task 命名空间、初始化标记和当前 task-archive，包括格式 5 的全部历史引用。只识别格式 4 的旧二进制拒绝格式 5；首次启用格式 5 不支持旧二进制普通自动回退或便携发布回退。当前 Linux 路径限定为新版完整配置、同一二进制与脚本的最小恢复配置、停止；旧快照不能覆盖上线后已产生的新回执。

- **先保存再执行**：派发、开始、结束、取消与每次通知尝试都先保存，再执行或回复。
- **幂等**：任务 ID 由派发者和来源派生。来源取会话、轮次与这次工具调用 ID 的摘要：同一次调用重复执行时返回原任务；模型在不同轮次复用调用 ID 也不会误认成旧任务。
- **重启**：
  - 新任务在每个模型请求前、工具批次执行前后以及最终结果产生后保存检查点；工具回执已配对且无未知副作用时，重启后自动接续原任务；
  - 结果已保存而结局未提交时，直接了结并通知，不再请求模型；
  - 旧执行中任务没有检查点、工具执行在途或回执异常、恢复次数或总期限已用尽时，记为“已中断”并通知，须先核对，不能盲目重派；
  - 已请求取消的执行中任务记为“已取消”；
  - 排队中的任务重启后照常执行；
  - 发送中的通知记为结果未知，不重发、不随回复附带。
- **关闭**：正常关闭时停下执行中的任务。它们留在“执行中”，下次启动按检查点安全接续或明确中断。
- **有限恢复**：临时网络故障、模型超时、HTTP 5xx/429，以及安全边界上的服务重启，合计最多自动恢复 3 次，依次等待 2/4/8 秒。原任务 ID、已用步数、模型请求数、task_progress、调用 ID 和首次执行的总期限都保留。鉴权失败、配置/协议错误、用户取消、未知工具结果不重试；每次恢复前重新检查管理员身份，当前提示与工具清单重新装配。
- **回滚**：旧二进制不能读取新格式，部署时禁止自动降级到旧二进制；保留备份用于人工核对，不能用旧备份覆盖上线后产生的回执。
- **严格读取**：重复键、未知字段、版本不符、ID 与派发者及来源不一致、状态与字段不一致（例如已完成却没有结果、用量超过步数）、通知尝试不一致时，宿主拒绝启动，原字节保留，不清空。
- **写入失败**：提交可能已经完成，也可能没有。实例关闭：工具返回失败，后台执行结束并停止通道准入，重新启动后按账本核对。
- **容量**：单份上下文或检查点上限 16 MiB；账本总上限 16 MiB，保存检查点也占空间。派发时预留最终结果空间；新快照或检查点放不下时明确失败并保留旧数据，绝不截断检查点或在未确认保存后继续执行工具。

## 分层

任务默认在派发三十分钟后产生进度提醒，同一完整会话身份两次认领至少间隔三十分钟、滚动二十四小时最多四十八次。提醒不调用模型，根据当前账本区分排队、执行器已接收、等待自动恢复、已停止待条件与取消；没有活执行句柄证据时不宣称“持续运行”。同一次阻塞只提醒一次，恢复后再次阻塞按新的终止时点处理。QQ 仅认领原 `qq:` 会话，复核业务权限、管理员身份和主动交流 quiet 偏好，间隔与配额在任务账本内持久核对，实际发送另受通道轮询间隔与连接器共享出站并发上限约束；Web 使用独立的持久收件箱。

进度提醒独立存于 `TaskExecution.progress_notices`，不把运行任务改成终态，不覆盖完成通知。发送之前原子保存序号、观测状态、时间和发送尝试，平台消息编号确认后才记录 Sent；缺少消息编号或网络结果不确定记录 Unknown。重启发现未结算尝试也记为 Unknown，并冻结这个任务后续进度提醒，终态通知仍按新事实独立结算。每个任务保留最近四十八条进度回执，序号不回退；旧数据缺少该字段按空数组读取，缺少执行记录的旧任务不会自动启用提醒。投递中记录以及最近二十四小时有进度发送的任务不会被容量回收，避免回收绕过出站预算；持久化无法确认时关闭句柄，不能继续发送。

本地 Web 收件箱先以稳定通知 ID 完成幂等写入，再以完整任务身份和进度序号记录 `LocalInbox/StoredLocally`，不冒充 QQ 平台 Sent。写入两份状态之间重启，只补结算原通知，不新增通知；任务在这期间结束也保留实际本地收件回执。任务冷目录只保存上述有界元数据，正文仍按不可变摘要核对读取。

- **定义层**：`eve-llm-api` 提供 `TurnCheckpoint` / `TurnJournal`，`eve-task-api` 规定任务、状态、用量、通知与 `TaskAdmin` 契约。
- **实现层**：`eve-task-plugin` 提供持久账本。
- **运行时**：`LlmHost` 提供：
  - 冻结工具批次前的当前消息，显式委派时可共享；
  - 注入持久日志并从安全检查点恢复（`with_turn_journal`）；
  - 按工具名覆盖执行期限（`tool_timeout_overrides`）；
  - 单次执行的工具调用上限（`with_tool_call_limit`）；
  - 不经会话服务、按给定可信范围执行一轮（`run_scoped_turn_with_events`），事件接收端关闭即取消。
- **组合层**：QQ 宿主提供执行器、四个对话工具、`eve.background_tasks` 上下文、后台执行、通道投递适配与 `runtime.tasks` 配置。

## 已知限制

- 执行一次期间，执行器与对话一样持有内核的运行准入。操作者在面板里启停插件时，生命周期操作要等进行中的轮次结束，排队期间新的对话轮次也会等待，后台任务可能让这段等待长达 `task_timeout_ms`。目前面板只允许启停分段投递偏好插件。
