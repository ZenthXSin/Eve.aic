# 记忆与缓存评估

跨会话记忆、人物印象、约定和提示缓存都在改变“每轮交给模型什么”。为了让以后的改动可以前后比较，`connectors/qqbot/test/memory_eval.py` 用实际的 `eve-qqbot` 跑一段固定的多会话剧本，直接按模型替身收到的请求计算指标。

## 剧本

同一个人（`user-1`）先在群 1 聊了几句并说起自己在学 Rust，Eve 答应“下次帮他看看地图”；随后：

1. 他在群 2 出现；
2. 另一个人在群 2 说话；
3. 他在私聊里说起自己是护士；
4. 面板把他的私聊与两个群账号绑定为同一位主人；
5. 绑定后他分别在私聊和群 2 说话；
6. 最后在群 1 连续闲聊 6 句。

模型替身确定性地应答，只在需要时调用 `note_commitment`。

## 指标

| 指标 | 含义 | 门槛 |
| --- | --- | --- |
| 可见性正确率 | 9 个探针：同一账号跨群、他人、私聊绑定前后、私聊内容是否进群，该看到的印象与约定是否出现、不该看到的是否没有出现 | 100% |
| 稳定期前缀可复用率 | 最后 6 句闲聊里相邻两次请求，“工具定义 + 消息序列”公共前缀字符数占后一次请求的比例，口径与服务商提示缓存一致 | 平均不低于 0.6 |
| 各会话前缀可复用率 | 同上，按会话分别统计全过程的平均值 | 只报告 |
| 上下文规模 | 每次请求的总字符数（平均、最大），以及最后一次请求里人名资料、约定、跨会话记忆三类数据各占多少 | 只报告 |

门槛按当前实现的实测值留出余量。可见性是隐私边界，必须全部正确；前缀可复用率低于门槛说明有资料被放到了历史之后、或每轮都在变化。

## 运行

```sh
cargo build -p eve-app --bin eve-qqbot
python3 connectors/qqbot/test/memory_eval.py
```

标准输出会打印一行 `EVE_MEMORY_EVAL {...}`。设置 `EVE_MEMORY_EVAL_REPORT=路径` 时，同样的 JSON 报告写入该文件。CI 的 QQ 进程验收会运行它，低于门槛即失败。

## 局限

- 替身不代表真实模型：评估衡量宿主组装上下文的行为，不衡量模型是否用好了这些资料。
- 前缀可复用率是按请求内容计算的上限：实际命中还取决于服务商的缓存策略与最短缓存长度。真实服务的命中率见面板“模型健康”的缓存统计（[模型健康与就绪状态](./模型健康与就绪状态.md)）。
- 剧本很短，没有覆盖主动压缩；压缩与闲聊预算的行为见[上下文主动压缩](./上下文主动压缩.md)的验收。

评估不写入任何状态，不需要持久化与恢复语义。
