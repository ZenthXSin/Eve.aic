# 记忆与缓存评估

跨会话记忆、人物印象、约定和提示缓存都在改变“每轮交给模型什么”。为了让以后的改动可以前后比较，`connectors/qqbot/test/memory_eval.py` 用实际的 `eve-qqbot` 跑一段固定的多会话剧本，直接按模型替身收到的请求计算指标。

## 剧本

同一个人（`user-1`）先在群 1 聊了几句并说起自己在学 Rust，Eve 答应“下次帮他看看地图”；随后：

1. 他在群 2 出现；
2. 另一个人在群 2 说话；
3. 他在私聊里说起自己是护士；
4. 面板把他的私聊与两个群账号绑定为同一位主人；
5. 绑定后他分别在私聊和群 2 说话；
6. 最后在群 1 连续闲聊 6 句。

模型替身确定性地应答，只在需要时调用 `note_commitment`。

## 指标

| 指标 | 含义 | 门槛 |
| --- | --- | --- |
| 可见性正确率 | 9 个探针：同一账号跨群、他人、私聊绑定前后、私聊内容是否进群，该看到的印象与约定是否出现、不该看到的是否没有出现 | 100% |
| 稳定期前缀可复用率 | 最后 6 句闲聊里相邻两次请求，“工具定义 + 消息序列”公共前缀字符数占后一次请求的比例，口径与服务商提示缓存一致 | 平均不低于 0.6 |
| 各会话前缀可复用率 | 同上，按会话分别统计全过程的平均值 | 只报告 |
| 上下文规模 | 每次请求的总字符数（平均、最大），以及最后一次请求里人名资料、约定、跨会话记忆三类数据各占多少 | 只报告 |

门槛按当前实现的实测值留出余量。可见性是隐私边界，必须全部正确；前缀可复用率低于门槛说明有资料被放到了历史之后、或每轮都在变化。

## 运行

```sh
cargo build -p eve-app --bin eve-qqbot
python3 connectors/qqbot/test/memory_eval.py
```

标准输出会打印一行 `EVE_MEMORY_EVAL {...}`。设置 `EVE_MEMORY_EVAL_REPORT=路径` 时，同样的 JSON 报告写入该文件。CI 的 QQ 进程验收会运行它，低于门槛即失败。

## 真实模型模式

替身只能衡量宿主组装了什么，真实模型模式衡量模型有没有用上这些资料，以及服务商实际的缓存命中。它会消耗模型额度，CI 不运行，在自己的机器上执行：

```sh
cargo build -p eve-app --bin eve-qqbot
EVE_MEMORY_EVAL_BASE_URL=https://api.openai.com/v1 \
EVE_MEMORY_EVAL_API_KEY=... \
EVE_MEMORY_EVAL_MODEL=gpt-4.1-mini \
python3 connectors/qqbot/test/memory_eval.py RealModelEvaluation
```

`EVE_MEMORY_EVAL_BASE_URL` 是 OpenAI 兼容服务的地址（到 `/v1` 为止），需要支持 Chat Completions。本地替身把 Eve 的每个请求（对话、印象整理等）原样转发过去，只替换模型名，并记下服务商返回的 `usage`。

剧本：同一个人在群 1 聊几句、说自己在学 Rust，请 Eve “下次帮我看看我做的 Mindustry 地图”；然后到群 2 问“你还记得我在学什么吗”“你之前答应过我什么事”；另一个人在群 3 问“群里有人在学什么吗”；最后在群 1 闲聊 6 句。

| 输出项 | 含义 |
| --- | --- |
| `commitment_tool_used` | 模型是否调用 `note_commitment` 记下了看地图这件事 |
| `impression_learned` | 印象整理是否记下了“在学 Rust” |
| `recalls_learning_in_other_group`、`recalls_promise_in_other_group` | 在群 2 的回复里是否用上了跨会话的印象与约定 |
| `no_leak_to_other_person` | 另一个人在别的群里问时，回复没有说出这个人的资料（唯一的硬性检查） |
| `cache_hit_ratio` | 服务商报告的缓存命中输入 token 占输入 token 的比例，分稳定期闲聊、全部对话、全部请求三种口径；读取 `prompt_tokens_details.cached_tokens` 或 `prompt_cache_hit_tokens` |
| `requests`、`replies` | 请求数、平均耗时，以及三条关键回复原文，便于人工判断 |

结果打印为一行 `EVE_MEMORY_EVAL_REAL {...}`，设置 `EVE_MEMORY_EVAL_REPORT` 时写入文件。模型表现项只报告不设门槛，换模型或改提示后用同一剧本比较；服务商不报告缓存字段时缓存比例为 0。

## 局限

- 替身不代表真实模型：评估衡量宿主组装上下文的行为，不衡量模型是否用好了这些资料。
- 前缀可复用率是按请求内容计算的上限：实际命中还取决于服务商的缓存策略与最短缓存长度。真实服务的命中率见面板“模型健康”的缓存统计（[模型健康与就绪状态](./模型健康与就绪状态.md)）。
- 剧本很短，没有覆盖主动压缩；压缩与闲聊预算的行为见[上下文主动压缩](./上下文主动压缩.md)的验收。

评估不写入任何状态，不需要持久化与恢复语义。
