# 会话历史窗口

QQ 装配摘要服务时默认启用[上下文主动压缩](./上下文主动压缩.md)：在约 150k 估算 token 时压缩，目标约 100k，此时不使用本文的固定历史窗口。将 `runtime.history.compact_at_tokens` 设为 0，或运行未装配摘要服务的入口时，才使用以下窗口行为。

终端和 QQ 核心对话默认只向模型提供最近的完整历史轮次，控制长会话反复发送的历史规模。会话账本继续保存所有轮次，记忆与兴趣记录不删除。QQ 宿主还会把被省略的较早轮次压缩成有来源的摘要交给模型，见[对话历史摘要](./对话历史摘要.md)；没有可用摘要时，窗口只提示有内容被省略。

## 面板配置

在“插件页面 → `runtime.history`”设置以下字段，保存后下一轮生效，无需重启 QQ。同一轮的全部工具往返固定使用开始时捕获的窗口。

| 字段 | 环境变量 | 默认 | 范围 |
| --- | --- | --- | --- |
| `max_turns` | `EVE_HISTORY_MAX_TURNS` | 16 | 1–256 |
| `max_bytes` | `EVE_HISTORY_MAX_BYTES` | 65536 | 1024–8388608 |

配置优先级为文件覆盖、环境变量、默认值。恢复默认会移除文件覆盖。无效配置不会静默改用默认值，损坏配置继续拒绝启动并保留原文件。新增命名空间由配置插件提供页面，插件可以通过公开 ConfigService 读取。

## 如何选择

- 从最近一轮向前，选择同时满足轮数和字节限制的连续历史；不会跳过中间的大轮次再拼入更旧内容。
- 每轮以用户输入开始，包含其完整助手回复，以及配对的工具调用和结果；不截断 UTF-8 文字、不拆开工具协议。
- 失败轮仍由会话服务提供原话和明确的宿主失败说明；取消轮继续排除。最近失败请求能解释后续“继续”，不会冒充成功回复。
- 有历史被省略时，模型会收到宿主窗口说明与计数，知道当前上下文不包含全部历史，需要早期信息时应查询已有记忆工具或说明不确定。说明只存在于当前请求，不写成助手回复或训练样本。
- 最近一轮本身超过字节上限时，本轮保存为失败，在请求模型、执行工具之前停止。QQ 明确提示调整 `runtime.history.max_bytes`；可以在面板调大后发出新请求，原消息不自动重放。

字节预算按每个完整历史轮次的 JSON UTF-8 字节数累计，**不是 token 额度或整个请求大小**。系统提示、召回资料、工具定义、当前输入、本轮新产生的工具结果与输出预算另计。因此窗口能限制历史增长，不能保证外部模型接受请求或余额足够。

## 持久化与恢复

历史选择只作用于发给模型的副本，不裁剪 Session 状态、QQ 回执、记忆证据或开发操作日志；工具不会因历史被纳入而执行。扩大窗口后可重新纳入旧轮次。保存的窗口配置在重启后继续生效，会话状态格式不变，旧消息和工具不重放。

公开定义是 `eve-llm-api::HistoryWindow` 与 `HistoryWindowResolver`；实现由 Runtime 选择完整轮次，组合层按请求读取 ConfigService。独立装配的 Runtime 未设置 resolver 时，继续保留原有完整历史行为。

## 验证

`cargo test -p eve-runtime --test history_window` 验证整轮工具协议、失败原话、动态窗口、停止边界与完整账本。`python3 connectors/qqbot/test/history_window_test.py` 用实际 QQ 宿主、本地 HTTP 和隔离桥接验证面板热配置、QQ 超限通知、重启恢复和扩大窗口后的历史恢复，不调用真实模型、不发送正式 QQ 消息。
