# 异步启动与回执内存

重启时的长时间无响应来自历史账本恢复，而不只是 systemd 是否 enabled。守护与执行服务先发布管理状态出口，再在后台恢复；恢复中状态返回 available=false，所有业务动作仍等待恢复完成。私有 startup/{runtime,guardian}.json 每五秒更新恢复阶段与条数，完成后停止刷新。面板服务可独立启动，通过 admin.recoveryFiles 指定这两个文件，在监督接口尚未就绪时显示“恢复中”；失效状态不能冒充健康，控制操作不回退、不重发。

FactJournal 恢复以最多四条的有界预读重叠文件等待，依旧逐条验证路径、序号、摘要和前件。每128条让出事件循环。同步恢复回调复用刚验证的原件：守护直接重建状态，执行服务直接重建请求索引及在线模型拒绝状态，去掉再次读取并哈希整个历史的恢复扫描。回调或原件校验失败仍使日志不可用，不启动业务。

执行服务的终态回执只常驻请求元数据及 resultSeq；value/error 正文按需从 FactJournal 校验读取，保持原同步 receipt 形状、null/false、错误和动作幂等语义。每次读取得到独立解析对象，不重复 structuredClone 大正文，不删除或改写历史账本。改动基于 Eve 留下的离线候选 c7c1b1c，重新适配并验证当前主线。

部署需让面板不再 After=supervisor 阻塞，并保留 supervisor 的核心就绪检查；wait-core-ready 应检查 runtime.available 与 guardian.available（旧守护未返回该字段时沿用原状态语义）。启动等待允许真实恢复完成，不能反复超时将恢复清零。AGENT.md 属于经主人确认的私有运行配置，由启动前同步脚本放入当前提示的自定义前缀，不属于恢复账本或模型自动生成的事实。

验证只运行相关55项：恢复顺序/篡改/事件循环、恢复前管理拒绝、面板新鲜状态回退、回执按需读取与隔离、仲裁、模型拒绝及切换、执行服务；0失败。未重复全量验收。实际内存收益和冷启动时长以部署测量为准，不能用合成测试或重启后的低读数冒充稳定收益。
