# 用户反馈驱动的内生重规划

本切片补齐“待办 → 反思 → 用户提供新事实 → 自动再次反思”。保存反馈后，QQ 后台会按新的目标修订评估并派生草稿，不需要再次 `/goal` 或手动下达规划指令。它沿用已有目标、驱动与议程循环；用户事实进入第二轮模型输入，执行结果仍以真实 Control/Session 保存和产物校验为准。

## QQ 使用

1. 以 `--cognition --cognition-max-executions 4` 启动已有 QQ 宿主。
2. 发送 `/goal 整理房间的计划`。回复给出目标 ID 和版本；`/mind` 查询当前草稿。
3. 发送 `/goal-feedback 目标ID 1 只整理书桌，不移动书架`，使用实际显示的版本。反馈保存后返回新版本，后台在预算允许时自动重新规划。
4. `/mind 目标ID` 只返回当前版本草稿；新稿尚未形成时显示等待或执行状态。继续补充时使用新版本，例如预算或环境发生变化。

普通聊天不会自动当作目标反馈。原目标正文保留；反馈是用户提供的事实或纠正，尚未经独立工具验证，不赋予工具权限。重复同一消息不再次增加修订，不触发重复规划；新消息携带旧版本时明确拒绝。QQ 的可信身份仍包含 AppID、群/私聊、目标和发送者范围，不能借目标 ID 跨范围修改。

## 本地 CLI

```bash
cargo run -p eve-app --bin eve-cognition -- --state-dir .eve-cognition add --id report --text '整理报告'
cargo run -p eve-app --bin eve-cognition -- --state-dir .eve-cognition run --seconds 30 --max-executions 1
cargo run -p eve-app --bin eve-cognition -- --state-dir .eve-cognition feedback --id report --revision 1 --feedback-id report-fact-1 --text '只允许一页'
cargo run -p eve-app --bin eve-cognition -- --state-dir .eve-cognition run --seconds 30 --max-executions 1
cargo run -p eve-app --bin eve-cognition -- --state-dir .eve-cognition show --id report
```

`add` 和 `feedback` 不读取模型密钥或发出模型请求。`feedback` 支持显式 `--user`，默认 owner；本地 CLI 操作者属于受信宿主。`run` 沿用主模型配置，只在有可执行目标时调用模型。CLI 是独占状态的有限运行窗口，先结束前一命令再提交反馈，不能与正在使用相同目录的 QQ 进程同时运行；在线反馈使用 QQ 命令。

`show` 保留所有历史草稿，每项新增 `current` 与 `stale`；只有精确绑定父目标当前修订的草稿为 current。子目标 Completed 只证明草稿已经保存并通过结构校验，父目标仍 Waiting。显式查看旧子目标仍能看到原产物，但标记为历史。

## 契约与原子提交

`eve-cognition-api` 定义 `GoalFeedbackInput`、`GoalFeedbackReport`、`GoalFeedbackService` 和严格的 `GoalUserFeedback` JSON。用户身份、主体和可修改的父目标来源由宿主绑定到服务，不从反馈正文或调用参数接受任意身份。

`eve-cognition-plugin::UserGoalFeedback` 只处理同用户、同来源通道的有效 Waiting 用户目标。它比较期望目标修订，再通过现有 CognitionAdmin 的全局 CAS 一次保存来源事件和最新反馈快照。原 description、priority、budget 和执行 `Goal.feedback` 不变；后者只用于执行结果，不能用于尚未执行的用户事实。

每条反馈正文最多 4096 UTF-8 字节；序列化事件最多 8192 字节，极端转义超限明确拒绝而不截断持久证据。事件记录包含前后目标修订、反馈标识和原文。相同反馈 ID、目标、来源、用户和正文在修订检查前幂等返回原结果；重送时间及当前期望修订不使已提交消息重复生效。相同 ID 的不同正文被拒绝。

规划提示有 8192 字节总上限，优先容纳最新反馈，再包含有界的近期用户反馈与原目标；未包含的历史或正文缩减明确标记。近期事实只来自匹配来源的持久用户事件，旧模型建议不作为真实观察。新旧用户事实有冲突时以新修订为准；提示缺失部分不能被模型臆造。完整原文仍保留在持久事件中。

`eve-cognition-loop-plugin::current_reflection` 用主体、父目标 ID、父修订及 input/created 因果事件共同定位当前草稿；保留命名空间记录残缺或矛盾时返回错误，不按最新完成时间猜测。默认 QQ 策略在准入前再检查版本；可替换规划器若产生可执行反思，须使用这套因果证据契约，不能用来源引用绕过当前版本校验。

## 并发、预算与恢复

反馈与新候选的派生是两次独立原子提交。反馈保存失败不发布新版本；若随后派生因容量或存储失败而停止，已保存反馈保留，不能宣称已经完成规划。CAS 冲突不隐式重试，QQ 明确提示重新查看版本。状态损坏继续报错，不能清空修复。

旧 Ready 草稿被取消，旧 Executing 草稿允许在原预算内收尾，旧 Completed/Cancelled/Blocked 留档。新稿使用新的父修订标识，不覆盖旧执行结果。认知循环同主体一次只执行一项；旧执行收尾之后才执行新候选。反馈不会撤销现实工具副作用，也不会提高单目标或本次启动的派生/执行上限。

每个父修订仍最多派生一次，失败或不确定的旧执行不自动重试。本次启动名额耗尽时反馈仍可保存，回复说明留待后续启动评估；启动期间连续反馈可合并到最新未规划版本，不承诺每条消息都发出一次模型请求。

认知快照仍为版本 1，不迁移或重写旧事件。重启只评估未执行的当前版本，旧稿不重放。QQ 回执与认知提交没有跨插件事务：保存反馈后但确认回复前崩溃，可能已经生效而用户没有收到确认；新 `/goals`、`/mind` 可查询，重启不补发旧回复。

验证包含实际 QQ 替身与环回模型的双轮交互、在途反馈、连续事实、来源隔离、幂等、旧版本拒绝和重启不重放。协议替身验证的是控制链与输入内容，真实模型的规划质量仍需本地 QQ 交互检验。本地 CLI 已增加[显式文件观察](./本地文件观察.md)，Environment 证据与用户反馈共同进入后续规划；受控现实工具执行、更广泛环境感知、长周期计划与通用 AGI 是后续能力。

连续反馈的验收还覆盖旧执行阻塞期间的两次修订：中间 Ready 草稿取消且没有执行记录，只调用旧执行与最新版本；恢复后不重建中间稿。确认回复投递失败时，已提交反馈与新草稿仍保留，QQ 回执为 Failed；重启只允许查询当前结果，不补发确认或再次规划同一反馈。
