# 有条件多步计划

本切片把“当前草稿 → 一次导出”扩展为可持久推进的多步计划：计划绑定目标修订与输入摘要，步骤之间有依赖，每步引用宿主登记的能力、声明尝试次数与期限，并给出可核对的效果条件。只有宿主独立读取得到的证据满足条件时，步骤才算完成；上游输入变化会使尚未完成的步骤失效。

计划有两种来源：本地操作者以 JSON 提供，建立即活动；或由模型就当前目标修订提出建议，经宿主校验后保存为待确认，操作者确认后才活动。模型建议不授予任何执行权限。QQ/面板入口和“目标完成”判定属于后续切片。计划完成只说明每一步的效果条件都被证据满足；父目标仍保持 Waiting，不代表现实任务完成，也不代表 AGI 已实现。

## 使用

先按[本地文件观察](本地文件观察.md)建立目标、观察输入文件并完成一次反思，再用 `show --id ID` 查看当前目标修订和最近一次文件观察的 SHA-256。步骤文件只包含 `steps`：

```json
{"steps": [
  {"id": "check", "title": "确认输入仍是计划依据", "capability": "eve.file.observe.v1",
   "depends_on": [], "max_attempts": 1, "timeout_ms": 5000,
   "effect": {"kind": "digest_equals", "sha256": "<当前输入摘要>"}},
  {"id": "export", "title": "导出当前草稿", "capability": "eve.artifact.export.v1",
   "depends_on": ["check"], "max_attempts": 1, "timeout_ms": 30000,
   "effect": {"kind": "verified"}},
  {"id": "wait", "title": "等待用户按清单更新材料", "capability": "eve.file.observe.v1",
   "depends_on": ["export"], "max_attempts": 3, "timeout_ms": 5000,
   "effect": {"kind": "digest_differs", "sha256": "<当前输入摘要>"}}
]}
```

```bash
eve-cognition --state-dir .eve-observe plan-create --id report --revision "$REV" \
  --input-sha256 "$INPUT_SHA256" --steps ./steps.json
eve-cognition --state-dir .eve-observe plan-show --id report
eve-cognition --state-dir .eve-observe plan-step --plan "$PLAN" --step check --observe-file ./progress.txt
eve-cognition --state-dir .eve-observe plan-step --plan "$PLAN" --step export \
  --observe-file ./progress.txt --output ./exports/report-plan.json
eve-cognition --state-dir .eve-observe plan-step --plan "$PLAN" --step wait --observe-file ./progress.txt
```

`plan-create` 只在目标属于 `--user`（默认 owner）、仍在等待且修订与命令一致时保存；给出 `--input-sha256` 时须等于目标最近一次文件观察的摘要。相同内容重复创建返回原计划（`duplicate: true`），同一目标已有其他活动计划时冲突；旧计划的绑定已经失效时，创建前会先把它封存为过时。

`plan-step` 每次执行一个就绪步骤。路径参数每次显式给出，不进入计划或状态；缺少能力所需参数时在保存执行状态之前拒绝，不消耗尝试次数。命令退出码为零表示返回了结构化结果：`executed: false` 加 `reason: binding_changed` 表示发现绑定已变化并封存了计划，没有执行任何能力。只有 `plan.status == "completed"` 才表示全部效果条件满足。`plan-show` 列出计划、就绪步骤和 `binding_current`（当前绑定是否仍成立）。

## 模型建议与确认

```bash
eve-cognition --state-dir .eve-observe plan-propose --id report --revision "$REV"
eve-cognition --state-dir .eve-observe plan-confirm --plan "$PLAN"
eve-cognition --state-dir .eve-observe plan-withdraw --plan "$PLAN"
```

`plan-propose` 需要与反思相同的主模型配置（`EVE_OPENAI_API_KEY` 等，complete 模式）。宿主先核对目标所有权、等待状态与 `--revision`，再把目标描述、当前修订已验证的反思草稿（尚未完成时省略）和登记能力的说明与上限作为一条 JSON 数据交给建议器；不传文件路径、文件正文或会话历史，不安装工具。计划绑定由宿主按当前修订与最近一次文件观察摘要确定，模型不能选择。

- 每个绑定（目标修订与输入摘要）至多保存一条建议记录、发起一次无工具请求，期限不超过 30 秒。已有记录时直接返回（`duplicate: true`），失败、中断或空建议也不重试；目标出现新修订后才能再次请求。模型配置缺失、修订不符或他人目标在保存记录之前拒绝，不消耗这次机会。
- 输出须是严格的 `{"steps": [...]}`：拒绝 Markdown、额外字段与重复键。账本按记录的绑定与登记能力重新校验依赖、尝试次数和期限；不合规记为 `invalid_output`，不保存计划。空步骤记为 `empty`。请求结束时目标或输入已变化，记为 `binding_changed`。
- 校验通过的建议保存为 `proposed`：不准入任何步骤，同一目标也不能另建计划或另发请求。`plan-confirm` 再次核对当前绑定，仍成立才转为 `active`（记录确认时间）；已变化时封存为 `stale` 并返回 `confirmed: false`。确认之后的执行与操作者计划完全相同。
- `plan-withdraw` 撤销待确认或活动计划：未开始的步骤 `blocked`，已满足步骤的证据保留；有步骤执行中时拒绝，避免掩盖可能已发生的副作用。撤销后可以建立新计划。

建议计划的 ID 另含建议记录 ID，不会与内容相同的操作者计划混同。草稿、目标描述与建议标题都是未经验证的数据。

## 能力与效果

| 能力 | 作用 | 上限 |
| --- | --- | --- |
| `eve.file.observe.v1` | 重新读取本次显式绑定的文本文件，得到完整字节 SHA-256；不修改目标或输入证据 | 最多 3 次尝试，期限 ≤ 30 秒 |
| `eve.artifact.export.v1` | 经[受控产物行动](受控产物行动.md)导出当前修订已完成的草稿，独立回读产物摘要 | 1 次尝试，期限固定 30 秒，计划须绑定输入摘要 |

引用能力不授予权限；宿主只执行登记过的能力，并在登记上限内接受计划。效果条件只比较证据字段：`verified`（得到经独立读取的证据）、`digest_equals`（摘要等于给定值）、`digest_differs`（摘要不同于给定值，用于等待输入被修改）。条件不解释正文语义，文件内容和导出草稿仍是未经验证的数据。

## 状态与转换

| 步骤状态 | 含义 |
| --- | --- |
| `pending` | 未开始，或上一次尝试的效果未满足且仍有尝试次数 |
| `executing` | 已保存执行状态，正在执行能力 |
| `satisfied` | 证据满足效果条件 |
| `failed` | 尝试次数用完仍未满足，或能力失败且不可重试 |
| `blocked` | 执行中断、被取消，或因其他步骤失败计划停止 |
| `invalidated` | 计划绑定的输入已变化，本步骤不再按原计划推进 |

计划状态：`proposed`（模型建议，待确认）、`active`、`completed`、`blocked`、`stale`（绑定已变化）、`withdrawn`（操作者撤销）。同一目标同一时间至多一份 `proposed`/`active` 计划或一条进行中的建议请求。

就绪步骤须同时满足：计划活动、没有其他步骤执行中、依赖全部 `satisfied`、仍有尝试次数。计划最多 8 步，依赖不能自指、重复或成环。一次只执行一个步骤。

- 效果未满足或能力失败、超时时，剩余尝试次数内回到 `pending`，用完则 `failed`；有副作用的导出只允许一次尝试。取消与中断直接 `blocked`，不自动重试。
- 任一步骤 `failed` 或 `blocked` 时计划进入 `blocked`，其余未开始步骤一并阻塞，不再准入。需要换一种做法时，建立新的计划。
- 全部步骤 `satisfied` 时计划 `completed`。

## 上游变化与失效

计划绑定目标 ID、目标修订和（可选的）输入摘要。用户反馈、新的文件观察等任何使目标修订提高的变化，或最近一次观察摘要变化，都使绑定不再成立；待确认的建议同样会被封存。`plan-step` 在保存执行状态之前核对当前绑定；不成立时把计划封存为 `stale`：所有未开始步骤变为 `invalidated`，已满足步骤的证据作为历史保留。执行中的步骤结束时只记录证据，不计为满足。导出能力自身还会在写入前后重新核对目标与输入，执行中发现变化时记为 `binding_changed`。

已完成、已阻塞或已撤销的计划保留原结论，不因之后的输入变化改写。过时计划之后不能再执行任何步骤，但可以为新修订建立新计划。计划中的观察步骤只读取文件，不写入目标的输入证据，因此等待文件变化的步骤不会让自己的计划过时。

## 持久化与恢复

计划账本 `eve.plan/plans.v1` 经公开 StateStore 保存，文件与 PostgreSQL 后端语义相同，内含计划与建议记录。每次变更先持久化，成功后才更新内存；写入失败时保留旧状态，并提示可能已经提交、需要重新打开核对。

账本格式当前为版本 2。版本 1（只有操作者计划）仍可读取：只在内存中升级，读取不改写原字节，下一次写入时保存为版本 2；版本 1 字节中出现建议记录或计划来源字段视为损坏。版本 2 账本不能被只认识版本 1 的旧程序读取，旧程序会明确报错并保留原字节。

| 情况 | 结果 |
| --- | --- |
| 保存执行状态失败 | 不执行能力，步骤仍 `pending` |
| 能力已执行但结果保存失败 | 命令报错，账本保留 `executing`；下次打开封存为 `blocked/interrupted`，不重放 |
| 重启发现 `executing` | 封存为 `blocked`（计划过时时为 `invalidated`），尝试记录 `interrupted`，不重放可能已发生的副作用 |
| 保存建议请求记录失败 | 不请求模型 |
| 已请求模型但结果保存失败 | 命令报错，记录保留 `requested`；下次打开记为 `failed/interrupted`，不重放请求 |
| 重启发现 `requested` 建议 | 记为 `failed/interrupted`；同一绑定不再请求，迟到的结果不能写回 |
| 账本达到 64 份计划或 64 条建议记录 | 新建计划或新的建议请求失败（计划已满时也不请求模型），不淘汰旧记录；已有记录仍可幂等读取 |
| 账本损坏、重复键、未知版本或属于其他主体 | 打开失败，原字节保留，不清空 |

所有计划命令打开账本时都会先执行上述恢复，属于恢复性读取；`plan-show` 同时列出该目标的建议记录。每次修改都用计划记录修订做 CAS，旧修订的写入被拒绝。时钟回拨到计划创建之前时拒绝开始步骤，不写入矛盾时间。

## 分层

| 层 | 职责 |
| --- | --- |
| `eve-plan-api` | 计划、步骤、效果条件、能力上限、建议记录与账本接口，可替换的 `PlanProposer`；纯函数状态机负责依赖、重试、确认、撤销、失效和完成判定 |
| `eve-plan-plugin` | 持久账本、CAS、启动恢复与容量；`ModelPlanProposer` 发起一次无工具请求并严格解析输出；管理句柄不发布到服务目录 |
| `eve-app` | 登记能力及说明、核对目标所有权与当前绑定、准备建议上下文、显式绑定路径并执行观察或受控导出 |

当前绑定沿用文档行动准入的目标所有权与最近文件观察校验；观察记录残缺或矛盾时报错，不退回旧证据。

## 后续

1. QQ 与本机面板入口：查看计划进度与建议记录、确认执行与撤销计划。
2. 明确效果条件下的目标完成判定：哪些计划条件满足时可以把父目标标为完成，以及用户确认的位置。
3. 用可复验场景评估模型建议的质量（被确认比例、无效输出、效果达成），再考虑由后台循环自动请求建议。
4. 更多能力需要分别定义授权范围、预算、证据与恢复语义后再登记。
