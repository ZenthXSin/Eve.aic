# EVE.AIC 第一阶段执行书

## 执行原则

1. 先确定边界，再写实现。
2. 先让最小闭环运行，再增加抽象。
3. 插件只能通过 Context 访问 Runtime。
4. 内核不硬编码 Memory、LLM、Personality 等认知模块。
5. 所有生命周期资源必须能够自动清理。
6. 每个阶段都必须有可执行的验收场景。
7. 不为了未来可能的需求提前引入复杂插件协议。
8. 自动推进既定计划，遇到需用户判断的关键问题再询问；每次 PR 前检查已有评论、Issue 和其他 PR。

## 当前执行顺序

```text
文档边界
    ↓
Plugin API
    ↓
Kernel Skeleton
    ↓
Registry / Dependency
    ↓
Lifecycle / Scope
    ↓
Event / Service
    ↓
State / Task
    ↓
Failure / Cleanup
    ↓
Shutdown / Recovery
```

## 第一条验收链（已实现）

```text
Runtime 启动
    ↓
注册 ServiceProviderPlugin
    ↓
注册 EventConsumerPlugin
    ↓
消费者声明并解析提供者依赖
    ↓
启动消费者，自动启动提供者
    ↓
消费者获取 Service
    ↓
提供者发布 Event
    ↓
消费者收到事件并写入 State
    ↓
停止消费者，再停止提供者
    ↓
清理监听器和 Service
    ↓
启动失败插件并验证资源回滚
```

运行 `cargo run -p eve-runtime` 实际执行以上验收链；`cargo test --workspace` 同时验证后端替换、权限拒绝、类型冲突、事件重入、状态隔离、停止顺序和回滚错误。

任务管理已有独立测试；持久化 State 和重启恢复使用下述独立验收，不作为基础协作验收链的前置条件。

## 暂停条件

遇到以下情况时，应先回到设计讨论，不继续堆代码：

- 插件需要访问 Runtime 私有结构
- 两个插件直接互相调用内部方法
- 生命周期状态无法解释
- 失败后无法清理已经创建的资源
- 状态恢复需要依赖具体插件实现细节
- 为了实现一个功能而引入动态 ABI 或微服务

## 任务验收（已实现）

运行示例同时执行前台立即、延迟、指定时间和三次重复任务，共六次，随后停止后台周期任务。独立任务测试采用 Tokio 虚拟时钟验证调度与共同截止时间，并覆盖停止准入、任务错误与 panic、实际次数、失败回滚、丢弃等待、可替换后端和未退出任务诊断。

扩展验收：仅依赖定义层的插件自行定义 `WriteStateTask` 和递增间隔调度，实际完成三次状态写入，并将同一类型用于后台周期执行。独立扩展测试验证事件触发、调度实例隔离、次数上限、提前结束、取消等待、工厂及调度失败，以及完成后释放工厂捕获资源。

## 日志验收（已实现）

示例插件通过 Context 记录消息处理、任务完成和预期启动失败，默认写入标准错误；宿主停止后显式刷新。Runtime 测试注入内存后端，检查三条日志的插件来源、级别和字段。独立日志测试覆盖级别过滤、按容量淘汰、并发短写不交错、控制字符转义、后端错误与启动回滚、替代实现重入 Context，以及任务收尾和旧 Context 的日志边界。

## 状态恢复验收（已实现）

连续两次运行 `cargo run -p eve-runtime --example state_recovery -- ./target/state-recovery-demo`，独立进程依次读取“无”和“1”，写入“1”和“2”。自动化测试覆盖跨进程锁、重新创建 Kernel 后恢复、任意字节、严格格式校验、并发提交与 Windows 实际替换失败，均使用隔离临时目录。

## 诊断验收（已实现）

协作示例通过 `RuntimeInspector` 查询四个插件的终态和残余任务，验证正常停止与预期失败的区别。独立测试检查清单排序、快照独立性、启动/停止中间状态、共享依赖只停止一次、多插件失败保留、同插件不同阶段失败保留，以及退出检查失败或残余任务必然报告失败。
