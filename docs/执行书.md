# EVE.AIC 第一阶段执行书

## 执行原则

1. 先确定边界，再写实现。
2. 先让最小闭环运行，再增加抽象。
3. 插件只能通过 Context 访问 Runtime。
4. 内核不硬编码 Memory、LLM、Personality 等认知模块。
5. 所有生命周期资源必须能够自动清理。
6. 每个阶段都必须有可执行的验收场景。
7. 不为了未来可能的需求提前引入复杂插件协议。

## 当前执行顺序

```text
文档边界
    ↓
Plugin API
    ↓
Kernel Skeleton
    ↓
Registry / Dependency
    ↓
Lifecycle / Scope
    ↓
Event / Service
    ↓
State / Task
    ↓
Failure / Cleanup
    ↓
Shutdown / Recovery
```

## 第一条验收链（已实现）

```text
Runtime 启动
    ↓
注册 ServiceProviderPlugin
    ↓
注册 EventConsumerPlugin
    ↓
消费者声明并解析提供者依赖
    ↓
启动消费者，自动启动提供者
    ↓
消费者获取 Service
    ↓
提供者发布 Event
    ↓
消费者收到事件并写入 State
    ↓
停止消费者，再停止提供者
    ↓
清理监听器和 Service
    ↓
启动失败插件并验证资源回滚
```

运行 `cargo run -p eve-runtime` 实际执行以上验收链；`cargo test --workspace` 同时验证后端替换、权限拒绝、类型冲突、事件重入、状态隔离、停止顺序和回滚错误。

任务管理已实现并有独立测试；持久化 State 和重启恢复属于后续阶段，不作为当前验收链的前置条件。

## 暂停条件

遇到以下情况时，应先回到设计讨论，不继续堆代码：

- 插件需要访问 Runtime 私有结构
- 两个插件直接互相调用内部方法
- 生命周期状态无法解释
- 失败后无法清理已经创建的资源
- 状态恢复需要依赖具体插件实现细节
- 为了实现一个功能而引入动态 ABI 或微服务
