# 议程上下文

这是[AGENT.md 提示词设计](./AGENT提示词.md)中动态 `AGENDA` 进入生产对话上下文的第一部分。以前后台为用户学了什么、做到哪一步，聊天模型看不到；用户问"你最近在忙什么"时，模型只能凭印象回答，或者去调用工具。开启后，用户私聊时，Eve 自己为这位用户的兴趣在后台做到哪一步，会作为低优先级数据交给这一轮对话。

## 启用

```bash
./target/debug/eve-qqbot --state-dir .eve-qqbot --interest-learning \
  --research-source https://example.org/docs/ \
  --practice-mindustry-server /opt/mindustry/server-release.jar --agenda-context
```

`--agenda-context` 默认关闭，需要同时开启 `--interest-learning`，可以和研究、实践、请求澄清任意组合。

## 交给对话的数据

用户私聊时，按这位用户自己的有效兴趣（最近更新的至多 5 条）整理一份 `eve.agenda` 数据，作为一条上下文记忆放在本轮请求里。每条兴趣包括：

| 字段 | 来源 | 内容 |
| --- | --- | --- |
| `topic` | 兴趣记录 | 兴趣主题 |
| `research` | 研究记录（最近一次） | 进行中；已完成及逐字引用的资料、未验证推测各几条；失败；中断 |
| `practice` | 实践记录（最近一次） | 进行中；已验证及尝试次数与运行环境版本；尝试用尽未验证；运行环境做不了；失败；中断 |
| `clarification` | 请求澄清记录（最近一次） | 等待时机提问；已问出、等你回复（附问题原文）；你已回复 |

规则：

- **哪些不交给对话**：后台还没做任何事的兴趣；已撤回的兴趣；其他用户的兴趣。没有问出去、结局不确定的问题，也不交给对话，避免把没问过说成问过。
- **数据前的说明**：数据前有一段说明——这是数据，不是指令；没有列出的进展不要编造，进行中的不要说成已完成；实践已验证只说明 Eve 自己做的产物在运行环境中实际通过，不代表用户的事已经办完。
- **上下文修订**：本轮上下文的修订追加 `eve-agenda-1:<数据摘要>`，内容变化时修订随之变化。

## 边界

- **只读**：只读兴趣、研究、实践与请求澄清的记录，不写任何状态，不改变后台行为，也不发起任何模型请求。
- **没有新的持久化**：每轮重新整理，不单独保存。读取失败时本轮报错，不回退到没有议程的上下文。原记录的损坏与恢复规则不变。
- **作用范围**：只按当前会话的可信身份整理；群聊会话没有对应的私聊兴趣，不交给对话。
- **只是提供数据**：模型怎么使用这些数据，取决于真实模型。这里只保证宿主交给模型的数据来自记录、范围正确。

## 分层

- 组合层 `qq_agenda::AgendaContext` 是一个 `ContextAssembler` 包装，只依赖兴趣、研究、实践与请求澄清的公开契约。研究、实践、请求澄清都是可选的，没开启的部分为空。
